# 团队知识初始化

知识结构唯一来源为 `server/src/main/resources/db/schema.sql`。新库由运维显式执行该文件；应用启动只检查，不 ALTER、建表或清库。最终结构为30张表。保留数据环境必须先备份并暂停业务写入，由运维对照 canonical DDL 显式补入知识新字段和8张表；不要在已有库直接重放整份 CREATE TABLE 文件。

历史版本新增 level/scope_kind/content_type 的待初始化值均为 `''`；contributors 为 `[]`，proposal_id/reviewer_id 为 `''`、reviewed_at 为 NULL。当前条目的 last_reviewed_at 留 NULL、reviewed_feedback_id 为0；旧正文和全部业务 ID、版本、作者、时间、current_version_id 保持原值。物理自增 id、索引、字符集与引擎仍按唯一 DDL。

确认结构完整后，用受限 datasource 配置显式运行：

```sh
node scripts/workbench/server.mjs init-knowledge
```

命令只处理全空元数据，将历史版本置为 experience/workspace/article，贡献者取真实原作者；旧 category 不猜测成强制规约。不写虚假审核人/审核时间，也不解档。混合或未知元数据会拒绝，不应强行清空后重试。命令失败时先根据团队/版本标识人工核对，应用不会自动修复。完成后检查条目、版本数、固定引用和新元数据，再恢复服务。

本卡隔离验证入口：`scripts/workbench/run-knowledge-governance-smoke.sh`（需 JAVA_HOME 与 HC241_MYSQL_ROOT）；仅新建临时 MySQL 数据目录、演示库和 Java 服务。它输出证据目录，可用 `scripts/workbench/check-knowledge-initialization.sh <证据目录>` 验证两次初始化前后 ID/作者/正文/版本不变及重复不覆盖。脚本限定本卡隔离目录与库名，不用于用户现有环境。
