# Harness Code 内网依赖安装

## 适用范围

本说明对应 OpenTUI `0.4.3` 已提供原生包的 macOS、Windows、Linux x64/arm64 目标，以及 CPython 3.11+、Bun 1.3.13、Node 20+、npm 11.11.0 和 uv 0.11.1 及以上版本的内网安装。Linux 默认选择 glibc 原生包，musl 环境设置 `OPENTUI_LIBC=musl`。JavaScript 依赖由 npm 与 `package-lock.json` 管理，实际下载源由安装命令显式传入；不要把公网地址或凭据写入仓库。依赖安装、依赖检查与 Python 测试入口不启动 Bun。

同一条 `npm run deps:sync` 同时服务企业外开发和企业内安装。脚本通过 `npm config get registry` 读取 npm 当前源，并优先读取 `PIP_INDEX_URL` 或 `python -m pip config get global.index-url`；已有 `UV_DEFAULT_INDEX` / `UV_INDEX_URL` 也可继续使用。企业外保持公网配置即可，两边都没写地址时默认 `https://registry.npmjs.org/` 和 `https://pypi.org/simple`。企业内把 npm/pip 配到企业源；若工具配置仍指向公网，`HARNESS_NPM_REGISTRY` / `HARNESS_PYPI_INDEX` 会把这一次安装切到内网。一边已经是内网源时，另一边不会默认为公网。若 Python simple index 与制品下载使用不同的内网主机，再提供逗号分隔的 `HARNESS_PYPI_ARTIFACT_HOSTS`。脚本拒绝凭据、query/hash、与所选源不一致的锁文件下载地址，以及工具链版本不符。公网模式接受 `registry.npmjs.org`、`pypi.org` 和 `files.pythonhosted.org`；内网模式仍拒绝公网下载地址。

目标是让解析结果和实际安装环境都不包含 `anthropic`、`langchain-anthropic`、`claude-agent-sdk`、`@anthropic-ai/*` 或其他包名含 `anthropic` 的依赖。

## HC-179 Windows x64 临时源码化例外

临时分支 `feat_hc_179_内网依赖源码化` 为 Windows x64 提前验证提供五个精确 npm 发布工件：

```text
third_party/npm/@opentui/core              # @opentui/core@0.4.3
third_party/npm/@opentui/react             # @opentui/react@0.4.3
third_party/npm/@opentui/core-win32-x64    # @opentui/core-win32-x64@0.4.3
third_party/npm/bun-ffi-structs            # bun-ffi-structs@0.2.4
third_party/npm/react-devtools-core        # react-devtools-core@7.0.1
```

这些目录由精确 npm tarball 解包而来。来源、MIT license 元数据、目标 `win32/x64` 和 `opentui.dll` 记录在 `third_party/npm/provenance.json`；tarball integrity 只作记录，安装时不再和脚本常量对账。CLI 和五包运行时边精确锁定 vendored 版本（npm 的 workspace 链接语义）；安装运行 npm（冻结同步一次 `npm ci`，更新锁先只写锁再安装一次），peer 策略由根 `.npmrc` 承担，其他依赖继续使用显式内网 npm 源。五个目标包任一在 lock 中出现 registry 解析、版本/文件/平台篡改、缺少发布入口或根 `patchedDependencies` 重复打补丁，安装前即失败；安装后还会检查实际 `package.json`/入口 realpath 是否仍落在 `third_party/npm/`。

`react-devtools-core` 的 `ws@7.5.10` 修改已经固化在 vendored `package.json`，根 `patchedDependencies` 不再应用同一补丁；原 `patches/react-devtools-core@7.0.1.patch` 仍作为 provenance 来源证据。`@opentui/react`、`bun-ffi-structs` 和 `react-devtools-core` 的源仓库开发期 metadata 仅为本地 workspace 可安装而归一化；`@opentui/react` 保留现有内网可安装的 `@types/react@19.2.14`，不额外 vendor `@opentui/keymap` 或其他开发依赖。发布目录内的运行文件、声明、资源、完整 `dist/**`、README 和已有许可证保持完整。

这是临时分支例外，不是 canonical `master` 的永久依赖策略。正式内网 registry 能稳定提供五个同版本包、完成 `deps:sync -- --update-lock`，并在 macOS、Windows、Linux 目标环境完成空缓存安装与 TUI 验收后，应删除源码化目录及门禁并恢复普通 registry 依赖。

## 统一入口

首次在内网重新解析锁文件前，可以先确认企业配置已经生效：

```text
npm config get registry
python -m pip config get global.index-url
npm run deps:sync -- --update-lock
```

若任一工具没有配置可用内网源，可仅为该项设置 `HARNESS_NPM_REGISTRY` 或 `HARNESS_PYPI_INDEX` 作为备用，无需重复配置已经正常工作的另一项。

`deps:sync -- --update-lock` 会在选定的内网源下只更新 `package-lock.json` 和 `packages/agent/uv.lock`，不先做一遍完整安装。锁校验通过后，用一次冻结安装完成 JavaScript/Python 依赖、DeepAgents 补丁、来源复核和 smoke；不需要再执行第二条安装命令。提交前必须审查锁文件中所有 Python registry/制品地址均属于该内网主机；不要手工把旧公网 URL 替换成猜测地址或改写哈希。

`deps:sync` 的默认模式和 `--update-lock` 模式允许在 `darwin/{x64,arm64}`、`win32/{x64,arm64}`、`linux/{x64,arm64}` 执行；其他目标及非法 `OPENTUI_LIBC` 值会在解析内网源或任何安装动作前失败。Windows x64 使用 vendored native workspace，另外七个 OpenTUI native optional package 必须由当前 npm 企业源提供，禁止回退公网。

当前提交中的 `package-lock.json` 和 `packages/agent/uv.lock` 是公网来源快照，企业外可直接冻结同步。把它带进企业内之前，必须先执行一次内网 `deps:sync -- --update-lock` 并审查差异，之后才能在内网做冻结同步。

后续工作副本只执行冻结安装：

```text
npm run deps:sync
npm run deps:check
```

`deps:sync` 在任何联网动作前按以下顺序执行；`--update-lock` 只是在冻结同步前先更新两个锁文件，其余步骤相同：

1. 检查当前执行平台属于 OpenTUI 支持矩阵，并在 Linux 校验 `OPENTUI_LIBC`；再检查 node 满足 `>=20`（读当前进程版本）、npm 满足 `>=10.0.0`、uv 至少为 `0.11.1`、Python 满足 `>=3.11,<4.0`；`packageManager` 的精确 npm 版本由测试核对，不在安装前置里再读一遍。Bun `1.3.13` 只在启动 CLI/OpenTUI、Bun bundler 或尚未迁移的 CLI 测试时要求，不属于依赖安装前置；
2. 检查五个源码化 npm 包的版本、MIT license 元数据、显式发布入口、Windows x64 DLL、workspace lock 和 `ws@7.5.10` patch 状态；
3. 检查 npm/Python 源均为内网，并核对 `uv.lock` 与 `package-lock.json` 的 registry/制品地址；
4. `--update-lock` 先用 `npm install --package-lock-only --ignore-scripts` 更新锁并校验，再使用显式内网源和 `package-lock.json` 冻结运行一次 `npm ci` 安装 JavaScript 依赖；默认冻结同步直接执行这一次 `npm ci`；
5. 校验 npm 安装后的五个目标包 realpath、`package.json` 和入口文件仍来自 `third_party/npm/`，并校验当前平台 native optional package 的身份、平台 metadata、入口和非空原生库；
6. 使用 `packages/agent/uv.lock` 和 `test` extra 冻结安装 Python 依赖，强制 `copy` 链接模式；
7. 对官方 `deepagents==0.7.3` 安装结果应用 `scripts/dependencies/apply_deepagents_patch.py`，再执行真实假模型 smoke；
8. 检查 Python 安装树、DeepAgents 源码、`uv.lock`、`package-lock.json` 和实际 npm 链接树。

`deps:check` 只读检查，不安装、不修补。根脚本 `test:py` 也通过同一套虚拟环境选择器运行，兼容 Windows 的 `.venv/Scripts/python.exe` 和 Unix 的 `.venv/bin/python`。

验收隔离环境可设置 `UV_PROJECT_ENVIRONMENT`（相对 `packages/agent` 或绝对路径）；未设置时默认使用 `packages/agent/.venv`。

## 依赖调整

### JavaScript/Bun

- 临时分支把 `@opentui/core@0.4.3`、`@opentui/react@0.4.3`、Windows x64 optional 包 `@opentui/core-win32-x64@0.4.3`、`bun-ffi-structs@0.2.4` 和 `react-devtools-core@7.0.1` 放入 `third_party/npm/` workspace；Core 的其他 optional 平台包和 `diff@9.0.0`、`marked@17.0.1`、`string-width@7.2.0`、`strip-ansi@7.1.2` 仍按内网 lock 解析。
- `react-devtools-core@7.0.1` 通过 vendored package.json 固定 `ws@7.5.10`；根不再使用 `patchedDependencies`。安装门禁核对这两项，不再校验目录哈希。
- `lucide-react` 降至 `1.16.0`；`@happy-dom/global-registrator` 固定为 `20.0.11`；`@types/react-dom` 固定为 `19.2.3`。
- CLI 显式固定 `@types/node@26.1.1`；registrator 自身的 `@types/node@^20` 保留为隔离传递解析，避免旧类型包控制工作区类型检查。
- `@playwright/test`、`playwright`、`playwright-core` 统一为 `1.59.1`；本阶段不下载浏览器运行文件，不执行 Web E2E。
- 根 `overrides` 将 `fast-uri` 固定为 `3.1.7`。
- OpenTUI/happy-dom 继续保留 `ws@8.21.1`，两个主版本不合并；五包 workspace 门禁只禁止目标包回退 registry，不扩大源码化范围。

### Python/DeepAgents

`packages/agent/pyproject.toml` 的 `[tool.uv]` 使用 `exclude-dependencies` 排除三个禁止包，并用 `constraint-dependencies` 锁定内网报告确认的兼容版本。没有把这些传递依赖提升为项目直接依赖，也没有启用 `langsmith` 或 `openai` 的 Anthropic/`httpx2` extra。

`uv.lock` 顶部 `manifest.excludes` 只记录解析时的排除规则，不是 `[[package]]` 依赖节点；`uv tree --locked`、安装后的 distribution 清单和 `deps:check` 都只检查实际解析/安装结果。

官方 DeepAgents 0.7.3 wheel 本身仍声明 `langchain-anthropic`，因此安装后执行受控补丁：

- `graph.py` 删除 `ChatAnthropic` 导入；默认模型入口明确要求调用方传入模型，不自动选择 Claude；
- `middleware/_prompt_caching.py` 删除 Anthropic prompt-cache middleware，保留其他供应商逻辑；
- `middleware/memory.py` 删除 Anthropic 类型判断和 provider-specific cache-control 分支，保留记忆提示词注入；
- 同步清理 `METADATA` 的 Anthropic `Requires-Dist`，更新修改文件的 `RECORD` 哈希/大小，并写入补丁标识。

补丁只接受 `deepagents==0.7.3` 官方 wheel 的已知目标文件哈希（wheel SHA-256：`fc48690259a457ddffa7da0397e575c872386f2a96e4a7a7858ee10fa842756f`），并逐项核对安装器生成的 `RECORD` 哈希/大小。重复执行会重新验证已修补哈希；版本错误、源码漂移、部分修补、伪造 `RECORD` 或不完整安装都会返回非零，不会吞掉导入错误或伪造 Anthropic 模块。

## 验收顺序

在全新、无旧 `.venv` 和 `node_modules` 的内网工作副本中执行：

```text
npm run deps:sync
npm run deps:check
npm run deps:test
npm run typecheck
npm run build
npm run project:check
npm run test
```

企业外可以直接用公网源完成依赖同步。企业内如果锁文件仍是公网下载地址，冻结同步会失败，需要先 `--update-lock`。macOS、Windows、Linux 的空缓存安装、证书/凭据注入、native 加载和最终全量测试仍需分别在目标环境验收。若只运行 `uv sync` 而未执行补丁，不能视为安装完成；若 `deps:check` 发现任一禁止包、锁节点或 Anthropic import，必须停止并修复解析或制品问题。
