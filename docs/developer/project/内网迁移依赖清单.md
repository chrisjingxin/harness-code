# 内网迁移依赖清单

## 结论

本清单是交给内网模型查询的输入，不是“内网已可安装”的结论。当前快照包含：

- 3 项工具链要求：Bun `1.3.13`、Python `>=3.11,<4.0`、未固定版本的 `uv`；
- 17 个 JavaScript/TypeScript 直接外部依赖，`bun.lock` 中共 98 条外部解析记录、96 个唯一包名；
- 18 个 Python 直接外部依赖，其中 17 个进入 `uv.lock`，构建隔离依赖 `hatchling==1.27.0` 未进入锁文件；
- `uv.lock` 中 92 个外部包，下载源全部指向 `https://mirrors.aliyun.com/pypi/simple/`；
- 8 个 OpenTUI 平台原生 npm 包和 17 个无通用 wheel 的 Python 包，需要按实际内网目标平台检查制品，而不能只检查包名或版本元数据。

目标 OS、CPU、libc 和 Python 小版本尚未由本仓库规定。因此，只有内网模型返回目标环境矩阵及对应制品后，才能判断迁移是否可行。

## 内网回填判定

内网模型应对每条解析记录返回以下状态之一：

- `exact_available`：精确版本存在；若是原生包，还必须有目标平台制品；
- `metadata_only`：能查到版本元数据，但目标制品或下载权限尚未验证；
- `source_build_required`：只有源码包，需额外构建链；
- `alternative_only`：精确版本不存在，只找到其他版本；不能自动视为兼容；
- `not_found`：查询成功但未找到包或版本；
- `not_applicable`：经目标矩阵确认不适用，例如非 Windows 环境的 `pywin32`；
- `query_error`：超时、无权限、仓库异常或查询方法不可用；不能与 `not_found` 合并。

只有所有适用的直接依赖与锁定传递依赖都是 `exact_available`，工具链可取得，构建隔离依赖已满足，原生制品覆盖目标矩阵，且锁文件能从内网源重新生成并离线安装，才能给出“依赖迁移通过”的结论。
