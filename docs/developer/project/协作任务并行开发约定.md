## 5. HC-195/196 首轮交界审查

2026-11-07，两份首轮Spec已回调，统筹读完双方草案，以下作为修订方向；不是生产实现或双方Spec已通过的记录。修订后仍需复核，当前不派发Plan/Todo。具体字段的唯一来源分别留在HC-195的execution/conversation和HC-196的device规格，本文只记录裁定，不维护第三套DTO。

1. **受理与首次调用之间保留一次运行决定。** Runner先持久受理，Java在保存首次受理事实的同一短事务中复核原发起人、共享版本和取消，持久保存allow/deny；Runner保存allow后才可首次调用。决定直接归HC-195的执行记录，不新增权限服务或独立许可表。决定消息的稳定ID复用其平台头messageId，不再增加等价的permissionId字段；一经提交，重传原决定，不因重连重造。已获allow的在途工作不因随后停止共享自动变成从未执行；本地已确认停止共享且尚未调用的项仍拒绝启动，已运行结果可继续补传。取消先于allow则拒绝首次调用，晚于allow则独立请求真实取消，不能改写原决定。拒绝决定不冒称Runner已经停止；终态按可核实事实收敛。新许可要查当前授权，已获准工作的结果补传只核对原设备/命令归属，不因发起人后来停用或项目停止共享丢弃既有结果。
2. **执行载荷唯一归HC-195。** 采用execution.start/cancel及具名accepted、native.bound、running、output、terminal、cancel.received消息；决定消息为execution.start.decision。共同头加闭合payload，commandId是命令头messageId，来源事件ID是Runner事件头messageId；不再并列receiptId/eventId或另一套execute正文。执行来源统一runnerSequence，受理/绑定/运行/输出/取消确认/终态均在同一executionId内连续编号；确认统一executionId与lastCommittedRunnerSequence，只确认已提交连续前缀。重复必须核对原完整内层正文，缺号不能放行终态。设备外壳只加连接归属，重连只更换外壳，不改变内层ID、发生时间、正文和指纹。
3. **保留现有公共业务端口分工。** HC-196提供SharedProjectAccess.requireSharedTarget和DeviceDelivery.sendStart/sendCancel；HC-195提供ExecutionDispatch.onDeviceAvailable、ExecutionReceipts.recordBatch与ExecutionRecovery.reconcile，并在受理保存事务内生成运行决定。HC-195是唯一队列选择/状态推进方，HC-196只唤醒、传输和核对；网络不进入JDBC事务。双方修订时补全实际请求/结果/错误和决定重传，不能仅改方法名而留下两种收敛流程。
4. **原生会话保持一份标识。** 云端保存不透明nativeSessionId关联，Runner保存同一值及本地进程归属，不再增加nativeBindingId代理引用。首次命令可以为null；Runner在首次创建/恢复后先持久native.bound并有序补传，后续原目标/绑定必须一致。当前命令仍保留首次固定正文，不因首次绑定产生而改写其null字段或指纹；后续命令使用已确认的原生标识。UI不读取或解释它，恢复失败不能静默创建替代会话。
5. **单活动Java使用一个当前连接标识。** 使用服务生成的connectionId及已认证deviceId，Java内存核对当前socket/connectionId，Runner同样核对当前socket。旧帧和旧close不能影响新连接；Java重启全部重新核对。首版不持久递增connectionVersion，也不增加serverInstanceId三元组或集群连接协议；持久ledgerId仍用于识别同一本机账本，不能与连接ID混用。
