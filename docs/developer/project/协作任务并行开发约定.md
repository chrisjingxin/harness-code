## 5. HC-195/196 首轮交界审查

2026-11-07，两份首轮Spec已回调，统筹读完双方草案，以下作为修订方向；不是生产实现或双方Spec已通过的记录。修订后仍需复核，当前不派发Plan/Todo。具体字段的唯一来源分别留在HC-195的execution/conversation和HC-196的device规格，本文只记录裁定，不维护第三套DTO。

1. **受理与首次调用之间保留一次运行决定。** Runner先持久受理，Java在保存首次受理事实的同一短事务中复核原发起人、共享版本和取消，持久保存allow/deny；Runner保存allow后才可首次调用。决定直接归HC-195的执行记录，不新增权限服务或独立许可表。决定消息的稳定ID复用其平台头messageId，不再增加等价的permissionId字段；一经提交，重传原决定，不因重连重造。已获allow的在途工作不因随后停止共享自动变成从未执行；本地已确认停止共享且尚未调用的项仍拒绝启动，已运行结果可继续补传。取消先于allow则拒绝首次调用，晚于allow则独立请求真实取消，不能改写原决定。拒绝决定不冒称Runner已经停止；终态按可核实事实收敛。新许可要查当前授权，已获准工作的结果补传只核对原设备/命令归属，不因发起人后来停用或项目停止共享丢弃既有结果。
2. **执行载荷唯一归HC-195。** 采用execution.start/cancel及具名accepted、native.bound、running、output、terminal、cancel.received消息；决定消息为execution.start.decision。共同头加闭合payload，commandId是命令头messageId，来源事件ID是Runner事件头messageId；不再并列receiptId/eventId或另一套execute正文。执行来源统一runnerSequence，受理/绑定/运行/输出/取消确认/终态均在同一executionId内连续编号；确认统一executionId与lastCommittedRunnerSequence，只确认已提交连续前缀。重复必须核对原完整内层正文，缺号不能放行终态。设备外壳只加连接归属，重连只更换外壳，不改变内层ID、发生时间、正文和指纹。
3. **保留现有公共业务端口分工。** HC-196提供SharedProjectAccess.requireSharedTarget和DeviceDelivery.sendStart/sendCancel；HC-195提供ExecutionDispatch.onDeviceAvailable、ExecutionReceipts.recordBatch与ExecutionRecovery.reconcile，并在受理保存事务内生成运行决定。HC-195是唯一队列选择/状态推进方，HC-196只唤醒、传输和核对；网络不进入JDBC事务。双方修订时补全实际请求/结果/错误和决定重传，不能仅改方法名而留下两种收敛流程。
4. **原生会话保持一份标识。** 云端保存不透明nativeSessionId关联，Runner保存同一值及本地进程归属，不再增加nativeBindingId代理引用。首次命令可以为null；Runner在首次创建/恢复后先持久native.bound并有序补传，后续原目标/绑定必须一致。当前命令仍保留首次固定正文，不因首次绑定产生而改写其null字段或指纹；后续命令使用已确认的原生标识。UI不读取或解释它，恢复失败不能静默创建替代会话。
5. **单活动Java使用一个当前连接标识。** 使用服务生成的connectionId及已认证deviceId，Java内存核对当前socket/connectionId，Runner同样核对当前socket。旧帧和旧close不能影响新连接；Java重启全部重新核对。首版不持久递增connectionVersion，也不增加serverInstanceId三元组或集群连接协议；持久ledgerId仍用于识别同一本机账本，不能与连接ID混用。
6. **限额和字段名同步收敛。** 当前用户text继续32KiB UTF-8、最多16,384字符，HTTP正文64KiB；本轮固定实际执行文本使用同一上限，不提前承诺未来引用后的256KiB。HC-198/197接入时共同扩展。执行命令沿用initiatedByUserId、input:{text}、shareVersion及固定目标；取消使用requestedByUserId。指纹包含固定内层头与完整payload、排除指纹字段自身和连接外壳，双方用同一确定性序列化及字节夹具；不得静默截断/规范化文本或另写inputText/actor别名。
7. **离线与权限失效分开。** 共享关系及固定目标仍有效时，原设备暂时离线不阻止创建会话或保存queued输入；ready只控制实际派发。新保存、派发及首次运行决定按相同授权→项目→会话→执行锁顺序核对；既有事实/结果的记录不能被误当成新的执行授权。明确停止共享后云端共同历史仍可读，新的实时项目操作不可用。
8. **规格须能直接实现且保持最小范围。** HC-196补齐登记/列表/共享/撤销响应和welcome/resume/status/ready等控制帧的完整字段、分页/核对结束条件；执行事件只引用HC-195唯一源，未来工具/审批/文件Git形状由各主责扩展，不填任意payload或默认成功。HC-195明确SSE下HttpSession真实失效/活动规则及关闭清理，避免新增第二份身份活动状态或宣称未经证明的容器行为。HC-196将实际托管运行时的node:sqlite可用性与单实例锁放入后续Plan最早技术验证停点，不以standalone Node文档代替Electron宿主证明。

SQL版本号、根契约聚合、安全装配、唯一根锁仍由统筹在Plan/实施派发时顺序协调。两对话此轮只修改各自Spec/Task，检查文档并回调；公共审查记录和看板由统筹维护，未启动产品服务或运行产品测试。

## 6. HC-195/196 修订稿复核与计划输入

2026-11-08，统筹已对照两份修订稿的执行消息、一次运行决定、设备控制/恢复、公共端口及本地持久规则，主要交界方向通过。两任务先将下述补充写回各自Spec，再按Spec→Plan→Todo顺序编写各自实施计划；这是后续文档阶段派发，不是生产实现授权，不再为这些已裁定细节单独停一轮Spec。

- **取消先到采用HC-195的唯一序列特例。** 原start尚未到达但原cancel有效时，Runner同一事务保存禁启记录及连续的cancel.received和notInvoked cancelled终态；不生成accepted或运行决定，也不等待重新传来start才报告确切未调用。来源字段从cancel中已固定的目标/startCommandId/startBodySha256取得。恢复清单的cancelBeforeStart记录须携带本地来源前缀/确认位置及真实终态，能够补传；迟到start只作正文/摘要一致性核对，不生成第二份accepted/终态或首次调用。Java只在确有原持久cancel时接受这一特例。HC-196删除“必须等start后才产生取消来源”的旧措辞，避免已取消而授权不再允许重发start时永久卡住队首。
- **本地预检失败必须能闭合。** 合法来源、完整start形状和已登记目标归属一致、且可以落盘时，accepted只证明收到并持久记录，不承诺目录/能力预检已经通过；取得原运行决定后，尚未invoking的本地拒绝按明确终态收敛。PROJECT_ROOT_CHANGED和CAPABILITY_UNAVAILABLE加入HC-195的ExecutionReasonCode及rejected原因闭合集合，HC-196引用同一字段，不能临时映射成成功、failed或任意错误正文。ID/正文/目标冲突走协议冲突，不伪造accepted/终态；账本写失败不发成功记录。目录忙仍是受理后等待，占用/取消规则不变。
- **线上时间复用现有唯一类型。** occurredAt、createdAt等公开时间使用HC-194的UtcTimestamp（UTC、三位毫秒、Z结尾的字符串）；数据库可存epoch毫秒，不能把“毫秒精度”误实现成新的线上数字时间。顺序/版本仍用受限十进制字符串，确定性指纹按实际同源字段编码。
- **计划中的依赖是最小停点。** HC-195先安排execution/conversation契约与具名端口，HC-196先安排实际Electron托管node:sqlite/单实例锁技术验证；两者可并行。HC-196设备/项目元数据和SharedProjectAccess最小实现就绪后，HC-195的真实目标保存/派发才接通；WSS/Runner回执联调依赖HC-195对应事务端口，不等待对方整个Task结束。每个Plan标明具体共享文件、接入时机、必要真实观察和不能由替身代替的部分，避免生产默认注入mock或不可编译的半套装配。
- **SQL迁移顺序预留。** V002归HC-196设备/项目/设备请求三表，V003归HC-195会话/消息/执行/事件/请求/来源回执六表；本阶段只在计划中使用该分配，不创建迁移。共享基础授权提取、HTTP安全聚合、资源登记与根锁由统筹按实施停点顺序派发。实际数据库/端口和工具进程由统筹在开始冒烟时隔离安排，不允许两边并发启停HC-194实例。
