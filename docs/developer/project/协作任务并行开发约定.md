# 协作任务并行开发约定

2026-11-06，用户要求复用现有中央对话和右侧文件/变更 UI，新增协作区域另写，并让任务可以上传到云端后由同事独立认领。本文是 [HC-192](../task/HC-192-协作工作台与会话交接.md) 的任务分工约束，不增加产品内的任务分配系统。本轮只更新设计和任务，不上传云端、不新建分支或改变其他人的工作。

## 1. 先固定交界，再同时开发

接口前置表示双方已经审查同一份 Spec，知道输入、输出、错误和取消语义；实现前置表示需要的最小代码停点已经合入；集成前置表示真实上下游已可运行。三者不能混为“等上游整个任务完成”。

各任务先写自己的 Spec，由统筹组织接口双方审查，再写 Plan/Todo。接口有共同夹具后，各自可以使用测试端口开发；替身只进入开发预览或冒烟，不进入生产默认入口。尚未固定的接口不能凭本表直接编造实现。真实联调前置未满足时保持待验收，不声称端到端完成。

| 交界 | 先要共同确认什么 | 主责与消费者 |
| --- | --- | --- |
| UI 公共基础 | 主题变量、Markdown/代码/图标出口、通用视图类型及扩展槽 | HC-205；HC-206/207/208/201 消费 |
| 身份基础 | 用户/工作区、错误、会话隔离和 CollaborationHost | HC-194；后续云端任务和 HC-202 消费 |
| 会话与执行 | 消息/事件标识、顺序、执行状态、受理/取消/回执以及事务入口 | HC-195 负责会话/排队，HC-196 负责设备通道，HC-197 负责 ACP 映射，三方共同审查 |
| 项目操作 | 原设备/项目定位、文件/预览/Git 结果、占用与拒绝原因 | HC-199 负责业务端口，HC-196 负责派发，HC-207 负责视图，HC-202 负责装配 |
| 交接与引用 | pending/accepted/cancelled、固定引用、发送事务及来源定位 | HC-198；与 HC-195 共同确认事务接入，HC-206/208/202 消费 |
| Agent 扩展 | 可选视图/配置注册、stderr 归属和能力声明 | HC-197/200/201 与 HC-205 共同审查；通用包不导入 Harness 类型 |

接口文件的唯一主责人负责修订；影响消费者时同时更新同源夹具和变更说明，由相关负责人确认后合入。不能各写一份类型、任意 payload 或临时兼容分支来避开协调。

## 4. 上传云端后的认领与集成

每份 Task 是可移植的任务单，必须同时带上关联设计、接口前置、实现/集成前置、负责目录、禁止交叉修改范围、验收步骤和未验证项，链接全部相对仓库。任务 ID 在云端/分支/提交保持一致，不依赖本机路径、某个聊天的隐藏上下文或 coop 下载目录。

云端平台选型和实际上传另按用户后续指令，本轮不预设服务或创建远端事项。文档仍是工程范围与证据的事实源；认领信息由指定统筹回写 owner/branch/status，避免云端和仓库分别产生互相冲突的状态。当前工具只维护既有 front matter 字段，依赖/并行信息放 Task 正文，不加会被认领脚本丢弃的自定义字段。

同事认领后使用约定集成基线和自己的任务分支；提交应列出接口、依赖、必要冒烟及实际限制。合入前由统筹确认无跨任务改写、公共契约一致，再顺序集成共享文件。当前本机可见实施聊天仍沿用 harness_lody 既有工作树，文件有重叠时先暂停其中一方，不擅自新建 worktree/分支。

每任务只做必要构建/类型/边界和真实冒烟，阶段通过标待验收；完整单元/集成、双平台与真实目标环境测试统一 HC-204。没有服务器、内网 SDK 或真实 Agent 的证据按实际缺口记录，不能用占位页面、替身或普通 MySQL 冒充验收。回调替代轮询，不调用 Skill，不自动提交/推送。
