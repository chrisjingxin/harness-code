# HC-246 全局待办收件箱与IM轻通知

## 当前阶段

2026-11-23 结合企业级多团队协作演进需求拆解立项。待认领，认领后按 Spec → Plan → Todo 推进。

## 要解决的问题

- 随着团队、Project 增多以及知识审核（HC-241）、系统地图审核（HC-243）、技能审核（HC-245）引入，需要真人拍板和处理的事项散落在各个 Project 和页面里，员工很难知道“现在到底有哪些事在等我”。
- 当成员处于其他 Project 或最小化了桌面客户端时，纯靠桌面端内红点无法及时触达，而一旦把全量聊天过程灌进企业 IM 群又会造成严重刷屏与数据外泄隐患。

## 预期使用过程

```text
产生待办：他人指派 Task / 提交待验收结果 / 成员提议知识或地图待审 / 本机 Agent 卡在审批等待 / 收到他人批注或 @提醒
  → 聚合进桌面左栏顶部“待办收件箱（Inbox）”，按“待审批/阻塞 → 待我审核/验收 → 指派给我 → 提醒与批注”排序并显示角标
  → 服务端按用户订阅偏好向已接入的企业 IM（企微/飞书/钉钉）推送轻量摘要卡片（含标题、发起人、项目名与 deep-link）
  → 员工在 IM 点链接唤起桌面端或在 Inbox 内点击条目 → 直达对应审批/审核/任务详情页 → 处理完成后条目消退
```

## 已确认的范围

1. **跨 Project / 跨团队统一收件箱**：位于桌面左栏顶部，把“需要我动作的事项”与普通会话浏览彻底分开；区分“待处理 / 已超期 / 已解决”筛选。
2. **覆盖本机与云端两类卡点**：不仅聚合云端 Task、验收、知识/地图/技能审核、只读会话批注与被 @，也置顶提示当前设备正在等待人工确认（`waiting_approval`）或运行报错的本机会话，避免切走页面后遗忘。
3. **不抢焦点、不越权**：收件箱基于现有轻量通知机制（`HC-220`）增量刷新，不打断用户当前输入焦点与滚动位置；点击直达页面但不自动触发 Agent 执行。
4. **企业 IM 轻通知安全出口**：服务端支持企业微信、飞书、钉钉等通道的可插拔 webhook / 应用消息适配器，默认只发送事件类型、标题、发起人、所属 Project 和唤醒桌面端的 deep-link，**严禁携带对话正文、代码片段或敏感内容**。

## 不在本卡范围

- 把企业 IM 改造成双向执行控制台（不支持在飞书/企微群里直接发指令遥控他人或本机 Agent 写代码）。
- 复杂的跨平台日程/工时/绩效考核系统。

## 职责与前置

- 服务端（由后端同事维护）负责跨 Project 待办聚合查询接口、企业 IM 通道配置与消息投递适配器、已处理状态同步；缺口按分工交同事，前端不私自新增后端 API。
- 桌面端负责左栏 Inbox 入口与列表页、本机待审批状态合并、deep-link 协议注册与页面精准跳转、用户通知降噪偏好设置。
- 依赖 [HC-220](HC-220-项目看板与轻量通知.md) 的轻量通知基础链路与 [HC-239](HC-239-个人优先使用本机Agent.md) 的双轨桌面外壳。

## 待定问题（Spec 阶段确定）

1. 桌面端 `workbench://` 自定义协议在 macOS 与 Windows 上聚焦已有实例并跳转到具体资源的详细路由格式。
2. 企业 IM 轻通知的免打扰与合并频次默认策略（例如同项目 1 分钟内连续变更合并推送）。
3. Inbox 已处理记录默认保留天数与清空方式。
