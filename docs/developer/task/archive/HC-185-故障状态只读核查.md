# HC-185 故障状态只读核查

用户反馈“你看下测试进程是否属于当前会话”也触发 FUSION_OUTCOME_UNKNOWN，并且界面同时说没有活动任务。沿用已授权的故障修复和测试。

实际记录显示 Sidekick 显式 cd /，误把虚拟文件根当作系统根，之后 find / 全盘搜索在 120 秒超时；未确认停止的操作保留在旧任务中。这是操作停止凭据缺失，不是已经发现某个测试进程占用。当前只读进程检查未发现匹配的测试/全盘搜索进程，但缺少原始 PID，不能据此自动认定所有副作用已停。

## 单一停点 A

结果不明/因目录占用等待时，新的用户消息启动 Lead 只读核查，允许读文件和 fusion_status，直接回答，不再要求派单或报告；不能修改文件、执行 Shell、派单、验收、恢复或结束任务。普通修改仍需原有停止确认。无当前任务时，状态也显示实际目录占用者，并可使用当前会话 resolve。Shell 目录含义明确，错误根目录命令在登记副作用前拒绝。

设计见 [Spec](../../spec/HC-185-故障状态只读核查.md)，顺序见 [Plan](../../plan/HC-185-故障状态只读核查.md)，清单见 [Todo](../../todo/HC-185-故障状态只读核查.md)。保留 HC-184 既有修改，不自动改用户任务数据库或停止系统进程。


## 实施结果

- Host 按状态选择只读核查，不把普通检查问题当作恢复写入。读取当前任务或占用任务的状态、文件后，可以直接回答；不会要求先补报告或新派单。
- 核查使用独立的能力视图与运行标记；工具注册及 Service 均拒绝修改控制。原任务的停止事实、归属和 Worker checkpoint 在成功、取消、受理失败和 Host 关闭时保持原样。
- 模型误选未提供的写工具时，连续三次同类失败后带说明结束，不再无限重复请求模型。
- 状态响应增加必需的可空 workspace_blocker，规范所有测试响应并同步生成物；无任务和只有终态历史任务时仍显示实际目录写者。身份无法定位或属于其他项目时，不提示无法执行的当前对话取消。
- Lead 与 Sidekick 提示包含实际命令目录；显式 cd /、find / 和嵌套 Shell 变体在登记副作用前拒绝。没有改写真实用户数据库，也没有结束系统进程。

## 代码审查

仓库指定的 `agent-skills:code-review-and-quality` 当前不可用，按停点 A 手工复核差异，没有声称调用过该技能。检查了准备/受理/取消/关闭的归属清理、实际工具与 Service 边界、未知状态的普通执行保护、配置漂移下的只读/写入区别、异步 Thread/Task/占用者身份、跨项目隐藏、协议生成物和虚拟路径解析。

结论：本停点无阻塞项。普通写入权限及明确停止确认规则保留；核查期间不会自动恢复旧 Worker 或提升权限。旧记录缺少 PID 时仍不能证明真实进程已停止，这是停止证据边界，不能通过清空数据库处理。用户重启 CLI 和 Python Host 后，可在原对话重新发送检查问题。
