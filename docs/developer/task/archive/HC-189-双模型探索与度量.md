把“是否省钱”和“如何协作”变成可观察的能力：模型调用 → 记录角色消耗 → Sidekick 只读探索或实施 → Lead 核实和验收 → 状态展示已知用量及失败提醒。

## 验证与审核

测试只用临时数据库、假模型与测试密钥；不操作用户旧任务或真实配置。不提交 Git commit，保留 dev_wdl 供用户检查。

### 实现与逐项结论

- A：Lead/Sidekick 输入、输出、缓存、完整性、可选同币种价格和假设差额。保留每次模型调用的已知计数，失败观测先于输出回滚；同事件重复提交不重复累计。图未调用模型就结束时不虚增调用；故障只读核查不修改旧任务。
- B：fusion_explore 使用独立只读图和临时 checkpoint，过程同页显示。查询不增加实施轮次，不改变票据；Guard 和 Service 阻止执行、写入、报告和再次委派。真实审批、取消、异常清理都有 Host 回归。
- C/I：提示词改为委派策略，操作步骤放工具及状态；可信追加进入指纹。保留角色可见和 Lead 核实路径；按实际设置/明确价格提示，拒绝按 default 别名猜模型。
- E1：相邻两轮重复失败提前建议换策略；同一轮重复查询不计数，同轮重检变好后清除过期提醒。不改变上限或授予权限。
- G：检查与审阅移入 FusionAcceptance；Sidekick 资源和收尾移入 FusionWorkerRunner；新增用量、价格、提示和策略独立模块。Store 的事务顺序保留。架构历史移入单独记录，连续两次真实摘要后仍能读取当前任务单和 r1/r2。
- 容量边界：池容量为 2 时，“探索→实施→探索→返工”可能淘汰旧图的规格缓存；借用前从冻结 Spec 重新登记，避免返工报 RUNTIME_RESOLVED_AGENT_SPEC_MISSING。探索资源暂满时返回 FUSION_EXPLORATION_BUSY 及读取/等待建议，不使整个 Run 因资源不足失败。
- D、E2、F、H 未照搬，原因、当前替代路径和证据范围见审查表。没有声称实测商业模型降本比例，也没有发保活请求。

### 审核

手工逐项对照 Task、Spec、原文 A–I 及补充的 FUSION_SPEC(1).md，检查了原始权限求交、工具双层限制、真实审批、取消和 Pool 清理、同任务 checkpoint、快照/检查/票据和终态。未给 Lead 增加写权限，未把探索摘要当验收，没有新增旧 API alias 或平行 Run 通道。

价格在 ModelProfile 外围配置中解析，不传给模型客户端；API Key、Header、URL 与追加正文不进入任务状态统计。任务原始数据仍私有，协议仅给固定计量与建议字段。金额仅为已观测 token 按配置的三类单价估算，缺数据为未知；不覆盖所有服务商账单项目。
