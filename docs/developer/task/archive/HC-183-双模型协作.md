## 用户得到什么

Lead 负责判断、派单和审阅；Sidekick 负责执行和返工。Host 保存任务、核对改动、运行检查并约束写权限。完整目标与安全边界见 [设计](../../architecture/fusion-dual-model-workflow-design.md)。

## 验收与阶段边界

- A：配置可加载、覆盖、校验；`config show` 能展示脱敏的模型组合和检查摘要；提供后续 Run 可直接使用的冻结绑定解析器。
- B：选择 Fusion 后实际启动双模型；Lead 只读，Sidekick 保留用户原有权限；普通 Build 不受影响。
- C：任务单和持续 Sidekick 可用；返工沿用同一逻辑会话，执行 ID 分轮记录。
- D：Host 检查和 Lead 审阅闭环可用；旧证据、越界改动和结果不明不能通过。
- E：状态查询、恢复、取消与共享界面接入完成；异常恢复及普通执行回归通过。

### 实现结果

- `FusionService` 使用持久化任务单和当前文件决定状态；模型最终文字不能绕过完成门禁。
- 一个任务固定一个 Worker checkpoint，各轮使用独立 execution ID。缺失、不一致和未完整结束的历史会停止返工。
- 工作区写者与任务单/派发原子登记，文件提交检查授权代号；完成/取消与写者释放原子提交。
- 普通 Build、Compose、Direct Shell、撤销/重做受同一写者保护。直出 Shell 在进程停止前持有 Host 写锁。
- Host 复用 `runtime/verification.py` 执行检查；原 Compose 调用迁移，旧实现删除。审批后重查动态权限、目录、候选文件和写者。
- 保存报告时记录文件摘要；显式继续可续发未派发消息、单独运行检查、复用已有回执和恢复票据。结果不明绝不自动重放。
- 子执行通过 canonical child approval 路径处理真实审批，传递执行 ID、父取消信号、用量及每轮索引租约。
- v3.11 生成物与两端更新；旧 minor 连接不接收整个 Fusion Run 流。共享 Feature/Gateway/reducer 用实际模型记录和中文状态显示结果。
