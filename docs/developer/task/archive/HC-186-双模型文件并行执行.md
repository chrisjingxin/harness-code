# 双模型文件并行执行

用户已确认：放宽整目录单写者限制，采用文件范围并行、冲突自动排队、命令期间临时协调、保留版本检查的方案。沿用已有测试授权，在当前 dev_wdl 分支实施。

## 用户可以看到什么

- 会话 A 改 a.py，会话 B 改 b.py，两者可以同时派单和执行。
- 两者都改 a.py，后发任务显示等待的文件和会话；前一任务释放后自动继续，无需切换会话或再次输入“继续”。
- 命令执行时其他写操作临时等待，命令确认结束后自动继续。已知停止的取消或失败自动收尾。
- 查看、提问和模型分析继续可用。结果不明只保护尚未确认的范围；不能凭等待时长自动判定命令已停。

## 唯一交付停点 A

文件范围、命令协调、验收版本三者必须配套，单独放开其中一项会产生并发误写或错误验收，因此作为一个可演示工作包交付。验收包括跨 Host、真实 SQLite、取消、重启、过期授权、协议及界面提示。

设计见 [Spec](../../spec/HC-186-双模型文件并行执行.md)，实施见 [Plan](../../plan/HC-186-双模型文件并行执行.md)，执行见 [Todo](../../todo/HC-186-双模型文件并行执行.md)。仓库列出的 agent-skills / mattpocock 工作流 Skill 当前不可用，使用可用的 requirements-analysis-design Skill、手工 TDD 和逐项审核。

## 数据迁移边界

为保留现有用户数据，只做一次原子迁移：旧目录租约改为文件预留记录；旧结果不明的命令保留整目录保护。删除旧表，运行时只使用新结构。升级应重启相关 Host。开发与测试只操作临时数据库，不改用户正在使用的任务记录。


## 实现与审核记录

- 文件范围：真实路径规范化、文件/目录前缀冲突、整组申请、交叉扩范围和取消均有回归。不同范围同时持有授权，重叠范围由 Host 等待，不让模型重复派单。
- 写入口：原生文件契约、图工具与内联子执行、普通 Shell、Compose 检查、历史撤销/重做共用实际操作队列；审批在排队前完成，跨进程许可先于本地工具锁。
- 授权：保留 revision/generation、角色与原文件版本复查；写前拒绝明确记为未开始，取消未启动派发保留 prepared。
- 命令与退出：未知文件仅保护实际范围，未知命令保护目录；Host 消失不等于子命令停止。纯读取快照不留下永久写保护；普通未知操作有当前对话的精确核查入口。
- 验收：任务快照只计算允许范围，扩大范围保留原基线；整组检查绑定源码摘要及检查轮，源码变化重新检查并签发新票据，最终版本检查与完成受同一屏障保护。
- 数据：真实临时旧库覆盖备份、迁移、范围投影、未知命令保留和备份失败不迁移。只保留一次安全数据迁移，运行时不双写、不保留旧租约 API 路径。
- 进程与界面：两个真实 Python 进程同时预留不同文件；两个独立 Host 的原生 Sidekick 图同时写文件、检查并审阅。TUI/Web 通过同一 Selector 展示资源等待和独立角色过程。
