# 模型故障原因提示

用户指出错误只显示 Provider rejected the model request，无法判断怎么处理。实际故障是本地代理已接受密钥、上游 cn-cli 账号返回 401；现有界面隐藏了这种区别。

唯一停点 A：所有模型运行路径展示中文原因和下一步，保持原错误码、重试及已公开输出保护。见 [Spec](../../spec/HC-188-模型故障原因提示.md)、[Plan](../../plan/HC-188-模型故障原因提示.md)、[Todo](../../todo/HC-188-模型故障原因提示.md)。沿用已有测试授权。仓库列出的 agent-skills / mattpocock 技能当前不可用，使用手工 TDD 和逐项审核。

## 审核与验证

### 实现和审核

- 一个 provider_failure_message 函数共用于执行器、Goal 提案和流式中断；Compose 转发已处理的安全原因，原有阶段错误码继续保留。
- 401 区分已确认的上游登录失效、已确认的密钥被拒绝与尚未确定来源的鉴权失败。权限、地址/模型、参数、上下文、限流、5xx、超时及连接问题各给下一步。
- 只输出固定中文文案、HTTP 状态和有限站点枚举。畸形 body、HTML、未知账号名、密钥、URL 与 Header 不回显；没有根据原始字符串中的 401 就猜登录失效。
- 对照 Spec 审核：没有修改重试分类、取消、错误码、retryable、审批、数据库或协议；已公开输出仍不自动重放。普通模式、Lead 和 Sidekick 的原生 Host 终态及 CLI 共享时间线都有回归。
- 延续 dev_wdl 和上一轮已存在的 HC-187 改动，只修改本次登记文件；未提交、回滚用户改动或修改用户模型配置。
