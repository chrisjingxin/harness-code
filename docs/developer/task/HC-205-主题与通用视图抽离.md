- 从旧 Web 迁出浅/深公共主题、品牌 `Command`、Agent `Sparkles` 和用户 `MessageCircle` 头像、公共按钮与纯格式化函数；提供 `@workbench/ui/theme.css`、`@workbench/ui/native-theme` 和根组件出口。旧 Web 源码和设计稿保留，HC-193 临时基础样式仅限定作用域，尚未迁成新主题。

## 需求与交付

先把已经打磨好的界面公共基础迁入独立 UI 包，后续对话、文件/变更和新导航能分开开发。此任务以原代码为起点保留视觉与行为；当前 HC-193 的基础窗口只是工程停点，不能作为最终 UI 的替代设计。

## 范围与目标归属

- 来源：packages/cli/src/web/presentation/theme.css、brand-logo.tsx、markdown.tsx、code-block.tsx、code/、web/syntax/ 以及所需的 presentation-shared 纯函数/语言目录。
- 目标：packages/workbench-ui 的 theme、common、rendering 及对应资源/必要开发预览。保留已有品牌、头像/SVG 资源与单一颜色变量入口，拆出真正通用的格式化/图标。
- 公共渲染、语法高亮 worker 的打包/资源定位和所需依赖随同迁出；不要求 Bun、旧 Web server 或旧 Controller。
- 先在 Spec 固定公共出口、CSS 作用范围和通用扩展槽；区域专属视图模型由 HC-206/207/208 各自负责。Harness 专有投影留 HC-201。

## 依赖、并行与负责边界

实现前置为 HC-193 已可运行的基础工程，可与 HC-194 云端基础同时推进，不需要服务器/数据库/ACP。HC-206/207/208 的 Spec 可同时讨论，实际公共渲染复用以本任务最小出口合入为代码前置。

本任务只负责公共资源，不迁出整个 Timeline/Composer、Dock 或左侧导航。旧 styles.css 中公共与区域样式的切分清单先登记，区域规则分别交 HC-206/207/208，不能把整份全局 CSS 复制到三个目录。根 manifest/lock、UI 总导出等共享改动交统筹顺序集成，不与其他任务同时编辑。

## 验收结果

- [ ] 新 UI 公共模块可独立构建/预览，不 import packages/cli、旧 protocol、Harness 内部类型、Node/Electron 主进程。
- [ ] 冷紫浅/深主题、语义状态色、头像/用户 SVG 和品牌资源沿用现有实现，换品牌变量不会要求改每个组件。
- [ ] Markdown、代码块/高亮/复制等公共行为可用，worker/语言资源随新包正确打包，不依赖旧目录或开发机路径。
- [ ] 只有一套主题/reset/公共渲染实现；HC-193 临时基础样式与迁入样式有明确收敛方案，区域样式不互相覆盖。
- [ ] 公共出口与最小夹具可供三个 UI 任务消费；普通工具显示与 Harness 专有投影不混在通用模块。
- [ ] 必要类型/边界/真实 Electron 公共组件冒烟通过，记录实际主题/缩放/窗口尺寸与未覆盖平台。
