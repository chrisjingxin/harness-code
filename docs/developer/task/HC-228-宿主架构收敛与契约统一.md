# 宿主架构收敛与契约统一

## 背景与痛点

1. 早期 `HC-195` / `HC-196` 预留的独立 `Runner` 运行时、桌面 `RunnerSupervisor`、已失效的 `executionSchema` 加载，以及未挂载的演示/设备注册 UI 骨架长期滞留仓库，增加构建面并干扰后续模块边界判断。
2. 桌面主进程 `local-directory-host.ts` 曾自行维护一套 800 余行的目录列表、`@` 候选检索、文件预览与 Git 状态/Diff 实现，与 `@workbench/project-service` 大量重复；同时 `project-service` 仍保留了按顶层设计已暂缓的跨端 Git 写入代码。
3. 桌面宿主接口（`OrganizationHost`、`CollaborationAppsHost`、`ProjectUpdatesHost`、`PersonalHost`）散落在 `apps/desktop/src/` 顶层，且个人状态类型耦合了渲染层实现细节。
4. 桌面多组 IPC 处理器重复编写可信来源校验与错误包装，`CollaborationState` 存在大量单行工作区透传方法，协作应用 IPC 注册存在不安全函数类型断言。

## 解决思路与实施范围

### 1. 下线遗留 Runner 与未挂载 UI 骨架

- 删除 `packages/runner-core`、`apps/runner` 与 `apps/desktop/src/main/runner-supervisor.ts`，同步清理主进程入口、窗口创建与协作 IPC 中的 `RunnerSupervisor` 引用。
- 下线未挂载的 `packages/workbench-ui` 演示工作台与设备注册面板及其导出，清理渲染样式中不再使用的 `.device-*` 规则，保留 `.identity-*` 登录/成员样式。
- 移除 `apps/desktop/src/main/collaboration-client.ts` 中未使用的 `executionSchema` 加载，保持 `packages/workbench-contracts` 既有 schema 与夹具完整。

### 2. 复用 `@workbench/project-service` 并收敛只读边界

- 删除已暂缓的 Git 写模块与 `commit` / `push` 导出，保持跨端 Git 只读边界。
- 补充只读工程服务能力：非 Git 目录与 Git 子目录平稳返回空状态而不报错、限定作用域的 `@` 候选检索与忽略目录过滤、未跟踪文件 Diff、超大文本摘要兜底、Windows/Unix 统一拒绝反斜杠与空字节路径、符号链接逃逸拦截及根目录失效检测。
- 将 `apps/desktop/src/main/local-directory-host.ts` 改写为围绕 `createProjectService` 的薄适配器，保留原有调用签名、错误语义与符号链接拒绝码，并通过新增 `packages/project-service/tests/project-service.test.ts` 与原有 `apps/desktop/tests/local-directory-host.test.ts` 双重验证。

### 3. 统一宿主契约到 `@workbench/contracts`

- 在 `packages/workbench-contracts/src/` 新增 `desktop-hosts.ts` 与纯数据化的 `personal.ts` 并通过包入口导出，解除个人持久化类型对 `@workbench/ui` 的直接耦合。
- 删除重复的顶层 `organization-host.ts`、`collaboration-apps-host.ts`、`project-updates-host.ts`，保留 `apps/desktop/src/personal-host.ts` 作为类型转发垫片以保证既有会话模块零改动兼容。
- 更新主进程、预加载与渲染层各对应模块及预览入口从 `@workbench/contracts` 导入。

### 4. 统一 IPC 守卫与状态访问封装

- 新增 `apps/desktop/src/main/ipc-guard.ts` 与单测 `apps/desktop/tests/ipc-guard.test.ts`，统一可信渲染帧检查（复用 `verifyDesktopSource`）、精确参数个数校验、UUID/用户 ID/非空字符串/普通对象校验及统一错误封装，接入 `desktop-ipc.ts`、`collaboration-ipc.ts`、`organization-ipc.ts`、`project-updates-ipc.ts`。
- 在 `apps/desktop/src/main/collaboration-state.ts` 中新增类型安全的 `withWorkspace<T>` 包装，收敛 12 个工作区单行透传方法，保留 `personalIdentity`、`identityError`、`getProjectConversation` 与 `applicationWorkspace` 公共入口并补充 `apps/desktop/tests/collaboration-state.test.ts`。
- 在 `collaboration-ipc.ts` 与 `organization-ipc.ts` 中用显式运行时类型守卫与泛型句柄 `handleApp<K extends keyof CollaborationAppsHost>` 替代不安全类型断言。
