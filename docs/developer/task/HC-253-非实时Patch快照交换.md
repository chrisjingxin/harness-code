# HC-253 非实时Patch快照交换

## 当前阶段

2026-11-23 结合跨人代码协作高杠杆体验需求拆解立项。待认领，认领后按 Spec → Plan → Todo 推进。

## 要解决的问题

- 按既有顶层设计，平台严禁跨机器读取他人实时文件目录且暂缓产品内直接 Git Push，但团队成员在联调、帮忙修 Bug 或交接 WIP（未达到提交 PR 标准的草稿修改）时，经常需要把“我本机刚刚试通的几处改动”直接发给队友。
- 目前只能把大量代码片段手动贴进聊天框，既超过消息预算、丢失上下文行号，也容易因未脱敏或无法一键应用而反复手工复制。

## 预期使用过程

```text
生成与发布：
  输入：成员 A 在本机会话或提交 Task 交付物时，点击“附带本机变更 Patch”
  执行：
    1. 展示当前绑定 Git 仓库的工作区变更文件列表，由 A 勾选文件与基线范围
    2. 本机生成标准 unified diff / git patch，校验大小上限并调用 HC-249 脱敏扫描规则检查明文密钥
    3. 上传为只读 Patch 快照（关联对应团队仓库标识与基线 commit），不暴露 A 本机真实绝对路径
  输出：共享会话或 Task 交付物中出现只读 Patch 卡片

预览与本机应用：
  输入：成员 B 打开只读卡片
  执行：
    1. 直接使用既有 Diff 渲染组件彩色预览全部修改，不要求 A 的电脑在线
    2. B 点击“应用到我本机仓库”，桌面端通过 personal.md 匹配对应本地仓库（或请 B 选定目录）
    3. 先执行安全 git apply --check 预检；无冲突且经 B 确认后写入 B 本机工作区；若冲突则阻断并提示差异位置
```

## 已确认的范围

1. **严守非实时与权限红线**：Patch 是一次主动打包上传的**静态只读快照**，生成后即独立存在，不建立跨机器实时文件通道，不触发远端机器执行，也不绕过 Git 托管平台的分支合并权限。
2. **前置脱敏与安全防护**：上传前必经 `HC-249` 敏感信息扫描；应用到接收方本机时严格校验路径合法性（严禁 `..` 路径穿越、严禁修改 `.git/` 目录或符号链接逃逸），且强制先 `dry-run` 预检再由接收方明确确认落地。
3. **复用既有 UI 与附件存储**：预览端复用 `desktop/src/ui/project/git-diff.tsx` 既有 Diff 渲染能力，存储传输复用 `HC-247` 的 Project 共享附件通道。

## 不在本卡范围

- 跨多仓库自动创建合并远端 PR/MR 或直接执行 `git push`。
- 非 Git 普通文件夹的二进制大文件全量同步。

## 职责与前置

- 服务端主要复用 [HC-247](HC-247-任务交付物共享附件与验收.md) 的共享产物存储与鉴权，不单独建设一套重型代码托管服务；如需增加 Patch 元数据字段则由后端同事承接。
- 桌面端负责在本机安全生成标准 Git Patch（剥离隐私路径）、接入 [HC-249](HC-249-共享出口脱敏与组织审计日志.md) 扫描、Diff 预览展示以及在接收方本机的安全校验与应用（`git apply --check` / `git apply`）。

## 待定问题（Spec 阶段确定）

1. Patch 文件大小上限（例如默认 1 MiB 或 5 MiB）及包含二进制文件变更时的拒绝/提示策略。
2. 接收方当前本机工作区已存在未提交修改时，是默认拒绝并建议先暂存，还是提供新建临时分支选项。
