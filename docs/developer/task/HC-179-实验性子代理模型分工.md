## 通俗说明

主模型每次读取源码，工具返回的内容都会进入它的上下文。单次读取的行数限制能控制一次返回多少，但不能阻止多次阅读逐渐累积。主模型还可能承担本可独立交给其他模型完成的明确工作。

本功能让用户主动开启一种实验分工：主模型负责明确问题、关键判断和验收，指定子代理负责调查或有明确要求的实现。原始文件与调查过程留在子代理上下文，主模型接收有证据的短结果，并在需要时精准查证。

```text
用户开启实验功能并指定角色模型
  → 主模型明确任务、范围和交付要求
  → 子代理使用指定模型阅读或执行
  → 返回结论、证据或变更摘要、验证结果与未解决问题
  → 主模型按疑点查证并继续完成用户任务
```

例如，调查登录状态的保存和恢复时，fast 可以阅读多个相关文件，返回调用链与关键位置；pro 再检查少量关键代码，不必例行重复整个调查。`pro`、`fast` 都只是用户已有的模型 Profile 名称，不是固定供应商或能力保证。

## 用户最终得到什么

1. 不启用时，现有模型选择、工具、子代理与交互行为保持不变。
2. 显式启用后，可以让只读 `explore` 使用指定模型；还可选择让 `general-purpose` 使用指定模型完成明确的小型执行任务。
3. 主模型接收助手的最终文本结果，不自动接收助手阅读的全部原文和中间工具消息；需要查证或编辑时仍可直接阅读。
4. 能查明每次主、子执行实际使用的模型、状态、用量与耗时，不把父模型用量误认为整个任务开销。
5. 实验能力可通过配置关闭；不承诺固定的成本、速度或正确率提升。

## 已确认决策

### 默认关闭，按角色指定模型

- 未配置或显式关闭时，不启用实验角色绑定，也不注入实验委派规则。
- 使用现有模型 Profile，不建立另一套供应商、密钥或模型档位配置。
- 主模型继续由用户当前模型选择决定，不因开启功能自动切换为 pro。
- `explore` 与 `general-purpose` 分别可选绑定；未指定的角色沿用现有选择方式。
- Plugin Agent 已显式指定的模型不被实验角色配置覆盖。
- 开启后引用不存在的 Profile 必须明确报错；模型不可用或执行失败不能悄悄替换模型。
- 配置字段、来源优先级及生效生命周期由 Spec 按现有配置契约明确，本 Task 不将对话中的示例字段宣称为已支持接口。

### 阅读隔离与执行分工属于同一功能

- 首个可演示结果为 `explore` 独立模型的只读探索；后续在同一 Task 内交付可选的 `general-purpose` 模型绑定，不拆成多套过程文档。
- 主模型在委派前明确问题、范围、限制与交付要求，不先完整阅读资料再重复交给助手。
- 子代理只接收必要的任务上下文，不为本功能新增父完整对话的自动复制。必要规则和权限仍沿现有受控机制传递。
- 只读助手返回结论、文件与符号位置、必要短引文、未覆盖范围和疑点；执行助手返回变更摘要、文件列表、验证结果和未解决问题。
- 主模型按疑点、关键风险和编辑需要查证，不要求每次接手都重新调查所有文件。最终判断与验收仍由主模型负责。

### 保留真实读取与权限语义

- `read_file` 继续返回原文，不透明替换成摘要；摘要、引文和助手声称的行号不能代替编辑者自己取得的有效 Snapshot 与已读范围。
- 只读探索沿用只读能力边界，不新增写入、任意 Shell、外部网络工具或递归委派权限。模型请求仍按所选 Profile 发往其配置的服务。
- 通用执行助手继续遵守现有审批、工作区权限、Plan 约束、Snapshot 修改及并发保护；切换模型不扩大权限。
- 子代理中间过程可沿现有子代理事件链展示给用户，但不能因此自动写回父模型上下文。
- 首版由主模型决定是否委派。确定性保证是已委派任务的上下文隔离，不保证所有大批阅读都被强制转交。

### 明确失败并记录完整开销

- 实验和普通子代理共用现有最终文本返回与通用大工具结果处理机制，不新增实验专用 JSON、固定正文长度上限或格式校验错误。通过提示词要求结论简洁、提供证据、说明未解决问题；不强制固定字段或段落。
- 运行时负责记录执行成功、失败、取消等事实；任务是否全部完成由助手正文说明和主模型验收判断，不新增机器解析的 partial 交付状态。沿用已有大结果外存、缩短内容和提示，不将其等同于完整任务验收。
- 子代理失败向主模型返回明确状态，由主模型决定直接继续或向用户报告；不新增隐藏重试、自动升级或递归委派链。沿用现有模型请求重试政策不属于新增编排重试。
- 用户取消后，不再为该任务启动新的替代子执行。执行助手部分修改后失败，必须保留并报告已发生的变更，不能假定没有副作用。
- 按真实模型调用记录主、子执行用量，区分模型和缓存；失败调用有用量时也计入。无法取得的指标标记未知，不记作零。
- 汇总区分父自身与任务合计，避免丢失子执行用量或重复统计。不依据未配置的单价推算货币节省。

## 实现约束与相邻工作

复用现有 `task`、AgentCatalog、ModelProfile、权限和生命周期机制。独立模型执行优先复用现有 Managed 路径；同一角色在一次运行中只解析一份实际模型绑定、使用一条执行路径。具体构图与接口由 Spec 明确，不通过修改角色摘要冒充实际模型切换。

配置入口是拟新增的 Host TOML `[experimental.delegation]`，必须登记为 ConfigManifest 已实现区段；它与 Plugin 清单里的 `experimental` 不是同一份配置，也不是 `[models.roles]` 的第二入口。绑定后的内建角色改走 Managed 时，必须保持该角色现有能力：`explore` 仍是五只读工具；`general-purpose` 仍继承父 MCP/Skill 与现有审批例外，不能被做成 Plugin Agent。

已有基础与缺口见 [研究记录](../research/179-模型路由委派评估.md)。其中历史验证路线 A–E 与“先测收益再扩大”的继续门槛已被本 Task 的“直接作为实验功能推进、不做真实模型评测”决策替代，历史研究不构成本任务的验收要求。

与 [HC-161](HC-161-内置子代理可用化.md) 的内建角色能力、[HC-169](archive/HC-169-隔离子代理超时.md) 的超时生命周期衔接，不重建子代理 UI 或另一套超时系统。HC-161 仍为进行中，但生产路径已有两个内建角色；本功能只加实验性模型绑定，不重做可用化。HC-169 为待验收，超时隔离已落地，本功能沿用其 `DELEGATION_TIMEOUT` 语义。配置和 Agent 行为归 Python agent，跨进程公开载荷如有变化归 protocol，用户展示归 cli。

## 可观察验收

1. **关闭不变**：缺省配置与显式关闭均不启用实验规则或模型绑定；既有内建和 Plugin 子代理路径通过回归验证。
2. **真实绑定**：开启并指定 `explore` 后，模拟模型请求和执行记录证明该子执行使用指定 Profile，主模型仍使用用户所选 Profile；未指定角色和显式绑定的 Plugin 不受覆盖。
3. **可选执行助手**：只配置 `explore` 不改变 `general-purpose`；额外绑定后，通用执行助手使用指定 Profile 完成有明确验收的小型变更，并返回变更与验证摘要。
4. **原文隔离**：在子代理工具结果放入可识别的测试原文，父模型后续输入仅包含现有返回链处理后的最终结果，不含未选择返回的原文及完整子消息历史；用户事件展示不突破此约束。
5. **可定向查证**：主模型可根据助手的证据位置直接读取相关区段；摘要不会授予主模型修改 Snapshot，也不阻断合法精准读取。
6. **权限一致**：只读助手不能写入或再委派；执行助手仍受父权限、审批、Plan 与文件契约限制，不能因换模型绕过限制。
7. **失败可辨识**：不存在的 Profile、模型调用失败、取消与超时有明确运行状态；助手通过正文说明未完成部分，由主模型判断，不把正常结束当作任务全部完成；不因 JSON、段落或字段格式拒绝有效文本，不会静默换模型或把部分修改当作无副作用重跑。
8. **总账完整**：主、子执行的模型、耗时及可获取的输入/输出/缓存用量可核对；任务合计不漏子执行、不重复计算，未知值不显示为零。具体查询或展示入口由 Spec 明确。
9. **正常工程验证**：使用 mock 模型或 mock 服务覆盖上述行为，不调用真实凭据；涉及协议、生命周期时验证 Python 与 TypeScript 两端。相关测试及仓库要求的项目检查通过。
10. **文档与关闭方式**：用户配置示例明确默认关闭、角色绑定、如何关闭、失败行为与收益不保证；功能交付时更新相关长期架构文档。本 Task 完成前按规范记录 review、验证和版本影响并归档。
