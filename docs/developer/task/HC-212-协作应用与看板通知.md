# HC-212 协作应用与看板通知

## 现状痛点与解决思路

### 1. 现状痛点

- 成员只能看到会话消息流，无法把"哪一段值得看"沉淀下来——需要**会话快照**（方案 §4.4，替代旧交接）。
- "请乙改某仓库模块"靠聊天喊话，无法追踪与验收——需要**任务卡片**（§4.5，D8 一对一、仅发起者可撤销）。
- "这个字段叫什么、为什么"没有团队级术语规则库——需要**知识条目**（§4.7，D6 初版只做显式引用）。
- 各域动作（简报更新、快照、任务流转、知识变更）产生的事件没有统一出口，看板与通知无处取数——需要**看板聚合 + 用户级通知流**（§4.6）。

### 2. 核心解决思路

四个能力共用同一套前提（项目成员制 + 已同步会话数据），按依赖停点串行：**快照 → 任务 → 知识 → 看板与通知**（通知流最后接通各域事件）。事件一律"对象 ID + 摘要"轻量载荷，正文走 TDSQL/ES；业务事务按用户相关性保存通知，Kafka `wb.collab.notifications` 唤醒集群节点，SSE 按发件箱游标补读。

## 关键流程（输入 → 判断 → 执行 → 输出）

### 任务卡片流转

```text
成员 POST transitions（targetStatus + expectedVersion/requestId）
  → 校验：项目成员且项目 active；迁移边合法且角色匹配（todo→doing 仅受让人、
          doing→review 仅受让人、review→done|todo 和未结束任务撤回仅发起人）
  → 执行：按版本写 wb_task 及 wb_task_transition 审计；关联会话时只登记双向关系
  → 输出：任务详情；版本不符返回 409；重复 requestId 返回原响应
```

### 通知投递

```text
域服务产轻量事件 → 同事务按相关性写 wb_notification_outbox
  → 提交后唤醒在线流，集群借 Kafka wb.collab.notifications 跨节点唤醒
  → SSE 或分页校验当前资格，按已处理游标之后的事件补读
  → 桌面收到对象标识后主动拉取所需详情
```

## 停点划分（实施顺序）

1. **会话快照**：`wb_snapshot`（≤64KB、超限写 `storage_uri`+`sha256`）+ 生成/读取路由；范围=截至序号或指定消息区间。
2. **任务卡片**：`wb_task`/`wb_task_transition`/`wb_task_link` + 创建/详情/流转/关联会话路由 + 状态机。
3. **知识条目**：`wb_knowledge_item`/`wb_knowledge_version` + CRUD/归档/版本列表 + ES `wb_knowledge_v1`（术语键建议查询）。
4. **看板与通知**：`GET .../projects/{p}/board`（人×会话×任务聚合）+ `wb_notification_outbox` + `GET /notifications/stream`（用户级 SSE）+ `GET /notifications` 分页 + 各域事件接入 Kafka 主题 + 设备在线展示。

## 验收标准（可观察结果）

- [ ] 项目成员可生成快照并查看；非成员 404；快照不可变，超限正文落对象存储且 hash 一致；引用解析返回快照卡片。
- [ ] 任务创建/详情/流转符合角色限定；非法迁移 409、版本冲突 409、重复 requestId 幂等；`task_transitions` 审计完整；关联本人会话后保持原运行状态，受让人在本机主动开始。
- [ ] 知识条目按分类管理、术语键团队唯一；版本不可变且可回看；ES 可按分类/术语检索；归档后不可再引用。
- [ ] 看板聚合返回各成员活跃会话简报与待办任务；通知 SSE 只向相关用户推轻量事件，断线重放不重复；设备在线状态由心跳键驱动展示。
- [ ] `mvn test` 全绿（各域授权/状态机/幂等/快照超限/outbox 去重用例）；`server:contracts`、`project:check` 通过；隔离库端到端冒烟。

### 停点四补验 SSE 注销与连接结束（2026-11-17）

- HC-220 联调发现，Spring 异步收尾在注销清除登录态后再次经过鉴权，原流最终被 Tomcat 记为 500。现在只允许已通过用户和团队校验、同一 URI 且已产生异步结果的 SSE 请求继续收尾。连接写入失败时由 Servlet 容器通知 Spring 完成响应。
- 用 JDK 21、Tomcat 11.0.21、MySQL 8.4.11 隔离库复现并对照。流已连接时从独立请求注销，再由另一成员发布知识事件。原流正常 EOF，访问日志由 500 变为 200，注销后原流未收到新事件，Java 未出现鉴权异常。旧 Cookie 和匿名新流均为 401，未加入该 Workspace 的新流为 403。重新登录，以 `Last-Event-ID` 补读注销期间的持久事件成功。
- 主动断开已收到 HTTP 200 的流后，Tomcat 11.0.21 仍将连接终止记为 `500 X`，Java 应用日志无异常。访问日志格式中的 `%X` 表示连接结束状态，`X` 表明客户端在响应结束前断开。可用该字段与正常结束的 `200 +` 对照。[Tomcat 访问日志字段](https://tomcat.apache.org/tomcat-11.0-doc/config/valve.html#Access_Log_Valve)
- `npm run server:build` 通过，构建内 87 个 Java 测试通过。整卡保持待验收。
