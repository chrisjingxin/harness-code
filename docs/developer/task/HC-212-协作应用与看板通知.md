# HC-212 协作应用与看板通知

## 现状痛点与解决思路

### 1. 现状痛点

- 成员只能看到会话消息流，无法把"哪一段值得看"沉淀下来——需要**会话快照**（方案 §4.4，替代旧交接）。
- "请乙改某仓库模块"靠聊天喊话，无法追踪与验收——需要**任务卡片**（§4.5，D8 一对一、仅发起者可撤销）。
- "这个字段叫什么、为什么"没有团队级术语规则库——需要**知识条目**（§4.7，D6 初版只做显式引用）。
- 各域动作（简报更新、快照、任务流转、知识变更）产生的事件没有统一出口，看板与通知无处取数——需要**看板聚合 + 用户级通知流**（§4.6）。

### 2. 核心解决思路

四个能力共用同一套前提（项目成员制 + 已同步会话数据），按依赖停点串行：**快照 → 任务 → 知识 → 看板与通知**（通知流最后接通各域事件）。事件一律"对象 ID + 摘要"轻量载荷，正文走 TDSQL/ES；Kafka `wb.collab.notifications` 消费后按用户相关性过滤推 SSE，替代旧会话级推送。

## 关键流程（输入 → 判断 → 执行 → 输出）

### 任务卡片流转

```text
成员 POST transitions（targetStatus + expectedVersion/requestId）
  → 校验：项目成员且项目 active；迁移边合法且角色匹配（todo→doing 仅受让人、
          doing→review 仅执行者、review→done|todo 仅验收者、任意→cancelled 仅发起者）
  → 执行：CAS 更新 wb_task；append wb_task_transition 审计；
          若关联会话 idle 且受让人是本机 owner → 置 waiting_approval
  → 输出：任务详情；版本不符 409 重复处理；重复 requestId 幂等返回
```

### 通知投递

```text
域服务产事件（对象 ID + 摘要）→ Kafka wb.collab.notifications
  → 消费：按用户相关性过滤（项目成员 ∩ 非操作者本人）
  → 执行：写 wb_notification_outbox（event_id 唯一去重）→ SSE 推在线用户
  → 输出：轻量事件，桌面端按需回源拉详情；离线后重连按 outbox 补发不重不漏
```

## 停点划分（实施顺序）

1. **会话快照**：`wb_snapshot`（≤64KB、超限写 `storage_uri`+`sha256`）+ 生成/读取路由；范围=截至序号或指定消息区间。
2. **任务卡片**：`wb_task`/`wb_task_transition`/`wb_task_link` + 创建/详情/流转/关联会话路由 + 状态机。
3. **知识条目**：`wb_knowledge_item`/`wb_knowledge_version` + CRUD/归档/版本列表 + ES `wb_knowledge_v1`（术语键建议查询）。
4. **看板与通知**：`GET .../projects/{p}/board`（人×会话×任务聚合）+ `wb_notification_outbox` + `GET /notifications/stream`（用户级 SSE）+ `GET /notifications` 分页 + 各域事件接入 Kafka 主题 + 设备在线展示。

## 验收标准（可观察结果）

- [ ] 项目成员可生成快照并查看；非成员 404；快照不可变，超限正文落对象存储且 hash 一致；引用解析返回快照卡片。
- [ ] 任务创建/详情/流转符合角色限定；非法迁移 409、版本冲突 409、重复 requestId 幂等；`task_transitions` 审计完整；关联会话执行权正确翻转。
- [ ] 知识条目按分类管理、术语键团队唯一；版本不可变且可回看；ES 可按分类/术语检索；归档后不可再引用。
- [ ] 看板聚合返回各成员活跃会话简报与待办任务；通知 SSE 只向相关用户推轻量事件，断线重放不重复；设备在线状态由心跳键驱动展示。
- [ ] `mvn test` 全绿（各域授权/状态机/幂等/快照超限/outbox 去重用例）；`server:contracts`、`project:check` 通过；隔离库端到端冒烟。
