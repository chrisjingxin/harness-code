# HC-219 引用任务与团队知识

## 要解决的问题

成员需要借用同 Project 的讨论结论，或者明确把工作分派给另一位成员。阅读和引用不能变成远程操作，发布任务也不能直接让对方 Agent 写代码。

本卡是客户端 UI 和接口消费卡；Project 内的产品任务与本文件这样的 HC 工程任务不同。当前待认领，只登记范围，认领后按同名 Spec → Plan → Todo 推进。

## 本卡负责

- 在现有输入区扩展 @菜单，分组选择会话、成员、任务和团队知识；保留已有本机文件提及。会话/任务只查询当前 Project 可读范围，知识来自当前团队。
- 主动选择来源后获取引用预览，显示来源、版本、时间、范围和实际材料。使用 HC-212 返回的不可变快照/版本；来源变化不替换草稿，刷新由用户明确触发，发送与历史展示沿用同一份材料。
- @成员进入明确的任务发布表单，填写被指派人、说明和上下文，确认后才发布；不在输入普通提及时隐式发送任务，更不向对方 Agent 派发命令。
- 提供 Project 任务列表、详情及接口实际允许的流转/关联动作。接收或认领不自动开始执行，另设“在本机开始”，选择本人本机会话或新会话、用户选择的目录，再交给已交付宿主动作。
- 任务状态词、允许动作和版本冲突按 HC-212 正式返回展示；不在前端新增“已接收”等后端不存在的持久状态。若独立接收动作尚无对应接口，登记缺口给同事，不以本地假状态绕过。
- 提供团队知识列表、正文、版本及允许的编辑/历史入口；通过显式 @知识引用固定版本，不默认注入整个知识库，不自建搜索或分类后端。
- 通过现有 ConversationView 引用卡片和扩展槽装配，读取和预览不自动提交输入。资料或任务后续变更不改写已发送材料。

## 建议停点

| 停点 | 用户能看到什么 | 真实接线前置 |
| --- | --- | --- |
| 1. 表单与入口 | @分组、引用预览、任务列表/详情、知识阅读的独立界面 | 与 HC-217/218 确认页面和输入扩展接点；可先独立预览 |
| 2. 会话引用 | 主动取材、预览、固定引用并带入已有输入 | HC-212 快照交付及 HC-218 本机会话输入接点 |
| 3. 产品任务 | 发布、查看、按接口接收，再明确在本机开始 | HC-212 任务停点及同事交付的本机公开宿主能力 |
| 4. 团队知识 | 按权限阅读/编辑、查看版本、显式引用 | HC-212 知识停点；不等待看板/通知全部完成 |

## 目录归属与并行

- 建议独立模块：`apps/desktop/src/renderer/features/collaboration/`，内部按 references、tasks、knowledge 分开；只在本区维护页面和展示适配。
- 快照/任务/知识请求的 desktop 客户端消费由本卡主责，公共 main/preload/输入动作接点经 HC-217/218 串行集成；不改 Java、线上契约、Runner 或 ACP。
- 本卡可与导航、会话和看板并行设计/开发界面；真实请求按 HC-212 各停点逐步接入，不把整卡完成当作所有 UI 开工前置。
- HC-220 只聚合和定位任务，本卡唯一负责产品任务表单/详情；会话下载与个人阅读状态仍由 HC-218 主责，不重复实现正文同步。

## 验收标准

- [ ] @会话/任务/知识展示实际固定材料；来源更新不会自动替换所选快照，发送与历史展示一致。
- [ ] @成员必须明确确认发布任务；查看、引用、接收和通知均不会操作对方 Agent 或自动执行本机请求。
- [ ] 接收后用户可独立选择本人本机会话或新会话及工作目录，主动开始；缺少宿主入口时如实不可用。
- [ ] 列表/详情使用接口的权限、版本和状态，失败保留输入；没有在前端伪造接收状态或新增任务状态机。
- [ ] 团队知识可按已交付接口阅读、编辑和回看版本，显式引用后固定版本，不自动注入无关知识。
- [ ] 复用现有输入、引用卡片、主题和弹窗样式，与中央对话和项目页面视觉一致。

## 必要验证与非范围

实施时做受影响构建/类型/边界检查，按交付停点冒烟各自一条正常路径：固定引用进入草稿；明确发布任务并由本人主动开始；知识按版本引用。合并时沿用未受影响证据，不逐项穷举弹窗细节，完整组合及双平台留 HC-204。

服务端快照存储、任务状态机、通知、知识检索和 ACP 由同事负责。预览数据不进入正式入口，也不代表真实任务已发送或 Agent 已接通。旧 HC-198 历史保持已过时，服务端工作沿用 HC-212，不重新开交接后端卡。
