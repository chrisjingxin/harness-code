# HC-245 团队技能与MCP配置分发

## 当前阶段

2026-11-23 结合企业级多团队协作演进需求拆解立项。待认领，认领后按 Spec → Plan → Todo 推进。

## 要解决的问题

- 当前团队已有“文档型”知识（规约、经验、术语），但企业研发日常高度依赖“可执行型”资产——如团队代码审查 Skill、单测规范 Skill、内网日志/监控/工单系统的 MCP Server。
- 新人入职或换电脑时，仍需要手工拷贝配置、逐个排查环境变量，一旦有成员写出存在危险命令或携带明文密钥的 Skill，直接分发会在全团队扩散。

## 预期使用过程

```text
提议与上架：
  输入：开发者打包上传 Skill 包或填写受控 MCP 配置提议
  判断：执行结构校验 + 静态安全扫描（路径穿越、危险指令、外发风险、明文密钥）
  执行：命中高危阻断并列明原因；通过后进入“待审核”列表，由 Workspace 管理员审核发布

订阅与生效：
  输入：同团队成员在“团队资产中心”浏览已发布 Skills 与 MCP 目录并点击“订阅启用”
  执行：桌面端拉取/物化已审核 Skill 到本机隔离目录，并将已启用的团队 MCP 随既有 ACP 会话配置透传给本机 Agent
  输出：下一轮对话中 Agent 直接使用团队工具与技能；管理员更新或下架后成员同步刷新
```

## 已确认的范围

1. **个人与团队资产分层清晰**：本机原有的个人自定义 Skill / MCP 保持本地私有不受影响；团队资产归属 Workspace，支持版本化与按适用的团队仓库标签筛选。
2. **提议 → 安全扫描 → 管理员审核**：任何成员可提议，但未审核条目对其他人不可见；结构校验（如必须含规范 `SKILL.md`、禁止 `..` 与符号链接）与静态安全扫描不通过则阻断提交或强制人工高危确认。
3. **本机主动订阅与隔离物化**：成员在自己桌面自主勾选需要启用的团队 Skill 与 MCP（或采纳团队推荐默认集），不未经同意强行覆盖成员本机个人配置；通过 `HC-234` 已交付的通用 ACP 会话 MCP 透传通道注入当前会话。
4. **生命周期更新与下架**：团队资产发布新版本或被管理员停用/下架时，通过轻量通知提示成员更新；已下架条目在后续新轮次停止自动透传。

## 不在本卡范围

- 纯文档形态的团队规约、经验、术语：HC-241。
- 面向外部公网无鉴权任意抓取第三方未审核插件市场自动安装。
- 在云端容器内替员工托管运行本机 MCP 进程（本机类工具仍在用户本机或通过企业既有内网网关访问）。

## 职责与前置

- 服务端（由后端同事维护）负责团队 Skill 包与受控 MCP 目录的存储、版本、安全扫描门禁与审核流接口；缺口按分工交同事，桌面端不私自新增后端 API。
- 桌面端负责资产中心界面、上传预检、审核差异展示、本机 Skill 缓存目录物化以及向既有 `LocalAcpSessionSetup` 装配启用的 MCP/Skill。
- 依赖 [HC-234](HC-234-桌面通用能力上移与ACP收口.md) 的通用 ACP MCP 透传能力与 [HC-240](HC-240-Workspace角色管理.md) 的管理员角色。

## 待定问题（Spec 阶段确定）

1. 团队 MCP 若需要员工个人内网鉴权（如个人 Git/工单 OAuth 或本机环境变量占位符），本机如何安全填写绑定且不上传云端。
2. Skill 包静态扫描规则集的维护位置（桌面预检 + 服务端强制复核）。
3. 成员启用某团队资产后，生效粒度是“按团队全局默认启用”还是支持“按单个会话覆盖”。
