# HC-180 代码索引闭环

## 需求来源与当前阶段

2026-09-15，用户要求评估并集成企业包源可用的 CodeGraph `1.1.6`，让 Harness 在大型仓库中更少地依赖反复 grep/read，并将建图、自动同步、模型探索和失败回退做成一个闭环。需求已按 `grilling` 方法用三轮对话确认；一手源码结论见 [180-CodeGraph集成评估.md](../research/180-CodeGraph集成评估.md)。

当前已完成并确认 Spec，Plan / Todo 已生成并等待用户检视；Task 仍未认领，未修改产品代码，也未安装依赖或建立新索引。后续实现只能执行已确认清单，不得改用其他版本、默认开启或重新暴露供应商名称。

## 通俗说明

Harness 现在要理解一个代码区域，通常需要多次搜索、打开文件、追踪调用方。对大仓库来说，这会增加工具次数、上下文和等待时间。

本功能增加一个默认关闭的“实验性代码索引”。用户先在配置中开启，再在当前项目执行 `/code-index`。Harness 建立本地图形索引，以后的对话优先通过一个代码库探索工具定位符号、文件和调用路径。索引没找到、暂时不可用或语言未覆盖时，Agent 继续使用原有搜索和读取，不会因实验功能中断工作。

```text
用户在配置中开启实验代码索引
  → 重启 Harness / AgentHost
  → 执行 /code-index
  → 首次建立或增量更新 .harness-index
  → 健康后启动查询与自动同步
  → 下一次 Run 取得 codebase_explore
  → 未命中时回退现有搜索与读取
```

所有索引数据都留在当前机器。正常产品界面使用“代码索引”和 `codebase_explore` 这组 Harness 概念，不显示底层组件名称。依赖清单、开发者调研和许可证仍保留真实来源；这是产品抽象，不是把本地依赖当作安全秘密。

## 用户最终得到什么

1. 一个默认不产生任何副作用的实验功能：未开启时不起进程、不扫工作区、不建目录、不注入工具。
2. 在现有 TOML 的实验区段开启后，TUI 和 Web 都能用 `/code-index` 管理同一工作区索引。
3. `/code-index` 默认在无索引时首建、有索引时增量同步；`status` / `rebuild` / `cancel` / `remove` 分别用于查看、全量重建、取消和删除。
4. 健康索引在 Host 重启后自动恢复查询和 watcher；watcher 不可用时明确降级为手动增量更新，不安装 Git hooks。
5. 后续模型 Run 优先使用 `codebase_explore` 一次定位相关代码；它不可用或不足时，原有搜索、读取和子代理能力照常工作。
6. 索引的阶段、数量、完成统计、失败、取消、未完成和重试方式均可见；不伪造上游未提供的整体百分比。
7. 索引数据位于 `.harness-index/`，不生成 `.codegraph/`，不污染 Git 状态，也不让底层组件拥有 `.harness/` 的删除权。

## 已确认决策

### 1. 默认关闭的实验功能

- 复用已有 `[experimental.*]` TOML 配置体系；本功能的配置归入 `[experimental.code_index]`，`enabled` 默认为 `false`。
- 配置缺失、显式 `false` 或解析失败都不能开启索引；不启动上游子进程，不读取包版本，不创建 `.harness-index`，不在模型能力中注入索引工具。
- 关闭时 Slash 菜单不推荐 `/code-index`；用户手工输入时给出开启路径，不把命令发给模型，也不自动改配置。
- 配置修改后沿用现有实验配置语义：重启 AgentHost 后生效，不做运行中热切换。
- 用户可随时改回 `enabled = false`。下次 Host 启动后不启动查询与 watcher，但不自动删除已有索引；数据删除必须由开启后的 `/code-index remove` 明确确认。

### 2. 供应商无关的产品表面

- 上游数据目录只接受工作区根下的单路径段，不支持 `.harness/index`；不为改名引入上游 fork、运行时 patch、symlink/junction 或双目录。
- 唯一数据目录为 `<workspace>/.harness-index/`。Harness 在初始化前写入供应商无关的目录内 `.gitignore`，并在 Git 工作区使用本地 exclude 保持状态干净；不修改项目根 `.gitignore`，不安装 Git hooks。
- 命令为 `/code-index`，界面名称为“代码索引”，不显示“实验性”字样或徽标；模型可见工具为 `codebase_explore`，受管 MCP 服务使用 Harness 内部身份；不向用户透传上游进度文案或原始 stderr。
- 用户文档和正常产品界面不出现供应商名称。开发者调研、依赖声明、许可证及必要诊断仍保留真实来源，不声称该依赖无法被本地用户识别。

### 3. CodeGraph 1.1.6 作为唯一运行基线

- 主包与当前平台包必须都是 `1.1.6`；版本不同、缺包、包布局不对或随包 Node 不可用时失败关闭，不尝试混用或公网自愈。
- 平台范围与 Harness 当前发行基线一致：macOS Intel/Apple Silicon、Linux glibc x64/ARM64、Windows x64。Linux musl 与 Windows ARM 不在首期验收中。
- CodeGraph 使用匹配平台包自带的 Node 与编译后 JS/WASM；不在 Bun TUI 进程直接 import SDK，不要求用户另行维护系统 Node。
- 不使用上游自动下载、遥测或升级路径。Harness 只向受管子进程传入本版本确实支持的离线/遥测关闭环境，并用企业网络策略承担最终外联边界。
- 依赖缺失或未通过 preflight 不影响 Harness 启动、普通模型 Run 或现有工具；开启实验功能后执行 `/code-index` 才显示可操作的缺失包名与精确版本。

### 4. 共享命令与索引生命周期

- TUI 和 Web 共用一份命令控制器、Host 状态和当前工作区索引，不各自启动进程或建第二份图。
- `/code-index`：无索引时首次建立，健康索引存在时增量同步。`status`：显示根、锁定版本、文件/符号统计、当前 job、watcher 和查询状态。
- `rebuild`：关闭受管查询/watcher 后全量删库重建；`cancel`：取消当前 job；`remove`：二次确认后关闭资源并删除唯一 `.harness-index`及 Harness 自己添加的本地 ignore 规则。
- 首建成功后开启 watcher；Host 重启看到健康索引时自动恢复查询和 watcher，不再要求用户执行一次命令。watcher 不可用时说明手动 `/code-index` 更新方式，不安装 Git hooks。
- 首期进度只展示上游实际回调可支撑的阶段和数量；不解析 ANSI 动画、不绑定英文 CLI 文案、不伪造总百分比。

### 5. 查询闭环、并发与回退

- 只暴露供应商无关的 `codebase_explore`，底层映射 1.1.6 的主探索工具；不同时暴露 node/search/callers/status 等重叠 MCP 工具。
- 索引健康后，下一次 Run 的模型指导优先使用 `codebase_explore` 定位与理解代码；未命中、语言未覆盖、结果不足或运行失败时，允许普通搜索和读取。
- 索引返回的源码不是 Harness Snapshot；任何编辑前仍必须用 Harness `read_file` 读取目标文件，不伪造 Snapshot，不使用上游工具文案覆盖本机安全契约。
- 一个 Host / workspace 同时只能有一个索引 job。已经存在可能使用索引的 active Run 时，新的建立/同步/重建请求拒绝并提示等待，不中断该 Run。
- job 运行期间允许用户继续对话；新 Run 暂时不取得 `codebase_explore`，使用现有工具。不热切换已经开始的 Run；job 成功后的下一次 Run 再取得索引能力。

### 6. 失败关闭和 1.1.6 风险

- Host 在执行写操作前持久记录 `running`，仅在子进程正常结束且状态校验通过后改为 `succeeded`。Host 强杀、取消、超时、非零退出或校验不一致都收敛为 `cancelled` / `incomplete` / `failed`。
- `cancelled` 和 `incomplete` 不重启 MCP/watcher，不允许模型查询可能部分写入的图；用户通过 `/code-index rebuild` 恢复。下次 Host 启动看到未完成标记时仅报状态，不自动删库。
- 全量重建前先等待受管查询释放、关闭 MCP/watcher，再删库重建；完成后按新 generation 重连。不把 generation 切换误当旧资源已关闭。
- 外部编辑器或其他进程持有索引锁时，Harness 只等待、失败或提示用户，不终止其他产品的进程。
- 1.1.6 不具有后续 native engine、可见 incomplete marker、WAL 强杀恢复和若干同步正确性修复；本功能在配置与发布状态上仍属实验性，但界面不标记实验性，也不宣称具有后续版本的稳定性。

### 7. 验收范围与实验退出条件

- 效果评测固定覆盖 Harness 的 TS/Python 混合仓库、一个中大型 TypeScript 仓库和一个中大型 Python 仓库；记录答案正确性、未命中、工具调用数、总 token、耗时、首次/增量索引时间、峰值内存和 DB/WAL 大小。
- 本 Task 不预设必须提升的百分比，但不能缺少数据或用节点数代替真实问题验证。
- 源码交付要求所有支持平台的包解析、路径、命令参数、取消和回收契约测试，并至少完成当前 macOS 的真实闭环。Windows/Linux 真机或企业 runner 结果是去掉“实验性”标记的后续门槛，不阻止本 Task 按实验功能归档。
- 用户文档必须写明如何开启、重启生效、如何查看/更新/重建/取消/删除，以及 1.1.6 不保证固定的速度、token 或正确率提升。

## 可观察验收

1. **实验默认关闭**：新用户和未配置用户启动 Harness，无代码索引进程、目录、watcher、MCP 工具或建图网络请求；Slash 菜单不展示该命令，手输时收到启用与重启说明。
2. **开启门禁**：用户在 TOML 中设置 `[experimental.code_index] enabled = true` 并重启后，TUI 和 Web 的 `/code-index` 可用；关闭并重启后不再启动索引资源，已有数据保留到用户明确删除。
3. **无供应商目录**：首次建图只创建 `<workspace>/.harness-index/`，不创建 `.codegraph/`、不修改项目根 `.gitignore`、不安装 Git hooks；普通 Git 状态不出现该派生数据。
4. **版本和离线 preflight**：主包/当前平台包都是 `1.1.6` 且布局完整时才启动；缺包、版本错配、包缺文件和不支持的 OS/架构得到可操作错误，Harness 对话、文件工具和其他命令仍可用，不访问公网下载包。
5. **首建与增量**：无索引执行 `/code-index` 后，界面显示实际阶段/数量并在成功后显示文件、符号与关系统计；已有健康索引再执行时只做增量同步，不默认删库。
6. **管理入口**：`status` 同时显示索引、job、watcher 和查询健康度；`rebuild` 显式全量重建；`cancel` 不把中断当成成功；`remove` 在二次确认后删除索引和只属于本功能的本地 ignore，不删除用户其他数据。
7. **重启与自动同步**：开启实验配置且索引健康时，重启 Host 会自动恢复一个受管 MCP session 和 watcher；watcher 不可用时界面告知增量更新方式，不暗中安装 hook。
8. **失败恢复**：取消、超时、异常退出、Host 终止或完成后状态校验失败会留下持久的 `cancelled` / `incomplete` / `failed` 事实；新 Run 不取得 `codebase_explore`，重启后也不自动删库，用户可查看状态并重建恢复。
9. **模型闭环与 Snapshot**：健康索引使下一次 Run 可见且优先使用 `codebase_explore`；未命中、未覆盖或服务失败时转用现有搜索/读取；索引源码不会生成可写 Snapshot，编辑前必须再读目标文件。
10. **并发与界面一致**：同一 workspace 不可同时建两份图；active Run 可能使用图时拒绝新建图 job；job 期间的新 Run 继续使用普通工具；TUI 与 Web 查看和操作的状态、确认和终态一致。
11. **资源与效果证据**：三类真实仓库记录准确性/未命中、调用数、token、耗时、首建/增量、内存和 DB/WAL；数据退化也如实记录，不作固定收益宣传。
12. **平台证据**：macOS/Linux/Windows 支持包的解析与进程契约有自动化测试，当前 macOS 完成真实离线闭环；其它平台真机稳定性是未来去掉实验标记的条件，本 Task 不把实验交付冒充为已经完成五平台生产验收。
13. **文档与正常用户表面**：用户文档说明配置和发布状态仍属实验性，以及默认关闭、配置/重启、管理命令、本地数据、失败回退和不承诺固定收益；正常界面仅显示“代码索引”，不显示实验性字样或徽标，命令文案和模型工具也不出现供应商名称。
