# HC-257 个人会话与目录整理

## 现状痛点

桌面左栏的个人空间只能新建、重命名、发布和停止共享会话：

- 试错的、失败的、做完的会话越积越多，不能收起，也不能清掉；
- 按工程目录自动聚合的“文件夹”分组没有任何菜单，旧目录里十几条会话只能一条条处理（实际上连处理都做不到）；
- 想在同一目录再开一个会话，必须重新选目录；
- 想把整段对话带到周报或 Wiki，没有一键复制；
- 本机存储里其实早已有 `remove()`，但界面没有入口。

## 解决思路与改后收益

```text
输入：右键会话 / 点击目录分组“更多”
判断：是否运行中？是否 local_only？是否已归档？
执行：本机元数据打标记（归档、置顶）或清理本机数据（删除）
输出：左栏结构更清爽，常用会话置顶，旧会话收进“已归档”，用不到的会话彻底清掉
```

- 归档可逆，会话收进“已归档”分区，继续发送消息会自动恢复；
- 删除只对纯本机会话开放，并一次性清掉正文、草稿、待发队列、Agent 绑定与代码检查点；
- 目录分组只是视图，文件夹操作等价于对组内每条会话各执行一次，绝不删除磁盘上的真实目录。

## 已确认的范围

1. **P0 整理基础**：单条归档/取消归档、单条删除、已归档分区、目录分组整组归档与整组删除、运行中保护。
2. **P1 高频便利**：置顶、在此目录新建会话、复制为 Markdown、复制目录路径、在文件管理器中显示、搜索含已归档开关。
3. **已停止共享会话**：归档只改本机标记；删除置灰并提示“该会话在团队侧仍有记录，暂不能删除”。
4. **只在 `desktop/` 内完成**：不新增后端 API，不改 `contracts/`、`server/`、`packages/collaboration-client/`。

## 不在本卡范围

- 团队会话的归档、删除、强制移除与服务端新接口（后续另立任务）。
- 多选批量、按时间平铺视图、智能清理建议、会话正文搜索（HC-248）。
- 命令面板（HC-248）检索范围调整。
- `LocalImageStore` 的孤儿图片回收。

## 职责与前置

- 本卡仅涉及桌面端，无前置任务。
- 协调器文件 `local-execution-coordinator.ts` 同时被主工作区其他改动触及，合并时需注意冲突；本卡只在协调器上新增“遗忘会话”和“是否有进行中轮次”两个窄入口，不改动既有执行流程。

## Review 结论（2026-11-26）

对照 Task 范围、Spec 与验收项审阅了全部 diff（`desktop/` 内 20 余个文件，不含契约、服务端与协作客户端）：

- **通过**：数据模型采用可选字段，无迁移分支；归档/置顶不改 `updatedAtMs`，`appendTurn` 自动恢复已归档会话；busy、`local_only` 与已发布会话的拦截都在主进程落实，渲染层只做置灰；删除顺序为“权威校验 → `store.remove` → 尽力清理”，清理各项独立容错；目录分组只做视图，整组操作逐条串行并汇总；`revealDirectory` 的路径只来自主进程读取的本人记录。
- **审阅中发现并已修复**：①取消归档被 busy 校验误拦截（已改为仅归档时校验并补测试）；②菜单用目录文案反推“有无目录”（已改显式字段 `hasDirectory`）；③整组删除弹窗复选框被重命名弹窗样式撑大（已修复并复验）；④架构文档引用了不存在的任务编号（已改为“后续任务，编号待定”）。
- **已知限制**：不清理用户 Git 仓库内的 `refs/workbench/checkpoints/*` 引用（需要在用户磁盘上执行 Git 命令）；`LocalImageStore` 的孤儿图片不随会话删除；已停止共享的会话本期只能归档，删除待团队侧能力。
- **遗留**：`local-execution-ipc.test.ts` 的 HC-239 用例在基线即失败，建议另行处理。
