# HC-224 本机执行流修复与恢复优化

## 要解决的问题

1. **思考片段拆断定稿正文 & 缺少工具摘要同步**：主进程 `local-execution-ipc.ts` 此前在 `thought-delta` 时标记 `needsSegmentBreak = true`，导致词内穿插思考后向云端上传的定稿正文被强行插入 `\n\n`；且工具执行完后未收集 `tool_summary`，使跨端只读或重开历史丢失本轮执行过的工具摘要。
2. **穿插/追尾思考隐藏最终回复**：当回复尾部出现追尾 `reasoning` 条目时，`splitTurnProcess` 因末尾不是 `assistant` 而将整轮（含最终回答）吞进折叠组；当词间穿插思考时，`local-execution-view.ts` 把半截词拆成多条助手消息。
3. **Shell 命令标题被错误截断**：`splitToolTitle` 对 `kind === "execute"` 工具按首个空格拆分，导致 `"wc -l pi-probe.txt"` 变成 `label: "wc"`, `summary: "-l pi-probe.txt"`。
4. **重启后已选目录授权丢失**：工作目录 `grants` 仅存内存，桌面重启后 `prepare` 无法识别此前通过系统目录选择器授予的目录。

## 修改范围与关键实现

- `apps/desktop/src/main/local-execution-ipc.ts`：
  - 仅在 `tool`、`permission` 或 `messageId` 切换时触发分段空行，且合并前后已有的 `\n` 避免叠出多余空行；`thought-delta` 不再触发定稿分段换行。
  - 在 `ActiveTurn` 中按 `tool.id` 增量归并工具元数据，收集终态为 `completed`/`failed` 的工具摘要（单轮上限 50 条）并在 `completed` 且 `shareable` 时传给 `uploads.enqueue`。
  - 新增可选参数 `grantsDir`；仅在 `captureDirectorySelection()` 成功校验目录后将 `{ path: canonical, dev, ino }` 原子写入 `grantsDir/<sha256(accountId)>.json`（`0o600`）；`prepare()` 在内存缺省时校验实时 `realpath`/`dev`/`ino` 完全匹配方恢复授权，未选目录、跨账号或已替换目录仍拒绝 `PROJECT_PATH_INVALID`。
- `apps/desktop/src/main/collaboration-ipc.ts`：仅在调用 `createLocalExecutionIpc` 时传入 `join(app.getPath("userData"), "local-execution-grants")`。
- `apps/desktop/src/main/conversation-uploads.ts`：在 `user` 与 `assistant` 消息之间顺序生成 `tool_summary` 消息；对超长摘要按 UTF-8 字节二分裁剪（必要时跳过超限项），确保每条消息不超过 `syncPayloadLimit`（32 KiB）且整批不超过服务端限制。
- `apps/desktop/src/renderer/features/session/local-execution-view.ts`：记录上一条正文后是否出现 `tool`/`permission`；若仅夹杂 `thought` 且 `messageId` 未变，将续写合并进原正文并整体移到思考条目之后；`splitToolTitle` 接收 `kind`，对 `execute` 返回 `{ label: "终端命令", summary: trimmed, originalName: trimmed }`。
- `packages/workbench-ui/src/conversation/timeline-model.ts`：`splitTurnProcess` 跳过末尾连续追尾 `reasoning`，若紧邻一条 `assistant` 回复且其后无其他条目，保留该回复作为 `finalEntry`。
- 测试：`apps/desktop/tests/local-execution-view.test.ts`、`apps/desktop/tests/timeline-model.test.ts`、`apps/desktop/tests/local-execution-ipc.test.ts`。
