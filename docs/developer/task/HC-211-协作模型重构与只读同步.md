# HC-211 协作模型重构与只读同步

## 现状痛点与解决思路

### 1. 现状痛点

按 [Java 中继调整方案](../project/Java中继调整方案.md)，现有 `services/collaboration-server` 的整套协作模型被新结论整体替换：

- **协作单位不对**：`wb_device_project` 把"项目"当成"某台设备上共享的一个本地目录"，而新模型是"团队 → 用户自建业务项目 → 项目引用部分团队仓库"；`wb_device` 绑 `workspace_id`，设备其实属于用户本人。
- **协作方式不对**：成员可往别人会话远程输入，Java 经 execution 状态机 + Redis 设备路由表 + Kafka 指令主题 + Daemon WSS 把 `execution.start/cancel` 派发到对方设备执行，再由会话级 SSE 向全员实时推送——方案安全不变量明确禁止：**Java 永远不代表甲方向乙方设备下发会执行或改代码的命令**。
- **建库方式不对**：Flyway 三个迁移文件在企业内网无落地条件，方案 D7 定为"只维护一份完整 `schema.sql`，应用启动只核对不建表"。
- **读模型不对**：看简报、按需拉增量即可，不需要会话级实时推送。

### 2. 核心解决思路

1. **组织层先行**：新增 `domain/project`（项目 + 成员 + 仓库引用）、`domain/repository`（团队仓库目录 + 本机登记）、`domain/access`（ProjectAccessPolicy 统一权限口径）；`wb_device` 去 `workspace_id` 回归"设备属人"。
2. **会话只读共享**：`wb_conversation` 按新形态重建（owner 固定 + project 归属 + 简报字段 + `synced_sequence`）；消息序号由主人 Runner 单调分配（单写者），Java 只校验连续与幂等——`POST /device/conversations/{c}/sync` 上传、`GET .../history?afterSequence=` 增量拉取、简报列表随会话行返回；设备心跳 `POST /device/heartbeat` 只用于展示在线。
3. **整条派发链路回收**：execution 包、Daemon WSS、`wb.daemon.commands`、`wb:daemon:presence:*`、`wb:exec:*`、会话级 SSE、设备共享目录接口全部删除，"不能远程驱动别人的 Agent"在协议层面成立。
4. **单文件 DDL（D7）**：一份 `schema.sql` 声明全部 11 张表；`Foundation` 启动只读核对必需表/关键列/禁止表，缺失打印清单并拒绝启动，应用从不执行 DDL。

## 关键流程（输入 → 判断 → 执行 → 输出）

### 主人设备同步上传

```text
设备 POST sync（凭据 + 批次定稿消息 + 简报）
  → 校验：设备凭据有效且属于会话 owner；会话属于声明的项目
  → 校验：批次首条序号 == synced_sequence + 1 且批内连续；重复批次幂等返回
  → 执行：消息写 Redis 热窗 + 异步入 ES；更新会话行 status/简报/synced_sequence
  → 输出：已确认最大序号；跳号 409 返回期望值；越权/吊销 401/403
```

### 项目成员按需拉取

```text
成员 GET history?afterSequence=N
  → 校验：项目活跃成员（非成员 404，不泄露存在性）
  → 执行：先查 Redis 热窗，缺段回源 ES 按序号翻页
  → 输出：N 之后的增量消息（user/assistant/tool_summary/status），只读
```

## 范围与非范围

- **范围内**：schema.sql + demo-data.sql + 启动核对；组织层三包与访问策略；项目/成员/仓库目录/引用/绑定全部新路由；`wb_conversation` 新形态 + `wb_conversation_repository`；会话登记/简报列表/单个简报/增量历史/同步上传/心跳路由；旧派发链路全量拆除（代码、路由、Redis 键、Kafka 主题、pom 依赖）；`workbench-contracts` 同步增删；受影响测试迁移与新增。
- **非范围**：快照（HC-212）、任务卡片（HC-212）、知识（HC-212）、看板与用户级通知流（HC-212，`conversation.brief_updated` 事件载荷本任务只产出不投递）；桌面端 UI；ACP 协议；多团队切换 UI（B3）、发版后增量 DDL（B4）、Agent 生成简报（B1，仅留 `brief_source` 字段预留）。

## 验收标准（可观察结果）

- [ ] `schema.sql` 手工执行建出 11 张表；空库/缺表启动打印完整缺失清单并非零退出；探测到 `wb_device_project` 等禁止表拒绝启动。
- [ ] `wb_device` 无 `workspace_id`；设备注册/吊销/列表按 owner 维度工作；`wb_device_project` 不存在，`wb_local_repo_binding` 以 `(device_id, repository_id)` 唯一。
- [ ] 项目/成员/仓库目录/项目引用/本机绑定路由按方案 §4.3 生效：非项目成员访问项目资源 404，非负责人做管理操作 403，唯一冲突/CAS/归档约束 409；成员置 removed 后立即失去读权。
- [ ] `POST /device/conversations/{c}/sync`：主人设备可上传，非主人 403；连续批次入库更新简报与 `synced_sequence`；重复批次幂等；跳号 409 返回期望序号。
- [ ] 会话登记（`POST .../projects/{p}/conversations`）校验设备归属与"涉及仓库 ⊆ 项目引用"；简报列表/详情/增量历史仅项目成员可读，消息类型限 `user/assistant/tool_summary/status`。
- [ ] `POST /device/heartbeat` 写 `wb:device:hb:{deviceId}` 短 TTL；无任何 Java→设备下行帧。
- [ ] `RouteCatalog` 白名单不再含 inputs/executions/cancel/requests/events/stop-sharing/device projects/device channel；旧路径 404；`execution` 包、`DaemonWebSocket*`、`SharedProject`、websocket starter、Flyway 依赖全部移除；Kafka 无 `wb.daemon.commands`/`wb.conversation.events` 使用。
- [ ] `mvn test` 全部通过（含访问策略、成员生命周期、同步序号校验、幂等、授权边界、启动核对清单的新增用例）；`server:contracts`、`check:boundaries --self-check`、`project:check` 通过；按权限矩阵 curl 冒烟走通。
