## 需求与交付

不同用户读取同一份云端会话历史；刷新、重连或服务重启后内容保持一致。发送输入先可靠保存，随后按顺序交给执行层，界面能区分保存、排队和真实执行。

属于 [HC-192 总任务](./HC-192-协作工作台与会话交接.md)，共同边界以 [独立桌面总体设计](../architecture/多人协作工作台顶层设计.md) 为准，参考来源见 [Lody 对照](../research/192-Lody协作能力对照.md)。设计基线为本地提交 `0250561`；当前实施基线为已合入HC-194的 `e4e4493`。2026-11-07用户确认开始HC-195/196，统筹已将本任务认领为Codex / harness_lody，先派发同名Spec设计，尚未进入生产实现；具体接口待双方及统筹审查。

## 范围与目标归属

- Java conversation、execution、realtime：平台会话、消息、输入受理、执行登记、队列与事件发布。
- workbench-contracts 的通用会话/消息/状态契约；平台会话 ID 与 Agent 原生会话 ID 分开。
- 历史分页与 SSE 恢复、稳定消息/事件 ID、请求 ID 和正文一致性校验。
- 服务重启恢复、排队与失联/结果未知的共同状态；不依赖 Java 内存充当持久队列。

## 依赖与范围边界
