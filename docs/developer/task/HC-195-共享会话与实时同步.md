# HC-195 共享会话与实时同步

## 需求与交付

不同用户读取同一份云端会话历史；刷新、重连或服务重启后内容保持一致。发送输入先可靠保存，随后按顺序交给执行层，界面能区分保存、排队和真实执行。

属于 [HC-192 总任务](./HC-192-协作工作台与会话交接.md)，共同边界以 [独立桌面总体设计](../architecture/多人协作工作台顶层设计.md) 为准，参考来源见 [Lody 对照](../research/192-Lody协作能力对照.md)。设计基线为本地提交 `0250561`。本文是待审阅的子 Task，不是已确认 Spec 或实施计划，尚未认领或实现。

## 范围与目标归属

- Java conversation、execution、realtime：平台会话、消息、输入受理、执行登记、队列与事件发布。
- workbench-contracts 的通用会话/消息/状态契约；平台会话 ID 与 Agent 原生会话 ID 分开。
- 历史分页与 SSE 恢复、稳定消息/事件 ID、请求 ID 和正文一致性校验。
- 服务重启恢复、排队与失联/结果未知的共同状态；不依赖 Java 内存充当持久队列。

## 依赖与范围边界

代码前置为 [HC-194](./HC-194-协作契约与云端基础.md) 已合入的基础契约/身份/最小服务停点，不要求其真实 TDSQL/完整桌面验收已结束。会话/执行交界先与 HC-196/197 共同审查，接口确定后可分别开发；真实派发的集成验收仍需 HC-196。

本任务可用执行端口的测试替身验证协作语义，不据此宣称真实 Agent 已接通。WSS 与本机账本归 HC-196，ACP 归 HC-197，完整桌面展示归 HC-202；不同时新增离线发送或 CRDT 同步。

## 并行认领与接口交付

主责 Java conversation/execution/realtime、会话/消息/队列 schema 与夹具；HC-196 通过公开派发/回执端口接入，不直接编辑本任务队列和事务内部。与 HC-198 共同固定同一事务内引用/交接事件接入方式，不把发送保存逻辑复制到两个服务。HC-206/208 通过窄视图输入开发，HC-202 做真实投影，本任务不重写 UI。

可与 HC-196/197/198/199 和 UI 各线并行；公共定义/OpenAPI 聚合、全局配置和 SQL 版本分配由统筹顺序合入。依赖的消息顺序/执行状态/取消/去重接口与输入输出夹具在 Spec 中共同确认，未确认前只可设计，不能临时造一套兼容协议。其余见[并行开发约定](../project/协作任务并行开发约定.md)。

## 验收结果

- [ ] user01 和 user02 对同一会话读取到相同消息顺序和正确作者，刷新不改写历史归属。
- [ ] 消息、引用关联入口和执行登记具备明确事务边界；同一请求 ID/相同正文只受理一次，正文冲突返回可识别错误。
- [ ] 同一会话输入顺序排队，保存/派发/运行/终态分别表达，未收到设备回执不会假装开始或完成。
- [ ] SSE 重连和历史转实时补齐不漏、不重复；慢连接可通过持久记录恢复。
- [ ] 重启 Java 后历史和已保存队列保留，已知未受理任务与结果未知任务分开，不盲目重发有副作用操作。
- [ ] 用户缓存、页签、草稿和在线提示不成为共同历史；他人输入不替换当前用户的个人视图。

## 验证与后续流程
