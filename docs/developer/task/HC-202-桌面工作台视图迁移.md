# HC-202 桌面工作台视图迁移

## 当前可做与等待范围（2026-11-10）

可先做装配设计；HC-206/207/208 组件和非 ACP 平台端口分别就绪后，逐块接入真实 UI、身份、共享历史、交接/引用和文件/Git。组件尚未交付时不重写一份替代界面，业务未接通时明确不可用。

所有 ACP 能力/事件映射、内容块、实际发送/取消/人工回答、Agent 运行与 Harness 扩展的开发、接线和调试，都等同事完成 ACP 交付后再安排；不把组件预览或云端排队成功当实际执行完成。见[当前并行约定](../project/协作任务并行开发约定.md#0-当前调度等待同事交付-acp2026-11-10)。

## 需求与交付

把已经复用的中央对话、右侧文件/变更和新协作导航接到真实业务链路。HC-205～208 分别交付公共基础、既有对话、既有文件/变更和新导航/布局，本任务负责装配与状态/动作投影，不再承担整个界面重写。原有外观和操作延续，页面不依赖旧 CLI。

属于 [HC-192 总任务](./HC-192-协作工作台与会话交接.md)，共同边界以 [独立桌面总体设计](../architecture/多人协作工作台顶层设计.md) 为准，参考来源见 [Lody 对照](../research/192-Lody协作能力对照.md)。设计基线为本地提交 `0250561`。本文是待审阅的子 Task，不是已确认 Spec 或实施计划，尚未认领或实现。

## 范围与目标归属

- 组合 packages/workbench-ui 中 HC-205 公共主题/渲染、HC-206 conversation、HC-207 project、HC-208 navigation/layout 的公开出口。
- apps/desktop 网络/原生适配及可选扩展装配；替换旧 WebAdapterSnapshot/WebIntent/InteractiveController。
- 云端/Runner 的公共 DTO → 各区域窄视图模型与具名动作；共享内容与个人页签/滚动/草稿分开，不在 renderer 再建业务服务。
- 共享附件上传/查看、执行器授权下载与 ACP 内容块衔接，保留既有文件提及并新增会话/消息引用。
- 当前用户/工作区/原执行设备状态与个人草稿、滚动、工具展开、页签及 Git 选择的隔离。
- 对话装配需按完整 `ConversationScope` 保留内容版本 `contentRevision` 与个人滚动状态中的 `seenContentRevision`。切换中央页签或重新挂载时沿用该版本，保证恢复阅读位置后能提示新输出。规则见 [HC-206 Spec 第 3 节](../spec/HC-206-既有对话视图复用.md#3-窄视图模型与动作)。
- 装配审批与问答时，按完整 scope 和请求 ID 保留在途、结果未知及 `retryRevision`。仅在业务确认允许重新提交后推进该值，重连只更新可用性。该装配和实际审批验证随 ACP 交付安排。规则见 [HC-206 Spec 第 3 节](../spec/HC-206-既有对话视图复用.md#3-窄视图模型与动作)。

## 依赖与范围边界

接口与各最小停点到达后即可逐块装配，不等全部任务结束才开始 UI。Plan 必须区分三步：

1. 组件装配：[HC-205](./HC-205-主题与通用视图抽离.md)、[HC-206](./HC-206-既有对话视图复用.md)、[HC-207](./HC-207-文件与变更视图复用.md)、[HC-208](./HC-208-协作导航与桌面布局.md) 到达公开组件停点后，组合真实组件并验证外观/个人状态；未接通业务明确不可用，不能生产内置假聊天。
2. 通用主链：可先绑定 [HC-194](./HC-194-协作契约与云端基础.md) 身份、[HC-195](./HC-195-共享会话与实时同步.md)、[HC-196](./HC-196-设备接入与本机执行.md)、[HC-198](./HC-198-会话交接与内容引用.md)、[HC-199](./HC-199-文件与Git服务迁移.md) 已交付的非 ACP 最小停点；[HC-197](./HC-197-通用ACP运行时.md) 等 ACP 工作由同事完成交付后，再接实际 Agent 执行主链。可选 Harness 未完成不阻碍非 ACP 页面开发。
3. 可选扩展：再接 [HC-200](./HC-200-Harness独立ACP接入.md)、[HC-201](./HC-201-Harness轨迹与设置扩展.md)，保持无 Harness 时仍可运行。完整待验收要求对应链路全部接通，不能以组件演示代替真实协作。

本任务默认负责 desktop renderer/装配与必要网络连接组合；conversation/project/navigation 的内部改动交对应负责人，公共出口/根锁/全局配置由统筹顺序集成。详见[并行开发约定](../project/协作任务并行开发约定.md)。

不重设计已确认的中央消息/工具交互，不新增独立浏览器或 TUI 产品。不通过包装旧网关保留旁路；Harness 专有 UI 留在集成包，通用视图不依赖其类型。

## 验收结果

- [ ] 沿用独立颜色变量、冷紫浅色/深色、三栏宽度、头像/用户 SVG 与工具呈现，窗口/缩放变化不出现写死高度或关闭按钮错位。
- [ ] 中央消息/工具/输入与右侧文件/变更实际使用 HC-206/207 迁出的组件，具备来源和行为保持证据；左侧协作导航使用 HC-208，不另写替代中右区域。
- [ ] 会话、流式工具、发送/取消、人工审批和待设备状态消费新契约，无旧 CLI 或内核对象依赖。
- [ ] 左侧共享会话与待交接可辨识；中央显示实际设备/项目、接续人、交接说明和引用来源，离线限制清楚。
- [ ] 文件树、只读预览、中央新文件页签及关闭行为、Git 勾选/全选/说明/提交/推送均落到原设备项目。
- [ ] 共享附件可上传查看并在目标设备授权取得，内容按 Agent 能力提供，不能把新上传功能误当作迁移前已存在。
- [ ] 他人发言/交接不替用户切文件或页签、不覆盖草稿/滚动/Git 选择；换账号隔离缓存与订阅。
- [ ] 设置保留居中弹窗；Harness Trace 通过可选扩展加载，全矩阵保持，不需要时通用工作台仍正常。
- [ ] 键盘焦点、模态背景、窗口拖动/原生按钮和重新打开行为可用；关闭窗口进入后台与明确退出有区别。
