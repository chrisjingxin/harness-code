# HC-252 只读会话异步批注

## 当前阶段

2026-11-23 结合高杠杆异步协作体验增强诉求拆解立项。待认领，认领后按 Spec → Plan → Todo 推进。

## 要解决的问题

- 当成员 B 同步查看成员 A 分享到 Project 的只读会话并发现一个设计漏洞或思路偏差时，目前只有两种过重或割裂的选择：要么“在自己电脑新建一个会话把 A 的快照引用进来（A 却不知道）”，要么“正式建一个 Task 指派给 A”；缺少类似 GitHub/GitLab PR Review Comment 的“就在这轮回复旁边留一句轻批注”。

## 预期使用过程

```text
发起批注：
  输入：成员 B 在成员 A 的已同步只读会话中，选中第 5 轮助手回复并点击“添加批注”
  执行：写下评审意见并提交到 Project 服务端批注流
  输出：批注锚定在第 5 轮消息旁；A 的收件箱收到提醒且不触发 A 本机 Agent 运行

处理与采纳：
  输入：成员 A 切回自己的本机会话，看到第 5 轮旁的待处理批注气泡
  执行：A 可直接文本回复讨论、点击“标记已解决”，或点击“带入我的草稿”让自己的本机 Agent 依据这条评审意见继续修正
  输出：批注线程解决闭环，整个过程保持人类主导、零打扰自动执行
```

## 已确认的范围

1. **锚定到已上传定稿消息**：批注只能附加在已上传到 Project 的只读/共享消息 ID（及可选文本摘录区间）上，不依赖原设备在线。
2. **严守不遥控他人 Agent 红线**：提交批注只产生人和人之间的异步评审线程与收件箱/轻量通知，绝不向会话所有者的本机 Agent 发送 Prompt 或触发自动运行。
3. **本机会话无缝带入草稿**：会话所有者在本机端侧查看批注时，支持一键“带入我的下一轮草稿”（作为受控引用文本片段），由所有者补充确认后主动发送。
4. **线程状态管理**：支持多轮简洁文本回复、编辑/删除本人批注及“已解决 / 重新打开”状态切换；停止共享或归档后的会话仅允许浏览已有批注。

## 不在本卡范围

- 多人像 Google Docs 一样的实时光标同屏协同编辑。
- 在批注里直接调用命令行或远程修改对方代码目录。

## 职责与前置

- 本卡全栈实施：服务端（`contracts/` + `server/` + `packages/collaboration-client/`）负责会话消息批注线程的存储、Project 成员权限校验、解决状态流转与轻量通知事件发出；桌面端负责在 `HC-218` 只读与本机会话时间线旁渲染批注气泡、划选/按轮新建批注交互、收件箱联动及“带入草稿”按钮。
- 依赖 [HC-218](HC-218-会话只读与主动同步.md) 的只读同步视图与 [HC-246](HC-246-全局待办收件箱与IM轻通知.md) 的收件箱提醒入口。
