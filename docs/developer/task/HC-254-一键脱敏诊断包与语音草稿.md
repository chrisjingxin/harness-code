# HC-254 一键脱敏诊断包与语音草稿

## 当前阶段

2026-11-23 结合运维排障效率与高频口述输入体验提升拆解立项。待认领，认领后按 Spec → Plan → Todo 推进。

## 要解决的问题

- 本机运行多种 ACP Agent 且涉及知识注入、多目录授权、定稿补传和 SSE 断线续读，员工一旦遇到“知识没带进去 / Agent 没响应 / 同步卡住”，目前很难一次性拿出干净、可供内网运维或研发定位的上下文，自己手工拷贝日志又极易误传凭据或业务代码。
- 员工在撰写复杂任务描述、长篇排障背景或口述复盘感想时，纯键盘输入较慢，如果支持语音转文字写入草稿再修改，可显著降低输入摩擦。

## 预期使用过程

```text
一键脱敏诊断包：
  输入：用户在设置或连接异常提示条点击“导出脱敏诊断包”
  执行：桌面主进程收集系统与桌面版本、ACP 能力协商结果、脱敏后运行错误日志、上传/同步状态水位摘要（不含会话原文、源码正文与凭据）
  输出：生成本地 ZIP 诊断包，并先向用户展示包含文件清单与已脱敏项数量，由用户自行决定是否发送给支持人员

语音输入写入草稿：
  输入：用户在会话输入框或 Task 表单点击麦克风图标开始说话
  执行：识别引擎实时或分段将语音转为文字，追加写入当前可编辑草稿框并保持焦点
  输出：停止录音后文字留在草稿框等待用户核对修改，绝不自动发送或触发 Agent 执行
```

## 已确认的范围

1. **严格的诊断包脱敏原则**：诊断包默认只采集结构化运行摘要与脱敏错误堆栈，自动剥离 Cookie、Authorization 头、API Key、环境变量秘钥、对话消息正文、本地项目源码正文及个人身份隐私字段；导出前向用户展示清单。
2. **本地生成、用户自愿外发**：诊断包只保存在用户选定的本地路径，不未经用户同意在后台静默上传云端。
3. **语音转文字仅写草稿**：语音输入覆盖主对话输入框、发布 Task 表单与知识沉淀编辑框；识别结果作为普通文本填入草稿，保留发送前编辑与撤回权利，严禁自动发送。

## 不在本卡范围

- 后台静默自动上报用户电脑全量行为埋点。
- 全双工实时语音通话直接控制本机 Agent。

## 职责与前置

- 本卡主要为桌面端本机能力建设（主进程诊断日志汇聚与脱敏器、语音识别接入封装及输入区录音控件）；若使用企业内网可选统一语音识别接口，则按现行分工接入服务端已有认证通道或本机 OS/离线能力。
- 依赖 [HC-239](HC-239-个人优先使用本机Agent.md) 与现有桌面设置及输入框组件。

## 待定问题（Spec 阶段确定）

1. macOS / Windows 语音转文字的首选引擎方案（系统原生听写 / 本地轻量离线模型 / 可选内网语音转写接口降级）。
2. 诊断包保留的最近日志时间窗口与单包体积上限（如最近 24 小时、上限 10 MiB）。
