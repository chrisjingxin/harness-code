# HC-179 内网依赖源码化

## 通俗说明

Windows x64 内网环境需要提前验证 OpenTUI 的 native DLL，但目标环境的 npm registry 还不能稳定提供五个关键发布包。这个任务把精确发布包直接放进临时分支的 `third_party/npm/`，让 Bun 仍按 workspace 方式链接它们，同时继续从现有内网源安装其他直接和间接依赖。

源码化范围只包含以下五个完整发布工件：

- `@opentui/core@0.4.3`
- `@opentui/react@0.4.3`
- `@opentui/core-win32-x64@0.4.3`（必须含完整 `opentui.dll`）
- `bun-ffi-structs@0.2.4`
- `react-devtools-core@7.0.1`

每个工件从精确 npm tarball 提取，以现有 `bun.lock` 的 SHA-512 校验原始内容；仓库不保存 tarball、`node_modules` 或缓存，只保存完整发布目录、许可证、机器可读 provenance 和最终目录哈希。`react-devtools-core` 的 `ws@7.5.10` 修改固化在 vendored `package.json`，根 `patchedDependencies` 不再重复应用。

## 临时分支边界

本任务只服务 Windows x64 内网提前验证，不进入 canonical `master`。正式内网 registry 已经能够稳定提供五个同版本包、完成内网重新解析并验证 Windows 空缓存安装后，应删除 `third_party/npm/`、源码化门禁及本任务文档中的临时例外，再回到普通 registry 依赖路径。当前分支不 push、不合并、不声称已完成 Windows 安装或 TUI 验收。

## 完成定义

- 五个包均以 `workspace:*` 进入根/CLI/包间依赖链，`bun.lock` 对五个包只出现 `workspace:` 解析。
- 安装前门禁 fail closed：版本、MIT license 元数据、provenance tarball integrity、目录哈希、Windows x64 `os/cpu`、`opentui.dll`、`ws@7.5.10` 来源证据、workspace lock 或 registry 回退任何一项不满足均失败。
- 五个发布目录必须包含显式声明的运行入口与声明文件；`bun-ffi-structs`、`react-devtools-core` 的完整 `dist/**` 属于发布内容，不得被根 `dist/` 忽略规则排除。
- 安装后五个目标包从 CLI 或包间真实消费者位置解析出的 `package.json` 和入口 realpath 必须落在对应 `third_party/npm/` 目录；安装前没有 `node_modules` 时只运行静态门禁，不误报。
- `deps:install` 与 `deps:resolve` 只允许在 `win32/x64` 执行；普通依赖测试、typecheck 和 build 可在开发机运行。
- 原有 `deps:install`、DeepAgents 0.7.3 受控补丁、Python 安装路径和禁止 Anthropic 依赖门禁继续生效。
- focused tests 覆盖错误版本、文件篡改、缺 DLL、错误平台、registry 回退、重复补丁和 Anthropic 回归；项目级检查结果如实记录。
- 完成本停点后分支可被搬运到目标内网；内网解析、Windows x64 空缓存安装、TUI 和浏览器 E2E 不在本停点内。
