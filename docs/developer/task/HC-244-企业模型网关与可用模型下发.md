# HC-244 企业模型网关与可用模型下发

## 当前阶段

2026-11-23 结合企业级多团队协作演进需求拆解立项。待认领，认领后按 Spec → Plan → Todo 推进。

## 要解决的问题

- 当前每名员工需在本机或各 Agent 运行时中自行配置模型 API Key，既带来明文凭据泄露与离职无法收回的安全风险，也导致模型版本与成本配额无法按团队统一治理。
- 新员工首次打开桌面端还要到处找网关地址、密钥和模型名，缺少两步引导与发送前连通性校验。

## 预期使用过程

```text
输入：员工登录工作台并选择所属团队（或无团队默认授权）
判断：桌面 main 通过现有登录态向服务端请求当前账号在企业模型网关的可用模型清单与短期消费令牌
执行：
  1. 新会话或模型切换面板列出已授权模型；发送前或配置页支持一键连通性预检
  2. 本机 ACP 运行时通过网关地址 + 短期消费令牌调用模型，不接触真实上游 API Key
  3. 管理员调整团队授权模型或撤销成员权限 → 下一轮请求或刷新配置时立即生效
输出：员工免手填 Key 开箱即用；企业统一收敛成本、配额与上游凭据安全
```

## 已确认的范围

1. **凭据零暴露**：真实上游模型服务商 API Key 留在服务端/AI 网关侧，桌面端与本机 ACP Agent 仅持与账号及团队绑定的受控网关消费令牌（短期有效、可随时吊销）。
2. **按团队与角色下发模型清单**：不同 Workspace 可配置各自允许使用的模型列表与额度策略；桌面端只允许选择授权范围内的模型，若当前会话绑定的模型已被撤权或下线，在发送前显式提示切换。
3. **前置连通性预检**：在设置页与新会话引导页提供轻量网关/模型可用性检测，快速区分“未登录/令牌过期”“无模型授权”与“网关不可达”。
4. **本地隔离与不落盘明文**：短期令牌仅托管在桌面主进程受保护状态中，不向 React 暴露，不写入本机日志与诊断导出文件。

## 不在本卡范围

- 团队 Skills 与 MCP Server 分发：HC-245。
- 上游模型网关本身的跨机房部署与计费报表后台建设（复用或对接既有网关接口）。
- 非企业托管场景下员工自备外部个人 Key 的高级自定义扩展策略（在 Spec 阶段明确边界）。

## 职责与前置

- 服务端（由后端同事维护）提供按登录身份查询授权模型列表、签发/刷新短期网关消费令牌以及团队模型授权管理接口；缺口按分工交同事，前端不私自新增后端 API。
- 桌面端负责模型列表消费、切换 UI、发送前失效拦截、预检引导与向 ACP 会话透传受控网关入口。
- 依赖 [HC-239](HC-239-个人优先使用本机Agent.md) 的登录即用入口与 [HC-240](HC-240-Workspace角色管理.md) 的 Workspace 管理员角色边界。

## 待定问题（Spec 阶段确定）

1. 短期消费令牌的默认有效期、自动续期时机及离线缓存宽限策略。
2. 未加入任何团队的个人账号是否给予平台级默认基础模型配额。
3. 成员跨多团队时，无团队上下文个人会话默认使用哪个模型的扣费与授权归属。
