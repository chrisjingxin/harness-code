# Web 历史轮次分叉

## 现在有什么问题

用户想在长对话的某一轮回答之后尝试另一条思路，同时保留原会话继续使用。
目前 `/web` 的回答下没有这种入口。已有撤销功能会改变原会话的可用历史，不能替代创建独立会话。

## 已确认的用户需求

- 在 `/web` 弹出的对话界面中，从任意历史轮次的 Agent 回答处分叉新会话，入口参考用户截图，放在回答下方复制按钮旁。
- 分叉仅继承对话上下文，不恢复分叉时的代码文件状态。
- 截止点包含被选中的那一轮回答，不包含后续轮次。
- 2026-11-10，用户明确允许跳过 `mattpocock:grill-me`，直接开始工作；该例外仅用于本次需求确认。

## 准备怎么解决

在回答下点击「Fork / 从此处分叉」 → 校验目标轮次可用 → 创建独立会话并保存截止该轮的历史 → 在左侧列出新会话并切换过去 → 用户继续输入。

分叉不是重新执行过去的对话，也不是复制当前最新的模型状态：如果源会话在分叉点之后还有对话或发生过上下文压缩，新会话不能因此读到后续信息。原会话的记录及后续继续对话能力保持不变。

## 本期范围与拟定默认行为

以下默认行为随本 Task 一并检视，确认后进入 Spec；尚未作为已实现能力发布。

1. 入口放在主 Agent 每轮已经成功完成的最终回答下。一次 Run 内的过程文本、工具卡、子 Agent 回答，以及仍在生成、取消或失败的半轮输出不是本期分叉点。
2. 当前会话有运行或待处理审批/问答时暂时禁用分叉，显示原因；完成后可从任意可用历史轮次分叉。复用现有切换会话的忙碌约束。
3. 成功后自动切换新会话，左侧即时出现可辨认的新条目，名称默认采用源会话标题加「（分叉）」；不自动向模型发送新请求。
4. 新会话保留截止点以前的用户输入、Agent 回答，以及维持有效模型上下文所必需的工具调用与结果；不只是复制屏幕上可见的正文。工具调用与结果必须保持配对。
5. 继续对话使用当前工作区文件。新会话不继承旧会话的文件已读凭据、待处理审批、正在执行的任务、撤销/重做状态或 Goal/Compose 调度进度。历史文本中提到的这些内容可以作为对话历史保留。
6. 新会话可持久化恢复，并可再次从其历史回答处分叉。分叉后双方新增对话互不影响；不得依靠读取源会话的最新状态来补充新会话上下文。
7. 操作期间显示忙碌反馈并阻止重复点击；失败明确提示，保留当前会话和草稿，不留下半成品会话。连接中断后的重试一致性由 Spec 明确。
8. 无法可靠还原的历史轮次明确提示不可分叉，不猜测截止位置、不退化为复制最新上下文。正常保存的完整历史必须支持分叉。

## 可观察验收

| 场景 | 完成信号 |
|---|---|
| 三轮对话，从第二轮分叉 | 新会话显示前两轮（含第二轮回答），不显示第三轮；原会话保留三轮 |
| 在新会话追问前文 | mock 模型收到截止点以内的有效上下文；前两轮事实可用，第三轮独有内容不进入请求 |
| 截止点前有工具调用 | 下一次模型请求中的工具调用/结果完整配对；分叉动作不执行任何历史工具 |
| 分叉点之后发生压缩 | 新会话的请求和摘要不混入截止点之后的信息 |
| 源会话包含同文回答或多段输出 | 精确对应用户点击的轮次，不按文本、时间或屏幕索引猜测 |
| 创建后刷新或重启 | 列表中能找到新会话，历史截止位置与继续对话能力保持一致 |
| 两边分别继续对话、再次分叉 | 各自历史独立，重复分叉得到独立会话 |
| 分叉时工作区已有文件变更 | 文件内容、Git HEAD、暂存区不变；不执行 Git 还原 |
| 正在运行、等待交互、重复点击或请求失败 | 按约定禁用或提示；不误切换、不重复创建、不留下不完整新会话 |
| 历史缺少可靠截止点 | 清楚说明不可分叉，不复制不完整或超出截止点的上下文 |

## 非范围

- 恢复代码、切换 Git 分支、创建 worktree、隔离工作区。
- 原会话撤销、编辑历史问题、重新生成回答、合并分支或分叉关系树。
- 复制后台执行状态、审批授权、Goal/Compose 执行进度、Trace 日志或完整工具运行轨迹。
- 新增 TUI 分叉入口或斜杠命令；共享底层能力的改动需保证现有 TUI 路径不回归。

## 源码核查与后续规格重点

- `packages/cli/src/web/presentation/timeline.tsx` 承载回答及复制按钮，作为入口邻近实现。
- `packages/cli/src/interactive/features/thread-feature.ts` 的历史恢复映射目前只保留消息种类、正文、工具名和时间，没有用于分叉的稳定轮次身份；Spec 需要贯通实时与恢复路径，禁止拿 UI 数组下标作为持久化边界。
- `packages/agent/harness_agent/threads/thread_records.py` 与 `thread_persistence.py` 提供规范对话记录及持久化能力；应以可靠的历史边界构建独立上下文，不能直接复制源会话当前 checkpoint。
- HC-165 的撤销/重做改动原会话，并会在后续输入时清理历史；本功能不能把「先撤销再复制再重做」当作实现。
- 会跨越 CLI、Protocol 和 Agent，不符合快速通道判据。后续同编号 Spec 需明确截止身份、创建原子性和重试、压缩历史、上下文引用、模型/模式配置选择及错误语义，然后生成 Plan/Todo。
- 当前环境没有可调用的 CodeGraph 工具、命令或根目录索引，因此本次采用定向源码检查。
