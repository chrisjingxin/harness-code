# HC-196 设备接入与本机执行

> 当前安排（2026-11-08）：用户接手认领，负责人为“用户（本机）”，分支保持 `harness_lody`。Spec、Plan、Todo 已齐备；按用户要求暂停实施，等待审阅后的明确派发。任务保持进行中，53 项实施清单与七项产品验收均未勾选；以下分阶段记录保留当时事实。

## 需求与交付

本机 Runner 主动连到云端，接收绑定设备/项目的任务并回传真实结果。另一台电脑可以操作已授权的原执行机器，不需要两台电脑互开入站端口。

属于 [HC-192 总任务](./HC-192-协作工作台与会话交接.md)，共同边界以 [独立桌面总体设计](../architecture/多人协作工作台顶层设计.md) 为准，参考来源见 [Lody 对照](../research/192-Lody协作能力对照.md)。设计基线为本地提交 `0250561`；当前实施基线为已合入HC-194的 `e4e4493`。2026-11-07用户确认开始HC-195/196，统筹已将本任务认领为Codex / harness_lody，先派发同名Spec设计，尚未进入生产实现；具体接口待双方及统筹审查。

## 范围与目标归属

- apps/runner、packages/runner-core：设备身份、WSS 连接、命令路由、持久受理记录与待确认事件。
- Java device/设备 WSS 传输与契约：设备登记、项目标识/共享、派发状态、回执和授权；execution 队列/事务经 HC-195 公开端口接入。
- 本机项目 ID 到根目录的登记映射及注入的执行/项目端口，不接受远端任意目录或启动命令。
- 断线、重复连接、服务/Runner 重启、取消待送达与共享停止等真实状态。

## 依赖与范围边界

代码前置为 [HC-194](./HC-194-协作契约与云端基础.md) 最小身份/服务；与 [HC-195](./HC-195-共享会话与实时同步.md)、HC-197、HC-199 先审查命令/回执、执行/项目端口后，可用端口替身独立开发，不等三者整个任务结束。真实设备协作仍须对应执行/排队/项目服务均接通。

不把 WSS 当作裸 ACP 透传，也不把关闭窗口等同于关机。ACP 进程实现归 HC-197，文件/Git 业务归 HC-199；本任务使用端口替身验证派发，不自动迁移机器、复制代码或运行离线新增协作任务。

## 并行认领与接口交付

本任务主责 runner-core、runner 装配、Java device 和设备传输命名空间；不直接修改 HC-195 execution 内部、HC-197 ACP 生命周期或 HC-199 项目策略。设备凭据/项目目录登记、命令受理/取消/回执/补传与端口生命周期必须在 Spec 和共同夹具中明确，失败状态不能由两端各自推断。

左侧设备/项目状态组件由 HC-208 新写、HC-202 接线，本任务不写第二套导航或对话。桌面托管/preload/根配置等共享点由统筹顺序集成；可与云端队列、ACP、文件服务和 UI 并行。详见[并行开发约定](../project/协作任务并行开发约定.md)。

## 验收结果

- [ ] 设备凭据与 UI 登录分开，本机登记必须由用户明确触发；远端成员不能注册本机目录或重绑设备所有者。
- [ ] 只对明确共享项目受理成员命令，目标设备/项目/输入匹配；停止共享后拒绝新远端读写。
- [ ] Runner 先持久受理再调用执行端口，相同命令重试核对 ID/目标/正文，不触发第二次执行。
- [ ] WSS 主动出站接收命令并回传事件；重连前后同一设备不出现两个竞争命令接收者。
- [ ] 已开始任务断线后可保存未确认事件，重连按稳定 ID 补传；记录失败有明确状态，不继续无记录的新副作用。
- [ ] 关机/休眠/执行器退出后显示失联和实际执行限制；取消未送达不能当作已停止，未知执行不转派到另一机器。
- [ ] Java 和 Runner 分别重启后可核对状态与原生绑定，待设备输入和结果未知输入不会混为同一重试队列。
