# HC-233 项目记忆与团队知识读取

## 当前阶段

2026-11-20 用户确认沿用 HC-233，将原团队知识自动索引与读取、本机项目记忆及跨机引用解析合为一份设计。编号继续使用 HC-233，统一行为以[同名 Spec](../spec/HC-233-项目记忆与团队知识读取.md)为准。当前状态为待认领，本文记录审阅范围。

2026-11-19 的[团队知识源码调研](../research/233-团队知识按需上下文.md)保留固定提交证据，供统一设计中的知识发现与按需读取部分使用。项目记忆新增范围按本次确认的行为推进。

## 要解决的问题

用户需要反复手动引用团队知识，Agent 容易遗漏规约。跨机引用中，A 的工程名、相对目录和口语表达，也难以直接对应 B 的本机副本。

桌面为每个账号、Team 维护两份本机项目记忆，同时自动提供用户维护的知识标题。当前 Agent 读取相关材料、判断工程和任务所需规范，缺信息时询问用户，并通过工具保存本轮获得的新事实。

## 已确认的首版范围

1. **团队知识发现与读取**。现有标题目录自动附带，正文按需读取固定版本。知识规约按任务相关性使用，工程定位成功后也能读取相关规范。
2. **知识列表共享刷新**。A 保存知识后，同团队 B 的列表和候选沿现有通知更新。Agent 已取得的材料保留其来源版本。
3. **两份本机 Markdown**。`team.md` 记录团队工程、用途、关系和仓库，`personal.md` 记录本人的目录、副本与团队工程对应关系。按服务实例、账号和 Team 隔离。
4. **统一上下文与工具服务**。标准 ACP 文本附带 Skill 式说明、记忆条目及知识标题。由同一个本机 MCP 服务提供两种记忆工具和两种知识只读工具，模型推理沿用当前 Agent。
5. **跨机引用解析**。保留共享原文，B 的 Agent 结合 B 自己的资料理解工程。缺失或冲突时查知识，再询问用户或请用户选择本机目录。
6. **记忆更新与纠正**。用户确认的目录立即保存，AI 提案在成功轮次结束后合并。条目版本、原子写入和重复提案处理保证更新结果一致，失败返回实际状态。
7. **现有交互复用**。使用当前引用、目录选择、工具卡和知识页展示，区分关联工程副本与变更会话起始目录。额外目录访问沿用实际 Agent 能力和授权。

## 职责与实施前置

- 桌面负责两份 Markdown、资料装配、四个具名工具、知识元数据缓存、既有通知消费和界面反馈。工具的范围来自真实身份及会话绑定。
- 当前协作客户端已提供 Project、仓库、知识列表与固定版本读取。Java 继续使用现有服务接口与权限模型。
- HC-234 已交付通用 ACP 会话 MCP 配置透传。完整流程需要本卡实现桌面服务与业务工具，再通过现有 `LocalAcpSessionSetup` 传入当前会话配置，结合通用维护方确认具名装配接点。
- 当前 Harness 已支持会话 HTTP MCP，首条路径使用该能力。平台仍按实际协商结果接入不同 Agent。

## 设计交付与默认值

[统一 Spec](../spec/HC-233-项目记忆与团队知识读取.md)完整描述条目与工具、身份范围、注入、知识刷新、跨机目录解析、写回时机和必要冒烟。独立本机记忆草案的正文迁入此 Spec。

首版默认单条本地记录上限 4 KiB，自动记忆正文合计 8 KiB，知识标题正文 8 KiB，记忆查询最多 10 条且完整结果最多 8 KiB。知识标题元数据第一页内存缓存 60 秒，更新通知使缓存失效。这些是实现常量。

## 验收与下一阶段

实施后演示 A 保存知识、B 看到并通过实际工具读取，随后 B 引用 A 的多工程对话、确认缺失目录、成功写回本机记忆并在下一轮复用。顺带确认账号和 Team 隔离、原文和固定引用，以及取消与写回失败的结果。

设计阶段只检查文档、任务和样例一致性，当前运行证据仍按各既有 Task 记录。用户审阅后建立同名 Plan、Todo 并确认实施分工，必要冒烟完成后标待验收，完整组合验收沿用 HC-204。
