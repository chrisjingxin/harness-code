# HC-217 项目导航与资料

## 要解决的问题

原导航以设备和本地项目为入口，新的协作方式则围绕团队下的 Project。需要让用户先明确正在参与哪件协作事项，再查看会话、任务和进度；云端 Project 不能被误认为本机代码目录。

本卡只登记前端工作范围，当前待认领。认领后依次补充同名 Spec → Plan → Todo，经评审再实施；不因建卡自动开始开发。

## 本卡负责

- 左栏以会话为主，新对话与搜索置顶；Project 下按成员展开会话，自己的会话默认展开撑满主要空间，其他成员默认收起置底。看板/任务合为一行轻量入口，项目切换菜单集中展示项目并在分隔后提供创建入口，资料与成员由当前项目旁的设置按钮进入，团队知识和账号置底。首版使用一个团队。
- 本卡负责成员树布局、独立折叠及搜索交互，HC-218 提供条目、所有者标识和同步状态。设备不作为树层级，同名成员按现有标识区分；无会话成员显示空态。默认恢复会话或进入新对话准备页。
- 本卡提供当前项目成员名单和稳定成员标识，HC-218 提供会话条目与本机阅读状态；本卡按所有者归组。搜索仅过滤已加载的当前项目成员/会话，搜索期间展开命中成员，清空后恢复原折叠状态。无会话成员保留空态，列表加载、失败及重试均有可见反馈。
- 项目菜单中的条目只用于选择项目，创建入口在分隔区，项目设置按钮独立打开资料与成员；项目列表加载失败与当前无项目分别显示。切换或重开时恢复当前账号在该项目仍可访问的会话，无历史选择时进入准备页；失去访问权限时移出失效选择。
- 创建 Project 先填写名称和说明，成功后进入资料页，再按已有接口权限维护团队成员及关联仓库；仓库可以不选，也可关联多个。
- 复用现有 WorkbenchLayout、BrandMark、主题、居中设置及侧栏开合/拖宽。左栏以 280 逻辑像素为基线，选中用清晰填充色，图标与文字对齐。
- 定义前端页面装配接点，让 HC-218 的会话、HC-219 的任务/知识、HC-220 的看板能够分别接入。页面选择及个人状态按账号和 Project 隔离，切页不清除未发送草稿或文件页签。
- 消费 HC-211 已交付的组织接口，沿用 desktop main 的身份与响应处理；React 不持有服务凭据。创建后某项资料保存失败时保留项目及输入，如实提示失败项。

## 建议停点

| 停点 | 用户能看到什么 | 交付边界 |
| --- | --- | --- |
| 1. Project 导航外壳 | 我的会话展开撑满、其他成员收起置底，项目切换与独立设置，搜索及短窗口滚动 | 交付具名页面/会话定位动作、成员视图和内容槽；用受控数据展示至少两个项目的切换，不依赖真实业务接线 |
| 2. 项目资料 | 真实项目选择、创建、成员及仓库资料 | 消费已交付组织接口，不扩展后端权限模型 |
| 3. 页面装配 | 会话、任务、知识、看板接入同一外壳 | 按后三卡最小交付逐块接入，不等待所有整卡完成 |

## 目录归属与并行

- 建议独立模块：`apps/desktop/src/renderer/features/project-navigation/`；布局/导航的必要公共调整由本卡统一协调，不重写中央消息和右侧文件组件。
- 本卡拥有导航的项目/页面选择、成员折叠、搜索和布局偏好；HC-218 拥有会话草稿、正文、同步位置及文件页签。项目/账号切换由本卡通知各模块，各模块维护自己的状态，返回结果须仍属于当前选择，避免迟到数据串到另一项目。
- 本卡统筹 `desktop-workbench.tsx` 等页面装配文件及公共页面出口的集成。HC-218～220 在各自目录交付组件和具名动作，由本卡实施者或集成协调人串行合入共享接点。
- main/preload 的公共身份、请求基础和宿主出口不由四卡同时编辑；组织请求的消费适配在本卡范围，具体文件拆分在 Spec 确认。新增客户端接点不等于新增服务端接口。
- HC-218～220 可以同时设计和开发独立界面；接入外壳只依赖停点 1，不依赖本卡整卡结束。细分归属见[任务衔接](../project/项目协作设计任务衔接.md#3-前端任务与并行顺序)。

## 验收标准

- [ ] 当前团队、Project 和本机工作目录分开展示；选择 Project 不自动指定目录、创建会话或下载他人正文。
- [ ] 可通过真实已交付接口选择/创建项目，按返回权限查看和管理成员、仓库；失败不会显示虚假的创建成功或丢弃输入。
- [ ] 成员可展开/折叠查看其会话，自己的会话默认展开占主要空间，其他成员默认收起置底；展开后支持独立滚动；搜索成员/标题可定位条目；看板与任务只占一行，短窗口会话列表独立滚动。
- [ ] 项目切换菜单只列项目及分隔后的创建入口；资料与成员从独立项目设置打开，项目选择与管理动作可辨识。
- [ ] 搜索清空恢复成员折叠状态；无项目、无会话和加载失败有明确反馈；新增会话出现在本人组，轻量更新不会自动展开其他成员。
- [ ] 左侧选中、顶栏字体/图标、居中设置和浅深主题符合[视觉预览](../previews/project-collaboration/README.md)，窄窗口和高度变化沿用既有响应式布局。
- [ ] 切换 Project 或中央页面时，当前账号的个人草稿、文件页签和阅读状态保持正确归属；其他页面更新不会抢走选择。
- [ ] 新页面通过既有组件和独立模块装配，未复制 ConversationView、工具卡、ProjectDock 或第二套主题。

## 必要验证与非范围

实施时做受影响包的构建/类型/边界检查，并冒烟一条“切换项目 → 展开他人成员再收起 → 打开项目设置 → 回到本人会话”的正常路径，覆盖本轮关键入口与状态恢复。受控视觉证据与真实接口证据分别记录，完整组合及 Win/Mac 留 HC-204。

服务端、线上契约、SQL、Runner 核心和 ACP 由同事负责；本卡不修改其设计或实现，也不恢复跨机器执行和实时文件/Git。HC-208 的原成果与待验收记录保留，本卡承接新的 Project 导航增量。
