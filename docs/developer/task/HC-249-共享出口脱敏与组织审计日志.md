# HC-249 共享出口脱敏与组织审计日志

## 当前阶段

2026-11-23 结合企业级安全合规与《个人与团队协同用户旅程》待定问题 #6 收口拆解立项。待认领，认领后按 Spec → Plan → Todo 推进。

## 要解决的问题

- 企业安全合规部门要求关键团队协作动作可审计、可追责，同时开发人员担心一旦“个人会话”被管理者随时审计，员工就会退回私人工具，破坏“个人优先”战略。
- 开发调试过程中日志与终端输出极易混入数据库密码、JWT、Cookie、内网密钥或个人隐私信息，直接将个人会话发布到 Project、生成跨机快照或沉淀为团队知识时存在误泄露风险。

## 预期使用过程

```text
共享出口防泄漏（本机侧）：
  输入：用户在桌面端触发“发布会话到 Project / 生成固定快照 / 沉淀团队知识 / 上传共享附件 / 导出 Patch”
  判断：桌面端在本机对即将离开本机的内容执行规则化敏感信息扫描（不调用远程模型、不上传原文检查）
  执行：若未命中则直接继续；若命中密钥/Cookie/PII 则弹出预览高亮命中片段，提供“一键打码替换”或“返回手工编辑”
  输出：只有经确认且脱敏后的内容才会离开本机进入云端

治理审计与追溯（服务端 + 管理员视图）：
  输入：发生角色变更、知识/地图/技能审核、会话发布/停止共享、任务转交等治理或边界跨越动作
  执行：服务端将结构化、封闭 Schema（仅包含操作人、时间、对象 ID、变更前后枚举/摘要，绝不写正文与密钥）事件写入只增审计账本
  输出：Workspace 管理员可在管理页按时间、类型、操作人分页查验审计流
```

## 已确认的范围

1. **明确的隐私与审计边界**：“个人会话正文不进入组织审计”；模型调用合规侧由企业 AI 网关（HC-244）审计，协同工作台只审计**跨边界共享动作**（发布会话/停止共享/生成快照/上传附件）与**组织治理动作**（角色、成员、知识/地图/技能/Playbook 审核发布）。
2. **四大共享出口本机前置脱敏**：覆盖发布到 Project（含带入历史选项）、生成跨机快照、沉淀团队知识、上传文本/Patch 附件；扫描完全在本地规则引擎完成，默认覆盖常见云厂商 AK/SK、Bearer/JWT、Private Key、Cookie、数据库连接串及常见 PII，支持团队补充自定义正则规则（由管理员维护、只读下发到本机）。
3. **封闭 Schema 不可篡改审计日志**：审计记录采用只增（append-only）存储与严格闭合字段白名单，在数据结构层面杜绝真实密钥或长段会话原文意外写入审计事件；普通开发者无权查看全团队审计记录，跨团队访问统一隔离拒绝。
4. **共享中途持续提醒（已发布会话）**：对于已处于“Project 可见”状态的会话，后续每轮自动定稿上传前同样做轻量本机规则拦截或打码（配置清晰且可预期，避免静默篡改用户真实意图时出现信息失真）。

## 不在本卡范围

- 监控或审查员工未共享的纯本机私人会话内容。
- 替代企业网络侧 DLP（数据防泄漏）或代码托管平台的仓库密钥扫描网关。

## 职责与前置

- 服务端（由后端同事维护）负责封闭 Schema 只增审计日志写入、按团队/时间/类型游标分页查询接口以及团队级自定义脱敏规则列表下发；缺口按分工交同事，前端不私自新增后端 API。
- 桌面端负责本机敏感信息扫描引擎、高亮与一键打码确认交互、以及 Workspace 管理面板中的审计日志查看页。
- 依赖 [HC-239](HC-239-个人优先使用本机Agent.md)、[HC-240](HC-240-Workspace角色管理.md) 与 [HC-241](HC-241-知识分级与审核沉淀.md) 定义的权限与出口点。

2. 组织审计日志的保留期限与导出格式（CSV / JSONL）要求。
3. 自定义脱敏正则规则的语法校验与性能防回溯（ReDoS）限制。
