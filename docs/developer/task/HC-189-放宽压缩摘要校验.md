# HC-189 放宽压缩摘要校验

## 用户问题与已确认结果

内网模型能够生成有用的摘要，但标题改名、乱序、缺项或提到 AGENTS.md、Skill、审批策略时，当前代码会拒绝摘要并显示“未满足安全压缩条件”。

用户于 2026-10-28 选择参考 Pi，要求先生成计划后修复，并明确允许本次用等价步骤替代环境缺失的需求、规格、规划、TDD 和 Review Skill。用户确认的草案已转入本任务与同名 Spec/Plan/Todo；不会声称使用了未安装的 Skill。

目标：摘要模型只需返回可用文本，章节模板用于引导；真正影响可用性和会话一致性的检查继续生效。

## 已确认范围

1. manual、auto、overflow 共用同一接受规则：不验证固定标题、顺序、每节非空，不以正文关键词拒绝全文。
2. 调整摘要提示词，允许正常记录涉及规则文件、Skill 和审批实现的事实，禁止工具执行及输入之外的推断；不把摘要提升为运行权限来源。
3. 保留空/非文本结果、输出截断、输出上限、工具调用、归档来源、消息原子性、收益和事务检查。
4. 补充 fake model 与临时 SQLite 的集成回归，同步用户及既有架构文档。

## 非范围

不改变协议、SQLite/checkpoint 形状、历史重写版本、micro 策略、最近轮数、token 预算、20% 自动收益门槛、自动熔断和传输重试。不新增解析框架、格式纠正调用、配置开关或 CLI 提示改造。不更新依赖，不调用真实模型。

## 可观察验收

- 普通文字、列表、中英文/乱序/额外标题和空可选章节均可压缩成功。
- 正常记录 AGENTS.md、Skill、审批策略的摘要可压缩成功。
- 三种触发均生成可恢复的 full checkpoint；原始 Transcript 不变，近期消息按原规则保留。
- 空白/非文本、工具调用、明确截断、超限输出和编造归档引用仍失败，旧投影和持久化记录不被部分覆盖。
- Todo、执行/审批模式及 snapshot 仍从结构化状态恢复，不由摘要决定。
- 到达唯一演示停点后保持待验收，由用户在内网模型上执行 /compact 验证，不自动完成或归档。

## Review 结论

依据用户批准的等价 Review 流程，复核了 Spec、全部 diff、回归及文档，并检查实际改动边界。

- AST 对比确认生产函数仅 `_validate_summary_response()` 改动、`_summary_sections()` 删除；其余生产方法实现不变，额外变动为提示词、常量和文件说明。
- 格式/关键词只退出接受门槛；工具调用、空结果、截断、输出上限以及后续 Artifact 来源检查仍在同一路径。
- 正常格式矩阵覆盖 manual/auto/overflow；拒绝矩阵在已有有效 checkpoint 上验证失败后投影、完整 Transcript 和三张持久化表的行数不变。
- 正常摘要回归确认持久化后的执行模式、审批模式、Todo 和 snapshot 都来自指定结构化状态；手动最近两轮仍完整保留。
- Protocol、ThreadPersistence、ContextProjector、RuntimeState、依赖及版本文件未改；当前所有 11 个跟踪/新增文件均属于本任务范围。
- 同步用户/架构说明并删除本任务路径中的旧格式枚举和死解析代码，没有第二种接受模式或兼容开关。

结论：未发现本次改动的阻断问题，可交用户验收。全量入口失败、现有依赖不匹配和内网实测缺失属于仍需明确保留的验证限制。

## 用户演示停点

在内网目标环境使用这批改动重启 Harness，打开有足够历史的空闲 Thread，执行 /compact。普通文字或不同标题的有效摘要应显示“上下文已压缩”，继续对话应能接续工作；失败时旧历史继续可用。

当前状态待验收，不自动归档；用户已授权本地提交，禁止推送。没有真实模型输出样本，不能保证每次模型响应都有足够内容或收益；保留的空/截断/来源/收益检查仍可能正确地拒绝或跳过压缩。

用户已确认本轮保留自由格式，暂不增加内容退化检查或内容重试。非空但无信息的响应（例如“好的”）仍可能在来源和收益检查通过后提交；原始 Transcript 保留，模型接续工作的事实完整性仍需真实环境验收。
