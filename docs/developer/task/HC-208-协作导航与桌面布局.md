# HC-208 协作导航与桌面布局

## 当前可做与等待范围（2026-11-10）

可先做左侧账号/工作区/设备/共享会话/交接入口、布局插槽和响应式表现，使用已确认的非 ACP 平台状态或受控 UI 数据检查；按能力是否可用如实展示，不自造 Agent 业务状态。

ACP Agent 发现、配置、能力与实际运行入口的新增开发、接线和调试，都等同事完成 ACP 交付后再安排。本卡不通过假启动按钮或 ACP mock 补齐界面演示，见[当前并行约定](../project/协作任务并行开发约定.md#0-当前调度等待同事交付-acp2026-11-10)。

本卡属于 HC-192。原左侧会话已交付协作导航、三栏布局和独立预览，通过必要冒烟后进入待验收。正式工作台装配归 HC-202。[Spec](../spec/HC-208-协作导航与桌面布局.md) · [Plan](../plan/HC-208-协作导航与桌面布局.md) · [Todo](../todo/HC-208-协作导航与桌面布局.md)

## 需求与交付

左侧承担新的工作区、设备、共享会话和待接手入口，参考 Lody 的信息组织；中央对话及右侧文件/变更保留原 UI。桌面外壳只负责布局和导航，不再写第二套消息区或 Git 面板。

## 范围与目标归属

- 目标：packages/workbench-ui/src/navigation 与 layout，提供工作区/设备/共享会话导航、当前账号入口、协作上下文/交接入口和可组合布局。
- 复用 HC-205 的颜色变量、品牌/图标和公共部件；中间 conversation、右侧 project 通过输入/插槽装配，不拷贝 HC-206/207。
- 顶栏只表达必要的当前会话、原执行设备/项目、接续人/待接手和连接事实，次要动作收进菜单；用户身份没有岗位/角色。
- 明确列表选择、搜索范围、空态/加载/失联/待接手、右区开合和窄窗口时的布局规则；原生窗口拖动/点击区由 HC-202 与 Electron 适配。

## 依赖、并行与负责边界

代码前置为 HC-205 公共出口。UI 本区输入/动作先在 Spec 固定，可用受控数据与 HC-206/207、HC-194/195/196/198 并行开发；真实用户/会话/设备和交接由 HC-202 装配。不会因为后端未完成就在 UI 内自造账号或另一套业务状态源。

本任务只写新导航/布局，不重画原消息/工具、右侧文件/变更或共享主题，不直接联网/执行、不替换 DesktopHost。Lody 截图不是新增定时任务、云更新、worktree 管理等功能的授权；没有后端能力时明确未接入，不放无效入口。

## 验收结果

- [ ] 左侧工作区/设备/共享会话/待接手信息层级清楚，选中可辨识且延续纯色选中风格，图标与文字对齐。
- [ ] 账号入口消费普通用户状态；切换工作区/账号只触发具名动作，不在导航实现登录凭据或业务请求。
- [ ] 中央和右侧由插槽/公开组件组合，同一原组件可显示；新布局不覆盖对话头像、工具卡、文件页签或 Git 交互。
- [ ] 冷紫浅/深主题统一，左栏宽度和可调/响应式行为有明确约束；不同高度/缩放不挤坏右侧上下结构或原生窗口按钮。
- [ ] 原设备/项目、接续人、交接进展和失联状态可以从输入展示，当前选择不被他人发言或交接擅自覆盖。
- [ ] 键盘、焦点与设置入口可用，设置保持居中弹窗；开发夹具不进入生产数据，不自动加入截图里的额外功能。

## 验证与交付

`npm --workspace @workbench/desktop run preview:navigation` 构建并打开了 macOS Electron 预览。展开示例设备和项目、选择会话后，中央出现 `ConversationView` 的消息，右侧出现 `ProjectDock` 和示例文件树。关闭窗口后进程正常退出。构建完成后的桌面类型检查与 `check:boundaries -- --self-check` 通过。

统筹核对了生成页面的 CSP 和右栏收合逻辑。右侧覆盖层拖宽使用临时宽度，保留并排布局的偏好。真实数据装配与完整场景分别由 HC-202 和 HC-204 验证。[预览启动说明](../../user/独立桌面工作台.md#协作导航与三栏预览)

2026-11-11 根据用户的视觉反馈，侧栏采用设计稿的 13px 导航字号，工作区和搜索控件减少边框，选中填充使用公共冷紫主题变量。预览的设置弹窗接入已有外观选项。中央容器按剩余高度排列消息和输入框，顶栏为 macOS 原生按钮留出空间。重新构建后在实际深色窗口核对了选中会话、完整首条消息、底部输入框和右侧文件面板。浅色窗口效果留待核对。
