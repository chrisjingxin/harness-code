# HC-198 会话交接与内容引用

## 需求与交付

用户可把同一个会话交给另一普通用户，并在提问中引用已有会话或消息。交接保留原机器和上下文，引用预览与实际发送内容一致。

属于 [HC-192 总任务](./HC-192-协作工作台与会话交接.md)，共同边界以 [独立桌面总体设计](../architecture/多人协作工作台顶层设计.md) 为准，参考来源见 [Lody 对照](../research/192-Lody协作能力对照.md)。设计基线为本地提交 `0250561`。本文是待审阅的子 Task，不是已确认 Spec 或实施计划，尚未认领或实现。

## 范围与目标归属

- Java handoff/reference、平台契约与 UI 用例端口；交互由 HC-206/208 增量表达，HC-202 真实集成。
- 交接说明、发起/取消/确认、并发状态更新与事件去重。
- 同工作区会话/消息检索、选区、固定预览草稿、发送事务与来源定位。
- 原设备在线/离线、来源继续输出、来源权限变化与已发送快照保留。

## 依赖与范围边界

代码前置为 HC-194 最小服务；先与 [HC-195](./HC-195-共享会话与实时同步.md) 评审消息/执行登记/事件及同事务接入方式后，可并行实现独立 handoff/reference。真实发送与引用原子保存须等 HC-195 对应代码停点接通，不以替身验收代替。

不引入岗位角色，不转移设备凭据或自动迁机，不复制会话/私有检查点。首版引用由平台形成普通文本随输入发送，不要求新增 MCP 或跨 Agent 状态转换；附件存取与发送主链在 HC-195/202 衔接。

## 并行认领与接口交付

本任务主责 Java handoff/reference、对应 schema/fixture；HC-195 主责消息/执行保存，双方共同固定事务入口，避免重复改写同一发送服务。交接状态/操作、引用搜索/快照/来源失效结果交 HC-206/208 消费，HC-202 装配，不在后端任务重画对话和侧栏。

可与 HC-195、设备/ACP/项目和 UI 分线并行，UI 尚未绑定前用受控客户端观察真实业务结果。聚合契约和 SQL 版本号由统筹顺序集成；认领/接口/证据规则见[并行开发约定](../project/协作任务并行开发约定.md)。

## 验收结果

- [ ] 新会话当前接续人为创建者；发起交接只产生 pending，目标用户确认后才原子更新 accepted、接续人和事件。
- [ ] 同一会话最多一笔 pending；取消/接手并发只发生一次有效变化，旧页面不能接手已取消记录。
- [ ] 只有目标普通用户可确认接手，其他成员的普通参与能力不变，不依据岗位或角色判断。
- [ ] 交接保留原平台会话、设备、项目和 ACP 绑定；原设备离线可记录交接，但不假装能继续执行。
- [ ] 用户选中来源后预览生成固定草稿，来源后续输出不改变快照；明确刷新生成新草稿并重新预览。
- [ ] 发送再次核对访问与归属，在同一事务保存消息、引用和执行登记，实际输入与已预览快照一致。
- [ ] 发送前来源不可访问时阻止发送；已发送快照不因来源变化被改写，点击可定位或提示来源不可用。

## 验证与后续流程

用两个普通用户测试交接竞争、重试与来源变更，检查数据库事务和实际提交给执行端口的文本；不以生成摘要代替同会话接续。
