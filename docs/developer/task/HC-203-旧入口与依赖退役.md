# HC-203 旧入口与依赖退役

## 需求与交付

让分叉后的代码库真正成为独立桌面产品，迁移完成后删除旧入口和无消费者依赖，避免新工程看似分包却仍由旧 CLI 或协议驱动。

属于 [HC-192 总任务](./HC-192-协作工作台与会话交接.md)，共同边界以 [独立桌面总体设计](../architecture/多人协作工作台顶层设计.md) 为准，参考来源见 [Lody 对照](../research/192-Lody协作能力对照.md)。设计基线为本地提交 `0250561`。本文是待审阅的子 Task，不是已确认 Spec 或实施计划，尚未认领或实现。

## 范围与目标归属

- packages/cli 中旧产品入口、TUI/OpenTUI、Web server、PresentationCoordinator/WebUiGateway 及无消费者实现。
- 根 workspaces、脚本、锁文件、依赖维护/检查、打包与用户/开发文档。
- 旧 packages/protocol：只保留确实仍被 Harness 自用的内部生成/通信，平台契约保持独立。
- 迁移来源的相对源码链接、历史任务口径和旧测试：按实际消费者清理，不为文档链接保留死代码。

## 依赖与范围边界

实现前置：[HC-202](./HC-202-桌面工作台视图迁移.md) 子任务的需求/Spec 可先评审，前置依赖未满足时不得宣称集成已经完成。目标包名和具体接口需在对应 Spec 固定，当前目录建议不等于已有源码。

先迁出并验证再删除；不以删除测试代替通过回归，不顺带改写模型/工具逻辑。该任务只影响当前分支，不自动修改 master、备用仓库或内网仓库，不删除设计稿或用户数据。

## 并行认领与接口交付

可提前只读整理消费者/依赖退出清单，与实施线同时准备；实际删除必须等 HC-205～208/201 各来源已迁出且 HC-202 对应替代链路可用并有证据。不得为清理旧入口而删掉尚未迁出的工具/审批/文件/Git/Trace 组件、公共资源或设计稿。

本任务负责最终旧入口、无消费者依赖与相关旧测试收口；业务/视图实现仍由对应任务负责人处理。根锁/入口/构建配置等共享改动由统筹串行集成。现有视图只保留一处活跃实现，不长期复制维护；规则见[并行开发约定](../project/协作任务并行开发约定.md)。

## 验收结果

- [ ] 新产品默认安装、开发、构建、检查和发布路径不启动/打包旧 CLI、TUI、独立 Web 或接管网关。
- [ ] 最终无新包到 packages/cli/旧协议/Harness 内部结构的错误依赖；可选 Harness 集成无反向必需边。
- [ ] 通用工具链不要求 Bun/OpenTUI/Python；Python 与必要内部协议只由 Harness 可选制品/检查需要。
- [ ] React、文件/Git、Harness Trace/设置各项迁移证据完整，无长期复制维护、双写采集或兼容 Controller。
- [ ] 无消费者的源码、依赖和旧测试被删除；保留下来的测试覆盖实际新行为，文档链接仍有效。
- [ ] 根 AGENTS、README、用户指南和架构总览描述真实新入口，不残留已退役启动指引或把目标当既有能力。
- [ ] 设计稿、参考材料与用户的项目/Agent 数据保留；工作范围不扩散到其他分支或仓库。
