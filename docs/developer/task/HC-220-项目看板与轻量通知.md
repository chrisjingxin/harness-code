# HC-220 项目看板与轻量通知

## 要解决的问题

Project 成员需要快速了解每个人的会话简报和任务进度，避免逐条下载别人全部对话。看板负责信息汇总，轻量通知负责提示变化，正文阅读仍由用户主动发起。

本卡实施前端页面和通知消费，按同名 Spec → Plan → Todo 推进。服务端聚合模型、通知协议和投递实现由 HC-212 提供。

## 本卡负责

- 使用中央独立页面呈现 Project 概览：成员、会话简报、任务统计和分组列表。任务分组、成员范围和动作以后端结果为准，不自创另一套业务状态。
- 点击成员会话进入 HC-218 的本机或远端只读页面，点击任务进入 HC-219 的详情；不把看板塞进会话的对话/轨迹/文件标签，也不为看板占用右侧文件区。
- 清楚区分原设备在线状态、最近上传时间和当前电脑是否已同步正文，不用“已连接”概括。原设备离线时仍可查看已上传的简报及可读材料。
- 消费 HC-212 用户级轻量 SSE 及聚合查询，按正式契约处理断线与重放反馈；沿用同一身份与客户端基础，不为每个页面建立独立通知连接。
- 通知消费随已登录桌面身份运行，用户停留在会话页也能收到元数据变化；切换到看板不会另开连接。通过 HC-218 更新成员会话条目，通过 HC-219 更新任务数量/状态和知识版本提示，再由 HC-217 展示导航结果。
- 收到事件后只刷新相关简报、任务、知识版本提示和未同步标识；使用 HC-218/219 的消费接点，不另取所有正文，不替换已选引用、不自动发送、不跳转当前页。
- 点击看板条目调用 HC-217 的统一定位动作，展开目标成员并定位会话，或打开 HC-219 任务详情；主动点击才改变导航选择。后台简报更新保持成员折叠、搜索及当前选择。
- 退出或切换账号/Project 后按当前可见范围更新展示，保留属于本人的草稿和阅读位置。通知尚未交付时保留明确的手动刷新路径，不编造“实时已连接”。
- 页面使用现有冷紫主题及中性背景，适应不同宽高，避免大面积染色和过多边框；浅深色与确认预览一致。

## 建议停点

| 停点 | 用户能看到什么 | 真实接线前置 |
| --- | --- | --- |
| 1. 独立看板 | 成员进展、任务概览和详情入口，浅深主题/自适应布局 | 与 HC-217 确认页面接点，HC-218/219 确认目标定位动作；可先独立预览 |
| 2. 聚合查询 | 真实 Project 看板及手动刷新 | HC-212 看板查询交付；不等待 SSE 全部接通 |
| 3. 轻量更新 | 通知驱动元数据和更新标识变化，正文保持主动同步 | HC-212 用户通知流及前三卡消费接点 |

## 目录归属与并行

- 建议独立模块：`apps/desktop/src/renderer/features/board/`；本卡负责看板展示及 desktop 的通知消费模块，具体客户端文件拆分在 Spec 确认。
- 导航和页面根装配交 HC-217；会话简报/正文同步的唯一请求适配归 HC-218；任务/知识详情归 HC-219。本卡调用公开接点，不复制三者的业务模块。
- 可与前三卡并行开发独立界面，按 HC-212 的查询和通知停点分别接真实接口；“界面可做”“最小接点已交付”“真实联调可做”分别记录。
- main/preload 身份/公共客户端和共享根出口串行集成，不在公共文件中与其他卡同时改动；不修改服务端、Runner 核心或 ACP 设计与实现。

## 验收标准

- [x] 看板展示当前 Project 的成员会话简报和任务情况，点击进入正确的会话模式或任务详情。（正式窗口实点远端只读会话和任务；本机或跨设备判定沿用 HC-218。）
- [ ] 页面数据来自已交付聚合接口，失败保留可读内容并提供刷新；预览替身不进入生产默认入口。
- [x] 通知只更新相关元数据和更新标识，未下载的远端正文保持未同步，不因看板、事件或重连批量下载。（正式窗口和独立断流联调均无正文历史 GET。）
- [x] 停留会话页时通知仍能刷新左栏条目及任务数量；打开看板不会重复建连接；只有用户点击看板条目才展开并定位目标成员/会话。（正式窗口在同一订阅内多次打开看板，任务数量从 1 增为 2。）
- [ ] 后台更新不改变当前页面、成员折叠、搜索、滚动、草稿和固定引用，也不触发本机或他人 Agent。
- [x] 在线、上传及本机同步状态分别表达；断线/未接入不显示虚假的已连接。（正式窗口校验三项状态；独立联调确认断线进入重试。）
- [ ] 浅深主题、图标与文字基线、不同高度布局符合原 `project-collaboration` 视觉预览（已清理），不重画中右区域。

## 必要验证与非范围

实施时做受影响构建/类型/边界检查，冒烟一条“打开真实看板 → 定位会话/任务 → 接收一条轻量更新 → 正文仍未下载”的正常路径。聚合查询和 SSE 可按上游交付分次记录，完整重连矩阵、双设备和 Win/Mac 留 HC-204。

本卡不设计新的通知载荷、服务端状态机、Kafka/数据库方案或 Agent 调度，不实现远端控制、后台全文预取或新的知识检索服务；缺少接口时登记依赖给同事。

## 2026-11-17 实施证据

### 独立看板与通知续读

- 独立看板使用隔离 Java/MySQL 返回的聚合数据。Chrome 构建预览验证浅色 1050 px 三列、深色 415 px 单列，均未出现横向裁切。会话和任务动作传出对应服务端 ID，预览动作由测试接点接收。
- `acf2600` 的 Java 服务与独立 MySQL 8.4.11 中，真实响应含 3 位成员、上传水位 2 的会话及待处理任务。会话分别显示原设备离线、最近上传与本机未同步正文。
- 隔离登录适配器将服务端真实 SSE 字节流交给通知模块。收到 `conversation.brief_updated`（游标 1），保存后主动断流，重连携带 `Last-Event-ID: 1`，随后收到 `task.assigned`（游标 3）；游标 1 仅分发一次，另一账号的本机游标仍为 0。服务访问日志没有正文历史 GET。本轮证据在本机 `/tmp/hc220-smoke.EB0aUB/module-evidence.json`。

### 正式桌面装配与验证

- 共享文件交接后，看板和通知接入现有认证客户端及正式窗口。工作台复用 HC-217 导航与项目刷新、HC-218 会话简报和本机正文水位、HC-219 任务数量及知识版本刷新入口。看板暂时刷新失败时保留本项目已有内容，失去访问权限时清除。
- 用正式 macOS Electron 构建、独立窗口数据目录、`acf2600` Java 服务和隔离 MySQL 8.4.11 实测。登录后立即点击「看板」，验证三位成员、手动刷新及原设备离线、最近上传和本机未同步三个提示；点任务打开同 ID 的详情，点另一成员的会话展开该成员并打开只读页。修复了个人导航记录稍晚返回会把首次点击切回旧页面的问题，修复后复验通过。
- 停留在只读页时，另一账号上传新简报并指派新任务。正式窗口收到事件 4（简报）和 6（任务），简报刷新、左栏待处理任务从 1 增为 2，页面、成员展开和搜索保留；正文仍提示未同步，服务端正文历史 GET 为 0。再打开看板时可见新简报和任务，同一登录期间只使用一条 SSE。
- 退出后旧连接关闭。第二账号进入同一团队时从游标 0 建立新连接，未继承第一账号已落盘的游标 6，也未收到第一账号的事件。两次退出均关闭流。
- 修复关窗时读取已销毁窗口而弹出主进程异常的问题。正式 Electron 带着活跃通知关窗、在同一进程重开并读到看板，再次关闭后正常退出。两次关闭都结束对应 SSE，主进程未捕获异常为 0，退出码 0。本机证据：`/tmp/hc220-window-close.8tobh9w3/close-evidence.json`。
- Java 将注销或关窗后结束的 SSE 请求记作 500。注销场景的 Java 日志显示 Spring 异步处理缺少认证上下文。前端登录、收取通知、注销和关窗均正常，服务端现象交由统筹转 HC-212 核查。
- 桌面 `npm --workspace @workbench/desktop run build`、`npm --workspace @workbench/desktop run typecheck`、`npm run check:boundaries -- --self-check` 和 `git diff --check` 通过。正式证据在本机 `/tmp/hc220-desktop.wzqu1czu/` 的 `evidence.json`、`access/http.log`、`board.png` 与 `java.log`。用户操作与架构说明已更新；环境没有 `openwiki` 命令。
- 本轮未单独触发真实知识更新、看板失败分支、团队切换或草稿/固定引用等同时编辑场景；跨平台、正式桌面断线组合与完整回归留 HC-204。
