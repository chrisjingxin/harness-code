# HC-233 团队知识自动索引与读取

## 当前阶段

2026-11-19 用户确认首版沿用当前知识列表，只自动注入标题，需要正文时通过工具读取；暂不增加摘要，实际使用不满足需求时再扩展。本卡需求范围已确认，状态仍为待认领；本轮已按用户要求交付同名 Spec 草案供审阅，未认领、编写 Plan / Todo 或修改生产代码。Project 看板、他人会话简报和产品任务不进入自动上下文范围。

## 要解决的问题

当前团队知识只有用户手动 `@` 或在详情中选择引用后，正文才会在发送时进入 Agent 上下文。Agent 不知道团队已有的规约、技术名词和经验，用户容易遗漏相关知识。

希望像 Skill 的发现和读取机制一样：先让 Agent 看到简短目录，发现与当前任务有关时，再通过真实读取能力获取正文。这里复用的是分层加载方式，知识仍是团队参考资料，不能自行授予执行权限。

## 预期使用过程

进入本人本机会话 → 发送时自动附带当前团队知识标题目录 → Agent 根据标题判断相关性 → 通过只读工具读取选定版本正文 → 在当前会话中使用并显示来源。

例如，团队已有「接口错误码规范」。用户提出新增接口需求时，Agent 从标题目录发现这条知识，再通过工具读取具体规范，不必先由用户 `@`。

## 已确认的首版范围

1. **自动提供标题目录**：只使用现有知识列表中的标题作为业务内容，不注入摘要、分类说明或正文；知识 ID 和版本用于准确定位及固定版本读取。目录来自当前账号有权访问的 Workspace，默认不含归档项。
2. **提供真实读取能力**：优先由桌面提供只读 MCP 工具，经标准 ACP 会话配置交给实际 Agent。名称写在提示词中不算接通，Agent 必须能实际发起调用并取得正文。
3. **保留显式引用**：HC-219 的 `@`、固定版本和取消本次引用继续使用；同一条知识同时被自动发现与手动引用时，不重复附带同版本正文。自动目录不得把用户选定的旧版悄悄换成新版。
4. **版本与更新**：一次读取指定确定版本，返回来源和版本。A 新建、编辑知识后，同团队 B 的知识列表沿现有通知刷新可见；不追更已注入 Agent 的目录或正文，不改写已发送记录，不触发全库正文同步或 Agent 执行。
5. **控制目录大小**：稳定排序并设置明确长度上限；超过上限时说明目录不完整，保留分页或搜索发现能力，不能静默漏掉其余知识。首版不引入向量库或自动生成摘要的模型调用。
6. **沿用已有界面**：保持当前知识创建、编辑和列表界面；读取过程复用现有工具展示，来源可定位至知识详情，保留已有主题和中间对话结构。

## 已确认的接入缺口与职责

- 当前 `KnowledgeSummary` 已有标题、知识 ID 和当前版本，满足标题目录首版；`listKnowledge` 与 `readKnowledgeVersion` 可直接复用。没有用途摘要不再是本卡缺口或前置依赖，不修改服务端 API、数据库或现行线上契约，也不提前读取所有正文补摘要。
- 当前 `packages/acp-runtime/src/session.ts` 在新建、加载与恢复会话时均传 `mcpServers: []`。Harness Agent 已有会话 MCP 接收能力，但桌面尚未连接。本功能依赖标准 MCP 配置的通用接线，不新增专用 ACP 协议方法，也不把知识业务写进 Harness 内核。
- 本卡由桌面侧负责知识目录、上下文装配、只读读取桥接及界面消费；涉及 ACP 通用接线的改动归属需与对应同事确认，沿用其现行方案，不新增知识专用 ACP 方法。
- 与 HC-219 分开登记，原卡待验收状态和既有交付范围不变。当前参考结论与替代方案见[源码调研](../research/233-团队知识按需上下文.md)。

## 首版实现约束

- 用户明确暂不增加用途摘要，现有知识无需补录或迁移。标题可能不足以表达某些知识的使用场景，首版通过清晰命名和保留手动 `@` 使用，后续根据实际效果决定是否扩展摘要或召回方式。
- 首版每次发送附带有长度上限的目录，目录来自本地元数据缓存；它不等于每轮请求 Java。目录读取按现有身份和接口执行。本期不实现历史目录差量或已注入内容的热更新。
- 首版保持「相关时读取」。目录中出现某个标题，不等于已经阅读该条知识正文；不增加逐轮强制加载全库正文的规则。

## 拟定验收结果

- 同团队 A 新建或修改知识后，B 已打开的知识列表收到既有通知后刷新可见；后进入知识页也能读到已保存条目，无需重启或重新登录，不要求替换已注入材料。
- 不操作 `@`，向本人会话提出与某条知识有关的任务，Agent 能看到目录并通过工具读取对应正文；正常回答能追溯到实际读到的固定版本。
- 不相关的对话不读取知识正文；只查看目录不会产生全库正文请求。目录超限后仍能查到未展示条目。
- 手动选择版本、取消草稿引用和已发送历史不被自动加载破坏；更新、归档和权限变化沿用实际服务语义，失败时明确告知未读成功。
- 工具只服务当前账号、团队和本机会话；不把登录凭据传进模型文本，不具备操作其他成员 Agent 或修改团队知识的能力。
- 实施时只做必要构建、类型与一条核心冒烟；完整双平台、组合回归和多 Agent 验收由后续统一验证承接，不能以静态调研充当运行证明。
