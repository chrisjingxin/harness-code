# HC-193 独立桌面工程与分包：实施计划

状态：已获统筹审查并派发实施，基础停点已实现、待验收（2026-11-06）。依据已经统筹审查并补齐工程边界的 [Spec](../spec/HC-193-独立桌面工程与分包.md)，执行清单见 [Todo](../todo/HC-193-独立桌面工程与分包.md)，结果写回 [Task](../task/HC-193-独立桌面工程与分包.md)。本计划已执行到基础停点，实际证据与未覆盖项见 Task；以下保留实施步骤供复查。

## 现状与交付方法

现有根 npm 安装图包含旧 CLI 与 vendor，默认构建启动 TUI，项目检查还前置旧协议。只增加 Electron 页面无法证明新产品独立。本计划先收窄安装图，建立公共契约和包骨架，再组合真实原生窗口，最后在干净的临时源码副本检查安装与启动。

输入：七个新工程目录与 Spec → 判断：依赖、导出和原生请求是否符合边界 → 执行：只安装和构建新平台 → 输出：无需 Harness/Python/Bun 的基础桌面窗口和实际冒烟记录。

## 唯一可演示停点：独立基础桌面

开发者按新说明安装后执行 `npm run dev`，出现真实 Electron 窗口；可以选择目录或取消、切换主题、调整 80%～150% 缩放并恢复 100%。构建产物也能独立打开相同窗口。基础内容不展示聊天样例，Runner 不自动启动。新包检查接受声明的公开入口，能拒绝旧依赖、反向依赖和跨内部路径访问。

下面是这个停点内部按依赖排序的步骤，不是多个独立验收停点。统筹审查 Plan/Todo 并派发实现后推进至此；通过必要冒烟后只标待验收并主动回调，不自动提交、推送或归档。完整回归与另一操作系统验收由 HC-204 汇总。

## 1. 收窄安装图与公共构建配置

修改根 `package.json`、`package-lock.json`、`.npmrc`，新增 `tsconfig.base.json`。根 workspace 显式列出 Spec 七个目录，按 contracts、核心骨架、UI、应用排序；删除根对旧 CLI/OpenTUI/Python 的安装或生命周期前置，移除根 Bun 引擎要求和旧 peer 冲突规避。旧源码、旧包声明、Python 锁文件和 vendor 文件不删除，均不进入新安装图。

新增七个目录各自的 `package.json` 和 `tsconfig.json`；内部依赖使用 npm 可解析的本地 workspace 版本，与当前 VERSION 一致，不发布或访问私有 @workbench 包源。根仍只使用一个锁文件；首次按新声明生成并审查，日常 `npm ci` 冻结安装。根直接工具只保留新工程和工程检查实际需要的依赖，版本按 Spec 固定，禁止沿用旧锁中与新产品无关的条目。

## 2. 建立契约、骨架与依赖检查

新增 `packages/workbench-contracts/src/index.ts`，定义 `ThemeMode`、`ZoomAction`、`WindowState` 与 `DesktopHost`。目录端口、状态读取、主题设置、具名缩放动作和取消订阅按 Spec 定义；类型与注释说明取消、失败及生命周期。新增下列骨架文件，只导出包标识，不实现后续业务：

- `packages/runner-core/src/index.ts`
- `packages/acp-runtime/src/index.ts`
- `packages/project-service/src/index.ts`
- `apps/runner/src/index.ts`（仅装配骨架，无服务监听、Agent 拉起或设备登记）

五个通用包各提供 `.` 导出和匹配的类型声明 / JS 构建产物。源码只通过包名和 exports 导入；不能借 tsconfig alias 直接连到另一个包的源码。

新增 `scripts/workbench/check-boundaries.mjs`，使用已声明的 TypeScript 工具解析新源码与配置，核对根 workspace 白名单、包依赖方向、公开 exports、跨目录相对导入和安装锁中禁用包；检查 renderer/UI 中的 Node/Electron 访问。扫描范围只限新平台及其构建配置，旧迁移来源不参与通过判定。检查器通过 `--self-check` 在内存或临时夹具验证合法子入口可通过，以及旧依赖、反向依赖、内部路径等会失败，不改真实生产源码作负例。命令退出码和诊断须能定位违规文件或包。

## 3. 组合主进程、preload 与基础 React 窗口

新增 `apps/desktop/electron.vite.config.ts`，为 main、preload、renderer 分别设置入口；preload 输出适配 Electron sandbox 的单文件产物，不把未打包的业务模块或 Node 能力泄漏给 renderer。开发只载入实际本机开发服务器，构建预览只载入本地页面；不引用旧 Web server。

新增以下桌面文件，职责按上下游分开：

| 文件 | 修改内容 |
| --- | --- |
| `apps/desktop/src/main/index.ts` | Electron 启动、基础窗口阶段关闭/重开/退出流程；无 Runner 托管 |
| `apps/desktop/src/main/window.ts` | 原生窗口、平台标题栏、contextIsolation/sandbox、导航与新窗口限制 |
| `apps/desktop/src/main/desktop-ipc.ts` | 校验主 frame 与参数，处理目录选择、主题、实际 webContents 缩放和状态订阅 |
| `apps/desktop/src/preload/index.ts` | contextBridge 暴露逐方法端口，订阅只返回业务状态并可解绑 |
| `apps/desktop/src/renderer/index.html` | 本地页面入口与适合开发/生产的内容安全策略 |
| `apps/desktop/src/renderer/main.tsx` | 注入受限 DesktopHost，挂载通用 UI |
| `apps/desktop/src/renderer/env.d.ts` | window.workbench 的契约声明 |
| `packages/workbench-ui/src/index.ts` | 唯一公共组件入口 |
| `packages/workbench-ui/src/workbench.tsx` | 真实基础内容、目录状态、主题和缩放控件、简明错误 |
| `packages/workbench-ui/src/theme.css` | 主题变量、响应式基础布局、拖动/点击区、缩放后的可用布局 |

主进程持有主题/缩放状态，renderer 以返回或订阅的实际值渲染；动作枚举、范围和调用来源由主进程校验。系统主题变更按 Spec 推送；目录取消不覆盖先前选择。窗口关闭的临时规则明确留给 HC-196/202 接入后台/托盘，不在本任务预建空生命周期业务。

## 4. 切换默认命令与工程一致性入口

根 `dev` 定向启动新桌面，准备所需公共包后交给 electron-vite；根 `build` 按依赖顺序构建七个工程，`typecheck` 检查同一清单，`check:boundaries` 调用新检查器。`apps/desktop/package.json` 提供 `preview`，供启动已构建产物；Runner 只有构建/类型入口。

根 `project:check` 改为新边界检查加现有 `project:tool -- project:check`，去掉旧 `protocol:check` 前置；移除根默认脚本中旧协议生成与校验入口。保留 `docs:check`、`tasks:sync`、`tasks:check`、认领和版本命令的单一入口。旧依赖同步、TUI 测试等根脚本若仍指向已退出 workspace 的包，同步移出新默认脚本清单；保留其源码供后续迁移，不增加 legacy 命令别名或兼容包装。

修改 `scripts/project/release.ts`，从根 workspace 清单读取新包版本检查对象；`checkRelease` 与 `setVersion` 使用同一对象，不再读写旧 Python/CLI 版本字段。当前 VERSION 和 CHANGELOG 不升版；新 manifest 初始化为当前值。按需修改 `scripts/project/project-management.test.ts` 的最小临时夹具和版本断言，验证工程检查无需旧目录；不扩成全库回归。`scripts/project/index.ts`、`docs.ts`、`tasks.ts` 和 `scripts/typescript_loader.mjs` 保留现有职责，只有实际发现新边界所必需的问题才改动。

| `npm run dev` | 原生开发窗口真实显示，关闭后可停止本次开发进程 |

当前读取到的宿主为 macOS 15.4 / x64、Node 22.23.2；实施时重新记录实际 Node/npm、Electron 与系统版本。用本机原生窗口实际点击选择/取消、切换主题并检查 80/100/150% 值及原生窗口按钮；至少保留启动、选择结果和主题/缩放截图或等价可复查记录，检查主进程缩放返回值和 webContents 实际值。未执行的 Windows 标题栏/托盘、安装包签名和完整业务测试明确留给 HC-204，不写成已通过。
