## 1. 顺序、范围和前置

现有对话区的视觉与交互已经可用，但输入仍绑定旧 Web 状态。按下面三个真正可见的停点迁出同一套组件，把输入换成本区视图值和动作：


## 4. 停点一：消息、普通工具与滚动

1. 在 `conversation/` 建立第 3 节 Spec 所需的稳定条目 ID、显示模型/动作及个人状态局部变更类型，先以真实 `ConversationTimeline` 子组件渲染消息、普通工具文本与历史交互。引用 HC-205 `RoleAvatar`、`Markdown`、`RenderingActions`，按最终生效 CSS 迁消息、工具和滚动区规则。
2. 保留相邻 Agent 内容/工具/推理的顺序、末项流式光标、状态可读标签及贴底 48px 跟随；上滚时新内容只改变提示。按 scope 和条目 ID 保存展开、滚动锚点/偏移；隐藏时暂停滚动与抢焦点，恢复后不因隐藏期间的新内容强制跳到底。
   按 Spec 第 3 节接入装配方提供的本地 `contentRevision`，随滚动状态保存 `seenContentRevision`。预览在时间线外维护版本，随样例新增或同条消息更新一同递增。组件用版本判断新输出，恢复位置时仍使用稳定条目锚点。
3. 统筹在相应时隙提供停点一所需根出口、区域 CSS 和第 3 节预览；受控外壳用 `hidden`/`inert` 模拟中央页签，证明组件卸载/恢复与个人状态分区，不实现正式页签。需要复制时经已存在的 `DesktopHost.copyText` 注入，不走浏览器旁路。
4. HC-207 公共图标和 Diff 函数未就绪时仍可完成本停点；此时路径类型图标及结构化工具块明确留待停点三，不冒充完整工具迁移或另写临时映射。

## 5. 停点二：输入、提及与个人草稿

**可见结果：**同一预览的 `ConversationView` 组合停点一真实时间线和输入区；多行/中文输入、命令/能力菜单、文件提及、发送/取消回调和身份切换均可操作。引用、附件、排队与失联以受控值显示，界面如实区分回调受理与真实执行。

   按 Spec 第 3 节使用可选的 `tabCycle` 轮转模式。预览覆盖空闲时按配置切换，以及无声明或草稿有内容时按 Tab 继续焦点导航。
2. 迁与宿主无关的 `@` 词法、光标替换、八行窗口和菜单键盘/鼠标策略。受控候选请求同时携带 `ConversationScope` 与 `ProjectTarget`；目录选择只浏览，文件选择只回填，显式打开才发 `preview/central` 意图。候选查询/排序由装配方或 HC-199 提供，不在本区读取项目或导入 HC-207 私有状态。
3. 受控预览以完整 `namespace/accountId/workspaceId/conversationId` 分区维护草稿、光标、引用/附件选择及修订号。检验两个账号/会话切换、旧候选迟到、发送结果迟到及用户继续编辑；只有原身份仍有效且修订相同的确认受理才清空相应旧分区。未知结果保留草稿，不自动重发。
4. 同一预览注入受控交接/引用和排队/失联显示，核对来源快照不被新消息改写；缺失能力时按钮禁用并说明原因。只验证回调参数和界面状态，不触发真实消息发送、取消、文件打开或授权。
