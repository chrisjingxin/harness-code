**状态：A–E 的 P0 代码、测试和说明已实现，本次交付一个完整闭环。**

依据 [Spec](../spec/HC-183-双模型协作.md) 和 [完整设计](../architecture/fusion-dual-model-workflow-design.md)。每步先测试、后实现、再回归与文档同步。本轮按用户“接着完成文档功能”的要求，把依赖紧密的 B–E 合为一个可演示 P0 闭环。实现顺序：持久化与写者 → 快照和验收 → 角色与工具 → Managed Worker/Host → 协议与共享交互。

## 停点 A：能配置和查看模型组合

1. 增加配置行为测试，观察未支持 Fusion 的失败。
2. 新建 `config/fusion.py`，实现不可变配置、逐层合并和引用校验；接入 `config.py` 与 Manifest。
3. 增加冻结绑定测试，覆盖凭据、能力、池容量、目录边界、指纹与脱敏。
4. 新建 `runtime/fusion/profile.py`，复用模型校验与指纹；冻结两角色和检查计划。
5. 覆盖现有 Host `config.show` 响应；运行配置、执行绑定与相关回归测试。
6. 同步模板、模型配置说明、架构实施状态；记录实际检查结果。

查看方式：配置 `fusion` 后运行 `harness --config <可信文件> config show`，输出有组合 ID、角色 Profile ID、检查 ID 与超时，没有命令或模型凭据。A 交付时只提供配置；现可在本地 Build 用 `/fusion <组合ID>` 启动完整流程。

## 实际落点与维护顺序

1. `store.py`/`guard.py` 维护任务版本、写者和副作用；完成与写者释放一起提交。
2. `snapshot.py`/`service.py` 维护报告摘要、检查回执、票据和安全续接。
3. `roles.py`/`tools.py` 维护角色能力与控制工具；风险分类、审批和提示词同步修改。
4. `host/fusion_runtime.py` 维护稳定 Worker checkpoint、分轮 execution、真实审批及资源释放。
5. Host/Protocol/共享 Feature 维护启动、重连、状态、恢复和取消。

详细方法、参数、状态流转与对应测试见完整设计。后续 agent 以文件和符号定位，不沿已删除的 `compose/verification.py` 建第二条执行路径。
