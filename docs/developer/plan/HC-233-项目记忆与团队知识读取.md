## 解决方式与实现边界

用户主动发送 → 按真实服务、账号和会话 Team 取两份完整正文与知识标题 → 同一 Agent 经 HTTP MCP 查询及提出更新 → 正常终态复核来源与条目版本 → 原子保存 → 下一轮复用。

新增代码集中 `desktop/src/main/workbench-context/`：`types.ts` 约定业务记录与可信来源，`memory-store.ts` 维护 Markdown、修订与短锁，`knowledge.ts` 查询/缓存现有知识接口，`mcp-server.ts` 提供回环 HTTP MCP，`service.ts` 管理会话凭据、轮次、提案与装配。只消费已有协作客户端和通用 ACP 公共类型，不新增线上接口或修改 HC-239 个人会话业务。

## 停点 1 · Markdown 可读、可确认保存

实现账号/Team 隔离、YAML 文件头与简短业务正文、来源与权限核对、条目修订、同范围写锁、临时文件替换、4 KiB 单条及 8 KiB 正文写入限制。初始化由现有 Project、仓库及本人目录生成；无团队不读写。确认目录立即保存，映射不授予目录权限。

查看方式：隔离临时目录运行必要主路径冒烟，查看两份 MD、正文完整性、修订号、相同事实不写、过期条目冲突与超限保留原文件。

## 停点 2 · 真实 HTTP MCP 与上下文模块

提供四个具名工具，服务只监听 `127.0.0.1:0`。临时凭据绑定账号、登录代次、会话、Team；异步结束再复核身份。标题首屏缓存 60 秒、合并并发与通知失效，正文只读固定版本。每轮完整装配两份正文与 ≤256 字节提醒，知识目录独立 8 KiB 预算。Agent 提案 pending，正常终态按条目合并，取消/失败/旧身份不写。

查看方式：使用真实 HTTP JSON-RPC MCP 调用工具，验证初始化、tools/list、读知识固定版本、提案 pending/成功保存/取消丢弃、下一轮读取新正文与令牌撤销。使用受控 Agent 证明实际请求，不接触真实模型密钥。
