## 1. 本机工具与隔离数据库准备

这些是停点一的前置步骤，不因缺少服务器或内网账号而暂停普通本机开发。后续实施授权后才下载/解压和运行，普通 `npm ci/build/dev` 不隐式安装或启动它们。

### 1.1 一条按宿主选择制品的路径

先记录实际 OS、系统版本、CPU 与进程架构；macOS 用 `uname -m`、`sw_vers`、`sysctl hw.machine`，再核对是否处于 Rosetta，防止把进程架构误当宿主。其他设备采用对应系统的只读查询。按“操作系统 + 宿主架构 + 制品最低系统版本”筛选官方二进制，解压到本次专用目录，验证版本后仅注入当前子进程。

| 工具 | 来源、选择与实施时验证 |
| --- | --- |
| JDK 21 | 从 [Temurin 官方发行入口](https://adoptium.net/temurin/releases/?version=21)选择本机 OS/架构的 JDK 压缩包，核对官方 SHA-256；macOS 解压后使用 `Contents/Home`。记录完整 `java -version`、架构和发行版本；不用系统安装器或写全局 JAVA_HOME |
| Maven 3.9.11 | 使用 [Apache 官方归档](https://archive.apache.org/dist/maven/maven-3/3.9.11/binaries/)的 bin.tar.gz，按随包 `.sha512` 核对；解压后用绝对可执行路径和本次 JDK 运行 `mvn -version`，确认不再调用旧 3.5.4 |
| MySQL 8.4 LTS | 从 [MySQL 官方下载](https://dev.mysql.com/downloads/mysql/8.4.html)及[官方归档](https://downloads.mysql.com/archives/community/)选择匹配 OS/架构的免安装压缩包；不同设备可解析到不同补丁/文件，不把某个 x64 包或补丁写成全员依赖。用官方 `.asc` 和官方公布的签名密钥指纹验签，记录 MD5/SHA-256、实际 `mysqld/mysql --version` 与二进制架构 |

MySQL 的选择算法只有一条：在 8.4 LTS GA 中筛选匹配平台和最低 OS 的官方制品，选择该平台可取得的稳定补丁，保存本次确切下载 URL/版本/校验与架构；已在本机的包通过同样验证后优先复用，不强制重复下载。macOS x64、macOS ARM、Windows x64 分别取其原生包，不安装跨架构包、不以模拟另一 CPU 为默认方案，也不切换到 9.x、H2、SQLite 或 MariaDB。若对应平台没有可运行制品，记录具体 HTTP/架构/动态库错误回调统筹，不再盲试多套数据库。

本轮只读证据（不是运行结果）：宿主 macOS 15.4 / x86_64；`hw.optional.arm64` 和 `sysctl.proc_translated` 不存在。Temurin 官方 `jdk-21.0.13+9` release API 列出 `OpenJDK21U-jdk_x64_mac_hotspot_21.0.13_9.tar.gz` 与 SHA-256，校验文本 HEAD 200；Apache 3.9.11 tar HEAD 200，官方 SHA-512 文本可读取。MySQL 当前 8.4.13 的 macOS 页面仅列 ARM；本机候选 `mysql-8.4.11-macos15-x86_64.tar.gz` 及 `.asc` 在官方 CDN HEAD 200（压缩包 171974960 字节）。这些仅说明此宿主有候选路径，其他同事按各自平台重新解析；未完整下载、验签、安装或运行，不将“HEAD 200”写成可用性验收。

Adoptium latest API 本轮返回 403，可从同一发行方的[官方 GitHub release](https://github.com/adoptium/temurin21-binaries/releases/tag/jdk-21.0.13%2B9)取得元数据；这只更换官方元数据入口，不更换 JDK 产品或架构。[MySQL 签名核对](https://dev.mysql.com/doc/refman/8.4/en/checking-gpg-signature.html)使用任务专用 GPG home，不写用户全局密钥环。下载后还要验证压缩包能完整展开、JDK/Maven 能执行、mysqld 的本机动态库可加载；失败留下具体证据，不能仅换个包名假定成功。

### 1.2 目录、端口、凭据与清理

使用系统临时目录建立 `hc194-<唯一后缀>/`，以 `HC194_RUN_ROOT` 记录实际路径；此变量只在本轮进程内使用，不写入项目固定配置。结构包括 `downloads/`、`tools/`、`mysql-data/`、`runtime/`、`maven-repository/`、`gnupg/` 和 `evidence/`。本轮专用秘密文件置于权限受限的 runtime，公开证据仅含版本/校验/端口/无敏感输出。临时目录名、socket 和 pid 路径保持简短以适应 macOS socket 长度限制。

JDK/Maven 不移动到系统目录，不安装 Homebrew/Docker、不修改 shell/profile、launchd、系统服务或已有数据库。Java/Maven 使用任务工具绝对路径；仅给对应子进程注入 JAVA_HOME/PATH 和独立 Maven 本地仓库，不改 HOME/CODEX_HOME。已有全局 Maven 配置先检查必要镜像/代理是否可用，但不改写用户 settings.xml；如需任务配置只写本轮目录，秘密不进仓库。

MySQL 建议先探测 `127.0.0.1:33074`，Java 用 `127.0.0.1:18084`；若占用，选择一个空闲高位端口并把同一值传给全部本轮进程，记录在证据中。不终止占用者，不使用既有 3306。MySQL 独立 datadir/socket/pid/error-log，关闭 MySQL X 的额外监听，经典协议只绑定 127.0.0.1；Java 也只绑定 loopback，桌面/服务的 origin 使用同一实际地址。其他设备运行自己本机实例，不连接这台电脑的临时目录。

按 [MySQL 初始化说明](https://dev.mysql.com/doc/refman/8.4/en/data-directory-initialization.html)以当前普通系统用户、`--no-defaults` 和显式 basedir/datadir 初始化空目录；采用 `--initialize` 的临时 root 密码，日志仅本机私有读取。启动后经本轮 socket 完成密码设置和演示库初始化，不把密码印到聊天、命令参数、进程列表或证据。使用临时受限 client 配置/标准输入或环境注入，不读取/改写 `/etc/my.cnf` 等系统配置，不重用旧数据目录。

实施时将已验签解压的目录记为 `HC194_MYSQL_ROOT`、实际空闲端口记为 `HC194_MYSQL_PORT`。创建权限受限的空 datadir/runtime 后，核心命令如下；变量只代指本次绝对路径，不是项目依赖。初始化只运行一次，故障恢复重启不得再次 initialize：

```sh
"$HC194_MYSQL_ROOT/bin/mysqld" --no-defaults --initialize \
  --basedir="$HC194_MYSQL_ROOT" --datadir="$HC194_RUN_ROOT/mysql-data" \
  --log-error="$HC194_RUN_ROOT/runtime/mysql-init.err"
"$HC194_MYSQL_ROOT/bin/mysqld" --no-defaults \
  --basedir="$HC194_MYSQL_ROOT" --datadir="$HC194_RUN_ROOT/mysql-data" \
  --bind-address=127.0.0.1 --port="$HC194_MYSQL_PORT" --mysqlx=OFF \
  --socket="$HC194_RUN_ROOT/runtime/mysql.sock" \
  --pid-file="$HC194_RUN_ROOT/runtime/mysql.pid" \
  --log-error="$HC194_RUN_ROOT/runtime/mysql.err"
```

第二条以前台子进程交给本轮进程句柄托管，不注册系统服务。初始化密码只由本机私有日志读取，随后的 SQL/连接秘密通过前述私有输入方式提供。macOS 使用对应压缩包，其他系统选自己的原生免安装包并采用该系统等价进程参数；Windows 进程启动/清理的真实验证归 HC-204，不冒充已在本机验证。

为 `hc194_demo` 创建迁移账号（仅本库所需 DDL/DML）和运行账号（业务三表所需 DML、迁移历史读取），与业务 `user01/02/03` 的普通用户身份区分。本机 JDBC 使用 MySQL 初始化产生的 CA，导入本次 JDK 的独立信任库并通过受限外部配置传入驱动，采用 `sslMode=VERIFY_CA`；本机 CLI TCP 连接也核对同一 CA。不全局关闭 TLS 验证、不记录密码，不将本机自动证书视为外网/内网证书验收。目标环境身份校验和真实 CA 单独核实。

结束时先停止本轮 Java/桌面，再用本轮 socket、受限 client 配置调用 mysqladmin shutdown 并等待退出，核对记录 PID 的命令行/datadir 后才处理残留。保持审查所需的脱敏 evidence；工具和数据目录在待验收期间可保留但不留下进程。验收后仅清理本次创建并有清单标记的目录，删除私有凭据；不运行全局 pkill、不删除用户既有包/库/缓存。临时下载的工具只是本机准备，项目不依赖这份副本的绝对位置。

正常 MySQL 停止命令为 `"$HC194_MYSQL_ROOT/bin/mysqladmin" --defaults-file="$HC194_RUN_ROOT/runtime/admin.cnf" --socket="$HC194_RUN_ROOT/runtime/mysql.sock" shutdown`；admin.cnf 只含本实例连接配置、权限 0600，不保留在公开证据。

## 2. 停点一：本机云端与数据基础能真实启动

**观察方式：**在本机 MySQL 上运行显式构建、迁移、初始化与启动；终端可看到三名普通用户/一工作区/三条成员，访问 `/meta` 和 `/health` 得到真实结果。缺迁移或非法 schema 的启动命令非零退出，成功启动后停止数据库能观察 503 DOWN，恢复数据库后 UP。

按依赖顺序完成：

1. 复核工作树、当前 Task/Spec 与工具准备结果。只在必要 manifest 上增加精确 Ajv/tough-cookie 依赖并更新唯一根锁，正常同步当前 node_modules；不改变七 workspace 和旧包的退出边界。
2. 在 contracts 建立唯一 `schema/platform.schema.json`、引用它的 `openapi/platform.openapi.json` 与 `fixtures/`。根类型出口增补平台 DTO/状态/CollaborationHost，公开纯 JSON `/schema` 子入口；不改已有窗口接口。schema 包含 Spec 的身份请求/响应/错误/基础消息头，不预建未来事件 payload。Node 必要夹具检查使用 Ajv2020，禁止强转、补默认值、删除未知字段和远程 `$ref`。
3. 建立 services/collaboration-server 的单 Maven 应用，使用 Spec 版本与 Java 21；分离应用启动、transport、identity、workspace、infrastructure。Maven 将 contracts 源 schema/OpenAPI/同组 fixtures 原字节打包；只让产品版本资源取 VERSION，不过滤修改契约/SQL 内容。建立 Java record 与同源 runtime validator，校验各端使用同一份夹具。
4. 在 `scripts/workbench/server.mjs` 建立显式 `build/migrate/init-demo/start/contracts` 分派，根 npm 对应 `server:*` 入口仅在主动调用时检查 Java/Maven。build 读取 VERSION 传 Maven revision，产出 JAR 与 SQL/校验清单；contracts 命令只编译/校验 JAR 中契约和共同夹具，不启动 HTTP 或连接数据库。另有 Node `contracts:smoke`；两者不挂到纯桌面 install/build/typecheck 前置。
5. 建立 V001 三表、JDBC 仓储、显式 Flyway migrate 和短事务 init-demo。migrate/init-demo 完成即退出，serve 不能自动迁移、补成员或修复数据库。启动同步编译 schema、连接 DB 并 validate 历史/checksum/所需版本，通过才开放 HTTP；失败非零退出。成功启动后 `/health` 只做有界 DB 探测，运行期故障返回 DOWN/安全 503，恢复后自然 UP。
6. 建立基础 HTTP 来源/版本/requestId/安全错误入口。实现 /meta、/health 和数据访问，尚未接通的受保护业务保持拒绝访问，不临时开放“绕过登录看库”的 API。

本停点必要验证：

- `server:build`、Node/Java `contracts` 夹具入口成功，记录有效依赖组合；对缺字段、额外字段、错误类型/ID/时间/版本至少各一例，两端判断一致。
- 对空 `hc194_demo` migrate 后 init-demo 两次，对比三表行数、稳定 ID 与名称/启用状态；修改一个显示名/停用状态再显式初始化，确认不被覆盖，然后仅恢复本次演示夹具。
- 只在额外隔离 `hc194_txn` 库验证一次初始化回滚：同一 V001 建表，给探针账号读取/用户插入权限，但拒绝其工作区 INSERT，使用户名插入后发生错误；确认事务回滚后没有本次新增用户/成员。验证完删除本次探针账号/库，不向产品增加失败注入开关、触发器或新管理 API。
- 未迁移库启动失败；用临时制品副本注入非法 schema/checksum 不符，确认启动失败且端口不存活，不修改 canonical 源/已执行 SQL。运行中停/启本次 MySQL，观察 health DOWN→UP；需 DB 的读取返回 503，不写成用户不存在。启动失败和运行期断库分别留证。

## 3. 停点二：普通用户通过真实 HTTP 登录与退出

**观察方式：**使用同一个本机服务和三名数据库普通用户，从空 CookieJar 完成 csrf → login → 新 csrf → me → workspaces/members → logout。终端只输出用户名/工作区/状态码/安全错误，Cookie/token 不展示。

实现 Spring Security JSON 认证入口、会话 ID 轮换、SecurityContext 显式保存、HttpSessionCsrfTokenRepository 和退出处理；不靠控制器 ThreadLocal 伪造登录。补齐 Spec 全部身份/工作区路由、DB 用户启用/成员校验、403/404/503 与响应 schema 校验。普通启动不重新插数据，移除成员不会因服务重启被加回。请求来源用固定服务 origin 校验，不为 renderer 开启跨域。

在 desktop main 建立可在 Node 中调用的业务网络适配器，单一 Node fetch + 内存 Jar；把身份/工作区具名方法与 wire 校验分开，UI 不接触 URL/header/token。必要真实冒烟驱动直接调用同一适配器访问本机 Java；不在脚本重写另一套登录实现。脚本只保留身份接口必要场景，完整框架回归留 HC-204。

最小场景包括三账号各一次成功链路、匿名访问 401、未知/停用用户拒绝、非成员或未知工作区 404、旧 Cookie/旧 CSRF 失效、缺 token/错误 Origin 被拒绝。移除成员/停用账号只在本次演示库操作并恢复夹具；原作者 ID 不修改。登录后短暂停库，`/me` 得安全 503 且会话不被清除；重启同一 datadir 后原会话仍可确认。另行重启 Java 后旧 UI 会话失效、用户/工作区行不变。退出失败只承诺本机清理，重登使用空 Jar。

构建 Java 与 desktop 受影响代码，执行必要类型/边界检查；保存脱敏请求结果与宿主信息，不把完整请求头和 session 序列化进报告。

## 4. 停点三：桌面真实身份、成员与用户切换

**观察方式：**运行已有桌面开发/构建预览，选择用户 01 后显示真实工作区/成员，再退出切到用户 02；故意延迟的旧用户响应不能覆盖新身份。原主题、缩放、目录选择仍可使用，没有假聊天/设备/SSE/WSS。

| 修改归属 | 实施内容 |
| --- | --- |
| `apps/desktop/src/main/` | 组合前一停点的网络适配、身份代次、独立 Jar/AbortController、内存缓存与受限业务 IPC；复用已有可信主窗口校验，不改窗口地址规则 |
| `apps/desktop/src/preload/index.ts` 与 renderer 类型/装配 | 新增 `window.collaboration`，逐方法暴露 CollaborationHost 并注入 UI；现有 `window.workbench` 五方法原样保留 |
| `packages/workbench-ui/src/identity/` | 最小演示用户选择、当前身份、成员和退出/错误组件；沿用现有主题公共出口，不编辑 conversation/project/navigation/layout，也不自写第二套左侧导航 |
| contracts / 依赖边界 | 类型和纯 schema 按公开 exports 消费，renderer/UI 不引入 Node、Electron、Cookie 或 Java 类型；检查器只因实际新增边界做必要增补 |

契约只实现本阶段基础域；后续任务按命名空间分文件扩展唯一 schema/fixture，公共形状通过本地引用复用，根 schema/OpenAPI/总导出顺序合入。Maven 按同源目录打包登记的引用资源，不维护服务侧副本。身份状态到布局的接线由当轮统筹协调，HC-194 不因演示登录而扩大成完整工作台开发。

切换顺序严格为开始退出即阻止新请求/取消旧通道 → 丢弃旧视图/缓存 → 尝试退出旧会话 → 新 Jar 登录新账号。每个异步结果（包括响应头中的 Cookie 更新）先核对身份代次，过期结果不得写任何新状态；不是只在最后渲染时过滤。关闭/重开窗口时注销对应监听，不能累积处理器。
