用户从独立预览点击“预览会话引用”，查看会话、所有者、版本、时间、范围和正文。选择已有本人本机会话或新建后，点击“加入草稿”，在同一个 `ConversationView` 的输入区看到刚确认的固定材料。

1. 在 `apps/desktop/src/renderer/features/collaboration/references/` 实现取材、预览和确认流程。HC-219 负责展示选择界面，读取装配方提供的本人本机会话，并把选定目标和材料交给草稿动作。用固定样例模拟已存在的会话、草稿、新会话目录选择和定位结果。
2. 在独立预览中通过 `ConversationReferenceView`、`referenceIds` 和 `onReferenceAction` 显示引用。提供同一来源的两份快照供刷新演示，用户确认新预览后才替换草稿卡片。移除只更新引用选择。正式草稿动作接入时，由 HC-218 恢复目标个人状态并合并到最新草稿，定位与保存反馈各沿用既有机制。[Spec 草稿流程](../spec/HC-219-引用任务与团队知识.md#2-从项目会话快照到本人草稿)
3. 独立预览放在 `docs/developer/previews/hc219-reference/`，提供该目录专用的 `index.html`、`main.tsx`、`tsconfig.json` 和 `vite.config.mjs`。沿用现有 [Project 视觉预览](../previews/project-collaboration/README.md) 的本地构建方式，通过公开出口复用 UI 与主题，使用固定候选和内存草稿。预览按钮可放在 `slots.composer` 底栏，验收从预览至草稿。输入 `@` 选择会话在共享接点就绪后另验。

从仓库根目录运行以下命令。当前 contracts 和 UI 产物与源码一致时，可跳过前两步。

```sh

npm run check:boundaries
node node_modules/vite/bin/vite.js build --config docs/developer/previews/hc219-reference/vite.config.mjs
node node_modules/vite/bin/vite.js preview --config docs/developer/previews/hc219-reference/vite.config.mjs --host 127.0.0.1 --port 57842 --strictPort
```

构建产物写入 `tmp/hc219-reference-preview/`。打开 <http://127.0.0.1:57842/>，点“预览会话引用”，选择已有本人会话，再点“加入草稿”。核对卡片与预览材料一致，原文字、原目录仍在，受控发送回调次数为零。新建分支提供目录选择，刷新、移除按 Spec 实现。首个停点以这一条正常路径做窗口冒烟，记录观察结果后退出预览。

### 停点二的工作台会话引用

2026-11-16 统筹授权串行修改上表的公共输入区和类型出口、HC-218 会话装配和既有个人草稿动作、`desktop-workbench.tsx`。以 [Spec 草稿流程](../spec/HC-219-引用任务与团队知识.md#2-从项目会话快照到本人草稿) 和 [桌面交界](../spec/HC-219-引用任务与团队知识.md#4-与现有桌面代码的交界) 为准。服务端、线上契约、Runner、ACP 沿用当前交付。
