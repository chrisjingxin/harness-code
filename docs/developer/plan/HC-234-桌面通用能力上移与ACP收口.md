# HC-234 桌面通用能力上移与ACP收口 · 实施计划

[Task](../task/HC-234-桌面通用能力上移与ACP收口.md) · [Spec](../spec/HC-234-桌面通用能力上移与ACP收口.md) · [Todo](../todo/HC-234-桌面通用能力上移与ACP收口.md)

按三个停点推进。每个停点走一遍正式 Electron 入口，记录命令、可见结果和环境限制，再回调统筹。首个实施批次交付会话改名。Git 快照和 ACP 兼容分别在后续停点接入。实施沿用本卡独立 worktree 和 HC-192 分工。

## 停点 1 · 桌面直接改名

1. 从 `desktop/src/shared/personal.ts`、`desktop/src/main/personal-store.ts` 入手，保存本机 `customTitle`。沿用现有个人记录校验和并发保存机制，在每条可以改写标题的主进程入口校验当前账号确实拥有该会话。
2. 在 `features/session` 把持久化标题、有效连接的 Agent 建议、服务端登记标题合并到一个展示入口。为左栏、顶栏和搜索加载本机标题。处理未打开会话、登录或项目切换、Agent 推送与写盘失败。
3. 在左栏本人会话菜单接入“重命名”，复用现有菜单和输入控件。更新协作交接说明中的服务端持久化缺口。

**演示方式**。运行 `npm run dev`，在本人本机会话的左栏菜单改名，检查顶栏和搜索。切换项目并重启，确认未再次打开该会话时左栏已保留标题。他人会话保持只读。标准外部 Agent 或一致性测试 Agent 推送新标题后，手动标题优先生效。

**最小回归**。用桌面现有 `personal-store.test.ts`、`session-model.test.ts` 覆盖旧记录、本人授权、写并发和标题优先级。

## 停点 2 · 轮次 Diff 与隔离工作树回退

1. 在 `desktop/src/main/project-service/` 复用 `detectGitRoot`、现有 Git 调用及输出上限，加入隔离索引、快照引用和本机轮次索引。用本机执行协调层串起基线、实际 prompt、执行终止和终态快照，对同一个物理目录顺序受理。捕获失败按 Spec 释放对话入口。
2. 主进程核对当前账号、项目与会话归属后，按 `turnId` 从本机轮次索引解析 Git 数据。新增受限桌面 IPC，接入现有 Diff 面板，显示改动清单、单文件差异和快照不可用原因。
3. 复用本机目录授权确认实体身份。主进程以 Git 登记的 linked worktree、用户明确确认的单会话用途和桌面记录的会话目录重叠情况决定是否开放回退。目录登记覆盖绑定后已关闭或空闲的会话，可从本机记录校验。共享或无法确认的目录继续提供 Diff。预览并确认后，完成保护快照与路径冲突检查，再还原文件，返回成功、拒绝或部分写入状态。
4. 接通文件树刷新与保护快照恢复入口，清理中文撤销卡片。Harness 对话撤销仍可经现有 `conversation` 模式执行。

**演示方式**。在临时仓库准备普通工作树与专用 linked worktree，使用桌面正常入口连接标准 ACP Agent。让 Agent 修改一个文件并查看轮次 Diff。在专用工作树确认回退，核对文件、用户索引及 HEAD。在普通工作树看同类 Diff，在非 Git 目录再发送一轮。

**最小回归**。用桌面 `project-service.test.ts`、`local-execution-ipc.test.ts` 或同目录的小型 Git 夹具覆盖捕获先后、同目录并发、超时放行、空闲共享会话、忽略文件同名覆盖、目录变更、部分失败后保护快照以及暂存区和 HEAD。

## 停点 3 · ACP 兼容与 Harness 扩展

1. 在 `packages/acp-runtime` 的绑定和会话生命周期集中校验及过滤附加目录与 MCP 参数。让建会、加载、恢复共用参数构造。统一模式来源、更新事件和写入路由。
2. 沿用恢复硬超时，增加按宿主配置启用的回放静默判定。将恢复失败与旧连接清理衔接到已有 `restorePolicy`。桌面从现有本机定稿缓存准备前情，在新原生会话第一次发 prompt 时交接一次，覆盖启动绑定及发送期间发生重置的路径。
3. 在 `desktop/src/main/local-acp-host.ts` 按已选 descriptor 装配扩展能力。由 `packages/harness-acp` 解析已协商的元数据，经主进程投影子代理归属、审批作用域、旁路标记和用量。协作上传前识别旁路轮次。纯标准响应仍走原有渲染与上传流程。

**演示方式**。从正式桌面启动，对照旧版模式和配置型模式各完成一次切换并发消息。看到恢复失败时能按配置继续运行或显示明确错误。连接 Harness 检查嵌套工具卡、审批作用域和 `/btw` 本机展示，确认旁路轮次未进入上传队列。切回标准 ACP Agent 验证普通对话及已有平台能力。

**最小回归**。扩展 `session-compat.test.ts`、`conformance.test.ts` 与桌面上传相关测试，覆盖模式通知和写入、协商过滤、无响应及迟到帧、摘要单次发送、标准 Agent 无扩展，以及旁路内容与普通定稿的入队差异。复用 `harness-acp.test.ts` 校验已有解析器。

## 交付核对

每个改动停点执行受影响的测试与类型、边界、应用启动检查。收口核对 `npm run build`、`npm run typecheck`、`npm run check:boundaries -- --self-check` 和 `npm run project:check`，同一版本已有等价结果可引用。更新独立桌面工作台用户说明及 Agent 接入架构，证据写回 Task，通过后同步看板为待验收。HC-204 负责真实目标环境和跨平台回归。
