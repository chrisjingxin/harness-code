目前只有身份/工作区服务，没有会话队列。按下面五个可观察停点实施，先让唯一载荷与字节可核对，再建立真实存储与同步，最后接设备执行。每个停点只在统筹明确派发后开展，完成或遇真实阻塞主动回调一次，停止等待下一停点；不轮询、不把整份 Todo 连做完。

```text
共同契约/字节夹具 → 真实共享目标与保存历史 → HTTP/SSE 与同一宿主客户端
```

## 6. 停点四：执行、决定、取消与恢复事务可独立观察

**观察方式：**冒烟进程用真实数据库和生产执行服务登记同会话两项输入，受控传输只记录实际发出的固定消息；回放已登记来源事件后，从真实 GET/SSE 看到 dispatching→accepted→running/终态和后项放行。没有 WSS/Runner 的结果明确标为“事务端口观察”。

1. 在 `execution/ExecutionReceiptsService.java` 实现 recordBatch：完整来源比较/唯一约束/连续前缀，首次 accepted 与唯一 allow/deny 同事务保存，native.bound 无公开投影也登记；有变化才追加 execution.changed。字段/理由/终态合法性严格按 Spec，不因后来停用/停止共享丢已获准结果。
2. 在 `execution/ExecutionRecoveryService.java` 实现同账本核对及原决定/ack 重传；摘要不能绕过来源事务写绑定/终态。notFound、原绑定不同、调用边界未知分别处理，不让 unknown 回到普通重试队列。
3. 在 `execution/ExecutionDispatcher.java` 实现数据库选择/登记/提交后发送、15 秒无受理核对和唯一唤醒器。消费 196 的真实公开 DeviceDelivery 声明，不直接写 device 仓储；设备 ready 是可达事实，保存权限与派发可用性分开。
4. 完成取消先到、决定前后竞争、denied 后未调用证明、两个本地预检 rejected、真实终态闭合消息和占位释放。原决定不可改写，未提交决定不发 allow；同一 command 的固定 null/头时间/指纹不变。
