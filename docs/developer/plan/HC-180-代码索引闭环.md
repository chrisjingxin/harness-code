# HC-180 代码索引闭环实施计划

关联：[Task](../task/HC-180-代码索引闭环.md) · [Spec](../spec/HC-180-代码索引闭环.md) · [Research](../research/180-CodeGraph集成评估.md) · [Todo](../todo/HC-180-代码索引闭环.md)

## 1. Overview

本计划把默认关闭的代码索引按四个可演示停点纵向交付：先让配置、离线 preflight 与 `/code-index status` 在 TUI/Web 可见；再打通首次建图、私有 MCP 和模型内部 `codebase_explore`；随后补齐增量、重建、取消、删除、崩溃恢复与 watcher 降级；最后完成平台契约、真实 macOS 闭环、三类仓库评测、文档和 review。

一次实现只推进到下一个可演示停点。完成该停点的 Todo、focused tests、演示说明与 `tmp/handoff.md` 后必须停止，等待用户查看；不得连续做完整份 Todo。

## 2. 依赖图与实施原则

```text
Protocol v3.10
  ├─ 配置 capability 门禁
  │    └─ Host status
  │         └─ CLI/TUI/Web 状态入口                 → 停点 A
  └─ apply + changed 契约
       └─ 安全目录/state store
            └─ 受管 Node 索引进程
                 └─ CodeIndexManager happy path
                      ├─ CLI 非阻塞进度
                      └─ 私有 MCP → Harness tool → Run lease → 停点 B
                           ├─ sync/rebuild/generation
                           ├─ cancel/crash/incomplete
                           ├─ remove/ignore 清理
                           └─ restart/watcher/外部锁             → 停点 C
                                └─ 平台/真实包/评测/文档/review  → 停点 D
```

执行原则：

- 每项先写最小失败测试，再写实现，再整理；生成文件只由生成脚本更新。
- `CodeIndexManager` 是状态机与并发 invariant 的唯一实现处；Host handler、CLI 和 Node adapter 不复制判断。
- `CodeIndexRuntimePort` 的生产 adapter 内部使用私有 MCP，测试 adapter 为进程内 fake；MCP/LangChain/供应商类型不穿过 seam。
- 原始 MCP tool 不进入 `create_harness_agent(tools=...)`。模型只看到 Harness canonical tool `codebase_explore`。
- 默认关闭回归贯穿所有停点：不探测包、不访问目录、不启动进程、不改变普通 Run profile。
- 现有用户改动一律保留；实现前先认领 Task，并使用分支 `feat_hc_180_代码索引闭环`。

## 5. 停点 C：完整生命周期与失败恢复

用户可以增量、重建、取消和确认删除；干净重启恢复，异常退出保守 incomplete，watcher/外部锁降级可见。所有状态在 TUI/Web 一致。

**Description:** 扩展 Node/runtime adapter 与 Manager：ready 上 ensure 执行 sync；rebuild 先阻止新租约、等待现有租约归零、关闭 MCP/watcher，再重建并连接新 generation。

**Acceptance criteria:**

- ready ensure 不删除数据库；rebuild 明确删除上游数据库后全量建立。
- 活动查询 Run 得到 `CODE_INDEX_RUN_ACTIVE`，不会被中断；状态切 job 后新 Run 无索引继续。
- 新 generation 就绪前旧 session 已关闭，旧 profile 不再获租。

**Verification:** V15。  
**Dependencies:** B7b。  
**Files likely touched:** Node adapter、`code_index/runtime.py`、`manager.py`、manager/runtime tests。

## 8. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 企业 1.1.6 包重新打包或平台资源缺失 | A/B 无法进入真实运行 | A4 先用 manifest/layout preflight fail fast；D1 再核对实际 tarball，不公网自愈 |
| Node adapter stdout 污染 Host JSONL | 协议/进度错乱 | 单独子进程、严格 JSONL schema、stderr 有界、畸形帧终止为 incomplete |
| watcher 在 Host 强杀时可能写 WAL | 部分索引被误查询 | serving marker；非干净退出一律 incomplete+rebuild |
| AgentEngine 复用旧 generation | Run 查询错误图 | generation 进入 profile 指纹；Manager lease 原子检查；旧资源 drain |
| raw MCP tool 混入外部工具路径 | 技术栈泄露、审批/策略错误 | Harness 自有 tool catalog；架构测试断言外部列表和 `/mcp` 不含该工具 |
| explicit job 与 active Run 竞态 | 删除/重建正在查询的图 | Manager 单锁线性化 lease/job；写动作先阻止新租约并要求当前租约为零 |
| local exclude 清理误删用户规则 | 用户数据损坏 | 标识块和精确内容比对；不匹配 fail closed；测试保留邻接条目 |
| TUI/Web 演进分叉 | 状态和确认不一致 | controller/selector 为唯一业务映射；adapter parity fixture |
| 三仓评测成本高、结果无提升 | Task 结论不完整 | 固定小问题集与资源记录；如实报告，不以提升比例判成功 |
