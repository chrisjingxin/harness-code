## 2. 已确定的实现取舍

- **先评测后改码**：HC-131 规定 `edits[]` 无证据不得进生产 schema。停点 A 不改任何生产代码，只动 `evaluations/zc133/` 与研究文档；不通过就停下回上游修订。
- **纯函数承载匹配规则**：把“多项精确匹配 → 唯一 → 已读范围 → 重叠 → 合成新全文”写成 `snapshot_file_support.py` 里的一个纯函数（输入当前全文、已读范围判断函数、edits，输出新全文或带 `edit_index` 的错误）。生产代码调用它；模拟器是独立实现，不 import 生产代码，保持评测与实现互为对照。
- **一个出错载体**：`FileToolContractError` 增加可选 `edit_index`，`_error` 输出到 `error.edit_index`。不新增异常类。
- **不动提交层**：`FileMutationService.commit`、`backend.compare_and_replace_text`、写锁、`ConcurrencyGuardMiddleware` 不改；批量原子性来自 prepare 阶段合成一份完整新全文。
- **不动协议**：`FileDiffPresentation` 与 `packages/protocol` 不改。`edit_count` 只放进 `MutationMetadata` 并出现在审批文案里。
- **目录 schema 记号**：`file_tool_catalog` 的参数类型只是用于指纹的字符串，直接写 `"array"`，不需要额外适配（已核对 `schema_shape()` 只做 `dict(parameters)`）。
- **TDD**：每个 B 步骤先把相关既有测试迁移为 `edits[]` 形状并确认失败，再写最小实现。
