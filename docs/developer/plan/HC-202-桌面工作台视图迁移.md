## 停点一：正式三栏与真实身份设备

**前置。** HC-205～208 的公开 UI 部件已合入，HC-194 的身份端口和 HC-196 的设备端口已到 renderer。真实演示需要可用的 Java 服务、已初始化的数据和当前账号可见的设备/项目，沿用现有服务配置与初始化方式。[桌面和服务启动说明](../../../README.md) · [UI 公开入口](../../../packages/workbench-ui/src/index.ts)

1. 在正式 renderer 入口用 `WorkbenchLayout` 组合 `CollaborationNavigation`、中央和右侧插槽、居中设置。一次加载公共主题，使用窗口状态订阅和现有主题/缩放端口。预留平台原生按钮位置，空白顶栏可拖动，各控件保持可点击；保留现有 main 的窗口与 Runner 生命周期。
2. 先监听、再取初始状态，初始请求期间若已收到更新，丢弃迟到的初始快照。复用 `window.collaboration` 的演示账号、登录、退出、身份及成员调用。唯一工作区可默认进入，多工作区由用户选定，成员和设备管理都使用已选工作区。保留现有本机登记、共享与托管入口，组件或接点需要变更时先交统筹。
3. 复用 `window.devices.getState/onStateChanged`、`listDevices` 与 `listProjects`。选工作区取设备首页，展开设备取对应项目首页，本机托管状态单独显示。让列表明确区分加载、空、失联、无权、未接入以及还有未加载的条目。已有端口只取首页；搜索过滤已加载内容，续页具名参数待单独接入。
4. 在窗口内按服务域、账号和工作区维护导航展开、选择和手动栏位偏好。变更身份或工作区立即切换状态范围，旧请求及错误按身份代次、目标和请求顺序过滤。服务未配置时三栏、主题与设置仍能打开。此停点中央和右侧使用实际空态/未接入提示，有真实项目范围时可用 `ProjectDock` 呈现不可用；没有已确认会话时显示引导。预览夹具留在预览入口。

**怎么演示。** 在获派的 macOS 窗口时隙，以 `WORKBENCH_SERVICE_ORIGIN=http://127.0.0.1:18084 npm --workspace @workbench/desktop run preview` 启动已构建的正式窗口，服务地址按实际配置替换。打开三栏 → 选服务返回的演示账号登录 → 确认或选择工作区 → 展开实际设备并看到项目和本机设备状态。中央、右侧显示各自当前状态，核心操作应能完成。通过受影响 workspace 构建、类型和 `npm run check:boundaries -- --self-check` 后走这一条正常路径。构建覆盖本停点实际需要的 UI、desktop 及其上游，沿用未受影响的既有验证。双主题、尺寸/缩放、键盘、异常组合与双平台整体验收留 HC-204。

## 停点二：共享会话列表与只读历史

**前置。** 在正式三栏上接线，沿用 HC-195 的 Java GET 和同一窗口的 `CollaborationClient.listConversations/getConversation/history`。接口评审固定三个具名 IPC 调用和参数范围，真实联调需要当前账号有权读取的已保存会话。[客户端](../../../apps/desktop/src/main/collaboration-client.ts) · [HC-195 历史接口](../spec/HC-195-共享会话与实时同步.md#8-http-历史分页与-sse)

1. 从 main 经可信窗口、认证代次及工作区校验，将 `listConversations(workspaceId, page?)`、`getConversation(workspaceId, conversationId)`、`readHistory(workspaceId, conversationId, page?)` 接到 preload。复用既有 DTO，列表续页为成对的 `beforeCreatedAt/beforeId`，历史页只接收 `afterSequence/throughSequence/limit`。
2. 共用会话列表数据生成共享入口和项目分组。用户选择或恢复会话时读取概要，绑定实际的设备与项目 ID。历史首读取得固定 `throughSequence`，续读按同一上界有界分页。连续应用后以消息 ID 投影真实文本、作者和执行状态到 `ConversationView`，保存当次已应用的十进制游标。消息渲染的复制和外链绑定已有宿主动作。会话概要和写回执都不能推进游标。
3. 在同一会话范围内保存草稿、滚动和内容修订号。项目读取与会话历史按各自服务许可处理。共享历史的 Git 平台权限仍在讨论，本停点沿用现有端口，按其无权与失效结果隐藏相应数据。创建、实际发送、取消与审批保持不可用并说明。

**怎么演示。** 从正式窗口选一条有权访问的已保存会话，看到真实标题、原设备/项目、消息作者、文本和执行状态。服务端数据可用现有 HC-195 隔离验证入口准备；此停点可在没有 Agent 的情况下走通。

## 停点三：实时共享更新与补读

**前置。** 停点二可给出当前会话连续应用的游标。复用 main 的 `CollaborationClient.subscribeConversation` 和 Java SSE；同一窗口只订阅当前会话。

1. 增加具名 `subscribeConversation(workspaceId, conversationId, afterSequence)`、`readConversationEvents(subscriptionId, afterSequence)`、`unsubscribeConversation(subscriptionId)`。订阅标识绑定窗口、身份代次和会话。main 持有一个按条数与字节限制的队列，包括已读出、尚未确认的事件。现有 SSE 校验和网络重连继续在 main，补足连通、断开、停止及需要补历史的状态。
2. renderer 同时只等一个读取结果。main 有事件或状态变更就返回一批，无更新时在有限等待后返回状态。renderer 先确认当前订阅及范围、验证顺序，再把事件应用到同一个历史投影；下一次读取携带最后已应用游标，main 用它确认并释放已应用事件。只接受该订阅已交付批次范围内的确认。读取失败、超过页面等待期限、队列超限或发现缺号时，关闭旧订阅，按 renderer 最后已应用位置走既有 history 补到新上界后再订阅。失去可验证投影或游标超前时按当前权限重建。
3. 退出、账号/工作区/会话切换、关窗及确认失权时同时释放流、队列和等待中的读取。HTTP 401 或流身份失效由同一窗口身份状态处理，明确拒绝时隐藏受限内容。同一会话的非对话中央页签保持订阅，更新只写入会话投影与新内容提示。

**怎么演示。** 正式窗口停留在已授权会话，通过现有隔离服务写入一条已提交更新，观察同一时间线收到更新、当前阅读位置保持。另用受控交付中断验证最后一批未应用时能从 renderer 的游标补回；完整断连、异常和高负载组合由 HC-204 验收。

## 停点四：个人恢复与原生后台

使用 main 具名读取/保存个人记录，宿主从当前已验证身份和服务域确定存储范围，按 Spec 隔离工作区、会话和原项目。保存草稿、页签、选择和阅读锚点等个人状态，同一范围以最新修订为准，重开后重新登录并核对权限再恢复。文件正文和 Diff 由项目服务授权读取，共享历史由 HC-195 授权读取。个人存储只保存个人记录，不保存文件正文、Diff、共享历史、消费游标或凭据。

关闭窗口进入后台，关窗释放窗口身份与订阅，Runner 仍由应用级监督器托管。调整 Windows 无 Runner 时关最后一窗退出的现有行为，确保可经托盘重开；显式退出沿用等待 Runner 收尾再终止应用的流程。正常路径演示「关窗 → 重开 → 重新登录 → 恢复有权的个人视图」，Windows 有无 Runner、托盘/原生按钮与平台组合归 HC-204。[顶层窗口生命周期](../architecture/多人协作工作台顶层设计.md#43-桌面与后台生命周期) · [现有应用入口](../../../apps/desktop/src/main/index.ts)

两条非 ACP 链路各自达到真实端口前置后即可接入，互相无需等待。2026-11-11 共享实时更新停点通过复核，HC-199 原设备只读端口已就绪，先装配本节的只读文件/Git 视图及中央文件页签，再安排停点四的个人持久恢复与原生后台。

- **HC-198。** 评审待接手、交接、授权引用检索和固定快照的端口。真实服务就绪后将当前用户可见结果投影到导航、顶栏、时间线与 `@` 候选，显式打开来源时校验权限。正常路径看一条真实待接手或固定引用。原生会话接续和引用进入 Agent 随停点六。
- **HC-199 与 HC-196，当前只读部分。** 复用已交付的会话级项目读取：main 以 `readProject(workspaceId, conversationId, action)` 调用 `POST .../project/read`，沿用身份代次、CSRF 及 `ProjectReadAction/ProjectReadResponse` schema，原设备和项目由 Java 解析。`listDirectory`、`searchCandidates`、`readPreview`、`gitStatus`、`gitDiff` 分别接文件树、输入候选、右侧/中央预览、变更列表和 Diff；分页、版本和快照按服务结果处理。右侧 `ProjectDock` 与中央 `ProjectFileTab/ProjectFilePanel` 共享已授权内容，按完整项目范围和路径维护个人页签、选择及滚动；对话保持挂载及实时订阅。切换范围过滤迟到结果，失权清除业务缓存，离线缓存标为非实时。提交和推送维持实际不可用原因。正常路径走原项目目录 → 右侧预览 → 中央文件页签 → 关闭回到对话，再查看真实 Diff；写入等端口与授权就绪后另派发。[HC-198 Task](../task/HC-198-会话交接与内容引用.md) · [HC-199 Spec](../spec/HC-199-文件与Git服务迁移.md)
- **共享附件。** 上传和查看随已交付的具名端口及权限确认接入。目标设备授权下载与 ACP 内容块等停点六。
