# HC-218 会话只读与主动同步 — 实施计划

> 严格按停点推进：每到达一个停点立即完成受影响验证并停下等待统筹/用户确认，不跨停点连做。不调用 Skill，不自行修改服务端、Runner 核心或 ACP。

## 停点 1：两种会话模式与受控独立预览

**目标**：在不改后端、不打通真实执行的前提下，先确立 `features/session/` 领域状态模型与全部视觉/交互组件，并在独立预览中完整验证新会话准备、本机会话、跨机器只读（含同账号其他设备）与五种同步状态的正确切换。

1. 在 `apps/desktop/src/renderer/features/session/` 新建核心模块：
   - `contracts.ts`：定义会话本地同步状态（`unsynced | syncing | synced | has_update | sync_failed`）、`SessionIntegrationApi`、`SessionExternalHooks`、`LocalSessionExecutionPort` 与预览/宿主适配器契约。
   - `session-model.ts`：实现会话分类判定（本人本机 / 本人其他设备 / 他人设备）、`NavigationSessionEntry[]` 左栏条目与五态徽标生成、`HistoryMessage`（`user` / `assistant` / `tool_summary` / `status`）到 `ConversationTimelineEntry[]` 的防御性解码与序号递增校验（附完整单元测试）。
   - `new-session-page.tsx`：新会话准备页（"今天想推进什么？"、"选择文件夹"按钮、非 Git 文件夹提示、Agent 不可用状态说明、草稿保留）。
   - `remote-session-page.tsx`：跨机器只读页（只读头 + 简报卡 + 主动「同步会话 / 同步更新」触发区 + 已同步只读 `ConversationView` + 底部「创建任务 / 引用到我的会话」只读操作条）。
   - `local-session-page.tsx`：本人本机会话页（工作目录条 + `ConversationView` + 按实诚实禁用/启用输入区）。
   - `session-provider.tsx`：实现 `HC-217` 的 `ProjectPageProvider` 接口，负责中央页面分发、`right()` 仅向本人本机返回右侧栏、以及 `context()` 顶栏信息输出。
   - `session.css`：对齐 `docs/developer/previews/project-collaboration` 的主题变量、间距与浅深配色。
2. 建立独立预览入口 `apps/desktop/src/renderer/hc218-preview/` 与 `apps/desktop/electron.vite.hc218-preview.config.ts`，并在 `apps/desktop/electron.vite.config.ts`、`apps/desktop/package.json` 及 `scripts/workbench/ui-preview.mjs` 增加 `hc218` 预览配置。
3. **验证与停点收口**：运行 `npm run build` / `npm run typecheck` / `npm run check:boundaries -- --self-check`、会话模型单元测试，以及通过构建并启动 `preview:session`（或 `hc218` 预览）人工/截图核对两种会话模式、同账号其他设备只读与浅深主题，勾选停点 1 Todo 并等待确认。

## 停点 2：真实契约切换、简报列表与主动正文同步

**目标**：接入 `HC-211` 真实的四个项目会话 HTTP 路由，完成契约统一与 `PersonalStore` 同步状态持久化，在正式桌面端登录真实演示账号看到成员简报并主动同步正文。

1. **契约与主进程网络迁移**：
   - 在 `packages/workbench-contracts/` 中整理旧 `conversation.ts`（保留 `device.ts` / `execution.ts` / `runner-core` 所需的基础时间与标识类型），从 `organization.ts` 正式导出 `ConversationSummary`、`ConversationListResponse`、`ConversationDetailResponse`、`ConversationRegisterRequest`、`ConversationHistoryResponse`、`HistoryMessage` 等，并新增 `session.ts` 声明 `ProjectConversationHost` 与 `LocalDirectoryHost`。
   - 升级 `apps/desktop/src/main/collaboration-client.ts`、`collaboration-state.ts`、`collaboration-ipc.ts`、`preload/index.ts` 与 `renderer/env.d.ts`：接入 `/api/v1/workspaces/{workspaceId}/projects/{projectId}/conversations*` 四个真实接口（使用 `organization` Schema 严格校验）。
2. **`PersonalStore` 升级与正文缓存隔离**：
   - 升级 `apps/desktop/src/personal-host.ts`、`apps/desktop/src/main/personal-store.ts` 与 `apps/desktop/src/renderer/personal-persistence.ts`：
     - `kind: "conversation"` 改为 `{ workspaceId, projectId, conversationId }` 并通过 `getProjectConversation` 鉴权，支持保存阅读滚动、工具折叠、草稿、绑定本机目录及带容量兜底的正文缓存 `syncCache`；
     - 新增 `kind: "projectDraft"`（`getProject` 鉴权）持久化新会话准备页草稿与待选目录；
     - 将旧 `kind: "project"` 改名为 `kind: "sessionWorkspace"`（`getProjectConversation` 鉴权）。
3. **客户端真实数据流驱动**：
   - 在 `features/session/use-project-sessions.ts` 实现：
     - 进入项目后仅拉取 `listConversations`，生成 `NavigationSessionSource`；
     - 切入他人/其他设备会话先读简报，**仅在用户点击「同步会话 / 同步更新」时**调用 `readHistory(afterSequence)` 分页增量拉取并落盘；
     - 支持后台元数据刷新对比远端 `syncedSequence` 与本地缓存水位产生「有更新」标识，且不覆盖当前页面与滚动；
     - 支持账号切换、项目切换、注销及断网失误时的竞态丢弃与缓存回退。
   - 在 `desktop-workbench.tsx` 串行接入 `useProjectSessions` 的会话来源与新会话/只读浏览页面（本机文件浏览在停点 3 装配）。
4. **验证与停点收口**：运行 `npm run build`、`npm run typecheck`、`npm run check:boundaries -- --self-check`、`npm run test:project`，并启动桌面端连接真实 Java 后端进行停点 2 冒烟（登录 → 查看真实项目各成员简报 → 点击主动同步 → 重开恢复「已同步」状态），记录结果并停下等待确认。

## 停点 3：本机目录装配、HC-219/220 接点收口与旧废代码清理

**目标**：完成本机会话右侧 `ProjectDock` 与中央 `ProjectFileTab` / `ProjectFilePanel` 复用、本机原生选目录建会与普通目录安全阅读、暴露 HC-219/220 协作用接口、诚实锁定 Agent 不可用边界，并彻底清除被替换的 HC-202 旧会话代码。

1. **本机安全目录阅读适配（`apps/desktop/src/main/local-directory-host.ts`）**：
   - 主进程新增绑定到用户选定目录根的只读文件服务（`bindDirectory`、`readDirectory`），严格执行 `realpath` 与作用域防逃逸校验，提供目录树、`@` 文件候选与文件内容预览；
   - 检测目录内是否存在 `.git`：普通非 Git 文件夹在「变更」面板正常返回温和空态（不报错），有 `.git` 时提供只读 Git 状态与 Diff，保留 `commit`/`push` 禁用状态（「Git 写操作暂缓」）。
   - 接入 `local-session-page.tsx` 右侧 `ProjectDock`（含宽度/面板持久化到 `sessionWorkspace`）与中央 `ProjectFileTab` / `ProjectFilePanel`。
2. **新会话建会与 `LocalSessionExecutionPort` 装配**：
   - 在已登录且拥有可用 `localDeviceId` 时，新会话准备页支持「选择文件夹 → 输入 → 登记项目会话元数据并绑定目录进入本人本机会话」；未登记设备时清楚提示而不造假记录。
   - 接入 `LocalSessionExecutionPort` 默认只读不可用提示（「本机 Agent 与运行链路（ACP/Runner）尚未接入，暂不支持发送或取消」），预留给同事后续接线。
3. **暴露 HC-219/220 协作用接点并验证**：
   - 通过 `desktop-workbench.tsx` 与 `session/contracts.ts` 对外提供 `SessionIntegrationApi`（`refreshMetadata`、`prepareMySession`、`listMyLocalConversations`）及 `SessionExternalHooks`（只读条「创建任务」「引用到我的会话」回调槽与输入扩展槽）。
4. **废码清理与文档收尾**：
   - 删除已被完全替换的 HC-202 旧文件：`apps/desktop/src/renderer/{conversation-area.tsx,conversation-feed.ts,conversation-history.ts,conversation-personal.ts,workspace-conversations.ts,project-workspace.ts,project-center.tsx,list-availability.ts}`、`apps/desktop/src/main/conversation-delivery.ts` 与 `apps/desktop/src/project-read-host.ts`（并检查全局无悬空导入）。
   - 同步更新 `docs/user/独立桌面工作台.md`（若适用/按 Task `user_docs` 要求）与 `docs/developer/architecture/` 中桌面会话架构描述，并在 `HC-218` Task 登记真实阻塞/外部前置与验证证据，状态置为 `待验收`（不自动归档）。
5. **最终验证与交付**：执行 `npm run build`、`npm run typecheck`、`npm run check:boundaries -- --self-check`、`npm run project:check`、`npm run test:project`、Session 模块单测与完整正式入口主路径冒烟（新建选择普通文件夹 → 浏览本机文件 → 切换至跨机器会话确认只读与主动同步 → 核对 Agent 未接入如实提示），汇报结果并标 `待验收`。
