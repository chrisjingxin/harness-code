# HC-217 项目导航与资料：实施计划

状态：草稿，待评审。行为与接口以 [Spec](../spec/HC-217-项目导航与资料.md) 为准，范围以 [Task](../task/HC-217-项目导航与资料.md) 为准，执行清单见 [Todo](../todo/HC-217-项目导航与资料.md)。三个停点依次推进，每个停点完成后停下等待确认，不连做。

## 1. 总体顺序

```text
停点 1：导航外壳（受控数据，隔离预览）
   └─ 纯视图组件 + 导航状态逻辑，替换旧导航与 hc208 预览
停点 2：真实项目资料（演示服务）
   └─ 契约导出 → 主进程客户端/IPC/preload → 个人状态 → 项目选择、创建、资料页 → 删除旧设备项目链路
停点 3：页面装配
   └─ 页面提供者接点 → desktop-workbench 改为 Project 外壳 → 摘下旧会话装配 → 接入已交付的页面
```

停点 1 先交付，HC-218～220 即可按 Spec §3.5 的类型开发各自页面；停点 2、3 不阻塞它们的独立界面。

## 2. 停点 1：导航外壳（受控数据）

**用户能看到**：在隔离 Electron 预览中，左栏与视觉稿一致；三个示例项目可切换，各自恢复上次页面、选中会话和成员展开；本人组撑满，他人组置底，展开后独立滚动；搜索时命中组临时展开、折叠按钮禁用，清空恢复；有一个成员无会话时显示"暂无会话"；项目设置与"创建项目"入口分开；浅深主题与短窗口正常。中央只显示页面名占位，不接真实服务。

**做法**：

1. `packages/workbench-ui/src/navigation/`：删除 `CollaborationNavigation` 及设备树类型和样式，新写 `ProjectNavigation`。输入为一个视图对象：品牌、项目列表与当前项目、项目列表可用状态、成员组（`userId`、显示名、是否本人、是否已离开、展开状态、会话行）、会话来源可用状态、搜索文本、当前页面、任务数量（可空）、账号显示信息。输出为具名动作：`selectProject`、`createProject`、`openProjectSettings`、`openPage`、`selectConversation`、`toggleMember`、`setSearch`、`retry(area)`、`openSettings`。组件内不发请求、不存状态。样式以视觉稿 `preview.css` 的导航部分为基准迁入 `navigation.css`，只用公共主题变量。
2. 同目录导出纯函数 `buildMemberGroups(members, entries, selfUserId, expanded, selfCollapsed, search)`：按 Spec §2.2 归组、排序、同名区分、空态、已离开标记和搜索临时展开。逻辑集中在这一处，桌面与预览共用，便于后续测试。
3. `packages/workbench-ui/src/index.ts` 与 `package.json` 的出口改为新组件名，去掉旧名。
4. 预览：`apps/desktop/src/renderer/hc208-preview/` 删除，新建 `hc217-preview/`（入口、样式、受控夹具：3 个项目、4 名成员含 1 名无会话和 1 对同名、若干会话条目）。`electron.vite.config.ts` 的预览目标、`electron.vite.hc208-preview.config.ts`（改名为 hc217）、`scripts/workbench/ui-preview.mjs`、`apps/desktop/src/main/index.ts` 的预览标题表和 `apps/desktop/package.json` 的 `*:navigation-preview` 命令统一改指 hc217。
5. 检查其他引用旧导航的地方（`hc205`～`hc207` 预览、正式 `desktop-workbench.tsx`）。正式装配在停点 3 才重写；停点 1 期间 `desktop-workbench.tsx` 先改用 `ProjectNavigation` 并传入"项目列表尚未接入"的空视图，保证正式入口能构建和打开。

**验证**：`npm run build --workspace @workbench/ui`、`npm run typecheck`、`npm run check:boundaries -- --self-check`、`npm --workspace @workbench/desktop run build:navigation-preview`；打开预览走"切换项目 → 展开他人成员再收起 → 搜索再清空 → 打开项目设置入口 → 回到本人会话"，切换浅深主题并缩小窗口高度各看一次。

## 3. 停点 2：真实项目资料

**用户能看到**：连接本地演示服务并登录后，左栏项目下拉显示真实项目；可创建项目并进入资料页；所有者能编辑名称/说明、添加/移出成员、关联/取消仓库，普通成员只读；失败时看到具体原因且输入保留；重开应用回到上次项目。成员组为真实项目成员，会话区显示"会话列表尚未接入"。

**做法**：

1. **契约包**：`packages/workbench-contracts/package.json` 的 `exports` 加 `./schema/organization`；删除 `device.ts` 中 `ProjectSummary`、`ProjectListResponse`、`ProjectPageCursor`、`ProjectStopSharingRequest`、`ProjectSavedResponse`，若 `DeviceProjectPublishRequest` 等因此无引用一并删除（以类型检查结果为准，不碰 Runner 使用的消息类型）；`index.ts` 去掉组织层过渡别名，改为正式名导出。改完 `npm run contracts:smoke`，并在 Task 记录中告知同事。
2. **主进程客户端**：`collaboration-client.ts` 的类型定位改为 `(schemaId, name)`；写请求支持 PATCH/PUT/DELETE，均附 CSRF，204 返回 `null`；新增 9 个组织方法（Spec §3.2）。删除 `listProjects`、`stopSharing`。
3. **主进程状态与 IPC**：`collaboration-state.ts` 新增组织方法，沿用"已登录 + 工作区属于本账号 + 回包核对代次"的同一模板；`collaboration-ipc.ts` 注册 `organization:*` 通道，参数按 UUID 与契约 Schema 校验；`device-ipc.ts`、`device-host.ts` 删除 `list-projects`、`stop-sharing`。
4. **宿主端口**：新建 `apps/desktop/src/organization-host.ts`（`OrganizationHost` 类型）；preload 暴露 `window.organization`，删除 `devices.listProjects/stopSharing`；`renderer/env.d.ts` 补全局声明；`DeviceRegistrationPanel` 删除"停止共享"。
5. **个人状态**：`personal-host.ts` 与 `personal-store.ts` 按 Spec §3.4 重定义 `workspace` 记录、新增 `projectNavigation` 记录（授权时调用 `getProject`），存储目录改为 `personal-view-v2`。`conversation`、`project` 两种记录保持现状，留给 HC-218。
6. **renderer 功能模块** `apps/desktop/src/renderer/features/project-navigation/`：
   - `use-projects.ts`：项目列表加载/刷新/失败、当前项目选择、失效选择处理、无项目空态。
   - `use-project-members.ts`：项目详情 + 团队成员合并显示名，提供成员名单和 `role`。
   - `use-navigation-personal.ts`：读写 `workspace`、`projectNavigation` 记录，按范围隔离，迟到结果丢弃。
   - `project-info-page.tsx`：资料页三块内容及管理操作，错误码按 Spec §4 转提示。
   - `create-project-dialog.tsx`：居中表单，一次性 `requestId`，失败保留输入。
   - `index.ts`：模块出口。
   `desktop-workbench.tsx` 接入以上模块：左栏用真实项目与成员；中央暂只有资料页可用，其他页面显示"尚未接入"。
7. 删除 `renderer/conversation-navigation.ts` 和 `workspace-devices.ts` 的设备树部分；设置页本机设备登记改为直接读 `DeviceHost.getState`。

**验证**：受影响包构建与 `npm run typecheck`、`npm run check:boundaries -- --self-check`、`npm run contracts:smoke`；`npm run server:build && npm run server:init-demo && npm run server:start` 起本地演示服务，用演示账号走"创建项目 → 进入资料页 → 添加成员 → 关联仓库 → 换普通成员账号确认只读 → 重开应用恢复项目"。真实接口证据与停点 1 的受控证据分开记录。

## 4. 停点 3：页面装配

**用户能看到**：会话、看板、任务、知识四类页面通过同一外壳切换；已交付的页面显示真实内容，未交付的显示"尚未接入"；从会话切到看板再回来，草稿、文件页签和阅读位置不变；切换项目后各页面只显示新项目内容。

**做法**：

1. 在 `features/project-navigation/` 定义并导出 Spec §3.5 的 `ProjectNavigationScope`、`ProjectPage`、`ProjectNavigator`、`NavigationSessionEntry`、`NavigationSessionSource`、`ProjectPageProvider`。
2. `desktop-workbench.tsx` 重写为：身份/团队恢复 → 项目选择 → `WorkbenchLayout` + `ProjectNavigation` + 按 `page.kind` 选择提供者；会话提供者在项目范围内常驻挂载，切页只改 `visible`；右栏与顶栏由提供者的 `right`、`context` 决定。
3. 摘下旧会话装配（`ConversationArea`、`ProjectCenter`、`ProjectDockArea`、旧 `conversations`/`projects` 端口的调用），文件本身由 HC-218 替换后删除。
4. 按 HC-218～220 的实际交付逐个接入：会话来源与会话/新对话页（HC-218）、任务/知识页（HC-219）、看板与任务数量（HC-220）。每接一个做一次构建与主路径冒烟，未交付的保持"尚未接入"。

**验证**：受影响构建/类型/边界检查；走 Task 指定冒烟"切换项目 → 展开他人成员再收起 → 打开项目设置 → 回到本人会话"，并确认回到会话后草稿保留。完整组合与双平台归 HC-204。
