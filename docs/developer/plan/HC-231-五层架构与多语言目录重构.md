# HC-231 五层架构与多语言目录重构 — 实施计划（Plan）

## 总体推进策略

按**自底向上、每步独立可编译或独立可测试**的原则分 **5 个可演示停点** 渐进完成目录收敛，避免一次性大搬家导致编译报错难以定位：

1. **停点 1**：先把跨语言协议源 `contracts/` 提纯并抽出可独立发包的第 2 层 `@workbench/collaboration-client`；
2. **停点 2**：完成第 3 层 `@workbench/acp-runtime` 收口、第 4 层 `@workbench/harness-acp` 简化与顶层 `agent/` 归位，下线 `pi` / `qwen` 测试桩；
3. **停点 3**：完成第 5 层 `server/` 归位与第 1 层 `desktop/` 内聚（合并 `workbench-ui`、`project-service`、桌面内部契约，并拆分瘦身 `local-execution-ipc.ts`）；
4. **停点 4**：收口 4-workspace 根配置、`check-boundaries.mjs` 新五层门禁、`scripts/project/*` 与全仓架构及用户文档；
5. **停点 5**：完成 TypeScript + Python + Java 三语言全量校验与 Electron 桌面启动冒烟，申请验收。

## 停点详细规划

### 停点 1：跨语言协议提纯（`contracts/`）与第 2 层 SDK 独立成包（`packages/collaboration-client`）

- **核心动作**：
  1. 在仓库根目录建立纯净 `contracts/`，迁入 `platform` / `organization` / `collaboration` 的 OpenAPI、JSON Schema、合法/非法 fixtures 与 `resources.json`；删除废弃 `device` / `execution` / `conversation` / `project` Schema/OpenAPI/夹具及对应的 `contracts:smoke` 死检查。
  2. 新建 workspace `packages/collaboration-client`（`package.json` 零内部 `@workbench/*` 依赖），提供 `"."` 与 `"./types"` 双入口：
     - 将线上协议 TS DTO（`identity`、`organization`、`collaboration`）迁入 `src/types/`；
     - 将 `CollaborationClient`、`CollaborationState`、`ProjectUpdatesService`、`ProjectNotificationStream`、`ProjectNotificationCursor`、`ConversationUploads` 及相关单测迁入该包；
     - 在 `CollaborationClient` 中移除已无用的 `conversationSchema` 与 `projectSchema` Ajv 编译预加载；
     - 为 `ConversationUploads` 定义自有纯 `CollaborationConversationScope` / `collaborationConversationKey`，彻底解除对桌面执行层的反向引用；
     - 配置该包 `build` 脚本自动将顶层 `contracts/schema/*.json` 内联进自身 `dist/schema/`，确保单包独立发布可用。
  3. 让旧位置（尚未重命名的桌面与 Java 服务临时过渡或双向指针同步）先切换至 `@workbench/collaboration-client` 与顶层 `contracts/`。
- **停点验证**：
  - `packages/collaboration-client` 独立完成 `tsc` 编译、独立打包校验及原有协作客户端/更新流/上传队列单测全绿；
  - `scripts/workbench/check-contracts.mjs` 基于顶层 `contracts/` 通过；`server`（或 `services/collaboration-server`）指向新 `contracts/` 后 `mvn test -Dtest=ContractsTest` 通过。

### 停点 2：第 3 层 `packages/acp-runtime` 收口 + 第 4 层 `packages/harness-acp` 与顶层 `agent/` 归位

- **核心动作**：
  1. 在 `packages/acp-runtime/src/` 中建立 `descriptor.ts`、`discovery.ts` 与 `registry.ts`，统一导出标准 `AcpAgentDescriptor` 接口、`buildAugmentedGuiPath` / `findInPath` / `resolveGitMainWorktreeRoot` 公共探测函数、`AcpAgentRegistry`、`createCommandAgentDescriptor` 通用外部命令驱动与 `"./types"` 纯 DTO 子入口。
  2. 将 `packages/providers/harness/` 迁为 `packages/harness-acp/`（包名 `@workbench/harness-acp`），删除其内部重复的 `types.ts` 与通用 `PATH` 遍历实现，仅保留 Harness 专属 `agent/.venv` / `harness-agent` 定位与 `_meta.harnessCode` 扩展解析。
  3. **移除测试桩包 `packages/providers/pi` 与 `packages/providers/qwen` 及其空父目录 `packages/providers/`**；将多代理切换、自定义外部命令接入、纯标准 ACP 无 `_meta` 扩展兼容性测试沉淀到 `packages/acp-runtime/tests/` 的 Mock 标准 ACP 子进程单测中。
  4. 将 `packages/agent/` 迁为顶层 `agent/`，把 `examples/plugins/` 移入 `agent/examples/plugins/`；升级 `agent/pyproject.toml`（名称对齐 `harness-agent` 并同步检查 `uv.lock`），更新 `agent/scripts/check_dependencies.py` 的仓库根回溯路径 `parents[2]` 与 `desktop/node_modules` 扫描路径及对应单测（核查协议兼容断言）。
- **停点验证**：
  - `packages/acp-runtime` 与 `packages/harness-acp` 构建、类型检查及 Bun/Node 单测（含 Git worktree 自动探测 `agent/.venv` 与 Mock 标准多代理切换）全绿；
  - `agent/` Python 依赖防 Anthropic 检查脚本与相关单测全绿。

### 停点 3：第 5 层 `server/` 与第 1 层 `desktop/` 去套壳内聚及 IPC 瘦身

- **核心动作**：
  1. 将 `services/collaboration-server/` 移至顶层 `server/`（更新 `server/pom.xml` `<directory>../contracts</directory>` 及 `scripts/workbench/` 内的服务端部署/冒烟路径），移除空 `services/` 目录。
  2. 将 `apps/desktop/` 移至顶层 `desktop/`，移除空 `apps/` 目录；
     - 合并 `packages/workbench-ui/src/` → `desktop/src/ui/`（保留各 CSS 独立分组与导出口）；
     - 合并 `packages/project-service/src/` → `desktop/src/main/project-service/`（将 `local-directory-host.ts` 类型统一复用内部类型，避免重复 `ProjectReadResponse`）；
     - 将原 `workbench-contracts/src/` 中的桌面专属端口/类型（`DesktopHost`、`desktop-hosts`、`session`、`personal` 及本地只读 `project` 精简类型）迁入 `desktop/src/shared/`，删除 `personal-host.ts` 与 `packages/workbench-contracts`（清理完遗留引用后删除该包）。
     - 收敛桌面渲染层直接消费 `@workbench/acp-runtime/types`，移除 `desktop/src/local-execution-host.ts` 中冗余同构 DTO 复制与 `toExecutionSessionState` 逐字段搬运。
  3. 拆分 954 行的 `desktop/src/main/local-execution-ipc.ts`：拆为“目录授权存储与 `@file` 沙箱读取模块”“ACP 回合执行与 `@workbench/collaboration-client` 定稿上传协调模块”“纯 Electron IPC 注册层”，并扩展 `ipc-guard.ts` 以接管全部 `localExecution:*` 通道入参校验。
  4. 清理空余 `packages/workbench-contracts`、`packages/workbench-ui`、`packages/project-service`。
- **停点验证**：
  - `desktop/` 主进程 + Preload + 渲染层 `electron-vite` 全量构建、TypeScript 类型检查与桌面原单测全部通过；
  - 全部历史 preview 入口可正常编译；
  - `server/` 目录独立 Maven 编译/测试通过。
