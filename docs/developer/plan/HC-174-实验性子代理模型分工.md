## 1. 交付顺序

先让只读助手真实使用指定模型，并保持当前文件和权限规则；随后让用户核对主、子模型完整用量；最后让可选的通用执行助手复用同一机制。每段跨越必要的配置、运行时和展示层，形成可观察结果，不按技术层逐层堆积。

```text
A1 配置与预检 → A2 唯一角色绑定 → A3 只读 Managed 执行
  → A4 文本交接、错误与只读展示 → 停点 A：指定模型调查
  → B1 按调用计量 → B2 全终态归账 → B3 协议、历史和界面
  → 停点 B：看清主子总开销
  → C1 通用角色执行 → C2 审批恢复与部分修改失败
  → C3 完整验收和文档 → 停点 C：指定模型执行任务
```

一轮实现只到下一个停点，完成后更新 Todo、记录验证证据和 `tmp/handoff.md`，等待用户看过。A/B 是阶段性交付，不代表整个 Task 完成；完整 Task 只能在 C 验收与 review 后归档。

## 2. 已确定的实现取舍

- 一个配置入口：Host TOML `[experimental.delegation]`，默认关闭、重启生效；必须先把 `[experimental]` 登记进 `ConfigManifest.SECTIONS`。模型引用已有 Profile。未绑定角色保持原路径，Plugin 与 `[models.roles]` 不被覆盖。不加入 `config.write` 白名单。
- 一个角色一个实际 target：绑定角色使用现有 Managed engine/executor，且 `engine_profile_key` 必填；未绑定角色 Inline。图与记录共用实际绑定，池身份包含有效绑定。
- Managed 化保持内建角色现有能力：`explore` 仍五只读、不挂父 MCP/Skill；`general-purpose` 仍继承父 MCP/Skill 与 auto-edit 例外，不走 Plugin Agent Hook 装配。
- 一个现有文本返回链：不新增 JSON、12 KiB、partial 元数据、格式错误或修复模型调用；复用通用大结果外存行为（`task` 不在 DeepAgents 排除列表中）。
- 主模型只接收最终文本，工具过程与完整阅读历史不自动回灌；简洁与证据由实验提示词引导。
- 计量以一次可观察模型调用为单位，不能相加 `StreamSession.update_usage` 的 session 最大值或依赖 UI 事件推算；未知值保持不完整。旧 `run.completed.usage` 保持现有整数形状；新摘要是另加的可选 `delegation_usage`。
- 不安装依赖、不改真实用户配置、不进行真实模型实验。所有自动演示和验证使用隔离 fixture 与 mock provider；真实 `bun run dev` 仅作为用户自行启用后的查看方式。

完成信号：关闭不解析闲置引用；开启后预检失败不启动 root/child 模型调用；有效 Profile ID 可在脱敏配置中核对，凭据和 endpoint 不出现。

验证：V1；Task 验收 1/2。规模 M，Host 接入与配置解析分开提交/验证，避免一个执行项修改整个配置栈。

### A2 唯一绑定与 engine 身份

完成信号：同名角色不会同时注册 Inline 和 Managed；父 `/model` 切换不改变已显式绑定的 child；未绑定者继承本次父模型，Plugin 保留自身规则；不同绑定不能错误复用池内图。

完成信号：mock pro 发出 task，mock fast 实际处理只读子任务，父收到最终文本并继续；execution 身份、lease 和 checkpoint 独立；只读工具上限、父动态权限、Plan 约束和池容量限制保持有效。

### A4 交接、错误和用户可见证据

范围按依赖分小步：① `agent_delegation.py` / `child_stream.py` 的失败收敛；② 实验角色提示装配；③ CLI 现有 child 卡片的实际 Profile 展示及隔离 fixture。

先覆盖 provider 已知失败、超时、父取消竞态和 lease 回收，再接入现有 task 错误转换。权限/身份/未知错误不吞掉。普通文本和 Markdown 不做 JSON 校验；超大 task 结果经过真实 middleware，外存成功/失败与基线一致。用原文标记测试父请求与历史隔离；摘要不授予父 Snapshot。

完成信号：child 卡片显示真实 Profile 与状态，父可继续精准读取；关闭时提示与行为无变化。只读助手禁写、禁 Shell、禁嵌套 task；没有新长度阈值。

### 停点 A 怎么看

## 4. 停点 B：主子用量可核对

### B1 按调用记录，保留未知与重试消耗

范围：既有 model lifecycle、`execution_stream.py`、相邻 runtime 测试。沿实际模型调用分配身份，关联 execution/Profile/round/attempt；同一调用分片与最终消息只结算一次，不从日志回读。

完成信号：多轮 10+20 得 30，不取最大值 20；同一事件重复不增加；失败 attempt 的已知用量不会随内容回滚消失；缓存不重复算输入，推理不盲目加输出；缺字段显示不完整，零调用才是完整零。

验证：V5；Task 验收 8。规模 M。辅助调用无法覆盖时必须使合计不完整，不扩大为新计费平台。

### B2 Inline/Managed 全终态归账

范围分两步：① `child_stream.py` / `managed_agent_executor.py` / `agent_delegation.py` 传递调用自身用量；② `agent_execution.py` / `run_coordinator.py` 终态汇总与历史落点。

完成信号：root=30、child=7 得 total=37；子流进父 UI 不算父调用；正常、失败、取消均保存已知消耗，Registry 丢弃前已生成摘要；墙钟不相加并行 child 时长。实验关闭不改变旧 usage 展示与终态形状。

验证：V5 + V6；Task 验收 7/8。每小步 M。Plugin/未绑定 Inline 若在该实验 Run 内发生调用，同样纳入合计或明确不完整，不能无声遗漏。

### B3 协议、历史与展示一次接通

范围分两步：① `packages/protocol/schema/v3.json` 定义 Spec 6.2 摘要，经生成脚本更新 Python/TS；Host 将摘要加入 completed/failed/cancelled 并沿现有终态持久化。当前 cancelled/failed payload 没有 usage，三份 payload 均为 `additionalProperties: false`，必须改 schema 而不能塞额外字段。旧 `usage` 仍是整数 input/output/cached。② CLI shared state/selector 和 TUI/Web 终态展示消费同一摘要；`/agents` 对已绑定角色显示实际 Profile。

完成信号：实时与回放均区分“主模型自身”“含助手合计”，执行详情显示实际 Profile、状态、耗时和用量；缺失为未知或至少 N，旧历史不伪造完整统计；不建立新计费数据库、页面或货币估算。诊断契约同步生成，内容不含提示词/源码/秘密。

验证：V6 + V7 + V8；Task 验收 8/9。这是跨层纵向行为，生成文件随 schema 一次更新，不为符合文件数量人为拆断契约；手写生产逻辑按 Host 与 CLI 两个相邻步骤推进。

### 停点 B 怎么看

用 fixture 重放三种终态和未知数据，终态区显示 root 30 / total 37；刷新或切回历史后数值一致，child 行为 7。失败与取消仍显示已知消耗，没有 child 的实验 Run 合计等于自身。用户真实使用时仍由 `rtk bun run dev` 查看同一摘要，不要求本轮发真实模型请求。更新文档和证据，停止等待查看。
