## 1. 实施总览与拆分原则

一个 Maven 模块内整体换模型，按"先立 DDL 与拆旧 → 再建组织层 → 再装会话只读面"推进，每停点独立可演示。**拆旧必须最先做**：旧表列删掉后所有编译引用是天然的拆除清单（spec §1.2 不变量 1）。

```text
停点一：单文件 DDL + 启动核对 + 旧派发链路拆除（骨架换血）
  → 停点二：组织层领域 + 持久层 + 访问策略（血肉）
  → 停点三：组织层路由 + 契约 schema + 权限矩阵（可见接口）
  → 停点四：会话登记/同步/简报/历史 + 设备心跳（协作打通）
```

依赖顺序固定：一 → 二 → 三 → 四（停点三可演示后停点四纯增量）。

## 2. 停点一：单文件 DDL + 启动核对 + 旧派发链路拆除

**目标**：`schema.sql` 声明 11 张表可手工建库；启动核对生效；所有引用旧表/旧链路的代码删除，模块编译通过。

| 步骤 | 内容 | 说明 |
| --- | --- | --- |
| 2.1 | `src/main/resources/db/schema.sql` | 按 spec §2 写 11 张表 DDL + `demo-data.sql` |
| 2.2 | 拆 Flyway 与旧迁移 | `pom.xml` 删 flyway 依赖与 websocket starter；`application.yml` 删 flyway 段；删 `db/migration/`；`Application` 删 `migrate` 命令 |
| 2.3 | 改 `Foundation` | 只读核对 REQUIRED（11 表 + 新语义列抽查）+ REMOVED 清单，缺失打印并 `IllegalStateException` |
| 2.4 | 拆派发链路（编译引用清单驱动） | 删 `domain/execution/`、`DaemonWebSocket*`、`ConversationSseController`、`DaemonCommandPort`/`DaemonPresence*`/`SharedProject`、`ExecutionCodec`/`ContractEventEncoder`/`RealtimeBroadcastPort`、会话/执行控制器与 `ConversationAppService`/`ExecutionAppService`、device 共享项目方法与 `DeviceProjectPO`；`RouteCatalog` 删旧路由/常量；`Topics` 删两主题、`CacheKeys` 删三模式；`DevicePO`/`ConversationPO` 按新列裁剪（会连带编译错误处先删引用代码） |
| 2.5 | 拆测试与夹具 | 删被拆代码的全部用例；保留消息存储/身份/设备/基础设施用例并修到编译通过 |

**演示方式**：隔离空库不建表启动 → 打印 11 张缺失表并退出；执行 `schema.sql` 后启动成功；手工建一张 `wb_device_project` 再启动 → 拒绝启动打印禁止表；`mvn -q compile` 全绿。

**卡点**：编译报错即拆除遗漏清单，逐一处理不留引用；`ConversationPO` 新列此时无 Mapper 填充属正常（停点四补）。

## 3. 停点二：组织层领域 + 持久层 + 访问策略

**目标**：`domain/project`、`domain/repository`、`domain/access` 三包纯 POJO 落成，6 张新表持久层可读写，访问策略单测全绿。

| 步骤 | 内容 |
| --- | --- |
| 3.1 | `domain/project`：Project/ProjectMember/ProjectRepositoryRef + 枚举 + Repository 端口（含 CAS `updateIfVersion`、成员 upsert、引用存在性查询） |
| 3.2 | `domain/repository`：Repository/LocalRepoBinding + 端口（`remoteUrl` 唯一、归档翻转、绑定幂等 upsert/删除） |
| 3.3 | `domain/access`：`ProjectAccessPolicy`（spec §4.1 七方法语义，404/403/409 边界） |
| 3.4 | `domain/device`：`Device` 去 `workspaceId`、补 `DeviceHeartbeatPort`；`listByWorkspace`→`listByOwner` |
| 3.5 | `persistence`：5 张组织层新表 PO/Mapper/Converter/RepoImpl（`wb_conversation_repository` 留停点四）；`DevicePO`/`DeviceRepositoryImpl` 对齐 |
| 3.6 | `cache`：心跳键 `wb:device:hb:{deviceId}` TTL 45s 的 Memory/Jedis 实现 |
| 3.7 | 单元测试：访问策略全分支 + 领域不变量 + 持久层 fake（MyBatis fake 沿用现有内存实现模式） |

**演示方式**：`mvn test` 组织层用例全绿；策略测试覆盖"非成员 404 / removed 视同非成员 / 非负责人 403 / 归档 409 / owner 不能移出自己"。

**卡点**：`wb_project_member` 用 `(project_id, user_id)` 唯一 + `status` 翻转，不写删除——重新加入 = 翻回 active（D9 语义在此固化）。

## 4. 停点三：组织层路由 + 契约 schema + 权限矩阵

**目标**：项目/成员/仓库目录/引用/绑定 18 条新路由上线，契约 schema 更新，权限矩阵 curl 走查可演示。

| 步骤 | 内容 |
| --- | --- |
| 4.1 | `ProjectAppService`（创建/列表/详情/PATCH CAS/成员管理 + 幂等键）→ `ProjectController` + DTO |
| 4.2 | `RepositoryAppService`（目录 CRUD/归档）→ `RepositoryController` + DTO |
| 4.3 | `RepoBindingAppService`（设备凭据 + 拒绝本地路径）→ `DeviceRepoBindingController` |
| 4.4 | `RouteCatalog` 登记新路由；`workbench-contracts` + Java `Contract*` 新增 schema；`Application contracts` 自检含新路由 |
| 4.5 | `DeviceAppService`/`DeviceController` 改造：注册不写 workspace、`listByOwner`、DTO 删 workspaceId、吊销仅 owner |
| 4.6 | 应用层与控制器单测：矩阵正反例 + 幂等 + 409 语义 |

**演示方式**：隔离库启动后按 spec §5 矩阵 curl：团队成员建项目 → 加成员（非团队成员 409）→ 建仓库 → 项目引用 → 设备凭据 `PUT /device/repo-bindings/{repoId}` → 非项目成员访问详情返回 404；`server:contracts` 全绿。

**卡点**：404 vs 403 严格按 spec §5（存在性不泄露优先）；`clonedDevices` 联表只取调用者本人设备。

## 5. 停点四：会话登记 / 同步 / 简报 / 历史 + 设备心跳

**目标**：会话以新形态回到项目作用域，主人设备 sync 上传、成员拉简报与增量历史，整条只读共享链路走通。

| 步骤 | 内容 |
| --- | --- |
| 5.1 | `domain/conversation` 对齐 spec §2.4：`Conversation` 新字段 + `Brief` 值对象 + `SyncBatch` 校验规则 + `ConversationRepository` 端口（登记/简报/推进 `synced_sequence`）+ `wb_conversation_repository` PO/Repo |
| 5.2 | `ConversationSyncAppService`：会话登记（设备归属 + 仓库 ⊆ 项目引用）、`sync`（spec §4.3 流程：鉴权→校验→幂等→热窗→会话行→ES 索引→brief_updated 事件载荷经 `NotificationPort` 本地实现）、简报列表/详情、`history`（热窗优先 ES 回源） |
| 5.3 | 路由：`ProjectConversationController`（登记/简报列表/简报/历史）+ `DeviceSyncController`（sync + heartbeat）+ `RouteCatalog` 登记 |
| 5.4 | `MessageStorePort` 复用为"按序号读"：热窗 zset 写/范围读、ES 按序号翻页；`DeviceSummary.state/lastSeenAtMs` 接心跳键 |
| 5.5 | 契约 schema：会话登记/简报/历史/sync/心跳请求响应；`server:contracts` 更新 |
| 5.6 | 单元测试：SyncBatch 校验、幂等重复批次、跳号 409 返回 `expectedSequence`、非主人设备 403、owner 被移出后 sync 被拒、登记仓库越界 400、历史分页/afterSequence 边界 |

**演示方式**：隔离库走通"建项目→登记会话→设备 sync 两批消息+简报→成员 `GET conversations` 看到简报→`GET history?afterSequence=` 只拉到增量→重复 sync 幂等→跳号 409"；`DeviceSummary` 展示在线来自心跳 TTL。

**卡点**：事件载荷本停点只产出不投递（`NotificationPort` 日志实现，Kafka 投递归 HC-212）；`task_id` 落列不校验存在性（`wb_task` 未建）。
