## 1. 交付顺序与不变量

旧 Web 的右侧文件与变更、中央只读文件页签已有组件和样式，但依赖旧 Adapter。新 UI 按源码迁出这些界面，替换为受控视图值、个人状态与动作，不重新绘制整区，也不复制旧控制器。用户能先在真实窗口中查看和操作文件视图，再在同一预览中观察 Git 变更和分离结果。

```text
统筹分配公共图标/解析器及出口的串行时隙
→ 停点一：右侧文件树、阅读器和中央文件部件可演示
→ 停点二：右侧变更、Diff 和个人选择/提交说明可演示
→ 真实项目服务、原设备路由与完整工作台另行集成和验收
```

每个停点由统筹明确派发文件与构建/窗口时隙后执行；到达可见停点或遇到真实阻塞时回调一次并停止，不轮询。两份公共源码是支持两个可见停点的最小前置，不单独冒充用户可演示停点；可在同一停点派发中安排两个互不重叠的写入时隙，尽早提供 HC-206 使用。HC-206 不必等待 HC-207 整卡完成才做其他对话工作。

全过程保留当前 `harness_lody` 工作树和已有未提交内容，不切分支、不建 worktree、不 stash/reset/clean，不提交/推送；旧 Web 源码与设计稿只读保留。不要调用 Skill 或派生隐藏代理。ACP 协议、适配、能力/事件映射、Agent 状态接线与联调等待同事交付；不启动 ACP、mock Agent、Java、Runner 或实际项目服务。受控回调与展示结果不能冒充真实读取、Git 提交或推送。

## 3. 停点一：文件树、阅读器和中央文件部件

**可见结果：**统筹接好第 5 节隔离预览后，在真实 Electron 窗口看到右侧“文件/变更”主 tab、文件树及右侧只读阅读器。打开两个路径不同但同名的文件，能切换和关闭右侧页签、看到路径/语言/大小/行数、高亮与行号，也能把文件显式打开到预览中的中央文件部件。窗口缩放和浅/深切换后内容、图标及按钮仍可读；没有连接项目服务。

### 3.1 实施内容

1. 在独占的 `packages/workbench-ui/src/project/` 下按 Spec 拆 `project-dock.tsx`、`file-explorer.tsx`、`file-tree.tsx`、`file-panel.tsx`、`file-tabs.tsx`、`file-preview-header.tsx`、`file-content.tsx`、`file-meta.ts`、`workbench-file-tab.tsx`、`workbench-file-panel.tsx`、区域类型/动作和 `project.css`；组件实际拆分可保持等效，但不能改公共契约或侵入其他目录。文件树仍在右侧，使用公共 `FileTypeIcon`。
2. 将旧最终生效的 Dock、树、阅读器和文件页签 JSX/CSS 分区迁出；保留主 tab 的开合/宽度/键盘、树缩进/焦点/目录展开、右侧页签最近使用顺序与上限、路径/元信息、空态/加载/错误/截断、刷新与独立打开中央的意图。使用公共主题与 `HighlightedCode`，未知语言保持可选择原文；Markdown 默认仍为带行号的源码，不新增渲染切换。
3. 以 `namespace/accountId/workspaceId/deviceId/projectId` 作为项目状态范围，文件再按相对路径分区。明确目录树投影、两个独立文件页签的引用与释放、刷新失败时旧内容的非实时标记、离线/无权/只读/过大/截断等视图；迟到的旧 scope/旧请求不能改变当前内容。中央文件页签仅暴露部件与动作，整体对话/文件/扩展标签、焦点和真实页面由 HC-202 装配。

## 4. 停点二：变更、Diff 与个人操作状态

**可见结果：**在同一隔离预览切到右侧“变更”，看到分支、状态、文件和 Diff；可全选、取消某项并看到部分选，填写说明并触发受控提交意图。受控结果分别显示已提交 SHA、推送失败及独立重试推送，或结果待确认；切换右侧面板与不同 scope 后各自选择和说明不串。

统筹已授予独占构建与窗口时隙，代表性观察及未覆盖项见 Task 停点二阶段记录；实际结果等待统筹复核，不作为真实项目服务验收。

1. 将旧 `context-dock/git-panel.tsx` 的列表、Diff、说明、结果与最终 CSS 迁到 `project/git-panel.tsx`、`git-diff.tsx` 等区域文件；用公共 `parseFileDiff` 显示 hunk/行号及增删，保留原始 Diff 和非标准/二进制原文回退。公共解析器只作显示，不负责业务授权。
2. 用调用方提供的可用性、原因、分支、upstream、仓库标记、文件 `version`、Diff 和分离的提交/推送结果替换旧 snapshot/selector；`snapshot`/`version` 只作不透明 UI 标记。默认不选，保留全选/部分选；刷新后只保留路径和版本均未变的选择。提交说明最大 8192 字符，切换面板不能丢失；scope/namespace 变化严格隔离。
3. 根据 Spec 发出提交、提交并推送、单独推送等受控意图，忙碌或能力缺失显示禁用原因。只根据输入的已确认结果展示成功：推送失败保留已确认 SHA，重试只发推送意图；未知结果不自动重试。迟到结果不能清理别的 scope 或用户已修改的草稿。
4. 在同一真实窗口检查列表与 Diff 的独立滚动、按钮图标/文字对齐、浅/深主题、缩放及较小窗口；用受控数据演示单项/全选/部分选、文件版本变化撤选、离线/只读/无权、提交成功加推送失败、结果未知和新草稿保留。解析非法 Diff 时仍能读原文。必要构建、类型、边界与实际观察按第 6 节记录。

完成后只回调本任务的实际组件与冒烟证据，不声称 HC-199 已执行 Git 或 HC-202 已接通原设备；阶段通过由统筹标记待验收，完整回归与 Windows 留 HC-204。
