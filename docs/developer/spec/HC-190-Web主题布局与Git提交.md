## 3. Git 用户流程

打开变更 → 获取真实仓库根/分支/状态 → 勾选文件（或全选）→ 查看 Diff → 填写非空提交说明 → 提交 / 提交并推送 → 分别展示提交 SHA 与推送结果。

### 文件与提交

- 以 Git 根目录为边界；即使 CLI 启动于子目录也操作该 Git 工作树。列表使用真实路径，不用行号或显示名称作为执行身份。
- 文件级选择，提交选中文件当前完整内容，包含新增/删除；不提供逐 hunk 暂存。已暂存且又有工作区修改时明确提示完整文件语义。默认零选择，刷新仅保留仍存在且内容未变的选择。
- 必须保留所有未选文件的工作区与暂存内容；重命名作为 old/new 路径整体操作。冲突、子模块、进行中的 merge/rebase/cherry-pick、detached HEAD 阻止写操作并给出原因；未初始化仓库提示在终端处理。
- 服务端重新核验仓库、分支、HEAD、所选文件内容与索引快照。展示后文件被更改则拒绝提交并刷新，防止提交未经查看的新内容。空消息/空选择/没有可提交改动拒绝。
- 消息及路径作为参数/标准输入传递，不拼接 shell 字符串；路径按 Git 返回的合法集合验证，拒绝越界与 pathspec 魔法。NUL 分隔覆盖空格、换行、中文和以短横线开头的文件名。
- 保留 Git hooks、用户身份与签名配置；检查失败、身份缺失或签名失败原样分类为用户可处理错误，不自动设置身份、不跳过 hooks。失败不撤销用户文件，不执行 reset --hard/clean。

### 推送

- 只使用当前分支已配置 upstream，界面显示 remote 与目标分支（不显示凭据 URL）；无 upstream 时仍可提交，提交并推送禁用并提示先在终端配置。
- 推送会发送当前分支相对 upstream 的全部未推送提交，提交前展示已有未推送提交数量，不能误称仅推送勾选文件。
- 禁止 force、自动 pull/rebase、修改 remote、创建远端分支等附加操作。认证使用已有 Git 环境，非交互执行，有界超时；不会收集或保存凭据。
- commit 成功而 push 失败，保留成功 SHA；提供“重试推送”，重试不再 commit。超时/断线且结果不确定时先刷新 HEAD/状态并核实结果，禁止自动重放写操作。

### 执行边界

- 共享 `InteractiveController` 拥有写操作 busy/结果状态；新增 workspace Git port 与本地 infrastructure adapter，复用现有工作区探测边界。人工工作区操作不调用模型、不修改 Agent 文件检查点。
- `WebUiGateway` 继续验证当前 handoff、revision 与 requestId；仅 active 的可写连接可发起，服务端与 UI 同时校验 activeRun、Interaction、Compose/Goal 忙碌及 Git 操作锁。不能仅靠按钮 disabled。
- Git busy 时阻止新 Run/切换工作区及重复 Git 写入；成功/失败后刷新真实视图。断线不取消已执行的提交，也不在重连时自动重复；同 requestId 不得产生第二个 commit。
- 暂不新增 Python JSON-RPC：人工 Git 操作沿现有 CLI 工作区能力路径实现，若实施发现必须跨协议，先修订本 Spec/Plan 并补两端测试。

## 4. 验证与回滚

第一阶段：主题隔离、变量引用闭合、改品牌变量派生生效、对比度、已有 Timeline/工具测试、CSS 打包和真实浏览器 light/dark 验证。第二阶段：文件树状态/预览、配置入口、焦点和忙碌规则回归。第三阶段：临时仓库+本地 bare remote 验证完整 Git 流程与异常，不使用真实用户提交或远端。

回滚按工作包恢复本任务相关文件，保留用户其他修改；主题/布局无数据迁移。Git 提交成功后不提供自动回滚或破坏性撤销，保留 SHA 并由用户决定处理。正式文档只描述已实现阶段，待实现能力留在本规格与 Todo。

## WP3 接口落点

`interactive/ports/workspace-git.ts` 定义 status/diff/commit/push 与结构化快照；`infrastructure/workspace-git.ts` 执行参数数组 Git 命令。`features/workspace-git.ts` 管理共享 busy、快照、Diff 和提交/推送分离结果。人工 Git intent 通过现有 interactive.intent 路径，内部 UI 契约升为 8；Python Protocol 不变。Git 写操作要求网关 revision 等于当前值（重放先查 outcome），并重验内容/HEAD/索引摘要。独立 index 从 HEAD 构建选中文件，成功后仅推进真实 index 的选中路径；原 index 用 index.lock 保护，失败保留未选暂存内容。已有 post-commit 超时/索引同步失败若 HEAD 已写入，保留 SHA 并提示检查，禁止自动重复 commit。

Git hooks 通过一次性包装路径调用现有可执行 hooks，仓库配置不改写；每个提交前 hook 之后核验已审阅的独立暂存树。hook 若加入未选文件或重写暂存内容，本次提交拒绝并要求刷新重看，避免夹带文件；工作区格式化结果保留。签名与身份配置继续正常执行。


### WP3 收尾边界（2026-11-02）

推送前通过实际 push URL 查询目标 ref；远端分支已删除或无法确认时拒绝，不根据陈旧的 remote-tracking ref 主动重新创建分支。探测后再次核验快照，推送 refspec 固定使用已确认的 SHA，不在执行时重新解析可变 HEAD。提交命令正常或异常退出后都核对新 HEAD 的父提交及审阅树，避免把其他进程/Hook 写入的提交错误认领为本次成功；归属不明时保留原索引并提示不要重复提交，已确认成功但命令异常的结果带 SHA 和警告，不自动继续推送。启动恢复 Thread 期间同样拒绝人工 Git 写入。
