## 目的与范围

当前默认命令启动旧 CLI，桌面工程无法独立运行。本任务建立 Electron + React 桌面入口和通用包骨架：开发者安装 Node 依赖后可打开真实原生窗口，看到基础工作台，调整主题、缩放和选择目录。窗口不展示虚构聊天、Trace 或协作数据；选择目录不意味着已经实现项目管理。云端、ACP、文件/Git、Trace 和真实协作均由后续任务实现。

## 工程与依赖方向

以下为实施时建立的 npm workspace 与公开入口；包名使用 `@workbench/` 前缀，应用不作为库导出。五个通用包本停点通过 package.json exports 暴露 `.`，类型与构建产物对应。包间导入必须匹配目标包已声明的 exports，不能跨路径读取内部实现。检查器不能永久写死只有 `.` 合法：例如将来可选 harness-provider 可显式声明 `/runtime` 和 `/ui` 窄入口，仍须遵守依赖方向。除 contracts 的窗口端口外，空骨架只导出明确的包标识，不预先设计未来业务接口。

| 路径 / 包名 | 本停点职责 | 允许直接依赖的内部包 |
| --- | --- | --- |
| apps/desktop / @workbench/desktop | Electron 主进程、preload、React 装配 | workbench-ui、workbench-contracts |
| apps/runner / @workbench/runner | 独立执行器装配骨架，不随窗口启动 | runner-core |
| packages/workbench-ui / @workbench/ui | 基础工作台 React 组件，原生能力通过传入的受限接口使用 | workbench-contracts |
| packages/workbench-contracts / @workbench/contracts | 本停点跨进程桌面端口的类型，无运行时宿主依赖 | 无 |
| packages/runner-core / @workbench/runner-core | 执行器核心骨架 | workbench-contracts |
| packages/acp-runtime / @workbench/acp-runtime | 通用 ACP 骨架，无 Agent 实现 | workbench-contracts |
| packages/project-service / @workbench/project-service | 本机项目服务骨架，本停点不读写项目 | workbench-contracts |

上述依赖为允许方向而非要求全部实际引入。通用包不依赖应用、旧 CLI、旧 protocol、Python、Harness 或未来可选 Harness 集成；UI 不导入 Electron/Node。依赖检查覆盖新工程 package.json、源码静态导入/导出和可静态确定的动态导入；同时核对相对路径、TypeScript 路径映射与构建配置，避免绕过 exports 或包边界。不允许新源码用不可静态确定的跨包加载绕过检查。边界检查只扫描新工程，拒绝未声明依赖、内部路径、反向依赖和上述禁用项，并纳入新工程检查。Harness 将来作为可替换 ACP Agent 和可选扩展接入，不能成为启动条件。应用与包不经旧 CLI、Web server 或网关装配。

## 默认安装与锁文件

根 workspaces 改为上述七个目录的显式清单，不再用 `packages/*` 或 `third_party/npm/*` 通配；按 contracts → 通用核心 / UI → 应用的顺序编排构建。旧 CLI、protocol、Python 和 vendor 源码保留在原目录，退出根 npm 安装图；不通过 `file:`、安装脚本或传递依赖重新引入。

只保留一个生效的根 `package-lock.json`，实施时根据新清单重新生成，清除旧 workspace、Bun/OpenTUI 和旧私有制品条目；不保留双锁文件或安装时选择旧产品的分支。迁移来源的 package.json、Python 锁文件和源码暂留，旧根锁文件可从设计基线 Git 提交追溯，无需复制为另一个安装入口。根 `.npmrc` 移除专为旧 TUI peer 冲突设置的 `legacy-peer-deps=true`，新依赖按正常 peer 规则解析。

新默认源码安装为根 `npm ci`，只需 Node/npm 和目标平台 Electron 下载所需的网络或已配置镜像；不要求模型 Key、企业私有 JS/Python 制品、Bun、uv、Python 或 Harness。npm workspace 选择和冻结安装行为依据 [npm workspaces](https://docs.npmjs.com/cli/v11/using-npm/workspaces/) 与 [npm ci](https://docs.npmjs.com/cli/v11/commands/npm-ci/)。普通安装不得自动更新锁文件；只有实施者更改依赖声明时生成并审查新锁。去掉根安装/检查链对旧 `deps:sync`、OpenTUI 校验和 Python 同步的调用，旧脚本文件留待 HC-203 清理。不能用跳过生命周期脚本来假装 Electron 已可启动。

## 桌面组合与受限端口

主进程创建 BrowserWindow、处理生命周期和原生目录对话框；preload 通过 contextBridge 暴露固定 API；renderer 只加载本地 React 工作台。开启 contextIsolation 与 sandbox，关闭 nodeIntegration；禁止通用 IPC 转发、任意 shell、文件系统或远程代码加载。生产窗口仅加载构建的本地页面；开发服务器仅用于本地开发，禁止任意导航和新窗口。主进程校验发送方和参数，原生对话框使用所属窗口。

`window.workbench` 暴露下表具名端口，接口类型放 contracts，preload 逐方法转发，不暴露 ipcRenderer 对象。所有请求只接受当前窗口主 frame，不接受 iframe、其他 WebContents 或任意窗口 ID；失败以 Promise 拒绝交给界面显示简明错误。状态订阅不暴露 Electron 事件对象，组件销毁时取消订阅。

| 方法 | 契约与校验 |
| --- | --- |
| `chooseDirectory(): Promise<string \| null>` | 无参数，只选一个目录；成功返回绝对路径，取消返回 null；不接受默认路径或其他操作选项 |
| `getWindowState(): Promise<WindowState>` | 返回当前主题模式、实际浅/深色和缩放百分比，无路径、窗口句柄或业务状态 |
| `setThemeMode(mode): Promise<WindowState>` | mode 仅为 `system` / `light` / `dark`，同步网页与原生标题栏颜色 |
| `adjustZoom(action): Promise<WindowState>` | action 仅为 `in` / `out` / `reset`，主进程计算并返回实际百分比，不接受任意数字或通道 |
| `onWindowStateChanged(listener): () => void` | 仅推送上述 WindowState，覆盖系统主题变化与窗口状态更新，返回取消订阅函数 |

渲染器展示所选目录，但不读取、保存或上传它；取消不清掉之前成功的选择，首次取消仍显示未选择。主进程不把路径当成后续文件访问授权。

窗口显示产品标题、基础内容区、选择目录按钮、主题与缩放控制，不包含虚构业务。主题提供跟随系统、浅色、深色，默认跟随系统，变更立即可见；本停点不承诺重启持久化。缩放通过主进程调用 Electron [webContents.setZoomFactor](https://www.electronjs.org/docs/latest/api/web-contents#contentssetzoomfactorfactor) 调整真实窗口网页缩放，默认 100%，按 10 个百分点调整并限制在 80%～150%，边界按钮禁用。主进程校验枚举并限制范围，返回实际值；不使用 CSS transform 冒充窗口缩放，不提供绕开范围的菜单、快捷键或手势入口。缩放只影响当前窗口，重启恢复 100%。macOS 保留系统红黄绿控制，Windows 保留系统窗口控制；拖动区域与交互按钮分离，按钮可正常点击。

本停点没有 Runner 托管或运行任务：Windows 关闭最后窗口退出；macOS 关闭窗口后保持应用，可由应用菜单或 Dock 重开，明确退出结束应用。这是基础窗口阶段的临时生命周期。顶层设计中“托管 Runner、关窗进入后台、托盘重开与退出前收敛任务”由 HC-196 / HC-202 接入，本任务不改变该最终约定，也不建立伪后台或空托盘。

## 工具链与命令

选用 npm workspace 与 electron-vite 构建 main、preload 和 renderer；开发宿主 Node 固定要求 `>=22.12.0`，npm 使用仓库已指定的 11.11.0。实施时直接依赖精确版本：Electron 45.2.3、electron-vite 6.0.0、Vite 8.3.6、@vitejs/plugin-react 6.2.1、React 与 React DOM 19.3.0、@types/react 与 @types/react-dom 19.3.0、TypeScript 6.0.3、@types/node 22.20.5（对应最低宿主 Node 的编译类型）。锁文件记录完整传递依赖；不引入未使用的可选编译器插件。版本核对依据：[Electron 稳定版本](https://releases.electronjs.org/?channel=stable)、[React 版本](https://react.dev/versions)、[Vite Node 要求](https://vite.dev/guide/)、[electron-vite 指南](https://electron-vite.org/guide/)；其余精确版本和 peer/engines 以 npm 官方 registry 元数据核对。已完成安装、构建和 macOS 窗口冒烟；实际覆盖与下载限制见 Task。

根 `npm run dev` 启动桌面开发窗口；`npm run build` 构建新应用和新通用包，`npm run typecheck` 检查新工程，新增 `npm run check:boundaries` 执行依赖边界检查。新路径不调用 Bun/OpenTUI、Python、旧 CLI 或旧 Web。Runner 可单独构建但不自动运行。具体构建产物不是安装包，双平台分发由 HC-204 负责。

根 `project:check` 执行新边界检查与既有文档 / 任务 / 版本一致性检查，取消前置 `protocol:check`；旧协议生成/校验脚本不进入新产品默认脚本、生命周期或检查链，其源码留待迁移。`scripts/project/index.ts` 继续作为文档/任务/版本入口。版本检查与 `version:set` 改为同一份新 workspace 清单，版本值仍以 VERSION 和 CHANGELOG 为准，新包初始化沿用当前 VERSION，本任务不升版；不再要求旧 CLI 常量或 Python 文件与新平台同步。必要的工程脚本用例随之迁移，避免用旧夹具强迫新平台重建旧工程。文档本地链接检查继续覆盖现存文档，不因旧源码暂留而宣称旧产品仍可运行。
