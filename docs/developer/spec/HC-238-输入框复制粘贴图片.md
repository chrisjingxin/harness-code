# HC-238 输入框复制粘贴图片规格

[任务](../task/HC-238-输入框复制粘贴图片.md)

## 1. 架构归属与核心原则
- **跨层边界**：`desktop/` 与 `agent/` 两层协同；`packages/acp-runtime/` 已原生支持 `LocalAcpPromptBlock` 的 `image` 块，`packages/collaboration-client/`、`contracts/` 与 `server/` 不做契约变更。
- **二进制与元数据分离**：图片字节存放在桌面主进程隔离目录 `<userData>/local-images/<accountHash>/`（绝不写入用户项目工作区）；`PersonalStore` 的 `draft.images`、`sentImages` 与队列 `QueuedPrompt.images` 仅存轻量元数据。
- **两阶段不可变缓存（借鉴 t3code）**：粘贴暂存写入 `pending-<uuid>.<ext>`（经 `.part` 原子改名）；真正发送时 `copyFile` 复制并冻结为 `sent-<uuid>.<ext>`，保留原 `pending-*` 直至发送受理清空草稿，发送失败重发时不丢失草稿图片。

## 2. 桌面层功能与边界规格
- **粘贴与并发保序**：在输入框 `<textarea>` 监听 `paste`，识别 `clipboardData` 中的图片文件，先同步分配临时占位（保持多张粘贴顺序与数量配额），再异步完成缩放压缩与 IPC 落盘替换。仅支持粘贴触发，本期不做拖拽或文件选择按钮。
- **客户端压缩策略**：
  - 支持 MIME：`image/png`、`image/jpeg`、`image/webp`、`image/gif`（GIF 保留动画原字节，不做重编码；源图 decoding 上限 50 MiB）。
  - 静态图若任一边超过 `2000px` 或原始大小超过 `2 MiB`，在渲染端等比缩放到长边 `≤ 2000px` 并按体积步进压缩至 `≤ 4 MiB`；否则保留原始字节。
  - 配额上限：单轮最多 **6 张**图片、单张原始字节 **≤ 4 MiB**、单轮所有图片原始总字节 **≤ 5 MiB**（确保 Base64 后安全低于 ACP stdio `8 MiB` 单帧上限）。
- **主进程校验与安全**：
  - 不轻信渲染层传入的 `mimeType`，通过文件头魔数（Magic Bytes）校验 PNG/JPEG/GIF/WEBP 真实格式；
  - 所有 IPC 经 `ipc-guard.ts` 校验来源与参数，`local-image-store.ts` 校验规范 ID 正则与 `realpath` 归属；
  - 定期对孤儿 `.part`（> 1h）与未引用超期 `pending-*`（> 48h）及超出账号配额（~150 MiB）的历史图片执行清理。
- **UI 与预览体验**：
  - **输入框顶部图片条**：位于输入框内部最上方（若有 HC-237 引用块则在引用块上方），底部带细分割线。每张图为 `48×48px` 圆角缩略图，右上角悬浮圆形 `×` 移除按钮（触发删除并清理暂存 `pending-*` 图片）；处理中显示加载态；移除 `onClick` 需 `stopPropagation` 防止误触预览。
  - **放大预览（Lightbox）**：点击缩略图通过 Portal 弹出遮罩居中预览大图，支持显示文件名/尺寸/序号、多图左右切换（按钮及键盘 `←/→`）、`Esc` 与遮罩点击关闭，关闭时将焦点归还触发前元素。
  - **时间线气泡回显**：本机发送并受理后，用户消息气泡顶部显示紧凑缩略图条，点击同样弹出 `ImageLightbox`。通过 `ConversationPersonal.sentImages`（按服务端序号键缓存，最多保留最近 50 轮）让本机重开会话后历史已同步用户消息也能恢复本地缩略图。
- **能力协商与执行收敛**：
  - `LocalExecutionSessionState` 透传 `supportsImagePrompt = Boolean(agentCapabilities?.promptCapabilities?.image)`。
  - 当草稿含图片但当前 Agent 声明 `supportsImagePrompt === false` 时，输入区进入阻断提示状态并禁用发送（Fail-Closed），不静默丢图。
  - 仅含图片无正文时允许发送/加入队列；含图片时不允许走纯文本 Steer（隐藏草稿/队列立即发送）。
  - 协同上传（`ConversationUploads`）仅写入文本摘要（如 `[附 2 张本机图片]`），避免超出服务端 32 KiB 上限。

## 3. Harness Code（`agent/`）多模态规格
- **ACP 能力协商**：`HarnessAcpServer.initialize()` 声明 `PromptCapabilities(image=True, audio=False, embedded_context=True)`。
- **图片块接收与校验**：`_prepare_prompt_parts` 接收 `type == "image"` 内容块，校验 MIME（`png/jpeg/webp/gif`）、合法 Base64、数量（`≤ 10`）、单张（`≤ 4 MiB`）与累计字节（`≤ 5 MiB`），非法则返回 `-32602`（`INVALID_IMAGE_BLOCK` / `IMAGE_TOO_LARGE`）；`audio` 等未支持类型仍返回 `UNSUPPORTED_CONTENT_BLOCK`。
- **模型输入与 Transcript 隔离**：
  - `UserRunInput` 新增 `images: tuple[PromptImage, ...] = ()`，计入 `StartRun.fingerprint()`（按 MIME + Base64 SHA-256 去重，不把整张图 Base64 塞进指纹）。
  - 当用户仅发图片无文字时，Transcript 写入 Readable 标记 `[附 N 张图片]`，避免空 Prompt 被 `agent_host.py` 拒绝且不往 SQLite Transcript 写 Base64。
  - `BuildRunAdapter` 与 `ComposeRunAdapter` 主模型调用构造 `HumanMessage(content=[{"type": "text", "text": ...}, {"type": "image_url", "image_url": {"url": f"data:{mime};base64,{data}"}}])`。
  - 子代理文本提取（`runtime/agent.py`）与协议 `echo=True` 测试适配器（`managed_agent_executor.py`）安全抽取多模态内容中的文本部分，不把 `image_url` Base64 字符串转成工具文本。
