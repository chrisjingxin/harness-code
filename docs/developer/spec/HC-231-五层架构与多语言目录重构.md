## 1. 设计原则与五层全景结构

本次架构收敛的目标，是把原本混合在多级套壳目录与桌面主进程里的逻辑，按**三语言构建边界（TypeScript / Python / Java）**与**严格单向依赖的五层职责**彻底拉开：

```text
+-------------------------------------------------------------------------+
| 第 1 层：desktop/（TypeScript · Electron 桌面应用壳）                     |
|   - src/ui/         纯 React 通用视图组件（严禁 Node/Electron 导入）       |
|   - src/renderer/   工作台页面与协作特性装配（严禁 Node/Electron 导入）    |
|   - src/preload/    contextBridge 安全窄桥                              |
|   - src/shared/     桌面内部 IPC 契约（桌面窗口、本地目录、个人视图）       |
|   - src/main/       窗口 + ipc-guard + 本机只读目录/Git + 目录授权 + 薄 IPC|
+----------------------+-------------------------------+------------------+
                       | 调用协调 SDK / 仅引 ./types     | 装配通用 ACP 与默认桥
                       v                               v
+-----------------------------------+   +---------------------------------+
| 第 2 层：packages/collaboration-client|   | 第 3 层：packages/acp-runtime   |
| （独立可发布 TS SDK，零内部包依赖）  |   | （ACP 统一接入层，零特定 Agent）  |
| - client/state/updates/uploads    |   | - LocalAcpHost / BoundSession   |
| - ./types（纯类型与轻量纯辅助导出）   |   | - AcpAgentDescriptor 标准接口   |
| - 构建内联顶层 contracts/schema     |   | - AcpAgentRegistry + 命令工厂   |
+----------------------+------------+   +----------------+----------------+
                       |                                 ^
                       | HTTPS + 轻量 SSE                | 实现标准接口
                       v                                 |
+-----------------------------------+   +----------------+----------------+
| 跨语言协议底座：contracts/          |   | 第 4 层（TS 桥）：packages/harness-acp
| - openapi / schema / fixtures     |   | - 探测 agent/ 内核 + 扩展元数据 |
| （仅保留 platform/organization/    |   +----------------+----------------+
|   collaboration 纯线上协议）        |                    | stdio JSON-RPC
+----------------------+------------+                    v
                       ^                +---------------------------------+
                       | Maven 校验对齐  | 第 4 层（Python）：agent/        |
                       v                | - 独立 uv 工程（harness-agent）  |
+-----------------------------------+   | - examples/plugins 归并至此      |
| 第 5 层：server/（Java Spring Boot）|   +---------------------------------+
| - 协调层服务端（interfaces → dom）  |
+-----------------------------------+
```

## 2. 目录迁并全量映射表（旧路径 → 新路径 / 处置）

## 3. 各层职责规格、公开接口与数据约束

### 3.1 跨语言协议底座（`contracts/`）

1. **纯线上三协议边界**：仅允许存在以下语言无关协议资产，彻底剥离所有桌面端与已废弃设备通道模型：
   - `contracts/resources.json`（清单索引）
   - `contracts/openapi/{platform,organization,collaboration}.openapi.json`
   - `contracts/schema/{platform,organization,collaboration}.schema.json`
   - `contracts/fixtures/`（仅保留 `platform` / `organization` / `collaboration` 合法与非法夹具）
2. **废弃清理**：删除 `device.*`、`execution.*`、`conversation.*`、`project.*`（旧跨机器文件读取命令）以及 `deterministic.ts`（`executionMessageBody`/`canonicalJson`/`isSequence` 全仓无外部生产消费；`isUuid` 已由 `desktop/src/main/ipc-guard.ts` 自有实现）。
3. **跨语言共检**：
   - `scripts/workbench/check-contracts.mjs` 指向顶层 `contracts/`，继续以 Ajv（Draft 2020-12）验证三套 Schema 与全部 fixtures；
   - `server/pom.xml` `<build><resources>` 指向 `../contracts` 并打包为 classpath `platform/`，Java `ContractsTest` 持续对同一批 JSON 资源运行 `json-schema-validator` 检验。

### 3.2 第 2 层：协调层 Client SDK（`packages/collaboration-client`，包名 `@workbench/collaboration-client`）

1. **零内部依赖与单包自包含**：
   - `package.json` 的 `dependencies` **禁止包含任何 `@workbench/*` 内部包**、**禁止包含 `electron`**，仅依赖必要的运行时库（如 `ajv`、`ajv-formats`）；
   - 构建步骤将 `contracts/schema/{platform,organization,collaboration}.schema.json` 复制/内联进 `dist/schema/`，使第三方工程只需安装或引入 `@workbench/collaboration-client` 这一个包即可运行完整的请求与响应 Schema 校验。
2. **双公开入口契约（Strict Exports）**：
   - `"."`：Node/宿主入口，导出：
     - `CollaborationClient`（原 `CollaborationClient`，**移除构造函数中无用的 `conversationSchema` 与 `projectSchema` Ajv 预加载**）；
     - `CollaborationState`（登录态、Workspace 归属与 Epoch 代次守卫，防止账号或团队切换期间的晚到响应覆盖当前状态）；
     - `ProjectUpdatesService`、`ProjectNotificationStream`、`ProjectNotificationCursor`（轻量 SSE 断线退避重连与游标推进）；
     - `ConversationUploads`（定稿消息与工具摘要磁盘待传账本与重试队列）；
     - 显式声明环境依赖仅限 Node `fetch` / 磁盘持久目录参数（如 `createCollaborationSdk({ origin, storageDir })`），不接触 Electron API。
   - `"./types"`：**严格零 Node 内置模块、零 `fs`/网络副作用的纯前端安全入口**，导出 `identity` / `organization` / `collaboration` 全量 TS DTO 与纯常量（如协作错误类型与状态枚举），供 `desktop/src/renderer/` 与 `desktop/src/ui/` 或外部 Web/CLI 前端直接 `import type`。
3. **解除反向耦合**：
   - **输入规范**：`ConversationUploads` 当前通过从桌面 `local-execution-host.js` 导入 `localExecutionKey` 构造队列 key（反向耦合第 1 层）。改造后改为在 `packages/collaboration-client/src/scope.ts` 自行定义纯作用域 `CollaborationConversationScope`（`{ workspaceId, projectId, conversationKey }`）与 `collaborationConversationKey(scope)`；由第 1 层向第 2 层适配传参，第 2 层完全不知道“本机执行宿主”的存在。

### 3.3 第 3 层：ACP 统一接入层（`packages/acp-runtime`，包名 `@workbench/acp-runtime`）

1. **中立协议与单一接口定义源（One-Version Rule）**：
   - **唯一接口定义**：在 `packages/acp-runtime/src/descriptor.ts` 定义并从 `"."` 与 `"./types"` 导出：
     - `AcpAgentDescriptor`（支持 `id`、`label`、`description`、`family`、`hostHints`、`resolveCommand(env, options)`）
     - `AcpAgentHostHints`（`enableElicitation`、`enableClientFs`、`restorePolicy`）
     - `AcpAgentDiscoveryOptions`、`AcpAgentResolution`
   - **共享进程探测工具**：将原三份重复实现的 `isExecutableFile`、`ancestorDirs`、`resolveGitMainWorktreeRoot`、`buildAugmentedGuiPath`、`findInPath` 收拢进 `packages/acp-runtime/src/discovery.ts` 并统一导出。
2. **通用注册表与配置接入任意外部 Agent**：
   - 在 `packages/acp-runtime/src/registry.ts` 提供 `AcpAgentRegistry`：
     - 不再写死 `[harness, pi, qwen]` 静态导入列表；构造参数显式接收调用方注入的 `descriptors: readonly AcpAgentDescriptor[]` 与可选的环境变量/配置文件加载的外部 Agent 列表；
     - 内置通用命令驱动工厂 `createCommandAgentDescriptor({ id, label, description, executable, args, env, hostHints })` 与环境变量 `"custom"` 工厂（解析 `WORKBENCH_ACP_EXECUTABLE` / `WORKBENCH_ACP_ARGS_JSON`），外部 CLI Agent 只需提供可执行路径与参数即可按标准 ACP stdio 接入，无需新建 npm 包。
3. **测试桩取代**：
   - 删除原 `packages/providers/pi` 与 `packages/providers/qwen` 两个正式包，改为在 `packages/acp-runtime/tests/` 下保留轻量标准 ACP Mock Agent 子进程脚本与多实例切换回归测试，确保“默认切换、回退、无扩展纯标准 ACP Agent 兼容”100% 受控验证。
4. **纯类型子出口 `"./types"`**：
   - 将标准 ACP 会话显示 DTO（Tool/Plan/Elicitation/ConfigOption/SessionSnapshot 等纯数据接口，不含 Node/child_process）通过 `"./types"` 对外暴露，供 `desktop` 渲染层按契约消费，消除桌面内冗余重复的手写镜像类型定义（注意 `desktop/src/renderer/` 严禁直接从 `@workbench/acp-runtime` 根入口引入任何运行进程/stdio 能力）。

### 3.4 第 4 层：默认 ACP 实例 Harness Code（`packages/harness-acp` + `agent/`）

1. **极薄 TS 适配桥 `packages/harness-acp`（包名 `@workbench/harness-acp`）**：
   - 唯一职责：① 通过 `@workbench/acp-runtime` 的公共探测辅助定位 `agent/.venv`（含 git worktree 向上回溯至主仓库根目录的 `agent/.venv`）或活跃虚拟环境/`PATH` 中的 `harness-agent` 可执行入口；② 导出 `harnessAcpDescriptor: AcpAgentDescriptor` 与 `_meta.harnessCode` 扩展元数据解析函数 `meta.ts`（工作流、计划、目标、思考链、子代理归属与命令来源）。
   - 不持有窗口或全局运行状态，不包含已复制的 `types.ts` 或重复的 `PATH` 遍历实现。
2. **独立 Python `uv` 内核 `agent/`（移至仓库顶层）**：
   - 目录内整合：`agent/harness_agent/`（Python 内核）、`agent/scripts/`（DeepAgents 补丁/检查/冒烟脚本）、`agent/tests/`、`agent/evaluations/`、`agent/examples/plugins/`（原根目录 `examples/plugins`）、`agent/pyproject.toml`、`agent/uv.lock`；
   - `agent/pyproject.toml` 与 `agent/uv.lock` 的分发包名称由历史旧称 `za38-agent` 对齐为 `harness-agent`；
   - **路径深度与跨工具链校验适配**：由于少了一级 `packages/`，更新 `agent/scripts/check_dependencies.py`：
     - `--lock` 默认改为 `Path(__file__).resolve().parents[1] / "uv.lock"`（保持指向 `agent/uv.lock`）；
     - 仓库根目录与 `--npm-lock` 默认由 `parents[3]` 更新为 `Path(__file__).resolve().parents[2]`；
     - `check_installed_packages(root)` 扫描的桌面节点依赖目录由 `root / "apps/desktop/node_modules"` 更新为 `root / "desktop/node_modules"`；
     - 同步更新 `agent/tests/test_dependency_check.py` 与文档引用路径；
   - **兼容性提示**：Python 内核对外通过 ACP `initialize` 返回的底层兼容字段或协议行为，若现有前端/脚本或特定集成测试（如 `test_v3_characterization.py`）依赖具体字段，须先确认是否保留协议标识或同步更新对应断言，不静默破坏已有运行契约。

### 3.5 第 1 层：Electron UI 与宿主壳（`desktop/`，包名 `@workbench/desktop`）

1. **内部层次清晰划分（不把可独立复用包吞回桌面，仅内聚纯桌面专属资产）**：
   - `desktop/src/shared/`：收拢桌面端前后端通信内部窄接口，包括窗口/主题/剪贴板（`DesktopHost`）、组织/协作/更新/应用宿主接口（原 `desktop-hosts.ts`）、本地目录与会话端口（原 `session.ts` + `project.ts` 的只读数据与错误码子集）、个人草稿与视图状态（原 `personal.ts`）、以及 `collaboration-reference.ts` / `local-execution-host.ts` 的宿主通道类型。彻底删除 `personal-host.ts` 2 行转发垫片。
   - `desktop/src/ui/`：迁入原 `packages/workbench-ui/src/`（样式主题、Markdown/代码高亮渲染、通用对话时间线与提问组件、文件树与只读 Git Diff 面板、协作导航与身份面板）。**必须保持严格的静态无宿主边界：`desktop/src/ui/` 内部任何文件严禁导入 `electron`、Node 内置模块、`src/main/`、`src/preload/` 或 `@workbench/acp-runtime` 根入口**。
   - `desktop/src/renderer/`：工作台布局装配 `desktop-workbench.tsx`、`features/`（`project-navigation`、`session`、`collaboration`、`collaboration-views`、`board`、`project-updates`），及规范化的预览入口（统一或参数化管理 Vite 配置，避免根下继续无序堆叠预览配置）。
   - `desktop/src/preload/`：`contextBridge.exposeInMainWorld` 安全桥。
   - `desktop/src/main/`：薄适配器与 Electron 生命周期宿主：
     - `index.ts`：组装入口，实例化 `CollaborationClient`、`CollaborationState`、`ProjectUpdatesService`、`ConversationUploads`（均来自 `@workbench/collaboration-client`）、`AcpAgentRegistry`（来自 `@workbench/acp-runtime`，注入 `harnessAcpDescriptor` 及可选环境自定义驱动）与 Electron 窗口；
     - `project-service/`：迁入原 `packages/project-service/src/`（安全路径防逃逸、文件搜索/预览、只读 Git 状态与 Diff），消除原 `local-directory-host.ts` 与 `project.ts` 之间的双份重复响应类型包装；
     - **拆分 954 行的 `local-execution-ipc.ts`**：
       1. `local-directory-grants.ts`（或归并目录授权模块）：专责目录持久化授权表与 `dev`/`ino` 校验、`@file` 沙箱附件读取与字节上限拦截；
       2. `local-execution-coordinator.ts`：专责本机 ACP 会话执行流事件投影、取消/关闭、终态捕获及转交 `@workbench/collaboration-client` 上传队列；
       3. `local-execution-ipc.ts`：瘦身为纯 Electron IPC 通道注册层，与 `collaboration-ipc.ts`、`organization-ipc.ts`、`project-updates-ipc.ts`、`desktop-ipc.ts` 一致，**100% 统一经 `ipc-guard.ts` 登记校验（扩展 `ipc-guard.ts` 支持可变参数计数范围 `[min, max]` 或校验组合，消灭本地手写重复校验代码）**。

### 3.6 第 5 层：Java 中继服务端（`server/`）

- 原 `services/collaboration-server/` 整体平迁至顶层 `server/`，保持内部 `workbench.collaboration.{interfaces,application,domain,infrastructure}` 四层包结构不变；
- 修改 `server/pom.xml` 中 `<resources>` 路径为 `<directory>../contracts</directory>`；
- 若原有构建/部署辅助脚本（如 `scripts/workbench/server.mjs`、`deploy-remote.mjs`、`smoke-remote-commands.mjs`、`run-identity-smoke.mjs`）引用了 `services/collaboration-server`，统一改指向 `server/`。

## 4. 工程门禁与架构不变量（`scripts/workbench/check-boundaries.mjs`）

重构完成后，依赖门禁升级为“**4 个根 workspace + 内部子层静态边界 + 已退役路径防回流**”的机器强校验：

### 4.1 Workspace 级允许依赖矩阵

| Workspace 路径 | 包名 | 允许依赖的内部 Workspace | 禁止项 |
| --- | --- | --- | --- |
| `packages/collaboration-client` | `@workbench/collaboration-client` | `[]`（**零内部依赖**） | 禁止引用 `electron`、`@workbench/acp-runtime`、`@workbench/harness-acp`、`@workbench/desktop`、`contracts` 源码外相对路径 |
| `packages/acp-runtime` | `@workbench/acp-runtime` | `[]`（**零内部依赖**） | 禁止引用 `electron`、`@workbench/collaboration-client`、`@workbench/harness-acp`、任何特定 Agent 名称硬编码 |
| `packages/harness-acp` | `@workbench/harness-acp` | `["@workbench/acp-runtime"]` | 禁止引用 `electron`、`@workbench/collaboration-client`、`@workbench/desktop` |
| `desktop` | `@workbench/desktop` | `["@workbench/collaboration-client", "@workbench/acp-runtime", "@workbench/harness-acp"]` | 跨包禁止深路径导入 `src/*` |

### 4.2 `desktop/` 内部子目录静态隔离规则（等价原分包防线）

- `desktop/src/ui/**`、`desktop/src/renderer/**` 与 `desktop/src/shared/**`：
  - **严禁**导入 `electron` 或任何 Node 内置模块（`node:*` / `fs` / `path` 等）；
  - **严禁**导入 `desktop/src/main/**` 或 `desktop/src/preload/**`；
  - **严禁**导入 `@workbench/collaboration-client` 主入口（只允许 `@workbench/collaboration-client/types`）、`@workbench/acp-runtime` 主入口（仅允许 `@workbench/acp-runtime/types`）或 `@workbench/harness-acp` 主入口；
  - `desktop/src/ui/**` **严禁**反向导入 `desktop/src/renderer/**`（保证通用组件层可独立预览与抽离）。
