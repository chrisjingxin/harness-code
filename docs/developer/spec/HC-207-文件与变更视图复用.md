## 1. 目的、边界与可观察结果

旧 Web 的右侧文件树、文件预览、变更和中央文件页签已经有用户熟悉的界面，但依赖旧 Web Adapter、交互快照和协调器。独立桌面需要把这些现成 React 结构与最终样式迁入 `packages/workbench-ui/src/project/`，把业务输入改为本区需要的视图值，把用户操作交给回调。两区共用的文件图标和 Diff 纯解析器分别按统筹指定时隙迁入公共 `common/` 与 `rendering/`。用户仍能在右侧查看文件和变更，在中央打开独立的只读文件页签，调整勾选、填写说明并看清提交和推送各自的结果。

受控界面输入仅用于观察与冒烟，按钮回调被调用不代表原设备已经读取、提交或推送。与 ACP 能力、Agent 运行状态有关的开发、接线、调试和验证仍等待同事交付 ACP；本任务不启动 ACP 或模拟 Agent。中央总页签和真实页面装配归 HC-202，新的三栏外壳归 HC-208；本任务提供可组合的项目部件，不另建完整工作台。

## 3. 项目视图输入：只表达本区需要的信息

下列字段是供评审的 UI 契约，不是线上 DTO；名称可在共同审查后收敛。状态由装配方根据真实权限、设备和服务结果投影，受控预览可用固定数据提供相同形状。所有路径是**原项目内的相对路径**，显示名不作为身份，也不在渲染器拼接查看者电脑的路径。

```ts
type ProjectScope = {
  namespace: string; accountId: string; workspaceId: string; deviceId: string; projectId: string
}
type ProjectAvailability =
  | { state: "available" }
  | { state: "offline" | "denied" | "unavailable"; message: string }
type ProjectActionAvailability = { enabled: true } | { enabled: false; reason: string }
type ProjectTreeRow = {
  path: string; name: string; kind: "directory" | "file" | "symlink"
  depth: number; expanded: boolean; loading: boolean; hasChildren: boolean
}
type ProjectTreeView = {
  status: "loading" | "ready" | "error"; rows: readonly ProjectTreeRow[]
  limited: boolean; message?: string; freshness?: "live" | "cached"
}
type ProjectFileContent = {
  path: string; content: string; language: string | null
  sizeBytes: number; lineCount: number; truncated: boolean
  displayedBytes?: number; freshness: "live" | "cached"
}
type ProjectFileView =
  | { status: "loading"; path: string }
  | { status: "ready"; file: ProjectFileContent; refreshError?: string }
  | { status: "unsupported" | "too-large"; path: string; reason: string; sizeBytes?: number }
  | { status: "error"; path: string; message: string }
```

`ProjectScope` 是服务/身份域、账号、工作区、执行设备和项目的组合，必须都来自当前装配上下文，不能用项目名代替；无完整目标时展示不可用。`namespace` 由宿主区分服务/身份域，不含凭据，也不是新线上字段。`ProjectAvailability` 表达项目当前能否访问，不将离线写成成功；`ProjectActionAvailability` 分别控制读取、刷新、查看 Diff、提交和推送，并给出可读禁用原因，不能只靠一个全局 `disabled` 代替各项能力。只读是可读但写动作不可用，不等于设备离线或无权限。树提供加载、空目录、错误和部分列出状态；如果服务提供更细的读取失败或显示限制，投影为可读信息，不由 UI 发明错误码。

文件 `ready` 仅表示当前提供的可展示内容；`cached` 必须显式标注“缓存/非实时”，不能冒充在线读取。刷新一般性失败时可保留原内容并显示 `refreshError` 和过期提示；无可用旧内容时显示错误和重试入口。对于 `denied` 或账号/授权失效，装配方撤回并隔离不可再访问的树、Diff 和文件正文，界面不继续展示这些旧数据；离线时只有上游明确提供且允许展示的缓存才可显示，不能把缓存当新的授权或实时状态。`unsupported` 表达二进制等不可预览类型，`too-large` 表达没有可展示正文的过大文件；`truncated` 表示正文只是部分内容，显示实际限制/字节数（如果提供），不把旧实现的 256 KiB 硬写成新项目服务的规则。

变更视图使用以下信息；`snapshot` 和 `version` 仅是上游提供的**不透明视图标记**：UI 可以保存、比较和原样带回，但不计算其算法、不认定其等同于未来线上字段，也不自行决定服务端冲突规则。

```ts
type ProjectChangedFile = {
  path: string; oldPath?: string; status: string; version: string
}
type ProjectChangesView = {
  status: "loading" | "ready" | "error"; busy: boolean; message?: string
  freshness?: "live" | "cached"
  repository?: {
    snapshot: string; branch: string; head?: string
    upstream?: { remote: string; branch: string; ahead: number; behind: number }
    files: readonly ProjectChangedFile[]
  }
  diff?: { snapshot: string; path: string; text: string; truncated: boolean }
  result?:
    | { commit: "succeeded"; commitSha: string
        push: "not-requested" | "succeeded" | "failed" | "unknown"
        warning?: string; message?: string }
    | { commit: "failed" | "unknown"; push: "not-requested" | "unknown"
        warning?: string; message: string }
}
```

具体读/写可用性与结果由装配方分别提供；展示树或变更的缓存时也必须由相应 `freshness` 明确标注“缓存/非实时”，不能只标注文件正文。`commitSha` 只有上游确认时才显示。UI 不根据回调已返回、设备掉线或本地勾选推断提交成功、推送成功或没有副作用。`unknown` 明确显示“结果待确认”，不自动重试提交。`oldPath`、完整相对路径及状态用于区分重命名与同名文件；没有 upstream 时展示原因，不能通过 UI 自行指定或猜测推送目标。

## 4. 个人状态、动作和异步边界

### 4.1 个人状态

一个 `ProjectScope` 下保存右侧 Dock 开合、宽度与活动面板，树的展开/选中/滚动，右侧文件页签、活动路径及阅读滚动，Git 当前查看的 Diff、按文件路径和上游 `version` 绑定的勾选、提交说明及局部焦点。中央已打开文件列表和活动文件由 HC-202 的总页签管理，文件部件只提交打开、激活和关闭意图；它与右侧页签可以引用同一份由装配方提供的文件内容，但关闭任何一侧不关闭另一侧。

个人状态按 `namespace + accountId + workspaceId + deviceId + projectId` 隔离；文件内容、滚动和选择再按相对路径区分。切换服务/身份域、账号、工作区、设备或项目时先卸载或切换到对应作用域，再应用新输入；即使其他 ID 相同，不同 namespace 也不能共享内容或草稿。同名项目、同名路径和同名文件不串内容/选择/提交说明。不同会话如果绑定不同项目，必须切换到其原目标；他人的共享事件不替当前用户打开页签、勾选文件或覆盖说明。是否持久保存到磁盘由 HC-202 后续决定；本 Spec 不要求联网共享个人状态或新增持久存储格式。

旧右侧文件页签按最近使用排序，最多 12 个，超出淘汰最久未使用项；右侧关闭活动文件时选邻近文件，关闭最后一个仍保留 Dock 并显示从文件树打开的引导。中央页签按打开顺序单独维护；关闭当前文件后选择相邻文件，最后一个关闭时由 HC-202 回到对话或其当前非文件视图。若中央仍引用被右侧关闭/淘汰的文件，内容不能随右侧关闭被清掉，反之亦然；最后一个引用关闭后可释放该作用域对应缓存。Dock 隐藏时保留表现状态并使隐藏区域不可聚焦；切换“文件/变更”也不能因 Git 子组件卸载而丢失勾选或说明。

### 4.2 动作边界

组件只发出明确的用户意图，由同一 `ProjectScope` 的装配方执行或更新个人状态；以下括号是必需语义，不规定 IPC 或 HTTP 字段。受控预览可记录动作并显式改变输入状态，不得把回调本身写成真实操作结果。

| 动作 | 输入及归属 | 可观察规则 |
| --- | --- | --- |
| 切换/关闭 Dock、拖宽，切换文件/变更 | 新开合状态、活动面板或宽度；本地状态 | 关闭不清理文件/变更草稿；主 tab 支持左右方向键、Home、End 和焦点 |
| 展开/收起目录、刷新树、打开右侧文件 | scope、相对路径或刷新意图 | 文件树支持上下/左右、Enter、Home、End，树聚焦跟随路径而非变化后的数组序号；刷新状态和失败可见 |
| 选择/关闭右侧页签、刷新文件 | scope、相对路径 | 文件路径、语言、大小、行数、加载/错误/截断、行号和高亮可见；刷新失败不能把旧内容说成最新 |
| 在中央打开文件、激活/关闭中央文件 | scope、相对路径；发给 HC-202 总页签 | 同一文件重复打开只激活已有页签，右侧状态和对话草稿保留；两个同名文件以完整路径区分 |
| 刷新变更、查看 Diff | scope；查看 Diff 时附当前 `snapshot` 和相对路径 | 显示分支、状态、旧路径、当前选中文件及工作区与 HEAD 的对比；过期结果不覆盖当前选择 |
| 勾选单个/全选、填写说明 | 本地选择及说明 | 默认未选；全选有全选/未选/部分选三态，勾选保留完整路径；文件从上游消失或 `version` 改变时撤销该文件选择并要求重新审阅，不擅自重选 |
| 提交 / 提交并推送 | scope、当前 `snapshot`、已选路径、原说明及是否同时请求推送 | 无权限、忙碌、无选择、空白说明或缺少当前快照时禁用并给出原因；推送还需上游允许及已知目标。回调只表达选择，不执行 Git 或更改原有服务策略 |
| 单独推送 / 重试推送 | scope、当前 `snapshot`、上游确认的提交 SHA | 仅当上游允许且当前头仍与结果关联时提供；不因推送失败再次提交，不自动排队离线写入 |

组件接口如下；`void` 回调只派发意图，不承诺动作成功。各种结果都以新的受控输入呈现。此处的名称和类型属于 UI 包，尚未实现，不作为其他包已存在的接口：

```ts
type ProjectGates = {
  refreshTree: ProjectActionAvailability; openFile: ProjectActionAvailability
  refreshFile: ProjectActionAvailability; openCentral: ProjectActionAvailability
  refreshChanges: ProjectActionAvailability; readDiff: ProjectActionAvailability
  commit: ProjectActionAvailability; push: ProjectActionAvailability
}
type ProjectPersonalView = {
  dockOpen: boolean; dockWidthPx: number; panel: "files" | "changes"
  selectedPath: string | null
  fileTabs: readonly { path: string; name: string }[]
  activeFilePath: string | null
  selectedChanges: readonly { path: string; version: string }[]
  commitMessage: string
}
type ProjectActions = {
  setDockOpen(scope: ProjectScope, open: boolean): void
  setDockWidth(scope: ProjectScope, widthPx: number): void
  selectPanel(scope: ProjectScope, panel: "files" | "changes"): void
  toggleDirectory(scope: ProjectScope, path: string): void
  refreshTree(scope: ProjectScope): void
  openFile(scope: ProjectScope, path: string): void
  selectFileTab(scope: ProjectScope, path: string): void
  closeFileTab(scope: ProjectScope, path: string): void
  refreshFile(scope: ProjectScope, path: string): void
  openCentralFile(scope: ProjectScope, path: string): void
  refreshChanges(scope: ProjectScope): void
  readDiff(scope: ProjectScope, snapshot: string, path: string): void
  setSelectedChanges(scope: ProjectScope, selected: ProjectPersonalView["selectedChanges"]): void
  setCommitMessage(scope: ProjectScope, message: string): void
  commit(scope: ProjectScope, input: {
    snapshot: string; paths: readonly string[]; message: string; alsoPush: boolean
  }): void
  push(scope: ProjectScope, input: { snapshot: string; commitSha: string }): void
}
type ProjectDockProps = {
  scope: ProjectScope; projectName: string; availability: ProjectAvailability
  tree: ProjectTreeView; files: Readonly<Record<string, ProjectFileView>>; changes: ProjectChangesView
  gates: ProjectGates; personal: ProjectPersonalView; actions: ProjectActions
}
```

`personal` 与各动作由同一 scope 的状态拥有者维护，组件不另存一份可能失步的可写副本；目录展开的个人状态投影为 `tree.rows[].expanded`。树可能需要上游加载目录，回调可以请求数据，但 UI 不规定该服务如何读取。中央 `ProjectFileTab` 只接收 scope、路径、显示名、选中状态、关联标识及激活/关闭回调；`ProjectFilePanel` 接收 scope、路径、相应 `ProjectFileView`、刷新能力/回调和可选 HC-205 `RenderingActions`。这些部件不接收整套对话状态。滚动和 DOM 焦点可由部件在该 scope 内持有或由装配方保存，但必须满足第 4.1 节的隔离与恢复行为。

说明长度与旧视图一致，上限为 8192 字符；提交保留原文，仅用去空白判断是否为空。受控数据刷新后，只有同路径且 `version` 未变的选择保留；全选部分态随有效选择重新计算。若上游返回确认成功的提交，只能对该次提交所属 scope 中仍与提交时相同的选择/说明收尾；这期间已经改变的草稿须保留。旧请求迟到、另一账号或另一项目的结果不得清空当前草稿或改变当前页签。推送失败应保留已确认的提交 SHA、错误和单独重试推送入口；提交失败或结果待确认时保留选择与说明，让用户根据上游可用性处理。

文件读取、Diff 和变更刷新允许异步返回：装配方必须按发起时的 scope、路径及本地请求次序关联；切换目标、关闭最后引用或发起较新请求后，旧结果不得写入当前可见内容。组件不为旧的单预览槽引入第二套业务控制器：请求排队/取消方式由实际服务与 HC-202 确定，目标是右侧和中央各自可见内容不互相覆盖。项目服务负责再次验证目标、权限、快照和实际写入，UI 的禁用与本地标记不是授权或并发保证。

## 5. 右侧、阅读器和 Git 的具体行为

1. 右侧常驻“文件/变更”两个主 tab，显示变更数量；可关闭、重开和拖动宽度，关闭状态仍保留上次面板。文件树占右区上部，有预览时树和阅读器按剩余空间自适应；不把树放到新增左侧协作导航。
2. 树保留文件类型图标、层级缩进、展开/收起、目录加载、所选高亮和完整路径提示。右侧页签支持左右/Home/End 移动与激活、Enter/空格激活和 Delete 关闭，关闭按钮不同时触发打开；被关闭项拥有焦点时，焦点移到实际激活的相邻页签，最后一个关闭后回到文件树或明确的打开入口。阅读器使用只读文本、同步行号和 HC-205 高亮；未知语言或高亮不可用时保留可选择的原文。长路径、元信息、刷新和在中央打开按钮在窄宽下可换行，不相互遮挡。
3. 中央文件部件提供文件名、完整路径提示、独立关闭按钮和内容面板；tab 的可访问名称与面板关联所需标识由总页签提供。总页签负责对话/扩展/文件混排和左右/Home/End、Delete、关闭后把焦点恢复到实际激活项。切换时保留已打开视图的状态与滚动，隐藏部分使用 `hidden`/`inert` 或等效隔离。项目部件不导入 Trace，也不复制全部 `WorkbenchViews`。
4. Git 区域保留变更数、分支、刷新、单个/全选/部分选、同名路径提示、说明和提交按钮。Diff 按 hunk 显示真实行号、增删和原始 Diff；无法解析或二进制内容显示原文/原因，文本作为文本渲染，不能变成可执行 HTML。Diff 截断要明确提示；只有服务明确承诺时才展示所选文件完整提交等策略说明，不能由局部预览推断实际写入范围。
5. 变更列表、Diff、说明及结果分别可滚动，按钮图标与文字、关闭控件和页签名对齐；浅/深主题不添加临时新色。忙碌或被上游禁用时显示原因；已确认提交和推送分别展示结果及警告，推送失败不抹去提交事实。
