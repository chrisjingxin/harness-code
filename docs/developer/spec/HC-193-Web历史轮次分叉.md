# Web 历史轮次分叉规格

关联需求：[HC-193](../task/HC-193-Web历史轮次分叉.md)。本文将 Task 的默认行为具体化，用户已在本会话确认；尚未实现。

## 用户流程

回答下点击「从此处分叉」 → 页面锁定本次操作 → Host 校验源会话和截止回答 → 原子创建独立会话 → 刷新会话列表并打开新会话 → 等待用户输入，不自动启动模型。

工作区文件保持当前状态，不调用 Git 还原、不重放工具。原会话可随时重新打开，后续轮次完整保留。

## 截止身份与操作契约

实时和历史消息都保留持久化 `record_id` 与 `run_id`。按钮仅挂在顶层成功 Run 的最终 assistant 记录上；不能用文本相等、时间或数组索引定位。过程回答、child 输出、失败/取消半轮没有按钮。

新增 JSON-RPC `threads.fork`：

```typescript
type ForkRequest = {
  source_thread_id: string
  source_record_id: string
  target_thread_id: string
}
type ForkResult = { thread_id: string }
```

SDK 在一次用户操作开始前生成 target_thread_id；网络重试沿用该 ID。相同目标及相同源/截止点返回已创建会话；同目标不同来源返回冲突，禁止覆盖。数据库保存不可变来源元数据，幂等检查不能仅比较标题。

Web intent 携带源 Thread 和记录身份，经现有 WebUiGateway revision 校验、Interactive Core、Agent gateway 调用 Host；页面不能直接连接 Agent。新契约在 Protocol schema 生成两端类型，Web UI 契约使用下一版本且全量迁移调用方，无双协议 fallback。

## 前置条件与错误

UI 在 active Run、待处理审批/问答、切换会话或分叉请求期间禁用操作。Host 在同一会话锁内再次检查源 Thread 无 active Run；运行受理、撤销、删除和分叉共享互斥边界。既有幂等结果可返回，不因源后续忙碌而再次创建。

错误分类：源会话/回答不存在为 not-found；存在但不是成功主回答为 invalid-fork-point；忙碌为 busy；历史或 artifact 缺失、工具链不配对为 history-unavailable；目标 ID 被不同请求占用为 conflict；其他持久化失败为 internal。映射到 Protocol canonical 错误注册，不以未注册字符串绕过生成器。

失败保留原页面与输入草稿；提示可重试原因。创建成功但打开失败时提示“已创建，打开失败”，保留 target ID，重试打开，不换 ID 再创建。源草稿按原会话保留，新会话输入为空。

## 独立上下文的生成

1. 在事务一致视图内找到 source_record_id，验证其属于源 Thread 的成功顶层 Run 最终回答，确定包含该回答的规范 transcript 截止序号。
2. 复制截止序号以内的规范用户、assistant、工具及必要 context 记录；完整保留工具调用及结果对应关系。创建新记录身份，并保存来源映射用于历史轮次/用量展示。不能复用源当前 LangGraph checkpoint。
3. 解析历史的脱水工具结果、摘要等引用。复制所需 artifact 并重写引用，使其不依赖源会话存在；无法得到完整历史则事务失败，不复制最新摘要补缺。
4. 从截止以内的规范历史建立新会话上下文；截止之后形成的压缩摘要、检索材料或状态一律不带入。需要压缩时在新分支下一次请求按正常策略生成，计入该次 Run 用量。
5. 写入独立 Thread、历史、artifact、来源元数据及继承用量摘要，单事务提交。任何环节失败都不留下可见空壳 Thread。

规范历史不足时明确拒绝；不能声称能从任意截图文本恢复完整执行上下文。新会话恢复和模型投影必须走现有 canonical 路径，禁止额外维护仅 Web 可读的复制历史。

## 继承与隔离

新标题为源标题加「（分叉）」，列表按创建时间显示。新会话绑定当前项目，使用当前可用模型选择和全新 Build 执行状态；不恢复源历史时刻的配置。历史中的计划正文只是文本。

不继承 Goal/Compose 调度、审批授权、文件已读 Snapshot、撤销/重做、active Run、待处理交互或 Trace。新 Run 必须重新读取文件后才能按当前工具契约编辑。

继承的轮次为只读历史，保留来源轮次映射；可再次从继承的最终回答分叉。历史用量沿用来源摘要（HC-194 未实现前为未知），仅作展示，不生成假的新模型调用。任一方之后继续输入、撤销或删除都不能改变另一方已复制历史和可用 artifact。

## UI 与状态一致性

使用分叉图标、提示「从此处分叉」和可访问名称，紧邻复制按钮。操作期间显示忙碌并防止双击；不同点击显式创建不同分支，网络重试保持一个分支。

只有持久化创建成功才更新列表。打开新 Thread 复用现有恢复和 threadEpoch 机制，拒绝迟到响应覆盖用户后来选中的会话；若用户已切到其他会话，不强行抢回选择。复制回答行为不受按钮影响。

## 可观察验证

- 三轮会话从第二轮分叉：可见历史及 mock 模型输入均截止第二轮，原三轮不变。
- 同文回答、多段 assistant、实时与重新打开后的按钮都指向同一持久化截止身份。
- 分叉点后压缩、前置 artifact、工具多调用、多层 child 均不能泄漏后续上下文或产生不配对工具消息。
- 刷新/重启可恢复；源会话删除后新会话仍可继续；从继承历史再次分叉可用。
- 重试、并发创建、运行受理竞态、事务注入失败、打开失败均符合前述结果。
- 文件、HEAD、index 无变化；Snapshot 不继承；协议两端、Interactive Core 与 Web 入口有对应测试。

## 阶段边界

本规格不新增 TUI 分叉命令、文件恢复、worktree、历史编辑或分叉树。后续 Plan/Todo 需以可演示的纵向结果为停点，不能未经确认一次实施全部清单。当前 Skill 豁免由用户明确授权；生产实现和版本尚未修改。
