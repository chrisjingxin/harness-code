## 1. 用户主路径

小王打开小李共享的「账单服务」会话。页面显示小李的执行设备和项目。以下是线上接通且小王拥有相应操作权限时的流程。本机停点由受信宿主注入项目根，直接验证同一套读取、审阅和写入策略。

1. **读文件。** 展开目录或从输入区查找文件候选，再显式打开文件。Java 从当前有权访问的会话解析原设备和项目，Runner 按本机登记目录读取，项目服务返回有界结果。右侧阅读器和中央页签可以显示同一次只读预览。
2. **看 Diff。** 打开变更页，看到原仓库的分支、HEAD、变更和推送目标。选择一项后，项目服务按该次 Git 状态的快照返回它相对 HEAD 的 Diff；状态已变时提示刷新。
3. **勾选。** 小王选中税率修复，填写提交说明。页面默认零勾选。选择和说明只留在小王的桌面。每项选择绑定文件版本，变化后需要重新勾选。
4. **提交。** 原设备复核权限、实际目录、占用及审阅快照，只将勾选文件的当前整文件内容提交。小李未选的日志文件和原暂存内容保留。桌面收到确认后显示真实提交 SHA。
5. **可选推送。** 有既有 upstream 时可点击「提交并推送」，也可在提交成功后单独推送。推送结果与提交 SHA 分别展示。推送被拒绝或尚待确认时，已确认的提交仍显示成功。

文件和 Git 由项目服务调用本机文件系统与 Git。项目服务以 Node/TypeScript 和新平台契约为依赖，可脱离桌面、云端、旧 CLI、Harness/Python 和 ACP 单独运行。ACP Agent 与 Git 的统一占用生命周期、ACP 协议接线和在途写入调试等同事交付后安排。[顶层设计](../architecture/多人协作工作台顶层设计.md) · [并行约定第 0 节](../project/协作任务并行开发约定.md#0-当前调度等待同事交付-acp2026-11-10)

## 2. 项目绑定、共享与缓存

- **原设备项目。** 桌面以会话定位并提交根内相对路径。Java 根据认证身份、工作区和所选会话解析固定 device/project。项目授权复用 HC-196 的设备有效性、工作区与成员关系、项目共享版本和当前 ready 连接，只向该设备即时派发。现有 `requireSharedProject` 含 Agent 配置检查，项目操作须复用其项目/设备事实，并在独立入口判断读写授权。文件和 Git 的可用性与 Agent 配置无关。Runner 用登记表复核设备和项目归属、共享开关/版本及真实根身份。目录被替换、项目未登记或共享版本失效时拒绝。查看者电脑即使存在同名项目，也始终由原设备负责。[现有设备授权](../../../services/collaboration-server/src/main/java/workbench/collaboration/device/DeviceService.java)
- **登记根。** 登记非 Git 目录或 Git 仓库子目录时，文件树、候选和预览可在登记范围内使用。Git 状态、Diff、提交和推送要求登记根与探测到的真实 Git 工作树根相同。检测到仓库根在登记目录上方时，说明需由所有者登记仓库根。远端请求无法扩大登记范围。
- **跨用户读取。** 访问者须有权访问会话，且设备所有者已显式共享该登记项目。内网 Git 托管项目还须由 Java 按访问者本人的 Git 平台身份核验绑定仓库的读取权限。文件树、候选、正文、Git 状态和 Diff 使用同一授权规则。纯本地目录由设备所有者决定是否共享。
- **跨用户提交与线上推送。** 线上推送以操作者的 Git 平台身份发起，由 Git 平台检查实际目标仓库和分支的推送权限。共享项目或接手会话本身仅提供对应的协作权限。跨用户在原设备创建提交的授权待确认。受信本机读取、Diff、选择提交与普通推送由独立停点交付。
- **撤回与离线。** Java 在允许每一步 Git 写入前复核授权。Runner 在首次调用该步之前检查当前连接、本机已知共享状态及目录，并登记即将调用。Java 在授权前发现撤回，或 Runner 在调用前收到新的禁止事实，都拒绝该步。Java 作出授权到 Runner 收到撤回之间存在传递时间，已越过调用边界的步骤按真实结果收敛。提交已确认但推送尚未开始时，推送再次检查该边界。设备离线、未 ready 或项目忙时，人工操作即时返回，不进入会话执行队列。
- **缓存。** 文件树、预览和已加载的 Git 阅读内容只在当次桌面会话内存中复用。按服务域、身份、工作区、原设备和项目隔离，按路径/快照定位内容。仍有访问权且原设备离线时，可显示旧内容并注明「缓存／非实时」。刷新失败保留该标记和原因。缓存不能授权写入或确认写入结果。退出、账号切换或确认项目共享或 Git 仓库读权被撤回时清除对应内容。重连后需要实际重读才恢复实时状态。[HC-196 Spec](HC-196-设备接入与本机执行.md) · [HC-207 Spec](HC-207-文件与变更视图复用.md)

## 3. 本机读服务

项目服务接收 Runner 已解析的绑定根，独立调用时也只能使用宿主明确注入的根。所有外部路径为项目相对路径，使用 `/` 分段。仅目录列表和候选允许用空路径指根。拒绝绝对路径、盘符/UNC、NUL、父目录穿越及该宿主不能无歧义表示的路径。核对真实路径及实际打开的对象，根外链接、Git 管理目录及特殊文件不可读。链接可显示为条目，目录链接不展开，文件链接仅在实际目标为根内允许读取的普通文件时可预览。路径按原值往返，保留可表示的中文、空格、换行及短横线文件名。

| 本机操作 | 输入 → 可观察结果 |
| --- | --- |
| 列目录 | 相对目录、可选续读位置 → 稳定排序的相对路径、名称、种类、是否可展开，以及下一位置或明确截断。沿用 Git 工作区已跟踪及未忽略文件、非 Git 常见产物目录过滤和目录优先排序。沿用 Git 索引 20,000 行、单层 2,000 项上限。续读位置只在同一根、同一目录和可核验的列表版本内有效；无法续读时要求刷新。 |
| 查候选 | 相对目录、查询、结果上限 → 文件、目录或链接候选、匹配范围与截断信息。复用同一项目路径和索引规则，每次最多返回 1,000 项。匹配范围按显示文本的 UTF-16 半开区间表达。仅在已知时提供总数。候选不带正文，选择候选只回填草稿。 |
| 读预览 | 单个相对文件路径 → UTF-8 只读正文、语言提示、源文件字节数、实际展示行数及截断。读取最多 256 KiB，展示最多 2,000 行、每行 20,000 字符。二进制、非法 UTF-8、找不到、无权、文件变化和读取失败可区分。内容过长时展示可安全读取的截断文本，无法生成预览时给出原因。读取时文件变化允许重读一次，再变化则提示刷新。 |

目录、候选、预览及 Diff 各有时间、条目或字节上限。设备回包受 Java `DeviceChannel` 的 **256 KiB（262,144 字节）文本消息上限**约束。发送方按最终 UTF-8 编码的完整文本消息核算，包括设备封包、标识、路径、结果元数据和 JSON 转义。正文或 Diff 超预算时在合法字符边界缩短，明确标记截断并更新实际展示量，再检查完整消息。若仍超限，发送可关联原请求的有界错误。目录和候选使用有界分页或明确截断，Git 状态不可发送能用于提交的部分变更集。错误只返回稳定原因和有界文案，绝对路径、命令环境和凭据留在原设备。[DeviceChannel 消息门槛](../../../services/collaboration-server/src/main/java/workbench/collaboration/device/DeviceChannel.java#L124) · [旧目录索引](../../../packages/cli/src/workspace/workspace-index.ts) · [旧路径策略](../../../packages/cli/src/workspace/path-policy.ts) · [旧预览](../../../packages/cli/src/workspace/file-preview.ts) · [HC-206 候选契约](../../../packages/workbench-ui/src/conversation/types.ts)

## 4. Git 审阅与执行

### 4.1 状态、文件版本和审阅快照

- **状态**来自原设备 Git。返回分支（含分离 HEAD 等状态）、实际 HEAD（初次提交前为空）、变更列表、可选 upstream 与 ahead/behind、写入阻塞原因。跟踪分支比较反映原仓库当前已知状态，实际推送前另核对远端。沿用变更最多 1,000 项及内容指纹扫描累计 32 MiB 的界面处理边界，越限不给出可提交的部分列表。
- **文件版本 `version`**用来判断旧勾选还能否保留。比较相对路径、旧路径、变更种类和该项参与审阅的基线、暂存条目及工作区内容/模式。刷新后，同一路径且版本未变才保留选中。文件 mtime 或列表顺序不足以表示该版本。
- **审阅快照 `snapshot`**绑定实际项目和 Git 工作树身份、分支/HEAD、索引、完整变更集及版本、upstream 目标和影响写入的状态。它由项目服务生成，调用者原样回传。Diff 前后核验快照；写操作在取得占用后且产生副作用前重验。任一依据变化即返回快照过期，刷新后按新版本检查选择。快照是对工作状态的校验值，调用仍需独立授权。
- **Diff**接受快照与变更路径，返回同快照下相对 HEAD 的有界统一 Diff、路径和截断标记。新增文件、首次提交使用空基线，重命名带旧/新路径。对二进制、权限或其他元数据变化明确说明可显示内容，禁用外部 Diff/textconv。沿用旧 96 Ki 个字符的展示上限，线上预算以编码后字节另外校验。截断只限制展示，提交仍为整文件。

### 4.2 选择提交

收到非空且不重复的相对路径集合、审阅快照、非空白提交说明（保留原文，最多 8,192 字符，禁止 NUL）后，复核所选项都属于该快照。未初始化仓库、分离 HEAD、冲突、子模块、进行中的合并/变基/拣选或选中内容无实际变更时，明确拒绝。已有合法分支但尚无 HEAD 的仓库可做首次提交。

取得实际项目占用并锁定真实索引 → 从 HEAD 或空树创建独立索引 → 只放入所选整文件的当前内容与模式 → 对照审阅状态核验提交树 → 通过原设备 Git 提交 → 核对真实提交与索引结果。重命名的旧/新路径一起处理，新增和删除按实际状态入树。Git 参数按字面路径传递，使用能无歧义处理文件名的 NUL 分隔与参数/标准输入。成功后只同步原索引里属于本次提交的路径。未选文件的工作区与暂存内容由项目服务保留，正常拒绝不动原索引；仓库 hook 自行修改的工作区内容按实际状态显示。

受信本机提交沿用执行设备的 Git author/committer、签名和 hooks。线上项目操作记录发起人 ID。保留现有 commit hooks，执行提交前的 hooks 后核验审阅树，暂存树被改写则拒绝并要求重看。Git 返回后核对真实 SHA、父提交与审阅树，并排除外部提交被当作本次结果。确认已提交而索引同步失败或提交命令异常时，保留 SHA 并显示警告，停止后续自动推送。证据不足时进入「提交结果待确认」。[旧本机 Git 策略](../../../packages/cli/src/infrastructure/workspace-git.ts) · [HC-190 验证记录](../task/HC-190-Web主题布局与Git提交.md)

### 4.3 普通推送

提交并推送要求提交前已确认可用 upstream，并显示目标与已知未推送数量。推送可能包含此前已有的未推送提交。**提交确认后重新读取仓库状态**，用新快照校验当前 HEAD 等于本次真实提交 SHA，分支和 upstream 仍与提交前一致。upstream 一致性包括 remote、目标 ref 和解析后的实际推送地址，由服务在设备内核对。提交前快照仅用于提交审阅。状态无法确认或目标变化时，保留 SHA 并返回推送未执行。

开始推送前复核该步骤的权限，用固定 SHA、新快照和已核对的目标查询实际 push URL 的目标分支。探测后再检查本机快照和目标，使用固定 SHA 与目标 ref 发起普通非 force push。保留 pre-push hook，设置非交互有界等待。受信本机推送沿用本机 Git 认证，线上推送按第 2 节使用操作者身份。目标不存在或无法确认时拒绝发起。探测与推送之间远端可能变化，普通 Git 预检只证明探测时的状态。调用者不能传 remote URL、refspec 或凭据，也不自动修改 remote、pull/rebase 或有意创建远端分支。

提交 SHA 与推送结果分别保存。提交成功后，如果 upstream 变化、权限失效或远端明确拒绝，继续保留 SHA 并说明推送未发生或失败。确切失败后只重试推送，要求当前状态与已确认的原 SHA 和推送目标一致。结果未知时先核对原请求。提交并推送的两个步骤分别记录。在线派发在第一次调用 push 时仍需连接就绪、授权有效。重启或重连不补做尚未开始的 push。[HC-190 推送策略](HC-190-Web主题布局与Git提交.md)

## 5. 即时执行与结果核对

同一实际项目上的 Git 写入串行。Runner 按真实根建立占用，同根、别名或影响同一 Git 写入资源的操作不能各自取得写权限。Git 自身的索引锁及快照重验继续防护来自外部终端的并发。项目 Git 写入期间，人工读请求可明确返回忙，避免中间结果成为审阅快照。后续与实际 ACP Agent 共用 Runner 的目录占用入口，遵循 HC-196 第 7.3 节。当前仅验证独立 Git 写入，实际 Agent 生命周期接入与联调等同事交付。[HC-196 Spec](HC-196-设备接入与本机执行.md)

| 可观察事实 | 语义 |
| --- | --- |
| 已受理／进行中 | Java 和 Runner 以同一稳定请求 ID 关联原设备、项目、共享版本、发起人、动作与请求摘要。Runner 在副作用前持久登记该阶段。重复的同 ID 同内容返回原状态；同 ID 内容不一致拒绝。受理或网络送达只说明进入流程。 |
| 明确未调用或失败 | 确认未进入相应写步骤，或已取得足以确认失败且该步未生效的证据。携带稳定原因。恢复在线本身不会重试；失败时保留未提交草稿。若提交已确认，后续推送失败只影响推送结果。 |
| 确认成功 | 提交返回实际 SHA，可附索引同步等警告。推送单独表达未请求、未执行及其原因、成功、失败或待确认。HC-207 现有结果可把明确的未执行投影为失败及原因，后端保留事实区分。 |
| 结果待确认 | 写请求可能已发出或已进入 Git，却缺少可信结果。超时、断线、进程退出或账本结果丢失时保留最后确认步骤。待确认的 commit 不再次提交，待确认的 push 不重复推送；仍保留已确认 SHA。相同请求身份用于读回结果，无自动转派或写入重放。 |

恢复时先查原设备持久结果，再按需核对原请求关联的 Git 证据。提交需能把实际 SHA 归属到本次请求，单独看到 HEAD 移动不足以归属。推送可用可靠的原返回，或可信查询证实既定 upstream 已包含目标 SHA，此时按实际远端状态显示已到达。只要 Git 写进程或本地索引占用仍可能在途，就保留对应写占用。确认写进程和本地索引操作均已结束后，可释放本地占用。推送结果仍未知时，继续保存原请求、原目标和已确认 SHA，界面保持「推送结果待确认」，重连只核对原结果。Java 可接收旧请求的原设备回执以闭合事实，向用户展示回执时仍检查当前权限。记录请求身份、阶段和必要 SHA 等元数据，项目正文和 Diff 不进入共享会话历史。[HC-196 设备与恢复约定](HC-196-设备接入与本机执行.md)

## 6. 共同审查的窄接口

下表是评审用业务形状。正式字段、设备封包和 Java/TypeScript 同源校验经共同评审后落到 `workbench-contracts`。一项动作只接收自身所需字段，浏览器通过具名受限宿主动作调用。

| 边界 | 允许传递与返回 | 主责 |
| --- | --- | --- |

### 8.1 当前底座和授权顺序

现有 `WorkspaceAccess.requireMember` 核验启用账号和工作区成员，`ConversationService` 从会话行取得固定设备和项目。设备服务持有项目归属、共享开关和版本，`requireSharedProject` 还检查 Agent 配置，适用于原执行链。Java `DeviceChannel` 以 Bearer 设备身份维持唯一当前连接，恢复核对后发送 ready。Runner `ProjectRegistry.verify` 读取本机登记、共享版本和真实目录身份。当前 ready 表示设备通道已完成恢复，个别项目可能仍未登记。本机服务已提供五项读取，Runner 当前尚未装配该端口。[成员授权](../../../services/collaboration-server/src/main/java/workbench/collaboration/identity/WorkspaceAccess.java) · [会话绑定](../../../services/collaboration-server/src/main/java/workbench/collaboration/conversation/ConversationService.java) · [设备项目](../../../services/collaboration-server/src/main/java/workbench/collaboration/device/DeviceService.java) · [设备通道](../../../services/collaboration-server/src/main/java/workbench/collaboration/device/DeviceChannel.java) · [本机登记](../../../packages/runner-core/src/project-registry.ts) · [Runner 装配](../../../apps/runner/src/runtime.ts)

1. **当前登录与固定目标。** Java 从当前用户会话取得操作者，核验账号、成员及该会话的访问权，再从会话读取固定 `workspaceId/deviceId/projectId`。请求方只能选会话和只读动作。查原设备未撤销、所属工作区和项目匹配、设备所有者已共享且版本有效。抽取执行和读取都需要的共享事实，保留执行端口自己的 Agent 配置判断。项目读取在 Agent 配置缺失、不可用或无 ACP 的情况下仍可独立授权。
2. **按项目来源加验。** 纯本地项目要求受信来源绑定和所有者明确开启该项目共享。托管项目还必须有可信的规范仓库绑定，至少能唯一定位 Git 平台实例和仓库 ID。读取范围受同一已核验来源约束，包含其他托管仓库的混合目录不能按纯本地项目授权。项目来源和绑定由服务端受信来源提供，工作区成员或读取请求不能自报。现有项目登记只有设备、项目、根标识和共享版本等事实，尚缺可用于授权的来源或仓库绑定。首轮允许隔离演示环境由受信服务端准备过程，将明确为纯本地的来源绑定到已登记项目的 `workspaceId/deviceId/projectId/shareVersion`。每次授权仍核对当前登记、所有者共享和相同版本。演示准备可预置候选元组，只有数据库中真实登记且共享版本匹配后才生效。该绑定仅针对明确指定的项目和版本；项目来源未知或元组不匹配时读取不可用。remote 是否存在不决定授权。正式的来源登记、托管仓库绑定及内网权限接入按后续阶段确定。
3. **内网身份和仓库读权。** Java 授权入口传入当前平台用户、可信仓库标识和读取意图，由内网身份/授权适配取得与该用户关联的 Git 平台身份，并向平台核验该身份当前有权读该仓库。适配返回允许、拒绝、身份未绑定或检查不可用。仓库读权明确允许后才可派发这五项动作；未绑定、超时、平台不可用和权限无法核实均拒绝，区别于已证实无权。凭据留在身份/权限接入层，Runner 只收到原项目操作。设备所有者的 Git 账号、设备 Bearer、会话接手人和本机 remote 配置均不能替代访问者的仓库授权。内网登录、可信绑定来源和权限适配真实接入后才开放该类项目。
4. **只向当前连接即时派发。** Java 复用 `DeviceChannel` 当前 ready 且已声明 `project.read` 能力的连接，在实际发送处校验连接代次和设备状态。先登记本次等待记录，再发送；项目共享或目标变化时按现有重连核对机制处理。Runner 在 ready 后收到请求，核对本连接的设备/工作区、原项目登记、共享版本及真实根。使用 `createProjectService` 绑定后再次核对登记身份，再调用对应只读方法，发送前复核同一连接和登记。目录替换需要重新登记，服务实例不能跟随同路径的新目录。读取期间项目忙时按 HC-196 现有占用事实和项目服务的实际反馈拒绝。
5. **返回前复核访问。** Java 将结果交还发起读取的登录会话前，以原 HTTP 会话检查当前仍登录且身份一致，再核验成员与会话访问、原绑定和共享版本。仅保存派发时的用户名不足以完成这次核对。托管项目重新核验访问者的仓库读权。已经读取的正文如果失去授权则丢弃。Java 在短事务中核对本地授权事实，设备等待和内网权限请求在事务和设备连接锁之外完成。

### 8.2 设备握手能力

现有 `DeviceHandshakeInterceptor.beforeHandshake` 从 WSS 升级请求的 `Authorization` 认证设备，把结果放入 `workbench.device`；`DeviceChannel.afterConnectionEstablished` 再生成当前 `connectionId` 并开始原有 welcome/resume/ready。Runner 收到未知帧时会关闭连接，因此只读帧需要在发送前确认当前连接支持。沿用现有升级请求和 `workbench.device.v1` 子协议，增加一个可选请求头：

```text
X-Workbench-Device-Capabilities: project.read
```

- 安装了只读端口的新 Runner 在发起升级时声明 `project.read`。`DeviceHandshakeInterceptor` 在设备认证成功后读取该可选头，将解析结果放入此次握手 attributes，供 `DeviceChannel` 建立当前连接时保存。未安装端口时不声明。能力只属于这一条连接，不能从设备 ID、上一次连接或 ready 推断；断开和连接替换后重新读取握手声明。
- 声明使用逗号分隔的 ASCII 能力名，每项为 1–64 个小写字母、数字、点、下划线或短横线，允许逗号两侧的空格或制表符。只认完整、大小写一致的 `project.read`。未知能力可忽略；缺失、重复头、空项、非法格式或长度超过 256 字节时，该连接不具备项目读取能力，既有设备握手和执行链继续。能力仅用于帧兼容性，用户、项目和仓库读取权限仍按第 8.1 节核验。
- 新 Java 只向**同一当前连接**同时满足 ready 与 `project.read` 的 Runner 发送项目只读帧。连接 ready 但没有该能力时，项目读取返回能力未接入，原连接继续处理现有执行。替换连接时清理旧连接的等待记录，新连接按自己的声明判断。
- 新 Runner 向旧服务发送额外请求头时，既有 `WebConfiguration.Boundary` 未对额外请求头设白名单，现有 `DeviceHandshakeInterceptor` 只消费设备认证。旧服务继续原有 welcome/resume/ready，Runner 无需等能力回执。现有帧和协议版本不变；项目路由由新服务在识别到能力后发起。[握手拦截器](../../../services/collaboration-server/src/main/java/workbench/collaboration/device/DeviceHandshakeInterceptor.java) · [Web 边界](../../../services/collaboration-server/src/main/java/workbench/collaboration/transport/WebConfiguration.java) · [Runner 消息接收](../../../packages/runner-core/src/device-connection.ts)

### 8.3 最小 HTTP、设备消息与结果关联

建议新增 `POST /api/v1/workspaces/{workspaceId}/conversations/{conversationId}/project/read`，沿用用户会话、固定 Origin、协议版本及 CSRF 校验，JSON 正文上限 16 KiB，结果使用 `Cache-Control: no-store`。方法用于传递读取参数，路径、查询和快照均在正文内。请求体按 `kind` 定义闭合联合，其他字段拒绝。响应按操作返回同源定义的结果或平台错误，不增加通用设备命令入口。无调用方提供的绝对根、设备目标、Git 命令、远端地址、身份或凭据。

| `kind` | 允许的业务参数 | 返回 |
| --- | --- | --- |
| `listDirectory` | 相对目录 `directory`，可选续读位置 `cursor`；根用空串 | 条目、可选下一位置及截断 |
| `searchCandidates` | 相对目录 `directory`、`query`、可选 `limit`，最多 1,000 项 | 候选元数据、匹配区间、可选总数及截断 |
| `readPreview` | 非空相对路径 `path` | 有界 UTF-8 文本、语言、源文件大小、展示字节/行数及截断 |
| `gitStatus` | 无额外业务字段 | 原设备分支、HEAD、变更及逐项版本、整体快照、可展示的 upstream 与阻塞原因 |
| `gitDiff` | `snapshot`、非空相对路径 `path` | 同快照的有界 Diff、路径及截断 |

- **设备请求。** 在现有 `DeviceEnvelope` 的单条 `message` 联合内增设 Java → Runner 的 `project.read`，复用 `connectionId`、`protocolVersion` 和服务生成的 UUID `messageId`。负载为权威 `workspaceId/deviceId/projectId/shareVersion` 及闭合操作。该命令不进入会话执行队列或来源批次。状态/Diff 读取本机已有 Git 数据，缺失对象时返回不可用；不为读取发起网络 fetch 或借用原设备身份去核验访问者权限。
- **设备回包。** Runner → Java 的 `project.read.result` 包含独立消息 ID、原 `requestMessageId`、原项目和共享版本、操作种类，以及一个对应成功值或稳定错误。Java 在等待记录上核对同一当前连接、设备/工作区、项目、共享版本、请求 ID 和操作。只接受一份匹配回包，由原 HTTP 请求返回；关闭、换连、取消和到期会释放等待记录，迟到或重复结果丢弃。结构错误沿用既有设备控制帧规则，未匹配结果不会交给其他请求。查询和正文不进入账本、SSE、会话历史或共享引用，也不写入日志。
- **时间及并发。** 首轮 Java 自 HTTP 请求进入起使用 8 秒总时限，覆盖初次授权、设备等待和返回前复核，为桌面现有 10 秒请求上限预留传输时间。每设备最多 4 个、全服务最多 128 个并发等待记录，超额即时返回忙。Runner 限制活跃读取数，底层已开始的读取如无法立即取消，持续占用本机读取名额直至收敛，逾时或旧连接不得再回包。重连后由调用方重新发起一次读取，新请求使用新消息 ID。
- **回包预算。** 设备请求和回包均核算完整编码消息，执行第 3 节 256 KiB 上限，并保持 Java 同源校验。正文/Diff 超预算时用合法字符边界裁剪，预览重新计算展示字节与行数。目录可在保有正确续读位置时缩页，否则明确截断；候选截断仍要遵守返回项上限；Git 状态超限返回有界错误，不能给出带可用快照的部分变更集。仍无法装入的结果使用可关联原请求的短错误，避免把超大数据送到现有 `sendEnvelope` 后触发断连。[设备控制帧](../../../packages/workbench-contracts/schema/device.schema.json) · [Runner 发送上限](../../../packages/runner-core/src/device-connection.ts) · [桌面 HTTP 客户端](../../../apps/desktop/src/main/collaboration-client.ts)

**失败反馈。** 沿用现有登录失效、成员/会话不可访问、项目未共享和共享版本冲突的错误边界。共同契约须能区分仓库无读权、身份未绑定或核验不可用、设备离线或未 ready、当前连接的项目读取能力未接入、项目未登记或目录已换、服务忙或超时、文件无权/不存在/不支持/超限，以及 Git 根不符或审阅快照过期。设备连接已就绪但本地登记缺失时，返回项目不可用。权限问题不得暴露路径、分支或仓库细节。输出已裁剪且可用时标为截断。读取失败按实际原因返回，后续桌面按第 2 节决定是否保留非实时数据。
