# HC-174 实验性子代理模型分工规格

关联任务：[HC-174](../task/HC-174-实验性子代理模型分工.md)。状态：用户已确认范围；2026-09-10 已与当前源码事实拉齐，尚未进入实现。

本文细化已确认 Task，不是实现完成声明。用户要求不再做真实模型收益实验；下文测试均指正常的工程正确性测试。保持一份 Spec，覆盖只读探索与可选执行两个交付停点，不拆平级功能。源码基线 `9847474`。

## 1. 用户看到的变化

默认什么都不变。用户在配置中开启实验并给角色指定模型后，主模型可以把有明确范围的调查或执行任务交给该角色。助手阅读的原文与工具历史留在自己的上下文；主模型收到最终文本结果，按疑点查证。不是把 `read_file` 的原文偷偷替换为摘要，也不保证每次都会委派。

```text
读取并校验配置 → 为本次 Run 固定角色模型绑定
  → 主模型通过现有 task 委派
  → 独立 child 执行、保留私有阅读过程
  → 沿用最终文本返回与通用大结果处理 → 主模型接收结果并继续
  → 终结时展示主模型与助手的完整用量摘要
```

关键设计选择：配置重启 sidecar 后生效；不做运行中热切换；显式绑定的内建角色使用 Managed 执行；未绑定角色保留 Inline；不增加新工具、Portal 服务或调度器。`[experimental]` 是 Host TOML 新顶层区段，沿用 `[goal]` 的登记方式；它不是 Plugin 清单字段，也不是 `[models.roles]`。

## 2. 配置 interface 与生效规则

以下是拟新增 TOML v1 interface，当前尚未实现：

```toml
[experimental.delegation]
enabled = false

[experimental.delegation.models]
explore = "fast"
# general-purpose = "fast"
```

| 字段 | 类型与默认 | 行为 |
| --- | --- | --- |
| `enabled` | boolean，默认 false | 总开关 |
| `models.explore` | 可省略的非空 Profile ID | 指定只读角色的实际模型 |
| `models.general-purpose` | 可省略的非空 Profile ID | 指定通用执行角色的实际模型 |

1. 当前 `ConfigManifest.SECTIONS` 没有 `experimental`。未知顶层区段会加载失败，因此必须把 `[experimental]` 登记为 `implemented`，允许来源与现有用户/显式 TOML 相同（`USER`、`EXPLICIT`）。这与 Plugin 清单里的 `experimental.themes/monitors` 不是同一份配置，禁止互相读取或复用解析。
2. 省略整个 `[experimental]` 等价于关闭。若出现该区段，只允许 `delegation` 子表；`[experimental.delegation]` 只允许 `enabled` 与 `models`；`models` 只允许 `explore` 与 `general-purpose`。未知字段、空串和错误类型均报配置错误。`enabled=false` 仍检查结构，但不解析闲置角色引用、不请求凭据、不构造 child engine。
3. `enabled=true` 时必须至少指定一个角色，且所有引用都存在于合并后的 ModelCatalog。否则配置加载失败，错误指出配置字段与 Profile ID，不输出 endpoint 或凭据。
4. 仅用户 TOML 与显式 `--config` 来源可设置；按现有配置来源顺序逐字段覆盖。没有新增环境变量、CLI 开关、项目自动加载。不加入 `ConfigChangeService` 白名单，不提供 `config.write` 入口。现有项目配置拒绝规则不变。
5. 修改配置并重启 sidecar 后，对下一次受理的 Run 生效。活动 Run 的绑定固定；历史 Run 仍显示历史实际模型。新配置不重解释已经发生的 child 执行。
6. 开关关闭后，角色覆盖和实验提示均不启用；返回格式始终沿用现有文本契约；已配置的闲置字段不影响正常使用。
7. 主模型继续使用现有 Thread/Run 选择。既有 `models.roles`（`planner/executor/reviewer/tester/summarizer`）不作为本功能的第二入口，也不被本功能改写。Plugin Agent 显式或继承模型的原有规则不被覆盖。
8. 主 Run 受理前校验已启用角色的 Profile、凭据可用性及现有工具调用/流式能力要求（与当前可选模型相同：`tool-calling`、`streaming`）；失败明确拒绝，不静默禁用角色或回退主模型。启动不发探测请求；实际 provider 失败在调用时处理。绑定与主模型不同的 Profile 会额外占用 `runtime_pool` 槽位，池满沿现有错误，不在池外建图。
9. `config show` 的脱敏结果包含开关、角色 Profile ID，以及“重启后对下一次 Run 生效”；不得包含密钥、endpoint 或 Header。实现上扩展现有 `Za38Config.redacted()`，不另开展示通道。

## 3. 模型选择、构图与生命周期

### 3.1 一次解析，运行与展示使用同一绑定

| 情况 | 实际执行路径 |
| --- | --- |
| 实验关闭 | 现有内建 Inline 与 Plugin Managed 路径 |
| 开启、内建角色未绑定 | 现有 Inline，继承本次父实际模型 |
| 开启、内建角色已绑定 | Managed，使用指定 Profile；即便与主模型同名也走该路径 |
| Plugin Agent | 现有定义解析路径，不应用内建角色覆盖 |

Host 在主图构建前解析角色上限、实际模型和 engine 身份，生成唯一 DelegationTarget。编译 `task` 的目标列表时，每个内建 ID 恰有一个 target；已绑定角色不能同时保留 Inline 备选。不得把内建角色伪装成可由插件覆盖的定义。

Managed target 必须填写现有字段：`mode=ExecutionMode.MANAGED`、`model=child_spec.model_view`、`engine_profile_key` 来自 `child_spec.runtime_profile`。缺 `engine_profile_key` 会在现有校验中失败（`DELEGATION_MANAGED_PROFILE_REQUIRED`）；Inline target 不得携带该字段。模型实际值来自 child_spec，不从提示文本或字符串替换产生。

已绑定角色复用 `ResolvedAgentSpec`、AgentEnginePool、ManagedAgentExecutor 和独立 child checkpoint。主 engine 的身份包含有效实验策略/目标绑定指纹，child engine 的身份包含实际模型、角色指令版本和能力上限，避免池复用错误的图。关闭时不为闲置实验字段制造新的有效运行身份。

Pool 容量不足沿现有错误路径返回，不在池外临时建图。每次执行独立 lease、execution ID、checkpoint namespace；不得因模型相同而共享父 messages 或不同子任务的历史。同一 child 的审批恢复继续自己的 checkpoint，不重新执行已完成文件修改。

角色、模型、权限、历史记录和 UI 取同一份脱敏实际绑定；模型名不能由助手自报决定。模型服务返回别名可留诊断，但不覆盖 Profile 选择事实。

### 3.2 权限保持角色语义

- `explore` 保持 `glob/grep/ls/lsp/read_file` 的工具上限并与父有效能力求交，无写入、任意 Shell、外部网络工具、MCP、Skill 或 `task`。实际缺失的工具不补造。当前 Inline 构图对 explore 不挂 Plugin middleware，Managed 化后保持这一上限。
- `general-purpose` 沿用内建角色现有能力与审批规则：继承父 MCP/Skill、在父 `default` 下保留角色默认 `auto-edit`、`plan` 与已激活 Plan 约束始终优先。Managed 化不得额外挂载 Plugin Agent 专属 Hook，也不得把能力收成 Plugin Agent 子集；不新增递归委派。当前 Inline 构图对 GP 挂 Plugin middleware 是为了继承父 MCP/Skill，不是把内建角色变成 Plugin 定义。
- 动态父权限收紧作用于 child 后续工具边界。父权限放宽不超过角色上限；Plan 限制和现有角色审批例外保持原义。
- 使用现有受控 RunContext 继承必要规则和取消状态，但不复制父完整对话。任务正文、路径范围只是模型指令，不等同于新的文件权限授权。
- Compose stage 与 Team 角色不走本实验绑定；它们继续使用既有装配，错误语义不变。

## 4. 委派与交接 interface

### 4.1 输入与主模型规则

保留现有 `task` 工具签名和目标 ID，不新增 `bulk_read` 工具。开启且角色已绑定时，在对应角色描述与主模型指令中说明：适合的任务、实际 Profile、交付要求及不适合的情形。`/agents` 只读浏览对已绑定角色展示实际 Profile ID；关闭或未绑定仍显示现有继承策略。子代理卡片与时间线使用同一份脱敏绑定，不从助手正文猜测模型。

task 正文应说明目标、范围、必要上下文、限制与验收。指令要求主模型将大范围定位/阅读交给 explore，将明确的局部实现交给 general-purpose；简单精准读取、复杂判断和关键风险仍直接处理。不得为了委派先读完整资料；收到结果后按疑点查证，不例行全量重查。这是提示策略，不是确定性任务分类器。

### 4.2 统一复用现有文本返回

实验角色和普通 subagent 共用现有返回链：Inline 最终 AIMessage、Managed final → 父 task ToolMessage。不开设实验专用 JSON 格式，不限制字段、段落、围栏或数组数量，不因格式不符拒绝有效回答，不额外调用模型修复格式。Plugin 现有契约不变。

对实验绑定角色通过提示词提出交付要求：

- 调查助手：简短结论、文件或符号位置、必要短引文、未覆盖范围与疑点。
- 执行助手：变更摘要、文件列表、已做验证和结果、未解决问题；未做验证时说明原因。
- 返回与任务有关的信息，避免复述大段源码和完整调查过程。这是表达要求，不是运行时保证的固定结构或长度。

运行时实际模型、execution ID、执行状态与用量继续走可信元数据，不依赖模型自报，不要求它们出现在助手正文中。

### 4.3 大结果处理与上下文隔离

不新增 12 KiB 或其他实验专用正文上限。复用现有 DeepAgents FilesystemMiddleware 的通用工具结果处理：当前默认 `tool_token_limit_before_evict=20000`，按 `NUM_CHARS_PER_TOKEN=4` 估算，即约 80,000 字符；`TOOLS_EXCLUDED_FROM_EVICTION` 含 `ls/glob/grep/read_file/edit_file/write_file/delete`，**不含** `task`。超过阈值后尝试保存结果到文件，向父模型返回缩短内容及文件引用。这是字符估算，不是 tokenizer 精确 token 上限，也不是要求回答简短的保证。数值属于当前依赖实现，不在 Harness 另复制一份阈值或配置。

现有 1 MiB 工具事件传输截断只保护 wire payload，不代替父模型上下文的结果处理。外存成功、失败与提示沿现有机制，不新增实验专用截断、格式错误或恢复分支；父模型需要全文时可按现有文件引用主动读取。回归测试应核对实际 middleware 路径，不能仅测试最终文本包装函数就宣称覆盖外存。

完整工具历史、原始文件和隐私推理不自动回灌父 messages。父 Transcript、历史重放与上下文恢复保持同一隔离原则。助手主动选入最终回答的引文或原文、父模型主动读取的全文仍可能进入父上下文；不承诺最终回答必然短小，也不承诺源码字符绝不进入父上下文。结果作为不可信工具资料，不提升为系统指令，行号与引文不授予 Snapshot。

### 4.4 执行正常结束不等于任务全部完成

不增加 completed/partial 的模型输出字段，也不解析正文生成新的交付状态。execution completed 只表示执行正常终结；助手在正文说明未完成部分，主模型根据证据和验收判断任务是否完成。UI 不把运行成功自动文案化为“用户任务全部完成”。

文件变更仍通过 canonical 工具执行。已有工具事件能证明的已提交操作与助手正文自报信息区分；不因本功能新增副作用扫描或另一套变更清单协议。执行失败后沿已有 child timeline 检视操作；无法确认副作用时明确可能存在部分变更，不能声明无修改或盲目重跑。

## 5. 错误、取消与资源收敛

| 场景 | 对父 task 的行为 |
| --- | --- |
| 配置/角色 Profile 无效 | 受理前失败，不创建 child |
| 已识别的 provider 调用失败 | 有界 error ToolMessage，主模型可继续；保留 child failed |
| 正常返回文本，正文说明未完成部分 | 原样沿现有结果链返回，主模型判断后续工作；不自动重试 |
| 很长的最终文本 | 复用通用大工具结果处理，不新增交付错误码 |
| 空正文或 provider 长度截断 | 沿现有执行/结果处理语义，不新增实验专用校验和格式修复；运行结束不证明答案完整 |
| child timeout | 沿 HC-169 的 `DELEGATION_TIMEOUT` Tool 级错误语义 |
| 父取消 | 原样取消传播；不转换成可恢复错误，不启动替代执行 |
| 权限、身份、Registry 不变量或未知内部错误 | fail closed，保留现有传播语义，不统统包装成可恢复失败 |

错误仅含稳定码、脱敏说明和执行身份，不泄露 traceback、请求/响应正文或凭据。已发生操作仍可在已有 child timeline 查看；对可能有副作用的执行失败明确提示可能存在部分变更，不附加伪造的模型回答。

转换发生在受控父 `task` 工具边界，按稳定错误类别判断；不在 RunCoordinator 全局吞错，不改变 Compose/Team 的错误语义。正常工具返回沿现有文本契约，不以新增 JSON 校验决定成功。父 Run 能继续不等于 child 成功。

沿用已有 provider retry；不新增模型升级或编排重试。取消/失败也必须 await runner 收敛并释放 slot/lease；已经提交的文件修改不自动回滚。用户在重启后开启的新 Run 可以使用新绑定，旧 child 的活动 checkpoint 不被本功能自动迁移到另一模型。

## 6. 用量计量与可观察 interface

### 6.1 计算规则

实验开启的 Run 为每次可观察模型调用分配唯一调用身份，关联 execution ID、实际 Profile、模型回合和 provider attempt。同一回合重试是不同 attempt；同一调用的流式分片、最终消息和事件重放只累计一次。

- 流式增量先合并为本次调用结果；累计快照只更新同一调用，不能直接逐块相加。
- execution 用量是自身各调用之和，不包含后代；Run 合计是 root 与所有后代自身用量之和。子事件到达父事件流不再计为父调用。
- 失败/取消前已取得用量的调用也计入；重试回滚内容不能回滚已经发生的消耗。
- 不把现有 `StreamSession.update_usage` 的 session 最大值当作多轮总账；新摘要使用统一的按调用记录，Inline 与 Managed 都接入，不从日志反向解析计费。
- SDK 内部未暴露的重试或未知用量标记不完整，不声称等同供应商账单。辅助模型调用若属于该 Run，按实际 Profile 归入调用所属 execution；无法覆盖时将汇总标为不完整。
- 输入、输出、缓存读取、推理 token 独立记录；缓存读取为输入明细，不再次加到输入。推理 token 是否包含于 output 由 provider 语义决定，禁止盲目相加生成总 token。
- 每个指标保存 `known` 非负整数和 `complete` boolean；没有调用时 known=0/complete=true，有调用但缺字段时 known=0/complete=false。界面分别显示 0、未知或“至少 N（不完整）”。
- `duration_ms` 表示该 execution 从启动到终结的墙钟时长；Run 时长不是各 child 时长之和，避免并行执行重复加时。

### 6.2 协议与显示

在协议 canonical schema 中，为 Run 的 completed、failed、cancelled 终态 payload 新增可选 `delegation_usage`，仅实验开启的 Run 提供；TypeScript/Python 从 schema 生成，同步迁移调用方，不手改生成文件。当前事实：`usage` 定义只有 `input_tokens/output_tokens` 必填和可选 `cached_tokens`，都是非负整数，没有 `complete` 标志，也没有 `reasoning_tokens`；`run.completed` 已有这份旧 `usage` 与 `duration_ms`；`run.cancelled` 只有 `reason`，`run.failed` 只有 `error`；三份 payload 都是 `additionalProperties: false`。本功能不改旧 `usage` 含义，只在三份终态上增加可选新字段。`reasoning_tokens` 只出现在新摘要里；现有 `StreamSession.update_usage` 只按调用取 input/output/cached 的最大值，不能当作多轮总账，也不提取推理 token。

该摘要包含：

| 字段 | 内容 |
| --- | --- |
| `executions` | 按 execution 列出 ID、parent ID、agent ID、实际 Profile ID、状态、duration_ms、按实际 Profile 分组的自身用量 |
| `root` | 根 execution 自身用量，不含子执行 |
| `total` | 根及全部后代自身用量之和；各指标带完整性标识 |
| `duration_ms` | 根 Run 总墙钟时长 |

每份用量含 `input_tokens/output_tokens/cached_tokens/reasoning_tokens` 四个指标及可观察调用数、缺失输入或输出用量的调用数；每个指标形状为 `{known: integer, complete: boolean}`。execution 的主 Profile 与其辅助调用的按 Profile 分组不能混为一谈。

现有 `run.completed.usage` 保留当前字段含义，不暗中换成含 child 的数值。实验 Run 的新展示以 `delegation_usage` 为准，并明确标注“主模型自身”“含助手合计”，不把两者再次相加。旧历史没有新摘要时显示“无完整委派统计”，不能从父 usage 补造。

TUI/Web 复用既有 Run 详情/终态摘要和 child 卡片，展示角色实际 Profile、状态、耗时及上述输入/输出/缓存/推理统计；不新建仪表盘。非交互消费者可从同一终态事件获取。摘要随现有 Run 终态事件持久化与回放，避免 Registry 丢弃后无法核对；不另建计费数据库。进程崩溃未产生终态时，不伪造完整总账。

诊断日志只记录执行身份、模型脱敏标识、用量及完整性，沿现有日志契约生成链更新；不记录提示词、源文件内容、endpoint 或秘密。未配置单价时不显示货币成本和节省百分比。

## 7. Module 职责与实现 seam

| 既有 module | 本功能职责 |
| --- | --- |
| `config/config_manifest.py`、`config.py` | 登记 `[experimental]` 区段、解析 `delegation`、扩展 `redacted()`；不写入 ConfigChangeService |
| `runtime/agent_spec.py`、`builtin_agents.py` | 从内建角色和指定 Profile 解析实际 spec、能力上限与身份 |
| `host/agent_host.py`、`runtime/agent.py` | 为每个角色装配唯一 target，复用 Managed engine 获取与构图；不把 Plugin 专属行为灌入内建角色 |
| `runtime/agent_delegation.py`、`managed_agent_executor.py`、`child_stream.py` | 委派生命周期、现有文本结果传递、用量传递与失败收敛；避免在 Host 复制整套 executor |
| `runtime/execution_stream.py`、`agent_execution.py`、`host/run_coordinator.py` | 调用自身用量、execution 终结及 Run 汇总，失败路径也保存已知消耗 |
| `packages/protocol/schema/v3.json` | 终态统计的唯一跨进程定义 |
| `packages/cli/src/interactive/` 及 TUI/Web 表现层 | 消费相同协议事实，展示与回放，不在前端重算计量规则 |

只在既有职责处增加真实变化，不创建泛化路由框架。复用同一个父子文本交付 seam，实际模型解析集中一次，计量集中在模型调用身份处，避免各展示端分别猜测。

## 8. 不变量与非范围

1. 关闭默认路径不注入实验指令、不创建额外 child、不改变已有交付文本和用量展示。
2. 一个 execution 的模型绑定固定且可核对，模型失败不静默换模型。
3. 原文进入 child，不因 UI、历史或错误包装自动进入父模型；父主动读取除外。
4. 执行状态与权限由运行时控制；简洁、证据与未解决问题通过提示词引导，不保证固定长度或格式，不把执行状态当作任务完成判断。
5. Snapshot、Plan、审批、取消和资源池限制不可因实验功能放宽。
6. 执行失败、可能的部分修改和用量未知都显式表达，不能伪装成功、无副作用或零消耗。
7. 不进行真实模型 benchmark，不承诺性能收益；不增加 Task 非范围中的门禁、平台、自动升级或通用 schema 引擎。
8. Compose stage、Team 调度和 `[models.roles]` 自动拓扑不在本功能内；实验绑定只作用于生产 `task` 的内建 `explore` / `general-purpose`。

## 9. 验证规格

| 测试场景 | 可观察结果 / 对应 Task 验收 |
| --- | --- |
| 缺省、false、true 无角色、未知顶层/子表、非法字段、未知 Profile、来源覆盖 | 关闭等价；未登记区段与非法配置明确失败；重启生效，Task 1/2 |
| 两个 mock Profile 分别响应、/model 切换父模型、池复用 | 已绑定角色始终用指定 Profile，未绑定者继承实际父模型，Plugin 不被覆盖，Task 2/3 |
| child 工具返回唯一标记原文，随后父继续、历史回放 | 未选入交付结果的标记不出现在父请求；短引文可出现，Task 4 |
| 父依据 evidence 定向读取、直接用摘要尝试修改 | 合法读取通过，无有效 Snapshot 的修改失败，Task 5 |
| 权限收紧、Plan 模式、只读助手写入/再委派、GP 继承父 MCP/Skill | 执行边界拒绝越权；Managed 后仍是原内建能力，不是 Plugin Agent，Task 6 |
| 普通文本、Markdown、不同段落结构、正文说明未完成 | 有效文本不因格式被拒绝；不解析正文生成 partial 状态，Task 7 |
| 超过通用外存阈值的 task 结果、外存失败、父主动读取引用 | 经过现有 middleware、提示和失败语义与基线一致；不引入新长度限制，Task 1/4/7 |
| provider 失败、排队与执行超时、父取消竞态、部分写入后失败 | 父错误分类正确、child 终态与副作用提示准确、slot/lease 回收，Task 7 |
| 多轮输入 10+20、child 7、重复事件、重试与未知用量 | root=30、total=37；重复不增计，失败已知值保留，缺失标不完整，Task 8 |
| 成功/失败/取消协议事件与历史重放 | Python/TS 接受同一形状，TUI/Web 展示自身与合计，旧记录不伪造，Task 8/9 |
| 用户配置示例与关闭操作 | 默认注释/关闭，明确与 `[models.roles]` 的区别、模型引用、重启、实验限制，Task 10 |

测试沿包内镜像目录：Python 使用 pytest，CLI/协议消费使用 Bun test。真实模型和真实凭据禁止进入测试。实现阶段先最小失败测试再实现；普通效果实验不作为正确性验证替代。
