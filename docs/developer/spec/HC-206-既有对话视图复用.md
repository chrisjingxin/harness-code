## 1. 目的、现状和边界

现有 Web 的中间对话、工具与输入区经过多轮调整，但组件直接读取旧 Web Adapter、交互状态和 Harness 私有类型。直接搬用会把旧控制器和单机假设带进新桌面；重画则会丢掉已被用户确认的头像、消息阅读流、工具细节和键盘操作。本任务以原组件及最终生效样式为起点，保留这些可见行为，只替换数据和动作的来源，再增量显示多人作者、引用和交接。

输入链路为：装配方提供当前账号和会话对应的窄视图值及动作 → 对话区展示并收集用户操作 → 回调把用户意图交还装配方 → 外部确认的状态再次作为视图值输入。对话区不自行访问网络、磁盘、Agent 或原设备，也不把一次点击或回调完成显示为真实执行成功。

- 本任务的生产文件限定在 `packages/workbench-ui/src/conversation/`。公共主题、公共渲染、项目视图、中央总页签、主进程和旧源码均不由本任务直接修改。
- HC-205 已提供 `RoleAvatar`、`Markdown`、`CodeBlock`、高亮及 `RenderingActions`；桌面已有 `DesktopHost.copyText/openExternal`。区域只消费这些公开出口和同一主题，不重建色板、头像或渲染器。
- 当前只允许独立 UI 模型、组件及受控数据。ACP 能力/事件映射和真实发送、取消、回答/审批的接线、调试与验证，等待同事完成 ACP 并交付代码，由统筹另行安排。受控回调不是 Agent 运行证据。
- HC-202 负责会话事实到视图的投影、中央页签及实际装配；HC-207 负责右侧文件/变更与中央文件页签部件；HC-198 负责交接/引用业务；HC-201 负责 Harness 专有展示。接口评审、最小组件就绪与真实集成是三个不同前置。
- 不复制或改名保留 `WebAdapterSnapshot`、`InteractiveSnapshot`、旧 Intent/Controller，不回引旧 CLI、旧 protocol、Harness Thread/Run 或专用 marker。旧源码保留给其他迁移任务，最终退役归 HC-203。

## 3. 窄视图模型与动作

以下为本区拟议接口。`id` 均为装配方在当前会话内提供的稳定显示身份，不要求对应某个协议字段；展示字符串可以包含不可信内容，普通文本按文本渲染，Markdown 只经 HC-205 安全组件。不得由显示名称推断权限、Agent 种类或身份。

本区公开类型统一使用 `Conversation` 前缀，避免和 project 区域的短类型名冲突。停点一先提供仅覆盖消息、推理、普通工具文本、历史交互及个人滚动/展开的窄时间线类型；Composer、结构化工具与人工交互完整模型留各自后续停点，不因预览而提前接线。

停点一的实际区域入口为 `ConversationTimeline`，其配套公开类型为 `ConversationScope`、`ConversationTimelineEntry`、`ConversationTimelineActivity`、`ConversationTimelineScroll`、`ConversationTimelineState`、`ConversationTimelineChange` 和 `ConversationTimelineProps`。这组类型是本节完整视图模型的时间线子集，不包含输入区或待处理审批；停点二按审定的 `ConversationView` 组合并收敛预览所需的临时根出口。

**停点一接口裁定（2026-11-10）。** `ConversationTimelineProps` 增加必填的本地 `contentRevision: number`，由装配方与时间线条目一起传入。每个完整 `ConversationScope` 的版本在同一装配生命周期内单调递增，且跨隐藏、卸载和切回同一会话保留。追加新条目或更新已有条目的实际输出时递增，包括同一条目 ID 的流式文字或工具输出变化。补载旧历史、重渲染、切换页签、工具展开和外观变化沿用原版本。

`ConversationTimelineScroll` 增加 `seenContentRevision: number | null`，与原滚动锚点、偏移和跟随状态一起按完整 scope 保存。初次显示且无可比较版本时以当前内容建立基线。随后只有可见对话跟随到最新输出、用户滚回底部或点击跳转到底部时才更新所见版本。隐藏或卸载后重开时，先恢复锚点与展开状态。如果当前版本更新，显示“有新输出”并保留原阅读位置。装配层重建内容版本时，将旧所见版本清为 `null`，仍可恢复保存的锚点。两个值用于本地阅读提示，正式提供与状态隔离归 HC-202。

**停点二 Tab 模式切换裁定（2026-11-10）。** 装配方通过可选的 `tabCycle` 指定模式控件及轮转顺序。`itemIds` 只列允许轮转的模式，管理入口继续由菜单处理。输入框空闲且无菜单，草稿既无有效文字也未选择引用或附件时，才处理无修饰键的正向 Tab。输入法组合、发送或停止等待期间以及 Shift+Tab 保留对应的输入和焦点行为。命令和文件提及菜单优先处理各自的按键。

仅当回调存在、目标控件可用且名单中有至少两个不同的可用选项时轮转。按名单顺序跳过禁用或不存在的选项，末项回到首项。当前选项不在名单时从首个可用项开始。只有真正发出 `onCapabilitySelect(scope, controlId, itemId)` 才拦截 Tab。该声明属于 UI 装配能力。

工具块为显示材料，`outputText` 在结构化块缺失或不可用时保持可读，`copyText` 是调用方明确指定的复制内容。选项要求反馈时不能设置为点击立即提交。调用方提供交互到期时间时使用毫秒时间值；没有期限时不显示倒计时。`ConversationReferenceView.id` 在草稿中指可提交的引用草稿显示身份，在历史中指正式引用显示身份；它们的业务含义和转换由 HC-198/202 负责。

审批与问答使用可选的 `retryRevision` 确认可重试。其默认值为 0，装配方按完整 scope 和请求 ID 保存非负整数，只有确认同一请求可以再次提交时才递增。视图记录每次提交时的值，回调结束后只在当前值大于该记录且请求仍可操作时允许再次提交。这样在切换页签或请求期间也能收到确认。设备或网络恢复只更新可用性。装配方还负责跨视图卸载保留在途及结果未知状态。该值只用于界面装配。

光标、匹配范围和 token 范围均为当前 JavaScript 字符串的 UTF-16 半开区间；查询返回后还要比较原 scope、目标、请求号及草稿修订，不能只比较查询文字。请求进行时由组件显示加载态；返回结果只对应该次请求，未知总数使用 `total` 缺省。`ConversationPersonalChange` 是局部变更而非全局快照替换；草稿正文、引用或附件选择发生变化时均递增修订号，修订号只用于同一 scope 的 UI 草稿竞态，不是服务端版本或安全凭据。`clear-draft` 只在当前分区修订号仍等于 `expectedRevision` 时原子清空正文和引用/附件选择并递增修订号；不匹配则不清空。`ConversationComposerView.references/attachments` 是对应 ID 的显示资料，不能成为另一份选择真源。

`ConversationView` 接收 `scope`、`visible`、上述时间线/输入/待处理交互模型、个人状态和动作；它不接收全局工作台快照。`visible` 由中央装配方传入，用于暂停隐藏时的滚动跟随和焦点恢复；中央页签本身不由本组件创建。

| 动作 | 输入与结果边界 |
| --- | --- |
| `onPersonalChange(scope, change)` | 仅提交本人的草稿、选择范围、滚动或展开状态的局部变更；调用方按完整 `scope` 合并，不能用全量远端消息覆盖个人状态。 |
| `onSend(scope, draftRevision, text, referenceIds, attachmentIds)` | 仅在外部允许且草稿可发送时触发。回调明确返回 `accepted`、带原因的 `rejected` 或结果 `unknown`；异常默认按结果未知显示，不能假定没有保存。`accepted` 只表示该调用方确认受理，不表示 Agent 已执行或完成。仅在原 scope、原身份仍有效且草稿修订仍匹配时清空对应草稿；被拒绝、状态未知、身份失效或用户继续编辑时保留草稿。结果未知时不自动重发或显示失败终态，由装配方确认后解除禁用。切到同账号的其他会话后可更新旧会话分区，但不能清空当前会话；实际受理及引用事务由 HC-202/195/198 实现，本轮不接线。 |
| `onCancel(scope)`、`onInteractionSubmit(scope, interactionId, answer)` | 只是用户意图；触发后防重复，回调返回仍等待调用方提供后续事实或明确告知可重试，不能立刻把时间线改成已取消/已批准。异常显示结果未确认并保留输入，不自动重试或假称请求未送达；是否能重试由调用方状态决定。回答中的选择值只来自当前请求列出的选项。 |
| `onCommand(scope, itemId)`、`onCapabilitySelect(scope, controlId, itemId)` | 只对当前可见且允许的条目触发；命令、模型、模式及管理入口的显示/禁用原因由调用方提供，组件不编码具体 Agent 的能力枚举。 |
| `onRequestFileCandidates(scope, target, request)`、`onOpenFile(scope, target, relativePath, destination)` | 候选请求与显式打开动作的输入、迟到结果和归属见第 5 节。选择一个文件提及只回填输入，不等于打开文件或读取正文。 |
| `onReferenceAction(scope, referenceId, action)` | `action` 仅为调用方允许的定位、刷新或移除；刷新等待新预览后替换草稿项，定位不绕过实际授权，不自行修改引用正文。 |
| `RenderingActions.copyText/openExternal` | 复用 HC-205；缺失时动作不可用，复制成功只在 Promise 成功后显示，失败可见且正文仍可选择。链接仅在用户主动操作时交给宿主，不能退回 `window.open`。 |

对外组件和回调的组合形状拟定如下；所有回调可缺省，缺省时相应按钮禁用。具体实现可在不扩大上述行为边界的前提下拆分文件。

```ts
type ConversationActions = {
  onPersonalChange?: (scope: ConversationScope, change: ConversationPersonalChange) => void
  onSend?: (scope: ConversationScope, revision: number, text: string,
    referenceIds: readonly string[], attachmentIds: readonly string[]) =>
      Promise<{ status: "accepted" } | { status: "rejected" | "unknown"; message: string }>
  onCancel?: (scope: ConversationScope) => Promise<void>
  onInteractionSubmit?: (scope: ConversationScope, interactionId: string,
    answer: ConversationInteractionAnswer) => Promise<void>
  onCommand?: (scope: ConversationScope, itemId: string) => void
  onCapabilitySelect?: (scope: ConversationScope, controlId: string, itemId: string) => void
  onRequestFileCandidates?: (scope: ConversationScope, target: ConversationProjectTarget,
    request: ConversationFileCandidateRequest) => Promise<ConversationFileCandidateResult>
  onOpenFile?: (scope: ConversationScope, target: ConversationProjectTarget, relativePath: string,
    destination: "preview" | "central") => void
  onReferenceAction?: (scope: ConversationScope, id: string,
    action: "open" | "refresh" | "remove") => void
  rendering?: RenderingActions
}
type ConversationViewProps = {
  scope: ConversationScope; visible: boolean; entries: readonly ConversationEntry[]
  contentRevision: number
  activity: ConversationActivityView | null; composer: ConversationComposerView
  interaction: ConversationInteractionView | null; personal: ConversationPersonalState
  actions: ConversationActions
  slots?: { aboveTimeline?: ReactNode; composer?: ReactNode }
}
```

扩展节点的所有数据和事件由装配方提供；`slots.composer` 是输入区的增量插槽，不替代或控制通用 textarea。`onPersonalChange` 缺失时对话视图只读；回调不能把某个 scope 的结果派到另一 scope。`onOpenFile` 和 `onReferenceAction` 为意图，不要求同步返回真实文件或来源权限结果。

上述动作缺失或 `enabled: false` 时，相关控件不可触发并展示可理解原因；状态值/禁用理由由装配方提供，不把失联误写为完成，也不由 UI 判定真实权限。空闲默认显示发送、活动状态默认显示停止的原布局可保留；若未来业务同时允许排队发送和取消，装配方必须能分别提供两项能力和布局，不能让组件假定二者互斥。

## 4. 保留的视觉和交互

### 4.1 时间线与工具

- 按 `styles.css` **最后覆盖后**的结果迁移：中央内容列居中、消息外层是扁平阅读流，用户与 Agent 的头像/名称/时间在同一行，正文与工具缩进对齐；不要恢复前段已被覆盖的消息外层卡片和头像样式。旧用户正文的 `--message-user-bg`、10px/12px 内边距和圆角未被后续规则覆盖，仍须保留。头像使用 HC-205，显示角色和作者文字由对话区负责。用户正文与 Agent 正文保持 14px/1.7 的阅读节奏。
- 原消息区、待处理交互区和输入区共享内容列，最大宽度和 Dock 开合时的整体定位由 HC-202/208 布局决定；窄窗口能收缩，不将旧 `.desktop-workspace` 三栏选择器复制进本区。时间线滚动容器有独立高度，审批区过长可独立滚动，不遮住输入框。
- 工具默认折叠为图标、标题、主参数、状态和常显展开箭头；失败有文字及图标，运行、完成状态也有可读标签。展开后输出与参数为同级详情卡，参数可再折叠；长输出受限高度并可“展开全部/收起”，展开后仍可在详情内滚动。文件、路径、搜索、Diff、终端等结构化显示在有相应视图值时保留原布局。
- 推理进行中保持状态与文本；旧 Timeline 对已结束推理默认不再显示。流式光标只出现在最后一个正在生成的位置，不能挂在其后已有工具或新消息的旧段上。时间线使用 `role=log`，状态/变化提供适当的可访问提示；减少动态效果偏好要生效。
- 输入的 `activity` 存在时，在时间线底部保留当前活动标签、可选阶段和已运行时长；活动期间可在所给时长基础上按秒更新显示，活动结束后停止计时。显示时长不证明远端设备仍在线或执行已经完成。
- 贴近底部时，当前可见对话的新内容跟随；用户上滚后保持阅读位置，先显示“回到底部”，有新内容时显示“有新输出”，显式点击后才回到底部并恢复跟随。原阈值为距底 48px，迁移时以实际滚动容器计算。

### 4.2 输入与菜单

- 输入框按原规则由一行增长至最多八行，超出后内部滚动；保留“聊天”标签、平面输入盒、焦点时整盒描边和发送/停止图形。颜色只引用 HC-205 语义变量。输入中的字符、换行与光标选择不因外部新消息被重置。
- 中文等输入法组合期间的 Enter 不发送、不选中菜单项；普通 Enter 发送、Shift+Enter 换行。命令菜单和文件提及菜单优先处理自己的方向键、Enter/Tab 与 Escape。Ctrl/Cmd+K 打开命令菜单；运行中输入框的 Escape 保留原“提示如何中断”语义，不静默取消。空闲、草稿为空且无浮层时的 Tab 模式切换只在调用方明确提供对应能力时生效。
- 命令和能力菜单保留可见/不可用原因、选中态及管理入口。模型/模式等下拉打开时焦点进入当前或首个可用项；上下/Home/End 在可用项间移动，Escape 关闭并还焦点给触发按钮，点击外部关闭。专有 Skill/模式的含义由扩展提供，通用组件不内建 Harness 菜单。
- 输入区允许调用方提供引用、附件和设备/排队状态的显示与动作；缺少能力时不制造可操作的假控件。引用只作为参考材料展示，不能冒充系统指令、静默刷新快照或自动改写用户原文。真实引用固定、权限复核与发送内容一致性仍由 HC-198/195 完成并验证。

### 4.3 审批与提问

- 待处理表单位于输入框上方，历史交互是只读记录。只显示调用方提供的决策；批准类动作先选择再提交，拒绝类是否可点击立即提交由提供的选项行为明确声明。拒绝并反馈时要求填写反馈，不能凭 UI 自行增加更宽的许可。
- 多题一次显示，单选用 radio、多选用 checkbox；选择“其他”时显示可编辑文字，必答项未完成或请求过期时禁用提交。`interactionId` 改变时不能携带上一请求的答案；等待结果时禁止重复提交，失败保留当前输入，处理结果由外部状态确认。
- 旧文件 Diff 审批展示路径、增删、行号、截断提示、左右/行内及 760px 默认切换；目录信任、计划行批注、Goal 审核等专有能力登记给扩展迁移。`preview` 插槽用于保留有审批按钮的通用外壳，完整表单插槽用于专有交互；不预先把旧协议结构写进通用分支。未装载扩展时不得显示仿佛支持该专有审批的按钮。

## 5. 文件提及与 HC-207/202 的交界

文件提及不属于右侧文件树布局。统筹已代表 HC-199 与 HC-206/207 裁定下列 UI 交界；实际服务契约和真实接线仍需对应任务完成：

1. 输入框在行首或空白后的 `@` 识别查询，支持未闭合引号中的带空格路径；邮箱中间的 `@` 不触发。命令菜单打开时优先处理命令。此处只解析用户正在编辑的文本，不读取文件正文。
2. `request` 至少包括本地请求序号、查询、当前浏览的相对目录和触发文本范围；`scope` 与 `target` 明确服务/身份域、账号、工作区、会话和原设备/项目。HC-202 从同一上下文为本区提供 `namespace/accountId/workspaceId/conversationId + deviceId/projectId`，并为 HC-207 提供 `namespace/accountId/workspaceId/deviceId/projectId`；不能按显示名或查看者本机路径猜测，两区也不相互导入整套状态。调用方返回有序候选 `{relativePath, name, kind, matchRanges}`、加载/空/错误/受限状态、可知的匹配总数及是否截断。`kind` 至少区分文件、目录和符号链接；这些只是显示值，不替代服务端路径校验。
3. 保留旧菜单最多八个可见候选、最多展示 1000 项及真实总数/截断提示的能力；空查询按当前目录浏览且目录在前，非空查询按文件名/路径相关度排序。上下键夹取、PageUp/PageDown 翻页、方向右进入目录、空查询方向左返回上级，鼠标 hover/滚轮及 Enter/Tab 选择保持一致。候选查询和排序由装配方/HC-199 提供；UI 不扫描查看者本机磁盘、不自建项目查询服务。未知总数不能伪称完整。
4. 选择目录只进入浏览；选择文件或符号链接时仅替换当前 `@` token，含空格路径使用引号，按原规则恢复输入焦点和光标。明确的“打开文件”动作才通过 `onOpenFile` 请求 HC-202：`preview` 调用项目侧右侧打开，`central` 调用中央激活；实际读取归 HC-199/196 的原设备项目端口。对话区不创建或管理文件页签，也不把候选选择等同文件读取。
5. 搜索结果须与当前 scope、原设备/项目、文本修订、token 范围、目录和请求序号相符；切换账号/会话/目标、移动光标或输入改变后，旧结果和旧错误不得覆盖当前候选。目标不可用时显示真实不可用原因，不退回查看者电脑同名路径。
6. 会话/消息引用也是 `@` 场景，后续由 HC-198/202 提供可选来源及固定快照；必须与文件候选的入口、分组和键盘优先级共同审查，不能让一个异步结果覆盖另一个。当前受控预览可直接注入引用显示项，不冒称已经接通搜索或快照服务。

## 6. 个人状态、隐藏与迟到结果

草稿和视图选择属于个人，不随共享消息广播。HC-206 定义本区个人状态及局部变更；HC-202 按 `namespace + accountId + workspaceId + conversationId` 保存和恢复，不能只按会话标题或路径索引。未选中会话时不把其他会话草稿当默认值；新建会话若需临时草稿，由装配方给出在该账号/工作区内稳定且独立的临时身份。

| 事件 | 草稿/光标、滚动与展开的规定 |
| --- | --- |
| 当前对话可见，新消息或流式更新 | 不重置草稿、选择范围或工具展开；贴底跟随与上滚提示按第 4 节执行。新增消息不能改变用户当前选中的菜单项或文件。 |
| 切到中央文件/轨迹页签 | 装配方保留已挂载的对话，并用 `hidden` 与 `inert` 隔离不可见交互；对话区记录隐藏前的滚动锚点、偏移、是否贴底和工具/输出展开状态，隐藏期间不抢焦点、不自动滚动。 |
| 回到对话或重新挂载 | 先按稳定条目恢复隐藏前的滚动锚点和偏移，再显示隐藏期间的新内容提示；即使之前贴底，也不因隐藏期间的消息强制改变原阅读位置。锚点不可用时使用最近可用位置并明确由装配方提供历史缺失状态。恢复草稿、光标及工具展开；只有用户主动回到底部或视口实际重新贴底后才恢复跟随。 |
| 切换会话/工作区/账号 | 先保存旧 scope 的个人状态，再只向组件提供新 scope 的状态；切回同一 scope 恢复自己的内容。旧 scope 的候选、发送、审批及其他异步结果不得写入新 scope，也不得将旧账号信息显示给新账号。账号码、工作区和会话相同的不同服务身份域仍须隔离。 |
| 同一会话的设备/项目目标变化 | 已输入的普通草稿不静默丢失；关闭并重新查询提及菜单，废弃旧目标的候选和在途结果。已有结构化文件引用须由装配方提示检查，不能悄悄改指新目标。 |
| 请求变更/删除、退出或关闭窗口 | 交互草稿按 `scope + interactionId` 隔离，新请求不能复用旧答案；退出先取消对旧身份的显示和订阅。组件卸载不能独占唯一草稿副本；跨应用重启持久保存是目标，由 HC-202 的账号隔离本地存储接入并单独验证，本受控 UI 停点只承诺当前预览会话内可卸载恢复。 |

个人状态至少包括草稿文本、光标/选择范围及单调修订号；按条目 ID 保存工具与长输出展开；保存滚动锚点、偏移和跟随状态；待处理交互另按请求 ID 保存选择与反馈。菜单开合和临时 hover 不必跨会话持久化。调用方处理 `onPersonalChange` 时只合并目标字段，避免一个迟到滚动事件覆盖已输入的草稿；发送确认还须比对完整 scope 与草稿修订号。组件自身不得把个人状态写入服务器或通过全局单例暴露给其他账号。
