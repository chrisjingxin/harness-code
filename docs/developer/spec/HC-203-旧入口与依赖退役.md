## 1. 背景痛点、解决思路与改后收益

### 1.1 现状痛点

当前仓库已完成独立桌面工作台核心链路的构建与合入（`HC-193`、`HC-194`、`HC-197`、`HC-200`、`HC-205`～`HC-208`、`HC-217`～`HC-220`、`HC-224`～`HC-229`），但早期 CLI/TUI/Web 架构的源码、第三方源码补丁、检查脚本和文档仍滞留在工作树中，带来四类明确问题：

1. **旧入口滞留**：`packages/cli/`（旧命令行入口、`OpenTUI` 终端渲染框架、独立本地 Web server、`PresentationCoordinator` 浏览器输入权接管状态机、`WebUiGateway` WebSocket 网关、`InteractiveController` 共享交互控制器及配套旧单测/E2E）与 `packages/protocol/`（`@za38/protocol` TypeScript 包与基于 `Ajv` JSON Schema 编译器的双端生成脚本）已无任何新桌面消费者，继续留存会误导贡献者与自动化检索。
2. **旧依赖与脚本混杂**：根目录仍保留 `third_party/npm/`（5 个用于旧窗口构建的 `OpenTUI` / `Bun` FFI / `React DevTools` 源码包，即 vendored 依赖）、`patches/`、`scripts/install/`（旧 `Bun` 与 CLI 一键安装脚本）、`scripts/e2e-pty.py`（旧终端伪终端测试脚本），以及把旧 `OpenTUI` 依赖校验与 `Python` 内核零 Anthropic 补丁混放在一起的 `scripts/dependencies/`。
3. **工程门禁滞后**：
   - `scripts/project/release.ts` 中的 workspace（工作区子包）路径校验正则 `/^(apps|packages)\/[a-z0-9-]+$/` 尚不支持 `packages/providers/{harness,pi,qwen}` 两级目录，导致当前 `npm run release:check` 与 `npm run project:check` 无法直接通过；
   - `scripts/project/docs.ts` 仍将已废弃的 `docs/user/交互使用.md` 列为必需文档，且未区分类别地对历史快照中的已退役路径链接做校验控制；
   - `scripts/workbench/check-boundaries.mjs` 尚未断言已退役目录不得回流。
4. **文档与看板口径残留**：`docs/user/` 目录同时存在文件名编码乱码的重复文件（`ä½¿ç”¨æŒŒå —.md`、`使用挌南.md`）以及废弃的 CLI/TUI/Web 使用文档（`使用指南.md`、`交互使用.md`、`Web界面.md`）；根 `AGENTS.md`、`README.md`、`CONTEXT.md` 与 `docs/developer/architecture/架构总览.md` 仍包含大量已退役的 TUI/Web/JSON-RPC 表现层描述；任务看板上仍有 `HC-179`、`HC-190`、`HC-191`、`HC-215` 等纯旧入口活动任务。

### 1.2 解决思路

本任务按“先保内核自治、再清旧包与 vendor（第三方内嵌源码包）、最后收口工程门禁与文档看板”的顺序执行退役：

```text
输入：存量目录、脚本、文档与任务清单
  │
  ▼
判断消费者归属：
  ├─ 新桌面 8 个 workspace 消费？ ──▶ 原位保留，纳入统一构建与边界检查
  ├─ 仅 Python Agent 内核消费？   ──▶ 内迁至 packages/agent/scripts/，更新相对引用与测试
  └─ 仅服务旧 CLI / TUI / 旧 Web？ ──▶ 列入退役清单
  │
  ▼
执行退役与门禁升级：
  ├─ 停点 1：内迁 Python 补丁脚本 → 删除旧源码/vendor/安装脚本 → 升级边界/发布/清理脚本
  └─ 停点 2：升级 docs:check 分层豁免 → 清理用户/核心架构文档 → 收口纯旧入口任务状态
  │
  ▼
输出：零旧入口回流、仅需 Node.js + npm 即可开发构建、Python 内核闭环自治、全门禁通过
```

### 1.3 改后收益

1. **目录与真实产品 1:1 对齐**：开发者进入仓库即见 `apps/desktop/`、`packages/workbench-*`、`packages/acp-runtime/`、`packages/project-service/`、`packages/providers/*` 与可选 Python `ACP`（Agent Client Protocol，代理客户端协议）内核 `packages/agent/`，不再被千行级废弃表现层干扰。
2. **默认工具链极简且防回流**：通用构建、类型检查与项目管理不再要求安装 `Bun`、`OpenTUI` 或 `Python`；边界检查自动拦截已退役目录与旧包依赖重新引入。
3. **Python 内核闭环自治**：`packages/agent/` 独立持有自身的内部通信生成文件（`harness_agent/protocol/`、`harness_agent/diagnostic_log/`）及零 Anthropic 补丁与校验脚本（`packages/agent/scripts/`），可在独立 Python 环境中单独运行和验证。
4. **文档与看板真实可信**：用户文档、架构说明与活动看板如实反映独立桌面协作工作台现状，同时保留历史过程记录的可追溯性。
