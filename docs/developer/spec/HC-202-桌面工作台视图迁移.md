正式 Electron 窗口目前可以登录和管理本机设备，但仍打开基础页。用户需要在同一窗口选择工作区和共享会话，阅读已保存的消息，再查看会话绑定的原项目。正式入口改为组合 HC-205～208 已交付的部件，沿用中央对话和右侧文件/变更的外观与操作。2026-11-11 统筹通过正式三栏首停点的规格，实施等 Plan/Todo 复核后派发。[HC-202 Task](../task/HC-202-桌面工作台视图迁移.md) · [总体设计第 10 节](../architecture/多人协作工作台顶层设计.md#10-ui-与现有功能) · [并行开发约定](../project/协作任务并行开发约定.md) · [Plan](../plan/HC-202-桌面工作台视图迁移.md) · [Todo](../todo/HC-202-桌面工作台视图迁移.md)

## 1. 正式窗口的装配

## 3. 共享历史如何进入正式对话

1. **确认范围。** 用户选中会话或恢复上次访问 → 用当前工作区读取概要 → 核对 `workspaceId/conversationId` → 按概要的 `deviceId/projectId` 绑定原项目。切换时先释放旧订阅；若选择被拒绝，只有仍有权限时才可保留并重新订阅旧会话。会话链接按总体设计走具名定位入口，校验配置服务域、目标工作区与当前账号权限后才定位；复制链接沿用宿主剪贴板。
2. **读完固定范围的历史。** 先读一页取得 `throughSequence`，后续页原样带该上界；按连续 `sequence` 应用事件，并用 `nextAfterSequence` 读下一页。游标使用十进制字符串，按精确整数比较。切换范围时丢弃旧结果；大历史允许分批展示加载进度。只有数据连续应用到上界后，才从该位置订阅 SSE。
3. **消费同一条事件链。** `message.created` 建立稳定消息 ID，`message.text.appended` 追加到同一条，`message.closed` 更新完成或中断状态；作者使用消息中的用户/Agent 身份。`execution.changed` 投影云端确认的排队、等设备和终态等事实，`conversation.created` 更新摘要。按权限可读的历史可独立于原设备在线状态展示。当前事件契约可供回放的是已保存文本与执行事实，结构化工具、审批、ACP 内容和实时 Trace 在对应契约到位后接入。
4. **以已应用的位置恢复。** main 负责 SSE 网络和校验，并为当前订阅暂留有界的一批待确认事件。renderer 同时只发起一次具名读取，核对订阅及范围，连续应用事件后才用新游标发起下一次读取。main 收到确认才释放对应事件；响应可携带连接状态，无事件时有界等待后返回。交付异常、积压超过上限或页面发现缺号时，停止旧流，用 renderer 最后连续应用的位置补读历史，再接新流。投影丢失或服务拒绝该游标超前时，经权限确认后从头重建。只忽略能核对为同一内容的重复；发现冲突时停止应用并补历史，已有投影无法核对时重建。概要、请求回执和心跳均不推进页面游标。
5. **按当前权限展示。** 首版只订阅当前会话；同一会话内切到中央文件页签时仍可消费事件，隐藏的对话不抢焦点。列表靠具名读取刷新。补充连接状态通知，覆盖现有客户端的正常流结束和重连成功，避免无新事件时一直显示在线或重连。短暂故障展示重连或可能过时，仍在当前授权范围内的已加载记录可继续阅读。401 由窗口的身份状态统一进入需重新登录，拒绝或失权时关闭相关流并隐藏受限内容；关闭窗口、退出、切换账号/工作区或选择另一会话时停止相应重连。旧作用域的回调、错误、缓存和通知不得覆盖新视图。

历史、投影与消费游标仅在当前认证窗口的内存保留，重开重新认证后从 history 恢复。云端已存历史与执行事实是共享真源。共享历史和项目读取分别服从各自服务的当前授权；共享历史是否增加 Git 平台权限仍在讨论，桌面按现有历史端口的真实许可接入。设备离线、项目共享或文件读取结果均不替历史端口作授权决定。[HC-195 历史与 SSE](HC-195-共享会话与实时同步.md#8-http-历史分页与-sse) · [Java 会话路由](../../../services/collaboration-server/src/main/java/workbench/collaboration/conversation/ConversationController.java) · [Java SSE 路由](../../../services/collaboration-server/src/main/java/workbench/collaboration/realtime/ConversationStreamController.java)

## 4. 个人视图和恢复规则

`namespace` 由宿主从配置的服务/身份域取得，不含凭据，也不加入 Java 协议。`accountId` 使用服务确认的用户 ID。下列个人记录由桌面装配统一持有，各部件通过局部回调更新各自字段。异步操作携带发起时的身份代次、完整作用域和请求顺序；失权、切换目标或更近请求取代后，旧数据与旧错误都不进入当前视图。

| 隔离范围 | 保存的个人选择 | 恢复规则 |
| --- | --- | --- |
| `namespace/accountId` | 上次选的工作区。 | 新登录后仅从服务返回的可用工作区中恢复。退出开始先隐藏旧账号视图，登录失败留在登录入口。 |
| 再加 `workspaceId` | 上次访问的会话、导航设备/项目展开、左右栏手动偏好与宽度。 | 复用已验证的选择。搜索、临时覆盖开合、菜单和弹窗为窗口内临时状态。右栏有项目时使用其个人偏好，无项目时使用工作区的布局默认值。 |
| `ConversationScope`，即再加 `conversationId` | 草稿文本、光标/选区与修订号；阅读锚点、偏移、跟随状态、工具/长输出展开；中央打开顺序和活动页签，文件项同时绑定其原 `ProjectScope` 与相对路径。 | 隐藏或重挂载时恢复原阅读位置和草稿。只有实际新增/更新的输出增加 `contentRevision`，保留同一内容生命周期的 `seenContentRevision`；切页、变主题和加载旧历史不增加版本。重建历史投影时先将已读版本设为 `null`，再由视图建立可比较基线。锚点暂未加载时待对应历史页到达后恢复，缺失时回到最近可用位置并提示。 |
| `ProjectScope`，即工作区下再加 `deviceId/projectId` | 右 Dock 开合/宽度、文件/变更面板、树展开/选择/滚动、右侧文件页签及活动路径、按路径保存阅读滚动、Git Diff 选择、勾选和说明。 | 会话切换到同一项目可恢复项目状态；换原项目不带入同名文件和 Git 选择。Git 勾选按路径和服务文件 `version` 关联，首次恢复或刷新后只保留仍相符项。中央和右侧的打开状态独立，同一作用域及路径可共用阅读结果。 |

同一会话的项目目标变化时，保留普通文本草稿，清掉旧目标的在途候选并重新查询；已有结构化文件引用提示检查，旧项目页签暂停展示，等待用户显式重新选择。文件候选仅修改当前草稿，显式打开才走右侧预览或中央页签动作。文件正文、Diff 与 Git 快照只按 HC-199 的授权范围在内存复用，旧内容在原设备断开时明确标为缓存；账号退出、切换或确认撤权时丢弃相应业务缓存。其他成员的消息/交接可以更新已有视图和提示，不能替用户切页、改草稿、移动阅读位置或改 Git 选择。

首个停点建立按作用域保存的窗口内状态。跨关窗与应用重启的目标是用 main 管理应用用户数据目录中的个人记录，提供按已登录作用域读取/保存的具名操作，目录位置由宿主决定。认证后且确认对应工作区、会话或项目可访问才恢复记录；同一作用域的保存顺序以最新修订为准，关闭窗口前保存最后可用状态，保存失败应能提示。磁盘保存的是个人输入、选择、阅读锚点等元数据，不保存业务历史/游标、文件正文、Diff 或凭据。审批与问答后续按完整会话作用域和请求 ID 保存选择、在途、结果未知与 `retryRevision`；只有业务确认可重新提交才更新 `retryRevision`，重连仅更新可用性。[对话个人状态](HC-206-既有对话视图复用.md#6-个人状态隐藏与迟到结果) · [项目个人状态](HC-207-文件与变更视图复用.md#41-个人状态)

停点四实施边界：主进程根据固定服务地址与已认证账号生成记录范围，分别读取账号、工作区、会话与原项目的个人记录；页面不能指定服务域、账号或存储路径。工作区须在登录结果中，会话读取须重新取得有权概要，项目读取须以该会话成功确认原项目。保存仅接受当前身份代次已确认的范围和闭合的个人视图字段，较旧修订不得覆盖较新内容；主进程合并待写入记录并以临时文件替换，关窗时等待最后的保存。恢复时先确认权限，文件正文与 Diff 再通过原项目端口重新读取。用户目录读写失败或关窗保存失败应显示原因并可重试，不把内存结果当作已持久化。

## 5. 窗口、页签与焦点

- **原生窗口与缩放。** 保留 macOS `hiddenInset`、Windows 标题栏按钮和托盘。正式布局的顶端为原生按钮留出空间，按实际平台、窗口和缩放检查边界。空白标题区可拖动，开合按钮、账号/设置入口、链接、输入、页签及独立关闭按钮、分栏拖宽手柄是可点击或可操作区。用户设置走现有 `DesktopHost.setThemeMode/adjustZoom`，保留 80%～150%、10% 步进和恢复 100%。以渲染后的可用逻辑宽度驱动 HC-208 布局，窄时先收右栏、再收左栏；内部独立滚动，高度随窗口变化。并排与临时覆盖通过 `WorkbenchRightSlot` 共用一个右侧开合/拖宽入口，覆盖操作和自动收起保留用户的并排偏好。[窗口配置](../../../apps/desktop/src/main/window.ts) · [原生动作](../../../apps/desktop/src/main/desktop-ipc.ts)
- **中央页签。** 「对话」常驻。文件按显式打开顺序增加，完整项目范围和路径相同则激活已有项。对话、已注册的可选扩展和文件共用一条页签栏及关联的内容面板。左右键、Home/End 在可见页签间移动焦点，Enter/空格激活，Delete 可关闭文件；关闭按钮有明确的可访问名称，点关闭只执行关闭。关闭活动文件后优先选相邻文件，最后一个关闭时回到先前的非文件视图或对话；若原焦点在被关闭项或其内容，移动到新的活动页签。关闭非活动项时保留当前活动项，只有焦点原在被移除项时才恢复焦点。右侧页签仍按 HC-207 的最近使用与数量限制独立处理。
- **隐藏、模态与焦点。** 同一会话下已打开的对话和文件面板保持状态，隐藏面板用 `hidden`/`inert` 或等效机制退出键盘与辅助功能导航。窄窗覆盖面板关闭或面板因尺寸被收起且其中有焦点时，回到对应触发按钮。设置保持居中，打开时焦点进入且背景不可交互，Tab 在弹窗内循环；Escape 先交当前最上层菜单或弹窗，关闭后回到仍可用的触发点。主题变化、缩放和新事件不重置页签、草稿或焦点；因收合需要转移焦点时按上述规则处理。
- **窗口生命周期。** 总体设计要求关窗进入后台，显式退出终止应用。关窗释放窗口身份和订阅，应用级 `RunnerSupervisor` 继续托管已启动的 Runner。macOS 通过应用入口、Windows 通过托盘重开，重新登录后按权限恢复已保存的个人视图。首个停点沿用现有宿主流程，Windows 无 Runner 时关最后一扇窗口仍会退出应用，后续原生停点修正，并纳入 HC-204 验证。显式退出沿用等待 Runner 停止的流程，停止未确认时显示实际结果。[应用生命周期](../../../apps/desktop/src/main/index.ts) · [布局组件](../../../packages/workbench-ui/src/layout/index.tsx)
