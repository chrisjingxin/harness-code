# HC-257 个人会话与目录整理规格

[任务](../task/HC-257-个人会话与目录整理.md)

## 1. 架构归属与核心原则

- **只在 `desktop/` 内**：`src/shared`（宿主接口）、`src/main`（本机会话存储、IPC、执行协调器、个人视图存储、代码检查点）、`src/preload`、`src/ui/navigation`（左栏视图）、`src/renderer`（个人会话 hook 与装配）。不改 `contracts/`、`server/`、`packages/collaboration-client/`、`packages/acp-runtime/`。
- **目录只是视图**：目录分组由 `directoryPath` 自动聚合，不新增文件夹实体；整组操作 = 对组内每条会话各执行一次单条操作，每条独立成败。
- **归档可逆、删除不可逆**：归档只在本机元数据打标记；删除才清理数据。
- **运行中不可整理**：运行中的判断以主进程为准，渲染层只做置灰提示。
- **只处理个人栏可见的会话**：`shareStatus === "active"` 的会话只在团队空间展示，本规格的所有操作均不作用于它们。
- **不写迁移分支**：新增字段是可选字段，缺省即“未归档/未置顶”，旧 `index.json` 无需迁移。

## 2. 数据模型

`LocalConversationRecord`（`desktop/src/shared/local-conversations-host.ts`）新增两个可选字段：

| 字段 | 含义 | 约束 |
|------|------|------|
| `archivedAtMs?: number` | 归档时间；缺省表示未归档 | 有限数值；与 `pinnedAtMs` 不同时存在 |
| `pinnedAtMs?: number` | 置顶时间；缺省表示未置顶 | 有限数值；仅 `shareStatus !== "active"` 且未归档时可设置 |

不变量：

1. 归档与置顶都**不修改** `updatedAtMs`，不改变会话在目录分组内按最近更新排序的位置。
2. 归档时自动清除 `pinnedAtMs`。
3. `LocalConversationStore.appendTurn` 一旦写入新轮次，就清除 `archivedAtMs`（有新活动的会话视为已恢复）。
4. `isRecord` 校验对两个字段为“缺省或有限数值”，其余字段校验不变；索引 `version` 仍为 `1`。
5. 单账号 500 条上限（`MAX_LOCAL_CONVERSATIONS_PER_ACCOUNT`）包含已归档会话，释放容量只能靠删除。

## 3. 宿主接口与 IPC

`LocalConversationsHost` 新增三个方法，`remove` 语义收紧：

```ts
setArchived(conversationId: string, archived: boolean): Promise<CollaborationResult<LocalConversationRecord>>
setPinned(conversationId: string, pinned: boolean): Promise<CollaborationResult<LocalConversationRecord>>
revealDirectory(conversationId: string): Promise<CollaborationResult<null>>
remove(conversationId: string): Promise<CollaborationResult<null>>   // 增加运行中与 local_only 校验、本机清理
```

IPC 通道（经 `ipc-guard.ts` 校验来源，参数使用既有 `isUuid`）：

| 通道 | 参数个数 | 渲染层方法 |
|------|----------|-----------|
| `workbench:local-conversations:set-archived` | 2（会话 ID、boolean） | `setArchived` |
| `workbench:local-conversations:set-pinned` | 2（会话 ID、boolean） | `setPinned` |
| `workbench:local-conversations:reveal-directory` | 1（会话 ID） | `revealDirectory` |
| `workbench:local-conversations:remove` | 1 | `remove`（已有通道） |

### 3.1 语义与错误

“运行中”（busy）定义：记录的 `status` 为 `running` 或 `waiting_approval`，**或** 执行协调器报告该会话有进行中的轮次。

| 操作 | 条件 | 结果 |
|------|------|------|
| `setArchived(true)` | 会话不存在 | `RESOURCE_NOT_FOUND` |
| | busy | `EXECUTION_STATE_CONFLICT`，“会话正在运行，请先停止后再归档。” |
| | `shareStatus === "active"` | `INVALID_REQUEST`，“已发布到项目的会话请在团队空间处理。” |
| | 已归档 | 幂等成功，原样返回 |
| | 其余 | 写 `archivedAtMs = now`，删除 `pinnedAtMs`，不改 `updatedAtMs` |
| `setArchived(false)` | 未归档 | 幂等成功 |
| | 已归档 | 删除 `archivedAtMs`，不改 `updatedAtMs` |
| `setPinned(true)` | 已归档 | `INVALID_REQUEST`，“已归档会话不能置顶。” |
| | `shareStatus === "active"` | `INVALID_REQUEST`，“已发布到项目的会话请在团队空间处理。” |
| | 已置顶 | 幂等成功 |
| `setPinned(false)` | 未置顶 | 幂等成功 |
| `remove` | busy | `EXECUTION_STATE_CONFLICT`，“会话正在运行，请先停止后再删除。” |
| | `shareStatus !== "local_only"` | `INVALID_REQUEST`，“该会话在团队侧仍有记录，暂不能删除。” |
| | 其余 | 删除记录与正文，再执行第 4 节清理 |
| `revealDirectory` | `directoryPath` 为 null | `INVALID_REQUEST`，“该会话尚未绑定目录。” |
| | 目录不存在或不是目录 | `RESOURCE_NOT_FOUND`，“目录不存在或已被移动。” |
| | 系统打开失败 | `INTERNAL_ERROR`，“无法打开该目录。” |

`revealDirectory` 的路径只来自主进程读取的本人会话记录，渲染层不传路径；打开动作通过可注入函数 `revealPath(path): Promise<string>` 实现（生产实现为 Electron `shell.openPath`，返回空字符串表示成功），以便单元测试替换。所有新方法都在 `LocalConversationStore` 的账号串行队列内执行。

## 4. 删除时的本机清理

顺序：校验 → `store.remove`（权威写入）→ 尽力清理（清理失败不使删除失败，但吞掉的错误不得影响其他清理项继续执行）。

| 清理项 | 位置 | 做法 |
|--------|------|------|
| 会话记录与正文 | `index.json`、`conversations/<id>.json` | 已有 `store.remove` |
| 个人视图文件 | `PersonalStore` 的 `conversation`、`sessionWorkspace`、会话待发队列 `prompt-queue-*` 三类文件及内存缓存 | `PersonalStore` 新增 `removeConversation(accountId, conversationId)`：文件名只由来源、账号、类型、会话 ID 计算（与 `workspaceId/projectId` 无关），无需再做归属授权；清除内存 `#entries` 与授权缓存 |
| 待上传队列 | 协作上传账本 | 仅当记录曾有 `workspaceId/projectId` 时调用已有 `uploads.cancelConversation`（沿用现有逻辑） |
| Agent 绑定、上下文会话、待发队列、代码检查点 | 执行协调器 | 协调器新增 `forgetConversation(scope)`：释放该会话的全部绑定（走既有 `release`，其中已包含 `contextSession.release`）、清除其待发队列、调用 `CodeCheckpoints` 新增的按会话清理，只删本会话作用域下的数据 |
| **不清理** | 用户磁盘目录（含用户 Git 仓库内的 `refs/workbench/checkpoints/*` 引用）、目录授权、`LocalImageStore`、Agent 自己的本机历史 | 目录授权按目录而非会话授予；图片按账号级目录存放留待孤儿回收；清理用户仓库内的引用需要在用户磁盘上执行 Git 命令，属于已知限制，不在本任务内处理 |

`set-archived` 的 busy 校验只对“归档”（`archived === true`）生效；取消归档不受 busy 限制，因为已归档会话被继续发送后，在该轮完成前记录仍是已归档状态，用户必须能随时取消归档。

协调器新增两个窄入口：

```ts
hasActiveTurn(accountId: string, conversationId: string): boolean
forgetConversation(accountId: string, conversationId: string): Promise<void>
```

`bindLocalConversationsIpc` 增加可选依赖 `cleanup?: { isBusy(accountId, conversationId): boolean; forget(accountId, conversationId): Promise<void> }` 与 `revealPath?`，由 `collaboration-ipc.ts` 用协调器与 `PersonalStore` 组合后传入；未提供时（例如单测）不做对应检查与清理。

## 5. 渲染层模型

`partitionPersonalRecords` 返回值扩展为：

```ts
{
  pinned: readonly LocalConversationRecord[]      // 未归档且有 pinnedAtMs，按 pinnedAtMs 倒序
  personal: readonly LocalConversationRecord[]    // 非 active、未归档、未置顶，用于目录分组
  archived: readonly LocalConversationRecord[]    // 非 active 且有 archivedAtMs，按 archivedAtMs 倒序
  publishedCount: number                          // active 数量，语义不变
}
```

`groupPersonalRecordsByDirectory` 保持不变，只接收 `personal`。`personalPartition` 同步返回 `pinned` 与 `archived`。

### 5.1 复制为 Markdown

纯函数 `conversationToMarkdown(title, turns, options)`（放在 `personal-sessions-model.ts`）输出：

```text
# {会话标题}

> 早期轮次已折叠或省略。            ← 仅当 detail.historyTrimmed

## 用户
{userText}
附件：{label}、{label}              ← 仅文件名/label，不含 path
[图片 ×N]                           ← 有图片时

## 用户（追加）
{followUp.text}                     ← 每条追加一个小节，按时间顺序

## 助手
{reply}                             ← reply 为空则省略本节
（本轮已停止）/（本轮失败：{failure}） ← status 为 cancelled / failed 时追加
```

规则：按 `sequenceStart` 升序；不输出工具调用与 `referenceIds`；各节之间空一行；末尾单个换行；绝不包含任何绝对路径（附件只写 `label`）；进行中的轮次不属于已定稿 `turns`，天然不包含。

### 5.2 在此目录新建会话

`usePersonalSessions` 的 `startNewDraft` 扩展为 `startNewDraft(init?: { directoryPath?: string; providerId?: string | null })`：

- 先清除 `selectedConversationId` 与 `createError`（现有行为），再把 `newDraft.directoryPath/providerId` 设为入参；
- 目录分组入口调用时，`providerId` 取该目录下最近更新且有 `providerId` 的会话；无则 `null`，由新建页现有逻辑回退默认 Agent；
- 目录失效的校验与报错沿用新建会话页现有逻辑，本任务不重复实现。

## 6. 左栏视图与交互

### 6.1 视图数据

`NavigationPersonalEntry` 新增可选 `pinned?: boolean`、`archived?: boolean`、`directoryLabel?: string`。`ProjectNavigationView` 新增：

```ts

archivedPersonal?: readonly NavigationPersonalEntry[]
personalIncludeArchived?: boolean
```

`ProjectNavigationActions` 新增（均为可选，未提供对应能力则不渲染相应菜单项）：

```ts

archivePersonalConversation?(conversationId: string): Promise<string | null>
```

约定：返回 `null` 表示成功，字符串为可直接展示的失败原因；成功后的提示（如“已归档「X」”“已删除 3 条会话，跳过 1 条运行中会话”）由 hook 通过现有 `onNotify` 提示，视图层不自行弹 toast。

### 6.2 区域与排列

个人栏自上而下：

1. **置顶**：`pinnedPersonal` 非空时显示，块标题“置顶”，行内沿用 `PersonalSessionRow`，行下方小字展示 `directoryLabel`，置顶会话不在目录分组里重复；
2. **我的个人会话**：现有目录分组，分组标题行右侧增加“更多”按钮；
3. **已归档 (n)**：`archivedPersonal` 非空时显示的可折叠区，默认折叠，扁平列表，每行显示标题、`directoryLabel` 与归档时间；
4. 底部“另有 N 个会话已发布到项目”提示保持不变。

搜索：个人搜索框右侧在存在已归档会话时显示“含已归档”开关（`aria-pressed`），默认关。搜索非空时：置顶与目录分组按现有规则匹配标题或目录名；已归档区仅在开关打开时参与匹配并展示命中项，开关关闭时整个已归档区隐藏。

“更多”按钮要求：目录分组标题行改为 `div` 容器，内含标题 `button` 与独立“更多” `button`（不得嵌套按钮），悬停或键盘焦点时可见，`aria-haspopup="menu"`。

### 6.3 菜单

个人会话菜单（自上而下，分组用分割线）：

| 条件 | 菜单项 |
|------|--------|
| 未归档 | 重命名、置顶/取消置顶 |
| 全部 | 复制为 Markdown；有目录时：复制目录路径、在文件管理器中显示 |
| `local_only` 且未归档 | 发布到项目…（现有） |
| 未归档 | 归档 |
| 已归档 | 重命名、取消归档 |
| 全部 | 删除（`danger`） |

置灰规则（`disabled` + `disabledReason`）：

- 归档、删除：会话 `status` 为 `running` 或 `waiting_approval` 时置灰，原因“会话正在运行，请先停止”（主进程仍会再次校验，渲染层提示以其返回信息为准）；
- 删除：`shareStatus === "stopped"` 时置灰，原因“该会话在团队侧仍有记录，暂不能删除”。

目录分组“更多”菜单：

| 菜单项 | 条件 | 行为 |
|--------|------|------|
| 在此目录新建会话 | 分组有 `directoryPath` | `newPersonalSessionInDirectory` |
| 复制目录路径 | 有 `directoryPath` | 取组内首条会话调用 `copyPersonalDirectoryPath` |
| 在文件管理器中显示 | 有 `directoryPath` | 取组内首条会话调用 `revealPersonalDirectory` |
| 归档整组 | 组内至少一条 | 打开确认，确认后 `archivePersonalGroup(组内全部 ID)` |
| 删除整组会话（`danger`） | 组内至少一条 | 打开确认，确认后 `deletePersonalGroup(组内全部 ID)` |

“未设置目录”分组没有前三项。

## 7. 批量操作语义（整组归档/整组删除）

在 `usePersonalSessions` 实现，按顺序逐条调用单条宿主方法，不并发：

1. 对每个 ID 取当前记录：已归档（对归档）、`active`（跳过）、运行中（跳过）、`stopped`（对删除跳过）归为“跳过”；
2. 其余调用宿主方法；失败计入“失败”，保留原状态，继续处理下一条；
3. 全部结束后 `reloadList()`；若所选会话被删除，选中项置为 `null` 并回到新建页；
4. 汇总提示：“已归档 X 条，跳过 Y 条，失败 Z 条”（为 0 的项省略）。全部失败时返回首个失败原因字符串让弹窗展示。

## 8. 单条删除后的渲染层收尾

`deletePersonalConversation` 成功后：从 `records`、`detailsById`、`personalRuntimes` 中移除该会话；若它是 `selectedConversationId`，调用 `startNewDraft()`；提示“已删除「标题」”。

## 9. 状态与异常

| 情形 | 行为 |
|------|------|
| 离线 | 所有本卡操作仅本机，不依赖协作服务，离线下均可用 |
| 未登录 | IPC 返回 `AUTHENTICATION_REQUIRED`（沿用） |
| 本机索引损坏 | 沿用 `CorruptStoreError`，返回内部错误，不覆盖原文件 |
| 清理阶段部分失败 | 删除仍算成功，失败项下次删除或应用启动无需特殊处理（残留文件不影响功能） |
| 并发 | 同账号所有写入走既有串行队列；批量操作串行 |

## 11. 验收（可观察结果）

对应 Task 验收，补充以下可核对项：

1. 归档后侧栏该会话消失、底部“已归档 (n)”展开可见、取消归档后回到原目录分组原位置。
2. 向已归档会话发送新消息并完成一轮后，该会话自动回到目录分组。
3. 运行中的会话，菜单中归档与删除置灰；绕过界面直接调用 IPC 同样被拒绝并返回“请先停止”。
4. 删除 `local_only` 会话后重启应用不再出现；`conversations/<id>.json` 与对应个人视图文件不存在；磁盘工程目录原样保留。
5. 已停止共享会话的删除置灰并写明原因，归档可用。
6. 目录分组整组删除弹窗显示条数与“不会删除磁盘目录”，勾选后才可确认；执行后分组消失，运行中与已停止共享的会话被跳过并在提示里体现。
7. “在此目录新建会话”打开的新建页目录已预填；“未设置目录”分组无此项。
8. 复制为 Markdown 粘贴后为“用户/助手”顺序，不含工具输出与绝对路径。
9. “在文件管理器中显示”打开该目录；目录被移走时显示“目录不存在或已被移动”，不崩溃。
10. 搜索框“含已归档”关闭时搜不到已归档会话，打开后可搜到。
