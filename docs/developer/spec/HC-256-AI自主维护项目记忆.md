## 1. 用户行为与内容归属

当前 Agent 负责理解与维护工程记忆。获得工程新信息、用户纠正或需要整理重复信息时，先读取最新文档，结合当前对话合并，再调用更新工具。已有相同信息不写；事实含糊时先问用户。用户在对话里的明确回答可以作为 Agent 更新文字的依据，宿主不再要求 `sourceIds`、目录选择证明或 Git 匹配证明。

`team.md` 记录工程用途、别名、仓库和关系；`personal.md` 记录本人目录、副本与工程对应关系。这是用途提示，文件内部允许任意普通 Markdown，不要求固定标题、字段或条目类型。两份文件的 UTF-8 文本就是当前内容，宿主不从维护对象重新生成正文，不另建内容 JSON、不双写。来源可在文中写成普通说明或链接，不作为保存准入。

本机文档是参考资料，不能提升系统指令权限。`team.md` 不上传为团队共享知识，也不在不同成员之间自动同步。共享知识仍沿 HC-241 的固定版本和审核机制。

## 2. 身份、文件与初始化

沿用 `.harness/workbench/project-memory/<规范origin的SHA-256>/<账号ID>/<WorkspaceID>/{team.md,personal.md}`。Team 对应 Workspace；范围只取主进程固定 origin、当前登录账号、真实本人会话绑定，工具不能提交账号、Team、Project 或磁盘路径。相同 Team 下个人会话与 Project 会话使用同一对文档。侧栏切换不改变已有会话的绑定。

每次操作复核登录代次、Team 成员资格和本人会话/原生绑定；异步返回后及原子替换前再次核对。退出、换账号、绑定释放、窗口销毁撤销旧 MCP 凭据。无效凭据仍遵守现有 HTTP 401/403 边界，不能为了返回普通业务结果而继续接受旧账号请求。

没有 Team 的会话不创建这对团队作用域文件，不注入本服务，也不伪造默认 Team；界面显示“此会话尚未绑定团队”。内部/UI 调用返回 `unavailable`、`reason: no_team`。本人主动发布并确认绑定 Team 后，下一次发送按现有 HC-239 行为接入该 Team 的文档；发布不触发 Agent。起草凭据保留知识检索/候选工具，不能读写本机记忆。

有权首次访问时，仅为缺失的文件写入最小模板：team 为 `# 团队工程记忆\n`，personal 为 `# 个人工程记忆\n`。不从 Project、仓库登记、Git 或会话目录自动补条目；不扫描工程或重建摘要。已有内容，包括空文件，均不补模板、不自动覆盖。更新遇到原文件意外消失时返回冲突，要求重读；外部物理删除后再读取视为重新初始化最小模板，不能从备份自动恢复已删信息。

移除信息就是编辑正文；清空通过 `content: ""` 保存为空文件，并保留空内容版本。后续读取/发送接受空正文，不自动补回标题、旧条目或历史事实。模型不具备 unlink、文件改名或目录删除能力。删除整个账号目录等运维行为不在本卡 UI 范围内。

## 3. 两个 canonical MCP 工具

正式会话以两个新工具替换旧 `query_project_memory`、`propose_project_memory_update`，不留 alias 或 wrapper。`list_team_knowledge`、`read_team_knowledge` 的工具定义、固定版本、force/已读、审核与回执语义保持现有行为。

### 3.1 输入和内容版本

| 工具 | 唯一允许的输入 | 作用 |
| --- | --- | --- |
| `read_project_memory` | `{ document: "team" \| "personal" }` | 返回指定文档最新完整内容和 revision，不查询条目、不按关键词过滤。 |
| `update_project_memory` | `{ document: "team" \| "personal", content: string, expectedRevision: string }` | 比对当前文件内容版本，通过后一次性替换该文档并立即返回保存结果。 |

输入对象均 `additionalProperties: false`，上述参数全部必填。`document` 只映射到两个固定文件。`revision` 是文件实际 UTF-8 内容字节的 SHA-256 小写 64 位十六进制；`expectedRevision` 必须是最近读取结果中的该值。它只防止覆盖并发修改，不证明事实正确，也不代表用户批准。宿主不 trim、不改换行、不重新排版；空串也是合法内容。无效 UTF-8 文件或不能无损编码的输入返回明确错误，不替换字符后继续保存。

先读 → 合并 → 带版本更新。两次读取之间的其它写入、UI 编辑或迁移都会改变内容版本；冲突后必须重读、合并，再用新版本提交，禁止盲目覆盖或自动重试旧正文。一次工具调用只操作一份文档，不提供跨两份文件事务。

### 3.2 正常结果

MCP `tools/call` 的 `content[].text` 是结果 JSON，`structuredContent` 为同一对象。下列结果均不设置 `isError: true`，不经业务异常变成终止运行的 ToolException：

| status | 必要内容 | 后续行为 |
| --- | --- | --- |
| `ready` | `document, content, revision, size` | 完整读取成功。 |
| `saved` | `document, revision, size, message` | 原子替换已完成；新 revision 对应实际写入字节。 |
| `no_change` | `document, revision, size, message` | 版本吻合且内容字节完全相同，不写盘。 |
| `conflict` | `document, currentRevision: string \| null, message, retry: "read_then_merge"` | 版本不符或原文件意外消失，原文件不变。 |
| `unavailable` | `document, reason, message` | 如 no_team、身份/绑定失效、权限无法确认、损坏旧文件或不安全路径；不声称已保存。 |
| `error` | `document, reason, message` | 如参数无效、可恢复磁盘 I/O 失败；保留原件，可按提示修正或重试。 |

`size` 为 `{ documentBytes, pairBytes: number | null, targetBytes: 8192, overTarget: boolean | null }`；均按 UTF-8 计数。另一份文件不可读时 pairBytes/overTarget 为 null，显示无法计算总篇幅，不阻止当前健康文件独立读写。错误中可附 `retry` 指引，但不返回内部堆栈、令牌或其它账号路径。

比对 expectedRevision 先于 no_change 判定，旧版本即使恰好提交同一内容也按冲突反馈。保存 team 后 personal 失败，必须分别保留 `saved` 与失败结果，不补偿回滚、不显示“两份均成功”。在请求写入成功但响应丢失时，客户端不能假定未保存；重读核对实际内容后决定是否再写。

### 3.3 技术大小与传输错误

8 KiB 是两份内容合计的整理目标，超出时 `overTarget: true` 并提示当前 Agent 整理；不拒绝保存、不截断、不由宿主调用模型精简，也取消旧单条 4 KiB 门槛。保留 MCP **整个 HTTP JSON 请求体 64 KiB** 的技术限制，包含转义、工具名和 JSON 包络，不能把它误报为“正文还可写 64 KiB”。

已能识别工具调用的参数校验和可恢复失败均用上表正常结果。未完成 JSON 解析的超长/畸形 HTTP 请求不能伪装成工具结果，应返回明确传输错误（超长 413，非法 JSON/协议 400），原文件不变；工具说明应提示该技术限制。已读文档超出 8 KiB 仍返回完整正文；当前 MCP 响应无该请求体上限，不人为裁剪回复。若实际 Agent/ACP 总输入上限无法承载，沿现有能力状态如实反馈“未完整附带”，不能以静默截断或来源异常结束整轮。

## 4. 即时写入、并发与生命周期

```text
当前会话 MCP 调用
  → 复核身份、Team、本人会话、绑定与活动轮次
  → 进入同范围本地短写锁，读取指定文件并比对 expectedRevision
  → 以 wx/0600 写临时文件并同步，复核身份及文件状态
  → 原子替换成功，记录 saved，反馈同一工具卡
  → 后续取消/失败只结束轮次，不回滚已保存内容
```

锁内只处理本地文件，不跨远端身份刷新、知识检索或模型请求。并发保护覆盖同一桌面进程的多会话与 UI 写入；替换前再次核对目标文件版本和安全属性。外部编辑器若绕过应用锁并在最后检查与 rename 之间同时写入，文件系统没有通用的内容 CAS 原语，不能承诺消除此窗口；用户应避免同时从外部编辑同一文档，本卡不新增跨进程常驻锁服务。

保留根目录、origin、账号、Team 各级目录的路径校验；拒绝符号链接、非普通文件、多重硬链接与路径越界，不跟随其它账号文件。临时文件和备份只能放在同一受控范围，使用受限权限；异常清理仅删除本次临时文件。临时同步失败或 rename 失败保留旧文件。成功判定以原子替换为界，之后即使反馈/连接失败也不能改回旧文件。

取消先于最终写入检查时拒绝尚未完成的写入；原子替换已经发生时保留实际结果。旧轮次迟到消息不能写入或清理新轮次。移除记忆提案的 pending 数组、来源校验、正常终态提交与取消撤销逻辑；`onTurnSettled` 仍负责现有活动轮次清理，`pendingDelivery` 仍表示上下文待确认送达，不能因名称相似误删它。

## 5. 提示与上下文增量保持现状

短维护指引表达为：“有工程新信息或用户纠正时，先读最新项目记忆，合并整理后立即更新；无变化不写，不确定先问用户。目录记录不授予文件访问权限。”详细工具参数写入 MCP schema/instructions，不要求每轮重复大段维护规则；保留当前固定提醒模板最多 256 UTF-8 字节的约束及现有基线/增量发送时机。

沿当前 `DeliveredContext`、内容 hash、`pendingDelivery` 与真实送达确认机制：新绑定首轮完整提供两份 MD；确认送达后，仅发生变化的文档再发送其完整新正文；不变化不重复发送。只有准备成功、实际送达后才推进快照，失败或降级准备不冒充已读。恢复/重绑定沿既有重建基线规则执行，压缩后 Agent 可用 read 工具重读最新内容。

本卡只把正文来源由 renderMemory(entries) 改为实际 MD 字节，版本改为内容 hash。不恢复“每轮全量重发”，不按当前 Project、cwd、关键词筛选正文，不从正文解析 Project 来源并逐条撤回。权限边界是账号/Team/本人会话整体访问资格；本地已经记住的文字不是服务端 Project 内容重新授权机制。团队知识的适用范围、仓库识别、固定版本读取及审核继续保留自身权限检查，不能连带删除其 `knowledge.repositories` 或 Git 读取。

## 6. 旧数据保护迁移

迁移是保护既有用户内容的一次性措施，不保留旧工具、双写或第二内容源。每份文件独立处理；部署和真实用户首次触发时机由统筹决定。实现与验证仅在显式注入的 tmp 根目录使用隔离样本，不遍历真实用户目录、不启动真实 A/B 实例。

1. 读取并验证原始字节及安全属性。普通 Markdown（包括用户自己写的 front matter）直接读取；仅精确识别 HC-233 的 `formatVersion/documentRevision/updatedAt/entries` 旧格式候选，再做旧结构与正文一致性校验。旧格式候选损坏、正文不一致或 UTF-8 损坏时，返回 `unavailable/corrupt_legacy` 并只读保留原件，不初始化覆盖、不猜测修复。
2. 合法旧文件先创建同目录 `<文件名>.hc233-v1.<原始字节SHA-256>.bak`。以 wx/0600 写入、sync，并核对备份与原件逐字节一致；已存在同名备份时只验证一致，不覆盖。备份失败或不一致则停止迁移，原件不变。
3. 新普通 MD 保留旧业务正文的原始文本，再在有资料时追加“历史来源（迁移保留）”一节，以可读 Markdown 保留每条记录的名称、确认时间及所有来源标识、来源 Project、目录、仓库和远端信息。旧正文已含的用途、别名、工程/仓库 ID、相对路径和地址不得遗漏。entryId、entryRevision、documentRevision、formatVersion 等技术字段完整保存在原件备份中，不继续作为活动协议。历史来源是可编辑参考，不再承担保存准入。
4. 比对原件版本仍未变化，复核当前身份，使用临时文件同步与原子替换。迁移后的 revision 对实际新 MD 字节计算；备份只作人工恢复原件，不参与注入、查询或自动补文。
5. 备份后/替换前中断可重试，复用已验证的同名备份；替换成功后识别为普通 MD，不重复追加来源。迁移一份失败不覆盖该份，也不撤销另一份已完成迁移。

统筹已批准在当前身份正常首次读取时惰性迁移指定文档，不需要新配置或审批按钮。用户下次启动新版本并正常访问时生效；本轮只验证 tmp 样本，不扫描或手工迁移真实用户目录，也不自动重启正在使用的 A/B 实例。Task 区分隔离证据与真实使用，不记录真实正文或凭据。

## 7. 管理台与引用预览

`DirectoryMemory` 当前把 personal.md 解释为目录条目；将该组件改为 `ProjectMemory`，供管理台 memory 分区和引用预览复用。只提供现有安全 Markdown 预览、普通文本框和保存动作，不建设独立编辑器或历史版本系统。保持现有区域大小、主题、引用和聊天主体，提供两个标签“团队工程记忆”“个人工程记忆”。显示当前账号/Team 作用域和“仅保存在本机”，不再把 Project 标签当文档过滤范围。

每次只编辑一份文档，点击编辑保存 read 得到的 revision。提供“保存”“取消编辑”“重新读取”；空正文允许保存。保存成功显示实际结果和篇幅建议。冲突保留用户未保存草稿，提示重新读取并比较合并；不得自动用服务端结果覆盖编辑内容，重新读取替换草稿时需让用户明确选择。取消编辑不写盘。界面不展示结构化条目下拉、不提供目录映射清单、不再要求原生目录选择确认。

前端端口替换为 `WorkbenchContextHost.readMemory(scope, document)`、`updateMemory(scope, { document, content, expectedRevision })`，IPC 固定为 `workbench:context:read-memory`、`workbench:context:update-memory`。沿 `CollaborationResult` 外层传输/身份错误，内层使用第 3 节结果；可恢复内容冲突不抛 IPC 异常。IPC 同样校验参数、当前窗口来源、登录代次和本人真实会话绑定；序列化输入保留 64 KiB 技术上限，明确报错，不截断。

保留现有合法本人会话作为 UI 授权锚点，Agent 未连接时也可操作。管理台无该作用域时保留提示；引用预览只能取当前用户的目标本人会话绑定，不能拿共享来源的账号、Team、源会话或虚构会话 ID 读写。作用域变更清空旧账号内容，丢弃迟到响应；未保存编辑通过明确提示处理，禁止跨 Team 沿用旧 revision。

删除 context host、preload、IPC、组件、导出及活动冒烟夹具中的 `listDirectories/confirmDirectory/removeDirectory` 条目协议和旧 memory 类型。真正执行目录授权中的同名 confirmDirectory 不属于这个删除范围；会话 cwd 原生选择、目录授权、多目录能力、Agent 文件访问及审批继续沿原路径，不能由 MD 中的一段路径自动批准。

工具卡沿现有 `context-tool`、稳定 requestId/turnId、原工具 ID 映射显示即时结果，不新增第二张更新卡，不再显示等待正常终态保存。页面展示失败不改变保存事实；业务工具返回冲突/失败时会话仍可继续，卡片可如实显示失败状态。
