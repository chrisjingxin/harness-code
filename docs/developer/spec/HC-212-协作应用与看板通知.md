# HC-212 协作应用与看板通知

## 停点一 会话快照

项目成员需要固定一段云端已同步的会话材料，用于预览和再次引用。一次创建分配一个新快照 ID，随后按该 ID 读取当时固定的正文、来源和范围。对方继续上传时，旧快照仍使用创建时的材料。刷新材料需要再次创建。

用户会话 → 校验工作区、Project 和当前成员 → 确认来源会话归属 → 以已确认同步序号为上界取材 → 检查 UTF-8 字节并计算 SHA-256 → 保存并返回快照。仅使用 HC-211 的正文读取与简报；无新的会话索引依赖。相关设计见 [Java 中继方案 §3.2、§4.4 和 D5](../project/Java中继调整方案.md)。

### 接口

基础路径为 `/api/v1/workspaces/{workspaceId}/projects/{projectId}/snapshots`。创建使用 POST（按现有用户会话和 CSRF 认证），返回 201。读取使用 GET `/{snapshotId}`，返回 200。两个成功响应的 `body` 都是同一个 `SnapshotResponse` 形状。创建返回的正文可直接用于预览。

请求必填 `sourceConversationId`。省略 `range` 时取最近最多 20 条。指定 `range` 时仅可使用以下一种形状，序号从 1 开始，区间包含两端。

| range | 取材方式 |
| --- | --- |
| `{"type":"latest","count":20}` | 从当前已确认序号向前取最多 count 条。count 可省略，允许 1–500。 |
| `{"type":"through","toSequence":5}` | 取 1 到 5。 |
| `{"type":"range","fromSequence":2,"toSequence":5}` | 取 2 到 5。 |
| `{"type":"brief"}` | 取已同步简报。 |

消息按序号升序固定为纯文本，每段格式为 `[序号 消息类型]\n原始 payload`，两段之间用两个换行分隔。定稿消息和工具摘要沿用同步时的载荷文本。简报快照直接使用简报文本，消息数为 0，起止序号均为 null。快照 ID 是引用版本标识。返回固定的来源会话标题、所有者、读取时的确认序号和同步时间。消息快照的同步时间沿用来源头最近更新时间，简报快照使用简报更新时间。

每次读取校验当前项目成员和快照所属 Project。非成员、跨工作区、跨项目来源或快照均返回 404。归档项目可读取旧快照，创建返回 409。反向区间或终点超过已确认同步序号返回 400。没有可取的消息或简报返回 409 `SNAPSHOT_EMPTY`；已确认范围缺段时返回 503 `SERVICE_UNAVAILABLE`，避免选中区间被静默缩短。

### 大小与持久化

正文最多 65,536 UTF-8 字节。保存完整正文及其 SHA-256 小写十六进制摘要。读取仍使用该记录，支持来源继续上传后逐字段一致。DDL 为对象存储预留 `storage_uri`。当前仓库无可用对象存储端口，超过上限返回 413 `SNAPSHOT_TOO_LARGE`，保留原始消息，且该请求不生成快照。对象存储接入和超限引用读取仍待补齐。正文为不可信参考材料，桌面预览和后续引用沿用同一份快照。

### HC-219 联调示例

在演示 Project 中准备一条已同步的来源会话。用登录会话及 CSRF 凭据向快照集合 POST。以下会话 ID 与响应取自一次隔离库冒烟，联调时用自己的来源会话 ID。

```json
{
  "sourceConversationId": "448d65eb-bc78-4294-8324-49492556fa3e",
  "range": { "type": "range", "fromSequence": 1, "toSequence": 2 }
}
```

成功包络示例。其材料与省略范围、来源当时仅有两条消息时相同。

```json
{

  "errorMsg": "",
  "body": {
    "snapshotId": "e6c2df43-475a-4597-b454-e42024a6b2c1",
    "projectId": "00000000-0000-4000-8000-0000000000a1",
    "sourceConversationId": "448d65eb-bc78-4294-8324-49492556fa3e",
    "sourceOwnerUserId": "000000000000400080000000000000d1",
    "sourceTitle": "HC-212 会话快照",
    "sourceSyncedSequence": 2,
    "sourceSyncedAtMs": 1794880406236,
    "fromSequence": 1,
    "toSequence": 2,
    "messageCount": 2,
    "text": "[1 user]\n核对账单\n\n[2 tool_summary]\n{\"toolName\":\"read\",\"summary\":\"已核对\"}",
```

草稿和历史用 `snapshotId` 保存引用，恢复时在同一 Project 的集合路径后带上该 ID 发 GET。显示时使用 `sourceTitle`、通过项目成员资料解释 `sourceOwnerUserId`、格式化 `sourceSyncedAtMs` 和序号范围，正文直接使用 `text`。刷新使用同一来源重新 POST，读取已固定材料使用 GET。404 表示该材料对当前调用者不可用。413 的错误包络返回 `returnCode=CLB3010` 和 `body.code=SNAPSHOT_TOO_LARGE`。

## 停点二 产品任务

以当前 Task 的五态为准。早期中继草图里的拒绝、阻塞等状态由该五态流程取代。Project 成员可发布给一位有效成员。发起人也是验收人，受让人是执行人。归档项目允许成员回查。所有改动要求项目 active，保存者始终重新检查项目和身份。

| 当前状态 | 动作 `targetStatus` | 操作者 |
| --- | --- | --- |
| `todo` | `doing`（接收） | 受让人 |
| `doing` | `review`（提交验收，可附说明和提交） | 受让人 |
| `review` | `done` 或 `todo`（验收或退回） | 发起人 |
| `todo/doing/review` | `cancelled` | 发起人 |

项目路径下 `POST /tasks` 使用 `title, description, assigneeId, requestId, snapshotIds?, knowledgeRefs?`，版本由 1 开始。材料只保存固定 ID，快照须属同 Project，知识版本须属同 Workspace 且条目当时有效。该版本通过原快照和知识版本接口回读。重复材料和未知材料分别返回 400、404。

- `GET /tasks?status=&assignee=me&creator=me&afterId=&limit=` 按 ID 顺序分页。列表返回摘要及 `nextAfterId`，详情 `GET /tasks/{taskId}` 返回固定材料、提交标识和逐次流转审计。
- `PATCH /tasks/{taskId}` 使用 `description, expectedVersion, requestId`，限发起人且任务为 `todo`。
- `POST /tasks/{taskId}/transitions` 使用 `targetStatus, expectedVersion, requestId, note?, commitSha?`。仅提交验收时允许附 40 或 64 位十六进制提交标识。审计记录操作者、版本、起止状态、说明、提交及时间。
- `PUT /tasks/{taskId}/conversation` 使用 `conversationId, expectedVersion, requestId`。仅进行中的任务受让人可关联同 Project、本人所有的会话，每端最多关联一个。先走 HC-211 会话登记，再由任务入口登记双向关联。Java 保存关联、版本和审计，执行继续由受让人在自己的设备主动开始。会话状态、Agent 权限及跨设备只读边界沿用 HC-211。
- 写请求的预期版本通过数据库条件更新。状态边非法、版本已改变均返回 409，角色不符返回 403。请求编号在同项目同操作者下绑定到原路径和正文，重复请求返回原响应，冲突复用 409。最终响应、业务变更、关联及审计在同一事务保存。

## 停点三 团队知识

Workspace 成员可按分类建立条目，术语键在同一 Workspace 中唯一。创建与编辑生成新的固定版本 ID，旧版本正文和分类等元数据继续保留。

- `GET /knowledge?category=&q=&afterId=&limit=` 查有效条目。standalone 走 SQL 包含查询，cluster 关键词查询走 `wb_knowledge_v1`，以 SQL 当前团队、条目状态、版本和分类校验索引命中。无关键词的列表读 SQL。
- `POST /knowledge` 使用 `termKey, category, title, text`。术语键为 1–64 个小写英文字母、数字、点、横线或下划线，首位为字母或数字。重复键返回 409。条目标题、分类和正文为当前版本元数据。
- `GET /knowledge/{knowledgeId}` 读取条目及当前版本。 `PUT /knowledge/{knowledgeId}` 使用 `category, title, text, expectedVersion` 创建新版本。术语键保持固定。
- `DELETE /knowledge/{knowledgeId}?expectedVersion=2` 归档。继续允许成员访问历史，归档条目退出列表和新引用候选。 `GET /knowledge/{knowledgeId}/versions` 分页返回版本元数据， `GET /knowledge/{knowledgeId}/versions/{versionId}` 读取固定材料。桌面判断新引用资格使用条目或固定版本返回的 `archived`。
- 索引仅供候选检索。集群写索引使用版本防止旧更新覆盖新版本。模型引用仍由用户显式选择固定版本。

## 停点四 看板与通知

- 项目 `GET /board` 返回成员、最近会话简报和进行中的任务，每条会话关联心跳得出的设备在线状态。会话和任务各取最近最多 100 条，响应给出是否截断。按成员 ID 汇总收件和发件情况。
- Workspace `GET /notifications?afterId=0&limit=100` 及 `GET /notifications/stream?afterId=0`。SSE 可传 `Last-Event-ID`，优先于查询参数。响应事件含 `eventId, type, objectId, projectId, occurredAtMs` 及游标 `id`，SSE 的 `id:` 使用相同游标。客户端持久记录已处理游标，收到事件后按需拉详情。首次连接省略游标时从 0 补读。
- 任务事件发给发起人和受让人，快照、简报和项目成员变更发给当前项目成员，知识事件发给团队成员。排除操作者自身。读取时重新核对团队、项目和当前身份。正文留在具名读取接口。
- 业务事务与通知记录一并提交。每个事件按接收人去重，写入同一 Workspace 的游标按提交顺序增长。SSE 和分页共用持久游标，跨节点仍可补读。在集群模式 Kafka `wb.collab.notifications` 加速唤醒各节点，定时查看持久通知可覆盖断线或信号丢失。每条流有限时长并发心跳，断线后带游标重连。

### HC-219 任务和知识联调

POST 任务请求示例，路径为 `/api/v1/workspaces/{workspaceId}/projects/{projectId}/tasks`。ID 随登录用户、Project 和固定材料替换。

```json
{
  "title": "核对结算",
  "description": "对照固定材料核对汇总",
  "assigneeId": "000000000000400080000000000000d2",
  "requestId": "00000000-0000-4000-8000-0000000000a1",
  "snapshotIds": ["e6c2df43-475a-4597-b454-e42024a6b2c1"],
  "knowledgeRefs": [
    {
      "knowledgeId": "c06494ac-1ce2-40cb-8cea-71ff13325187",
      "versionId": "06d896cd-b165-479d-86ee-ccdf7fb4580b"
    }
  ]
}
```

创建成功包络的 `body.task` 给出 `taskId, status, version`。状态改变时用新的请求编号和上次读取的版本。接收与提交验收的 `targetStatus` 分别为 `doing` 和 `review`。一次请求超时后用同一方法、路径、编号和正文重试。需要展示任务材料时，按 `snapshotIds` 和 `knowledgeRefs` 回读原快照或原知识版本。

新建知识的 POST 正文可以为 `{"termKey":"billing","category":"术语","title":"结算","text":"结算是账单周期的汇总。"}`。从 `body.item` 取 `knowledgeId` 及 `currentVersionId`。查找候选用 `GET /knowledge?q=billing&category=%E6%9C%AF%E8%AF%AD`。展开已固定引用使用 `GET /knowledge/{knowledgeId}/versions/{versionId}`，正文在 `body.text`，版本元数据在 `body.version`。

### HC-220 看板和通知联调

首次打开项目时 GET `/api/v1/workspaces/{workspaceId}/projects/{projectId}/board`。用 `body.members[].conversationIds/receivedTaskIds/sentTaskIds` 和同一响应中的 `conversations/tasks` 渲染。成员的 `deviceOnline` 表示当前至少一台有效设备有心跳，会话上的同名字段表示其绑定设备。

桌面宿主复用当前用户 Cookie、Origin 和协议版本头连接 `/api/v1/workspaces/{workspaceId}/notifications/stream`，并设 `Accept: text/event-stream`。事件示例：

```text
id:57
event:task.assigned
data:{"id":57,"eventId":"03bada23-517a-4bea-9eb4-1dc42d40dc49","type":"task.assigned","objectId":"c5599241-c8c8-4fb4-8a74-560001c65c3f","projectId":"00000000-0000-4000-8000-0000000000a1","occurredAtMs":1794870000000}
```

处理后按账号与团队保存 `57`。连接关闭后以 `Last-Event-ID: 57` 续读，也可用普通 GET `/notifications?afterId=57` 补读，翻页使用 `nextAfterId`。忽略 SSE 心跳注释，以游标识别已经处理的事件。收到事件时可用 `type` 与 `objectId` 选择刷新目标，项目成员变更的对象 ID 是项目 ID。
