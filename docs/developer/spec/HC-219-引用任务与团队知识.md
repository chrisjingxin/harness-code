# HC-219 引用任务与团队知识

2026-11-13 Spec 已通过统筹复核。2026-11-17 按 HC-212 的正式快照、任务和知识契约补齐接线。实施见[同名 Plan](../plan/HC-219-引用任务与团队知识.md)。

成员可以把同一 Project（协作事项）中的讨论片段带入自己的会话，也可以把工作明确分派给项目成员。引用先展示实际材料再加入草稿，产品任务提供可追踪的发布与接收记录，团队知识提供可回看的版本。产品任务是工作台里的协作记录，与工程 Task 编号分别管理。[HC-219 Task](../task/HC-219-引用任务与团队知识.md) · [桌面前端交互设计](../architecture/桌面前端交互设计.md#7-引用任务与知识) · [任务衔接](../project/项目协作设计任务衔接.md#3-前端任务与并行顺序)

## 1. 选择引用来源

在本人本机会话的现有输入区键入 `@`，按来源选择。打开菜单只读取候选信息，选择材料时才读取指定内容。菜单中的 Enter 或 Tab 选择候选，Esc 关闭菜单，输入法组合时沿用原键盘处理。输入与命令交互继续复用现有组件。

| 分组 | 可选来源与选中结果 |
| --- | --- |
| 会话 | 当前 Project 中有权读取的会话，包括本人会话及跨机器只读会话。按 HC-212 交付范围取云端已上传的定稿消息和工具摘要，进入固定快照预览。 |
| 成员 | 当前 Project 的成员。选择后打开产品任务表单，并预选被指派人。 |
| 任务 | 当前 Project 中有权读取的产品任务。按服务交付的固定材料标识预览，可带入草稿。 |
| 知识 | 当前团队中有权读取的知识条目及可引用版本。选定版本后预览正文，可供本团队的 Project 引用。 |
| 本机文件 | 沿用当前会话目录的文件候选、目录浏览、相对路径回填与显式打开。 |

首版按每人一台设备设计，其他成员的会话以只读方式打开。只读页的“引用到我的会话”以当前会话为来源进入同一预览流程，“创建任务”打开同一个任务表单。简报供浏览和选择，快照正文由用户主动取材。取材只读取选定范围，会话正文的阅读和同步进度仍由 HC-218 管理。

## 2. 从项目会话快照到本人草稿

### 新建准备页的引用（2026-11-19）

新建页的输入区复用公共提及菜单与引用卡。用户选当前 Project 可读会话 → 预览固定快照 → 确认加入尚未登记的新建草稿。取材、预览、移除和恢复草稿都只处理材料与个人状态。当前目录、文字和已选引用按账号、Workspace、Project 保存，历史个人记录中只有文字和目录时也可恢复。

用户点击「开始会话」后才沿用现有会话登记与首轮发送。文字或固定引用任一有内容即可开始，仍须先选择目录。登记后完整转移已确认引用，首轮按同一固定标识交给本机发送端口。创建失败保留准备页草稿，发送未受理则保留已建会话的草稿。等待登记期间的新编辑继续保留在准备页，等待受理期间的新编辑不被原修订清空。账号或项目变化使旧预览失效。

1. **选择会话并取材。** 选择 `@会话` 候选后，HC-219 请求生成或读取已上传范围的快照。范围选择和默认值以 HC-212 实际交付为准。预览等待时显示“正在读取引用”。空范围、权限变化或读取失败时说明原因，可恢复的失败提供重试；材料就绪后才可继续。
2. **查看固定快照。** 预览显示会话及所有者、返回的版本标识、上传时间、实际消息范围和正文。快照是该次取材后固定的一份内容。后续上传只更新来源提示，当前引用继续使用原快照。取消预览返回原入口，保留已有草稿。
3. **选择去向。** 预览中点击“引用到我的会话”，由 HC-218 提供当前账号、当前设备、当前 Project 的本人会话和“新建会话”。选已有会话时沿用它的工作目录，保留已有文字、附件和引用。新建时由用户通过 HC-218 复用的 `DesktopHost.chooseDirectory` 选择目录，普通文件夹也可使用。取消选择或准备失败时保留预览，用户可继续选择。准备失败时显示原因。
4. **确认加入草稿。** HC-218 核对目标仍属于当前账号、Project 和设备，使用最新目标草稿合并固定引用。已有目标尚未加载个人状态时，先按现有机制恢复草稿。仅当目标就是发起会话，草稿修订号、原 `@` 片段的起止位置和内容均仍匹配时，才在同一次变更中移除该片段。其余情况下保留现有文字。确认只应用草稿变更，用户可继续编辑并自行发送。
5. **打开目标会话。** 草稿变更应用后，HC-217 按目标会话标识定位，输入区展示预览时的来源、范围和正文。定位失败时保留已应用的草稿，重试只定位该会话。

HC-218 沿用桌面个人状态和保存机制。现有 `PersonalPersistence.save` 返回 `void`，异步提交给个人状态宿主，保存失败由现有提示和“重试保存”处理。受控回调成功只表示草稿变更已应用。正式持久化以宿主保存结果为准。[个人状态保存](../../../apps/desktop/src/renderer/personal-persistence.ts)

草稿卡片提供定位、刷新和移除。定位按当前访问权限打开来源。刷新重新取材并展示新版本，用户确认后才用新卡片替换原草稿项。取消或刷新失败保留原快照，并按当前权限展示。移除只从该草稿去掉对应卡片。取材和刷新返回时核对账号、Project 和当前请求，只有该次选择仍有效时才展示结果。

恢复草稿和展开历史时，按各自保存的引用标识读取原版本。确认失去会话快照或知识版本的访问权限时，使用现有 `unavailable` 显示状态，清空传入卡片的正文，历史只显示不可用提示。草稿保留，可移除该项，权限恢复后也可按原标识重试读取。

发送由本人在目标会话主动触发。正式发送按已交付入口核对材料的访问权限与固定标识，把预览确认的版本作为用户消息的参考材料。引用不可用时保留草稿并阻止携带该项发送。发送未获受理时保留草稿并说明原因，结果待确认时沿用现有等待行为。发送受理后按原会话的草稿修订号清理，等待期间继续编辑的草稿得以保留。

## 3. 产品任务与团队知识

- **发布任务。** 从 `@成员`、只读会话或项目任务页进入同一表单。填写标题和说明，选择当前 Project 的被指派人及要附带的材料，经“发布任务”确认后提交。引用来源先预览再加入表单。成功后用服务返回的任务标识进入详情。校验或提交失败保留表单内容并反馈原因。
- **查看与接收任务。** 任务页提供“指派给我 / 我发布的 / 项目全部”，详情展示说明、发布人、被指派人、固定材料及接口返回的状态和操作记录。接收、流转和关联只使用接口返回的状态及允许动作。版本冲突时提示重新读取详情并保留待提交的输入，任务列表、导航数量与看板读取同一任务状态。缺少独立接收或关联能力时提示对应动作暂不可用。
- **任务材料标识。** HC-212 的任务详情返回 `snapshotIds` 和 `knowledgeRefs`。任务详情、引用与本机草稿使用这组标识读取原始材料。`expectedVersion` 用于提交任务操作的并发校验。任务说明在本人明确准备草稿时按当时读取的详情带入。[HC-212 Spec](HC-212-协作应用与看板通知.md#停点二-产品任务)
- **本人在本机开始。** 被指派人通过独立的“在本机开始”选择或新建本人本机会话，复用同一目录与草稿准备动作带入固定的任务材料。用户确认所用 Agent 并明确开始后才调用已交付的本机宿主入口。缺少入口时明确显示暂不可用。发布、接收与关联只提交对应的任务操作，查看通知只定位详情，带入材料只写草稿。
- **团队知识。** 团队知识页显示列表和正文，按实际权限提供编辑与版本历史。保存或版本冲突按接口结果反馈，失败保留编辑内容。通过 `@知识` 或知识详情的引用入口选定版本、预览并确认加入草稿，知识仅在用户选中时进入会话。条目修改后，已选草稿和历史继续引用原版本。搜索结果、分类、归档状态及引用可用性按 HC-212 实际返回展示。

## 4. 与现有桌面代码的交界

公共输入沿用 `@workbench/ui` 的 `ConversationView`、`ConversationReferenceView`、`ConversationDraft.referenceIds` 和 `onSend`。协作候选在原 `@` 菜单传递选中意图，文件候选复用原目录和路径动作。引用回调支持定位、刷新、移除。历史使用时间线的 `extension` 条目按固定标识展示材料。正式发送时主进程按当前本机会话和固定标识核权并取材。[对话公开类型](../../../packages/workbench-ui/src/conversation/types.ts) · [输入区](../../../packages/workbench-ui/src/conversation/composer.tsx) · [桌面对话装配](../../../apps/desktop/src/renderer/features/session/local-session-page.tsx) · [本机发送](../../../apps/desktop/src/main/local-execution-ipc.ts)

下表供三卡对齐前端输入和结果，具体组件和动作签名在共同复核后确定。

| 归属 | 输入 | 结果和失败反馈 |
| --- | --- | --- |

会话候选查询、个人草稿和正文同步由 HC-218 维护。HC-219 的页面与客户端消费放在 `apps/desktop/src/renderer/features/collaboration/`，按 `references`、`tasks`、`knowledge` 组织。HC-217 或统筹串行装配 `desktop-workbench.tsx`、公共出口及 main/preload 接点。看板中的任务由 HC-217 定位到本卡详情，HC-219 提供任务元数据刷新。通知到达时，已确认的引用仍指向原版本。

## 5. 首条路径的演示与正式接入

首个受控停点复用公共对话组件与主题，通过独立预览的“预览会话引用”打开固定快照。演示覆盖预览、选择已有或新建本人本机会话、确认加入草稿。真正的“输入 `@` → 选会话”在共享菜单接入后验证。[同名 Plan](../plan/HC-219-引用任务与团队知识.md#停点一-固定快照进入本人草稿) · [Project 协作视觉预览](../previews/project-collaboration/README.md)

- 先核对快照 A 的所有者、版本、时间、范围和正文，再选择已有本人会话并确认。草稿应同时显示原文字和快照 A，目录沿用原绑定，受控发送回调调用次数为零。
- 将来源更新为 B 时，草稿仍显示 A。点“刷新”先预览 B，确认后才替换。点“移除”只去掉卡片。
- 用同一入口选择新建会话，取消目录选择可回到预览，选定普通文件夹后材料进入新会话的草稿。可用受控发送回调核对本人单独点击“发送”时收到的是草稿里已确认的版本。

| 接入事项 | 所需交付 |
| --- | --- |
| 公共工作台中的首条路径 | HC-217 最小页面与会话定位、HC-218 的会话候选和 `@` 扩展、目标选择和草稿动作。成员及会话候选由两卡消费 HC-211 已交付的组织与简报能力。 |
| 正式会话快照 | 使用 HC-212 的快照生成、固定标识读取、范围及访问结果。 |
| 产品任务 | 使用 HC-212 的列表、详情、发布、流转和关联能力，按任务详情的固定标识回读附带材料。 |
| 团队知识 | 消费 HC-212 交付的列表、正文、编辑、版本历史和固定版本引用能力。 |
| 实际发送与本机开始 | HC-218 对接同事交付的本机发送或执行入口，以及固定引用随输入保存、按标识读取并回显的能力。任务开始另需本人完成会话准备并明确确认开始。 |

服务端、线上契约、Runner 核心与 ACP 的设计和实现由同事维护。本卡按实际交付消费接口，缺口记录在对应接入项。后续实施按 Task 做受影响的构建、类型、边界检查和主路径冒烟，完整组合留 HC-204。
