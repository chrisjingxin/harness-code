状态：草稿，待评审。2026-11-13 由张景新认领后起草，经确认后才写 Plan/Todo。范围与验收见 [HC-217 Task](../task/HC-217-项目导航与资料.md)；交互依据为[桌面前端交互设计](../architecture/桌面前端交互设计.md)和[视觉预览](../previews/project-collaboration/README.md)；分工见[任务衔接](../project/项目协作设计任务衔接.md#3-前端任务与并行顺序)。服务端接口以 HC-211 已合入的实现和 [组织层契约](../../../packages/workbench-contracts/src/organization.ts) 为准，本文不新增后端接口、字段或权限规则。

## 1. 现状与改后收益

**现状痛点**：桌面左栏仍是"工作区 → 设备 → 本机项目 → 会话"树（HC-208），业务请求走已被服务端拆除的旧路由（团队级会话列表、`devices/{id}/projects`、`stop-sharing` 等）。新协作方式以团队下的 Project（协作事项）为入口，用户要先知道自己在参与哪件事，再看会话、任务和进度；现有界面做不到，也连不上当前服务端。

**解决思路**：左栏改为"当前 Project + 按成员分组的会话"，项目切换、创建和资料管理消费 HC-211 已交付的组织接口；同时定义中央页面的装配接点，让 HC-218 的会话、HC-219 的任务/知识、HC-220 的看板分别接入同一外壳。

**改后收益**：打开应用即看到"我在这个项目里的会话"，他人进展收在底部按需展开；切换项目时各自的选择、折叠和草稿不串；项目成员和仓库能在桌面内维护；后续三卡只需交付页面组件，不再改导航。

### 2.2 成员分组、折叠与搜索

分组规则（输入 → 判断 → 输出）：

1. 输入：当前项目的成员名单（本卡读取）+ 会话条目（HC-218 提供，含稳定所有者标识 `ownerUserId`）。
2. 判断：按 `ownerUserId` 归组，不按显示名；当前账号的组固定在最上方并显示为"我的会话"，其他成员按显示名排序，同名成员分别成组（组标题附用户名区分）。
3. 输出：每组显示头像、名称、会话数；行内只显示标题、时间和 HC-218 给出的同步标识，成员名只在组标题出现，设备不作为层级。

| 情况 | 行为 |
| --- | --- |
| 首次进入项目 | "我的会话"展开，其他成员收起 |
| 用户点成员标题 | 只切换该组展开/收起，不读取正文、不切换中央页面；状态按账号 + 项目保存 |
| 成员没有会话 | 仍显示该组，展开后显示"暂无会话" |
| 已移出项目的成员 | 若仍有可见会话，组标题加"已离开"；无会话则不显示 |
| 会话列表加载中/失败 | 组仍按成员名单显示，会话区显示"正在加载"或失败说明与"重试" |
| 会话来源未接入（HC-218 接入前） | 成员组正常显示，会话区显示"会话列表尚未接入"，不展示模拟数据 |
| 轻量更新、新会话出现 | 只更新条目与数量；不自动展开其他成员，不改变当前选择 |
| 定位会话（看板/任务/引用跳转） | 展开所属组并选中该会话，这是唯一会自动展开他人组的入口 |

搜索：只过滤当前项目已加载的成员名与会话标题，不发请求。输入非空时，命中的组临时展开、未命中的组隐藏，组标题的折叠按钮暂不可用（避免改动保存的折叠状态）；清空后恢复原折叠状态。无匹配时显示"没有匹配的成员或会话"。搜索文本不持久化，切换项目时清空。

### 2.3 项目切换与恢复

项目下拉只列当前账号参与的项目（含已归档，带"已归档"标记），当前项目带勾；分隔线下是"创建项目"。下拉内条目只做选择，不放管理操作；项目设置按钮在下拉旁独立存在。

切换流程：

1. 用户选择项目 B → 保存 A 的个人状态（已实时保存）→ 通知各页面模块范围变为 B。
2. 读取 B 的个人导航记录：上次的页面、选中会话、成员展开情况。
3. 判断：记录中的会话若仍在 B 的会话条目中 → 恢复该会话；若页面是看板/任务/资料/知识 → 恢复该页面；否则（无记录、会话已不可见）→ 进入新对话准备页。
4. 迟到的 A 的请求结果一律丢弃，不显示在 B 中。

重开应用：恢复上次项目；该项目已不在列表（被移出或删除）时，移除失效选择，提示"上次的项目已不可访问"，并选第一个可访问项目；一个项目都没有时显示"还没有项目"空态和"创建项目"按钮。项目列表加载失败与"没有项目"分开显示，失败带重试。

选择项目不会指定本机目录、创建会话或下载他人正文；工作目录名只在会话上下文中出现，与 Project 名分开。

### 2.4 项目设置：资料、成员与仓库

点击项目设置进入中央"项目资料"页（右栏不显示文件面板），三块内容：

| 区块 | 所有人可见 | 仅项目所有者（`role = owner`）可用 |
| --- | --- | --- |
| 概况 | 名称、说明、创建者、成员数 | 编辑名称与说明（带当前版本号提交） |
| 成员 | 活跃成员列表，所有者标"项目负责人" | 从团队成员中添加；移出成员（不能移出所有者本人） |
| 关联仓库 | 已关联仓库名、默认分支 | 从团队仓库目录选择关联；取消关联；可以不关联或关联多个 |

普通成员看到同样信息，管理按钮不显示。权限以服务端返回的 `role` 为准，前端不推断；服务端仍拒绝时按 §4 显示原因。已归档项目全部只读，显示"项目已归档"。本卡不提供新建团队仓库、归档项目或组织管理后台。

### 2.5 创建项目

1. 用户点"创建项目" → 居中弹窗填写名称（必填）和说明。
2. 提交时生成一次性 `requestId`；重复点击或重试使用同一 `requestId`，避免建出两个项目。
3. 成功 → 关闭弹窗，项目加入下拉并成为当前项目，中央打开该项目的资料页，提示可添加成员和仓库。
4. 失败 → 弹窗保留输入并显示原因，可重试；不显示"已创建"。

之后添加成员、关联仓库都是独立请求，逐项显示结果：某项失败时明确"项目已创建，××未添加"，保留选择供重试，不把多个请求包装成一次原子操作。

### 2.6 中央页面与右栏

| 页面 | 入口 | 提供者 | 右栏 |
| --- | --- | --- | --- |
| 新对话准备页 | 新对话；无可恢复会话时默认 | HC-218 | 不显示 |

顶栏：会话页显示会话上下文（由 HC-218 提供），其他页面显示页面名和当前 Project 名，字体与图标基线统一。

## 3. 接口与数据

### 3.1 消费的服务端接口

均为 `/api/v1/workspaces/{workspaceId}` 下的已交付路由，响应类型见组织层契约：

| 用途 | 方法与路径 | 契约类型 |
| --- | --- | --- |
| 项目列表（本人参与） | `GET /projects` | `ProjectListResponse` |
| 创建项目 | `POST /projects` | `ProjectCreateRequest` → `ProjectResponse` |
| 项目详情（含本人角色、成员、仓库） | `GET /projects/{projectId}` | `ProjectDetailResponse` |
| 修改名称/说明 | `PATCH /projects/{projectId}` | `ProjectPatchRequest`（必带 `expectedVersion`）→ `ProjectResponse` |
| 添加 / 移出成员 | `POST /projects/{projectId}/members`、`DELETE …/members/{userId}` | `ProjectMemberAddRequest` → `ProjectMemberChangeResponse` |
| 关联 / 取消仓库 | `PUT`、`DELETE /projects/{projectId}/repositories/{repositoryId}` | 无正文，成功 204 |
| 团队仓库目录（关联候选） | `GET /repositories` | `RepositoryListResponse` |
| 团队成员（显示名与添加候选） | `GET /members`（已有） | `MembersResponse` |

成员显示名：项目成员只返回 `userId`，与团队成员列表按 `userId` 合并得到显示名；找不到时显示"成员 {userId 前 8 位}"。

### 3.2 桌面宿主端口

新增页面可见的窄端口 `OrganizationHost`，类型放 `apps/desktop/src/organization-host.ts`（与 `PersonalHost`、`ProjectReadHost` 同级，属桌面内部接点，不进共享契约），preload 以 `window.organization` 暴露：

```ts
interface OrganizationHost {
  listProjects(workspaceId: string): Promise<CollaborationResult<OrganizationProjectListResponse>>
  createProject(workspaceId: string, request: ProjectCreateRequest): Promise<CollaborationResult<ProjectResponse>>
  getProject(workspaceId: string, projectId: string): Promise<CollaborationResult<ProjectDetailResponse>>
  updateProject(workspaceId: string, projectId: string, request: ProjectPatchRequest): Promise<CollaborationResult<ProjectResponse>>
  addMember(workspaceId: string, projectId: string, request: ProjectMemberAddRequest): Promise<CollaborationResult<ProjectMemberChangeResponse>>
  removeMember(workspaceId: string, projectId: string, userId: string): Promise<CollaborationResult<ProjectMemberChangeResponse>>
  listRepositories(workspaceId: string): Promise<CollaborationResult<RepositoryListResponse>>
  linkRepository(workspaceId: string, projectId: string, repositoryId: string): Promise<CollaborationResult<null>>
  unlinkRepository(workspaceId: string, projectId: string, repositoryId: string): Promise<CollaborationResult<null>>
}
```

主进程处理链：IPC 来源校验与参数校验（ID 为 UUID、请求体按契约 Schema）→ `CollaborationState` 确认已登录且工作区属于当前账号 → `CollaborationClient` 携带 Cookie/CSRF 发请求并校验响应 → 再次核对身份代次，过期结果返回"身份操作已结束" → 返回不含凭据的结果。React 不接触服务地址、Cookie 或 CSRF。

主进程适配要点：

- `CollaborationClient` 的写请求支持 POST/PATCH/PUT/DELETE，统一附带 CSRF；204 响应按 `null` 返回。
- 响应校验按"Schema 文件 + 类型名"定位类型，不按类型名全局注册：不同 Schema 可以有同名类型（如组织层与会话层都有 `ConversationSummary`），全局注册会互相覆盖。
- 组织层请求都走一个 `organization` Schema 和一组 `organization:*` IPC 通道，与身份、会话通道分开声明。

### 3.3 一并删除的旧实现

新导航上线后，下列代码只服务于已拆除的服务端路由或"设备 → 本机项目"导航，本卡直接删除，不保留别名、兼容分支或开关：

| 位置 | 删除内容 |
| --- | --- |
| `@workbench/ui` 导航 | `CollaborationNavigation` 及 `NavigationDevice`/`NavigationProject`/`NavigationScope` 等设备树类型与样式，由 `ProjectNavigation` 取代 |
| 桌面 renderer | `conversation-navigation.ts`、`workspace-devices.ts` 中的设备树/项目列表加载、`hc208-preview`；设置页仍需要的本机设备登记状态改为直接读取 `DeviceHost.getState` |
| 设备端口 | `DeviceHost.listProjects`、`DeviceHost.stopSharing` 及对应 IPC、preload、主进程与客户端方法；`DeviceRegistrationPanel` 的"停止共享"按钮 |
| 契约包 | `device.ts` 中只被上述调用使用的 `ProjectListResponse`、`ProjectPageCursor`、`ProjectStopSharingRequest` 与 `DeviceHost.listProjects/stopSharing`；仍被本机共享发布使用的旧 `ProjectSummary` 改名为 `SharedProjectSummary`，让组织层类型在 `index.ts` 去掉过渡别名、使用正式名（`ProjectSummary`、`ProjectListResponse`）。组织层会话类型与旧会话契约同名，由 HC-218 换成新会话模型时导出 |

边界：旧会话读取链（`conversations`/`projects` 端口、`ConversationArea`、`ProjectCenter`、会话事件投递、`DeviceHost.shareProject`）属于会话与本机执行，由 HC-218 用新实现替换并删除；本卡只把它们从 `desktop-workbench.tsx` 的装配中摘下，会话页在 HC-218 接入前显示"尚未接入"。实施中这一步随停点二完成：正式入口已不再引用这些模块。Runner 核心与设备上传消息类型不动。

### 3.4 个人状态

个人状态只保存本人的选择，不保存共享内容。存储格式按新模型定义，版本号提升，不读取旧版本记录：

| 记录 | 范围 | 内容 |
| --- | --- | --- |
| `account` | 账号 | `workspaceId`：当前团队 |
| `workspace` | 账号 + 团队 | `projectId`：当前项目（可空）；`panels`：左右栏开合与宽度 |
| `projectNavigation` | 账号 + 团队 + 项目 | `page`：当前中央页面（见 §3.5）；`expandedMembers`：展开的他人 `userId`；`selfCollapsed`：本人组是否被手动收起 |

- `projectNavigation` 读写前由主进程调用 `getProject` 确认当前账号仍可访问该项目，失败即拒绝。
- 搜索文本、加载状态不持久化。
- 会话个人状态（草稿、阅读位置、文件页签）的记录结构与命名由 HC-218 按新会话模型定义；现有名为 `project` 的记录指"会话的本机文件"，与新的 Project 同名易混，由 HC-218 一并改名。

### 3.5 页面装配接点

本卡在 `apps/desktop/src/renderer/features/project-navigation/` 交付外壳、状态和数据适配，并导出以下前端接点（只在桌面内部使用，不是线上契约）：

```ts
/** 当前导航范围；各模块按它隔离自己的状态，异步结果返回时须核对仍属于当前范围。 */
type ProjectNavigationScope = { namespace: string; accountId: string; workspaceId: string; projectId: string }

/** 中央页面；taskId 由 HC-219 定义含义，本卡只保存和传递。 */
type ProjectPage =
  | { kind: "new" }
  | { kind: "conversation"; conversationId: string }
  | { kind: "board" }
  | { kind: "tasks" }
  | { kind: "task"; taskId: string }
  | { kind: "info" }
  | { kind: "knowledge" }

/** 页面模块可调用的导航动作。 */
interface ProjectNavigator {
  openPage(page: ProjectPage): void
  /** 展开会话所属成员组并选中；会话不在当前项目时返回 false。 */
  locateConversation(conversationId: string): boolean
}

/** HC-218 提供的左栏会话条目；本卡只按 ownerUserId 归组和渲染，不解释同步含义。 */
type NavigationSessionEntry = {
  conversationId: string
  ownerUserId: string
  title: string
  timeLabel: string
  /** 行内标识文本与语气由 HC-218 决定，例如"未同步""有更新""只读"。 */
  badge?: { text: string; tone: "neutral" | "accent" | "warning" | "danger" }
}
type NavigationSessionSource = {
  entries: readonly NavigationSessionEntry[]
  availability: { state: "ready" | "loading" | "failed" | "unavailable"; message?: string }
  retry(): void
}

/** 每个页面提供者导出的渲染入口；外壳负责挂载和隐藏，不了解页面内部状态。 */
type ProjectPageProvider = {
  render(context: { scope: ProjectNavigationScope; page: ProjectPage; navigator: ProjectNavigator; visible: boolean }): ReactNode
  /** 可选：页面需要右栏时返回右栏内容，否则右栏收起。 */
  right?(context: { scope: ProjectNavigationScope; page: ProjectPage; slot: WorkbenchRightSlot }): ReactNode | null
  /** 可选：会话页的顶栏上下文。 */
  context?(context: { scope: ProjectNavigationScope; page: ProjectPage }): CollaborationContextView | null
}
```

- `desktop-workbench.tsx` 由本卡改为：身份/团队恢复 → 项目选择 → 外壳 + 按 `page.kind` 选择提供者。HC-218～220 交付各自的 `ProjectPageProvider`、`NavigationSessionSource` 和任务数量，由本卡实施者串行接入这一个文件。
- 会话提供者在整个项目范围内保持挂载，切到其他页面时只隐藏（`visible = false`），保证草稿和阅读位置不丢。
- 左栏视图组件 `ProjectNavigation` 放在 `@workbench/ui` 的 navigation 出口，是只收视图数据、发意图的纯组件，不持有请求或身份；状态、数据适配和装配放在 desktop 的 `features/project-navigation/`。

## 4. 错误语义

宿主返回的错误码按下表转为用户可懂的提示；未列出的沿用现有通用提示（连接中断、登录失效等）：

| 错误码 | 出现场景 | 用户看到 |
| --- | --- | --- |
| `PROJECT_OWNER_REQUIRED` | 非所有者修改资料/成员/仓库 | "只有项目负责人可以修改"，刷新角色并隐藏管理按钮 |
| `OWNER_CANNOT_LEAVE` | 移出所有者 | "不能移出项目负责人" |
| `VERSION_CONFLICT` | 他人已先修改名称/说明 | "资料已被更新"，重新读取并保留本次输入供确认 |
| `PROJECT_ARCHIVED` / `REPOSITORY_ARCHIVED` | 对归档对象做修改 | "项目（仓库）已归档，不能修改"，转只读 |
| `WORKSPACE_MEMBER_REQUIRED` | 添加非团队成员 | "该用户不在当前团队" |
| `RESOURCE_NOT_FOUND` | 项目/成员/仓库已不存在或无权 | 按 §2.3 移出失效选择，或刷新对应区块 |
| `REQUEST_ID_CONFLICT` | 同一 `requestId` 内容不同 | 视为客户端缺陷：提示失败并换新 `requestId` 后由用户重试 |

## 5. 不变量

1. 所有选择与个人状态以 `accountId + workspaceId + projectId` 隔离；账号或项目切换后，旧范围的回包不得更新新范围的界面。
2. 选择 Project 不会创建会话、指定目录、发起同步或下载正文。
3. 成员分组只用稳定标识，不用显示名或设备做分组依据。
4. 只有用户主动定位会话才会展开他人组；后台更新不改变选择、焦点和折叠。
5. 管理按钮的显示只依据服务端返回的 `role`，前端不新增权限规则；失败时不显示成功结果，也不丢弃用户输入。
6. 页面模块只经 §3.5 接点接入，不复制 `ConversationView`、`ProjectDock`、主题或第二套布局。

## 6. 已定决策与依赖

1. 设计不考虑旧实现的兼容：左栏、个人状态、设备端口和契约类型都按新模型定义，旧代码按 §3.3 删除。
2. 契约包 `exports` 增加 `./schema/organization`，指向已存在的 `organization.schema.json`；只暴露现有文件，不改 Schema 内容，变更告知同事。
3. 首版提供项目名称与说明的编辑（仅所有者），与成员、仓库一起放在项目资料页。
4. HC-218 提供 `NavigationSessionSource` 前，停点 2 的会话区按 §2.2 显示"尚未接入"；停点 1 使用受控示例数据。
