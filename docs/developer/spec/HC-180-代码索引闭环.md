# HC-180 代码索引闭环 Spec

> 对应 Task：[HC-180 代码索引闭环](../task/HC-180-代码索引闭环.md)  
> 一手源码调研：[180 CodeGraph 集成评估](../research/180-CodeGraph集成评估.md)

## 1. Objective

本 Spec 将 Task 已确认的结果收敛为可实现契约：用户在 TOML 中开启默认关闭的代码索引能力并重启 AgentHost 后，TUI 与 Web 共用 `/code-index` 管理当前工作区的 `.harness-index/`；健康索引为后续 Run 提供供应商无关的 `codebase_explore`，索引不可用时继续使用现有搜索和读取。

普通界面统一称为“代码索引”，不显示“实验性”标签，也不显示底层供应商名称。实验属性只体现在配置区段、用户文档中的稳定性说明及发布承诺上。

```text
配置开启并重启
  → Host 校验受管运行时
  → 用户执行 /code-index
  → Host 建立或同步 .harness-index
  → 校验成功后启动查询进程与 watcher
  → 下一次 Run 取得 codebase_explore
  → 未命中或失败时回退现有工具
```

本功能是一个端到端闭环，不拆成独立交付的多份 Spec：只有配置门禁、索引管理、查询注入和双界面投影同时存在，用户才得到可用结果。

## 2. 用户行为规格

### 2.1 配置门禁

配置沿用现有用户级 TOML：

```toml
[experimental.code_index]
enabled = true
```

- `enabled` 缺失时默认为 `false`。
- 配置缺失、显式关闭或配置加载失败时均不得开启能力。
- 配置关闭时，AgentHost 不解析依赖包、不访问 `.harness-index/`、不启动 Node/MCP/watcher，也不向模型注入工具。
- 开关只在 AgentHost 启动时读取，修改配置后必须重启；不提供运行中热切换。
- 关闭并重启后保留已有索引数据，但不读取、查询、同步或自动删除它。
- 配置键可标明实验性质；Slash 菜单、TUI、Web、命令结果和工具名称不显示“实验性”。

### 2.2 `/code-index` 命令

| 输入 | 行为 | 终态 |
|---|---|---|
| `/code-index` | 无索引时首次建立；健康索引存在时增量同步 | 成功后查询与 watcher 可用 |
| `/code-index status` | 刷新并展示索引、当前 job、查询、watcher、统计和恢复建议 | 不改变索引 |
| `/code-index rebuild` | 关闭查询与 watcher，删除上游数据库并全量重建 | 成功后产生新 generation |
| `/code-index cancel` | 取消当前索引 job；无 job 时返回可操作提示 | 被取消的索引不可查询 |
| `/code-index remove` | 经共享确认界面确认后关闭资源并删除索引 | 回到 absent |

补充规则：

- 参数缺失或未知时显示上述用法，不把文本交给模型。
- 默认命令遇到 `incomplete` 时不得尝试增量修复，提示执行 `rebuild`。
- `status` 在模型 Run 或索引 job 期间均可使用。
- 建立、同步、重建、删除遇到正在使用索引的 Run 时拒绝；不取消 Run。
- `remove` 请求除 revision 外必须携带显式 `confirmed: true`；CLI 只有在 TUI/Web 共用确认流程完成后才发送。
- 配置关闭时 Slash 菜单不显示命令；用户手工输入时显示开启配置并重启的说明。该说明仍使用“代码索引”，不展示供应商名称。

### 2.3 界面反馈

索引 job 是 Host 级工作区操作，不是模型 Run：

- 不复用 `run.progress`，不生成 thread/run id，也不写入对话 Transcript。
- `InteractiveState` 增加独立的代码索引状态；它不占用会阻塞输入的 `pendingOperation`。
- TUI 与 Web 从同一 `InteractiveController` 状态和 selector 渲染同一份 snapshot，不各自调用 Host 或启动进程。
- 运行中显示一个原地更新的状态行或状态卡；继续对话和发起不使用索引的新 Run 不受阻塞。
- 只显示上游结构化结果可证明的阶段、完成数与总数。没有可信总数时只显示阶段和完成数，不推算百分比。
- 原始 ANSI、英文 CLI 文案和 stderr 不进入界面。
- `status` 使用现有可检查结果的展示模式；重启后无需恢复历史进度卡，只展示当前持久状态。

## 3. Module 与 seam

### 3.1 模块归属

```text
CLI CommandRegistry / Dispatcher
  → InteractiveController
  → AgentGateway
  → protocol code_index.*
  → AgentHost
  → CodeIndexManager
       ├─ CodeIndexStateStore
       └─ CodeIndexRuntimePort
            ├─ 生产 adapter：受管 Node + 私有 MCP
            └─ 测试 adapter：进程内 fake
  → .harness-index/
```

| module | 职责 | 不负责 |
|---|---|---|
| CLI 共享交互层 | 命令解析、确认、状态归并、TUI/Web selector | 包解析、索引状态机、直接启动 Node |
| protocol | capability、请求、snapshot、通知与错误契约 | 业务状态推断、供应商类型 |
| `CodeIndexManager` | 单工作区状态机、租约、job、查询 session、watcher 和关闭顺序 | UI 文案、公共 MCP 配置 |
| `CodeIndexStateStore` | `.harness-index/state.json` 原子读写与校验 | 上游数据库读写 |
| `CodeIndexRuntimePort` | 运行时 preflight、索引子进程、供应商查询调用 | Host/Run 策略、LangChain tool 类型 |
| Node adapter | 对接 1.1.6 编译产物并输出 Harness JSONL | 产品状态机、用户文案 |

`CodeIndexRuntimePort` 是真实外部依赖 seam：生产 adapter 运行随平台包携带的 Node 与编译后 JS/WASM，并在内部使用私有 MCP；测试 adapter 提供确定性的进度、状态、查询、取消和故障。MCP transport、供应商工具名和 LangChain `BaseTool` 都不能穿过该 seam。其余实现保持在 `CodeIndexManager` 内，不为单一实现增加 factory 或多层 wrapper。

### 3.2 Host interface

`CodeIndexManager` 只向 AgentHost 暴露以下概念：

```python
class CodeIndexManager:
    def snapshot(self) -> CodeIndexSnapshot: ...
    async def apply(self, request: CodeIndexApplyRequest) -> CodeIndexSnapshot: ...
    async def acquire_query(self) -> CodeIndexQueryLease | None: ...
    async def close(self) -> None: ...
```

- `apply` 接受 tagged action，由同一把 workspace 锁线性化状态检查和启动动作。
- `acquire_query` 只在健康 generation 且查询 session 就绪时返回租约；租约随 Run 终态、取消或准备失败释放。
- `CodeIndexQueryLease` 提供已绑定 generation 的 `explore(query, max_files)` 查询 interface；调用方不能取得私有 MCP manager、原始 MCP tool 或供应商响应类型。
- `close` 幂等；先阻止新租约和 job，再终止当前 job、等待租约释放、关闭查询/watcher，最后持久化安全终态。

## 4. 受管运行时与依赖定位

### 4.1 固定版本

- `@za38/cli` 以精确版本 `1.1.6` 依赖 `@colbymchenry/codegraph`，不得使用范围版本。
- 主包和当前平台包都必须报告 `1.1.6`；缺包、错版、布局缺失或自带 Node 不可执行均为 preflight 失败。
- 支持映射固定为 macOS x64/arm64、Linux glibc x64/arm64、Windows x64；Linux musl 和 Windows ARM 返回不支持。
- 不调用系统 Node，不在 Bun TUI 进程 import SDK，不从公网下载、更新或降级包。

CLI 启动 Python sidecar 时，通过一个 Harness 内部环境变量传递已经解析的 CLI 安装根。该值只用于定位随 CLI 发布的依赖资源；Python 端仍须确认所有解析后的文件都位于该根目录内。配置关闭时 AgentHost 不读取该路径。

### 4.2 Node adapter 契约

Node adapter 是随 CLI 构建和发布的内部资源，使用平台包自带 Node，以 `--liftoff-only` 启动。stdout 只输出换行分隔的 Harness JSON 对象，stderr 只用于受限诊断。

adapter 支持最小操作：

- `preflight`：返回版本、平台和必要文件校验结果；
- `index`：执行 initialize/sync/rebuild，转译结构化进度并返回结构化终态；
- `serve`：启动只允许探索和内部状态工具的 MCP 服务；
- `status`：读取可验证的文件、符号、关系与 watcher 状态；
- `cancel/close`：先发正常终止，超过宽限期后强杀其整个受管进程组。

子进程固定设置：

```text
CODEGRAPH_DIR=.harness-index
CODEGRAPH_NO_DAEMON=1
CODEGRAPH_NO_DOWNLOAD=1
DO_NOT_TRACK=1
CODEGRAPH_TELEMETRY=0
```

内部 MCP allowlist 只包含主探索工具和内部状态工具。最终外联隔离仍由企业网络策略承担；Harness 不宣称环境变量等同于沙箱。

## 5. 数据目录与持久状态

### 5.1 唯一目录

- 唯一数据根是规范化工作区根下的单段目录 `.harness-index/`。
- Host 拒绝 symlink、junction、路径穿越、工作区根变化和解析到工作区外的目标。
- 初始化前写入供应商无关的 `.harness-index/.gitignore`，并在 Git 工作区的 `.git/info/exclude` 写入带 Harness 标识的精确规则。
- 不修改项目根 `.gitignore`，不创建 `.codegraph/`，不安装 Git hooks。
- `remove` 只删除 `.harness-index/` 与本功能自己写入的本地 exclude 标识块；不得删除 `.harness/`、其他 ignore 条目或未知路径。

### 5.2 `state.json`

Harness 在 `.harness-index/state.json` 保存版本化、供应商无关的状态。最小字段为：

```json
{
  "schema_version": 1,
  "workspace_fingerprint": "...",
  "engine_version": "1.1.6",
  "revision": 7,
  "generation": 3,
  "lifecycle": "ready",
  "last_job": {
    "id": "...",
    "action": "sync",
    "started_at": "...",
    "finished_at": "..."
  }
}
```

- `lifecycle` 取值为 `running | serving | ready | cancelled | incomplete | failed`。
- 写入使用同目录临时文件、flush、可用时 fsync、原子替换；不得在部分写入时覆盖最后一个可解析状态。
- 不保存工作区绝对路径、原始 stderr、源码内容或凭据。
- 数据库存在但 marker 缺失、版本/工作区不匹配或状态无法解析时，一律视为 `incomplete`，不接管为健康索引。

### 5.3 1.1.6 的保守崩溃规则

- 写操作启动前先持久化 `running`。
- 查询进程与 watcher 启动前持久化 `serving`；受管进程存活期间保持该值。
- 只有正常关闭查询/watcher 后才持久化 `ready`。
- Host 启动看到 `running` 或 `serving`，必须转为 `incomplete`，不恢复查询，并提示 `rebuild`。

这意味着即使 watcher 当时可能没有写数据，AgentHost 异常退出后也要求重建。该保守行为用于弥补 1.1.6 缺少可证明强杀恢复契约的限制。

## 6. 状态机与 invariant

### 6.1 核心状态

```text
absent
  └─ ensure → running → validate → serving → ready

ready
  ├─ ensure(sync) → running → validate → serving → ready(new generation)
  ├─ rebuild      → running → validate → serving → ready(new generation)
  └─ remove       → running → absent

running
  ├─ cancel                → cancelled/incomplete
  ├─ timeout/nonzero/crash → failed/incomplete
  └─ validation mismatch   → incomplete

serving + unclean restart → incomplete
incomplete ─ rebuild only → running
```

### 6.2 必须始终成立

1. 一个 AgentHost/workspace 最多有一个索引 job、一个查询 session 和一个 watcher。
2. `query_status=ready` 必须同时满足：配置开启、runtime 可用、`index_status=ready`、durable lifecycle 为 `serving`、无显式 job。
3. `codebase_explore` 只来自持有当前 generation 租约的 Run。
4. 显式写操作启动前活动查询租约必须为零；状态切到 job 后新 Run 不再取得租约。
5. job 成功必须同时满足退出码为零、结构化终态成功、状态统计校验成功；缺一不可。
6. 取消、超时、非零退出、畸形 JSONL、进程失联和校验不一致都不得产生 `ready`。
7. generation 只在一次成功建立、同步或重建并重新连接查询后增加；revision 在每次可观察状态变更时单调增加。
8. 已开始的 Run 不热切换 generation；job 成功后仅后续 Run 取得新工具。
9. 索引结果不是 Harness Snapshot；任何编辑仍须先通过 `read_file` 取得当前 Snapshot。

## 7. Protocol v3.10

### 7.1 capability

新增：

- `code_index.read`：读取状态并接收状态通知；
- `code_index.manage`：建立、同步、重建、取消和删除。

交互式 CLI 请求两项 capability。AgentHost 配置关闭时不把它们加入 `enabled`；配置开启但 runtime 缺失时仍可启用，使用户能查看可操作错误。非交互客户端不请求时不获得能力。

### 7.2 方法与通知

```text
code_index.status  requires code_index.read
code_index.apply   requires code_index.manage
code_index.changed notification, min protocol minor 10
```

`code_index.status` 返回最新完整 `CodeIndexSnapshot`。

`code_index.apply` 接受 tagged request：

```ts
type CodeIndexApplyRequest =
  | { action: "ensure"; expected_revision: number }
  | { action: "rebuild"; expected_revision: number }
  | { action: "cancel"; expected_revision: number; job_id: string }
  | { action: "remove"; expected_revision: number; confirmed: true };
```

方法在状态检查、持久化 `running` 并成功启动后台 job 后立即返回已接受的最新 snapshot，不等待长任务结束。后续进度与终态通过 `code_index.changed` 发送完整 snapshot。启动前失败直接返回 RPC error；接受后的失败必须收敛成终态 snapshot，不能留下永久 running。

AgentHost 只向协商了 `code_index.read` 的连接发送通知。当前产品中 Web 经 CLI controller 取得同一状态，不与 Host 建立第二套索引控制通道。

### 7.3 Snapshot

```ts
interface CodeIndexSnapshot {
  revision: number;
  generation: number;
  engine_version: "1.1.6";
  data_directory: ".harness-index";
  runtime_status: "ready" | "unavailable";
  index_status: "absent" | "ready" | "incomplete";
  query_status: "stopped" | "starting" | "ready" | "failed";
  watcher_status: "stopped" | "starting" | "ready" | "degraded" | "failed";
  job: null | {
    id: string;
    action: "initialize" | "sync" | "rebuild" | "remove";
    status: "running" | "succeeded" | "cancelled" | "failed";
    phase:
      | "preflight"
      | "preparing"
      | "indexing"
      | "resolving"
      | "validating"
      | "starting_query"
      | "removing";
    completed?: number;
    total?: number;
    message?: string;
  };
  stats: null | {
    files: number;
    symbols: number;
    relationships: number;
    db_bytes: number;
    wal_bytes: number;
  };
  error: null | {
    code: string;
    message: string;
    recovery: string;
  };
}
```

约束：

- `total` 只有上游明确提供且不小于 `completed` 时才出现。
- `message` 是 Harness 定义的有限文案，不透传供应商输出。
- `runtime_status=unavailable` 可与磁盘上 `index_status=ready` 同时存在，但查询必须停止。
- `index_status=incomplete` 时 query/watcher 必须停止。
- 绝对路径、包路径、命令行、PID、原始 stderr 和供应商名称不进入协议。

### 7.4 稳定错误码

至少定义并在 TS/Python 两端生成：

| code | 含义 | 恢复方式 |
|---|---|---|
| `CODE_INDEX_RUNTIME_UNAVAILABLE` | 包、Node 或平台不可用 | 安装匹配 1.1.6 后重启 |
| `CODE_INDEX_VERSION_MISMATCH` | 主包与平台包版本不一致 | 修复企业依赖版本 |
| `CODE_INDEX_RUN_ACTIVE` | 有 Run 持有查询租约 | 等待 Run 结束 |
| `CODE_INDEX_JOB_ACTIVE` | 已有索引 job | 查看状态或取消 |
| `CODE_INDEX_REVISION_CONFLICT` | 客户端状态过期 | 刷新 status 后重试 |
| `CODE_INDEX_JOB_NOT_FOUND` | cancel 目标已结束或变化 | 刷新 status |
| `CODE_INDEX_INCOMPLETE` | 索引不能安全查询或增量 | 执行 rebuild |
| `CODE_INDEX_PATH_UNSAFE` | 数据目录解析越过工作区或类型异常 | 修复目录后重试 |

错误 message 使用供应商无关的用户文案；开发日志可记录依赖身份、版本和有界 stderr 摘要，但不得记录凭据、源码或未清洗路径。

## 8. 模型查询闭环

### 8.1 工具 interface

对模型只暴露 Harness 自有的只读 `StructuredTool`：

```ts
interface CodebaseExploreInput {
  query: string;
  max_files?: number; // 1..12
}
```

- Harness tool adapter 调用 `CodeIndexQueryLease.explore()`；私有 MCP 只存在于 `CodeIndexRuntimePort` 的生产 implementation 内。
- 原始 MCP `BaseTool` 不得传入 `create_harness_agent(tools=...)`，不进入通用外部工具列表、MCP 延迟加载候选、MCP 审批分类或 MCP catalog。
- `codebase_explore` 进入 Harness canonical tool catalog，按只读内部工具参与 capability、Policy、schema 指纹和 AgentEngine profile 计算；它不因底层使用 MCP 而变成用户配置的外部工具。
- 不暴露 `projectPath`，工作区由 Host 固定。
- 不暴露底层 node/search/callers/status 工具。
- 单次文本结果上限 32 KiB；超限时截断并给出继续缩小问题的提示。
- 工具描述明确：用于定位符号、文件与调用关系；返回源码仅供理解，编辑前必须使用 `read_file`。
- 工具调用失败、未命中、语言未覆盖或结果不足时返回可恢复结果，模型继续使用现有 grep/search/read；不把整个 Run 标记失败。

### 8.2 注入时机

`AgentHost._prepare_run` 在确定 Run profile 时尝试取得 `CodeIndexQueryLease`：

- 成功：向主 Agent 以及内建 `explore`、`general-purpose` 子代理贡献同一个只读工具；profile 记录工具 schema 与 index generation 指纹。
- 失败或状态不健康：不贡献工具，Run 使用现有工具集合。
- Plugin Agent 不自动继承该工具，除非未来 Task 明确扩展其 capability。

系统指导只在工具存在时加入“优先用 `codebase_explore` 定位，失败时回退”的简短规则。索引 job 成功不会改变已开始 Run 的工具集合。

## 9. 并发与生命周期

### 9.1 Run 与显式 job

`CodeIndexManager` 用同一临界区完成以下竞争检查：

```text
Run 准备：状态 ready 且无 job → 租约数 +1 → 固定 generation
写操作：租约数为 0 且无 job → 切换 job 状态 → 后续 Run 无索引运行
Run 结束：释放租约
job 成功：启动新查询 session → generation +1 → 后续 Run 可取得租约
```

显式 job 期间用户仍可发起新 Run，但它不取得 `codebase_explore`。不得等待 job 后在同一个 Run 中热注入工具。

watcher 属于查询进程内部的自动同步能力，允许在持有查询租约时按上游契约运行；它报告 degraded 时工具结果须附带“可能过期，编辑前重新读取”的提示。显式 sync/rebuild/remove 仍必须先等租约归零并关闭查询/watcher。

### 9.2 Host 启停

启动：

1. 加载配置；关闭时停止。
2. 配置开启后执行离线 preflight。
3. 读取并校验 marker 与数据库状态。
4. `ready` 才启动私有 MCP/watcher；`running/serving` 转为 `incomplete`；其他状态只供查询。

关闭顺序：

```text
拒绝新 Run/job
  → 取消或等待现有 Run
  → 关闭 AgentEnginePool
  → CodeIndexManager 终止 job、等待租约、关闭 MCP/watcher、写 ready/incomplete
  → 关闭普通 MCP、workspace/provider 资源
  → 关闭持久化资源
```

外部进程持有索引锁时只等待到有界超时并报错，不枚举或终止非 Harness 进程。

## 11. Code Style

- TypeScript/Python 遵循仓库现有命名、中文文件说明和公开 interface 注释规则。
- 协议字段使用稳定 `snake_case`，内部 TS 视图模型按邻近代码使用 `camelCase`。
- 状态转换集中在 `CodeIndexManager`，UI 不根据多个布尔值重建业务状态。
- 供应商参数只存在于 runtime adapter；Host、protocol 和 UI 使用 Harness 领域名称。
- Harness tool adapter 只依赖 `CodeIndexQueryLease` 的查询 interface，不 import MCP client 或供应商类型。
- 不为未来多供应商实现 factory、注册表或插件机制；`CodeIndexRuntimePort` 仅用于隔离真实进程与测试。
- 进程参数使用 argv 数组，不拼接 shell 字符串；路径先解析、验证再传递。

推荐的状态转换写法：

```python
async def apply(self, request: CodeIndexApplyRequest) -> CodeIndexSnapshot:
    async with self._lock:
        self._require_revision(request.expected_revision)
        self._require_no_job()
        self._require_no_query_leases(request.action)
        return await self._start_job(request)
```

不推荐在 dispatcher、Host handler 和进程 adapter 各自重复检查 active Run 或 incomplete 状态；共享不变量只在 manager 中执行一次。

## 12. Testing Strategy

实现阶段必须按 TDD 逐个行为推进，使用 fake runtime 覆盖绝大多数状态机，真实 1.1.6 只用于集成证据。

### 12.1 自动化测试

| 层级 | 必测行为 |
|---|---|
| 配置 | 默认关闭、显式开关、非法类型、redacted 输出、重启语义、关闭时零文件/进程探测 |
| protocol | TS/Python schema 一致、capability、tagged apply、snapshot、notification、错误码、v3.10 fixtures |
| runtime adapter | 五个平台映射、精确版本、缺包/错版/缺文件、无系统 Node、空格/中文路径、JSONL 畸形、stderr 有界化、取消与强杀 |
| state store | 原子写、损坏 marker、工作区指纹、symlink/越界、running/serving 崩溃恢复、remove 精确范围 |
| manager | 所有状态转换、退出码+终态+校验三条件、revision 冲突、job 去重、Run 租约竞争、generation、幂等 close |
| 查询 wrapper | schema 不含 projectPath、max_files 边界、32 KiB 上限、MCP 失败回退、Snapshot 提示、按 Harness 只读工具分类、原始 MCP tool 不进外部列表或公共 catalog |

## 14. Boundaries

### Always

- 保持功能默认关闭，且关闭路径没有进程、目录、工具或依赖探测副作用。
- 主包与平台包精确锁定 1.1.6，所有启动使用平台包自带 Node。
- 先持久化不安全状态，再执行可能写图的操作；只有三重成功校验后恢复查询。
- 所有编辑继续遵守 Harness Snapshot 契约。
- 用户界面和协议错误使用“代码索引”等供应商无关文案。
- TUI/Web 使用共享 controller 状态与确认流程。

### Ask First

- 改用其他版本、允许版本混用或新增公网下载/升级路径。
- 改变 `.harness-index/`、根 `.gitignore`、Git hook 或数据删除范围。
- 默认开启、运行时热切换，或在无用户命令时首次扫描工作区。
- 向模型暴露更多底层工具、向 Plugin Agent 自动注入，或允许索引结果直接授权编辑。
- 改变 active Run 与显式索引 job 的互斥规则。
- 在普通界面增加实验标签或供应商品牌。

### Never

- 在 Bun TUI 中直接 import SDK，或要求用户安装系统 Node。
- 把原始代码索引 MCP tool 注入通用外部工具列表，或让 MCP 名称、schema 和类型穿过 `CodeIndexRuntimePort` seam。
- 创建 `.codegraph/`、symlink/junction 双目录、上游 fork 或运行时 patch 来伪装 `.harness/index`。
- 透传 stderr、ANSI、供应商 CLI 文案、绝对依赖路径或凭据到协议和界面。
- 将索引 job 冒充模型 Run，或用 `pendingOperation` 阻塞全部对话。
- 在 incomplete/cancelled/failed 状态下注入查询工具或自动删除数据。
- 终止不属于 Harness 的外部进程，或删除 `.harness/` 和用户其他 Git 配置。
- 宣称固定 token、速度或正确率收益。

## 15. Success Criteria

Spec 完成后的实现必须能逐项证明：

1. 默认关闭时无任何索引副作用，手输命令得到开启与重启说明。
2. 开启后 TUI/Web 通过同一 `/code-index` 状态完成建立、同步、状态、重建、取消与确认删除。
3. 只创建 `.harness-index/`，Git 状态干净，删除范围精确。
4. 只有匹配的 1.1.6 主包、平台包和随包 Node 通过 preflight；失败不影响 Harness 其他能力。
5. 健康索引在干净重启后自动恢复查询/watcher，异常退出后保守进入 incomplete 并要求重建。
6. 后续 Run 取得 `codebase_explore`，失败可回退，编辑前仍重新读取 Snapshot。
7. Run 租约、job、generation 与通知在竞争和取消下保持 invariant，不出现双 job、热切换或永久 running。
8. 界面不显示供应商名称或实验标签，不伪造百分比；开发依赖与许可证仍保留真实出处。
9. 自动化平台契约、当前 macOS 真实闭环和三类仓库效果/资源数据齐全。
