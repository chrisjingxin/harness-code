# HC-218 会话只读与主动同步 — 行为规格与接口定义

> 状态：**草稿，待评审**。先确认本规格与对应的 Plan / Todo，再进入停点 1 实施；不自动修改服务端实现、Runner 内部同步机制与 ACP 运行时。

## 1. 目标与范围

### 1.1 现状痛点与解决思路

目前桌面端只完成了左栏与项目资料壳层（[HC-217](../task/HC-217-项目导航与资料.md)）：`desktop-workbench.tsx` 中的会话来源仍指向不可用占位，旧的 HC-202 会话模块仍然按已下线的工作区级长连接与旧契约工作（[collaboration-client.ts](../../../apps/desktop/src/main/collaboration-client.ts) 与 `workbench-contracts/src/conversation.ts`），不能适配多人项目协作模型（同账号其他设备会话与他人的会话都必须只读、正文必须由用户主动同步、新会话在客户端自选任意本机目录即可准备）。

本任务在独立模块 `apps/desktop/src/renderer/features/session/` 以及共享前端契约/宿主适配层实现：

1. **区分新会话准备、本人本机会话与跨机器只读会话（含同账号其他设备）**：切换项目不自动建会话、不强制绑定仓库或 Git 目录，也不自动下载别人或自己其他设备的会话正文。
2. **明确的主动同步与个人阅读状态机**：远端会话先只展示元数据与简报；仅在用户主动点击「同步会话」或「同步更新」后按已确认水位拉取定稿消息与工具摘要，并分别展示「未同步 / 同步中 / 已同步 / 有更新 / 同步失败」五种本机同步状态。
3. **复用既有中央对话与本机文件面板**：本机会话复用 `@workbench/ui` 的 `ConversationView` 与 `ProjectDock` / `ProjectFileTab` / `ProjectFilePanel`（支持普通非 Git 目录只读浏览）；远端只读会话复用只读时间线，不展示输入框与右侧实时文件区。
4. **如实表达本机 Agent / ACP 前置边界**：真实发送、取消、同步上传与 Runner 调度消费同事已交付宿主端口；在运行内核或当前设备登记未交付时明确提示不可用并保留用户输入草稿，绝不用假回复或模拟定时输出冒充执行。

## 2. 行为规格

### 2.1 三类会话页面的模式判定

根据当前导航页面 `ProjectPage`、当前登录账号 `currentUserId`、以及本机设备当前已登记状态中的 `localDeviceId`（未登记或已吊销时视为 `null`），会话提供者唯一确定当前中央渲染模式：

| 入口条件 | 模式 | 关键判定规则 |
| --- | --- | --- |
| `page.kind === "new"` | **新会话准备页** | 不读取远端会话正文，不自动创建云端会话 |
| `page.kind === "conversation"`，且归属本人本机 | **本人本机会话** | `conversation.ownerUserId === currentUserId` 且 `localDeviceId !== null` 且 `conversation.deviceId === localDeviceId`（含尚未在云端登记完成的本地新建暂存会话） |
| `page.kind === "conversation"`，非本人或非当前本机 | **跨机器只读会话** | `conversation.ownerUserId !== currentUserId` **或** `localDeviceId === null` **或** `conversation.deviceId !== localDeviceId` |

> **关键不变量**：同一个账号在不同电脑上的会话，因为 `deviceId !== localDeviceId`，在本机**一律按只读模式展示**（徽标明确显示「其他设备 · 只读」或合并同步提示），绝不开放输入栏、目录编辑或远程控制对方设备。

### 2.2 新会话准备页（`page.kind === "new"`）

输入 → 判断 → 执行 → 输出：

1. **界面构成**（对齐 [视觉预览](../../../docs/developer/previews/project-collaboration/README.md)）：
   - 标题「今天想推进什么？」与副标题「在“{当前项目名称}”中创建自己的会话。」
   - 目录选择按钮：未选显示「选择文件夹」，已选显示目录末段名称，悬停显示完整本机路径；点击调用宿主原生目录选择器 `window.workbench.chooseDirectory()`。
   - 状态说明芯片：清晰展示当前工作方式与本机 Agent 可用状态：
     - 若本机执行器/ACP 未接入或设备未登记：明确标示（例如 `Agent 暂不可用 · 可先选目录并保留草稿` 或 `本机设备未登记，暂不可发起云端协作会话`）。
   - 多行输入框（随草稿持久化，切换页面、切换项目、重开不丢失）与「开始会话」按钮。
   - 底部提示：「目录由你选择，可以是普通文件夹。」
2. **目录绑定约束**：
   - 允许选择普通非 Git 文件夹；不强制包含 `.git`，也不将此目录提交为团队仓库。
   - 所选目录仅绑定到本台电脑的本人范围（通过 `PersonalStore` 隔离持久化），不回传绝对路径给其他成员。
3. **「开始会话」执行判定**：
   - 若未选择目录或输入为空白：按钮禁用。
   - 点击「开始会话」：
     - **情况 A（本机尚未登记未吊销设备，或云端登记失败）**：保留目录与草稿内容，提示清晰原因（如设备未登记 / 网络失败），不生成假会话记录。
     - **情况 B（已登录且已拥有可用 `localDeviceId`，但本机 Agent/ACP 执行端口未交付）**：先按 `requestId` 幂等调用 `POST .../conversations` 为本人登记云端会话元数据并绑定本地目录；登记成功后切入该会话的本人本机页并带入草稿文本与目录，同时在输入区明确说明「本机会话已就绪，Agent 执行内核尚未交付，暂不能发送执行」；登记失败则保留在准备页与原草稿，允许重试。
     - **情况 C（设备已登记且本机 Agent/ACP 执行端口可用）**：登记会话元数据、切入本人本机会话并提交输入流（由执行端口接管；不假装同步完成）。

### 2.3 本人本机会话（`local-session-page`）

1. **顶栏与工作目录条**：
   - 通过 `ProjectPageProvider.context()` 向三栏壳层输出当前会话标题、当前设备名称、当前项目名称与协作提示。
   - 在时间线上方显示当前绑定工作目录（显示末段名称与「本机」标签），允许用户通过「切换工作目录」重新选择本机目录；如尚未绑定目录，引导点击「选择文件夹」。
   - 若会话关联了云端已登记 ID，显示「Project 内共享（仅上传定稿摘要与消息，不同步本机未选目录）」提示。
2. **对话时间线与输入区**：
   - 中央区域复用 `ConversationView`，个人滚动位置、工具展开状态、草稿、引用选择全部按 `{ namespace, accountId, workspaceId, projectId, conversationId }` 持久化在 `PersonalStore`。
   - **真实执行边界**：`composer.send` 与 `composer.cancel` 的可用性严格来自 `LocalSessionExecutionPort.getAvailability()`：
     - 当 ACP / Runner 执行宿主尚未接入（当前默认阶段），`send` 与 `cancel` 处于禁用态并在输入框提示「Agent 执行内核尚未交付，暂不能发送或取消」；用户输入文字与 `@` 候选选择、添加引用仍可正常运行并保存草稿。
     - 当后续同事交付执行端口时，按 `ConversationActions.onSend` 语义提交并返回 `{ status: "accepted" | "rejected" | "unknown" }`。
3. **右侧本地文件/变更与中央文件页签**：
   - 仅当 `visible === true` 且处于本人本机会话且已绑定授权目录时，向壳层 `right(slot)` 返回 `@workbench/ui` 的 `ProjectDock`；未绑定目录时返回引导卡或可收起空状态；处于远端只读会话时 `right(slot)` 一律返回 `null`。
   - 中央区域支持在「对话」与本机「打开的文件页签」之间切换（复用 `ProjectFileTab`、`ProjectFilePanel`），文件页签与左右开关宽度按 `sessionWorkspace` 保存在本机。
   - **非 Git 目录宽容度**：在普通文件夹中，文件树、`@` 文件候选与文件正文预览全部可用；切换到「变更」标签时若检测到当前目录无 `.git` 仓库，展示温和状态「当前目录不是 Git 仓库，仅提供本地文件浏览」，不抛异常。
   - Git 写入口（`commit` / `push`）按设计决策保持禁用并注明「Git 写操作暂缓」，仅保留本地只读状态与差异浏览。

### 2.4 跨机器只读会话与主动同步（`remote-session-page`）

1. **五种本机同步状态**（针对远端会话按 `{ accountId, workspaceId, projectId, conversationId }` 独立保存）：
   - `unsynced`（**未同步**）：本地已同步序号 `localSyncedSequence === 0` 且云端水位 `remote.syncedSequence > 0`；
   - `empty_remote`（归类展示于未同步视图，文案区别）：云端水位 `remote.syncedSequence === 0`，表示原设备尚未上传任何消息正文；
   - `syncing`（**同步中**）：用户点击「同步会话」或「同步更新」后正在发起分页拉取；
   - `synced`（**已同步**）：`localSyncedSequence >= remote.syncedSequence` 且本地保存了已下载消息（若 `remote.syncedSequence === 0` 且已确认刷新过亦可视为最新但无正文）；
   - `has_update`（**有更新**）：本地已有正文（`localSyncedSequence > 0`），且最新简报水位 `remote.syncedSequence > localSyncedSequence`；
   - `sync_failed`（**同步失败**）：最近一次主动拉取失败；**保留原有已下载正文与本地序号不变**，允许重新点击同步。
2. **未同步态展示（绝不自动下载正文）**：
   - 顶部只读头：会话标题、拥有者姓名、来源设备名（如无可解析设备名则回退显示受限标识或「其他设备」）、`只读` 徽标、更多按钮（或刷新元数据按钮）。
   - 简报卡：
     - 「会话简报」标签及简报来源标注（`规则摘要` / `Agent 摘要`）；
     - 简报正文 `briefText`（为空时显示「原设备暂未生成简报摘要」）；
     - 元数据事实：最近更新时间（`briefUpdatedAtMs` / `updatedAt`）、已上传消息序号提示（`已上传至第 N 条消息`）、关联仓库芯片（`repositories`）。
   - 主动同步触发卡：
     - 文案：「正文尚未同步到这台电脑 —— 主动同步后，查看已上传的对话和工具摘要。」（若 `remote.syncedSequence === 0` 则提示「原设备暂未上传消息正文」，提供「刷新简报」而非无效下载提示）；
     - 主按钮：「同步会话」（进行中显示「正在同步…」，防重复点击）。
   - 安全承诺脚标：「查看会话不会操作对方的 Agent 或文件。」
3. **已同步态与增量更新**：
   - 顶部条展示同步进度提示：「已同步至第 N 条消息 · 最近同步于 {时间}」（有更新时提示「发现新消息（云端已上传至第 M 条），点击右上角同步更新」），并提供「同步更新」按钮。
   - 正文复用 `ConversationView`（`composer.primaryActions = "none"`，`send` 与 `cancel` 禁用，`onSend` 与 `onPersonalChange` 仅允许滚动、工具折叠、输出折叠与复制，**隐藏输入表单区**或严格只读）。
   - `HistoryMessage` 解码为时间线条目规则见 §3.3。
4. **底部只读操作栏**：
   - 常驻只读提示：「跨机器会话仅供阅读」。
   - 两个协作出口按钮：
     - 「创建任务」：触发可选回调 `SessionIntegrationHooks.onCreateTaskFromConversation(conversation)`（由 [HC-219](../task/HC-219-引用任务与团队知识.md) 接入弹窗/表单；未接入时清晰提示「任务创建将在项目任务功能接入后可用」）。
     - 「引用到我的会话」：触发可选回调 `SessionIntegrationHooks.onQuoteConversation(conversation)`（若已由 HC-219 接入则进入选会话/固定引用流程；未接入或仅本地直接引用时支持通过 §3.5 接点带入本人新建草稿并在 UI 如实标注尚未对接固定快照服务）。

### 3.2 主进程 HTTP、IPC 与已下线管道替换

### 3.3 `HistoryMessage` 解码与防错规则

后端 `HistoryMessage` 字段为 `{ sequence, type, occurredAtMs, payload }`，其中 `type ∈ { "user", "assistant", "tool_summary", "status" }`，`payload` 为 JSON 字符串（见 [ConversationSyncAppServiceTest.java](../../../services/collaboration-server/src/test/java/workbench/collaboration/application/service/ConversationSyncAppServiceTest.java) 与 [ConversationDtos.java](../../../services/collaboration-server/src/main/java/workbench/collaboration/interfaces/dto/ConversationDtos.java)）。

前端解码映射约定（防御性解析，任何畸形 JSON 不抛出崩溃）：

| `type` | 解析字段优先级 | 映射到 `ConversationTimelineEntry` |
| --- | --- | --- |
| `"user"` | `json.text ?? json.content ?? rawPayload` | `{ kind: "message", role: "user", text, createdAtMs: occurredAtMs, author: 会话所属成员信息 }` |
| `"assistant"` | `json.text ?? json.content ?? rawPayload` | `{ kind: "message", role: "assistant", text, createdAtMs: occurredAtMs }` |
| `"tool_summary"` | `label = json.label ?? json.toolName ?? json.name ?? "工具调用"`, `summary = json.summary ?? json.detail ?? json.text`, `status = "completed" \| "failed" \| "running"` (默认 `"completed"`), `tone = "read" \| "write" \| "neutral"` (默认 `"neutral"`) | `{ kind: "tool", label, originalName: json.name, summary, status, tone, detail: { outputText: json.summary ?? rawPayload, copyText: rawPayload } }`（严格按 D2 只显示摘要字段，不伪造未上传的完整文件正文） |
| `"status"` | `text = json.text ?? json.message ?? json.status ?? rawPayload` | `{ kind: "message", role: "assistant", text: "状态更新：" + text, createdAtMs: occurredAtMs }` 或轻量结构化扩展条目（保证按原 `sequence` 顺序渲染） |

**增量拉取与序连续校验**：
- 主动拉取时传入 `afterSequence = localSyncedSequence` 与固定页限 `limit = 200`；
- 对返回消息过滤出 `sequence > currentMaxSequence` 并验证单调递增，若发现非递增或负数序号立即视为 `INVALID_SERVER_RESPONSE` 并中止本次更新，保留已有缓存；
- 若单次返回满页（`messages.length === 200`）且末尾 `sequence < response.syncedSequence`，继续以最新 `sequence` 翻页补拉（设置安全轮次上限防无限循环），直到不再推进或到达服务端水位；
- 更新本地缓存水位 `localSyncedSequence = Math.max(currentMax, response.syncedSequence)` 与同步时间戳。

### 3.4 `PersonalStore` 键结构与安全升级

接手并升级 [personal-host.ts](../../../apps/desktop/src/personal-host.ts) 与 [personal-store.ts](../../../apps/desktop/src/main/personal-store.ts)：

1. **`kind: "conversation"`**：
   - Key：`{ kind: "conversation", workspaceId, projectId, conversationId }`（支持本项目内所有远端只读会话与已登记的本机会话）。
   - 鉴权：主进程调用 `getProjectConversation(workspaceId, projectId, conversationId)` 验证访问权限后再读写磁盘文件，失败即拒绝并返回用户提示。
   - Value：包含 `scroll`、`expandedTools`、`expandedOutputs`、`draft`、`interactions`、`localDirectoryPath: string | null`，以及可选远端正文缓存 `syncCache: { syncedSequence: number; syncedAtMs: number; messages: HistoryMessage[] } | null`。
   - **1MB 单文件容限不变量**：写入前检查序列化大小；若因超长远端历史导致 JSON 超出 800KB 安全阈值，优先按最早消息裁剪内存中持久化的历史快照并置 `cacheTruncated = true`（确保 `scroll`、`draft` 与最新阅读位置永远可正常存盘，再次打开会话时用户可从缓存起点或重新点击同步补全）。
2. **`kind: "sessionWorkspace"`（替代原易混的 `kind: "project"`）**：
   - Key：`{ kind: "sessionWorkspace", workspaceId, projectId, conversationId }`，以 `getProjectConversation` 鉴权。
   - Value：沿用右侧 `ProjectDock` 状态结构（`dockOpen`、`dockWidthPx`、`panel`、`selectedPath`、`fileTabs`、`activeFilePath`）。
3. **`kind: "projectDraft"`**：
   - Key：`{ kind: "projectDraft", workspaceId, projectId }`，以 `getProject` 鉴权。
   - Value：`{ directoryPath: string | null; draftText: string }`，专门用于持久化「新对话准备页」选择的目录与未发送草稿。

## 4. 错误语义

复用 `CollaborationClient` 已有的 `CollaborationError.code` 映射为用户可读提示，前端不自创错误码或隐藏失败：

| 错误码 / 场景 | 出现位置 | 用户看到提示与保留规则 |
| --- | --- | --- |
| `RESOURCE_NOT_FOUND` | 获取会话列表/详情/历史或项目已失效 | 提示“会话不存在或当前账号无权查看”；同步失败保留旧正文，不可访问会话在列表中标明 |
| `PROJECT_ARCHIVED` | 归档项目内尝试新建登记会话 | 提示“项目已归档，不能新建或修改会话”，保留原输入草稿 |
| `DEVICE_FORBIDDEN` / 设备未登记 | 尝试以非本人或未登记设备新建登记会话 | 提示“当前设备未登记或无权用于该操作”，停留在准备页保留草稿与目录 |
| `WORKSPACE_MEMBER_REQUIRED` | 非团队成员读写项目会话 | 提示“请先加入该团队”，同步不覆写已有状态 |
| `NETWORK_UNAVAILABLE` / `SERVICE_UNAVAILABLE` / `TLS_ERROR` | 列表刷新或主动同步历史中断 | 提示原中文错误信息并提供「重试」；保留已有简报与已同步历史，同步态置为「同步失败」 |
| `INVALID_SERVER_RESPONSE` | 响应不符合 `organization` 契约或历史序号非单调递增 | 提示“服务返回数据异常，已中止本次同步”，保留更新前本地状态 |
| 本机目录无权限 / 越界 / 不存在 | 浏览或刷新已绑定的本机文件夹 | 提示“原选择目录不可访问或不存在，请重新选择文件夹”，不影响会话本身查看 |

## 5. 不变量

1. **只读边界绝对刚性**：他人的会话、以及同一账号在**其他设备**（`deviceId !== localDeviceId`）创建的会话，一律不展示发送框、不允许修改标题/目录、不挂载右侧文件面板。
2. **正文绝不静默下载**：进入项目、查看看板、切换成员、刷新元数据或切换页面，**绝不**自动请求 `readHistory`；只有用户在本页明确点击「同步会话」或「同步更新」才发历史请求。
3. **范围与代次隔离**：所有状态以 `{ namespace, accountId, workspaceId, projectId, conversationId }` 键控；账号或项目切换后，旧范围的任何异步返回（列表、详情、历史同步、目录读取）必须立即丢弃。
4. **失败安全保留**：主动同步或刷新失败时，已有简报、已下载的历史正文、用户输入草稿和已选引用不得清空。
5. **诚实表达能力边界**：Agent / ACP 未接入前，不得以本地 `setTimeout` 或假消息冒充 Agent 回复；普通非 Git 文件夹不得强制报错阻塞。
6. **单一组件源与依赖边界**：绝不复制 `ConversationView`、`ProjectDock`、`ProjectFilePanel` 或主题样式；`apps/desktop` 严格遵守 `check-boundaries.mjs` 允许依赖集合。
