## 1. 目的和边界

旧 Web 已有经过调整的冷紫浅/深主题、头像、Markdown 和代码阅读体验，但它们分散在 CLI 的 Web 页面中；独立桌面目前仍是 HC-193 的绿色临时基础页面。把整份旧 CSS 搬过来会混入对话、文件、导航和 Harness 特有视图，也会与临时主题互相覆盖。

本任务把**真正公共**的颜色、品牌/图标、头像、Markdown、代码块、高亮及少量纯显示工具迁到 `packages/workbench-ui`，让后续区域使用同一套基础。保留旧 Web 已确认的外观和交互，以其最终生效样式为依据；不把 HC-193 基础页面当作最终设计，也不重画中央对话或右侧面板。旧源码和设计稿继续保留，供其他任务迁移；迁移到新产品后，新实现是该产品的唯一公共实现，旧入口及残留由 HC-203 在有替代和集成证据后收口。

- HC-205 负责 `theme/`、`common/`、`rendering/` 及其必要资源、公共出口和开发预览。
- HC-206 迁出 Timeline、工具、Composer、审批/交互视图及其专属样式；HC-207 迁出文件树、阅读器、文件页签及 Git/变更视图；HC-208 新建协作导航与布局。HC-202 负责桌面真实状态与动作装配。
- Harness 专有 Trace、设置、marker 和投影由 HC-201 负责；公共 UI 不解释这些数据。这里不迁对话、文件/Git、导航、Trace，也不改变其业务模型或动作。
- 新包不得运行时导入旧 `packages/cli`、旧 `packages/protocol`、`InteractiveController`、Harness 内部类型、Node 或 Electron；不依赖 Bun、旧 Web server 或开发机绝对路径。可以依赖正式声明的浏览器兼容库及 React，按 package exports 跨包消费。

## 3. 主题、样式与 HC-193 收敛

### 3.1 唯一颜色入口

桌面和独立预览各在其装配入口**一次**加载 `@workbench/ui/theme.css`；该公开样式入口汇总一套主题变量、最小 reset 和公共组件/渲染样式。组件自身及各区域不能再次建立 light/dark 色板，也不能通过 `packages/cli` 取颜色。对外选择器为 `:root[data-theme="light"]`、`:root[data-theme="dark"]`；未收到宿主状态时使用明确的浅色启动值。区域只引用语义变量，不按组件写死品牌色。

保留原主题的 `--brand` 单点入口、`--bg`/`--surface`/`--text`/`--line` 等基础色、`--action`/`--accent` 派生关系，以及独立的 `--success`、`--warning`、`--danger`、`--diff-*`、`--file-*`、`--syntax-*`。默认浅色背景 `#ffffff`、深色背景 `#19191c`；默认品牌改变时，按钮、焦点、链接和标志随之变化，正文背景、状态、Diff 和文件类型色不跟着变。浅深主题的对应变量集合完整，深色实心行动按钮保留品牌底和白字。

旧色表中 `--trace-*` 和 Harness 专有 `--compose-*` 必须逐项登记给 HC-201/206 的实际所有者：它们不能带入公共业务逻辑，也不能为了三个区域各复制一份色表。真正需要保留的额外语义色仍只有一处定义，消费方引用；Trace 专有映射及其可读性由 HC-201 接续，不提前迁其视图。默认颜色沿用旧主题的必要文字对比度要求；品牌被替换时需重新检查对比度，不能声称任意品牌色都自动合格。

`Workbench` 已根据 `WindowState.colorScheme` 写入 `document.documentElement.dataset.theme`；继续由同一个宿主状态决定网页颜色，`system`、`light`、`dark` 的选择和现有缩放行为不变，不增加新的持久化承诺。启动、系统主题变更、用户切换均为 `宿主实际状态 → 根节点 light/dark → 同一组变量`。不再使用旧 `.web-shell` 作为主题前提。

当前 Electron 的 `window.ts` 和 `desktop-ipc.ts` 还分别写有临时绿色的窗口背景、Windows 标题栏颜色。实施时必须把这些原生颜色和网页背景/文字收敛到同一颜色来源：以本主题唯一颜色定义为源，在构建时提取浅/深背景和文字生成无 React、无 DOM 依赖的原生色值产物，通过明确公开的纯数据入口交给 main；生成物不是第二份手工维护色表。原生窗口创建与主题通知使用同一产物，浅/深切换时与网页一致。若提取或产物加载方式尚未经统筹确认，不得继续把两套常量当成已收敛。

### 3.2 样式归属和加载

最小公共 reset 只负责盒模型、基础字体继承、页面默认 margin 和可访问焦点等全局基础；旧 `html/body/#root` 高度与 `overflow: hidden` 等布局假设须由实际桌面布局决定，不能原样全局套用。公共按钮、图标按钮、可访问隐藏文字以及 Markdown、代码块、语法色带各自明确作用域；避免无条件的 `main`、`h1`、`h2`、`footer`、`button` 样式影响其他区域。组件类名可以迁移成带公共前缀的选择器，但最终视觉需与旧页面最后生效的规则一致。

旧 `styles.css` 的分区迁移按规则而不是行数截取：

| 部分 | 归属与约束 |
| --- | --- |
| reset、字体/尺寸变量、明确通用的按钮和焦点 | HC-205；去除混在选择器列表里的区域类名，保留键盘可见焦点和减少动画偏好 |
| `.markdown*`、`.code-block*`、`.syntax-*`、围栏内 `.diff-code-*` | HC-205；作用在公共渲染组件或明确标记的高亮容器内；围栏 Diff 不等于完整 Git/审批 Diff 视图 |
| `.timeline*`、`.message-*` 的排版、`.tool-*`、`.interaction-*`、`.composer-*` | HC-206；头像**图形**来自 HC-205，消息缩进、工具展开和输入区域由 HC-206 保持 |
| `.file-*`、`.context-dock*`、文件预览/页签、`.git-*` | HC-207；文件类型/语法/Diff 颜色可引用公共变量，文件树及行号/交互样式不迁进通用代码块 |
| `.desktop-workspace`、顶栏、工作区/设备/会话导航、响应式分栏 | HC-208；旧左侧单机会话状态不迁入公共模块 |
| `trace/trace.css`、Trace 专属色和 Harness 设置/投影 | HC-201；不由公共基础识别或复制 Trace 类型 |
| 对话框基础与多个区域混合的 hover、滚动条、媒体查询 | 公共且没有业务依赖的部分由 HC-205 抽取；其余随实际区域迁移。后面的覆盖规则要一起核对，不能只按首段 CSS 判断 |

实施收敛时，将现有 `--panel`、`--border`、`--soft` 和设备页面的 `--wb-surface`、`--wb-border` 用实际语义映射迁到统一 `--surface`、`--line`、`--accent-soft` 等；身份/设备页面的按钮、表单、失败提示及布局应仍可使用。删除临时色表和不再需要的颜色 fallback，不长期保留新旧变量双套别名。基础页原有布局样式限定在其容器，等对应后续任务替换，而不是在 HC-205 重画整个桌面。

## 4. 公共出口和动作契约

业务只通过 `@workbench/ui` 的显式 exports 消费，不跨目录引用 `src` 或旧 CLI。样式为 `@workbench/ui/theme.css`；原生色值是独立纯数据子入口，供桌面 main 消费，不能迫使 main 加载 React/CSS。具体导出文件和共享 `index.ts` 由统筹顺序集成。

```ts
import type { ReactElement, ReactNode } from "react"

// 两个动作都只在用户明确操作时调用；缺失表示当前宿主没有该能力。
type RenderingActions = {
  copyText?: (text: string) => Promise<void>
  openExternal?: (href: string) => Promise<void>
}
type MarkdownProps = { text: string; actions?: RenderingActions }
type CodeBlockProps = { code: string; language?: string; actions?: RenderingActions }

// Markdown / CodeBlock 分别接收以上 props；HighlightedCode 只负责代码文本和高亮。
declare function Markdown(props: MarkdownProps): ReactElement
declare function CodeBlock(props: CodeBlockProps): ReactElement
declare function HighlightedCode(props: { code: string; language: string | null }): ReactElement
declare function BrandMark(): ReactElement
declare function RoleAvatar(props: { kind: "assistant" | "user" }): ReactElement

// 仅供审批等必须逐行组合的视图；范围基于 UTF-8 字节，右边界不包含。
type SyntaxScope = "comment" | "keyword" | "function" | "variable" | "string" | "number" | "type" | "operator" | "punctuation" | "tag" | "attribute" | "constant" | "plain"
type SyntaxSpan = { readonly startByte: number; readonly endByte: number; readonly scope: SyntaxScope }
type HighlightResult =
  | { status: "plain" | "loading"; spans: null }
  | { status: "highlighted"; spans: readonly SyntaxSpan[] }
declare function useSyntaxHighlight(input: { code: string; language: string | null }): HighlightResult
declare function renderSpans(code: string, spans: readonly SyntaxSpan[]): ReactNode

type LanguageId = "javascript" | "typescript" | "jsx" | "tsx" | "json" | "python" | "bash" | "go" | "java" | "c" | "cpp" | "html" | "css" | "yaml" | "markdown" | "plaintext"
declare function resolveLanguage(input?: string | null): LanguageId
declare function resolveLanguageForPath(path?: string | null): LanguageId
declare function formatDuration(ms: number | undefined): string | undefined
declare function formatElapsed(ms: number): string
declare function formatUsage(usage: { inputTokens: number; outputTokens: number } | undefined): string | undefined
declare function formatContext(estimatedTokens: number | undefined, inputCapTokens: number | undefined): string | undefined
```

上面的组件、函数及其参数/结果类型是拟议的具名公开出口，内部 Worker 协议不公开。`resolveLanguage`、`resolveLanguageForPath` 对外只提供与 Web 渲染有关的规范语言结果；空/未知语言为 plaintext，路径只作字符串判断，不访问磁盘。格式化时长/数字的函数只接受数值，不接受会话快照。对 `renderSpans`，调用方须给与当前 `code` 对应的范围；逐行切片时先正确换算每行 UTF-8 偏移，再在 `className="wb-syntax"` 容器内渲染。`HighlightedCode` 和 `CodeBlock` 自行提供同一作用域；一般文件视图直接用 `HighlightedCode`，不复制 worker 或颜色映射。

`BrandMark`、`RoleAvatar` 只是图形；消息作者名、时间、位置和含义由区域负责。装饰性 SVG 隐藏于辅助技术，独立表达身份时由调用方提供可读标签。其他公共图标可复用已声明的图标库，不把全部图标包装成新抽象。

扩展视图插槽的最低边界为：区域视图接收调用方传入的 `ReactNode`，不接收 Harness Span/marker 或通过 Agent 名称分支解析内容；区域负责决定插槽位置，HC-202/201 负责可选扩展的注册和装配，移除扩展仍可显示通用视图。具体插槽位置、注册与卸载生命周期须由 HC-201/206/202 共同审查，不能在本稿中假称已有通用注册系统，也不能为了占位把专有数据结构写进 HC-205。

### 4.1 复制和链接

- `copyText` 只接收代码原始 `code` 字符串，成功 resolve 后才显示“已复制”；拒绝或异常显示“复制失败，请手动选择代码”，保留文本可选择，并用 `aria-live` 报告。显示中的高亮、防抖和 Diff 样式不能改变复制文本。无回调时按钮不可用并给出可读提示，不能假报成功。
- Markdown 只把绝对 `http:`、`https:`、`mailto:` 解析成可触发链接；`javascript:`、`data:`、`file:`、相对及无效地址只显示文本。允许的地址经用户点击或键盘激活后阻止默认导航，再交给 `openExternal`；回调失败显示可读失败状态，无回调时显示不可操作的链接文本。不得自动打开或退回不受控 `window.open`。
- 停点二通过 `DesktopHost.copyText` 和 `DesktopHost.openExternal` 接入桌面剪贴板及外链。主进程复用可信窗口来源校验并重新检查参数和 URL 协议。桌面仍由 `setWindowOpenHandler` 拒绝新窗口、由 `will-navigate` 阻止页面导航。组件预览以真实端口核对复制结果。

## 5. Markdown 和代码高亮行为

Markdown 使用旧实现的 GFM 解析能力，保留标题、段落、强调、链接、列表/只读任务框、引用、表格、行内代码、围栏代码和 Diff 增删样式。原始 HTML 始终作为文本，图片只显示 alt，不生成图片请求；不能把 Markdown/模型输出作为 HTML 注入 DOM。解析失败时显示原文；无法识别的 token 保留其可读文本。代码块初始和高亮不可用时先显示可选择的原文，流式更新只延迟高亮计算，不能丢字或继续把旧文本的高亮范围用到新文本。

旧高亮 Worker 用 `shiki/core`、JavaScript 正则引擎和静态导入资源：15 种语言（JavaScript、TypeScript、JSX、TSX、JSON、Python、Bash、Go、Java、C、C++、HTML、CSS、YAML、Markdown）加 plaintext，保留已有别名及按扩展名识别。语法范围转换为受限 class，再由浅/深语义色着色；颜色主题不允许绕开公共 CSS 另建第三套界面色。中文、emoji 等多字节文本必须按 UTF-8 字节边界映射回原字符串；非法、交叉或过界范围退回原文。

沿用原服务的基本保护和可观察行为：单段超过 64 KiB 或 2000 行、未知语言、Worker 创建/加载/解析失败、约 1500ms 超时均显示纯文本，复制仍可用；连续超时/致命错误达到 3 次后停止反复启动，界面保持可读。服务缓存最多 128 项/4 MiB，视图侧小缓存有界；缓存键必须核对完整代码、规范语言及实际使用的高亮主题，不允许仅凭 32 位哈希把另一段代码的高亮误用到当前内容。卸载或输入变化后丢弃迟到结果，最后使用者结束时释放 Worker 和待处理请求。

### 5.1 Worker 构建与资源定位

当前旧服务默认 `/web/syntax-worker.js`，另有 ACP Web 的 `/assets/syntax-worker.js`；这两个路径都依赖旧服务，不能进入新产品。`workbench-ui` 当前构建仅由 `tsc` 生成 JS/声明并复制 CSS；它并不会自动替新包打出 Shiki Worker。新方案必须同时满足：

1. 新包包含 Worker 源、语言目录和正式声明的 `shiki` 依赖；`marked`、`lucide-react` 也由新包声明。旧 CLI 当前分别使用 `shiki@3.23.0`、`marked@17.0.1`、`lucide-react@1.16.0`，新包的实际版本、与现有 React 的兼容性和根锁由统筹协调。不得从旧 CLI 的依赖树或构建产物取库。
2. 使用构建工具可静态识别的模块 Worker 入口和相对于模块的资源引用，例如最终 JS 中的 `new Worker(new URL("./worker.js", import.meta.url), { type: "module" })`；由 electron-vite 把 worker 及其静态语言/主题资源打入 renderer 产物。实际构建应检查该写法被识别，并以最终输出为准，不能把示例当作已验证结论。
3. 开发服务和生产 `file://` 页面均从当前产物定位 Worker；不引用 `/web/`、`/assets/` 旧服务、机器绝对路径或远端 CDN，不在运行时下载语言、主题或 WASM。检查资源加载与现有 CSP、sandbox 相容；若需调整 CSP，先由统筹审查最小变更，不解除隔离或放开任意来源。
4. 在真实 Electron 的**构建后本地页面**观察至少一个已知语言出现语法色，并确认实际 Worker 从本次构建产物加载、无旧服务/网络请求；只看到纯文本不能当作 Worker 成功。另观察未知语言降级和复制真实结果。

## 8. 统筹审查结论（2026-11-09）

统筹已对照当前主题、Markdown/代码块、高亮协议、文件阅读器及逐行审批 Diff 的消费方式，并检查 Electron 窗口、preload、DesktopHost 和包边界。公共资源拆分和第 4 节接口通过，按以下决定进入 Plan/Todo；本节不表示生产实现已完成。

1. **一个主题来源，同时覆盖网页和原生窗口。** 接受从公共 CSS 颜色定义生成原生浅/深背景、文字数据的方案；公开纯数据入口固定为 `@workbench/ui/native-theme`，main 只消费该入口，不导入 React/CSS。窗口创建和后续主题通知均使用同一产物，不能只修网页或在 main 再手写一份色表。Plan 写明生成脚本、产物、构建顺序及共享文件清单，用小型构建脚本完成，不另建通用主题编译框架。
2. **本任务补齐必要宿主动作。** 公共组件继续只消费可选 `RenderingActions`。桌面装配通过具名 `DesktopHost.copyText(text): Promise<void>`、`DesktopHost.openExternal(href): Promise<void>` 接入真实剪贴板与外链；main 重用现有可信主窗口来源校验，重新检查参数及允许的 URL scheme，再调用原生能力。失败拒绝 Promise，由组件如实反馈；不开放导航、权限或通用 IPC，也不同时维护浏览器与原生两条生产 fallback。契约、preload、IPC 与实际注入列入本任务共享改动，在实施派发时统一授权串行修改，不等 HC-202 才解决公共组件所需动作。开发预览中的假动作不能充当真实复制证据；必要原生冒烟不自动打开任意第三方网址。
3. **保留满足既有消费者的高亮出口。** `HighlightedCode` 供文件阅读器组合，`useSyntaxHighlight`、`SyntaxSpan`、`renderSpans` 供审批逐行组合，UTF-8 范围规则沿用既有实现。公共组件只延迟高亮计算，始终展示当前代码；高亮与复制不能借用过期代码的范围。Worker 必须从本次构建产物加载，先验证现有 CSP；只有实际需要时再审查最小的 Worker 来源声明，不放宽脚本来源或关闭 sandbox。
4. **下游尚未认领不阻止本任务。** 本轮由统筹按现有中央和右侧消费者代表 HC-206/207/208 完成公共接口审查，不为此启动其他任务。后续区域可以接收调用方的 `ReactNode`，但具体插槽位置、注册/卸载属于 HC-201/206/202，HC-205 不建立占位扩展系统。Trace/Compose 专有 token 由对应模块单独定义并优先映射公共基础色，本任务不声称已迁移其视图或完整专有色表。
5. **按可演示停点交付。** 先交付公共主题与品牌，再交付 Markdown、高亮和宿主接线，最后收敛基础页面并做构建后原生冒烟。每个停点完成必要的构建、类型、边界和主流程验证。完整区域组合、Windows 与整体回归留 HC-204。共享文件按 Plan 中的停点由统筹串行派发。
