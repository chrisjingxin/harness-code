## 2. 数据与分层

[唯一 schema](../../../services/collaboration-server/src/main/resources/db/schema.sql)由开发者或运维显式执行。Java 启动只读检查结构，检查失败输出缺失或残留清单并拒绝启动。

当前 19 张表按用途如下。

| 用途 | 表 |
| --- | --- |
| 身份与团队 | wb_user、wb_user_org、wb_org、wb_workspace、wb_workspace_member |
| 组织层 | wb_repository、wb_project、wb_project_member、wb_project_repository |
| 会话 | wb_conversation、wb_conversation_repository |
| HC-212 共享增量 | wb_snapshot、wb_task、wb_task_transition、wb_task_link、wb_task_request、wb_knowledge_item、wb_knowledge_version、wb_notification_outbox |

Foundation 核对必需表、关键列、InnoDB、utf8mb4 和自增物理主键。时间使用 DATETIME(3)，状态使用数值码，接口仍使用已有字符串枚举。数据库规范和完整列定义由 schema.sql 维护。

已移除的 wb_device、wb_local_repo_binding、旧 execution 流水与共享目录表列进入启动拒绝清单。会话保留 project、owner、status、brief、synced_sequence 及时间字段。会话所属人固定为创建者，关联仓库必须来自项目已引用集合，目录位置留在本机。

继续使用领域、应用、基础设施、接口四层。ProjectAccessPolicy 统一授权，ConversationAppService 负责登记及读取，ConversationSyncAppService 负责上传，基础设施端口承担消息热窗、检索索引与轻量通知。

## 3. 当前公开接口

以下路由统一以 /api/v1 为前缀。响应使用 BeeResponseEntity 包络，类型和字段以 [organization schema](../../../packages/workbench-contracts/schema/organization.schema.json)及 [ProjectConversationController](../../../services/collaboration-server/src/main/java/workbench/collaboration/interfaces/rest/ProjectConversationController.java)为准。

用户登录 Cookie 保存在可信客户端。POST / PATCH / PUT / DELETE 经 CSRF 校验，所有业务调用仍遵守 Origin、协议版本及路由白名单规则。

| 方法和路由 | 行为与权限 |
| --- | --- |
| POST /workspaces/{ws}/projects | 团队成员创建业务项目，创建者成为负责人和活跃成员 |
| GET /workspaces/{ws}/projects | 列出调用者参与的项目 |
| GET /workspaces/{ws}/projects/{p} | 活跃项目成员读取详情 |
| PATCH /workspaces/{ws}/projects/{p} | 负责人按 expectedVersion 修改或归档，冲突返回 409 |
| GET /workspaces/{ws}/projects/{p}/members | 项目成员读取成员 |
| POST /workspaces/{ws}/projects/{p}/members | 负责人加入团队成员 |
| DELETE /workspaces/{ws}/projects/{p}/members/{userId} | 负责人移出成员，保留 removed 记录，负责人不能移出自己 |
| GET / POST / PATCH /workspaces/{ws}/repositories[/{repoId}] | 团队仓库目录、唯一地址与归档约束沿用现有实现 |
| GET / PUT / DELETE /workspaces/{ws}/projects/{p}/repositories[/{repoId}] | 项目引用读取及负责人维护 |
| POST /workspaces/{ws}/projects/{p}/conversations | 活跃成员登记本人会话，输入 title、repositoryIds、taskId 与 requestId 按现有契约校验 |
| GET /workspaces/{ws}/projects/{p}/conversations | 项目成员读简报列表，可按 ownerId / status 过滤 |
| GET /workspaces/{ws}/projects/{p}/conversations/{c} | 项目成员读单个简报 |
| POST /workspaces/{ws}/projects/{p}/conversations/{c}/sync | 活跃成员中仅会话创建者可上传定稿消息及简报 |
| GET /workspaces/{ws}/projects/{p}/conversations/{c}/history | 项目成员主动读取 afterSequence 之后的正文，limit 默认 100、最大 500 |

旧设备登记、设备上传、设备心跳、本机绑定、远程 inputs / executions / cancel / requests、会话级正文 events 及 WSS 路由已下线。HC-212 用户级轻量通知继续更新元数据，正文由 history 主动读取。

## 4. 上传、读取与不变量

### 上传

```text
用户带 Cookie + CSRF 提交 Project sync
 → 检查项目归属与活跃成员
 → 行锁读取会话，核对会话在当前项目且 ownerUserId 等于当前用户
 → 校验连续消息批次或确认同批重放
 → 写消息热窗、投递检索索引、更新会话简报及 synced_sequence
 → 产出简报更新通知
 → 返回已确认的 syncedSequence
```

- 序号由本人本机上传端分配。新批首为已确认水位加一，批内逐条加一。跳号返回 409 SEQUENCE_CONFLICT 和 expectedSequence。
- 相同已确认批次重发时返回当前水位，消息和通知保持幂等。客户端响应不明时保留原批次序号及内容重发。
- 消息类型固定为 user、assistant、tool_summary、status。payload 是字符串，单消息上限 32 KiB，批次合计上限 1 MiB。同步接口接收定稿和工具摘要，流式片段在本机归并。
- brief 可携带 status、briefText、briefSource。规则摘要使用 rule，空消息批可只更新简报且保持水位。重放已确认批次保持先前简报与水位。
- 他人的活跃成员账号上传返回 403 CONVERSATION_FORBIDDEN。非项目成员或已移出成员返回 404 RESOURCE_NOT_FOUND。跨项目会话同样返回 404。

### 读取

```text
成员读取简报
 → 展示 owner、status、brief、syncedSequence 等元数据
成员显式 GET history?afterSequence=N&limit=L
 → 检查项目和活跃成员
 → 按序号读取已上传消息，热窗缺段由现有检索存储回源
 → 返回 messages 和当前 syncedSequence
```

afterSequence 采用严格大于比较。请求水位之后的消息应为空。读取只返回已上传内容。本机文件和 Agent 执行入口由桌面及 ACP 对应任务维护。

### 组织层权限

非项目成员及 removed 成员访问项目资源返回 404。活跃成员执行负责人操作返回 403 PROJECT_OWNER_REQUIRED。项目版本冲突、仓库唯一约束、归档限制返回既有 409 错误。成员移出后既有会话可继续由其他活跃成员只读查看。
