# HC-211 协作模型重构与只读同步：行为规格与技术契约

入口：[Task](../task/HC-211-协作模型重构与只读同步.md)、[Plan](../plan/HC-211-协作模型重构与只读同步.md)、[Todo](../todo/HC-211-协作模型重构与只读同步.md)。

## 1. 背景、定位与核心不变量

### 1.1 现状问题与目标

按 [Java 中继调整方案](../project/Java中继调整方案.md)（下称"方案"），协作单位从"一个工作区 + 设备共享目录"改为"团队（Workspace）→ 业务项目（Project）→ 项目引用部分团队仓库（Repository）"；协作方式从"成员远程输入、Java 派发到主人设备执行"改为"各跑各的、只读共享、改动走任务"。`services/collaboration-server` 现有实现有四处根本不适配：

- `wb_device_project` 把"项目"等同于"某台设备上共享的一个本地目录"，无法表达"多人协作的业务项目包含多个代码仓库"；
- `wb_device` 绑死 `workspace_id`，而设备属于用户本人（D11）；
- 远程输入 + execution 派发 + Daemon WSS + 会话级 SSE 违反方案安全不变量（**Java 永远不代表甲方向乙方设备下发会让 Agent 执行或改代码的命令**）；
- Flyway 迁移链在企业内网无落地条件（D7：单文件 `schema.sql` + 启动只读核对）。

### 1.2 核心不变量（Invariants）

1. **单文件 DDL（D7）**：`src/main/resources/db/schema.sql` 是唯一建表依据（本任务声明 11 张表），MySQL 兼容常规语法（无外键、无触发器、无 JSON 列查询、`pk_id` 自增 + 业务 `id` 唯一索引、utf8mb4）；**应用从不执行 DDL**。`Foundation` 启动只读核对：必需表/关键列缺失 → 打印完整清单并拒绝启动；探测到禁止表 → 拒绝启动。
2. **无下行通道（D1）**：设备方向只有"上传自己的状态"（同步、心跳、仓库登记），Java 不向任何设备下发命令；Runner 只执行本机登录用户在本机界面发起的操作。
3. **设备属人不属团队（D11）**：`wb_device` 无 `workspace_id`；设备凭据（`Bearer {deviceId}.{secret}`）的能力边界 = 仓库登记 + 会话同步 + 心跳。
4. **项目成员制授权**：项目内资源读写以"项目活跃成员"为前提；**非项目成员访问项目及其子资源一律 404**（不泄露存在性）；成员做负责人才有的操作 → 403；唯一约束/CAS 冲突 → 409。
5. **会话单写者**：会话序号由主人 Runner 单调分配，Java 只校验连续、幂等去重，绝不代写或代分配；会话正文只在"已上传"范围内可读，不触碰对方设备实时状态（D10）。
6. **团队仓库目录（D3）**：`Repository` 是团队级资产，`(workspace_id, remote_url)` 唯一；归档后不能被新引用，已有引用只读；会话涉及仓库必须是项目引用集合的子集。
7. **沿用 HC-210 底座**：DDD 四层与 `domain` 零框架污染、MyBatis-Plus 持久层、Redis/Kafka/ES 7.6.0 中间件抽象、BoundaryFilter + RouteCatalog 白名单、`ApiProblem` 错误体、IdempotencyPort 幂等键模式全部保留。

## 2. 数据表契约（schema.sql）

`schema.sql` 声明以下 **11 张表**；`db/demo-data.sql` 预置演示数据（可选执行）。

### 2.1 保留不变

`wb_user`、`wb_workspace`、`wb_workspace_member`：列定义与原 V001 一致。

### 2.2 `wb_device`（去 workspace_id）

删 `workspace_id` 列，其余不变：`id`（uk）、`owner_user_id`、`installation_id`、`ledger_id`、`name`、`secret_sha256`、`registration_id`、`registration_body_sha256`、`revoked`、`created_at_ms`、`updated_at_ms`。

### 2.3 组织层新表

| 表 | 列（除 `pk_id` 自增主键外） | 约束与索引 |
| --- | --- | --- |
| `wb_repository` | `id`、`workspace_id`、`name`、`remote_url`、`default_branch`、`status`(`active`/`archived`)、`created_by_user_id`、`created_at_ms`、`updated_at_ms` | `uk(workspace_id, remote_url)`、`uk(id)`、`idx(workspace_id, status)` |
| `wb_project` | `id`、`workspace_id`、`name`、`description`、`owner_user_id`、`status`(`active`/`archived`)、`version`、`created_at_ms`、`updated_at_ms` | `uk(id)`、`idx(workspace_id, status)`、`idx(owner_user_id)` |
| `wb_project_member` | `project_id`、`user_id`、`status`(`active`/`removed`)、`created_at_ms`、`updated_at_ms` | `uk(project_id, user_id)`（状态翻转不删行，D9）、`idx(user_id, status)` |
| `wb_project_repository` | `project_id`、`repository_id`、`created_at_ms` | `uk(project_id, repository_id)`、`idx(repository_id)` |
| `wb_local_repo_binding` | `device_id`、`repository_id`、`created_at_ms` | `uk(device_id, repository_id)`、`idx(repository_id)` |

`wb_local_repo_binding` 只存 `device_id + repository_id`，**本地绝对路径只存本机**（隐私边界）。

### 2.4 `wb_conversation`（新形态）

| 列 | 说明 |
| --- | --- |
| `id`、`workspace_id`、`project_id` | 标识与归属（`project_id` 指向 `wb_project.id`） |
| `owner_user_id` | 主人 = 创建者，固定不变 |
| `device_id` | 主人执行设备 |
| `agent_config_id`、`task_id` | 展示/关联字段，允许 NULL（task 由 HC-212 写入） |
| `status` | `idle`/`running`/`waiting_approval`/`error`，默认 `idle` |
| `title`、`brief_text`、`brief_source`、`brief_updated_at_ms` | 简报字段；`brief_source` ∈ `rule`/`agent`，默认 `rule`（B1 预留） |
| `synced_sequence` | 已确认最大上传序号，默认 0 |
| `native_session_id`、时间戳 | 允许 NULL；`created_at_ms`/`updated_at_ms` |

删 `current_user_id`、`active_execution_id`、`next_sequence`；索引：`uk(id)`、`idx(project_id, updated_at_ms)`、`idx(owner_user_id)`。

### 2.5 `wb_conversation_repository`（会话涉及仓库）

`conversation_id`、`repository_id`、`created_at_ms`；`uk(conversation_id, repository_id)`。会话登记时写入，取值必须是项目已引用仓库的子集（D3）；项目后续取消引用不影响此历史关联。

### 2.6 预留不建

`wb_snapshot`、`wb_task*`、`wb_knowledge_*`（HC-212 建表时直接改 `schema.sql` 并重建库）。

### 2.7 Foundation 启动只读核对

```text
输入：REQUIRED 表清单（11 张）+ 关键列清单 + REMOVED 禁止表清单
判断：逐表核对存在性、InnoDB、utf8mb4、pk_id 自增主键；
      抽查新语义列（wb_device 无 workspace_id；
      wb_conversation 有 owner_user_id/status/brief_source/synced_sequence，
      无 current_user_id/active_execution_id/next_sequence）；
      REMOVED 计数必须为 0
执行：收集全部缺失表/列/禁止表，一次性打印清单
输出：全部满足 → 启动；任一不满足 → IllegalStateException 拒启动，绝不执行 DDL
```

REMOVED = 旧流水表集合 + `wb_device_project` + `wb_handoff` + `wb_message_reference`。

## 3. 接口契约

### 3.1 保留路由（不变或小改）

| 路由 | 调整 |
| --- | --- |
| `/health`、`/api/v1/meta`、`/api/v1/auth/*`、`GET /workspaces`、`GET .../members` | 不变 |
| `POST /workspaces/{ws}/devices` | 仍要求调用者是 `{ws}` 团队成员；不再写 `workspace_id` |
| `GET /workspaces/{ws}/devices` | 返回调用者本人设备（`owner_user_id = caller`），分页游标不变 |
| `POST .../devices/{deviceId}/revoke` | 仅设备所有者本人 |
| `DeviceSummary` DTO | 删 `workspaceId`；`state`/`lastSeenAtMs` 改由心跳键读取（见 §3.4） |

### 3.2 删除路由（整体下线）

会话/执行/共享全组：`conversations`（list/create/detail/inputs/executions/cancel/history/events）、`requests/{requestId}`、`devices/{deviceId}/projects`、`projects/{projectId}/stop-sharing`、`/device/projects`、`/device/channel`（WSS）。其中会话读写在 §3.4 以项目作用域重建。

### 3.3 组织层路由

**业务项目**

| 方法 路由 | 鉴权与语义 | 主要错误 |
| --- | --- | --- |
| `POST /workspaces/{ws}/projects` | 团队成员；`{name(1~80), description(≤2000), requestId}`；创建者为 owner+active 成员 | 400/401 |
| `GET /workspaces/{ws}/projects` | 团队成员；调用者 active 成员的项目列表（含角色、memberCount、updatedAt） | 403 |
| `GET /workspaces/{ws}/projects/{p}` | 项目成员否则 404；详情+成员+仓库引用 | 404 |
| `PATCH /workspaces/{ws}/projects/{p}` | 仅负责人；`{name?, description?, status:"archived"?, expectedVersion}`；CAS `version+1`；归档后写操作一律 409 `PROJECT_ARCHIVED` | 403/404/409 |
| `GET .../projects/{p}/members` | 项目成员；active + removed 列表（removed 带 `updatedAtMs` 供"已离开项目"标注） | 404 |
| `POST .../projects/{p}/members` | 仅负责人；`{userId, requestId}`；目标须为团队活跃成员；已 active 幂等 200；removed 翻回 active | 400/403/404/409 |
| `DELETE .../projects/{p}/members/{userId}` | 仅负责人；置 `removed` 不删行；owner 不能移出自己 409 `OWNER_CANNOT_LEAVE`；removed 立即失去读权且其设备对该项目的 sync 被拒 | 403/404/409 |

**团队仓库目录**

| 方法 路由 | 鉴权与语义 | 主要错误 |
| --- | --- | --- |
| `GET /workspaces/{ws}/repositories` | 团队成员；`?status=active|archived|all`（默认 active） | 403 |
| `POST /workspaces/{ws}/repositories` | 团队成员；`{name(1~120), remoteUrl(1~512), defaultBranch(≤128, 默认 "main"), requestId}` | 409 `REPOSITORY_CONFLICT` |
| `GET /workspaces/{ws}/repositories/{repoId}` | 团队成员；详情+引用它的项目列表（仅调用者可见项目） | 404 |
| `PATCH /workspaces/{ws}/repositories/{repoId}` | 团队成员；`{name?, defaultBranch?, status:"archived"}`；归档后不可被新引用 | 404/409 |

**项目仓库引用**

| 方法 路由 | 鉴权与语义 | 主要错误 |
| --- | --- | --- |
| `PUT .../projects/{p}/repositories/{repoId}` | 仅负责人；仓库同 `{ws}` 且 active、项目 active；已引用 200 幂等 | 403/404/409 |
| `DELETE .../projects/{p}/repositories/{repoId}` | 仅负责人；未引用 404；不影响既有会话历史关联 | 403/404/409 |
| `GET .../projects/{p}/repositories` | 项目成员；引用列表 + `clonedDevices`（调用者活跃设备中已绑定的 deviceId+时间） | 404 |

**设备本机仓库登记**

| 方法 路由 | 鉴权与语义 | 主要错误 |
| --- | --- | --- |
| `PUT /device/repo-bindings/{repoId}` | DEVICE 凭据；仓库 active 且设备 owner 是该仓库团队成员；`(device_id, repository_id)` 幂等 upsert；**拒绝包含本地绝对路径的请求体** | 401/403/404/409 |
| `DELETE /device/repo-bindings/{repoId}` | DEVICE 凭据；不存在 404 | 401/404 |

### 3.4 会话路由（项目内只读共享）

| 方法 路由 | 鉴权与语义 | 主要错误 |
| --- | --- | --- |
| `POST /workspaces/{ws}/projects/{p}/conversations` | 项目成员；`{deviceId, title?, repositoryIds[], taskId?, requestId}`；owner=调用者；deviceId 必须是调用者本人未吊销设备；repositoryIds ⊆ 项目引用集合（否则 400）；taskId 可选（`wb_task` 未建前不校验存在性） | 400/403/404/409 |
| `GET /workspaces/{ws}/projects/{p}/conversations?ownerId=&status=` | 项目成员；会话简报列表（id、owner、title、status、briefText、briefSource、briefUpdatedAtMs、syncedSequence、updatedAt、repositories）；`ownerId` 过滤支持看板按人分组 | 404 |
| `GET .../conversations/{c}` | 项目成员否则 404；单条简报 + 涉及仓库 | 404 |
| `GET .../conversations/{c}/history?afterSequence=&limit=` | 项目成员否则 404；返回 `afterSequence` 之后的消息（`limit` ≤500，默认 100）+ 当前 `syncedSequence`；先查 Redis 热窗、缺段回源 ES | 400/404 |
| `POST /device/conversations/{c}/sync` | DEVICE 凭据且属于会话 owner，否则 403；body `{messages:[{sequence,type,occurredAtMs,payload}], brief:{status,briefText,briefSource}}`；语义见 §4.3 | 401/403/409 |
| `POST /device/heartbeat` | DEVICE 凭据；写 `wb:device:hb:{deviceId}`（TTL 45s），仅用于展示在线；返回 204 | 401 |

**消息类型**（`type` 枚举）：`user` / `assistant` / `tool_summary` / `status`。`tool_summary` 的 payload 只含工具名、目标简述、成败、改动行数等摘要字段，**不含完整输出、文件正文、流式碎片**（D2）。

### 3.5 统一错误语义

沿用 `ApiProblem`：`400` 参数/体校验；`401` 未认证或设备凭据无效；`403` 已认证但角色不足；`404` 资源不存在或非项目成员访问项目资源；`409` 唯一约束、CAS 版本、归档只读、序号冲突。冲突 code：`REPOSITORY_CONFLICT`、`VERSION_CONFLICT`、`PROJECT_ARCHIVED`、`REPOSITORY_ARCHIVED`、`OWNER_CANNOT_LEAVE`、`SEQUENCE_CONFLICT`（响应带 `expectedSequence`）、`DEVICE_FORBIDDEN`。写路径 POST 接受 `requestId` 走 `IdempotentCalls` 幂等键。

## 4. 领域与流程

### 4.1 新增领域包

- `domain/project`：`Project`、`ProjectMember`、`ProjectRepositoryRef`、枚举 `ProjectStatus`/`MemberStatus`。
- `domain/repository`：`Repository`、`LocalRepoBinding`、`RepositoryStatus`。
- `domain/access`：`ProjectAccessPolicy` —— `requireWorkspaceMember`/`requireProject`/`requireActiveMember`（removed 视同非成员→404）/`requireOwner`/`requireRepository`/`requireActiveRepository`/`requireBindingAuthority`（设备未吊销 + owner 是仓库团队成员）/`requireSyncAuthority`（设备属于会话 owner 且该 owner 仍是项目活跃成员，D9）/ `isActiveMember`/`isOwner`。

### 4.2 既有领域调整

- `domain/device`：`Device` 删 `workspaceId`；删 `SharedProject`/`DaemonPresence`/`DaemonPresencePort`/`DaemonCommandPort`；新增 `DeviceHeartbeatPort`（`beat(deviceId)`、`isOnline(deviceId)`、`lastSeen(deviceId)`，仅展示用途）；`listByWorkspace` 改 `listByOwner`。
- `domain/conversation`：`Conversation` 对齐 §2.4；新增 `Brief` 值对象与 `SyncBatch` 校验规则（批首序号 == `synced_sequence+1`、批内连续、type 枚举合法、payload 尺寸上限）；`ConversationRepository` 提供登记/简报/序号推进读写；`MessageStorePort` 保留（热窗写、按序号读）；删 `EventWindowPort`。
- `domain/execution` 整包删除；`domain/identity` 不变。

### 4.3 同步处理流程（ConversationSyncAppService）

```text
POST /device/conversations/{c}/sync
  → requireSyncAuthority：设备凭据有效、设备属于会话 owner、owner 仍是项目活跃成员
  → SyncBatch 校验：序号连续性、type 枚举、payload 上限（单消息 ≤32KB、批 ≤1MB）
  → 幂等：批次首序号 <= synced_sequence → 直接返回当前 synced_sequence（不重复写）
  → 执行：消息写 Redis 热窗（zset，cap 100）→ 更新会话行（status/brief/synced_sequence/updated_at）→ 投递 wb.search.index 异步入 ES
  → 产出 conversation.brief_updated 事件载荷（仅对象 ID + 简报摘要，经 NotificationPort；本任务为本地空实现，HC-212 接 Kafka 投递）
  → 输出：{syncedSequence}；跳号 409 SEQUENCE_CONFLICT{expectedSequence}
```

### 4.4 历史读取流程

```text
GET history?afterSequence=N&limit=L
  → requireActiveMember（非成员 404）
  → Redis 热窗取序号>N 的消息；不足 limit 且热窗缺段 → ES wb_message_v1 按序号翻页
  → 输出 {messages, syncedSequence}；afterSequence 大于已同步值 → 空列表
```

### 4.5 应用层与接口层

- 删：`ConversationAppService`、`ExecutionAppService`、会话/执行控制器与 DTO、`DaemonWebSocket*`、`ConversationSseController`；`DeviceAppService` 删共享项目方法与 presence/executions 注入。
- 新增：`ProjectAppService`、`RepositoryAppService`、`RepoBindingAppService`、`ConversationSyncAppService`（含会话登记/简报/历史）；`ProjectController`、`RepositoryController`、`DeviceRepoBindingController`、`ProjectConversationController`、`DeviceSyncController`。
- `RouteCatalog`：删旧路由与 `OPERATION` 常量，登记全部新路由（query 正则：`status`/`ownerId`/`afterSequence`/`limit` 等沿用并扩展现有模式）。

### 4.6 基础设施调整

- `persistence`：6 张新表 PO/Mapper/Converter/RepoImpl（含 `wb_conversation_repository`）；`DevicePO`/`ConversationPO` 对齐新列；删 `DeviceProjectPO`。
- `cache`：`CacheKeys` 删 presence/execution/source/events，新增 `deviceHb(deviceId)` → `wb:device:hb:{deviceId}`（TTL 45s）；`Memory*`/`Jedis*` 精简为消息热窗 + 幂等 + 心跳。
- `messaging`：`Topics` 仅留 `SEARCH`；删会话事件与指令通道（`wb.collab.notifications` 由 HC-212 建）。`NotificationPort` 本任务定义为接口 + 本地日志实现。
- `contract`：Contracts 注册表删会话/执行/设备信封/共享项目 schema，新增项目/仓库/绑定/会话登记/同步 schema（`workbench-contracts` 包同步改）；删 `ExecutionCodec`、`ContractEventEncoder`、`RealtimeBroadcastPort`。
- `Application`：删 `migrate`，保留 `contracts`/`init-demo`/`start`；`init-demo` 幂等写演示用户/团队/成员；演示项目/仓库数据放 `demo-data.sql`。
- `pom.xml`：删 `flyway-core`/`flyway-mysql`/`spring-boot-starter-websocket`；`application.yml` 删 `flyway` 段。
