# HC-235 本机会话消息排队

[任务](../task/HC-235-本机会话消息排队.md) · [T3 Code 队列交互参考](https://github.com/pingdotgg/t3code/blob/d7373c44feaa85f561c0f1e829ea1c31918acbeb/docs/user/composer.md#queued-messages)

- 本人本机会话运行时，输入区显示「加入队列」图标，同时保留停止按钮。输入框上方的「待发消息」卡片显示数量，可折叠列表。每条消息用图标编辑或移除，提交成功才清除原草稿。编辑保留原有固定引用和工作区附件。
- 每个会话最多保存 20 条且序列化队列不超过 256 KiB。按本机服务来源、账号、工作区、项目和会话隔离。另一账号与共享会话不可访问待发项。
- 正常结束后由桌面主进程复用现有发送流程提交队首。发送仍校验归属、Agent 绑定、目录、附件和引用，等待上轮的 Git 快照。队列项在 Agent 受理后才进入当前会话；已定稿内容按现行规则同步。
- 用户停止、Agent 失败、审批拒绝、绑定更换、退出后重启均暂停待发项。当前绑定空闲且用户点「继续发送」图标后才恢复。常规暂停只显示继续入口，需要用户处理的问题显示简短原因。暂停期间可编辑和移除。
- 提交队首前，本机持久化该项正在发送的标记。遇到进程退出导致无法确认是否受理时，显示结果待确认并保留原文，由用户移除或重新输入后主动发送。此状态禁止自动重试。
- 复用现有 ACP 发送、终态和目录权限。运行中追发及跨设备执行沿用各自现行范围。
