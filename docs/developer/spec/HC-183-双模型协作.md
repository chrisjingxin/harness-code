# HC-183 双模型协作行为规格

## 背景与目标

以 [Task](../task/archive/HC-183-双模型协作.md) 为需求来源，以 [完整设计](../architecture/fusion-dual-model-workflow-design.md) 为跨阶段实现依据。本页明确已实现 P0 的配置契约、公开接口和验收约束。

## 设计思路

用户通过可信 TOML 声明模型组合。加载配置时检查结构和引用；选中组合准备启动时检查模型能力、凭据、池容量与检查目录。读取配置不运行命令，也不连接模型。

## 整体架构

`ConfigManifest → load_config → FusionSettings → resolve_fusion_profile → FrozenFusionProfile`。

`config show` 沿现有 `config.show` 调用 `Za38Config.redacted()`。Fusion Run 经 BuildRunAdapter 接入 FusionService，由 Host 复用 Managed Worker 与共享检查执行器；SQLite 保存任务事实。Run 只消费冻结绑定，不重新从可变配置决定角色。

## 详细设计

### 配置契约

```toml
[fusion.profiles.default]
lead_profile_id = "pro"
sidekick_profile_id = "fast"
check_plan_ids = ["unit"]
max_rework_rounds = 3

[fusion.check_plans.unit]
command = "python -m pytest"
cwd = "."
timeout_seconds = 300
```

- 仅支持用户配置和显式 `--config`，不自动信任项目 TOML。未配置时组合为空，不启用 Fusion。
- 按组合 ID、检查 ID、字段逐层合并；显式文件覆盖用户文件，列表整项替换。
- Lead、Sidekick 必填，必须引用现有模型 Profile；允许两角色使用同一 Profile。
- 检查列表默认空且不得重复，必须引用已定义检查。无检查表示后续只可记录人工审阅。
- 返工上限默认 3，允许 0；检查超时默认 300 秒且必须为正整数；布尔值不得当作整数。
- 拒绝未知字段、空 ID、空命令及字段类型错误。错误不回显命令或凭据。
- 检查命令保留可信 TOML 的完整字符串，不裁剪首尾空白或换行，保证冻结指纹对应原文。
- `cwd` 默认为工作区根；仅允许相对目录，拒绝绝对路径、Windows 盘符、反斜杠和 `..`。冻结时解析真实目录并拒绝 symlink 越界或不存在目录。
- 解析结果使用不可变映射和元组；检查命令不进入 `repr` 或配置摘要。

### 冻结与启动前校验

`resolve_fusion_profile(config, profile_id, environ=None)` 返回冻结的组合、两角色模型、检查计划和 SHA-256 指纹。它是 Fusion Run 的接入边界，Host 在启动前调用。

- 两模型必须具备 `tool-calling` 和 `streaming`，且存在环境变量或可信用户 TOML 凭据；失败不降级为别的模型。
- 选中 Fusion 时要求池 `max_profiles >= 2`；普通加载、普通 Run 不新增此限制。
- 复制模型的 Header 映射，防止冻结后被外部配置修改。
- 指纹包含角色、模型配置指纹、检查命令摘要、真实目录、超时及返工上限；不包含实际 API Key 或动态 Header 值。
- 模型配置或检查计划改变会改变指纹；单纯轮换凭据不会改变指纹。
- 冻结对象的 `to_record()` 只含脱敏模型摘要、组合/检查 ID 和指纹。不保存 endpoint、Header、命令、API Key 或环境值。

### 异常与兼容性

结构或绑定错误使用 `ConfigError`，冻结失败包含 `FUSION_PROFILE_INVALID` 和安全原因。复用现有模型可用性校验；普通 Run 的现有实验委派语义保持一致。配置摘要新增 `fusion` 字段；完整运行时新增 SQLite 扩展表、v3.11 协议及角色/写者约束，详见后续契约。

### 交付边界

A–E 的 P0 闭环已接通。首版仅支持本地工作区；远程 backend 在创建任务前报 `FUSION_SNAPSHOT_UNAVAILABLE`。P1/P2 不包含在当前验收中。

## P0 运行契约（本轮）

### 入口与角色

- `run.start.fusion_profile_id` 显式选择可信配置中的组合，协议 minor 11 起支持；只支持 Build 用户消息，拒绝 Goal、Compose、Skill、Plan 或同时指定主模型。
- Lead 使用组合里的 Lead 模型，只可读、提问、派单和审阅；Sidekick 从原始权限派生，使用另一个模型，不能再次派单或请求用户。
- `fusion_delegate/rework` 走现有真实审批；每条执行命令仍单独服从当前权限。角色、任务、版本和写者不匹配时拒绝调用。

### 任务与副作用

- 每个项目 Thread 最多一个活动任务；SQLite 借用 ThreadPersistence 的连接和锁。任务版本按 compare-and-swap 更新。
- 每轮执行使用不同 execution ID，同一任务保持 Sidekick checkpoint。每轮结束保存完整 checkpoint 标记；丢失、被覆盖或未完整结束时停止返工，不能静默创建空历史。派发、报告、检查、票据和副作用记录可恢复。
- 原始用户消息完整送给 Sidekick；要求必须能在原文中找到。允许路径只接受项目相对文件或以 `/` 结尾的目录，拒绝越界、内部目录和 glob。目标文件和目录可以尚不存在，Sidekick 可以创建；读取工具的虚拟路径 `/calc.py` 在派单中应写成 `calc.py`。
- 派单/返工的路径格式错误返回 `FUSION_PATH_INVALID`，标明 `allowed_paths` 并提示项目相对路径及新文件规则，不派发 Worker、不改变任务状态。工具参数说明和 Lead 提示必须包含这些规则；不向模型透出未知异常的原文。
- 真实工作区只有一个写者。写入前和提交时都校验任务、revision 与 generation；普通 Build/Compose、Direct Shell、文件撤销/重做也受约束；Shell 执行期间持有同一 Host 写锁。完成/取消和交还写者原子提交。
- 副作用在执行前登记；取消或崩溃不能证明停止时保留写者，并进入 `OUTCOME_UNKNOWN`。用户确认操作停止后才可恢复。Shell 任意程序不具备独立文件系统隔离；Host 按 tracked/非忽略文件及允许范围内的忽略文件核对快照，不能承诺范围外忽略生成物均受控。

### 检查与接受

- Host 独立记录基线、候选和检查后快照；检查失败、越界、候选漂移、缺失要求或旧票据都拒绝接受。
- 检查沿共享 backend、权限、审批和执行锁运行。没有检查时仅可标为 `review_only`；检查全部成功时为 `verified`，仍须完成 Lead 逐项审阅才能宣布任务完成；UI 区分检查通过和审阅完成。
- Lead 结束前必须直接完成、验收完成或明确等待用户；否则提示继续一次，再保存待处理状态。Sidekick 未提交报告不能按完成进入验收。

### 查询和恢复

- `fusion.status(thread_id)` 返回脱敏状态；`fusion.recover(task_id, expected_version, inspection_note, effects_stopped)` 只解除已人工核查的不明状态；`fusion.cancel(task_id, expected_version)` 在无未停止副作用时终结。
- `/fusion <组合>`、`/fusion status/off/cancel/recover --stopped <核查说明>` 通过共享 Feature 和 Gateway 接入 TUI/Web。活动任务不能静默退出或切换组合。
- 进度走现有 Run 事件。协议和入口测试覆盖两端；运行测试使用虚构凭据与可控模型。

### 恢复的可观察结果

- 状态查询不执行模型或命令。新 Run 明确继续时，`prepared` 原消息沿原操作、轮次与会话派发。
- 报告和派发已完成时核对报告快照，只执行检查；已有检查回执复用，仅运行剩余计划。
- 文件漂移使票据失效；已开始却缺少回执的检查等待核查，不自动重跑。
- 结果不明保留写者和待核查操作；人工确认只进入 `PAUSED`，不视为验收完成。
- 上一轮 Worker 完整结束且 checkpoint 一致才允许同会话返工；中断工具不自动续跑。
- `run.cancel` 暂停当前任务；`fusion.cancel` 停止所属 Run 后确认无未停止副作用才终结，且不回滚文件。
- 旧 minor 连接不接收整个 Fusion Run 流，普通事件流继续可用，不产生新事件过滤造成的序号缺口。

## 工作区占用与继续（2026-10-20）

- 工作区被另一活动任务占用时，首轮任务单、轮次、消息和 Worker 均不得部分登记。当前任务进入 `WAITING_USER`，原因 `workspace_busy`。
- 状态增加可空的 `workspace_blocker`：仅包含占用任务/会话 ID、阶段、轮次、安全原因和是否需要人工核查，不包含用户消息、文件路径、模型连接或命令。占用原因不得从不可信内容生成。
- Lead 图在下一次模型调用前由程序结束本轮，并给出占用说明；同一 Run 不重试、不改走 rework、不追问如何处理这一已知错误。结果为等待处理，不能记录成完成。重复工具调用不改变轮次和写者。
- 查询只刷新占用事实。占用解除后提示可以继续；只有用户新消息才重新派单。保留原始需求、当前 Thread 和 Sidekick 会话身份。旧任务必须由用户通过原有取消/恢复流程处理；不得按“无运行进程”自行夺取或释放写者。
- 尚无首轮任务单时，rework 返回 `FUSION_FIRST_ORDER_REQUIRED`，说明应使用 `fusion_delegate`；尚无票据但已经有任务单仍按现有返工规则处理。
- 现有 v3.11 尚未发布，直接扩充 canonical 状态及两端生成物，不保留第二份状态形状或兼容路径。`workspace_blocker` 只作为诊断，不授予任何权限。
- 问答历史的 `resolved` 标签改为“已处理”。Fusion 是否完成仍只看任务的完成状态及检查/审阅结果。

## 双角色实时过程（2026-10-21）

1. 沿用 `content.delta`、`reasoning.delta`、`tool.started/delta/completed` 和真实执行 ID。仅 Fusion Sidekick 使用实时正文策略；普通 Plugin/Compose 的正文策略不变。正文不重复追加最终结果，也不写入父模型 Transcript。
2. 增加严格的 `fusion.execution` 事件：安全任务 ID、`role=sidekick`、轮次（至少 1）、实际模型名、状态 `running/completed/cancelled/failed`。执行与父执行 ID 在既有事件信封中给出；不得携带 URL、密钥、提示词或工具参数。事件在该轮输出之前发出，明确开始与结束。
3. `run.started.fusion` 建立 Lead 过程组；Sidekick 事件只与同一 Run、任务及父 Lead 关联。主时间线仅显示有此明确绑定的 Fusion 子执行，普通子执行继续隔离。相同工具 ID 在不同角色/轮次不能合并。
4. 保持事件时间顺序；同一角色的连续记录合成带角色、模型和轮次的可折叠组。Lead 返回审阅时形成后续段，不能把全部 Lead 内容提前到 Sidekick 之前。分段 React key 唯一；Sidekick 活跃组默认展开，结束后可展开回看。
5. 轮次结束即停止该执行的流式文本和思考指示；迟到的开始、正文或工具帧不得复活执行。失败/取消不得把未完成工具标成成功。父 Run 终结或连接失败时收敛剩余过程。`completed` 只表示该次执行结束，不能替代 Fusion 的检查与审阅完成。
6. Fusion 状态说明更新一条已有记录，避免每次状态版本变化都插入相同长说明。过程组、工具详情、实时滚动和审批入口在 TUI/Web 都可用。
7. 过程属于本次连接的展示状态，Web 接管/刷新沿用共享 Controller。重开历史会话保留原 Transcript 行为，不另建持久过程表。本次不新增依赖或数据库表，v3.11 未发布契约原地同步两端生成物。

实现位置：Host `fusion_runtime.py`；事件定义 `packages/protocol/schema/v3.json`；共享状态 `interactive/fusion-execution.ts` 与 `state.ts`；共享分组和过滤 `presentation-shared/timeline-*.ts`；两端原有 Timeline renderer。按仓库既有 TypeScript/Python 风格及中文说明编写。

测试：先用门控的可控模型证明子执行尚未结束时已收到正文，再验证两轮执行身份和结束事件；Bun 覆盖共享 Controller、分组、串线与取消；真实 OpenTUI 和浏览器验证两角色及工具状态。构建 `npm run build`，类型 `npm run typecheck`，契约 `npm run protocol:check`，完整测试 `npm test` 和 Python `pytest --import-mode=importlib`。禁止真实密钥进入测试，禁止跳过失败用例掩盖问题。

## Sidekick 长等待与停滞（2026-10-21）

目标是结束无界等待和没有进展的重复执行，同时保留现有权限、写者与审阅规则。假定继续使用已配置的 OpenAI-compatible 流式模型，不更换用户模型或密钥。

1. 统一模型适配器使用已有 `models.profiles.<ID>.timeout_seconds` 限制一次流式响应的总时长，覆盖建立请求、接收首包、持续正文及心跳。超时关闭流并抛出安全的 `MODEL_RESPONSE_TIMEOUT`；手动取消仍是取消。此规则对同一适配器中的 Lead 和普通模型也一致生效。该时限不是整个开发任务的总时限。
2. 复用现有 provider 重试规则。无公开输出时按 `max_retries` 有限重试；已有公开正文时不得重放。任何超时不得自动释放未知副作用或把失败标记为完成。
3. Fusion 命令检查复用 Bash 语法树：区分 Shell 后台操作与引号、here-doc 中的 Python 按位运算；继续拒绝真实后台运行、嵌套 Shell 后台、Git 修改和内部目录操作。无法可靠解析时拒绝，不用宽松字符串匹配兜底。
4. Sidekick 本轮报告一经保存，下一次模型边界直接结束；状态中的报告、检查与审阅继续走现有闭环，不再请求模型生成结束语。
5. 在 Sidekick 自身消息中，连续三次同一工具、同一 Fusion 拒绝码且中间没有成功工具结果时，由 Host 经现有 `submit_result` 保存 blocked 报告并结束本轮。成功工具结果、不同错误或新的人类任务消息会打断计数。不得取消任务或擅自接受需求。
6. 不新增协议字段、数据库表或运行时依赖。错误收尾、返工及实时过程仍使用现有生命周期事件；已提交报告后的流测试迁移到提交报告之前的真实正文阶段。

验收包含模拟 SSE 保活、正常返回、取消、真实 Host 重复拒绝、报告后零多余调用、按位运算和后台/Git 负例，以及普通执行和实时过程回归。完整检查命令沿用停点 G。
