# 每轮 Token 用量规格

关联需求：[HC-216](../task/HC-216-每轮Token用量.md)。用户结果及范围以 Task 为准。本规格已由用户在本会话确认，未描述已交付能力。

## 目标流程

用户提交一次请求 → 主模型、子代理和压缩模型分别报告调用用量 → Python 按调用身份去重汇总 → Run 结束时保存同一份统计并发送终态 → Web 在该轮回答下显示 → 重新打开会话从持久化恢复。

一轮对应一个顶层 Run。工具往返、所有深度的子代理、该 Run 触发的上下文压缩均属于同一轮。独立执行的压缩命令不倒算进上一轮。

## 现状与职责

现有 Protocol `Usage` 有 `input_tokens/output_tokens/cached_tokens`，`RunCoordinator` 初始化用量为零，Interactive State 主要保存 `lastRun.usage`。仅将最后一次运行摘要展示出来不能满足多轮历史，也无法区分未知与零。

- Agent 内建立 Run-scoped 用量收集器，唯一负责调用去重和统计。
- 各模型调用边界报告原始供应商用量，主调用、managed/inline child、压缩路径接入同一收集器；Trace 只读取同源事实。
- ThreadPersistence 保存 Run 最终用量及完整性；不能读取 Trace 文件推算。
- Protocol 定义唯一 wire 类型；CLI SDK、Interactive Core、Web 使用生成类型。迁移所有已有消费者，不保留旧形状 fallback。
- Web 只格式化数据，不重新累计通知或推算 Token。

## 统计值与调用身份

最终 `Usage` 为严格对象，未知字段也显式传 null：

```typescript
type Usage = {
  input_tokens: number | null
  output_tokens: number | null
  input_complete: boolean
  output_complete: boolean
  cached_tokens?: number
}
```

数字必须是非负安全整数。每一方向分别处理：有实际报告则为已知值之和，完全没有报告为 null；只有所有已发起模型请求都明确报告该方向时 complete 才为 true。complete=true 必须有数字，包括真实零。部分缺失时返回已知小计且 complete=false。此类型在完成、失败、取消终态及历史摘要中一致。

缓存 Token 是输入中的明细，不能再次相加；cached_tokens 仅在本轮所有输入请求的缓存明细都已报告且合法时提供，供现有状态面板展示，缺失或部分报告时省略，避免伪造精确命中率。供应商 reasoning 若已包含在 output_tokens 中不能再加。主回答不新增缓存展示。供应商仅返回 total 时，两方向均未知。

每次实际发出的模型请求生成唯一 invocation_id，绑定 root_run_id、execution_id 和 purpose（主对话/子代理/压缩）。重试的新请求使用新身份；同一请求的流式累积快照、最终消息、回调重复通知共用身份。适配器将流式结果规范化为最终累计值，不能逐 chunk 累加累计值。一次请求只登记一次最终值；冲突的重复最终值视为采集异常并标记不完整，不任意覆盖。

父级委派工具不能再上报子调用汇总作为模型用量。收集器只统计实际模型请求，包括失败重试中供应商确实返回的用量；未报告的失败尝试令完整性为 false。重试不是账单保证，界面只反映实际获得的报告。

取消流程先停止并收拢本轮调用，再冻结汇总；终态之后到达的回调不能修改已发布的最终值。没有发送过模型请求则为 0/0 且完整；进程中断导致无法证明完整的记录显示未知或已知不完整小计。

## 持久化与历史

### 已确认的停点 A 验收修正：本轮总耗时

用户已确认包含准备阶段，到结果完成为止。`RunTimingLedger` 从 start 受理入口开始，在业务结果完成、进入终态保存前冻结；同一冻结值用于终态 payload.duration_ms、RunCompletion、持久化 run_summaries.duration_ms 和 Trace 根 attributes.run_duration_ms，后续提交与资源释放不能重新计算它。失败/取消同样携带此值。

Trace 继续保存物理 start/end/duration，作为诊断采集和收尾耗时；对话、Trace 主 Run ROOT 行及分组的“本轮总耗时”只读取权威值，并使用相同秒数格式。详情区单独标注采集耗时，不混称本轮总耗时；其他 span 计时不变。旧 JSONL/摘要没有权威字段表示未记录，不重新推算；摘要 duration_ms 可选是为了保留既有真实数据，不为旧记录伪造计时。

以 (project_fingerprint, thread_id, run_id) 定位一轮最终统计，与 Run 终态在同一事务内提交。保存四个 Usage 字段；未终结 Run 不冒充完整零值。终态通知必须使用提交的同一统计值，持久化失败不得先宣告统计成功。

`threads.open` 增加 `run_summaries`，每项包含 `run_id`、`outcome` 和 `usage`；消息恢复同时保留 run_id。历史与实时按 run_id 写入映射，不能只保存 lastRun；重复终态和重连快照覆盖同一项，不重复累加。

旧数据库新增可空统计字段，既有记录默认未知，不能回填零或重新调用模型。这是避免伪造历史事实所需的数据处理，不提供旧协议双路径。

Fork 的历史展示携带继承轮次摘要及其来源；新分支新增请求只记到新 Run。统计不依赖源 Thread 的后续变化。

## 展示行为

- 在每轮主 Agent 最终回答底部、复制/Fork 同一操作区显示「输入 12,345 · 输出 678 Token」。精确整数使用千位分隔，不缩写成 K。
- 缺失方向显示「输入 未知」；部分已知显示「输入 ≥12,345（统计不完整）」。输入与输出可以有不同完整性。
- 成功、失败、取消后均可展示；没有正文时挂在该轮终态提示下，不能落到上一轮回答。
- 子代理内部回答不再重复展示整轮总量。本期无需运行中实时累计。
- 窄屏允许用量单独换行；按钮仍可点击，读屏可读取完整标签；复制回答不附带统计文本。

## 错误与不变量

供应商缺失用量不是运行失败；无效、负数或溢出用量不得进入统计，按缺失处理并记录不含敏感载荷的诊断。统计采集异常不能令已经执行的工具重试。数据库失败遵循现有 Run 持久化错误语义，不新增“显示成功但恢复丢失”的路径。

必须始终满足：每请求至多一次、每轮独立、父子不重复、未知不等于零、历史不依赖日志、UI 不累计、终态与落库一致。
