# 模型故障原因提示规格

## 一、背景与目标

同一句英文错误涵盖参数错误、密钥错误、上游登录失效和权限问题，用户不能判断下一步。目标是展示已知原因、HTTP 状态和具体处理办法；未知细节不编造。

## 二、设计思路

模型异常 → 读取 HTTP 状态及有限的结构化错误 → 转换为固定中文说明 → 通过现有 Run 失败消息显示。若服务端明确报告上游登录失效，提示重新登录代理上游；普通 401 同时提示密钥和代理上游鉴权的可能性。

## 三、整体架构

| 模块 | 职责 |
| --- | --- |
| runtime/provider_retry.py | 唯一安全提示生成函数；各调用方共用，不新建重试器 |
| ManagedAgentExecutor、Goal proposal adapter | 原错误码及 retryable 保留，只替换用户消息 |
| compose/stage_agents.py | 转发执行器已经处理的安全原因，保留阶段错误码 |
| execution_stream.py | 已公开输出后出错仍保留原因，并说明当前片段保留、不自动重放 |
| CLI/Web 共享状态 | 直接显示服务端消息，以回归测试确认没有替换为笼统文本 |

## 四、详细设计

- 401 区分明确的本地 invalid_api_key、明确的上游登录失效与未确定来源的鉴权失败。上游失效判断要求 HTTP 401、结构化 upstream_error 标记和明确登录失效信号；不能仅凭异常文字中的 401 下结论。
- 403 提示账号/模型权限；404 提示接口地址/模型名；400/422 提示参数或工具能力不兼容；明确 context_length_exceeded 提示压缩上下文。429、5xx、连接失败和超时各给对应操作。
- 只读取 body 中有限的 code/type/message，不向界面或日志输出原文。只将固定枚举中的站点名用于指引，任意模型名、URL、HTML、Header 和错误正文都不直接回显。畸形或缺失 body 使用 HTTP 状态对应的一般说明。
- 常规消息与已公开输出后的失败共用原因说明。后者保留 PROVIDER_OUTPUT_INTERRUPTED、不重试；取消和工具审批不进入模型故障提示。
- 普通模式、Lead、Sidekick、Compose、Goal 提案使用现有公共路径；不改协议、数据库、模型配置或审批策略。
- 测试覆盖真实 OpenAI 异常、畸形正文、机密字符串不外露、401 不重试、流式中断不重放、两角色故障传到 Run 终态和 CLI 共享时间线。
