# 项目记忆与团队知识上下文

HC-233 将本人本机工程记忆与团队知识发现集中在 `desktop/src/main/workbench-context/`，消费现有协作客户端和通用 ACP 公共入口。行为以 [Spec](../spec/HC-233-项目记忆与团队知识读取.md) 为准，实施与未接线项见 [Task](../task/HC-233-项目记忆与团队知识读取.md)。本卡不增加线上接口、数据库表、通用 ACP 方法或独立推理模型。

## 数据与权限

系统用户主目录下 `.harness/workbench/project-memory/<规范服务origin的SHA-256>/<账号ID>/<WorkspaceID>/` 保存 `team.md` 与 `personal.md`。文件头使用 YAML 1.2 的标量与 JSON 流式值保存条目、修订与来源，正文由维护字段统一渲染。不另存 JSON 副本；损坏文件与正文/维护字段不一致时保留原件并返回实际原因。

每份文件记录自己的修订。同一服务、账号、Team 共用短写锁，锁内只做本地读改写；写入用 `wx/0600` 临时文件、同步并原子替换。单条维护记录最多4 KiB，两份业务正文合计最多8 KiB，在生成/更新时核对。自动发送不按关键词、Project或cwd选择工程，也不裁剪正文；来源Project已不可读的条目按实际权限撤回。

会话工具凭据只在当前登录代次与真实会话绑定内有效。退出、换账号、切换绑定和窗口销毁会撤销。每次异步读取后再次核对登录身份和绑定，正常终态写入前再查来源Project权限与条目版本。个人目录依据本人确认或真实会话目录，Git地址来自只读实际配置；带口令或查询参数的HTTP地址不提供给Agent。目录映射不发放目录访问权限。

## 模块分工与链路

```text
本人主动发送
  → 真实会话范围 → WorkbenchContextService
  → ProjectMemoryStore 读取完整有效正文 + TeamKnowledge 标题页
  → 通过现有 ACP prompt blocks 发送给同一 Agent
  → Agent 经本机 HTTP MCP 查询/读固定知识/提交提案
  → pending（未保存）
  → 正常终态复核 → 按条目保存 → 更新同一个桌面工具卡
  → 下一次主动发送/查询读取已保存修订
```

- `memory-store.ts`：唯一两份Markdown持久化与正文渲染入口。
- `directory-facts.ts`：只读当前目录的Git origin/upstream配置，不联网。
- `knowledge.ts`：沿 `applicationWorkspace` 调用既有列表与固定版本读取。第一页按服务、账号、登录代次、Team缓存60秒，合并并发请求，更新通知失效，迟到旧请求不回填失效缓存。自动目录只含标题、固定标识和版本，独立8 KiB预算。
- `mcp-server.ts`：单个 `127.0.0.1` 随机端口HTTP MCP，提供四个具名工具；按短期凭据区分会话，不暴露Java Cookie/CSRF。
- `service.ts`：会话MCP setup、完整材料、当前轮次的已读来源与提案、取消/正常终态和用户即时确认。固定更新提醒187字节，完整正文只附带业务内容。工具查询上限10条/8 KiB，与自动正文完整性无关。知识正文同轮重复读取只返回已读标识。
- `context-ipc.ts`：引用预览里的原生目录确认/纠正/移除，复核真实本人会话与选择发起时登录代次；Agent未连接时也可操作。

`collaboration-ipc.ts` 持有服务生命周期并注入既有 assembler；知识保存成功与 `project-updates-ipc.ts` 的既有 `knowledge.updated` 通知使标题页失效。未新建通知流。`context-tool` 是桌面内部保存结果通知，不占ACP事件序号；renderer按受理requestId对应真实轮次，沿原有工具组件更新同一桌面卡，允许正常终态后返回真实写入结果，不重画中央对话。
