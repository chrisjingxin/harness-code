本文补齐桌面左栏里"最基本的整理动作"：个人空间的会话与目录分组、团队空间的会话，目前都只能新建、重命名、发布或停止共享，不能归档，也不能删除。本文是整体设计；本期（个人会话）的 Task、Spec、Plan、Todo 见 HC-257，细节以 Spec 为准。

用户确认先做**个人会话**，团队会话（第 6 节）与团队侧删除接口留到后续。

## 2. 已确认的取舍

2026-11-26 与用户确认：

1. **团队会话**：以归档为主，仅本人可删。本人可归档/取消归档；删除在服务端是软删除（留审计墓碑，正文和检索清掉）。他人会话仍只读，Project 负责人可强制移除他人会话。
2. **个人会话**：归档＝从列表收起，可恢复；删除才清理本机正文与草稿。
3. **个人栏文件夹**：对它的操作是批量归档/批量删除其下会话。**绝不删除磁盘上的真实目录**。

## 3. 设计原则

- **先收起，再删除**：归档可逆，删除不可逆；菜单里归档在前、删除在后并标红。
- **目录只是视图**：文件夹操作只是"对分组内每条会话各执行一次会话操作"，不新增文件夹实体，不动磁盘。
- **以服务端为准的会话，先改服务端再改本机**：已发布（有 `projectId`）的会话在服务端有头记录，只改本机会被"团队列表"或"旧入口补建本机记录"（`rememberProjectConversation`）重新带回来，所以顺序固定为"服务端成功 → 本机落盘"，离线时置灰并写明原因（与现有"停止共享"一致）。
- **运行中不可整理**：`running`/`waiting_approval` 的会话不能归档或删除，必须先停止；界面置灰，主进程同样校验，不只靠渲染层。
- **不另起兼容路径**：未发版，字段直接加到 canonical 结构，不写旧数据迁移分支（见第 6 节关于可选字段的说明）。

|------|------|--------|----------|------|

## 5. 个人会话与文件夹

### 5.1 归档

```text
输入：右键会话 → 归档（或会话页头"更多"）
判断：是否运行中？是否已发布（有 projectId）？是否离线？
执行：local_only → 仅 LocalConversationStore 写 archivedAtMs
      有 projectId → 先调服务端归档，成功后再写本机
输出：会话从目录分组消失；底部出现"已归档 (n)"折叠分区；toast 提示"已归档「标题」"（现有 toast 只支持纯文字，不提供撤销按钮，恢复走"已归档"分区）
```

- 归档会话仍保留正文、草稿和目录绑定，只是不进默认列表、不进未读/收件箱计数、命令面板检索默认不命中（可切换"含已归档"）。
- 已归档会话可以打开阅读；在"已归档"分区里点"取消归档"后回到原目录分组并保留原更新时间。继续向已归档会话发送消息并完成一轮后，会自动恢复为未归档（有新活动即视为恢复），不需要额外禁用输入框。
- 目录分组下所有会话都归档后，该分组自然消失，不留空壳。

### 5.2 删除

```text
输入：右键会话 → 删除 → 确认弹窗（写明将清理什么）
判断：同 5.1；有 projectId 的先走服务端删除
执行：本机清理清单（见下）
输出：会话从列表消失；若当前正打开它，回到"新建会话"落地页；无撤销
```

本机清理清单（具体入口在 Spec 阶段逐项核对，不得遗漏也不得多删）：

| 要清理 | 位置 | 说明 |
|--------|------|------|
| 会话元数据 | `index.json` 记录 | 已有 `remove()` |
| 会话正文 | `conversations/<id>.json` | 已有 `remove()` |
| 草稿与阅读位 | `PersonalStore` 中 `kind=conversation / sessionWorkspace` 的文件 | 新增按会话清理 |
| 待上传队列 | 上传账本 | 已有 `uploads.cancelConversation` |
| 本机 Agent 绑定与上下文会话 | 执行协调器绑定、`contextSession.release` | 需新增对外的"遗忘会话"入口，只删绑定，不删 Agent 自己的历史 |
| 变更检查点 | `project-service/checkpoints.ts` | 按会话键清理 |
| **不清理** | 用户磁盘目录、目录授权（按目录而非会话授予）、`LocalImageStore`（账号级目录，按图 ID 存放，留给后续孤儿回收） | |

### 5.3 文件夹（目录分组）操作

分组标题行增加"更多"菜单：

1. **归档整组**：对组内非运行中的会话逐条归档，运行中的跳过并提示数量。
2. **删除整组会话**：确认弹窗写明"将删除 N 条会话，不会删除磁盘上的目录 `<路径>`"，需勾选确认；逐条执行，失败的保留在原处并汇总原因。
3. **折叠/展开**：现已有，菜单里补一个入口。
4. **在文件管理器中显示**：仅有真实路径的分组可用（"未设置目录"分组置灰）。

批量动作不新增事务语义：每条独立成功或失败，不做"全成或全败"。

### 5.4 P1 高频便利功能

| 功能 | 入口 | 行为 | 说明 |
|------|------|------|------|
| 置顶 / 取消置顶 | 会话右键菜单 | 个人栏顶部出现独立"置顶"分区（跨目录），置顶的会话不再在原目录分组里重复出现 | 本机元数据 `pinnedAtMs?: number`，缺省即未置顶；置顶/取消置顶不改 `updatedAtMs`，不影响其他排序；归档时自动取消置顶；`stopped` 会话也可置顶 |
| 在此目录新建会话 | 目录分组"更多"菜单 | 打开新建会话页，目录预填为该分组目录，Agent 沿用组内最近更新的一条会话，不可用时回退默认 Agent | "未设置目录"分组不显示该项；目录已不存在时沿用新建页现有的目录校验与报错 |
| 复制为 Markdown | 会话右键菜单与会话页"更多" | 把已定稿的轮次按"用户 / 助手"顺序复制到剪贴板 | 只含用户文字与回复；工具调用不输出；附件只写文件名不写绝对路径；图片写为 `[图片]`；失败或取消的轮次加标注；进行中的轮次不包含；复用现有 `host.copyText`，无需新接口 |
| 复制目录路径 | 目录分组"更多"菜单、会话右键菜单 | 复制该会话绑定的目录绝对路径 | 复用 `copyText` |
| 在文件管理器中显示 | 同上 | 打开系统文件管理器定位到该目录 | 需新增 `LocalConversationsHost.revealDirectory(conversationId)`：渲染层只传会话标识，主进程自行读本人记录里的目录、确认它存在且是目录后再打开，不接受任意路径 |
| 搜索含已归档 | 个人栏搜索框旁开关 | 默认关；打开后已归档会话也参与标题/目录名匹配，并在"已归档"分区内展示命中项 | 命令面板（HC-248）的检索范围不在本期改动 |

菜单排序（个人会话，自上而下，分组用分割线）：

```text
重命名 · 置顶/取消置顶
复制为 Markdown · 复制目录路径 · 在文件管理器中显示
发布到项目…（仅 local_only）
───────────
归档
删除（红，仅 local_only；stopped 置灰并写明原因）
```

## 6. 团队会话（后续，本期不做）

### 6.1 服务端

在 `wb_conversation` 增加两列（`schema.sql` 是唯一结构源，未发版不写迁移）：

| 列 | 含义 |
|----|------|
| `lifecycle TINYINT NOT NULL DEFAULT 1` | 1=active，2=archived，3=deleted |
| `lifecycle_at DATETIME(3) NOT NULL` | 最近一次生命周期变更时间（active 时等于 `created_at`，沿用 `stopped_at` 的写法） |

`lifecycle` 与 `share_status` **相互独立**：归档不改变共享状态，取消归档后同步从原水位继续，不需要补传。

新增接口（沿用现有 `ProjectConversationController` 风格与幂等 `requestId`）：

| 方法与路径 | 作用 | 权限 |
|-----------|------|------|
| `POST .../conversations/{id}/archive` | 归档 | 会话创建者 |
| `POST .../conversations/{id}/unarchive` | 取消归档 | 会话创建者 |
| `DELETE .../conversations/{id}` | 软删除 | 会话创建者或 Project 负责人 |
| `GET .../conversations?lifecycle=active\|archived` | 列表筛选，缺省 `active` | 项目成员 |

软删除的服务端行为：

- 会话头保留为墓碑（`lifecycle=3`，标题改为占位、简报清空），`conversationId` 不可再被 `register` 复用（现有 409 逻辑天然覆盖）。
- 清除消息热窗与 ES 中的正文，并向检索总线发布"移除索引"事件（现有 `publishConversationIndex` 只有写入，需补移除分支）。
- 迟到的 `sync` 请求返回确定性错误码（例如 `CONVERSATION_DELETED`），客户端收到后取消该会话的待传队列，不重试。
- 已归档 Project 内的会话允许创建者"删除"止损（与 `stopSharing` 现有口径一致），不允许归档/取消归档。
- 写入组织审计（HC-249 的封闭 Schema）：`conversation.archived / unarchived / deleted`，强制移除时记录操作者与原作者，并通过 `NotificationPort` 通知原作者。

### 6.2 与既有功能的关系

| 既有功能 | 处理方式 |
|----------|----------|
| 固定会话快照（`wb_snapshot`，不可变） | 不随会话删除；删除确认框显示"已有 N 个固定快照不受影响"。是否提供"同时删除快照"见待定问题 |
| Task 关联会话（`task_id` / 会话链接） | 未完结 Task 关联的会话**禁止删除**（409 并提示先解除关联），允许归档；已结项 Task 的会话可删，Task 页显示"会话已删除" |
| 看板与成员分组 | 默认只显示 `active`；归档会话进入"已归档"折叠区；墓碑不显示 |
| 停止共享 | 仍是独立动作。顺序上"停止共享"后仍可归档或删除；"删除"已隐含停止同步 |
| 项目归档（HC-250） | 项目归档后内部会话只读，归档/取消归档按钮隐藏，仅保留创建者删除 |

### 6.3 桌面端行为

- 本人团队会话菜单：重命名 / 归档 / 停止共享 / 删除。删除确认框写明"将同时从团队移除，其他成员不再能查看；本机副本一并删除"。
- 他人会话：Project 负责人看到"强制移除"，其他成员无整理菜单。
- 团队空间每个 Project 下增加"已归档会话 (n)"折叠区；仅本人看到本人的归档项，他人归档的会话对非创建者不展示。

## 7. 界面设计

沿用 `SessionContextMenu`（已有 `danger`、`separatorBefore`、`disabledReason`）和现有行内"更多"按钮，不引入新组件体系：

```text
个人会话菜单                     团队会话菜单（本人）
─────────────                   ─────────────
重命名                           重命名
发布到项目…                      归档
───────────                      ───────────
归档                             停止共享
删除（红）                       删除（红）
```

- 个人栏底部（发布数提示上方）新增可折叠"已归档 (n)"；行内操作为"取消归档"和"删除"。
- 目录分组标题行悬停出现"更多"按钮，菜单项见 5.3。
- 删除确认弹窗：标题写明对象名称，正文列出后果（几条会话、是否同时从团队移除、不会删磁盘目录），主按钮为红色"删除"，次按钮"取消"。
- 归档与删除成功用纯文字 toast 提示；归档靠"已归档"分区恢复，删除不可撤销。
- 离线、运行中、无权限的置灰项必须写明原因，不能只置灰。

## 10. 待定问题（Spec 阶段确定）

以下第 1～3 项属于团队会话，随团队会话后续任务再定；本期（HC-257）只需关注第 6 项和下面补充的 P1 细节。

## 11. 验收标准（可观察结果）

1. 个人会话右键出现"归档"和红色"删除"；归档后该会话从目录分组消失，底部"已归档 (n)"展开可见，"取消归档"后回到原目录分组。
2. 对运行中的会话，归档和删除均置灰并显示"请先停止"；绕过界面直接调用 IPC 同样被拒绝。
3. 删除个人 `local_only` 会话后，重启应用该会话不再出现，对应 `conversations/<id>.json` 与草稿文件已不存在，磁盘工程目录原样保留。
4. 目录分组"更多"→"删除整组会话"，弹窗显示条数和"不会删除磁盘目录"；执行后分组消失，若有运行中会话则被跳过并提示数量。
5. 团队会话本人菜单出现"归档"和"删除"；归档后团队列表与看板默认不显示，"已归档会话"区可见并能取消归档，取消归档后同步从原水位继续。
6. 删除团队会话后其他成员刷新即不可见，检索搜不到正文，直接请求该会话详情返回已删除错误；迟到的同步请求被拒绝且客户端不再重试。
7. Project 负责人能强制移除他人会话，原作者收到通知，审计日志可查到操作人与对象。
8. 离线时，凡需要服务端参与的操作均置灰并写明"协作服务离线"。
9. 未完结 Task 关联的会话删除被拒绝并提示先解除关联（若待定问题 2 采用建议方案）。

以上第 5～7、9 条属于团队会话（后续任务）。HC-257 的 P1 验收：

10. 右键"置顶"后，该会话出现在个人栏顶部"置顶"分区且不在原目录分组里重复；取消置顶或归档后回到原位置；置顶与取消置顶不改变会话在其他分组里的排序。
11. 目录分组"更多"→"在此目录新建会话"，打开的新建页目录已预填该分组目录；"未设置目录"分组没有该项。
12. "复制为 Markdown"后粘贴到任意文本框，能看到按"用户 / 助手"顺序排列的已定稿内容，不含工具调用输出和任何绝对路径。
13. "在文件管理器中显示"能定位到该会话的目录；目录已被删除时显示明确错误，不崩溃。
14. 搜索框打开"含已归档"开关后，已归档会话的标题能被搜到；关闭后搜不到。
15. `stopped` 会话的"删除"置灰并写明"需团队侧删除能力"，"归档"可用。
