# 团队知识审核与保鲜

团队知识沿用 Workspace、已有知识条目和固定版本；本卡没有第二个发布库、权限体系或模型服务。实现及待验证范围以 [HC-241 Task](../task/HC-241-知识分级与审核沉淀.md)、[Spec](../spec/HC-241-知识分级与审核沉淀.md) 为准。

## 业务边界

```text
本人选择定稿 → 本机临时 ACP 起草（真实 list/read/候选工具）
  → 本人编辑/确认共享 → 私人草稿或已提交提议
  → 当前 admin 审核 + 当前发布基线比较
  → 单事务写版本/范围/贡献/提议结果/knowledge.updated
  → 成员发现固定版本 → 工具真实读取 / 人的轻反馈 → 管理员复核
```

KnowledgeWorkflowService 先消费 HC-240 的团队行锁、active/enabled 和 admin，再处理状态及回执。私人 draft 仅本人可读；提交过的提议仅本人和当前管理员可读。提议不进入当前版本表、知识列表或检索投影；发布仍使用已有更新通知和标题缓存失效。

KnowledgeAppService 是唯一发布入口。版本保存级别、范围、内容类型、贡献与审核来源，正文只追加；范围关系只属于固定版本，不另存一份可独立编辑的当前仓库清单。条目并发 version 与正文 versionId 分开。现行知识检索统一从数据库按当前发布指针及范围分页，ES 保留已发布投影，不借索引回填未审核内容。

## 本机与普通发送接点

knowledge-drafts/ 仅做业务编排，复用现有 registry/LocalAcpHost 和标准 bind/sendPrompt、审批、停止、表单。executionId 与来源 conversationId 分离，不覆盖原生绑定；临时 MCP token 与233正式 token 共存。普通 token 四工具，起草 token 仅 list/read/propose_team_knowledge_draft。结构化候选来自真实工具调用与来源台账，模型不能指定账号或发布权限。

workbench-context/knowledge.ts 以当前已确认主目录实际 Git origin/upstream 匹配活跃团队仓库；无匹配/非 Git 仅用全团队范围。匹配失败时不声称取得整组规约。规则预算独立计量，整组失败/超限为空组及真实状态，不能阻断普通消息、截断条目或裁剪两份 MD。

assembleTurnContext 沿原 contextBlocks 可选返回 knowledgeStatus（code/message）和 preparedKnowledge（固定材料）；共享类型集中在 workbench-context-host。经统筹追加授权，resolvePrompt 复用真实手动 readKnowledgeVersion 的固定正文版本，以统一对象结果瞬态传 fixedKnowledge；service 创建本轮后先 registerFixedKnowledge 再装配规约。该材料不进用户原文、队列磁盘或上传。非 ready 状态沿既有 accepted notice/receipt 到当前绑定/请求的 composer status；下次成功受理清除旧降级，目录/发送错误优先。preparedKnowledge 仅留主进程，自动准备不登记为已读。普通每轮blocks及稳定轮次已由233/241本轮承接：当前资料只入本次blocks，历史恢复单独传入；ActiveTurn关联稳定上下文键和ACP turnId。受理后才登记实际纳入blocks的自动规约，prepare未发送不当已读。普通真实链路证据见Task，不把起草专用会话冒充它。

## 统计、反馈与初始化

MCP 正文成功完成 HTTP 响应后才登记读取；alreadyRead、列表、页面、自动材料和重放不计。随机 readId 在同轮同版复用，数据库首次回执与聚合更新同事务；回执不保存账号、会话、cwd 或模型输入。它是第一方桌面的实际交付遥测，不是服务端证明模型理解内容。

反馈按人和固定版本唯一，记录单调事件水位。确认有效仅处理管理员看到的水位，新来的反馈仍能进入队列；旧版票不套给新版。队列在查询时计算90天与未处理反馈，不增加定时 Agent 或通知总线。

30张 canonical 表及关键列由 Foundation 只读检查。保留历史环境先由运维显式补齐 schema.sql 对应结构、暂停业务写入，再运行 init-knowledge；命令只初始化全空且已核验的元数据为 experience/workspace/article，不执行 DDL，不改旧 ID/正文/作者/版本指针，不伪造复核。重复运行不覆盖已生效新数据。初始化与隔离复现见 [知识初始化说明](../project/团队知识初始化.md)。

来源入口正常 UI 已验证。knowledgeDrafts.source 由主进程按真实登记选择现有来源：独立本机会话库定稿，或 Project 个人目录配置与既有定稿历史接口；再次核验本人 owner。点击/重读才拉取 Project 定稿，最多1000条消息/1 MiB，部分读取明确提示；按真实 uploader 的 user→追发 user→tool_summary→assistant 排列完整收束轮次，全部原消息生成正文指纹选择标识，起草前重新读取校验，最多64 KiB。该标识不是 ACP turnId，未改239轮次映射。Project 提议来源用 conversation/projectId 供服务端再次校验；管理员整理不读取选定会话正文。


Project 来源只有遇到 assistant 终稿才形成可选轮次，累积跨页；来源上限或同步水位末尾仍缺终稿的尾段不提供选择，并标记未取全。工具只保留既有摘要字段 label/name/summary/status/tone/occurredAtMs；追发、摘要、终稿均进入实际预览和起草材料，选择指纹覆盖全部原消息，64 KiB按完整序列化选材计量。摘要或追发变化会要求重选，不读取完整工具输出，不改变 uploader 排列或239轮次映射。
