## 0. 产品定位与分支边界

本产品是面向任意 ACP Agent 的独立 Windows/macOS 桌面协作工作台。Electron + React 是图形入口；Java/TDSQL 保存协作业务及授权后的共享记录；TypeScript Runner 在用户本机管理执行、持久记录和补传。Harness 通过 ACP 接入，与其他 Agent 处于同一接入层级。

本分支可与 master 独立演进。旧 TUI、独立 Web、浏览器接管和旧 CLI 不属于新产品入口；现有中央对话、头像、用户 SVG、工具卡片、输入、文件阅读及中央文件页签继续复用。新协作逻辑按职责独立组织，不进入 Harness 的 Thread/Run、模型循环或私有数据库。

会话绑定的是本机工作目录，不是云端 Project，也不等同 Git 仓库。“工作区”只用于 Workspace 团队，“项目”用于 Project 协作事项，“工作目录”用于本机会话的起始目录。

## 1. 云端与本机分别记录什么

云端是各成员查询共同协作内容的入口，需要持久存储，不是只转发网络消息的无状态中继。它保存成员、Project、Task、知识、会话简报和已上传历史，但不远程启动其他成员的 Agent。

本机记录实际执行事实和待上传内容；云端记录已接收的共享投影。上传落库只能证明内容已同步，不能触发执行。个人阅读缓存只说明当前电脑下载到哪个版本，不反过来成为共享历史或执行事实的权威来源。

| 信息 | 主要保存位置 | 共享方式 |
| --- | --- | --- |
| 普通用户、Workspace / Project 成员、项目关联仓库 | Java / TDSQL MySQL 兼容版 | 按登录身份和成员范围查询 |
| Task、团队知识及版本、正式引用快照 | Java / TDSQL | 具名业务操作和有界读取 |
| 已发布会话的简报和上传水位 | Java / TDSQL 会话头 | 列表查询及轻量通知，不包含消息正文 |
| 已上传定稿消息和工具摘要 | Redis 热窗、Kafka 索引通道、Elasticsearch 消息存储 | 按远端 MessageStorePort 读取，正文在明确点击时分页拉取 |
| 原始执行记录、ACP 绑定、未获上传确认的事件 | 原设备 Runner 的本地持久存储 | 本机使用，按稳定来源标识异步补传 |
| Agent 私有模型上下文和检查点 | 原设备的 Agent 数据目录 | 不上传为可执行状态，不跨机器复制或续接 |
| 工作目录、代码、仓库分支与本机路径映射 | 原设备本地目录和登记记录 | 不上传目录映射，不提供跨机器实时文件/Git 读取 |
| 已拉取正文、同步位置、草稿、页签、滚动位置 | 当前电脑的个人应用数据 | 按服务域、账号、Project、会话隔离，不广播给其他人 |
| 共享附件 | 后续确定的服务持久目录和数据库关联 | 按所属 Project 授权；已有规划缺口不视为本轮实现 |

云端只拥有设备已上传的内容。“最新消息”指最新已上传版本，并显示最近上传时间；原设备尚未上传的片段无法凭空读取。原设备离线时，其他成员仍可拉取云端已有记录。

## 2. 已确认场景与技术选择

### 2.1 协作场景

1. 张三、李四、王五属于同一 Workspace，例如开发组。任意成员可创建 Project，再从该 Workspace 中选择参与者；加入 Project 不自动获得 Git 托管仓库权限。
2. 一个功能、一次架构改造都可以作为 Project。Project 可涉及多个仓库，也可仅用于方案讨论而不关联仓库。
3. 会话选择一个本机工作目录和 Agent。目录可以不是 Git 仓库；本机 Agent 根据自身权限访问目录内外的内容。仓库关联是协作信息，不充当唯一允许访问的路径清单。
4. Project 内会话默认共享，其他 Project 成员先看简报和未同步标识。轻量 SSE 可自动更新简报和 Task 状态；点击同步才下载正文，正文后续更新仍由查看者主动触发。
5. 张三在自己的会话 @李四的会话，主动获取云端可读范围的快照，预览后带入张三自己的 Agent；不向李四的会话发送命令。
6. 张三 @李四并明确发布 Task。李四接收后，在自己的电脑主动选择工作目录及 Agent 开始，把 @Task 材料交给自己的会话。
7. 同一个账号换到另一台电脑，也只能只读原会话；需要继续工作时，基于快照新建当前电脑的会话，不复用原设备的可执行 ACP 身份。
8. Workspace 下沉淀团队规约、术语和技术知识；Project 内会话可引用具体知识版本。Project 看板展示成员会话简报和 Task 情况。

不属于 Project 的个人会话保持私有，不因选中一个目录就自动发布。首次把会话发布到 Project 时应明确发布范围；既有个人历史不自动批量上传。

### 2.2 保留的技术栈

| 部分 | 目标职责 |
| --- | --- |
| Electron + React / TypeScript | 本机桌面、受限原生端口、复用 UI、个人缓存及协作页面 |
| runner-core | 本机发起和执行记录、设备归属、后台生命周期、异步上传及结果核对 |
| acp-runtime | 通过官方 SDK 连接本机 Agent；标准能力和可选 Provider 扩展分开 |
| project-service | 已有本机文件、阅读与 Git 策略；包名保留，不承担云端 Project 成员业务 |
| Java 单应用 | Spring Boot 4.0.6，interfaces/application/domain/infrastructure 四层；用户、组织、同步及协作应用分域 |
| TDSQL MySQL 兼容版 | 组织、会话头、Task、知识和快照等控制面数据；单份 schema.sql，由 DBA/开发者显式建表，启动只核对 |
| Redis / Kafka / Elasticsearch | 热消息窗口、幂等/会话等热状态、异步索引和轻量通知；定稿消息正文不回迁 TDSQL |
| workbench-contracts | 平台业务与设备上传契约，独立于旧 Harness 内部协议 |

Java 框架、MyBatis-Plus、连接池、日志及中间件版本以 [HC-210 Spec](../spec/HC-210-Java高可用基础框架.md)、当前 pom.xml 和 HC-211 后续整改为准，替代 HC-194 的旧依赖与 Flyway 方案。本轮不调整依赖或另建后端实现。standalone 开发模式不证明 Redis/Kafka/ES 集群已验证。

### 2.3 Lody 参考与本项目选择

参考固定提交的桌面分层、本机工作目录、ACP 会话、mentions、历史显示和作者身份。Lody 的同会话接管说明是参考产品事实，不再是本项目的协作目标。Java/TDSQL 的 Project 权限、Task、按需下载及知识模型由本项目定义，不能把公开客户端接口描述成完整托管服务实现。固定来源及许可线索见 [Lody 对照](../research/192-Lody协作能力对照.md)。

关系库目标仍为 TDSQL MySQL 兼容版；物理主键、业务 UUID、DATETIME(3)、状态数值码和索引按远端团队规范落地。当前只维护 schema.sql，已移除 V001–V003 和 Flyway；发版后的增量结构变更方式由后端后续任务确定。外网 MySQL 不能替代内网 TDSQL，standalone 消息存储也不能替代真实中间件验证。

桌面业务请求和用户级轻量 SSE 由 main 管理，React 消费具名端口。设备只通过 HTTPS 上传、心跳和登记仓库，没有 WSS 下行命令通道。通知只更新简报、Task 和相关元数据，不能携带流式正文或触发 Agent；跨机器正文下载后也不转为实时订阅。

按远端 D10，不提供 Java → 原设备的实时文件/Git 阅读路由，原只读路由成果仅保留历史证据。本机阅读器继续用于当前设备；跨机器视图只展示已上传消息和工具摘要，不用查看者电脑的同名目录冒充来源。Task 的保存、接收和通知均不是执行命令。

## 4. 模块边界

下表是新版目标职责，不表示新增业务已经创建。沿用既有七个 npm workspace，Java 内按业务包拆分，不为每种业务另建网络服务。

| 模块 | 负责 | 边界 |
| --- | --- | --- |
| apps/desktop | 窗口、main/preload、页面装配、本机与云端具名端口 | 不将通用 URL、shell、凭据或文件系统暴露给 React |
| apps/runner | Runner 装配、设备身份和进程托管 | 与窗口生命周期分开，执行仅来自本机已授权入口 |
| workbench-ui | 公共主题、既有对话/工具/输入/文件、导航、看板及 Task 展示 | 不联网执行业务，不依赖 Node/Electron 或 Agent 内核 |
| workbench-contracts | Workspace / Project / Task / 知识 / 上传 / 查询的公开契约 | 不暴露 Harness Thread/Run/检查点类型 |
| runner-core | 本机输入受理、持久事件、补传及设备关联 | 云端 Task 或他人查看动作不能直接变成本机执行 |
| acp-runtime | 本机 ACP Client、能力协商、通知、审批和取消 | 一个会话一个 cwd，不因 Project 或仓库表而假定文件访问范围 |
| project-service | 本机工作目录中的文件、预览、已存在 Git 能力 | 非 Git 目录可用文件能力；Git 写入口本期不装配 |
| 可选 Provider | 家族启动、认证差异及专有增强，如 Harness Trace/设置 | 通过公开扩展注册，通用模块不按 Agent 名称分支 |
| Java 服务 | interfaces → application → domain，infrastructure 实现领域端口；组织与同步由 HC-211、协作应用由 HC-212 承接 | 保留远端分层、状态机与中间件契约，不启动本机 Agent |

### 4.1 依赖方向

UI 依赖公共契约和本区视图模型；main/Runner 通过各包公开入口装配。Runner 使用 ACP 与项目服务；可选 Provider 依赖通用扩展接口，通用层不反向依赖 Harness。Java 只使用平台契约，既有公共 JSON Schema/OpenAPI 保持唯一源。具体 Agent 分层见 [Agent 接入架构](Agent接入架构.md)。

Workspace / Project 成员、Task 和知识的业务规则留在 Java 及桌面协作层，不写进 ACP 运行时或 Python Agent。@材料由平台固定为可显示、可发送的内容；Agent 无须理解团队成员表或工程任务编号。

### 4.2 旧代码迁移与退出

保留已提取的 UI、文件/Git 策略及其真实证据，不因产品模型变化重写整个中右区域。旧 CLI/TUI/Web 仍按替代能力交付后退役；不通过包装原 Controller 重建新平台。

HC-211 已拆除服务端 execution、设备 WSS、会话正文 SSE 和原共享目录路由。桌面 collaboration-client 与 Runner 仍留有旧调用，需按新契约替换；不能因为服务端完成就宣称客户端已接通。本轮保留既有 UI 和本机策略，不恢复已移除的旧服务端通道。

### 4.3 桌面与后台生命周期

沿用 Electron main / preload / renderer 隔离、CSP、受限原生目录选择和具名 IPC。应用监督本机 Runner；关窗保留后台执行，明确退出等待本机收尾。重开不启动第二个竞争相同设备身份和目录的 Runner。Windows 托盘、macOS 重开及平台组合按各自实际证据验收。

个人草稿、阅读位置、同步游标和页签按服务域、账号、Project、会话隔离；恢复共享内容前重新核对成员资格。本人其他设备读取云端副本，不取得原设备执行句柄。

### 4.4 设备、工作目录与权限

设备关联稳定普通用户和安装身份；本机登记工作目录，实际根路径由本机保管。会话关联原所有者、原设备和一个工作目录绑定。云端 Project 是协作范围，不是目录的上级路径或 Agent 沙箱。

起始目录可以没有 Git，也可以包含多个独立仓库。Agent 对额外目录的能力、OS 权限与用户授权沿用其真实执行机制；平台不强制把所有相关仓库迁到一个新父目录，不把 `CONVERSATION_REPO` 当执行白名单。

| 操作 | 谁可以做 |
| --- | --- |
| 查 Project 简报、主动拉取会话、引用可读快照 | 当前有效 Project 成员 |
| 发起、取消执行、回答运行中的人工交互、改变本机 Agent 配置 | 原用户在原设备通过本机受限入口操作 |
| 创建并指派 Task | 当前 Project 成员，目标同为当前 Project 成员 |
| 接收并主动开始 Task | 当前被指派用户；执行使用其当前电脑上的本人会话 |
| 同账号在其他设备继续工作 | 只读原会话，并基于快照新建本机会话 |
| Git 提交、推送 | 本期产品入口暂缓，后续另行设计本机操作 |

UI 提示、Java 业务接口和 Runner 的来源核对共同落实边界。不能只依据“同一账号”“同一 Workspace”或客户端提交的 deviceId 允许跨机器控制。Project 成员变更在上传、读取、引用和 Task 操作时由服务重新核对；退出成员后拒绝新的共享请求，已经展示的内容不宣称能够远程收回。

## 5. 数据归属与最小模型

下表区分云端模型与本机概念，不是新增 DDL。当前服务端 schema.sql 和正式契约以 HC-211 为准，快照/Task/知识/通知由 HC-212 交付。本机工作目录记录不要求另建云端表，不恢复已经移除的 V001–V003。

| 对象 | 必须表达的关系 |
| --- | --- |
| USER | 稳定用户 ID、显示信息和启用状态；无岗位预设 |
| WORKSPACE / WORKSPACE_MEMBER | 真实团队及其成员；Team 与 Workspace 不再分两层 |
| PROJECT / PROJECT_MEMBER | Project 属于一个 Workspace；成员必须来自该 Workspace |
| REPOSITORY / PROJECT_REPOSITORY | 团队级仓库目录；Project 引用其中零到多个仓库，同仓库可被多个 Project 引用 |
| DEVICE | 设备所属用户、安装身份及连接信息；在线不代表 Agent 正在运行 |
| LOCAL_WORKDIR_BINDING（本机概念） | 原用户、原设备的起始目录；可非 Git，真实路径仅本机保存，当前云端 schema 不含此表 |

## 6. 本机输入、上传与主动同步

### 6.1 本机执行主路径

    本机本人发送 → 固定问题和引用材料 → 本机持久保存输入与执行记录
    本机 Runner → 按一个 cwd 建立或继续本机 ACP 会话 → 即时显示输出
    本机保存完整执行记录 → 将定稿消息、工具摘要和状态按序异步上传 → Java 返回确认水位

本机输入、所用快照及最终执行文本需要来自同一份已持久材料。云端查询或快照准备失败时明确反馈；已经开始的执行若上传暂时失败，保留本地补传，不靠重新执行补齐历史。网络、模型调用和本机写入不组成一个跨系统长事务。

同一会话一次运行一个输入。本机 Runner 沿用账本、去重、取消和真实终态处理；同一消息重传不生成第二次执行。已知目录/仓库的写资源沿用本机占用策略，目录外访问的并发边界在 Spec 细化，不能宣称只锁 cwd 已覆盖所有外部路径。

### 6.2 异步上传

按远端 D2，本机完整事件留在本机；上传类型为 user、assistant、tool_summary、status，包含定稿消息和工具调用摘要，不上传 token 碎片、工具完整输出或实时文件正文。设备 POST sync 的批次、连续性、幂等与确认水位沿用 HC-211 契约；Java 使用 Redis 热窗和 Kafka/ES 消息通路，客户端按返回水位保存本机补传位置。

简报由 Runner 规则生成并随批次上传，brief_source=rule；Agent 总结是后端登记的后续增强。界面使用后端状态词及上传时间，不从设备在线状态推断执行完成。

上传失败与 Agent 执行失败分别显示。断网不回滚本机已发生的修改；结果未知时保留未知事实，不自动重跑。设备重连复用本机持久记录补传，不向其他设备转派旧执行。

### 6.3 其他成员主动读取

    进入 Project → 查询简报列表并接入相关用户的轻量通知
    明确点击某会话的同步 → 获取云端当前上界 → 按页拉取到该版本
    本机完整应用相应内容 → 保存自己的同步位置 → 显示已同步至该版本/时间
    简报通知/刷新发现更高水位 → 显示有更新 → 用户再次点击拉取正文增量

首次拉取正文前，明确展示这是一次下载操作；点击标题可以定位摘要及只读页，不能悄悄触发整段历史预取。不同页签仍展示同一份本机已应用版本，不因导航改变同步位置。

| 查看状态 | 含义 |
| --- | --- |
| 未同步 | 当前电脑尚未下载正文，仅有简报 |
| 同步中 | 正在拉取指定上界；不能把网络已接收冒充本机已应用 |
| 已同步至版本/时间 | 当前电脑已有该范围的正文，不表示原会话永久保持同步 |
| 有更新 | 最近一次简报查询或轻量通知表明云端水位高于当前电脑已应用位置 |
| 同步失败 | 保留已确认位置和可读的旧版本，明确错误并提供主动重试 |

“未同步/已同步”按服务域、账号、Project、会话和当前设备保存在个人状态，不能写成云端会话的一枚全局布尔值。成功拉取到某上界后，不能因为该页还有更高版本的简报就宣称已下载全部。

用户已确认采用远端轻量 SSE：项目简报、Task、知识等相关事件可自动更新摘要状态，必要时按事件回源查询对应元数据。正文仍只在用户明确点击同步、引用取材或继续翻页时读取，不因通知批量预取历史。流的权限过滤、去重、重连和补发按 HC-212 实际契约实现，不再设计一套独立通知协议。

## 7. Task 分派与本人主动开始

    张三 @李四 → 打开任务表单 → 明确发布到同一 Project
    李四查看任务 → 接收 → 选择本机工作目录、Agent 和本人会话 → 主动开始
    本机输入引用 Task 的固定版本 → 执行结果异步上传 → Task 关联会话供成员主动查看

@人只选择候选，发布必须是明确的业务动作。Task 记录目标、说明、验收条件、涉及仓库和引用材料；候选来自同一 Project 的有效成员。无需指定产品经理、开发或其他岗位。

接收只表示愿意承担，不能创建 `execution.start`、自动回答审批或在后台启动 Agent。开始操作由被指派人在自己的电脑发起，可以选择当前设备上的现有本人会话或新建会话；不改原会话所有者、原设备或 ACP session ID。

Task 的状态词、允许动作、CAS/幂等、审计和操作人规则以远端 HC-212 后续正式规格及返回结果为准，桌面不另外定义一套状态机。发布人、被指派人和项目负责人是对象关系，不是预设岗位。任务变更有版本，已经开始的本机输入保留当时材料，不被后续编辑替换。

Task 与执行会话的关联按远端交付契约消费，不因本地设计另建 TASK_CONVERSATION 后端模型。任务可以先独立存在；引用 Task 只带入材料，不等于接收或开始。工程 HC 编号与产品 Task 不自动互相创建。

旧设计中的 `currentUserId`、接续人和同会话控制权交接，不作为新版权限来源。交付工作内容通过 Task 与快照表达，不迁移 Agent 私有检查点。

## 8. @引用与团队知识

### 8.1 引用范围

| 选择来源 | 动作 |
| --- | --- |
| @会话 / 消息 | 只查同 Project 当前可读来源，主动获取云端已上传范围，预览后固定快照 |
| @人 | 从同 Project 成员中选择，明确发布 Task，不向其 Agent 发送 prompt |

会话共享和跨会话引用以 Project 为边界，不再只检查同一 Workspace。Workspace 知识是明确的跨 Project 例外；不因此允许读取其他 Project 的会话。Project 成员关系也不替代仓库本身的 Git 授权。

### 8.2 固定快照

选择 @会话并明确取材，属于一次主动读取；只取用户确认的有界范围，不先后台同步全项目。预览显示来源、上传版本、时间、消息范围和实际正文。来源继续输出不修改已经固定的引用；显式刷新生成新快照。

快照生成/读取、默认范围、存储、大小预算和返回卡片按 HC-212 契约处理；远端方案 D5 为 TDSQL 快照、默认最新 20 条和 64KB 预算，超限的正式返回行为由该任务明确。提交本机问题前核对访问和引用，固定来源 ID、版本、正文和用途；预览、本机实际输入和后续上传的引用来自同一份材料。桌面不另建引用后端或对象存储通路。

引用按普通文本材料接入通用 Agent，不需要新增 Agent 专有协作协议。材料是参考内容，不改变系统权限、Agent 配置或本机工作目录。跨机器新建会话只继承这些明确选定的可见内容，不宣称恢复了原 Agent 的隐含模型上下文。

### 8.3 团队知识

Workspace 知识保存规约、术语和通用技术说明，至少提供标题、正文、作者、更新时间与版本。Project 会话主动引用指定版本；后续知识修改不改写已发送内容。初版直接做条目管理和版本引用，不以向量数据库或自动注入整个知识库为前置。

知识条目、不可变版本、归档、搜索及引用解析由 HC-212 后端提供；桌面消费其权限与返回类型。首版只做显式 @知识，不增加默认知识自动注入或新的检索服务。

## 9. ACP 与 Harness 的接合点

通用 ACP Client 运行在本机 Runner，按真实 `initialize` 能力使用会话建立、恢复、内容块、取消与人工交互。一个会话绑定一个 cwd，目录不要求 Git；额外路径按 Agent 能力、OS 权限和用户授权处理，不凭 Project 仓库列表推导。固定 Lody 代码的 [acp-runner.ts](https://github.com/LodyAI/Lody/blob/58f594a27da5262cb51164daf8b6bbd0333c4541/apps/cli/src/agent/acp-runner.ts) 与 [agent-client.ts](https://github.com/LodyAI/Lody/blob/58f594a27da5262cb51164daf8b6bbd0333c4541/apps/cli/src/agent/agent-client.ts) 提供 workdir/cwd 及额外目录能力的参考，不代表所有后端支持完全相同。

原生 ACP session ID 与平台会话 ID 分开。原设备恢复仍核对原生绑定；同账号换机和其他用户引用旧会话，都创建当前设备自己的原生会话。Java 的共享历史不作为可执行检查点，不把平台 Task 直接转成原设备 ACP 调用。

标准事件、模型/模式/命令和审批仍按 [Agent 接入架构](Agent接入架构.md) 分层。Provider 可提供 Trace 和专有设置增强；通用 UI 与 Java 不读取 Harness 配置、日志 marker 或数据库。没有 Harness/Python 时平台仍能使用其他 Agent。

用户明确 ACP 协议以当前远端为准，SDK、消息和 Provider 能力均消费已合入的公开实现及规格，不按 Lody 另建一套协议。HC-197 同事归属不变；尚未交付的运行时入口要记录真实缺口，已交付部分不因旧等待记录被忽略。当前 acp-runtime 根出口仍是包标识骨架，不能由 Harness Agent 侧协议已交付推断正式桌面执行已经接通。

## 11. 部署、账号与数据维护

桌面 main 管理同一服务域的 Cookie/CSRF 和具名业务请求，凭据不暴露给 React。Runner 的设备身份与登录会话分开，切换账号不重绑旧设备或接管旧运行。服务地址、数据库与信任证书沿用现有单一配置路径，不为每项状态增加配置开关。

### 11.2 数据与制品

云端分别备份 TDSQL 控制数据、消息存储及后端要求的中间件持久记录；本机备份目录、账本、Agent 数据和未上传内容。建表依据为当前 schema.sql，应用启动只读核对，不再执行 Flyway 或 server:migrate。旧库不能仅靠新版启动自动转换，备份及导入按后端方案执行；本轮未操作数据库。

Git 写入口暂缓不改变本机仓库内容，也不要求用户挪动已有目录。知识、附件、Task 中的文件与本机代码分别表达，引用内容不冒充已克隆代码。

### 11.3 双平台与演示

继续交付 Windows/macOS 桌面、通用 Runner、Java 制品及 SQL，Agent 为可选制品。分别验证目标平台，Mac 构建 Windows 包不能替代 Windows 运行证据；普通 MySQL 不能替代内网 TDSQL 验收。保持手工升级和离线导入方向，不把公网自动更新作为内网前置。

新的两电脑演示为：A 创建 Project 并加入 B → A 本机会话异步上传 → B 只看简报 → B 主动同步并引用 → A 或 B 明确发布 Task → 被指派人接收并在自己的设备主动开始 → 看板查询新进度。原设备离线时仍能查看已上传内容；全过程不接管他人或本人另一台电脑的 Agent。

## 13. 后续可观察的验收目标

1. 同一 Workspace 的用户创建 Project 并加入部分成员，其他 Workspace 成员不能读取该 Project 会话；仓库关联可为空，也可有多个。
2. 在非 Git 本机目录创建会话并正常使用文件能力；Agent 对其他路径的实际支持按其能力和授权验证，不由仓库表限制。
3. 另一用户和同账号另一台电脑默认只见摘要；轻量通知可更新摘要和 Task 状态，但不下载正文。点击同步后按远端接口拉取增量，正文后续仍需主动读取。
4. 原设备停止上传后，查看者明确看到最后上传时间；自己的同步位置不改变其他用户或设备的标识。
5. @会话预览与本机执行所用快照一致；来源继续更新不改写旧引用，跨 Project 来源被拒绝，Workspace 知识可按版本引用。
6. 发布或接收 Task 不启动任何 Agent；仅被指派人明确在本机开始后执行，并关联本人会话，看板可查询相应事实。
7. 通过现有 HTTP/设备写入口也不能跨机器发送、取消、回答审批或提交推送；不能只验证按钮隐藏。
8. 保留本机头像、工具、主题、文件页签与短窗口布局；Git 写入口隐藏，跨机器实时文件/Git 入口不提供；双平台、实际中间件、TDSQL 与完整异常组合另验。

这些是新版实施和验收目标，不是本轮通过记录。前端已按用户确认登记 HC-217～220 四卡并准备本地提交；均待认领，不改旧卡状态，也不启动生产开发。
