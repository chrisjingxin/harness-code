# 桌面前端交互设计

更新：2026-11-12。本文整理已确认的前端方案，只定义页面、信息位置、交互、视觉和组件归属，不是生产实现或正式任务 Spec。前端工作已登记为 HC-217～220，当前均待认领；本次不自动开启生产实现。

服务端与 ACP 的实现及设计均由同事负责，我们只引用远端已有接口、文档和公开宿主能力，不补充其领域模型、状态机、数据库、传输或协议设计。接口尚未交付的部分记录为 UI 依赖，不反向要求服务端实现本稿自创的字段。

整体产品约束见[顶层设计](多人协作工作台顶层设计.md)，工程分工见[任务衔接说明](../project/项目协作设计任务衔接.md)。后端与协议文档仅作为输入引用，不在本文展开。

## 1. 沿用的确定事项

- Electron 桌面，首版使用一个团队；Project 是协作事项，工作目录是用户创建会话时主动选择的本机文件夹，两者分开展示。
- 现有冷紫主题变量、字体、品牌图标、头像、用户 SVG、消息、工具卡片和输入区继续复用。浅深色都使用中性大面积背景，紫色用于主要操作和选中，不重新做一套配色。
- 本人原设备的会话可操作；他人会话和本人其他设备的会话均只读。正文由用户主动同步，轻量通知只更新简报、任务和更新标识。
- 会话绑定一个目录，可以不是 Git；目录选择不代表创建云端 Project，也不自动共享个人历史。
- 本机文件树、只读预览、中央可关闭文件页签继续保留。跨机器不显示原设备实时文件/Git，产品 Git 提交/推送入口暂缓。
- 设置沿用居中弹窗。页面高度随窗口变化，左栏以现有 280 逻辑像素为基线，两侧收合和拖宽沿用现有布局。

## 2. 建议的信息架构

左栏以 Project 为主，不再先展开设备才能找会话。设备信息放在会话上下文及设置中。

| 左栏位置 | 入口与内容 | 选择后的中央页面 |
| --- | --- | --- |
| 顶部 | 品牌、当前团队名称、Project 切换和创建入口 | 切换 Project 后进入项目概览，保留之前项目的个人草稿和阅读状态 |
| 项目导航 | 概览、任务、项目资料 | 项目看板、任务列表、项目成员/仓库资料 |
| 会话操作 | 一个明确的新建会话入口、紧凑搜索 | 本机新会话准备页；搜索先过滤当前已加载会话 |
| 会话列表 | 我的/全部切换，可按成员或状态筛选 | 选择对应本机会话或远端只读会话 |
| 团队入口 | 团队知识 | 团队知识列表和正文，所属范围与当前 Project 分开展示 |
| 账号与设置 | 当前用户、设置和退出 | 设置居中打开，退出按现有身份流程处理 |

“我的会话”表示所有者是当前用户，可能包含其他设备上的会话，不因此一律可执行；列表额外显示设备或只读信息。会话行保留图标与标题对齐，标题省略但可查看全名，选中使用清晰实心底色，不加选中边框。

建议默认页面是 Project 概览；首次没有 Project 时显示创建入口。重开可恢复当前账号上次仍可访问的页面，不自动创建会话或下载他人正文。

## 3. 中央与右侧的使用规则

| 中央页面 | 中央主体 | 右侧 |
| --- | --- | --- |
| 本人原设备会话 | 复用对话、工具、输入及已有文件页签 | 当前工作目录文件/可用只读变更，按用户偏好开合 |
| 远端只读会话 | 简报、同步时间、只读消息和工具摘要 | 不显示实时文件面板，释放阅读宽度 |
| 项目概览 / 任务 / 项目资料 / 团队知识 | 对应页面及详情 | 默认不占用文件面板空间 |

会话的“对话 / 轨迹 / 文件”标签只属于该会话，Project 看板和任务列表不塞进这一栏。切换到项目页面时保留原会话的草稿、页签和文件阅读位置，返回时恢复。

顶栏统一字体和图标基线，主要显示 Project 或当前页面名称；会话上下文再显示所有者、原设备、工作目录或只读与同步时间。设备在线、执行状态和本地已下载版本分别表达，不用“已连接”笼统代替。

## 4. Project 创建与资料

建议先用居中表单填写名称和说明，调用已有创建接口。创建成功后进入“项目资料”，再逐项添加团队成员和关联团队仓库；仓库可以不选。

项目资料包含概况、成员和关联仓库。管理按钮按当前接口权限呈现，普通成员可读信息保持可见；不在前端定义新的负责人权限或 Git 授权规则。成员搜索和仓库选择只消费同事已提供的数据范围。

创建后的资料设置失败时，明确显示项目已创建及失败项，保留输入用于重试，不把多次接口调用包装成未提供的原子操作。首版不增加完整组织管理后台。

## 5. 新会话与本机会话

新建会话页显示当前 Project、“选择文件夹”按钮和可用 Agent 入口；目录由用户通过已有原生选择能力选择，不由系统自动指定。工作目录名称与 Project 名称分开，目录可非 Git，也不代表 Agent 只能访问这个目录。

本人原设备会话继续使用现有输入、消息头像、工具展示、模型/命令入口和人工交互部件。可用动作来自公开宿主能力及当前状态，未提供执行入口时可保留草稿并显示“Agent 暂不可用”，不能用空回调制造开始成功。

目录、Agent 和执行准备是否可用，由现有端口或同事交付决定。前端只负责选择和结果展示，不在本轮设计 Runner 内部流程、启动命令或 ACP 方法。

## 6. 远端会话与主动同步

第一次点开远端会话，中央显示标题、所有者、原设备、简报、最近上传时间和“同步会话”按钮。点击会话行本身只定位该页面，不在后台取整段正文。

| 本机阅读状态 | 显示和操作 |
| --- | --- |
| 未同步 | 展示简报，提供同步会话 |
| 同步中 | 显示正在同步，保留已有内容，避免重复触发 |
| 已同步 | 显示最近同步时间和只读正文，保留手动同步入口 |
| 有更新 | 显示更新标识和同步按钮，当前正文保持已下载版本 |
| 同步失败 | 保留已下载部分和阅读位置，说明失败并提供重试 |

这些是前端阅读状态，不是新后端状态字段。每台电脑按自己的已应用位置判断“有更新”，收到轻量通知不代表正文已同步。同步后保持原阅读位置，提示有新增内容，由用户选择跳转。

只读会话不显示可发送输入框、取消或审批操作。提供“引用到我的会话”和“创建任务”两个明确动作；即便所有者是当前账号，只要原设备不同也采用该模式。工具摘要沿用现有卡片的简洁显示能力，不展示未上传的完整工具输出。

## 7. @引用、任务与知识

### 7.1 输入区的引用选择

@ 菜单建议按会话、成员、任务、知识分组。本机文件提及保留既有路径和选中交互。会话/任务范围属于当前 Project，知识属于当前团队；列表只展示接口允许访问的条目。

选择会话后主动获取引用预览，显示来源、时间、范围和实际材料。用户可以移除或主动刷新引用；来源变化只提示有更新，不替换已选材料。输入区使用紧凑引用卡片，发送后的历史可展开同一份内容。

引用到我的会话时，先选择当前设备上的本人会话或新建会话，带入引用后由用户发送；不自动发送一条问题。引用卡片的读取和正文由既有接口/宿主给出，不在前端重造快照存储或协议。

### 7.2 @成员与任务

@成员打开任务草稿并预选被指派人，用户填写并明确发布。正常对话发送与任务发布区分为两个可见动作，避免输入一个人名就产生执行。

任务列表建议提供“指派给我 / 我发布的 / 项目全部”筛选，点击在中央打开详情。详情显示正文、引用、发起人、被指派人、状态和已返回的记录；状态名称、可用动作及权限全部消费服务端规则，前端不另定状态机。

接收后提供独立的“在本机开始”动作，选择当前设备上的本人会话或新建会话，确认工作目录及 Agent，再调用已有宿主动作。接收、查看通知、关联任务详情都不自动发送问题或启动执行。缺少接口时登记依赖，不补写服务端或 ACP 实现。

### 7.3 团队知识

知识在中央页面显示列表与正文，编辑和历史版本通过具名入口打开。版本信息在引用预览中可见；本期只做显式 @引用，不默认注入整个知识库。

知识分类、搜索结果、版本和归档状态以服务端交付为准。前端保持列表、阅读、编辑和引用的统一视觉，不设计新的后端分类或检索系统。

## 8. Project 看板

建议概览包含两块主内容：成员进展和任务看板。顶部只用紧凑统计及更新时间，不堆叠大面积统计卡片。

- 成员进展显示成员、最近会话简报、执行状态、上传时间及更新标识；点会话进入只读阅读页，仍需主动同步正文。
- 任务看板按后端实际状态分列，卡片显示标题、被指派人和简短进度；点击进入任务详情。拖动改变状态不作为首版前置，先使用明确操作按钮。
- 轻量通知只更新相关元数据，不抢焦点、不替换页面、不改变草稿和阅读位置。通知断开时显示可理解的状态并保留手动刷新；连接和补发按既有客户端接口消费。

看板在窄窗口优先纵向排列，必要的列在页面内部滚动；不以固定高度挤压主要内容。成员和任务区域的数据不足时显示具体空态，不用模拟数据冒充实际进度。

## 9. 视觉与通用交互

沿用公共字体、语义色、按钮、图标尺寸、圆角、间距和焦点样式。新增页面使用相同字号层级，正文与次要信息保持清楚区分；日期、状态和同步标识不争抢主标题。

大面积用中性背景和留白分区，仅必要容器使用细分隔线，避免每一层都套边框。左栏选中使用清晰纯色底，图标与标题按同一行对齐；主要操作使用冷紫色，普通文本维持中性色，浅深模式都能识别选中。

缩小窗口时沿用先收右侧、再收左侧的布局能力，中央保持主要阅读和操作空间。长标题省略、文件标签关闭按钮、长草稿滚动和设置弹窗使用现有已修复部件，不为新增页面再复制一套。

| CollaborationNavigation | 保留基础样式和动作分离方式，按 Project 导航改造视图模型 |

| 公共主题、BrandMark、RoleAvatar、Markdown、高亮 | 全部新增页面共同复用 |
| desktop renderer 的个人状态 | 页面选择、草稿、文件页签、阅读位置和本机同步状态的隔离装配 |

组件来源见 [UI 公开出口](../../../packages/workbench-ui/src/index.ts)、[导航组件](../../../packages/workbench-ui/src/navigation/index.tsx)、[布局组件](../../../packages/workbench-ui/src/layout/index.tsx)和[对话显示类型](../../../packages/workbench-ui/src/conversation/types.ts)。这些是前端内部接点，不是新线上契约。

服务端、共享传输契约、数据库、中间件、Runner 核心执行及 ACP/Agent 设计由同事维护。我们这边可以设计原生目录选择、可用动作展示和客户端调用的页面反馈；涉及同事端口的缺口只列依赖，不自行新增 API、设备命令、ACP 方法或后端状态。
