# 代码索引

代码索引是默认关闭的实验能力：CLI 共用 `/code-index`，Python AgentHost 管理当前工作区的 `.harness-index/`，模型只看到 Harness 只读工具 `codebase_explore`。底层运行时是精确锁定的 `@colbymchenry/codegraph@1.1.6`（MIT，主包 + 当前平台包，随包 Node / JS / WASM）。用户界面和用户文档不出现该名称。

```text
CommandRegistry /code-index
  → InteractiveController / selector
  → protocol code_index.status|apply|changed
  → AgentHost
  → CodeIndexManager
       ├─ CodeIndexStateStore  (.harness-index/state.json)
       └─ CodeIndexRuntimePort
            ├─ 生产：随包 Node + 私有 MCP/JSONL
            └─ 测试：进程内 fake
  → codebase_explore ← CodeIndexQueryLease
```

私有查询 MCP 不进入用户 `/mcp` catalog、AgentEngine 外部 tools 或审批分类。`codebase_explore` 进入 canonical 只读工具目录，失败时回退 glob/grep/read_file；编辑仍遵守 Snapshot。

## 配置与协议

`[experimental.code_index] enabled` 默认 `false`，只在 Host 启动时读取，不进 `config.write` 白名单。开启后协商 `code_index.read` / `code_index.manage`。建图 job 走 `code_index.apply` 与 `code_index.changed`，不复用 `run.progress`，不占 `pendingOperation`。

## 生命周期

`absent → running → serving → ready`。写操作前持久化 `running`；查询进程存活期间持久化 `serving`；干净关闭查询后才写 `ready`。Host 启动看到 `running`/`serving` 转为 `incomplete`，只允许 status/rebuild。generation 只在成功建图并重连查询后增加；活动 Run 不热切换。

同一 Host/workspace 最多一个 job、一个查询 session、一个 watcher。活动查询租约阻止 rebuild/remove；job 期间新 Run 不取得 `codebase_explore`。

## 平台

支持 macOS x64/arm64、Linux glibc x64/arm64、Windows x64。musl 与 Windows ARM 明确失败。当前 macOS 完成真实离线闭环；其它平台真机稳定性是去掉实验标记的后续门槛。主包 optionalDependencies 含 `win32-arm64`，Harness 仍拒绝该 target。已安装 tarball 的 `license` 字段为 MIT，包内无独立 LICENSE 文件。
