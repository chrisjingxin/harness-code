# Slash Command 体系实施设计

## 定位与边界

Slash Command 是交互式 Harness TUI 的功能入口，而不是面向脚本的命令行子命令树。它以少量稳定的顶层命令打开 OpenTUI 的 Picker、Manager、Viewer、Dialog 或执行明确的 Action；CLI Subcommand 与 JSON-RPC 则分别服务自动化和跨进程通信，三者复用底层服务但不共享文本语法。

```text
Slash Command → Command Registry → Dispatcher → InteractiveController → Snapshot
                                       │                 │                  ↓
                                       └→ AgentPort/RPC   └→ TuiAdapter → React/OpenTUI adapter
```

`packages/cli/src/interactive/commands.ts` 的不可变 Command Registry 统一驱动帮助、补全、菜单、解析、capability 可见性与未知命令建议。`interactive/command-dispatcher.ts` 中的 Builtin Handler 只返回表现层无关的 semantic operation（`notice`、`request-exit`、`clear-thread`、`request-confirmation`、`present`、`compact`、`mcp`、`request-handoff`、`submit-prompt`）；`interactive/controller.ts` 负责解释结果、通过 `InteractiveAgentPort` 调用 Agent 并维护多步工作流。TUI 只通过 `tui/application/adapter.ts` 把终端动作映射为 `InteractiveIntent`，再解释 `InteractiveResult` 打开 Picker 或交给宿主回调；未来 Web adapter 复用同一 Controller，不会重新实现命令语义。

`packages/cli/src/tui/presentation/overlays.tsx` 提供两项可复用基础：`SearchPicker<T>` 统一遮罩、尺寸、窄终端降级、搜索焦点、加载/错误/空态、滚动与 Enter 选择；调用方只提供稳定键和领域行渲染。`DialogShell` 复用同一浮层骨架，并接收确认、取消和可选内容。Skill、Thread 和 Model 选择器复用该 interface；浮层关闭后，在允许输入的状态下延后一 tick 恢复 Composer 焦点。

`/model [query]` 要求 `models.read` 且在 active Run/Interaction 中禁用。共享 Controller 消费 `models.list` 的脱敏 catalog、当前 `thread_selection` 与最近实际绑定；确认后立即更新 `ThreadExecutionSelection.primary_profile`，每次 `run.start` 都携带 `model_selection`。若协商 `config.write`，Controller 还会在保存态执行 `config.details → config.preview → config.commit`，只提交 `models.default_profile`；失败不回滚当前 Thread 选择。`run.started` 返回实际 primary 模型后再校准状态栏，`/new` 清除选择并采用已同步的默认值。缺少 `models.select` capability 且当前 Thread 使用 legacy immutable binding 时，Controller 发布 `model-binding` confirmation，adapter 只渲染 Dialog。

## 交互约定

- Picker：`/model`、`/resume`、`/skills`、`/agents`、`/undo`。
- Viewer/Manager：`/mcp`、`/help`、`/goal`、`/code-index`。`/mcp` 空参刷新 catalog 后把服务器连接状态、工具名和错误写成时间线通知；`/mcp add` / `/mcp remove` 走同一命令入口。`/code-index` 在协商 `code_index.read` 后可见，配置关闭时隐藏并对手输给出开启说明；`remove` 走共享 confirmation。详见 [代码索引](代码索引.md)。
- Dialog：`/new`、`/compact`。
- Action / Overlay：`/web`、`/quit`、`/btw`、`/status`、`/redo`、`/title`。

Registry 只声明当前已接入命令。尚未实现的交互入口记录在 [新功能候选](../project/新功能候选.md)，不能提前进入帮助、补全或 capability。`/btw <question>` 发起轻量只读旁路问答，由 `BtwModal` 浮层呈现；`/status` 打开结构化 4 模块运行状态仪表盘（`StatusModal`），两者的呈现均严格不向会话历史/持久化存储写入任何内容。`/goal` 仅 Build：空参查看，`edit`/`pause`/`resume`/`clear` 走 typed Goal operation，其它 remainder 创建或替换目标；Criteria 必须人工确认，Compose 隐藏。`/btw` 不参与 Goal 验收。`/undo`（别名 `/rewind`, `/rollback`）打开历史回合选择浮层 `UndoPicker` 与二次确认 `UndoDialog`，支持三档回退，并在同一 SQLite 事务中作废受影响的 Goal 验收；`/redo` 仅在暂存回退态可用，恢复最近一次撤销但不恢复已作废的 satisfied；提交新 Prompt 时暂存态自动清空。详细路径见 [目标闭环](目标闭环.md)。

`/new` 为创建新 thread 的 canonical 名称，`/clear` 保留为别名；活动 run 下会先发布 `clear-thread` confirmation，确认后才发起取消。`/quit` / `/q` 在活动 run 下发布 `quit-while-running` confirmation，确认后才 `request-exit`；压缩中没有可中止的 Run，不走该确认。`/resume` 的别名为 `/continue` 和 `/threads`。`/title` 的稳定 ID 是 `thread.title`，`safety.runtime` 为 `allowed`，执行中可改当前 thread 短标题；没有 `/rename` 别名，压缩中白名单仍不含 `/title`。不向用户展示内部 `thread_id`。

## 命令契约

每项命令必须拥有稳定 ID、canonical 名称、别名、来源、类别、展示类型、参数提示、所需 capability、thread/空闲状态要求、安全确认策略和执行器。执行器只返回结构化 `CommandResult`（semantic operation），不返回 RPC method 字符串、success/error closure、React callback 或 TUI local action；adapter 只解释 `InteractiveResult`。破坏性命令的确认不是回调，而是共享 snapshot 中的稳定 `confirmation`，adapter 通过 `confirmation.resolve` 回写。

Registry 在生成菜单、帮助和补全前统一计算可用性：缺少协商 capability 时隐藏；当前状态不满足时显示禁用原因。执行中（`activeRun`）是否可跑只由 Registry `safety.runtime` 决定：显式 `allowed` 才放行，未标记视为 `blocked`（失败关闭），禁用原因固定为「当前任务结束后可用」。表现层不得再写「running 就不能提交」。放行清单与子命令例外见 [HC-170 规格](../spec/HC-174-执行中可用运行时命令.md) 第 5 节。命令名称大小写不敏感，参数原文保持不变；未知 `/command` 显示建议而不能发送给模型，`//text` 是向模型发送以 `/` 开头文本的转义方式（执行中普通文字与 `//` 均拒绝并留草稿）。命令菜单数据由共享 snapshot 发布，TUI 只按 draft 做显示过滤，不能重新计算 capability/busy 可用性。

## 状态与安全限制

- 已启动 Run 的模型和 AgentEngineProfile 不可变，不能在运行中热切换。空闲 Thread 的 `/model` 可以更新下一次 Run 的主模型，并自动尝试更新后续新 Thread 的 `models.default_profile`；两条路径独立失败，服务端在 `run.start` 重新解析并写入独立的实际绑定。
- `/compact` 仍遵守现有最近轮次、节省率、归档和隔离规则。
- MCP 和 Skill 视图不得显示凭据、完整敏感 URL、Prompt 或原始大工具结果。

## 当前来源

Builtin 命令不能被覆盖。Skill catalog 以 `/skill:<canonical-id>` 形式提供动态 Prompt 入口，短名称只在全局唯一时可调用。当前不加载 MCP Prompt、Plugin Command 或 Prompt Template。

运行中不监听文件变化。catalog 只在 sidecar 启动时建立快照；没有对应 capability 或可信来源时，命令必须隐藏或拒绝。

## 架构收敛

```text
interactive/commands.ts      Command Registry / Parser
interactive/command-dispatcher.ts  Dispatcher / semantic operation
interactive/controller.ts    InteractiveController：状态、RPC、Picker/Dialog、Interaction
tui/application/adapter.ts   TuiAdapter：终端输入映射为 InteractiveIntent
tui/presentation             React/OpenTUI adapter：输入、焦点、尺寸、渲染
```

命令解析、可用性与执行只存在于 `interactive/`；`interactive/` 不依赖 `tui/`、`web/`、React、OpenTUI 或 DOM。后续命令变更必须沿该 module 接入，不在此文档维护已完成 task 的进度。
