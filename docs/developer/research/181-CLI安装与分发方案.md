# CLI 安装与分发方案

评估日期：2026-09-14。Harness 基线：当前 `dev` 分支工作区；产品版本 `0.1.0`。本文只提供调研结论与候选实施方案，不是已确认的 Task、Spec、Plan 或开发授权。没有修改产品代码。

用户目标：像 Devin / Grok / Codex 一样，一条命令安装后，进入任意文件夹输入 `harness` 即进入交互主界面。

```bash
# macOS / Linux
curl -fsSL https://<企业安装入口>/install.sh | bash

# Windows PowerShell
irm https://<企业安装入口>/install.ps1 | iex

cd some-project
harness
```

## 已确认方向（2026-09-14 对话）

1. **三个系统一起交付**：macOS、Linux、Windows 同一次交付，不把 Windows 留到第二期。Windows 走 PowerShell 安装脚本，不是 `curl | bash`。
2. **给用户的是包管理器安装，不是自包含大包**：安装脚本检测必要依赖（Bun、Python 3.11+、uv）；没有就帮用户装上，再安装 Harness 的界面包和内核包。
3. **不要用 Node 的 `npm install -g` 作为主路径**：CLI 必须由 Bun 运行。用户命令可以是一条 curl/irm，内部是 `bun install -g` + `uv tool install`。

下文第 1 节的「平台 tarball / Windows 第二期」是调研阶段的备选，已被上面三条取代，不再作为推荐方案。

## 1. 结论

**用户侧体验可行。推荐做成「安装脚本 + 依赖检测/补齐 + 包管理器安装」，不要做成 Grok/Codex/Devin 那种单原生二进制，也不要第一期打 200MB 自包含 tarball。**

原因不是安装脚本难写，而是 Harness 的运行时是双进程：

```text
harness（Bun / OpenTUI TUI）  --stdio JSON-RPC v3-->  python -m harness_agent
```

Grok、Codex、Devin CLI 能 `curl | bash` 后立刻变成一个 PATH 上的命令，是因为它们把整个产品打成**一个平台二进制**。Harness 现在还依赖：

- Bun `1.2.19` 跑 CLI（入口 shebang 是 `#!/usr/bin/env bun`）
- 企业源 `@opentui/core` / `@opentui/react` `0.4.3` 及其平台 native optional package
- 与源码树相对路径绑定的 Python sidecar（`packages/agent/.venv` + `PYTHONPATH`）
- Python 3.11+ 以及 `tree-sitter`、`pydantic-core`、`sqlite-vec` 等带 native wheel 的依赖

所以「输入 `harness` 就能进 TUI」这件事，本质是：**把上述运行时从仓库相对路径，改成安装前缀绝对路径，再用安装脚本放到 PATH 上。** 不需要改 Agent 协议、TUI 交互或模型配置语义。

不建议的目标：第一期就做成「用户机器零运行时、单个 50MB Rust/Bun 可执行文件」。那等于重写或冻结 Python Agent，工作量和风险都远超安装器本身。

推荐第一期交付物：

1. 企业托管的 `install.sh`（macOS / Linux；Windows 第二期）
2. 按 `os-arch` 发布的自包含 tarball（私有 Bun + CLI dist + 私有 CPython + 已安装的 `za38-agent`）
3. 安装到 `~/.harness/`，把 `harness` 放进 PATH
4. CLI 按安装前缀定位 sidecar，不再只认仓库 `packages/agent`

## 2. 当前仓库实际能做什么

### 2.1 启动方式

根脚本是源码开发入口，不是安装入口：

```text
bun run dev          → bun packages/cli/src/index.ts
bun run dev -- --cwd <工作区>
```

`packages/cli/package.json` 已经声明了命令名：

```json
"bin": { "za38": "./dist/index.js", "harness": "./dist/index.js" }
```

`dist/index.js` 仍需要 Bun 执行，且构建显式 external 了 OpenTUI / React：

```text
bun build src/index.ts --outdir dist --target bun
  --external @opentui/core
  --external @opentui/react
  --external react --external react-dom --external react-reconciler
```

也就是说：**现在的 `bun run build` 产物不能离开 `node_modules` 独立运行。**

文档已经把安装器标成未交付：`README.md`、`docs/user/快速开始.md`、`docs/developer/project/新功能候选.md`（「macOS、Linux、Windows 自包含运行包与独立安装器」）、以及 2026-07-14 的历史 v0.1 计划。

### 2.2 sidecar 定位（安装器必须改的核心）

`packages/cli/src/index.ts` 的 `startAgent()`：

1. `HARNESS_AGENT_PYTHON` 若存在则用它
2. 否则探测 `packages/agent/.venv/bin/python` 或 `Scripts/python.exe`
3. 再降级到 PATH 上的 `python3`
4. `spawn(python, ["-m", "harness_agent"], { cwd: 用户工作区, PYTHONPATH: agent 源码目录 })`

`resolveAgentRuntimeLocations(moduleDir)` 只认两种相对路径：

- `moduleDir/../../agent`（`packages/cli/src` 或 `packages/cli/dist`）
- `moduleDir/../../../packages/agent`

测试 `packages/cli/tests/index.test.ts` 也把「源码与 dist 都解析到 `packages/agent`」写成不变量。安装后的布局一旦离开 monorepo，这条路径就会失效，最后误用系统 `python3`，表现为「命令在、TUI 起不来 / sidecar 缺依赖」。

工作区 `cwd` 已经是用户当前目录，这部分符合「进入某个文件夹输入 harness」。需要改的是 **Python 解释器与 `harness_agent` 包的位置**，不是工作区解析。

### 2.3 还要一起带走的资源

| 资源 | 现在怎么来 | 安装包必须带 |
| --- | --- | --- |
| CLI JS | `packages/cli/dist/index.js`（约 2.9MB） | 是 |
| TUI 语法 WASM / scm | `with { type: "file" }` 打进 dist | 是 |
| Web 资产 | `dist/web.js`、`web.css`、`web-syntax-worker.js`、`web-assets.json` | 是（`/web` 依赖） |
| OpenTUI native | `@opentui/core-<platform>-<arch>@0.4.3` 共 8 个 optional package | 只带当前平台一份 |
| Python 包 | `uv sync` 后的 `.venv`（本机约 126MB，含 test extra） | 生产 extra 即可，仍要 per-platform native wheel |
| 用户配置 | `~/.harness/config.toml` | 安装器可复制示例，不能写入密钥 |

Python native 依赖已在 `uv.lock` 中出现平台 wheel：`tree-sitter`、`tree-sitter-bash`、`pydantic-core`、`sqlite-vec`（macos x86_64/arm64、manylinux aarch64/x86_64、win_amd64）。**tarball 必须按目标平台预装，不能让用户安装时再访问公网 PyPI。**

## 3. 竞品怎么做（对照本地源码与官方安装器）

| 产品 | 用户命令 | 实际产物 | 用户是否需要运行时 | 对 Harness 的含义 |
| --- | --- | --- | --- | --- |
| Grok Build | `curl -fsSL https://x.ai/cli/install.sh \| bash` 然后 `grok` | 单个平台二进制，装到 `~/.grok/bin`，必要时 symlink 到已在 PATH 的 `~/.local/bin` | 否 | UX 模板：探测 os/arch、校验 `--version`、写 PATH、当前 shell 尽量立刻能用 |
| Codex | `scripts/install/install.sh`：下载 standalone 包到 `~/.codex/packages/standalone`，`codex` 放到 `~/.local/bin` | Rust 单二进制 + 版本目录/current 软链 | 否 | 版本并列、原子切换、安装锁，值得抄 |
| Devin CLI | `curl -fsSL https://cli.devin.ai/install.sh \| bash`；Windows `irm ... \| iex`；另有 brew cask | 官方写明 Built in Rust，单二进制 | 否 | 用户点名的 UX；架构不可直接复制 |
| Oh My Pi | `install.sh --binary` 下载 `omp-<os>-<arch>`，或 `--source` 时安装 bun 再 `bun install -g` | bun compile 单二进制；agent 本身就是 TS | 二进制路径否 | bun compile 可行，前提是**没有 Python sidecar** |
| Qwen Code | standalone 优先，npm 兜底 | tarball 内含 **私有 Node.js** + `bin/qwen` shim + `lib/cli.js` | standalone 路径否 | **最接近 Harness 的双运行时分发模型** |
| MiMo Code | `curl -fsSL https://mimo.xiaomi.com/install \| bash` | 按 `os-arch[-baseline][-musl]` 下 zip/tar.gz | 否（预编译） | 平台矩阵命名可参考 |
| Claude Code | 典型是 `npm i -g @anthropic-ai/claude-code` | 单 TS/Bun 运行时，无 Python sidecar | 需要 Node/Bun 或自带 runtime | 全 TS 才能 npm 全局；Harness 做不到只靠 npm |
| dcode | 官方 README 一条 curl；进程内 `/update` `/install` | Python 产品，安装器服务的是同一运行时 | 由安装器解决 | 功能差距调研已把它列为 Harness 高优先级缺口 |

Grok 安装器里值得直接复用的产品细节（源码：`/Users/zhangjingxin/Code/OpenSource/grok-build/crates/codegen/xai-grok-pager/scripts/install.sh`）：

- 只依赖 curl/wget，不安装编译器
- 先探测 `stable` 频道指针，再下 `grok-${version}-${os}-${arch}`
- 下载后立刻跑 `--version`，失败则保留旧版本
- PATH：优先 symlink 到已经在 PATH 且可写的 `~/.local/bin`，再改 `~/.zshrc` / `~/.bashrc` / fish
- 企业部署密钥、managed config、代理是后置能力，第一期可以不做

Qwen standalone 的包布局（`docs/users` 与 `scripts/installation/INSTALLATION_GUIDE.md`）：

```text
qwen-code/
  bin/qwen
  bin/qwen.cmd
  lib/cli.js
  node/          # 私有 Node 运行时
  package.json
  manifest.json
```

Harness 需要在这个模型上再加一层私有 Python。

## 4. 方案比较

### 方案 A. 自包含平台 tarball + `install.sh`（推荐）

安装器只做：探测平台 → 下载校验 → 解压到版本目录 → 写 shim → 放 PATH。

用户机器不需要预装 Bun、uv、系统 Python、Node。企业构建机在发版时把所有依赖烘焙进 tarball。

这是唯一同时满足「像 grok 一样一条命令」和「不重写 Python Agent」的路径。

### 方案 B. `bun compile` 单 CLI 二进制 + 仍带 Python sidecar

OpenTUI 新文档声称 `bun build --compile` 能嵌入 native library 和 Tree-sitter WASM。Oh My Pi / MiMo 走的就是这条路。

但对 **本仓库当前钉死的 Bun 1.2.19 + OpenTUI 0.4.3** 未验证。现行 build 把 OpenTUI 全部 external，就是因为 native FFI。上游还记录过 compile 后 Markdown/Worker 静默丢高亮的问题（OpenTUI #807）。

可以作为第二期减体积手段，**不能作为第一期的门禁**。第一期先带私有 Bun，compile 做成可选构建实验。

### 方案 C. 要求用户已有 Python / Bun，安装器只装源码或 wheel

实现最快，体验最差。与「像输入 grok 或 codex 一样」冲突，也把企业 Python 索引、OpenTUI native 镜像问题丢给每个用户。否决为默认路径。

### 方案 D. PyInstaller / Nuitka 冻结 sidecar，追求两个二进制

`tree-sitter`、`sqlite-vec`、`pydantic-core`、LangChain 动态导入都会让冻结物变脆。工作量接近另做一套发布系统，收益只是少带一个 CPython 目录。否决为 v1。

### 方案 E. 把 Agent 重写成 TS/Rust 再单二进制

长期可以讨论，不属于「安装功能」。超出本调研范围。

## 5. 推荐实施方案

### 5.1 用户可见流程

```text
curl -fsSL https://<artifact-host>/install.sh | bash
  → 探测 darwin-arm64 / linux-x64 / …
  → 读 latest 指针或 --version
  → 下载 harness-<ver>-<os>-<arch>.tar.gz 与 SHA256
  → 解压到 ~/.harness/versions/<ver>
  → 原子切换 ~/.harness/current
  → 写入 ~/.harness/bin/harness（shim）
  → 尽量立刻出现在 PATH（symlink ~/.local/bin/harness）
  → 若没有 ~/.harness/config.toml，复制示例并提示设置 HARNESS_API_KEY

cd any-project
harness          # TUI
harness -n -m …  # 无头，用于安装后冒烟
```

命令名：对外 `harness`；`za38` 可作为同文件别名，不作为宣传名。

配置目录 `~/.harness/` 已经是用户配置根。建议拆成：

```text
~/.harness/
  config.toml              # 已有用户配置，安装器不覆盖已有文件
  bin/harness              # shim，加入 PATH
  current -> versions/0.1.0
  versions/0.1.0/          # 不可变安装前缀
  downloads/               # 安装器缓存
```

不要把安装前缀和用户配置混在同一个不可区分的目录里；`current` / `versions` 与 `config.toml` 并存即可，Grok 也是 `~/.grok/{bin,downloads,config.toml}`。

### 5.2 tarball 内部布局

```text
harness-<ver>-<os>-<arch>/
  manifest.json            # version, platform, bun, python, git sha, sha256 of files
  bun/bun                  # 私有 Bun 1.2.19（第一期）
  cli/
    dist/index.js
    dist/web-assets.json
    dist/web.js
    dist/web.css
    dist/web-syntax-worker.js
    dist/*.wasm / *.scm
    node_modules/          # 仅 OpenTUI/React 及其 native optional，不含整个 monorepo
  python/
    bin/python3            # python-build-standalone / uv python，同平台
    lib/python3.x/site-packages/
      harness_agent/
      …锁定依赖…
  bin/harness              # 包内 shim，安装器复制到 ~/.harness/bin
```

shim 必须 `exec`，不能再包一层会吞 TTY 的 runner（开发工作流已经强调过这一点）：

```sh
#!/bin/sh
ROOT="$(cd "$(dirname "$0")/.." && pwd)"
# 若通过 ~/.harness/bin/harness 调用，ROOT 应为 ~/.harness/current
export HARNESS_INSTALL_ROOT="$ROOT"
export HARNESS_AGENT_PYTHON="$ROOT/python/bin/python3"
unset PYTHONPATH   # 避免用户环境污染；改由 CLI 写入安装前缀
exec "$ROOT/bun/bun" "$ROOT/cli/dist/index.js" "$@"
```

Windows 第二期用 `harness.cmd` 做同等事情。

### 5.3 运行时必须改的最小代码

只改定位，不改协议。

1. **`resolveAgentRuntimeLocations` 增加安装前缀。**  
   优先级：`HARNESS_AGENT_PYTHON` → `HARNESS_INSTALL_ROOT` → 现有源码相对路径。生产安装包**不要**降级到系统 `python3`；开发态可保留，避免 `bun run dev` 退化。

2. **`PYTHONPATH` 指向安装前缀里的 `harness_agent`，不是用户 cwd。**  
   `spawn` 的 `cwd` 继续是用户工作区。

3. **Web / syntax 资源继续走 dist。**  
   `resolveWebBundleLocations` 已同时认 `dist` 与源码；只要 shim 启动的是 `cli/dist/index.js`，Web 资产不用新设计。

4. **安装形态的冒烟测试。**  
   现有测试断言 dist 解析到 `packages/agent`，需要并列一份「安装前缀」夹具：临时目录里放 fake python + `harness_agent`，断言 spawn argv / env，而不是连真实模型。

5. **`harness --version` / `harness doctor`（建议第一期带最小集）。**  
   `--version` 用于安装器下载后自检，对标 Grok。`doctor` 检查：Bun 能起、OpenTUI native 能加载、Python 能 `import harness_agent`、配置文件是否存在、密钥来源是否 `environment|toml|missing`（已有脱敏语义）。

不改：JSON-RPC v3、AgentHost、`~/.harness/config.toml` 的配置架构、模型 Profile。

### 5.4 发版流水线（企业侧，比脚本本身更关键）

安装器能否上线，取决于有没有**按平台烘焙**的产物，而不是 `install.sh` 写得好不好。

构建机对每个目标（建议第一期只做 `darwin-arm64` 与 `linux-x64`）：

1. `bun install --frozen-lockfile`（企业 npm，含对应 `@opentui/core-<platform>-<arch>`）
2. `bun run --filter '@za38/cli' build`
3. 用 `uv python install 3.12 --python-preference only-managed` 得到独立 CPython
4. `uv sync --frozen`（不要 `--extra test`）安装到该解释器；wheel 来自现有企业索引 / `UV_INDEX_URL`
5. 拷贝私有 Bun 官方二进制（固定 1.2.19）
6. 打 tar.gz + SHA256SUMS，上传到企业 artifact host
7. 更新 `latest` 指针文件（纯文本版本号，Grok/Qwen 同款）

`install.sh` 本身也要托管：无版本 URL 永远指向当前脚本；另存 `installation/vX.Y.Z/install.sh` 便于回滚。Qwen 就是这样拆「全局入口」和「版本快照」的。

企业约束（本仓库已经有）：

- Python 依赖走私有索引，安装时不能假设公网 PyPI
- OpenTUI native 必须从企业源烘焙，用户机器没有 Zig
- 安装器、日志、handoff 不得出现 API Key
- 代理：尊重 `https_proxy` / `HTTPS_PROXY`（Devin/Grok 文档都写了）

### 5.5 PATH 与「立刻能用」

`curl | bash` 跑在子 shell，改 rc 文件不会自动影响当前终端。Grok 的处理更完整，建议照抄优先级：

1. 若 `~/.local/bin` 已在 PATH 且可写 → symlink `harness`（当前窗口立刻可用）
2. 否则写 `~/.zshrc` / `~/.bashrc` / fish，并打印「重新打开终端，或 `source …`」
3. `--no-modify-path` 给企业托管镜像和 CI 用

不要默认 `sudo` 写 `/usr/local/bin`。

### 5.6 第一期明确不做

- Windows `install.ps1`（第二期；CLI 已能探测 `Scripts/python.exe`，但 tarball/OpenTUI win32 包要单独烘焙）
- 应用内 `/update`、后台自更新（Codex/Grok 有；第一期用重新跑 `install.sh` 即可）
- Homebrew / npm 全局包作为主路径
- 安装时引导浏览器登录（Harness 现有模型是 TOML + `HARNESS_API_KEY`）
- 把开发用的 pytest extra、benchmark、examples 打进安装包
- 改变 `bun run dev` 源码工作流

## 6. 可行性与风险

| 项 | 判断 | 说明 |
| --- | --- | --- |
| 用户命令 `harness` 进 TUI | 高 | cwd 已经是工作区；缺的是 PATH 与 sidecar 前缀 |
| 用户不预装 Bun/Python | 高 | 前提是构建机烘焙成功 |
| 一条 `curl \| bash` | 高 | 脚本模式成熟；要有 artifact host 和 checksum |
| 体积可接受 | 中 | 本机 agent `.venv` 已 126MB；再加 Bun ~90MB。压缩后估计百兆级，大于 Grok 单二进制，对企业 CLI 可接受 |
| macOS arm64 + Linux x64 第一期 | 高 | 覆盖主要开发机和服务器 |
| 三平台 + musl + Windows 一次齐 | 低 | native wheel 与 OpenTUI optional 矩阵会把发版复杂度抬满 |
| 当前 pin 下 `bun compile` 替换私有 Bun | 低/未证 | OpenTUI 0.4.3 被 external；不要绑在第一期 |
| 冻结 Python sidecar | 低 | native 扩展 + 动态导入 |
| 企业内网可安装 | 取决于宿主 | 代码改动小；没有内部 OSS/CDN 与签名策略就发不出去 |

主要技术风险不在 install.sh，而在：

1. **安装前缀解析写错**，静默落到系统 `python3`
2. **OpenTUI native 没打进对应平台包**，TUI 进程直接起不来
3. **Python native wheel 平台不匹配**（尤其 linux musl vs glibc、macOS x64 Rosetta）
4. **shim 没有 `exec`**，交互 TUI 因非 TTY 被 `validateInteractiveTerminal` 拒绝
5. **构建产物混入 test extra 或开发 `node_modules`**，体积和许可失控

缓解：安装结束强制跑 `harness --version` 和一次 `harness doctor`；CI 用容器/干净 mac runner 做「下载 tarball → PATH → `--help` → 无头 `--non-interactive`」端到端，不连真实模型。

## 7. 建议落地顺序（确认需求后再拆 Task）

若后续立项，建议一个 Task 覆盖「可安装成品」，内部按停点切，不要按 cli/agent 水平分层拆成多个 Task。

1. **定位缝**：`HARNESS_INSTALL_ROOT` / 禁止生产降级系统 Python；测试用夹具目录，不需要真实安装包。可演示：设置环境变量后，从仓库外目录用 `bun packages/cli/src/index.ts --help` 仍能找到 sidecar。
2. **打包脚本**：在仓库 `scripts/` 生成一个平台 tarball（先只做当前开发机 os-arch）。可演示：解压到 `/tmp/harness-prefix`，跑 shim `--version`。
3. **`install.sh`**：本地文件安装（`--archive`）+ PATH。可演示：新用户目录 `curl file://… | bash` 后输入 `harness`。
4. **企业托管与 latest 指针**：这才是对外那条 `https://…/install.sh`。可演示：干净机器一条命令。
5. **第二期**：Windows、`harness update`、评估 `bun compile` 能否丢掉私有 Bun。
