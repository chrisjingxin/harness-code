# 既有界面复用边界

2026-11-06，根据用户要求核对当前 harness_lody 工作树。本次只读源码并修订任务；CodeGraph 命令当前不存在，使用源码/import 与既有测试文件核对，未执行产品测试或搬迁代码。功能基线仍为 HC-190/191，设计稿继续保留。相关决策见[总体设计](../architecture/多人协作工作台顶层设计.md#10-ui-与现有功能)及[并行开发约定](../project/协作任务并行开发约定.md)。

## 1. 结论与实际限制

中央对话、工具、输入及右侧文件/变更具有现成 React/CSS 和行为测试，应该迁出复用。它们多数还接收旧 WebAdapterSnapshot/WebIntent，部分依赖 interactive/state、selectors 或 presentation-coordinator，因此不能直接在新包跨目录 import。需要保留 JSX/视觉/交互，替换状态输入、动作回调和宿主能力；这与重写界面是两种不同的工作。

Lody 截图用于新增协作外壳/导航的信息组织参考；不据截图重建中央对话或右侧面板，也不自动增加定时任务、更新服务、worktree 管理等未确认范围。颜色继续使用既有冷紫浅/深主题及语义变量。

## 3. 复用不携带旧业务依赖

通用组件只接收本区域需要的视图值、能力和动作回调。UI 内部的展开/滚动/页签/草稿与线上 DTO 分开；不把整个旧 InteractiveSnapshot 改名成平台对象，也不把个人视图广播到云端。公共传输契约仍在 workbench-contracts，UI 本区模型留在 workbench-ui。

云端/Runner/ACP 先将真实状态映射到公开契约，桌面再投影成组件输入。工具名称、内容和状态的通用呈现保留；Harness 独有结构由扩展投影/视图注册，不能让通用 Timeline 解析 marker/Thread/Run。缺失能力显示真实不可用状态，不伪造按钮行为。

文件、页签和 Git 选择的状态键包含账号/工作区/执行设备/项目，文件再加相对路径。换会话但同名路径不能串内容；查看者电脑目录和 Git 身份不能替代原执行项目。草稿和 Git 选择等仍属于各用户。

## 4. 验证与迁出顺序

先做 HC-205 公共主题/渲染与端口审查，随后 HC-206 对话、HC-207 文件/变更、HC-208 新导航可并行。无需等 Java、设备或 ACP 全部完成才提取 UI；开发夹具只用于独立预览/冒烟，HC-202 负责逐块真实接线。

沿用 packages/cli/tests/web/presentation 下的 timeline/composer/interaction-form、markdown、code-panel/workbench-views、context-dock/git-panel、theme/styles 等已有行为场景，按目标包迁移最小必要冒烟；Trace 场景由 HC-201 保留。检查浅/深色、头像/用户 SVG、工具展开、滚动、文件关闭/焦点、响应式高度、Git 选择和提交/推送结果，不能只凭截图相似验收。

本轮尚未运行上述场景。迁出后单一实现归新包所有，旧源只保留尚未迁移部分；HC-203 在消费者替换并有集成证据后退役旧入口和残留。设计稿不删除，HC-204 统一做整体和双平台测试。
