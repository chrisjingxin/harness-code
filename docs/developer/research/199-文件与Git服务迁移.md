## 旧 Web 和 CLI 的实际链路

旧入口在同一个 CLI 进程中按启动目录创建 `WorkspaceExplorer` 和 `WorkspaceGit`。文件请求由 `WebUiGateway.handleWorkspaceIntent` 转交 Explorer，Explorer 发布文件树和预览状态。Git 走 `interactive.intent`，由网关检查当前接管连接、写操作 revision 和 requestId，再交 `InteractiveController` 与 `WorkspaceGitFeature.execute`。Web Adapter 负责页签、候选菜单、选择和草稿。迁移时保留宿主策略与业务复核，把旧启动目录、接管和单窗口状态替换为项目绑定、服务端授权、设备回执和桌面个人状态。见 [CLI 装配](../../../packages/cli/src/index.ts)、[Web 网关](../../../packages/cli/src/presentation-coordinator/web-ui-gateway.ts)、[Controller](../../../packages/cli/src/interactive/controller.ts)、[Web Adapter](../../../packages/cli/src/web/application/adapter.ts)。

## 一次真实操作的建议流程

小王在自己的电脑打开小李共享的会话。会话绑定小李电脑上的「账单服务」。小王要检查一处税率修复，同时保留小李已经暂存的日志修改。

1. **定位项目。** 桌面显示原设备和项目名。Java 从已授权会话取得固定 device/project 并核对当前共享版本，只向该设备的已就绪连接发即时请求。Runner 用本机登记解析真实根，检查目录是否被替换。由受控端口接收相对路径，拒绝穿越、平台绝对路径和经链接越界。建议首版在探测到 Git 工作树根位于登记目录之上时，文件读取继续可用，Git 给出明确原因并引导所有者登记仓库根。否则旧 Git 的全仓状态和推送会超出共享目录。目录别名共用同一实际根，链接校验由原设备负责。
2. **读取并比较。** 展开文件树、预览和请求候选使用同一个原项目范围。读取返回实际条目/正文及预算内的显示信息。重新打开已缓存页签时可以显示缓存标识，手动刷新和成功重读后才更新为实时。Git 状态返回审阅快照和逐文件版本。逐文件版本用于保留仍有效的勾选，建议包含影响该文件所见比较的基线、路径身份及内容信息。聚合快照另外绑定项目范围、HEAD/索引、变更集和 upstream。Diff 仅在同快照下展示，清楚标出截断。文件、索引或分支变化导致旧快照失效时刷新，勾选只保留版本仍匹配的项。[HC-190 Git 规格](../spec/HC-190-Web主题布局与Git提交.md) · [HC-207 视图规格](../spec/HC-207-文件与变更视图复用.md)
3. **勾选并提交。** 小王勾选税率文件并填写说明，初始零勾选。发出写意图时带审阅快照和选中路径，Java 记录平台操作人，Runner 即时校验共享与占用，项目服务再次验证快照和允许路径。税率文件若已部分暂存，仍按当前**整文件**提交。新增/删除按实际状态处理，重命名作为 old/new 一组。独立索引从 HEAD 起只加入所选路径，提交确认后只把原索引的选中项同步到新 HEAD，小李未选文件的工作区内容与原暂存内容都应保留。冲突、子模块、进行中的合并/变基/拣选、detached HEAD 或没有可提交变化，返回可处理原因。
4. **确认写入事实。** 在小李设备上保留本地 Git 配置、author/committer、签名、hooks 和凭据。平台记录小王发起操作，Git 身份仍由原机器及仓库配置决定。保留 commit hooks，并复核提交前的审阅树，hook 改动了暂存内容则需刷新。Hook 自己改过的工作区文件按真实状态显示。核验实际父提交和树后回报 SHA。即使索引同步失败，只要提交已确认，仍展示 SHA 和警告。身份缺失、签名失败或 hook 拒绝若能确认提交未发生，返回明确失败。旧 adapter 的诊断与超时需要收敛成有界结构化结果，不能只根据命令退出或网络状态判断是否写入。[Git 实现](../../../packages/cli/src/infrastructure/workspace-git.ts) · [HC-190 用例](../../../packages/cli/tests/infrastructure/workspace-git.test.ts)
5. **可选推送。** 界面预先显示 upstream 及已积累的未推送提交数。沿用无 upstream 时禁用「提交并推送」的行为，仍可单独提交。推送会送出固定 SHA 所包含且远端尚缺的提交。提交成功与推送状态分别回报，远端拒绝仍保留 SHA。推送开始前复核权限、当前分支、upstream 与已确认的 SHA。如果提交后共享被撤回或目标变化，保留 SHA 并明确推送未执行。确切失败可只重试推送。保留原机器的认证和 pre-push hook，使用既有目标、显式 refspec、非 force 和有界等待。禁止自动 pull/rebase、修改 remote 或有意创建远端分支。远端分支在探测后被删除的竞态，需要在 Spec 明确支持的保证与原生 Git 限制。[旧推送策略与验证边界](../task/HC-190-Web主题布局与Git提交.md) · [Git push 文档](https://git-scm.com/docs/git-push)

**离线、旧数据和待确认。** 未派发时因设备离线、权限撤回或占用而拒绝，当前页面可保留个人草稿。仍授权时若展示此前成功读取的内存数据，要标出缓存并禁用依赖实时快照的写入；账号切换和撤权后隔离或清除该范围的数据。收到命令或写入 socket 只说明已传输或受理。如果请求已可能进入 Git，超时、断线或进程崩溃显示「提交结果待确认」或「推送结果待确认」，沿原请求查账和读回实际结果，不换 ID 或换设备重放。若 HEAD/远端 ref 已变化且无法归属，保留待确认状态。收到可验证的 SHA 时及时记录，即使随后推送、刷新或结果传输失败。建议只为写操作和回执保留必要元数据，文件正文和 Diff 不进入共享历史。已有执行账本说明了如何保存调用边界和补传，但项目操作需要自己的状态语义。[顶层设计第 6 节](../architecture/多人协作工作台顶层设计.md) · [HC-196 Spec](../spec/HC-196-设备接入与本机执行.md)

## 最小非 ACP 实施次序

1. **先定接口。** Task 确认后出同名 Spec，由 HC-196/207/202 共同审查项目范围、授权、审阅快照、读写结果和故障边界，再写 Plan/Todo。此时不依赖设备链路或 UI 全部就绪。
2. **先完成原设备可独立验证的策略。** 提取目录、候选、只读预览、状态和 Diff，再迁独立索引提交和既有 upstream 推送，提供有界类型化结果。后续用临时仓库/bare remote 复用 HC-190 证据场景，重点对照实际 SHA、未选文件和原索引、过期快照、hook/签名失败及只重试推送。旧签名配置会被保留，迁出后仍需验证执行环境与跨平台行为。[文件边界用例](../../../packages/cli/tests/workspace/path-policy.test.ts) · [预览用例](../../../packages/cli/tests/workspace/file-preview.test.ts) · [Git 用例](../../../packages/cli/tests/infrastructure/workspace-git.test.ts) · [旧写入状态用例](../../../packages/cli/tests/interactive/workspace-git.test.ts)
3. **接在线设备，再装配桌面。** HC-196 提供最小授权、派发与结果核对后，先验证同名目录在两台设备时总是读取原设备，离线时新写请求被拒绝。HC-202 绑定 HC-207 和候选视图，走一次「读取 → Diff → 勾选 → 提交 → 可选推送」的真实路径。ACP Agent 与 Git 占用生命周期接合、协议接线及真实在途写入调试，等同事交付代码后再安排。完整组合留 HC-204。

## 需要产品拍板的三项

1. **子目录与仓库根。** 建议共享子目录时保留原范围的只读浏览，Git 要求所有者登记仓库根。若允许从子目录操作全仓，需先明确授权范围和界面告知。
2. **共享权限。** 讨论项目共享是否同时授予当前有权访问的成员预览、提交及向 upstream 推送。建议在设备所有者共享时讲明读写范围，并按操作给出授权状态与拒绝原因，继续沿用工作区成员模型。接手人字段用于协作交接，是否影响 Git 写权限应由产品明确。
3. **离线缓存体验。** 建议只在仍可访问的同一身份和项目范围内显示会话期间已有的内存预览，标明缓存时间及离线状态。讨论重开桌面后是否需要保留文件内容，及允许的生命周期。离线写入和未知结果重放保持即时拒绝及核对语义。
