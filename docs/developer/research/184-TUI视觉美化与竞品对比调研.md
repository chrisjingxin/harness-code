# 184 TUI 视觉美化与竞品对比调研

本调研针对当前 Harness Code 全屏 TUI 界面存在的视觉粗糙、质感扁平与排版简陋等痛点，深入研读并对比了本地三大顶级/主流开源 Coding Agent 的一手源码：
- **Qwen Code** (`/Users/zhangjingxin/Code/OpenSource/qwen-code`)
- **Kimi Code** (`/Users/zhangjingxin/Code/OpenSource/kimi-code`)
- **Oh My Pi** (`/Users/zhangjingxin/Code/OpenSource/oh-my-pi`)

通过架构机制、视觉设计系统、信息层级、交互微动效等多个维度，系统分析当前 Harness Code 与顶级工业级实现的真实差距，并提出针对性美化重构方案。

## 二、当前 Harness Code TUI 为什么“丑”？（痛点深度剖析）

### 1. 输入框（InputBar）“视觉侵略性过强、沉重死板”
- **当前做法**：无论终端是否有焦点或处于何种状态，底部都顶着一个全封闭的大矩形线框，并且使用了高饱和度的纯金黄色（`#EAB308`）或纯亮紫色（`#A9A5D4`）。
- **感官问题**：即使在阅读长会话时，底部亮黄色的厚重方块都在死死吸引用户的注意力，造成强烈的视觉压迫与失焦。
- **竞品解法**：
  - **Qwen Code**：采用开放式线框（Open-Top Framing），只有顶部一条极细的分割线（右侧带当前状态药丸）和底部单线，两侧完全开放，整体通透轻盈；
  - **Oh My Pi**：将状态信息（模型、Git、Context 占用）**直接嵌入在输入框的顶边线中**（`╭─ π sonnet 3.7 ┆ main* ┆ 42% ── $0.12 ─╮`），不仅省掉了 1-2 行垂直空间，还让输入框与状态栏一体化，极具现代仪表盘质感；
  - **Kimi Code**：平时使用低调克制的暗灰边框（`#5A5A5A`），只有在弹窗审批或特定模式下才亮起重点色。

### 2. 空白欢迎页（Welcome Screen）“毫无质感、如同开发期调试输出”
- **当前做法**：Logo 下方就是 6 行毫无装饰的平铺文字：
  ```text
  Harness Code 0.1.0
  工作区: /path · 模型: gpt-4o · 模式: BUILD
    · 直接输入问题或任务开始
    · 输入 / 唤起本地命令菜单
    · 输入 @ 引用工作区文件或代码片段
  ```
- **感官问题**：没有任何容器包装、缺少对齐基准、快捷键没有键帽（Keycap）样式、缺少当前项目上下文（如 Git 分支、索引健康度、最近会话）。
- **竞品解法**：
  - **Qwen Code**：采用双栏卡片结构，左侧渐变 ASCII 艺术字，右侧带圆角框的信息卡片，下方配备随机小贴士（Tips）；
  - **Oh My Pi**：大圆角卡片居中呈现，左侧展示多彩渐变 Logo，右侧展示常用动作键帽、LSP/工具状态和最近活跃会话（带相对时间 `2h ago`），甚至在 Tip 上带有炫彩的 `[NEW]` 徽章；
  - **Kimi Code**：全圆角边框包裹，顶部块状 Logo，内嵌字段分列排版（`Directory: ...` / `Session: ...` / `MCP: 3 active`）。

### 3. 对话与时间线（Timeline）“缺少视觉呼吸感与卡片层次”
- **当前做法**：
  - 用户消息：`▎ ❯ 问题内容`（简单的单竖条）；
  - 助手消息：直接输出 Markdown 纯文本；
  - 消息之间没有明确的留白节奏或背景区分，整屏文字贴在一起。
- **感官问题**：在长篇对话中，分不清哪一段是人类提问、哪一段是助手分析、哪一段是工具执行，阅读极其疲劳。
- **竞品解法**：
  - **Kimi Code 的 `CHROME_GUTTER` 哲学**：所有历史消息强制向右平移 1 格（Gutter=1），使历史消息正文在水平方向上与输入框内 `>` 之后的输入文本**严格垂直对齐**，视觉规整感极强；用户提问使用专属的 `✨ ` 暖黄色前缀，助手使用实心圆点 `● ` 配合 2 格悬挂缩进；
  - **Oh My Pi 的微背景卡片（Tinted Cards）**：用户消息拥有非常低饱和度的微底色卡片（`userMessageBg: #221d1a`），工具执行卡片根据状态分别带有微蓝（Pending）、微深青（Success）、微暗红（Error）的半透明底色，层次分明，无需强烈的线框即可拉开空间。

### 4. 思考推理（Thinking）“单调生硬、缺乏动效与节奏”
- **当前做法**：流式阶段输出 `◐ 正在思考`，下方接 `│ 思考正文...`，虽然已接入流式，但文字格式单调。
- **感官问题**：长时间思考时用户只能干看着单调的转子，且大段思考文字直接占满屏幕，冲淡了主对话内容。
- **竞品解法**：
  - **Qwen Code**：流式阶段使用因为符号 `∵\uFE0E Thinking… [耗时]`，完成后自动变为因此符号 `∴\uFE0E Thought for 8s (ctrl+o to expand)`，默认收拢为单行，支持点击或快捷键展开；
  - **Kimi Code**：实时思考流采用**滑动尾窗（Sliding Window）**，始终只显示最后 2 行预览（使用 `italic textDim`），推理完毕自动收起，完全不抢占视口；
  - **Oh My Pi**：引入**升余弦呼吸星芒动效（Raised-Cosine Breathing）**（`✻ ✼ ❉ ❊ ✺ ✹ ✸ ✶`，帧间隔在 70ms~230ms 间模拟人类呼吸平滑加减速），同时在徽章上实时显示生成速度与 Token 吞吐量（`✻ Thinking (112 tok/s · 1,420 tokens)`），极具高科技与灵动感。

### 5. 工具调用（Tool Calls）“信息密度不足、缺少状态芯片（Chips）”
- **当前做法**：仅简单折叠为 `✓ 读取 3 个文件`，执行详情与 Diff 缺乏高质感包裹。
- **感官问题**：看起来像是简单的 console.log 输出，没有专业开发工具的“仪表盘”感。
- **竞品解法**：
  - **Kimi Code**：工具执行成功后，尾部统一挂接**数值型状态 Chip**：
    - 编辑：`+12 -4`（绿红增删标签）；
    - 写入：`45 lines`；
    - 搜索：`3 matches across 2 files`；
    - 网络：`4.2 KB`；
    - 执行超过 10 秒的工具自动浮出 `Press Ctrl+B to run in background` 提示；
  - **Oh My Pi**：专属工具字标（`✎` 编辑、`❯` 命令行、`💡` LSP、`🌐` 浏览器、`🧠` 记忆），并且在连续读取多文件时渲染为优雅的树状列表：
    ```text
    📖 Read 4 files:
      ├─ src/tui.ts (L1-80)
      ├─ src/editor.ts (L120-195)
      └─ src/terminal.ts (L45-90)
    ```
  - **Qwen Code**：使用 `DiffRenderer` 提供字符级行号侧栏（`selectable={false}` 确保复制时不误拷行号），折叠工具末尾带钩形分支符 `⎿ found 14 matches`。

### 6. 色彩体系“单薄、缺乏现代感”
- **当前做法**：`theme.ts` 仅有 12 个固定 Hex 字符串，大量依赖终端默认的 `dimColor` 或高饱和度的原始黄/紫。
- **感官问题**：在浅色终端、透明终端或特定主题终端下极易出现文字发灰不可读、黄色刺眼或对比度崩塌。
- **竞品解法**：
  - 全部采用**两级语义 Token 系统**（`text.primary`, `text.secondary`, `text.dim`, `text.muted`, `border.default`, `border.focused`）；
  - 强制禁止裸写 chalk 颜色；
  - 拥有精心调校的 Dark / Light 配色方案，严格满足 WCAG AA 对比度；
  - 引入微弱的渐变色（Gradient）提升品牌字与关键标题的高级感。

## 三、对标竞品：Harness Code TUI 美化升级路线图

结合上述三大竞品的顶尖设计，为 Harness Code 制定一套**不牺牲极速性能与全屏视口稳定性、立竿见影提升颜值**的美化落地方案：

### 1. 输入区“减负”与“一体化顶边状态栏”
- **改造边框语言**：
  - 淘汰刺眼的实心亮黄框；
  - 平时采用深灰柔和边框（`#3D424A`），光标聚焦时柔和高亮；
  - 借鉴 **Oh My Pi** 与 **Qwen Code**：将当前会话的上下文信息（工作模式徽章 `[BUILD]`、模型 `claude-3-7-sonnet`、Git 分支 `(main* +2)`、Context 进度 `18%`）**直接内嵌在输入框的顶边线中**！
  ```text
  ╭─ ⬢ BUILD · claude-3-7-sonnet ┆ ~/harness-code (main*) ──────── context: 18% ─╮
  │ ❯ 输入编码任务或问题…                                                       │
  ╰─ Enter 发送 · Shift+Enter 换行 · / 命令 · @ 引用文件 ───────────────────────╯
  ```
- **模式联动**：当输入 `!` 切换到 Shell 模式时，边框与提示符即时变为优雅淡紫色，并展示 `╭ ! bash ───╮`。

### 2. 欢迎首屏（Welcome Screen）卡片化重构
- 借鉴 **Qwen Code** 与 **Oh My Pi** 的双栏/居中卡片布局：
  - **外壳**：由优雅的圆角框包裹，宽度限制在 72~88 列；
  - **左侧/顶部**：保留方块字符 ASCII Logo，注入冷蓝至青绿的双色平滑渐变；
  - **右侧/中部**：分栏展示运行环境与键帽指引：
    ```text
    ╭─────────────────────────────── Welcome to Harness Code ────────────────────────────────╮
    │                                                                                        │
    │   █  █ █▀▀█ █▀▀▄ █▄ █ █▀▀▀  v0.1.0        Directory: ~/Code/MyRepo/harness-code        │
    │   █▀▀█ █▀▀█ █▀▀▄ █ ▀█ █▀▀                 Git:       feat_hc_183_全屏TUI (clean)       │
    │   ▀  ▀ ▀  ▀ ▀  ▀ ▀  ▀ ▀▀▀▀                Model:     claude-3-7-sonnet · [BUILD]       │
    │                                                                                        │
    │   快捷操作:                                                                            │
    │    [ / ] 唤起本地 Slash 命令               [ Shift+Tab ] 切换审批执行模式               │
    │    [ @ ] 模糊引用文件与代码符号            [ Ctrl+O ]    展开/折叠思考与工具详情        │
    │                                                                                        │
    │   💡 小贴士: 输入 ! 可以直接在终端执行本地 Shell 命令，无需切换终端                     │
    ╰────────────────────────────────────────────────────────────────────────────────────────╯
    ```

### 3. 全局基准线与消息节奏美化
- **对齐标尺**：引入 `CHROME_GUTTER = 1`，将时间线内所有消息正文与输入框内 `❯ ` 之后的文字在垂直方向完全平齐对齐，消除视觉凹凸不平感；
- **用户提问标识**：使用优雅的金色星星 `✨ `（或品牌 Accent `❯ `）作为引导符号，提问文字加粗微强调；
- **助手回复标识**：使用高质感实心小圆点 `●\uFE0E `（追加 `\uFE0E` 确保在任何中文字体下均为精确 1 列宽，绝不发生错位），正文统一缩进 2 列悬挂排版。

### 4. 思考推理（Thinking）体验升级
- **流式阶段**：
  - 采用呼吸感的平滑星芒动效（`✻ ✼ ❉ ❊ ✺ ✹ ✸ ✶`）；
  - 实时显示耗时与速度；
  - 引入滑动尾窗机制，在紧凑视口下仅滚动显示最后 2 行浅灰斜体预览，绝不让冗长思考推挤屏幕；
- **完成阶段**：
  - 自动折叠为单行精简徽章：`∴ 思考完成 (耗时 4.2s · 共 18 行，按 Ctrl+O 展开)`；
  - 支持 `Ctrl+O` 一键无缝平滑展开。

### 5. 工具调用（Tools）卡片化与指标芯片（Chips）
- **工具状态头部**：
  - 统一为固定 2 字符状态指示：`✓ ` (绿)、`✗ ` (红)、`⠋ ` (动态微旋转)、`⊘ ` (黄)；
  - 为不同工具配备个性化语义图标（`✎` 文件编辑、`❯` 终端命令、`🔍` 代码搜索、`📖` 文件读取）；
- **数字指标芯片（Metrics Chip）**：
  - 编辑文件后显示 `[+24 -8]`（绿色增加、红色删除）；
  - 读取文件后显示 `[120 行]`；
  - 搜索文件后显示 `[找到 5 处匹配]`；
- **只读工具树形化**：
  - 连续的多个 `read_file` 聚合展示为结构树，不再刷出多行工具块。

### 6. 语义色彩 Tokens 扩展与 CJK 宽字符防护
- 将 `theme.ts` 扩展为分级语义系统：
  - `text.primary` (明亮正文)
  - `text.secondary` (柔和中灰)
  - `text.dim` (思考流与次级说明)
  - `text.muted` (极淡快捷键与边框引导)
  - `accent.brand` / `accent.modeBuild` / `accent.modeCompose`
  - `border.default` (`#3D424A`) / `border.focused` / `border.active`
- **引入 `\uFE0E` 字符级护栏**：
  - 对所有常用 Unicode 符号（`◆`, `●`, `★`, `✓`, `✗`, `◐`）追加零宽变体选择符 `\uFE0E`，强力锁定在终端单列宽度，彻底终结中文终端下的排版跳变与折行对不齐。

## 四、调研结论与执行建议

三大竞品之所以给人“现代、专业、高级”的第一印象，并不是靠花哨的动画，而是依靠**克制的设计语言**、**严苛的像素级度量对齐**、**信息降噪（有条理的折叠与摘要）**以及**富有现代感的极简边框排版**。

Harness Code 已经在底层完成了非常扎实的全屏终端生命周期、视口缓存、ANSI 词法高亮以及鼠标事件防污染机制（性能基准已达到 2.27ms 极速水准）。底层骨架已经非常健壮，现在的“丑”完全属于**表现层（Presentation Layer）的排版密度与视觉设计调优范畴**。

后续可直接基于本调研成果，按步骤对 `fullscreen-shell.tsx`、`theme.ts`、`fullscreen-projection.ts` 及 `app.tsx` 进行精准的外科手术式视觉美化，无需重构核心交互逻辑。
