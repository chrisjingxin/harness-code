## 3. 两条适配路线

### 路线 A：知识写成本地文件，提供文件位置

借鉴 Pi：把知识保存为本地文件，索引列出位置，让 Agent 使用自己的文件读取能力。

优点是对具备文件工具的 Agent 直观；如果正文原本已在本地，不需要再提供专门的读取工具。

本项目正文默认在 Java 中继，若提前把全部正文落盘，会违背按需下载目标；如果仅保存目录文件，Agent 仍需要一个下载入口。文件位置还涉及不同 Agent 对目录外文件的访问方式，不能把写入用户仓库或改造项目 AGENTS 当成默认方案。

### 路线 B：自动目录 + 桌面只读 MCP，建议首选

借鉴 OpenCode 的目录与正文工具分离，再参考 Qwen 的稳定目录和更新方式：桌面提供轻量目录，并通过标准 MCP 暴露查询和读取能力，实际读取沿用协作客户端。

```text
用户发送当前消息
  → 桌面取得当前 Workspace 有权限的知识目录缓存
  → 给本轮 Agent 输入附带知识标题目录，以现有 ID、版本准确定位读取
  → Agent 判断是否相关，调用只读知识工具
  → 桌面以当前登录身份读取 Java 中继中的固定版本
  → 工具返回正文、来源和版本，现有工具界面展示读取过程
```

知识服务只放在桌面宿主，不把 Java 凭据写进模型输入，不把业务逻辑耦合到 Harness 内核。标准 ACP 的会话 MCP 接线是前置工作，具体传输与生命周期沿用通用宿主方案，不在本调研另造协议。其他 Agent 能否消费同一服务，需按其实际能力验证，不能把 Harness 跑通等同于所有 Agent 跑通。

建议先限定两类只读行为：查询知识目录（含分页或搜索），读取指定 ID 和版本正文。这里描述的是行为，不是新增服务端 API 或最终工具契约。

## 4. 团队知识部分的参考结论

1. **标题目录默认可见，正文相关时读**：普通对话不再要求用户先 `@`；只将标题作为业务内容注入，ID、版本用于工具定位。看到标题不代表已读正文，Agent 需要实际读取才能引用具体规范。
2. **直接复用当前知识列表**：用户确认首版暂不增加摘要字段或分类说明，不改知识编辑页，不要求历史知识补录，不扫描全库正文或调用模型补摘要。后续根据实际发现效果决定是否扩展。
3. **先简单接通**：每次发送附带一段有长度上限的目录，数据来自元数据缓存；目录稳定排序，同内容不反复请求 Java。以后若能可靠跟踪 Agent 会话恢复和压缩，再评估首次注入加变化提醒，避免为了复用第三方内部缓存机制扩大首版范围。
4. **溢出可继续发现**：目录超过预算时说明总量、截取情况和可用查询工具，不能静默隐藏未展示项。具体预算与分页行为在 Spec 中确认。
5. **固定版本可追溯**：按本轮已告知的版本读取；更新在后续发送时可见，已发送内容不变。手动引用保留锁定版本，自动加载不覆盖或重复附带它。
6. **沿用权限与知识归档语义**：每次读取仍由现有服务确认可读性；自动发现排除归档知识，旧版手动引用能否读取以服务实际授权结果为准。切换账号或团队后不得复用另一范围的目录与读取授权。
7. **保持现有 UI**：知识创建、编辑和列表保持现状；现有工具卡显示读取过程和来源，无需重画中间消息区、右侧文件或 Project 导航。
8. **暂不引入另一套系统**：不做 Project 看板注入、任务自动执行、向量召回、后台摘要模型或 Skill 安装市场。

## 5. 团队知识部分的接点

- 桌面：整理知识目录、上下文附带、只读知识工具、现有引用去重及来源展示。统一设计中的记忆工具与知识工具共用本机 MCP 服务。
- 服务端：首版复用当前列表与固定版本读取接口，不增加摘要字段，不修改 API、数据库或服务端设计文档；不再将服务端摘要能力列为前置依赖。
- 通用 ACP 维护方：HC-234 已交付会话 MCP 配置能力，桌面按现有标准入口装配知识与记忆工具服务。完整业务交付仍需实际调用和固定版本读取的冒烟证据。
- 产品范围已确认：只注入当前标题目录，正文按需读取，先跑通最小版本。标题笼统可能导致 Agent 漏读，这是首版发现精度的限制；继续保留手动 `@`，需要时再讨论扩展摘要等能力。
