# Web 工作台

Web 工作台通过 `/web` 在浏览器中接管当前 Thread。它与 TUI 共用同一条 Timeline、Run、审批和 Composer 语义；本页说明 Web 端的视觉层级和外围操作。

## 主题与状态

- 页面使用白色画布、近白侧栏与冷紫色强调；深色使用中性暗底与提亮的紫色交互色，两种主题均由独立的语义变量控制；切换入口是顶栏“返回 TUI”旁的单图标按钮（浅色显示月亮、深色显示太阳，图标表达点击后切换到的主题）。
- 冷紫色用于主要操作、当前选中、运行中、焦点和链接等交互强调；成功、等待、失败和取消保留独立语义色、文字与图标，Diff 仍使用红绿增删。运行中额外叠加动画或文字（如“正在运行 · 点停止取消”），不只靠颜色区分。Esc 只关浮层，不取消任务。
- 顶栏的 Run 状态是最高状态层级，会显示“正在运行”“等待交互”“运行失败”等可读文案和状态点。状态来源于当前 Run，不由 CSS 推测。
- 顶栏的返回 TUI、主题切换和更多操作属于次级 chrome；更多菜单只保留帮助与退出入口。模型与审批模式不放在顶栏，而是作为 Composer 底部操作条上的下拉控件，贴近输入动作。

## 工作区外围

- 桌面端顶栏左侧显示 Harness Code 品牌，中间用文件夹图标与项目名标识当前位置，右侧是“返回 TUI”、主题切换和更多操作。工作区位于 Git 仓库根目录时只显示项目名（如 `harness-code`）；位于子目录时显示项目名与相对路径（如 `harness-code / packages/cli`）。非 Git 目录或 Git 信息不可用时显示工作区目录名。长名称省略显示，悬停可见完整工作区路径；不再附加“/ 工作台”，Git 分支仍在右侧变更区域查看。
- 三栏工作区中，左栏贴紧窗口左缘、右侧 Dock 贴紧窗口右缘，两栏从顶栏下缘一直延伸到窗口底部；栏间保持 `16px` 列间距，中间对话列上下保留呼吸内边距。左栏默认约 `280px`（可拖动 `220–480px`），右侧 Dock 默认约 `340px`（可拖动 `330–760px`）。中间内容列（工作项横幅、消息流、审批卡、输入框）固定居中：宽度封顶 `880px`，按 Dock 预留宽度计算——Dock 打开时用其实际宽度，Dock 关闭时用默认宽度（`340px`），因此把 Dock 拖宽后关闭，内容列会恢复默认宽度，重新打开仍保持拖宽后的宽度。开关或拖拽时内容列随轨宽整体平移过渡（约 200ms，系统开启“减弱动态效果”时瞬时切换）。拖动侧栏或 Dock 分隔条时按当前窗口宽度动态限制最大宽度，保证内容列不低于 `480px`。
- Composer 底部操作条承载两个下拉控件：左端是审批模式下拉（显示当前模式，点击就地切换；待处理交互或压缩中锁定，运行中仍可改下一轮档位），旁边是工作模式 chip；右端是模型下拉（发送键旁，显示当前模型，点击就地切换，菜单底部“管理模型…”打开居中设置窗口的模型分类）。两个下拉都向上弹出，形态与行为一致。
- 左侧 Sidebar 承载“新建对话”、搜索和按日期分组的会话列表，列表独占可用高度。新建为轻量文字图标动作，搜索使用浅灰底；会话图标与标题首行对齐，选中只显示纯色填充。底部只保留“设置与工具”，直接打开居中设置窗口。连接异常通过页面提示展示，详细环境信息可在设置的“运行状态”中查看。顶栏右侧的面板图标可收起或重新打开右栏。
- Thread 项的主标签是短标题（`/title` 或第一条消息后的自动起名）；还没有标题时显示截断后的第一条原文。搜索同时匹配标题和消息摘要。自动起名或 `/title` 写入后列表会更新，不必手动点「重试」。
- 当前 Thread 使用独立的紫色填充标识，深色模式加强选中背景的亮度差；未选中的 Thread 仅在 hover 时显示轻量背景。
- 对话时间线是扁平阅读流：每条消息由角色行（小头像 + 名称 + 时间）和左对齐正文组成，用户消息保留中性底色，Agent 正文保持扁平阅读；思考和审批条目用 1px 边框表达结构，不带投影。时间线不显示常驻滚动条；新消息到达时，视口贴底则自动跟随滚动到底，手动上滚阅读历史时保持位置不打扰——此时浮出中性「回到底部」按钮，若上滚期间有新内容到达，按钮升级为强调的「有新输出」，点击恢复跟随。
- 工具调用默认折叠为融入阅读流的单行：语义图标 + 动词标签（如“读取文件”“执行命令”）+ 主参数 + 状态 + 常驻展开箭头；点击后在引导竖线内展开两张同级卡片——“输出”卡片带头部条（标题、行数统计、一键复制按钮），超过约一屏时钳制限高并可点“展开全部”就地放开；“参数”卡片默认折叠成一行头，点开看美化后的 JSON。输出内容按工具类型结构化渲染：“读取文件”显示路径元信息与行号栏，“列出目录/搜索文件”显示带文件类型图标的条目清单，“查找内容”按文件分组显示行号与命中行；“编辑文件/写入文件”把实际变更渲染为红绿 diff 行（新增淡绿底、删除淡红底，头部显示 +N −M 统计）；“执行命令”渲染为终端块（顶部 $ 命令行 + 输出，头部显示 exit code，截断时有提示）；其余工具结果是 JSON 时自动美化缩进，否则按等宽纯文本展示。写类工具（写入/编辑/删除/执行命令）用暖色图标提示副作用，失败行用淡红底、左侧红条与“失败”文字徽章突出；原始工具名挂在标签的悬浮提示上。
- Context Dock 默认打开右侧文件区，主标签为“文件／变更”。文件树与文件预览上下排列：打开文件后显示原有文件标签、内容、刷新与错误提示；关闭最后一个文件后文件树占满面板。目录展开、文件选择与预览继续共用原有状态。“变更”页读取真实 Git 状态，支持勾选文件、查看 Diff、提交和提交后推送。
- 文件树与预览按右栏可用高度约 2:3 分配，分别滚动；长路径省略显示，悬停可看完整路径。窗口变矮时，Git 提交区可独立滚动，避免提交说明或提示挤掉上方变更列表。
- 设置窗口左侧为模型、技能、MCP、Agent、运行状态、帮助分类，按当前能力显示，右侧内容独立滚动。分类支持方向键及 Home/End，Tab 在窗口内循环；关闭按钮、Escape 或点击遮罩关闭，焦点返回入口，下次打开记住分类。设置开关保留右侧文件预览、滚动位置、Git 勾选/提交说明和会话草稿。模型仍可从输入框底部快速选择或进入管理，帮助仍可从顶栏更多菜单打开同一设置窗口。
- Sidebar、Dock、Thread、Files、Model、Skills、MCP 和 Status 的现有操作保持不变。打开/关闭面板不会改变 Thread 或 Agent 状态。

## 控件与可访问性

Web 控件使用统一的 compact、standard、field 尺寸和中性边界，圆角与阴影有固定纪律（阴影只出现在浮层、菜单和对话框）。必要的小号文字使用较深的 muted token，键盘聚焦显示 2px 紫色 focus ring（Composer 输入框以整卡紫色描边表达聚焦）；运行、等待、失败和取消不只依赖颜色区分。

Composer 的发送、取消、IME、Slash Command 和审批/问答行为见[交互使用](交互使用.md#web-工作台)。

## 文件变更审批

- `write_file`、`edit_file`、`delete_file` 的人工审批使用专用 Diff 卡，显示逻辑路径、操作和增删统计；
  Web/TUI 使用 Codex 风格的低饱和酒红/墨绿色整行背景、行号色带，并保留 `-`/`+` 标记。
- 可用宽度达到 760px 时默认左右对比，较窄时默认行内；当前审批内可用“左右 / 行内”手动切换。
- 删除和新增同时使用背景色与 `-`/`+` 标记，old/new 行号始终可见；长行不会静默省略。
- 支持的语言复用离线 Shiki Worker。未知语言、超限、超时或 Worker 故障只关闭语法高亮，不影响审批。
- Diff 仍受 200 行、16 KiB 预览上限约束；截断提示位于审批按钮之前，批准对应完整拟议变更。
- 工具参数默认折叠在“请求参数”中；非文件审批继续使用通用 description 和参数预览。
- 普通“拒绝”点击后立即提交，批准仍需选择后点击“提交”确认；“拒绝并反馈”需填写反馈后提交。
- 审批、问答与目录信任卡与对话内容共用同一居中内容列（宽度规则见“工作区外围”，封顶 `880px`）。Diff 预览区高度上限约 240px，超出内部滚动。
- 长审批卡整体仍限制在工作区剩余高度内并自身滚动；滚动 Diff 或审批卡不会把底部的审批按钮和 Composer 推出视口。

顶栏沿用系列设计稿的紫色 Command 图标与工作区路径。会话区上方显示当前会话标题、工作模式与运行状态；消息头像、工具卡和输入框继续沿用原有交互。右侧文件/变更标签使用线形图标，文件预览保留多文件切换、刷新及错误提示。

## Git 变更与提交

打开右侧“变更”，先检查当前分支和文件列表。默认不勾选文件；可逐项勾选或使用“全选”。点击文件名查看相对 HEAD 的 Diff，填写提交说明后选择“提交”或“提交并推送”。 文件列表显示文件名，悬停可查看完整路径；Diff 标题下显示目录，标准文本差异带真实行号与增删符号，可展开“查看原始 Diff”检查完整元数据。非文本或无法解析的差异直接显示原文。提交说明与操作按钮位于面板底部，按钮显示当前勾选文件数量。

- 提交的是所选文件的当前完整内容，包含新增、删除以及 Git 已识别重命名的旧/新路径；部分暂存文件也使用当前完整文件。未选文件的工作区与暂存内容保留。
- 如果查看后文件、索引、分支或 upstream 状态发生变化，提交会拒绝，需刷新并重新检查。刷新只保留内容未变的选择；截断 Diff 会明确提示，提交范围仍是完整文件。
- 推送目标使用当前分支配置的 upstream，页面显示 remote/分支及未推送提交数量。推送会发送该分支全部未推送提交；没有可用 upstream 时仍能提交，请在终端配置推送目标。执行前检查实际推送目标分支仍存在，不使用 force、不自动拉取或变基。
- 提交和推送分别反馈。提交成功会保留 SHA；推送失败时可“重试推送”，不会再次提交。提交结果带警告时暂停自动推送，应先检查终端中的提交与暂存状态。
- 当前 Agent 任务、审批、上下文压缩、Compose 流程或活动 Goal 尚未结束时，禁止 Git 写入。Git 操作期间暂时锁定新任务与重复提交；执行结果会随共享状态在页面重连后恢复。
- 冲突、子模块、detached HEAD、进行中的 merge/rebase/cherry-pick 应先在终端处理。Git 身份、签名与 hooks 保留；hook 改写已审阅暂存内容或夹带未选文件时，本次提交拒绝，工作区格式化结果保留供刷新检查。
- hook 或其他 Git 进程在提交完成后移动 HEAD 时，界面会提示先核对提交记录与暂存区，不要重复提交。推送固定使用已确认的提交；目标探测期间文件、索引或分支发生变化时，先刷新并重新检查。
- 当前界面最多处理 1000 个变更文件、合计 32 MiB 的普通文件内容；超限或特殊文件应在终端处理。Git 操作不调用模型，也不创建 Agent 文件检查点。

## 轨迹视图

会话中央的“对话／轨迹”页签用于切换内容。轨迹固定使用开发者模式；顶部 Input／Model／Tools 图按调用顺序排列，点击节点会展开调用树并定位，右侧显示选中节点详情。多轮分组、工具失败、原始 JSON 与长文本折叠沿用已有 Trace 行为。图表高度和详情宽度可以拖动。

进入轨迹时文件／Git 栏暂时隐藏；返回对话后草稿、工具展开、滚动位置和右栏状态保留。设置仍从左下角进入居中窗口。轨迹只读，不新增审批、搜索或导出功能。

缩小窗口时，甘特图和详情列会收敛到当前可用空间，保留完整三轨与下方调用树。窄窗口可横向滚动查看详情，不裁掉字段。

轨迹按当前会话读取用户目录的 `~/.harness/trace/<工作区指纹>/Trace-log-*.jsonl`。与 Agent 对话后，CLI 会自动生成并持续更新日志；进入“轨迹”页签即可查看，页面会实时刷新进行中和已完成节点。文件名只用于定位日志，界面按事件内的 `session_id` 隔离不同会话，不会混入其他 Thread 的调用。

同一节点的开始和结束记录会合并后展示耗时与安全元数据。历史读取失败会结束加载并显示通知，重新进入轨迹可以重试；日志超过读取上限时显示加载失败，避免把不完整轨迹当作完整历史。界面不会生成示例事件填充空态。

### 在中央查看文件

右侧文件预览头部点击“在主区域打开”，文件会在中间的“对话 / 轨迹”旁新增只读页签；重复打开同一路径会直接切换。文件保留高亮、行号、刷新和错误提示。页签名称较长时省略，悬停可查看完整路径；打开较多文件时页签条可横向滚动。

点击文件页签的关闭按钮只关闭该视图，不删除文件，也不会关闭右侧预览。关闭当前文件后切到相邻文件，最后一个文件关闭后回到对话；对话草稿和已打开视图的滚动位置保留。焦点在页签上时用左右方向键、Home/End 切换，Delete 关闭文件页签。需要更宽的阅读空间时可收起右侧面板。

## 链路日志 v2

在“轨迹”页签查看当前会话的 Run → Step 调用树。每一轮包含模型、审批、工具与数据库事务；同一 Step 的多次数据库事务收成可展开的一组。选中节点后，详情按参数、输入、输出、用量、耗时、错误六区展示，可展开载荷原文。

载荷默认折叠并标明种类和字节数。跨轮转文件的载荷会合并读取；引用的载荷不在当前读取范围时显示“载荷不在当前读取范围内”。运行中的节点在结束记录到达后更新。schema v1 的 JSONL 不再展示；内网 SDK marker 日志仍沿用原索引读取。

采集配置和保留天数见[模型配置](模型配置.md#链路日志采集)。

## 对话中的运行过程

Build 对话每一轮在 Agent 标题下显示“已处理”及连续总耗时；准备、等待模型和工具执行切换时不会重新开始计时。阶段提示只说明当前工作，不另起一个计时。

回答完成后，总耗时行变为“已完成”及耗时，并可点击展开这一轮的中间文本、思考与工具执行过程。过程默认折叠，最终回答单独显示；时间与复制按钮只显示在最终回答末尾。对话底部不再追加独立的“已完成”提示。缺少历史耗时记录时不推算或补造耗时。

对话与轨迹分组、主 Run 根节点共用同一个“本轮总耗时”，包含准备阶段，截止到结果完成、进入终态保存时；三处使用相同的秒数格式。重新打开会话可恢复已记录的总耗时。轨迹详情中的“轨迹采集耗时”包含后台收尾，另行展示；模型、工具等子节点仍保留各自耗时。旧日志没有权威总耗时的会显示“未记录”，不会根据整棵树的时间包络补算。

## 每轮 Token 用量

Build 对话结束后，最终回答下显示该轮的「输入 12,345 · 输出 678 Token」。主 Agent、工具往返、各层子代理以及该轮触发的上下文压缩模型调用都会汇总，重复回调只记一次。输入已经包含缓存命中数，不会再次加上缓存。

已记录的用量会随会话保存，重新打开后可查看。网关未报告或旧历史没有记录时显示「未知」；只有部分用量时显示「≥…（统计不完整）」。失败或取消后也保留已经报告的用量。复制回答只复制正文。

不调用模型的微压缩没有额外 Token 消耗。独立执行的 `/compact` 不回写上一轮用量。子时间线不重复显示整轮总数；轨迹根节点与回答使用同一份终态用量。
