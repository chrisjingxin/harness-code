# 模型配置

v0.1 只支持 OpenAI 兼容协议。TOML 使用 v1 结构；当前只读取用户配置 `~/.harness/config.toml` 和用户明确传入的 `--config <PATH>`。覆盖优先级为 `--sandbox` 等 CLI 参数 > `HARNESS_*` 环境变量 > `--config` > 用户配置 > 默认值。

## 配置文件

从仓库中的 [用户级示例配置](examples/config.toml) 开始：

```toml
[config]
version = 1

[models]
default_profile = "fast"

[models.profiles.fast]
provider = "openai-compatible"
provider_label = "企业 Fast 网关"
model = "your-fast-coding-model"
base_url = "https://gateway.example.internal/v1"
api_key_env = "HARNESS_API_KEY"
context_window_tokens = 128000
capabilities = ["tool-calling", "streaming"]

[models.profiles.fast.reasoning]
effort = "medium"

[models.profiles.pro]
provider = "openai-compatible"
provider_label = "企业 Pro 网关"
model = "your-pro-coding-model"
base_url = "https://gateway.example.internal/v1"
api_key_env = "HARNESS_PRO_API_KEY"
context_window_tokens = 256000
capabilities = ["tool-calling", "streaming", "vision"]

[models.roles]
planner = "pro"
executor = "fast"
```

`api_key_env` 填写环境变量名，而不是密钥值。非空环境变量是首选来源。如果本机开发环境无法注入环境变量，可仅在 `~/.harness/config.toml` 的同一 Profile 中增加：

```toml
api_key = "你的企业网关密钥"
```

这是低安全性的降级方案。macOS/Linux 上 Harness 首次加载含 `api_key` 的用户级配置时会自动将文件权限收紧为 `600`；若文件系统拒绝修改权限，Harness 会拒绝使用该明文密钥并提示改用 `api_key_env`。该字段不得出现在显式 `--config` 或项目 TOML 中，配置文件也不得提交到仓库。

```bash
export HARNESS_API_KEY='你的企业网关密钥'
npm run dev -- config path
npm run dev -- config show
```

`context_window_tokens` 是模型 Profile 的输入窗口，用于上下文预算和压缩。未填写时为 `128000`；显式值不得小于 `16384`。`config show` 会显示最终值与 `context_window_source=default|config`，不依赖网关是否返回模型窗口。

可选的 `[models.profiles.<name>.reasoning]` 只配置 Chat Completions 的 reasoning effort：`effort` 可取 `low`、`medium`、`high`。Harness 将其作为 canonical Model Profile 配置传给 `ChatOpenAI` 的 `reasoning_effort` 参数，始终保持 `/chat/completions` 请求，不传 `reasoning` 或 `output_version="responses/v1"`，也不通过 `extra_body` 旁路，因此配置变化会改变 AgentEngine Profile 身份。模型返回 `reasoning_content`（如 DeepSeek/MiMo）时，Harness 会在运行期流式显示思考内容（不进入正文与 Transcript）；未返回该字段则只显示事实进度。

`config show` 仅展示脱敏后的有效配置。`api_key_source` 只会显示 `environment`、`toml` 或 `missing`，绝不返回密钥值。可用环境变量包括 `HARNESS_MODEL`、`HARNESS_BASE_URL`、`HARNESS_API_KEY_ENV`、`HARNESS_TIMEOUT_SECONDS`、`HARNESS_MAX_RETRIES`、`HARNESS_APPROVAL_MODE`、`HARNESS_SANDBOX`、`HARNESS_GOAL_GRADER_MODEL` 和 `HARNESS_GOAL_MAX_ITERATIONS`。`HARNESS_AGENT_PYTHON` 仅用于开发时定位 sidecar，不属于 TOML 配置字段。

每个 Profile 只支持 `provider = "openai-compatible"`。`provider_label` 只用于 TUI 分组和展示，默认是 `OpenAI-compatible`；它不启用 Anthropic、Gemini 等原生 SDK。`capabilities` 可声明 `tool-calling`、`streaming` 和 `vision`；不写时兼容为 `tool-calling`、`streaming`。未知能力、未知角色或引用不存在的 Profile 会阻止加载；缺失凭据会把该 Profile 标记为不可用，不能被选择或执行。Harness 不会静默降级。

当前主 Agent 只读取本页的 TOML ModelProfile，不读取 Agent JSON，也不能通过配置文件替换。未来已安装且受信任的 Plugin Agent 可以在其 Plugin 包内引用这里已有的 Profile ID；它们同样不能内联模型名、`base_url`、API Key 或 Header。因此切换 `/model` 和修改模型连接仍然只经过本页的 ModelProfile 配置。

受控委派的执行模式不会由模型决定。内置 `general-purpose` 是 Inline worker，沿用父 Agent 的模型；固定角色和 Plugin Agent 是 Managed execution，使用其受信定义引用的 ModelProfile，并按 Profile 复用独立 AgentEngine。Harness Agent 引用未知或不可用 Profile 时会失败。Claude Agent 的 `inherit` 明确继承父实际 Profile；`sonnet`、`opus`、`haiku` 缺少同名 Profile 时也按兼容规则继承，其他未知值仍会失败。

企业网关若需要非秘密固定头，可用 `[models.profiles.<name>.headers]`；若头值来自环境变量，使用 `[models.profiles.<name>.headers_env]`。认证 Header、Cookie 和除上述用户级 `api_key` 外的密钥仍只能使用 `headers_env` 或对应的 `*_env` 字段。

`[models.roles]` 可绑定 `planner`、`executor`、`reviewer`、`tester`、`summarizer`。未声明的角色回退到 `default_profile`。当前 Single Agent 仅将 `executor` 解析为实际 `primary` AgentEngine 模型；`planner` 等绑定会随 Thread 一起冻结，供后续多 Agent topology 使用，但本期不会触发 Planner→Executor 调度。它不是子代理模型绑定入口。

## 实验性子代理模型绑定

默认关闭。开启后，内置 `explore` 可以使用指定的 Model Profile，阅读过程留在子代理上下文。修改配置后需重启 sidecar，对下一次 Run 生效。这与上面的 `[models.roles]` 不是同一组字段。

```toml
[experimental.delegation]
enabled = false

[experimental.delegation.models]
# explore = "fast"
# general-purpose = "fast"  # 本期尚未交付运行路径；若开启并绑定会在 Run 受理时明确拒绝
```

`enabled = true` 时至少指定一个角色，且 Profile ID 必须存在于 `[models.profiles]`。关闭实验后，内置子代理仍继承父模型。`/agents` 对已绑定角色显示实际 Profile。不承诺成本或速度收益。完整用量合计见后续交付。

## 目标验收的 grader

Build 的 `/goal` 使用独立 grader 检查当前验收条件。配置写在 `~/.harness/config.toml` 的 `[goal]`，也可由环境变量覆盖；没有 `/goal model` 或 `/goal max-iterations` 斜杠命令。

```toml
[goal]
# 省略或留空：继承该次 Run 的实际主模型。
# 填写 [models.profiles] 中已有的 Profile ID，为 grader 单独选模型。
# grader_model = "pro"
# 单个 grading run 最多验收轮数，默认 3，范围 1～20。
max_iterations = 3
```

可用环境变量：`HARNESS_GOAL_GRADER_MODEL`、`HARNESS_GOAL_MAX_ITERATIONS`。覆盖优先级与本页其它字段相同。

未配置时 grader 继承当前 Run 的实际主模型。指定的 Profile 不存在、密钥缺失或被策略禁止时，该次 goal-backed Run 在受理前以 `GOAL_GRADER_MODEL_UNAVAILABLE` 失败，不会静默改用主模型。界面和审计只展示 Profile ID 与实际模型名，不展示 endpoint、Header 或 API Key。配置变化只影响之后的 Run；已经开始的 Run 继续使用受理时冻结的 grader 与轮数。

## 在 TUI 中选择模型

交互式运行可输入 `/model` 或 `/models` 打开模型 Profile Picker；`/model pro` 会将 `pro` 作为初始筛选条件。Picker 仅显示 Profile ID、模型名、Provider 标签、能力、窗口和可用状态，绝不显示 endpoint、Header、API Key 或环境变量值。

选择不会热切换正在执行的 Run。空闲 Thread 中确认后，Harness 会先将当前 Thread 的下一次运行切换为所选 Profile，再自动尝试以受控流程更新用户级 `models.default_profile`；Picker 底部会明确显示“选择后同时更新后续新 Thread 默认模型”。不提供勾选项、二次确认或 `/model --default`。

- 已完成的 Run 和正在执行的 Run 保持原模型；历史模型标签以当次实际执行为准，不会因后续选择而重写。
- `/new` 会清除当前选择，新的 Thread 使用刚同步的 `default_profile`。
- 重启或通过 `/resume` 恢复 Thread 时，Harness 会恢复最后一次成功 Run 的选择；服务端确认 `run.started` 后会以实际模型校准状态栏。
- 运行中、等待审批、问题、压缩或取消收敛时 `/model` 禁用；不可用 Profile 会显示原因但不能确认。
- 与旧 sidecar 协商时，既有 Thread 仍只能显示其脱敏绑定并提示新建 Thread；升级 CLI 与 sidecar 后即可在当前空闲 Thread 切换。

`/model` 会自动尝试更新 `config.toml` 中的用户级 `models.default_profile`：内部仍先读取详情、生成不含 endpoint、Header 或凭据的预览，再进行 CAS 和原子写入。默认值已等于所选 Profile 时不会写文件。策略锁、来源覆盖、冲突、Profile 不可用或写盘失败时，当前 Thread 仍会保留新选择，通知会说明“未来新 Thread 默认未更新”；已有 Thread 和历史 Run 不会被改写。

状态栏和 `/status` 只显示当前 Thread 的模型选择。每次 Run 的实际模型仍会随运行记录保存，用于历史追溯，但不在常驻界面重复展示。子代理不提供独立模型选择，统一继承父 Run 已冻结的 `ModelProfile` 快照；子代理运行期间修改配置文件不影响当前执行中的子代理。

工作区 `.harness/config.toml` 和 `.harness/config.local.toml` 当前不会被自动读取。检测到这两个文件时，Harness Code 会在发起模型请求前失败；请移至 `~/.harness/config.toml`，或由你主动传入 `--config <PATH>`。

工具执行默认在本机。企业远端 sandbox 的配置、启用方式和限制见 [安全与沙箱](安全与沙箱.md)。

## AgentEnginePool

sidecar 会让稳定配置相同的 thread 共享 AgentEngine；SQLite 中的 thread 历史、PromptEpoch 和 checkpoint 始终独立保存。默认的有界缓存如下，可在用户级或显式 TOML 调整：

```toml
[runtime_pool]
max_profiles = 8
idle_ttl_seconds = 1800
close_timeout_seconds = 15
pin_default_profile = false
```

`max_profiles` 范围为 `1-64`，`idle_ttl_seconds` 为 `60-86400`，`close_timeout_seconds` 为 `1-120`。到达容量或 TTL 后，只会淘汰没有活动 run、租约或排队任务的 AgentEngine；下次使用对应 Profile 会重建运行环境并从 SQLite 恢复状态。一般保持 `pin_default_profile = false`；设为 `true` 会使默认 Profile 不参与 LRU/TTL 淘汰，适合配置固定的单项目长会话。Thread 选择模型只会让下一次 Run 获取对应的新 Profile，不会驱逐或中断仍被其他 Thread 使用的旧 AgentEngine。

## 工具延迟加载

低频工具（`lsp`、`web_search`、`web_fetch`、`memory_save`、`memory_search`）与全部 MCP 外部工具默认不绑定模型，需要时用 `tool_search` 按关键词或 `select:name` 搜索，命中后下一轮请求自动可见。这能显著缩小每轮请求的 tools 段，代价是搜索命中那一轮的前缀缓存失效一次。

```toml
[tools]
tool_search_defer = "auto"
```

`tool_search_defer` 取值：

| 值 | 行为 |
| --- | --- |
| `"auto"`（默认） | 按模型自动选择：deepseek 系自动关闭延迟（保证前缀缓存稳定），其他模型启用延迟 |
| `true` / `"on"` | 始终延迟加载 |
| `false` / `"off"` | 始终全量注入，保持稳定前缀；`tool_search` 仅作发现辅助 |

需要稳定前缀缓存（长会话、缓存计费敏感）时可显式设为 `false`。
