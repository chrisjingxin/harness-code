# 交互使用

启动 `harness`（源码开发阶段可用 `npm run dev --`）后，直接输入编码任务。Harness Code 会将流式文本、工具调用、审批请求和问题显示在同一 thread 中。终端里底部打字的地方叫**输入栏**，不要和 Compose 工作模式混为一谈。

主 Agent 需要把独立调研交给内置 `general-purpose`、`explore` 或已启用 Plugin Agent 时，仍使用模型可见的 `task` 工具。该调用会先经过 Harness 的受控委派：校验父角色是否允许派发、最大深度与并发数，再创建可取消的 child execution。未绑定的内置 worker 使用短期 Inline 模式并与父角色共享模型和有效能力，不会自行扩大权限。开启 `[experimental.delegation]` 并给该角色指定 Profile 后，该内置角色改走 Managed，使用绑定模型，权限上限不变。Plugin Agent 使用 Managed 模式，可以绑定独立模型和更窄的 Policy，并复用相同 Profile 的 AgentEngine。

企业 OpenTUI Core/React `0.4.3` 使用随 CLI 分发的离线 Tree-sitter parser 与语法查询渲染 Agent Markdown。标题、强调、列表、引用和 fenced code 会按终端样式显示；代码高亮不在运行时下载任何资源。

## 执行时间线

每次工具调用都是独立的历史事件。即使 Agent 连续调用同一个工具，先前结果也不会被后续调用更新。

终端（TUI）按类型画，而不是所有东西一张左轨卡片：

- 你发出去的消息是短竖条加正文，颜色记住**那一次**的工作模式：Build 金色、Compose 紫色。切模式不会把旧消息重新染色。Agent 回答是干净正文，不跟模式变色。
- 读文件、搜索默认是一行；跑命令有一块输出（默认最多约 12 行，点开仍有上限）；改文件走红绿 Diff；`write_todos` 显示一份清单（`[ ]` / `[>]` / `[x]`），不是 JSON；`task` 派出显示角色与任务，点击卡片上的「进入子时间线」可进入只读的独立子代理时间线，按 `Esc` 或返回按钮退回主对话。Agent 继续干活时，完整清单只会钉在时间线底部一份，历史位置收成一行进度。不认识的工具仍会显示名称和有界输入/输出。
- 需要审批或回答时，底部**输入栏换成操作栏**。对话记录里不能再点允许/拒绝；决定之后操作栏消失，时间线只留「已允许 / 已拒绝 / 已回答」。
- 思考标题是独立的 `Thinking`，不用 Build 金。进行中必须展开，但屏幕只显示最后约 12 行；结束后收成一行，点开最多约 40 行。超长内容不会把终端画死。
- 一轮结束后，时间线末尾有一行模型、耗时和用量摘要。Build 与 Compose 用同一套对话页，没有单独的阶段顶栏。

Web 工作台仍把审批和问答画在时间线触发位置的交互卡上；完成后同样显示已允许、已拒绝或已回答。

思考、恢复执行和取消等当前状态只显示在时间线末尾，因此不会插入或覆盖已经完成的工具结果。

Run 受理后，TUI 和 Web 会立即显示活动状态、已运行时长和取消提示（TUI：`Ctrl+C 取消`；Web：`点停止取消`），即使模型还没有返回第一段正文或 Tool。阶段文案只表示已观测到的事实：`准备运行` 或 `等待模型响应`，不会虚构“正在读取文件”等内部步骤。输入栏在执行中仍可打字；普通文字不会送进当前任务，要用运行时命令（见下方「执行中」）。

当前支持的 OpenAI-compatible adapter 使用 Chat Completions。模型返回 `reasoning_content`（DeepSeek/MiMo 系思维链）时，运行期间会流式显示思考块（TUI 只画最后约 12 行）；正文或工具调用到达后思考块冻结为可展开的摘要头。思考内容不是 assistant 正文，不会写入 Transcript 或恢复历史，Run 完成、取消或失败后清除。模型不返回该字段时只显示事实阶段、活动时长和取消提示。Responses 专属 summary 不属于当前支持范围。

## 使用 @ 引用工作区文件

TUI 输入栏与 Web Composer 都支持用 `@` 把工作区文件附到下一次提问。输入单独的 `@` 时，菜单从工作区根目录开始，只列当前目录的直接子项；目录显示末尾 `/`，菜单底部显示当前浏览路径。使用上下键选择，`Right`、`Tab`、`Enter` 或鼠标点击进入目录，`Left` 返回上级，`Esc` 关闭菜单。选择目录不会修改草稿，选择文件才会回填相对路径并追加空格。

输入 `@app` 等文字会改为搜索整个工作区的文件名和相对路径；清空查询后回到此前浏览的目录。菜单标准显示 8 行，较矮的 TUI 显示 5 行，支持 `PageUp` / `PageDown` 和滚轮浏览；候选超过 1000 项时会显示完整匹配数与截断提示。路径含空格时自动写成 `@"docs/my guide.md"`。

发送时可以直接引用全文，也可以只附指定行：

- `@packages/cli/src/index.ts`：附加小型 UTF-8 文本文件全文；
- `@packages/cli/src/index.ts#L20-50`：只附第 20–50 行；
- `@"docs/my guide.md"#L10`：引用带空格路径的第 10 行。

单文件内联必须小于 10KB 且少于 300 行；一条消息累计最多内联 20KB、500 行。显式行号切片可以读取较大的源文件，但源文件超过 16MiB 时仍会降级为轻量引用。锁文件、压缩/生成文件、图片、字体、二进制或非 UTF-8 文件不会直接内联；越界路径和不存在的路径会被忽略。降级后的文件只把路径与大小告诉 Agent，由 Agent 按需使用受控的 `read_file` 检查。

## 快捷键

| 快捷键 | 行为 |
| --- | --- |
| `Enter` | 发送输入 |
| `Shift+Enter` | 输入换行 |
| `/` 或 `Ctrl+P` | 打开本地 Slash Command 菜单 |
| `Esc` | 关闭浮层、命令菜单或选择器；执行中无浮层时只提示取消方式，不停止任务 |
| `Ctrl+C` | 执行中一律取消当前任务并保留草稿；空闲时优先清空输入，无草稿则退出（Windows 下存在文本选区时优先复制选区） |
| `Ctrl+O` | 展开或折叠工具详情 |
| `Tab` | 空闲且无浮层时在 Build / Compose 工作模式间切换（Web 端在输入框为空时同样生效） |
| `Shift+Tab` | 循环切换审批模式，见 [安全与沙箱](安全与沙箱.md#审批模式) |
| 空输入时 `↑` / `↓` | 回填历史提示词；没有历史时浏览 thread |
| 空输入时 `PageUp` / `PageDown` | 按半页浏览 thread |

`Shift+Tab` 按 `plan → default → auto-edit → auto → yolo` 顺序循环切换审批模式，输入框右下角实时展示当前模式并附有 `Shift+Tab` 快捷键提示。空闲时切换会作用于下一次 Run；已有活动 Run 时，TUI/Web 会先把目标模式提交给 Host，Host 返回实际 `mode` 与单调 `revision` 后才更新界面，因此成功后同一 Run 的下一次模型/工具边界立即使用新模式。存在待处理审批、问答或目录信任时服务端返回可重试的 busy，repository-level trust registry 状态不单独阻止 owner 切档；RPC 失败或 Run 已结束时保留旧模式。选择器或命令菜单打开时 `Shift+Tab` 让位给浮层，不会误切换。Build 下也可用 `/plan` 进入计划模式（见下方 Slash Command）；这与 Compose 流程里确认计划文档不是同一件事。

## 执行中

Agent 正在跑时，输入栏保持可编辑（TUI placeholder：`正在执行；Ctrl+C 中断`；Web：`正在执行；点停止中断`）。只放行运行时命令；普通文字和 `//` 转义文本会被拒绝，草稿留在输入栏。

**立刻可用：** `/help`、`/status`、`/btw`、`/title`、`/goal`、`/plan`（空闲改下一轮档位，运行中提交给当前 Run）、`/plan-view`、`/mcp`（只读）、`/code-index`（只读 status；建立/重建/删除见 [代码索引](代码索引.md)）、`/agents`（只读列表）、`/teams list|show|status|cancel`、`/new`（先确认再取消当前任务）、`/quit`（先确认再中止）。未知 `/xxx` 只给本地建议，不送给模型。

**任务结束后再用：** `/compact`、`/resume`、`/undo`、`/redo`、`/model`、`/web`、`/skills`、Plugin Command、`/new-work`、`/abandon`、`/teams generate|run`。菜单会显示「当前任务结束后可用」，提交后草稿还在。

取消当前任务：TUI 用 `Ctrl+C`，Web 点停止按钮。`Esc` 只关浮层或菜单。

### 文本选中复制

在终端（TUI）时间线、弹窗（如 `/btw`）或侧边栏代码预览中，支持直接选中文本并复制到系统剪贴板，右上角会即时弹出 Toast 提示（“已复制到剪贴板”或“复制到系统剪贴板失败”）：

- **macOS / Linux**：使用鼠标拖选文本后松开左键，选区将自动复制到系统剪贴板。
- **Windows**：鼠标松开不会自动复制；在存在非空文本选区时，按 `Ctrl+C` 或松开鼠标右键复制该选区。无选区时，`Ctrl+C` 保持原快捷键行为（优先清空输入，其次取消运行，最后退出）。
- **空选区与保护**：未选中任何文本时不会调用系统剪贴板工具、不会清空状态，也不会产生 Toast 提示；浮层拖选结束不会触发底层误操作或重复 Toast。

## TUI 项目检查器

Thread 页面点击底栏 `[侧栏]` 打开或关闭项目检查器。标题区显示当前会话短标题（`/title` 或自动起名；还没有标题时用截断后的第一条原文），不是一份 Thread 列表。文件页把工作区文件树和选中文件的只读预览放在同一右侧面板内；终端达到 150 列时，文件树在左、预览在右，低于该宽度时改为上下排列，并把约 65% 的可用内容高度留给下方预览。预览复用随 CLI 分发的离线 Tree-sitter 高亮，不下载语法资源。状态页显示工作目录、带可视化轨道的上下文用量、MCP 连接和唯一的“工作区变更”列表。该列表来自 Git，包含已跟踪修改、暂存修改和未跟踪文件；每行在路径右侧显示相对 `HEAD` 的绿色 `+N` 与红色 `-N`，二进制文件或统计不可用时显示短横线。“工作区变更”标题始终固定，只有下方文件列表滚动；滚动条始终位于行数统计的最右侧，文件能全部放下时自动隐藏。列表支持鼠标滚轮、`↑` / `↓`、`j` / `k`、`PageUp` / `PageDown` 和 `Home` / `End`。Agent 成功写入、编辑或删除文件后，文件树、当前预览和 Git 变更会在 Run 进行中刷新；Run 结束时还会执行一次完整兜底刷新。非 Git 工作区或 Git 状态探测失败时不展示该区域。

终端宽度达到 116 列时，检查器停靠并让对话区自然变窄；达到 150 列后会扩大检查器以容纳文件预览列；73–115 列时使用右侧覆盖式面板；72 列及以下使用全宽面板。拖动终端跨过这些阈值时会重建对应布局，避免停靠面板的流式定位残留到覆盖模式。较矮终端保留可滚动状态页并压缩文件树高度。文件类型使用 `TS`、`TSX`、`MD`、`LINK` 等短文字标签，不依赖 emoji、Nerd Font 或额外图标库。

检查器打开时，`1` / `[` 切到文件页，`2` / `]` 切到状态页。文件页使用方向键或 `j` / `k` 浏览文件，左右方向键折叠或展开目录，`@` 把当前文件路径填入输入栏；状态页的上下键和 `j` / `k` 改为滚动变更列表。关闭检查器请再点一次底栏 `[侧栏]`，或点检查器内的关闭入口。

## 工作模式：Build 与 Compose

每次提交都发生在两种工作模式之一中，`Tab` 键（空闲、无浮层、输入框为空时）在两者间切换：

- **Build**：默认模式。一次消息交给主 Agent 自主完成，与既有行为完全一致。
- **Compose**：先问清需求、写出可确认的文档，再写代码，最后用内置检视看这一次改过的代码。一套需求放在
  `docs/compose/<短名>/` 下的 `task.md` / `spec.md` / `plan.md` / `todo.md` / `review.md`，可进 Git。
  进度条是：需求 → 规格 → 计划 → 实现 → 检视。确认文档后会自动进入下一阶段，不用打「继续」。
  实现按 TDD 写代码；写完进入检视，你确认后结束。简单需求可以不单独确认规格。

中断与恢复：`Esc` 只取消当前这一轮。退出后再进同一条 Compose 会话，已确认的文档不会重问。
完成后直接输入新目标就是下一套需求。工作模式与审批模式正交，Compose 不改变权限（见
[安全与沙箱](安全与沙箱.md#compose-模式不提权)）。

底部状态栏在终端宽度足够时显示工作区目录与 Git 状态：分支名、`detached@<短SHA>`（分离头）、`非 Git 工作区` 或 `Git 状态不可用`。

## 已实现的 Slash Command

- `/help`：显示命令说明。
- `/new`：创建新的 thread 并回到首页；当前任务仍在执行时会先显示确认框，确认后才请求取消。
- `/clear`：`/new` 的兼容别名。
- `/title <短标题>`：给当前 thread 起一个不超过 20 字的短名，立刻出现在 `/resume` 和 Web 侧栏。空 `/title` 只提示用法。新 thread 在发出第一条消息后会并行自动起名；失败时继续显示截断后的第一条原文。你改过的名字不会被迟到的自动结果盖掉。自动起名不进对话记录。执行中也可以 `/title`。
- `/compact`：在当前 thread 空闲时强制请求一次 full 压缩。它保留最近两轮、将更早内容写入本机归档；只要摘要后的模型投影严格小于原投影就会提交，不套用自动压缩的 20% 收益门槛。历史过短、连空摘要包装都无法缩小投影、原子组不完整或摘要无效时返回可读的 skipped/failed，不假装成功；明显无收益时会在调用摘要模型前跳过。它绕过自动三次失败熔断，但不会删除 `/resume` 可见的完整 Transcript。压缩期间输入栏会失焦，新消息、重复 `/compact`、`/resume`、`/model` 和 `/web` 都不会排队或执行；必须等待压缩返回成功、跳过或失败后再继续输入。
- `/new-work <目标>`：仅 Compose 模式。必须带新目标，放下当前需求并立刻开始新访谈；旧文档保留。空 `/new-work` 会被拒绝。
- `/abandon`：仅 Compose 模式且有进行中需求时可用。确认后进度回到空闲，文档和代码保留，不回滚。后面不能再跟新目标（换题用 `/new-work`）。
- `/btw <question>`：Build 与 Compose 都可用。临时只读问答，在终端中央弹出独立浮层展示问题与单轮回答；不带问题时提示用法；回答严格不写入 Work Item、LangGraph 状态、Transcript 或 SQLite 历史，也**不参与**当前 `/goal` 验收。支持按 `c` 键或点击复制按钮将回答复制至系统剪贴板（终端右上角以绿色气泡即时通知），按 `Esc` 或 `Enter` 键关闭浮层。
- `/plan`：仅 Build。空参切到计划模式，下一条消息才开始规划；已经在计划模式再打空 `/plan` 只提示，不改档。这不是 Compose 的 Plan 阶段，也不写 `docs/compose/`。
- `/plan <目标>`：仅 Build。空闲时切到计划模式并立刻把该句当作本轮用户消息提交；执行中先向 Host 提交 `plan`，当前 Run 在成功后立即进入计划约束，规划目标留到当前 Run 结束后再发。
- `/plan exit`：仅 Build。退出计划模式，恢复进入前的审批档位。当前不在计划模式时只提示。若当前 Run 已由 `enter_plan_mode` 点头开启不可逆的计划约束，Host 会拒绝退出并保留 `plan`；普通活动 Run 的切档不会取消任务。Compose 菜单不出现 `/plan`，手输会提示仅 Build 可用。
- `/plan-view`：仅 Build。重新打开当前 thread 已保存的计划；没有计划时只提示，不切换审批模式。若计划审批正挂起，则回到同一个审批预览，不创建第二次审批。

如果你在普通 Build 对话里明确说「先做计划」而没有先输入 `/plan`，Agent 可以提议在当前 Run 进入计划模式。界面只会询问“允许一次”或“拒绝”：允许后同一 Run 立即收紧为计划权限，不会生成会话级或项目级授权；拒绝后保持原审批模式继续对话。无交互界面的运行会安全拒绝该提议。

计划写在 `~/.harness/plans/<thread_id>.md`（不进仓库，也不会出现在 `~/.harness/` 根目录）。Agent 规划时把它写成虚拟路径 `/.harness/plan.md`，写完会全屏打开可滚动的 Markdown 预览。三个动作：

- **批准并开始实现**：退出计划模式，恢复进入前的审批档位，并自动开始改代码。
- **继续打磨**：可附文字意见；Agent 留在计划模式里改计划，项目文件仍不能改。
- **放弃计划**：退出计划模式，不开始写代码。

计划预览支持按原始 Markdown 行号选择起止行并写批注。批注会附上行号、原文摘录和意见：选择“继续打磨”时交给 Agent 修改计划；选择“批准并开始实现”时随自动实现轮一并交给 Agent。整体意见与行批注可以同时提交。

空计划也可以做这三个选择。TUI 与 Web 是同一套按钮。

计划模式能看见当前 `/goal`，但**不会**独立验收或把目标标完成。批准进入实现后，下一次普通 Build Run 才会继续 grading。

- `/goal`：仅 Build。设置并验收当前 Thread 的长期目标。Compose 菜单不出现，手输会提示仅 Build 可用。无参数时查看当前目标；其余 remainder：
  - `/goal <目标>`：没有目标时创建，已有目标时替换。Harness 会先生成 objective 与可观察的验收条件，必须由你接受、编辑或驳回后才生效；Auto/YOLO 也不会自动接受。
  - `/goal edit`：弹出编辑框修改当前目标；`/goal edit <反馈>` 直接提交修订。
  - `/goal pause` / `/goal resume` / `/goal clear`：暂停、继续或清除当前目标。`resume` 以及 blocked 后的普通 Build 消息会把目标恢复为进行中，并自动续跑一轮。
  - 接受后 Agent 会自动开始工作；之后的普通 Build 消息继续同一目标。目标跨 Run 和重启持久，但**没有后台调度**：你不发消息时不会自动连开新 Run。
  - 主 Agent 按当前 Build 审批模式工作。独立 grader 只读验收：Timeline 单独画出「验收中 / 验收通过 / 验收未通过」卡片，列出每条准则的通过或缺口；缺项时同一 Run 内补做，全部满足后目标变为 complete。`/plan`、`/btw`、Compose、direct shell 不参与验收。
  - grader 模型和单次最多验收轮数写在 `~/.harness/config.toml` 的 `[goal]`，见 [模型配置](模型配置.md)。
- 自动上下文处理：输入达到 50% 时先报告，达到 60% 时可归档旧工具结果；达到完整压缩水位时也会先做一次低损耗工具归档并重新估算，足够释放空间时不会调用摘要模型。归档显示为“正在归档工具结果”，原文仍可通过恢复后的 Artifact 指针读取，完整 Transcript 不会被删除。
- `/status`：打开运行状态仪表盘浮层，结构化展示工作区环境（目录、Git 分支与变更统计、CLI 版本）、运行模式与模型（工作模式、当前模型、执行环境、审批模式）、会话与上下文健康度（Thread 统计、Token 用量水位条与缓存命中率）及扩展生态（Python Sidecar 连接、MCP 服务与工具统计、Skill/Agent 数量）。按 Esc / Enter / q 快速关闭。
- `/model` 或 `/models`：打开模型 Profile Picker；`/model <query>` 会预填筛选。确认可用 Profile 后，当前 Thread 的下一次 Run 立即使用该模型，并自动尝试同步后续新 Thread 的用户级默认模型；Picker 会显示这项语义。已启动的 Run 不会被切换；不可用 Profile 不可选择。默认写入失败不撤销当前 Thread 选择，会显示安全原因；与旧 sidecar 协商时保留仅新 Thread 选择的兼容行为。
- `/skills`：在当前 thread 上打开可搜索的悬浮 Skill 选择器。输入关键词过滤目录，使用方向键或鼠标选中，按 Enter 后 Skill 会附到下一条消息；Esc 关闭且不改变当前输入。
- `/mcp`：查询并显示所有已配置 MCP 服务器的运行时状态，包括连接状态、已加载工具和错误信息。未配置时显示配置引导。执行中只能刷新状态，不能增删。
- `/code-index`：管理当前工作区代码索引。默认无索引时首建、健康索引存在时增量更新；`status` / `rebuild` / `cancel` / `remove` 分别查看、全量重建、取消和确认删除。配置关闭时菜单隐藏，手输提示开启路径。详见 [代码索引](代码索引.md)。健康索引会向后续 Run 提供只读 `codebase_explore`；编辑前仍必须 `read_file`。
  - `/mcp add <name> <command> [args...]`：添加 stdio 类型 MCP 服务器，例如 `/mcp add filesystem npx -y @modelcontextprotocol/server-filesystem /tmp`。
  - `/mcp add <name> --url <url>`：添加 HTTP 类型 MCP 服务器；加 `--sse` 使用 SSE 传输。
  - `/mcp remove <name>`：删除指定 MCP 服务器。配置持久化到 `~/.harness/config.toml`，添加后自动尝试热连接。

模型侧可通过 `tool_search` 工具按关键词发现已连接的 MCP 工具（支持 `select:name1,name2` 精确选择或关键词搜索，返回工具名称、描述和参数 schema），再按名称直接调用。

- `/agents`：打开子代理浏览浮层，查看内置角色（`general-purpose`、`explore`）与已启用的 Plugin Agent，标明来源、用途与工具边界。
- `/teams` 或 `/teams list`：列出固定 Plugin Team 和当前 Host 内已生成的 Team 预览。执行中可以 `list` / `show` / `status` / `cancel`；`generate` 与 `run` 要等当前任务结束。
  - `/teams show <team-id>`：查看 Team 的任务 DAG。
  - `/teams generate <team-id> <lead-agent> <worker1,worker2> [max-parallelism]`：从已注册 Agent 生成“并行分析 → lead 汇总”预览。
  - `/teams run <team-id> <任务描述>`：异步启动 Team 并返回 run ID。
  - `/teams status <run-id>`：查询可恢复的 Team 运行状态。
  - `/teams cancel <run-id>`：取消指定 Team Run，不影响其他 Run。
- `/web`：在当前会话空闲时启动本机 Web 工作台接管当前 Thread。Web 端的 Run、Slash Command、模型选择、Skill 装配、MCP 增删和审批/问答与 TUI 走同一共享 Core，详细说明见下文「Web 工作台」一节。
- `/undo`（别名 `/rewind`, `/rollback`）：打开历史回合选择浮层，回退当前会话与代码至指定历史回合。在二次确认框中支持三档选择：同时回退代码与对话（推荐）、仅回退对话、仅还原代码（非 Git 仓库仅支持仅回退对话）。回退后进入暂存态，在提交新 Prompt 前可随时恢复。若当前有已完成的 `/goal`，撤销会保留目标定义但把状态恢复为进行中，并作废之后的验收结果；不会把目标正文一起回退。
- `/redo`：恢复最近一次被撤销的会话与代码状态。仅在执行过 `/undo` 且尚未提交新 Prompt 时可用。redo 不会把已经作废的验收重新标为通过；需要下一次 goal-backed Run 再验收。
- `/quit` 或 `/q`：退出。执行中会先确认「当前任务将被中止」；取消确认则继续跑，确认后才退出。

### 文件修改

健康代码索引会向后续 Run 提供只读 `codebase_explore`，用于定位符号和调用关系；它返回的源码不是 Snapshot。修改已有文件使用 `edit_file`，创建新文件使用 `write_file`，删除文件使用 `delete_file`。`read_file` 会返回只属于当前 Thread 的 Snapshot ID 和局部源行；`edit_file` 必须携带该 ID、已读范围中唯一的 `old_string` 与 `new_string`。已有空文件也要先读取；当 Snapshot 和当前完整文本都仍为空时，用同一 Snapshot 和 `old_string=""` 写入初始内容。空字符串不能作为非空文件的开头、结尾或任意插入位置。`edit_file` 不支持 `replace_all`、行号 range 或批量 edits。`write_file` 不覆盖任何已有文件，包括空文件；`delete_file` 必须使用完整读取该文件得到的当前 Snapshot。Snapshot 过期、文件已变化或未读目标区域时，重新读取后再试。当前没有批量补丁文件入口。

文件修改审批展示路径、总增删行数和有界 diff 预览。预览超过 200 行、16 KiB 或终端可见高度时会明确标记或隐藏部分内容，但允许/拒绝选项仍然可用；批准绑定的是该次调用已经固定的完整拟议内容。工具输入、文件 mutation 大小、Snapshot、Policy 或 CAS 校验失败仍会阻止写入。

文件创建、编辑或删除需要人工确认时，会显示操作、工作区逻辑路径、增删行数和带行号的 Diff。
TUI 把这份预览放在底部操作栏里，不夹在对话中间；内容宽度达到 120 列时使用左右对比，较窄时使用行内 Diff。增删行会使用 Codex 风格的
低亮酒红/墨绿色整行背景并保留醒目的 `-`/`+` 标记；支持的文件类型会使用随 CLI
分发的 Tree-sitter 高亮，无法识别语言或高亮失败时仍显示带 `+`/`-` 的可读纯文本。Diff 最多预览
200 行、16 KiB；超过上限会在审批选项之前明确提示。批准应用的是该次调用已经固定的完整拟议变更，而不只是
屏幕内可见的行，因此截断时仍应根据路径、统计和已展示内容谨慎决定允许或拒绝。
长 Diff 只有正文区域滚动，标题、描述、文件统计、截断提示、审批选项和操作提示保持可见；有文件预览时，
鼠标滚轮位于 Diff 正文区域、或使用 PageUp/PageDown、Ctrl+↑/↓ 和 Ctrl+Home/End，可翻阅正文，这些滚动键
不会滚动背后的时间线。鼠标滚轮位于审批选项区域时只移动当前决定，不滚动背后的时间线；↑/↓、j/k 仍选择
审批决定，Enter 继续确认。连续审批切换到新的请求时预览会回到顶部。没有文件预览的通用审批不显示
“滚动预览”提示，Page/Ctrl 滚动键继续滚动对话时间线。
终端高度受限时（例如 127x40 且 TODO 或历史很长），审批栏仍优先保留文件摘要、截断提示、至少 4 行 Diff、
当前决定、确认提示和底栏；Diff 正文会限制在约 14 行以内并在自身区域滚动，时间线让出剩余空间。

创建或编辑成功后，结果会基于实际落盘内容返回新的 `snapshot_id`、`changed_range`（新版本源行号及增删统计）和最多 200 行、32 KiB 的局部内容。`shown_lines` 给出首尾行号时，这些返回行已记录为新 Snapshot 的已读范围；连续编辑它们不必再次完整读取文件。按字节截断时 `shown_lines` 为空，必须重新读取。保存钩子改写内容时会返回 `POST_WRITE_DRIFT`，其中分别给出已批准的 `proposed_diff` 和实际 `actual_diff`；后续只能使用返回的实际 Snapshot。显式 formatter 或其他外部写入会使该 Snapshot stale，必须重新读取。

已启用本机 Plugin LSP 时，创建或编辑后会额外返回短时、只读的 diagnostics 摘要。`status=ok, count=0` 表示已检查且没有诊断；`unavailable` 表示没有可用 LSP；`timeout` 表示检查超时。三种结果都不会撤销已写入的文件，也不会自动运行 formatter；完整诊断仍需显式调用 `lsp`。

命令名不区分大小写，参数会原样传给对应命令。未知的 `/命令` 不会发送给 Agent，而会在本地提示可能的命令；若要向 Agent 发送以 `/` 开头的普通文本，请输入 `//`，例如 `//api/users 的路由在哪里`。

菜单会根据协商 capability 和当前运行状态隐藏不可用功能；例如未协商上下文管理时不显示 `/compact`，未协商 `models.read` 时不显示 `/model`，正在执行、等待交互或压缩上下文时 `/compact`、`/resume`、`/model` 和 `/web` 会说明不可用原因。协商 `models.select` 后，`/model` 可改变当前空闲 Thread 的下一次运行；若未协商 `config.write`，仍保留当前 Thread 选择，但未来新 Thread 默认值不会同步并会给出提示。

项目 `<workspace>/.harness/skills/<name>/SKILL.md` 默认生效，用户 Skill 位于 `~/.harness/skills/<name>/SKILL.md`（也兼容 `~/.harness/skills/local/<name>/SKILL.md`）。同名 Skill 不会互相覆盖，冲突时使用完整 canonical ID，例如 `project/review`。需要暂时停用时运行 `harness skills disable project/review`；当前 Run 保持原快照，下一顶层 Run 生效，无需重启 Harness。
项目 `<workspace>/.harness/skills/<name>/SKILL.md` 默认生效，用户 Skill 位于 `~/.harness/skills/<name>/SKILL.md`（也兼容 `~/.harness/skills/local/<name>/SKILL.md`）。同名 Skill 不会互相覆盖，冲突时使用完整 canonical ID，例如 `project/review`。已启用 Plugin 的 Skill 使用 `plugin/<source-id>/<plugin-name>/<skill-name>`，例如 `plugin/local-a1b2c3/secure-review/review`。需要暂时停用普通 Skill 时运行 `harness skills disable project/review`；Plugin Skill 随整个 Plugin 启停，二者都在重新启动 Harness 后生效。

Skill 正文和参考资源仍应通过带 `/` 的 canonical 虚拟路径读取。为兼容模型偶尔把多段 ID 展平成一个连字符文件名的情况，`/.harness/skills/` 只读入口会在当前启用快照中能够唯一反解时接受该别名；Skill 管理命令和权限配置仍只接受 canonical ID。

命令行管理入口：

```bash
harness skills list
harness skills inspect project/review
harness skills enable project/review
harness skills disable project/review
harness skills trust project/review  # enable 的兼容别名
harness skills market --market enterprise
```

市场安装、更新和删除只调用企业 Provider 接口；未安装 Provider 时会返回明确诊断，不会访问公网。

Plugin Agent 既可由主 Agent 通过 `task`
选择，也可先通过 `/agents` 查看；固定或生成 Team 使用 `/teams` 控制。请使用 `/resume`
恢复普通 thread，使用 `/teams status <run-id>` 查询 Team 状态。

## Web 工作台

`/web` 在 `127.0.0.1` 打开 React 工作台接管当前会话，可从空首页或已有 Thread 启动。Web 端发起的 Run、Slash Command、模型选择、Skill 装配、MCP 增删和审批/问答全部走与 TUI 相同的共享 Core，两端语义一致；只在输入方式和布局上存在差异。视觉层级与外围面板说明见 [Web 工作台](Web界面.md)。

### 界面

桌面布局：左侧 Thread 栏（宽 260px，只展示摘要、更新时间与消息数） + 中央 Timeline（最大阅读宽度约 880px） + 底部 Composer + 右侧 372px 工作台。Thread 内部 ID 不直接显示。右侧工作台通过 Model / Skills / MCP / Status 四个 tab 切换，关闭后中央列自然扩展。移动端使用全高 drawer 代替侧栏，Thread 与工作台抽屉互斥，主区只剩 Timeline 与固定 Composer，主要触控目标不小于 44px。

页面每次打开固定使用浅色主题；顶栏更多菜单（…）可显式切换深色 / 浅色。主题选择只在本次 Web 接管内生效，不写入配置文件，不跟随操作系统主题，也不影响 TUI 外观。

### 常用动作

- 从空首页发送第一条消息即可创建 Thread；左侧栏可创建、搜索、恢复和切换 Thread。
- 右侧工作台通过 Model、Skills、MCP、Status 四个 tab 切换：Model 用于选择当前 Thread 的下一次 Run；Skills 可装配下一条消息的 Skill，并在具备 `skills.manage` 能力时启用 / 禁用已注册 Skill；MCP 用于增删 MCP 服务器；Status 是只读状态面板。Help 从顶栏更多菜单打开。
- 顶栏显示当前模型、审批模式与活动 / 连接状态 chip；模型与状态 chip 可点击打开对应工作台面板。项目名旁显示 Git 状态：分支名、`detached@<短SHA>`、`非 Git 工作区` 或 `Git 状态不可用`；Status 面板的「分支」行展示同一状态。
- Timeline 底部与 TUI 相同显示 `准备运行` / `等待模型响应`、活动时长和 `点停止取消`；模型返回思考内容时，正文前会出现“思考中 / 思考”块（流式展开，冻结后点击可展开/收起）。页面开启 reduced-motion 时 spinner 停止旋转，但状态文字、时长和取消按钮仍可用。Esc 只关浮层或菜单，不取消当前任务。
- 顶栏 `返回 TUI` 归还控制权；更多菜单（…）提供深浅主题切换、帮助、`返回 TUI`（移动端）与 `退出 Harness`。`退出 Harness` 与 `/quit` 走同一通道请求退出。
- 关闭页面会结束本次 Web 会话：CLI 归还表现层输入权给 TUI，TUI 恢复后与 Web 会话期间是同一个 Thread、同一条 Timeline。刷新页面会在短暂重连宽限内自动恢复：页面重连后重新同步完整视图，无需重新执行 `/web`；宽限到期或刷新后未能重连才会结束会话。Host 控制权始终属于 CLI 进程，Web 接管期间只转移表现层输入权。

### Composer 与命令菜单

- `Enter` 发送，`Shift+Enter` 换行；中文 IME 组合输入中的 Enter 只用于确认候选，不会发送消息；运行中同一位置的图标按钮变为取消。
- 单个 `/` 打开命令菜单（上下键 + `Enter`，`Esc` 关闭）；`//` 不打开菜单，可用于发送以 `/` 开头的普通文本。
- `Ctrl/Cmd+K` 也可打开命令菜单。
- 命令菜单按协商能力隐藏不可用项；Web 端与 TUI 共享同一会话，不提供 `/web` 入口以避免嵌套接管。

### Markdown 与代码

支持的 fenced code（JavaScript、TypeScript、JSX、TSX、Python、Go、C/C++、Bash、Java、HTML、JSON、YAML、CSS、Markdown 等）会在离线 Shiki Syntax Worker 中自动进行语法高亮；语言别名如 `py`、`ts`、`yml`、`sh`、`c++` 均可精确识别。代码块右上角提供复制按钮。标记为 `diff`、`patch` 的代码块（或能识别为 unified diff 的内容）会按行显示 Codex 风格的红色删除背景和绿色新增背景，保留 hunk 与上下文行；未知语言、超出 64 KiB 或 2,000 行、或加载失败时会自动降级为纯文本，且复制代码功能始终可用；运行期间零网络依赖，也不从远程下载语法资产。

### 审批与问题

Approval 只显示服务端允许的 decision 按钮（允许一次 / 本会话允许 / 本项目允许 / 拒绝 / 拒绝并反馈），反馈输入仅在该选项存在时出现。「本会话允许」只在当前会话内记住，进程退出即失效；「本项目允许」会把规则写入当前项目的 `.harness/settings.json`，对该项目后续会话持续生效。Question 一次展示全部题目，单选用 radio，多选用 checkbox，存在 `allowOther` 时显示“其他”自由文本；所有必答项完成后整体提交。Approval 与 Question 都用页面内原生 UI 渲染，不会弹出浏览器 `confirm/prompt` 对话框。

文件变更 Approval 使用专用 Diff 卡：宽度达到 760px 时默认左右对比，较窄时默认行内模式，并可在
当前审批中通过“左右 / 行内”切换。卡片显示 old/new 行号、红色删除面、绿色新增面和语法高亮；颜色之外
仍保留 `-`/`+` 标记。长行可水平滚动，未知语言或 Shiki 不可用时自动降级为纯文本。原始工具参数默认
折叠在“请求参数”中；预览截断时会明确说明批准仍会应用完整变更。

### 运行中限制

存在 active Run 或待处理审批 / 问答时，`返回 TUI`（桌面直接按钮与移动端更多菜单中的返回项）与 Thread 切换会显示禁用原因并保持只读；取消按钮不受此限制。退出 Harness 仍可请求，CLI 收敛会话后直接调用退出 handler。

页面只在 `http://127.0.0.1:<随机端口>` 提供服务，浏览器必须能访问该地址。Markdown 按 GFM 渲染但不执行 raw HTML、不自动加载远端图片，链接只允许 `http` / `https` / `mailto`。页面只公开固定的 app、Syntax Worker、Tree-sitter core 和 catalog WASM 路径；不会根据 URL 读取任意本地文件或加载远端语法资源。

## 恢复 Thread

运行 `harness --resume` 会直接打开与 `/resume` 相同的选择器。每条的主标签是短标题（`/title` 或自动起名），还没有标题时显示截断后的第一条原文；次行仍是更新时间和消息数。内部 `thread_id` 不会显示，也不需要手动输入。恢复范围始终是当前 project，不能浏览或恢复其他 project 的记录。

Harness 将完整用户可见 Transcript、版本化 CompressionCheckpoint、LangGraph 执行缓存和 Context Artifact 存在用户目录的 `~/.harness/threads.sqlite3`。下一次运行的模型历史由“最新有效 CompressionCheckpoint + 之后的 Transcript”重新生成；LangGraph `messages` 只是单向刷新的执行缓存，不用来恢复完整 UI 历史。压缩不会删除已写入 Transcript 的历史；旧库只会把当时能证明的视图标记为 `legacy/incomplete`，不会伪造更早历史。目录权限为 `0700`，新建数据库权限为 `0600`；数据库只保存 project 规范路径的 SHA-256 指纹，不保存原始 project 路径。Harness 停止后，可以手动删除 `threads.sqlite3`、`threads.sqlite3-wal` 与 `threads.sqlite3-shm` 清理全部本地 thread。

这里有两个不会互相 fallback 的视图：`threads.open` 和 `/resume` 展示 Transcript 中的完整用户可见历史；模型只接收最新有效 checkpoint 加其后的 Transcript tail。一次新的顶层 Run 会先冻结当时的 AGENTS/Skill snapshot，再原子受理 binding、snapshot 和用户消息，之后取得 AgentEngine、构造 RunContext 并刷新模型投影。因此同一 thread 修改 AGENTS 或 Skill 后，下一次 Run 才使用新内容，已经开始的 Run 和旧审计仍保持原 snapshot。

上下文状态通知只显示压缩动作和预算摘要，例如 report、micro、full、overflow、skipped 或 failed。界面不会显示 checkpoint ID、完整 Prompt、绝对路径、工具原文、密钥、Header 或认证 Query；如果恢复历史来自旧库且不完整，会明确标记 `legacy/incomplete`。

## Run 上下文刷新

同一 thread 的每个顶层 Run 都会重新准备一份上下文快照。除用户级 `~/.harness/AGENTS.md` 和项目级 `<workspace>/.harness/AGENTS.md` 外，Harness 还会从仓库根目录到当前 workspace 沿祖先目录查找普通 `AGENTS.md`；更远的目录先注入，更近的目录后注入，同一来源路径只加载一次，不支持 `@import`。这些文件发生修改、删除或新增后，下一次 Run 才生效；已经执行的 Run 继续使用启动时的快照，工具循环、重试和交互恢复都不会热切换规则。快照中的 AGENTS 和 Skill 索引只是低可信参考，不能增加真实的工具、Sandbox 或权限；快照 ID 会和本次 Run 的模型绑定一起保存，供本地审计。

刷新期间如果参考文件被替换、通过符号链接逃逸或无法形成一致读取，Run 会在首个模型调用和受理记录前失败，不会留下半套 Run。快照只保存确定性内容摘要和必要正文，并会脱敏常见凭据与宿主绝对路径。Skill 由 Host 的 Catalog manager 在顶层 Run 边界刷新：内容不变时复用 immutable snapshot，变化时创建新 snapshot；活动 Run 继续使用旧 snapshot，skills mutation RPC 返回 `effective_on=next_run`。

模型配置、无头调用和配置查询见 [模型配置](模型配置.md) 与 [快速开始](快速开始.md)。
