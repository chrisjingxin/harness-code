# 安全与沙箱

Harness Code 默认在本机执行，与 Qwen Code 未开启 sandbox 时一致。`--cwd` 决定本机主工作区：内置文件工具默认使用以 `/` 开头的虚拟路径访问该目录。

主工作区内的直接文件工具必须使用 `/` 虚拟路径。`glob` 和 `grep` 可以省略搜索目录，此时从工作区搜索；文件匹配模式不能使用绝对路径或 `..`。Harness Code 会在工具执行前解析符号链接，工作区内指向外部的链接不能用来逃逸到未信任目录。

工作区外的文件工具访问会弹出**目录信任**审批卡片（`yolo` 模式自动授予会话级信任）。卡片只有“允许（本会话信任）”与“拒绝”两个选项；允许后该目录在本次会话内与主工作区等价，读写按当前审批模式处理，退出即失效。需要跨会话长期信任时，可手工把目录写入项目 `.harness/settings.json` 的 `additional_directories`。不可注册的目录（文件系统根、用户 home 本身、系统目录、UNC）仍硬拒绝。子 Agent 只能继承已信任目录，不能自行发起信任审批。

对工作区内的创建、编辑和删除，确认框会展示文件路径、增删行数和有界 diff 预览。预览超过 200 行、
16 KiB 或终端可见高度时会明确省略或隐藏部分内容，但允许/拒绝选项仍然可用。Harness 会把完整
拟议内容、工具参数和当时的文件版本固定在一次性计划中；即使用户已经确认，真正写入前仍会再次比较文件版本。此间有 IDE、
其他 Agent 或人工保存了文件时，操作会返回 `COMMIT_CONFLICT`，不会用旧确认覆盖新内容。本机提交使用
同目录临时文件和原子替换，拒绝跟随符号链接，并保留受支持 UTF-8 文本的 BOM、CRLF/LF 与末尾换行。

确认框的 Diff 最多预览 200 行、16 KiB，并可能受当前窗口或终端高度限制；被省略时界面会明确标记，
但仍保留允许和拒绝选项。批准授权的是同一 `PreparedFileMutation` 固定的完整拟议内容，不是当前视口
可见行。双栏/行内布局、语法高亮和纯文本降级都只是这份计划的只读展示，不能替代或放宽 Tool Call
参数指纹、Snapshot、Policy、敏感路径检查或 compare-and-replace。

提交后 Harness 会重新读取实际内容再生成 Snapshot，并只返回变更范围附近的有界内容。保存钩子或远端系统
改写了已确认内容时，操作本身仍会成功，但会附带 `POST_WRITE_DRIFT` 的已批准 `proposed_diff` 与实际
`actual_diff`；请以返回的实际 Snapshot 为准，不要直接重放旧调用。远端 backend 不能证明
compare-and-replace 时返回 `BACKEND_CAS_UNSUPPORTED`，不会先读后盲写。

若已启用本机 Plugin LSP，创建或编辑完成后 Harness 最多等待 1 秒取得只读 diagnostics 摘要；结果最多
20 项、8 KiB，仅含严重级别、短 code 和源行范围，不包含诊断正文、源码或工具参数。`unavailable`、`timeout`
和 `ok, count=0` 分别表示没有服务、检查超时和确认无诊断；它们都不回滚文件，也不会触发 formatter。显式
formatter、IDE 保存或其他外部写入会使 Snapshot stale，后续编辑必须重新读取。

这不是操作系统隔离或完整沙箱：`execute`、MCP 工具和未来自定义工具仍可能具有各自的文件访问能力，并按其审批或企业策略执行。终端状态显示“本机执行 · 未隔离”时，请仅在可信开发环境中使用。

同一 Harness 进程中，访问同一工作区的多个 Agent 图会共享工具读写锁：只读操作可以并行，
写入和未知工具会等待前一个工具完成。`task` 本身不持有非重入写锁；Inline/Managed 子 Agent
的每个实际工具调用会重新经过同一把 Host 锁，因此不会自锁，也不能绕过跨图写入串行。审批只
决定是否允许执行；批准后的写入仍会串行执行。不同工作目录通常由不同 Harness 进程承载，不会
因此互相等待；两个独立进程同时操作同一物理目录目前不提供协调。

## 代码索引不扩大权限

代码索引只在本机工作区建立 `.harness-index/`，不把私有查询服务加入用户 `/mcp` 列表。`codebase_explore` 是只读定位工具，不能代替 Snapshot `read_file`，也不能绕过目录信任、审批或文件 CAS。关闭配置并重启后不再查询，但不会自动删除已有索引。详见 [代码索引](代码索引.md)。

不要将 API Key、云凭据或其他秘密放在工作区中。模型 API Key 推荐通过环境变量提供；如必须使用明文 TOML 降级值，只能写入用户级 `~/.harness/config.toml`。macOS/Linux 上 Harness 会拒绝读取存在 group/other 权限的明文密钥文件；建议保持目录 `0700`、文件 `0600`。

## 审批模式

启动时的初始审批模式在用户配置 `~/.harness/config.toml`、显式传入的 `--config` 文件，或环境变量 `HARNESS_APPROVAL_MODE` 中设置；优先级依次为用户配置 < 显式配置 < 环境变量。当前项目目录的 `.harness/config.toml` 和 `.harness/config.local.toml` 完全不支持，检测到即要求迁移。

未配置 `[approval].mode` 时默认为 `auto`。`auto-edit` 仍会为 Shell、子 Agent 和联网弹窗；需要减少打断时使用 `auto`。

```toml
[approval]
mode = "auto"
```

`auto` 模式支持 LLM 安全分类器：默认采用当前 Run 的主模型进行安全分类；也可在 `[approval]` 中指定 `classifier` 为 `[models]` 中的某个专用 profile 名（建议小快模型）。Shell、删除、子 Agent、联网等未被规则或确定性过滤器裁决的调用会先由该模型做两阶段安全分类：明确无害的自动放行，明确危险的直接拦截（不弹窗），拿不准的仍弹窗确认。Harness 会以 10 秒超时调用且不重试。分类调用超时失败或结果无法解析时，一律回退为弹窗确认（Fail-Closed），绝不会因此自动放行。

```toml
[approval]
mode = "auto"
# 可选：指定专用小快模型，未指定时默认使用当前主模型
# classifier = "small-fast"
```

运行中可以按 `Shift+Tab` 循环切换审批模式（`plan → default → auto-edit → auto → yolo`），composer 右下角实时展示当前模式。空闲时切换作用于下一次 Run；已有活动 Run 时，CLI 通过 `run.set_approval_mode` 向 Host 提交，Host 在没有待处理 Interaction 时原子更新 Run 状态并返回单调 `revision`，随后同一 Run 的模型提示词、HITL、AUTO 分类/守卫、目录信任和子 Agent 都读取新快照。待处理审批、问答、目录信任或串行审批队列存在时返回可重试 busy；repository-level trust registry 是否已有记录不单独阻止 owner 的活动切档。RPC 失败、取消或终态竞争时保留旧模式。该选择只保留在当前会话，不写入配置文件，退出后重新启动恢复配置中的默认模式。Goal continuation 使用启动时的当前 Build 审批模式，不会自行选择更宽档位。

| 模式 | 文件编辑与普通删除 | 只读 Shell | 有副作用 Shell、敏感删除、子 Agent、联网 | 上下文压缩 |
| --- | --- | --- | --- | --- |
| `plan` | 拒绝（会话计划文件 `/.harness/plan.md` 除外） | 自动放行 | 明确会写或破坏的 Shell、删除与子 Agent 拒绝；未知 Shell 单次确认；只读联网工具可用 | 自动执行 |
| `default` | 每次确认 | 自动放行 | 每次确认 | 自动执行 |
| `auto-edit` | 工作区内自动执行 | 自动放行 | 每次确认 | 自动执行 |
| `auto` | 工作区内自动执行 | 自动放行 | 自动安全判断；破坏性命令直接拦截，拿不准或失败时回退确认 | 自动执行 |
| `yolo` | 自动执行 | 自动执行 | 自动执行 | 自动执行 |

上表描述已授权工作目录（主工作区 + 已信任额外目录）内的操作。首次访问未信任的工作区外路径时会弹出目录信任卡片；信任之后回到上表规则。`plan` 模式下唯一可写路径是会话计划文件 `/.harness/plan.md`（落到 `~/.harness/plans/<thread_id>.md`，不进工作区 Git）；`git status` 等明确只读命令可直接运行，`rm` / `touch` 等明确会改文件或破坏状态的命令会被硬拒，无法静态判断的命令只询问本次。批准未知命令不会解除 Plan 约束或切换审批档位，之后的项目写入仍会被拒。会写的 MCP、`task` 和项目内写入同样会被硬拒并说明原因。Skill 目录和只读 MCP 仍可用。除了 `/plan`，普通 Build Run 中 Agent 也可在你明确要求先规划时发起一次性进入确认；只有你允许后，同一 Run 才会开启上述限制，拒绝或客户端不支持审批时均保持原权限。见 [交互使用](交互使用.md)。

弹窗出现时可选：允许一次、本会话允许、本项目允许、拒绝、拒绝并反馈。

- **本会话允许**：规则或额外目录只记在当前进程内存，退出即失效。
- **本项目允许**：权限规则写入当前项目的 `.harness/settings.json`，对该项目后续会话持续生效。
  - **解释器命令**（`python`, `node`, `bun`, `pytest` 等）：生成解释器裸根规则，后续执行同解释器的其他脚本或测试文件自动放行。
  - **已知子命令工具**（`git`, `npm`, `cargo`, `docker` 等）：保留有效子命令生成前缀规则（如 `git commit`, `npm install`, `npm run build`）。
  - **无子命令工具**（`ls`, `cat`, `echo` 等）：丢弃后续目录/操作数参数生成根规则（如 `ls packages` 规则覆盖所有 `ls`）。
  - **危险根命令**（`rm`, `del`, `curl`, `wget`, `docker` 裸根等）：严格禁止生成裸根规则，后续仍每次弹窗。
- **只读 Shell 自动放行**：所有审批模式下，常见只读命令（Linux/macOS 的 `ls`/`cat`/`pwd`/`git status`/`git diff`，Windows 的 `dir`/`type`/`Get-ChildItem` 等）会自动放行，无需弹窗。`plan` 会硬拒明确写入或破坏状态的命令，只对无法静态判断的命令询问一次；其它模式仍按上表处理有副作用或危险参数的命令。

`additional_directories`、运行时 `directory_trust` 和 `trusted_directories` 是三层不同概念：`additional_directories` 是配置的额外可访问根；首次访问工作区外路径时，由 `WorkspaceBoundary` 发起 `interaction.directory_trust`，授予当前 session/project 的外部路径访问；`trusted_directories` 只是历史的 repository-level trust registry，活动 owner 切档不读取它，也不把它当作外部路径授权。活动 Run 的模式切换不因 workspace trust 状态 unknown/untrusted 额外拒绝；只有已经存在 pending `directory_trust` Interaction 时按通用 busy 规则暂不能切换。已进入不可逆计划约束的 Run 不能切出 `plan`，计划中的项目写入、会写 Shell、`task` 和未声明只读的 MCP 仍由执行层硬拒绝。

`auto` 的安全分类只对当前 Run 与子代理 execution 生效；不同任务即使底层模型复用了相同的工具调用 ID，也不会共享旧的分类结论或连续拒绝计数。一次调用在模型后处理、审批预检和执行守卫之间复用的是同一 Run 内的结果。

## 目标闭环不扩大权限

`/goal` 只约束“怎样才算完成”，不改变 EffectivePolicy、Sandbox、工作区 roots 或审批规则。主 Agent 继续按当前 Build 审批模式工作；Criteria 草案在所有模式下都必须人工确认，Auto/YOLO 也不能自动接受。

独立 grader 只能使用当前主 Agent 工具的只读子集，外加受控的 `rerun_verification`：只能重跑本 Run 已经执行过、且通过安全分类的 exact command，不能注入任意命令字符串。重跑仍走当前审批；一次性批准不会升级为永久 allow。Goal 内容、grader 提示和工具结果都按不可信数据处理，不会自动生成 allow rule。

## Compose 模式不提权

Compose 工作模式改变的是**流程**，不是**权限**：

- 阶段 Agent 与主 Agent 使用同一份模型、Policy、Skill 与 MCP 快照；Compose、提示词或方法资产都不能放宽 EffectiveExecutionPolicy，也不能让模型自行宣称进入下一阶段。
- 验证命令只通过与 Agent 相同的执行后端运行，继续经过既有 Policy、审批、工作区边界、沙箱与并发锁；被策略拒绝或你拒绝的命令不会执行，也不存在降级到宿主机旁路的路径。
- 两个评审角色（需求/代码）使用只读能力视图，不能写文件、执行命令或委派。
- 方案确认不是工具授权：批准计划只推进流程，实际文件/Shell/网络/MCP 操作仍按审批模式逐次弹窗。
- 验证命令输出只保留有界摘要与摘要指纹；凭据形态会被脱敏，不写入审计 artifact。

## Compose 执行可见性与审计边界

Compose 只展示 Harness 已真实观测到且确认可公开的执行事实，可见性与权限收紧相互独立：

- 模型处理状态、可公开的思考摘要、工具执行、审批与验证命令按真实顺序展示，并带有阶段 / 任务 / Agent / attempt 归属；隐藏 chain-of-thought、加密 reasoning 与未知 provider 字段不展示。
- 原始 artifact JSON、完整工具输出、Prompt 与 ContextPack 不进入界面、日志、根 Transcript 或恢复记录；阶段摘要只由系统基于已校验结果生成，模型不能借摘要通道绕过字段白名单。
- 工具参数与结果在运行期经过有界截断与脱敏；界面只显示工作区相对路径，scope 不包含绝对路径或内部 Agent 配置。
- Thread 重新打开时恢复的是有界审计摘要（阶段、任务、工具终态、验证与评审结论），不恢复思考过程、原始工具内容或内部产物；记录达到 500 条或 1 MiB 上限后停止追加并明确显示截断，不会悄悄丢弃或伪装完整。

## Agent 与 Policy 文件

当前版本不从 `~/.harness/` 或项目 `.harness/` 读取 Agent/Policy 文件，主 Agent 由内置 Python
代码构建，不能被配置替换。只有经过复制安装、内容校验、能力指纹确认和启用的 Plugin 才能提供
可派发子 Agent；Plugin Agent/Policy 已进入相同的只收紧解析链。Plugin Agent 资产不能内联
API Key、endpoint、Header、Shell Hook 或任意 Python 工厂，模型连接仍只能在用户级
`config.toml` 的 `[models]` 中配置。

每个角色在构图前都会得到一份不可变的“有效能力视图”。它由宿主硬边界、父 Agent 可委派范围和目标角色 Policy 取交集产生，只能缩小权限。该视图同时决定模型能看到的工具、可读取的 Skill、可调用的 MCP 工具，以及工具执行入口最终会放行什么。即使 Prompt 或伪造的 tool call 请求了未显示的写文件、Shell 或 MCP 工具，执行入口也会直接拒绝。

Policy、审批和 sandbox 解决的是三件不同的事：

- Policy 决定某个角色最多可以使用哪些能力，不能通过审批扩大；
- 审批决定已获 Policy 授权的高风险操作是否还需要用户确认；
- sandbox 决定进程和文件系统是否真正与宿主隔离。

因此，只读角色即使运行在 `yolo` 模式也不能写文件；而一个允许写入但处于 `default` 模式的角色仍要等待审批。本机模式下的角色 Policy 仍不是操作系统沙箱。

子 Agent 委派同样受 Policy 与审批控制。模型只能请求目标 Agent ID 和任务，不能指定 Inline/Managed、任意模型或额外工具。Harness 会检查 allowedAgents、最大深度（固定为 1）和并发数（硬上限 4，超额自动排队）；父 Run 取消、子超时或异常会取消 child execution，并释放实际取得的并发槽位与 AgentEngine/resource lease。子代理审批遵循**不得比父更松**原则：仅当父处于 `default` 模式时，内置 `general-purpose` 内部按 `auto-edit` 运行（工作区内常规写入不弹窗，命令执行与敏感路径仍弹窗）；Plugin 子代理不得通过定义放宽审批（声明 `permissionMode: yolo` 不生效），且需要交互时保持 fail closed。

`plan` 只允许 `ls`、`read_file`、`glob`、`grep`、`ask_user` 和 `write_todos`。写入、`execute`、`task` 以及未识别的未来 MCP 工具都会直接返回拒绝结果，不会弹出审批框。

Harness 还提供只读的 `/.harness/` 逻辑命名空间。它不是本机文件路径：只有 `read_file` 可以按页读取 Skill 正文、Skill 资源或本 thread 已归档的历史；`write_file`、`edit_file`、`ls`、`glob`、`grep` 和 shell 命令都会被拒绝。该路径不会泄露 Skill 的宿主目录或 SQLite 文件位置。

`yolo` 只关闭 Harness Code 自身的人工确认。外部路径会自动授予会话级额外工作目录，但仍不能注册系统目录或绕过 Shell 白名单、远端 sandbox provider 与企业安全策略。旧值 `ask` 会兼容为 `default`；未配置时默认为 `auto`；未知值安全降级为 `default`，TUI 会显示对应提示。

## Plugin 子进程边界

安装 Plugin 不会执行代码；安装结果默认 disabled。只有用户确认当前
`capability_fingerprint` 并启用后，Plugin MCP、Claude command Hook、stdio LSP 和 Monitor
才会在下一次 Host 启动进入运行快照。package 内容或声明能力改变后指纹也会改变，旧确认不能
沿用。

这些进程使用仅包含 `PATH`、临时目录、locale 和必要 Plugin 占位符的最小环境，不继承模型
API Key 或任意 Harness 环境变量。Hook stdin/stdout/stderr、Monitor 单行与缓冲行数、LSP
文档和请求均有大小或时间上限；超时、协议损坏和输出溢出会停止对应进程或拒绝本次操作。
Host 关闭时会终止其持有的整个子进程组。

`PreToolUse` command Hook 可以在 Tool Policy 已允许后进一步拒绝执行，但不能扩大 Policy。
Monitor stdout 会用“不可信 Plugin 数据”边界注入模型上下文，不能当成系统指令。LSP 只能读取
当前工作区内、由 Harness 显式发送的文档。以上限制属于 Harness 进程级防护，不是操作系统
sandbox；只应启用来源可信的 Plugin。

## 交互式配置修改边界

当前没有可直接编辑任意 TOML 的 `/config set` 命令。后续 Settings/Permissions Manager 仅能修改用户级配置中的默认模型、审批模式、执行后端和 AgentEnginePool 白名单字段；写入前会校验完整配置、并发版本和企业策略锁，失败时不会覆盖原文件。API Key、认证 Header、环境变量、模型服务地址和远端 Provider factory 始终不可通过交互界面修改。

如果环境变量、`--config` 或企业 managed policy 覆盖了某个字段，界面会显示不可修改原因。项目内 `.harness/config.toml` 即使被显式选择，也不能作为交互式写入目标。

启用 Shell 白名单的集成只接受可可靠解析的单一命令。管道、重定向、`&&` / `||`、分号、命令替换、反引号、换行和畸形引号都会在执行前被拒绝。绝对可执行文件路径必须以完整路径显式加入白名单，不能仅凭同名文件匹配。白名单限制的是启动的程序和 Shell 组合语法，不分析获准程序自身参数的业务语义，也不等同于命令沙箱。

## 启用企业远端沙箱

企业提供远端 sandbox 插件后，在用户配置 `~/.harness/config.toml` 或用户明确传入的 `--config` 文件中设置：

```toml
[approval]
mode = "default"

[execution]
backend = "remote"

[execution.remote]
provider = "corp"
factory = "harness_corp_sandbox:create_backend"
working_directory = "/workspace"

[execution.remote.params]
project = "your-enterprise-project"
```

也可以单次执行：

```bash
za38 --sandbox
HARNESS_SANDBOX=true harness
```

远端 provider 负责认证、工作区同步、网络策略和生命周期，并必须实现 deepagents 的 `SandboxBackendProtocol`。沙箱不可用时命令会失败，不会自动回退到本机执行。

`sandbox.params` 只传递非秘密 provider 参数；认证信息必须由企业身份机制或环境变量处理，不得写入 TOML。

当前不提供 Docker、Podman 或本机容器 sandbox。企业网络白名单由远端 provider 管理。
