# 日志与诊断

Harness Code 内置了本地优先、低流量、结构化的异步诊断日志体系。它在 CLI 和 Python sidecar 中自动记录生命周期事件、执行结果与关键耗时，帮助开发者事后排查故障与分析性能。

诊断日志是完全单向的本地可观测性数据，独立于会话恢复数据库（SQLite），既不参与业务状态重建，也不会向任何远程服务上传遥测。

## 日志存储位置与文件

日志文件按执行日期分目录存放在用户主目录下：

| 操作系统 | 默认存储路径 | 权限要求 |
| --- | --- | --- |
| macOS / Linux | `~/.harness/logs/<YYYY-MM-DD>/` | 目录 `0700`，文件 `0600` |
| Windows | `%USERPROFILE%\.harness\logs\<YYYY-MM-DD>\` | 当前登录用户访问控制 |

### 文件命名与生命周期

CLI 与 Python Agent 在各自进程中独立写入文件，互不竞争文件锁：

- **正在写入的活跃文件**：以 `.active.jsonl` 结尾（例如 `cli-41230-1787800000000-0001.active.jsonl`、`agent-41231-1787800000456-0001.active.jsonl`）。
- **已关闭的归档文件**：在进程正常退出或触发容量轮转时，文件会被先关闭并重命名为标准 `.jsonl`（例如 `cli-41230-1787800000000-0001.jsonl`）。
- **孤儿活跃文件（Orphan Active）**：若进程被异常强杀（如 `kill -9`），未关闭的 `.active.jsonl` 会保留。查询工具会自动安全读取其中的有效数据并在诊断统计中提示，但容量回收策略绝不会误删或重命名可能仍在被写入的文件。

### 轮转与清理（Retention）

- **保留时间**：默认保留 **14 天** 内的日志文件。
- **总量上限**：默认总大小上限为 **200 MiB**。
- **单文件上限**：单个日志文件达到约 **16 MiB** 时自动关闭并开启新分片。
- **清理原则**：只有已关闭的 `.jsonl` 文件才会被清理；正在写入的 `.active.jsonl` 永不触碰。

## 配置与级别控制

诊断日志支持在用户级配置文件 `~/.harness/config.toml` 中持久配置，或通过环境变量临时覆盖。

### 配置文件 `[diagnostics]`

```toml
[config]
version = 1

[diagnostics]
# 日志级别：可选 "debug" | "info" | "warn" | "error"，默认为 "info"
level = "info"

# 历史日志保留天数（默认 14 天）
retention_days = 14

# 日志目录总容量上限（单位 MiB，默认 200）
max_total_mib = 200

# 单个日志文件分片容量上限（单位 MiB，默认 16，不得大于 max_total_mib）
max_file_mib = 16
```

修改配置文件后，在下次启动 Harness 时生效（`applies_to = "restart"`）。

### 环境变量临时覆盖

需要临时开启详细调试时，可使用 `HARNESS_LOG_LEVEL` 环境变量，其优先级高于配置文件：

```bash
# 临时开启 DEBUG 级别启动
HARNESS_LOG_LEVEL=debug npm run dev
```

### 级别语义

- `info`（默认）：记录进程启动/关闭、Run 开始与终态、模型轮次耗时、工具执行状态、MCP 连接、Skill 读取、Hook 执行与上下文压缩。
- `debug`：增加状态机流转、资源池（Runtime Pool）快照、模型重试决策、脱敏异常栈与诊断详细信息。
- `warn` / `error`：记录队列溢出丢弃、写入降级、执行异常与终态失败。

## 安全与脱敏红线

Harness 诊断日志执行严格的脱敏策略，在**任何级别（包括 DEBUG）**下均遵守以下安全红线：

1. **零业务正文**：不记录 Prompt、LLM 补全正文、源码内容、完整工具入参与返回结果。
2. **零凭据泄漏**：不记录 API Key、Token、认证 Header、密码、环境变量值或 Secret。
3. **零工作区绝对路径**：工作区以不可逆的 64 位 SHA-256 指纹（`project_fingerprint`）关联，日志中不出现用户磁盘目录全路径。
4. **零协议原帧**：不记录原始 JSON-RPC 帧或网络请求全文。

所有记录均通过闭合白名单 Schema 严格校验，任何包含多余未声明属性或格式不合规的记录都会被拒绝入队。

## 离线查询工具（`harness logs`）

`harness logs` 是完全离线的日志分析工具。它直接读取本地日志文件，**不启动 Python sidecar**，**不访问 SQLite 数据库**，查询自身也**不写入新日志**。

### 1. 查看当前工作区最近 Thread 列表

默认列出当前工作区最近 20 个 Thread：

```bash
# 开发模式
npm run dev -- logs

# 已安装命令
harness logs
```

输出展示 Thread ID 前缀、最后活动时间、执行 Run 次数、最近结果与总耗时。

### 2. 查看 Thread 完整中文过程树（推荐主视图）

使用 `--thread` 参数指定 Thread ID 或唯一前缀，合并展示该 Thread 下的所有 Run 与准备层事件：

```bash
harness logs --thread <thread-id-or-prefix>
```

**展示结构**：
- **摘要**：Thread 最终状态、Run 数量、有效耗时口径。
- **失败点**（如有）：清晰指出哪一步失败及原因。
- **准备层**：列出当前进程连接的 MCP 服务（如「MCP github 已连接」）。
- **历史 Run 折叠**：早期 Run 简要汇总折叠为单行。
- **最近一轮 Run 过程树**：层级展示模型交互、工具调用、Skill 读取、Hook 触发、子代理与上下文压缩。
- **慢项统计**：列出耗时排名前 5 的操作。

### 3. 放大查看单次 Run

如果只想精细分析某一次特定的 Run，使用 `--run` 参数：

```bash
harness logs --run <run-id-or-prefix>
```

> **注意**：`--thread` 与 `--run` 互斥，不能同时指定。

### 4. 过滤与条数限制

可配合过滤参数缩小排查范围：

```bash
# 只查看 WARN 及以上级别
harness logs --thread <prefix> --level warn

# 只查看工具相关事件
harness logs --thread <prefix> --event tool

# 只查看 Python Agent 产生的日志
harness logs --thread <prefix> --component agent

# 自定义单页条数（默认 200，支持 1～1000）
harness logs --thread <prefix> --limit 50
```

多过滤条件之间按 **AND** 逻辑组合生效。

### 5. 平铺表格视图与 Cursor 分页（`--flat`）

默认树形视图在遇到 200 条或 256 KiB 截断保护时，不会在树中间粗暴切断，而是给出切换 `--flat` 的提示。

使用 `--flat` 参数可将选中的 Thread 或 Run 输出为按时间正序对齐的逐事件中文表格：

```bash
harness logs --thread <prefix> --flat --limit 50
```

表格列包含：`时间`、`级别`、`来源`、`EVENT`、`详情`、`耗时`。

当表格输出被截断时，底部会生成一个受保护的 `--cursor` 续页命令：

```bash
harness logs --thread <prefix> --flat --cursor <token>
```

- **Snapshot 一致性**：Cursor 绑定首次查询时的日志快照。翻页期间即便有新日志写入，也不会导致重复记录或遗漏。
- **安全校验**：如果关联日志文件被清理或修改了过滤条件，系统会给出 `CURSOR_EXPIRED` 或 `CURSOR_MISMATCH` 明确错误，拒绝猜测位点。

### 6. 机器可读 JSON 输出（`--json`）

需要通过脚本或 CI 工具进行自动化分析时，使用 `--json` 输出结构化对象：

```bash
harness logs --thread <prefix> --json
harness logs --run <prefix> --json
```

JSON 输出包含 `query_schema_version: 1`、`summary` 耗时与状态、`events` 数组、`matched_count`、`returned_count`、`truncated`、`next_cursor` 以及异常日志诊断计数（`diagnostics`）。
