# 日志与诊断

> **适用范围**：本文说明可选 **Harness Python ACP Agent** 内核（`agent/`）的本地异步诊断日志与会话链路 Trace；通用桌面工作台及其他 ACP Agent 不依赖此日志系统。原独立 CLI / TUI / `/web` 入口已退役。

Harness Code Python 内核内置了本地优先、低流量、结构化的异步诊断日志体系，在 Agent 进程中自动记录生命周期事件、执行结果与关键耗时，帮助开发者事后排查故障与分析性能。

诊断日志是完全单向的本地可观测性数据，独立于会话恢复数据库（SQLite），既不参与业务状态重建，也不会向任何远程服务上传遥测。

## 日志存储位置与文件

日志文件按执行日期分目录存放在用户主目录下：

| 操作系统 | 默认存储路径 | 权限要求 |
| --- | --- | --- |
| macOS / Linux | `~/.harness/logs/<YYYY-MM-DD>/` | 目录 `0700`，文件 `0600` |
| Windows | `%USERPROFILE%\.harness\logs\<YYYY-MM-DD>\` | 当前登录用户访问控制 |

### 文件命名与生命周期

Python Agent 内核在自身进程中独立写入诊断日志：

- **正在写入的活跃文件**：以 `.active.jsonl` 结尾（例如 `agent-41231-1787800000456-0001.active.jsonl`）。
- **已关闭的归档文件**：在进程正常退出或触发容量轮转时，文件会被先关闭并重命名为标准 `.jsonl`（例如 `agent-41231-1787800000456-0001.jsonl`）。
- **孤儿活跃文件（Orphan Active）**：若进程被异常强杀（如 `kill -9`），未关闭的 `.active.jsonl` 会保留。查询工具会自动安全读取其中的有效数据并在诊断统计中提示，但容量回收策略绝不会误删或重命名可能仍在被写入的文件。

### 轮转与清理（Retention）

- **保留时间**：默认保留 **14 天** 内的日志文件。
- **总量上限**：默认总大小上限为 **200 MiB**。
- **单文件上限**：单个日志文件达到约 **16 MiB** 时自动关闭并开启新分片。
- **清理原则**：只有已关闭的 `.jsonl` 文件才会被清理；正在写入的 `.active.jsonl` 永不触碰。

## 会话链路 Trace JSONL

会话链路追踪用于还原一次 Run 内模型、图节点、工具、审批、策略、SQLite 与上下文处理的调用关系。它与上述 Diagnostic Log 是两套独立数据：诊断日志仍位于用户主目录，Trace 则写入**当前工作区根目录**的 `log/`，不参与会话恢复，也不改变现有 Transcript 或 Checkpoint。

- 一个 Thread 对应一个 session，使用现有 `thread_id` 作为 session 标识。
- 每次 Run 对应一条 Trace；同一 session 的多次 Run 追加到同一文件，以不同 `trace_id` 区分。
- 文件名为 `log/<安全-session-名称>-<session-摘要>.jsonl`，可避免目录穿越和同名碰撞。
- 文件采用 UTF-8 JSONL，每行是一个完整 JSON 对象；写入失败只产生有界诊断，不影响 Run、审批或持久化结果。

### 统一事件与字段

Trace 中只有 `trace.start`、`trace.end`、`span.start`、`span.end` 四类事件。图内 LangChain/LangGraph 回调和图外业务埋点共用相同结构：

- 公共关联：`schema_version`、`event`、`timestamp_ms`、`session_id`、`trace_id`、`run_id`。
- 调用关系：`span_id`、`parent_span_id`、`name`、`kind`，可按 Trace 分组并重建调用树。
- 时间与结果：`start_time_ms`、`end_time_ms`、`duration_ms`、`status`；失败时可包含有界的错误类型和状态信息。
- 业务字段：仅包含各埋点白名单允许的 `attributes`；提供稳定业务身份时可包含 `idempotency_key`，用于抑制 replay 或重复结束产生的重复 Span。

图内 `kind` 包括 `LLM`、`AGENT`、`NODE`、`TOOL`、`RETRIEVER`；根 Trace 使用 `ROOT`。本期不记录逐 Token 日志。

### 十二个图外标准 Span

| Span | kind | 用途与主要安全字段 |
| --- | --- | --- |
| `run.prepare` | `FUNC` | 受理前准备；`mode`、`outcome` |
| `run.accept` | `FUNC` | Run 受理；`mode`、`outcome` |
| `run.execute` | `FUNC` | Managed Agent 实际执行边界；`mode`、`outcome` |
| `runtime.acquire` | `FUNC` | Runtime 排队与构建；`source`、`queue_ms`、`build_ms`、`outcome` |
| `runtime.release` | `FUNC` | Runtime 释放；`outcome` |
| `run.complete` | `FUNC` | Run 终态收尾；`status`、`duration` |
| `interaction.wait` | `INTERACTION` | 审批或提问的真实等待区间；`phase`、`outcome` |
| `policy.evaluate` | `POLICY` | 权限决策；`decision` |
| `policy.classifier` | `POLICY` | Plan Shell 命令分类结果；`decision` |
| `thread.persist` | `DB` | 真实 SQLite 事务；`operation`、`outcome` 及真实计数或序号 |
| `context.project` | `CONTEXT` | 模型上下文投影；`matched`、`count` |
| `context.compact` | `CONTEXT` | 上下文压缩计算；`matched`、`compressed`、`status` |

`thread.persist` 的 `operation` 包括 `accept_run`、`transcript`、`transcript_batch`、`run_complete`、`context_commit`。内存中的 Transcript 排队不计为 SQLite 写入；压缩计算与 `context_commit` 落库分别计时，事务失败不会被记录为提交成功。

### 扩展埋点

新的图外函数通过统一的 `@func_monitor` 接入，声明稳定的点分 `name`、合适的 `kind`、白名单 `attributes` 和可选 `idempotency_key` 即可，无需增加 writer 分支或新的事件格式。跨异步任务无法自动继承上下文时，需要显式传递已绑定的 Trace 上下文。

### 脱敏边界与本期范围

Trace 默认不记录完整 Prompt、模型回复、源码、工具参数或结果正文、检索文档、审批 payload、命令正文、SQL 与绑定参数、API Key、Cookie、环境变量值或工作区绝对路径。埋点异常不得写入 sidecar stdout，也不得改变业务终态。

本期只交付 JSONL 数据，不新增 HTML 或终端 Trace 树；在独立桌面端，Harness 轨迹与专有设置扩展由后续 `HC-201` 接入 `@workbench/harness-acp`。排障时可直接逐行读取 `~/.harness/logs/` 与 `log/*.jsonl` 中的脱敏 JSONL 记录。

## 配置与级别控制

诊断日志支持在用户级配置文件 `~/.harness/config.toml` 中持久配置，或通过环境变量临时覆盖。

### 配置文件 `[diagnostics]`

```toml
[config]
version = 1

[diagnostics]
# 日志级别：可选 "debug" | "info" | "warn" | "error"，默认为 "info"
level = "info"

# 历史日志保留天数（默认 14 天）
retention_days = 14

# 日志目录总容量上限（单位 MiB，默认 200）
max_total_mib = 200

# 单个日志文件分片容量上限（单位 MiB，默认 16，不得大于 max_total_mib）
max_file_mib = 16
```

修改配置文件后，在下次启动 Harness 时生效（`applies_to = "restart"`）。

### 环境变量临时覆盖

需要临时开启详细调试时，可在拉起 Harness Agent 前设置 `HARNESS_LOG_LEVEL` 环境变量，其优先级高于配置文件：

```bash
# 临时开启 DEBUG 级别收集详细 Agent 诊断
HARNESS_LOG_LEVEL=debug npm run dev
```

### 级别语义

- `info`（默认）：记录进程启动/关闭、Run 开始与终态、模型轮次耗时、工具执行状态、MCP 连接、Skill 读取、Hook 执行与上下文压缩。
- `debug`：增加状态机流转、资源池（Runtime Pool）快照、模型重试决策、脱敏异常栈与诊断详细信息。
- `warn` / `error`：记录队列溢出丢弃、写入降级、执行异常与终态失败。

## 安全与脱敏红线

Harness 诊断日志执行严格的脱敏策略，在**任何级别（包括 DEBUG）**下均遵守以下安全红线：

1. **零业务正文**：不记录 Prompt、LLM 补全正文、源码内容、完整工具入参与返回结果。
2. **零凭据泄漏**：不记录 API Key、Token、认证 Header、密码、环境变量值或 Secret。
3. **零工作区绝对路径**：工作区以不可逆的 64 位 SHA-256 指纹（`project_fingerprint`）关联，日志中不出现用户磁盘目录全路径。
4. **零协议原帧**：不记录原始 JSON-RPC 帧或网络请求全文。

所有记录均通过闭合白名单 Schema 严格校验，任何包含多余未声明属性或格式不合规的记录都会被拒绝入队。

## 本地日志文件结构与检索参考

原旧版 `harness logs` CLI 离线查询命令已随 `packages/cli` 退役；日常排查可直接读取 `~/.harness/logs/<YYYY-MM-DD>/*.jsonl`（或按 `thread_id` / `run_id` / `level` / `event` 过滤 JSONL 行），其中的事件字段满足上述脱敏规范与 `query_schema_version: 1` 兼容字段约定。
