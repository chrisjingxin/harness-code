# 独立桌面工作台

正式窗口采用「56px 固定全局图标栏（Rail）+ 304px 双模次级侧栏 + 居中主舞台 + 可选右侧文件工作区」双层架构：56px Rail 顶置「工作台」「Inbox」「Project 看板」「团队知识」4 个核心入口，底部提供全局搜索（`⌘K` / `Ctrl+K`）、「管理与设置」与左下角个人头像弹出菜单（`UserPopover`，一键切换跟随系统/浅色/深色主题、直达设置或退出）。登录后无需先加入团队即可直接在个人空间开启本机对话，接入团队后按 Workspace 与 Project 组织协作会话、跨团队待办、融合看板与团队知识库。会话目录、本机只读文件、跨机器简报与主动正文同步已按 [HC-218](../developer/task/HC-218-会话只读与主动同步.md) 接入。研发可显式初始化和启动 Java 协作服务。[仓库启动说明](../../README.md#显式启动-java-数据基础)

首版按内网每人一台设备设计：本人会话在本机选择工作目录后可执行，他人会话只读已上传材料，不提供远程文件或远程执行。当前不需要设备登记或设备凭据；同账号第二台设备的识别不属于本期范围。

从仓库根目录 `npm ci` 后运行 `npm run dev`。已经构建时也可 `npm --workspace @workbench/desktop run preview`。

## 部署并连接现有远端服务

以下命令面向已经配置好 `collaboration-server.service` 的 Linux 服务器。本机需要 Node.js、JDK 21、Maven 和 OpenSSH；服务器需要 Python 3.11 或更新版本、PyYAML、systemd，以及当前 SSH 用户无需交互即可重启该服务的权限。先用 `ssh 用户@服务器` 确认主机指纹并配置 SSH 密钥；不要把服务器密码放进命令或仓库。

```sh
# 只检查现有服务、消息模式及数据库脚本，不构建或重启
npm run server:deploy -- 用户@服务器 --check

# 构建并部署本地 Java 服务
npm run server:deploy -- 用户@服务器

# 使用指定服务地址启动桌面；地址只填协议、主机和端口
npm run dev:remote -- https://中继服务地址
```

部署命令复用现有服务构建，上传前核对服务器的 `schema.sql` 与本地文件；上传后校验程序、备份旧 JAR，重启并检查 `/health`。新程序无法正常启动时会尝试恢复旧 JAR。命令不安装数据库、不修改服务配置或数据库结构，也不自动备份数据库；脚本文件一致不代表已验证实际数据库结构。

当前服务为 `standalone` 时，共享会话正文保存在服务进程内存中，重启会丢失；命令默认拒绝部署。只有明确接受这部分演示数据丢失时，才可在部署命令末尾加入 `--allow-memory-loss`。切换存储模式前需先处理已有消息并验证恢复；即使配置为 `cluster`，也要单独验证 Redis、Kafka 和 Elasticsearch 的持久化与恢复，不能仅凭 MySQL 已运行或模式名称认定正文可靠保存。

`dev:remote` 使用现有的 `WORKBENCH_SERVICE_ORIGIN` 接入点并启动正常桌面，不保存地址中的账号或密码。远程 HTTP 不加密；当前演示登录也不是正式身份认证，公网环境应先配置受信任的 HTTPS 和正式身份方案，再用于敏感数据。

## 个人优先双轨工作台（HC-239）

桌面工作台现采用「个人 | 团队」双轨导航，登录后即可使用本机 ACP Agent，不再强制先加入团队或等待服务在线：

- **登录即用与断网续用**：已登录账号即使尚未加入任何团队（或暂无法连接协作服务端）也能直接进入工作台。服务端不可用时，顶栏显示离线提示并提供「重连」按钮，个人会话可继续在本地新建和对话。
- **本机 Agent 连通性预检**：本机 ACP Agent 正常就绪时，首页保持极简零打扰；仅当无可用本机 Agent 时在新建会话准备页提示异常与「重新检测 / 本机 Agent 设置」。完整 Provider 状态清单与「重新检测」入口收口在「管理与设置 → 本机 Agent」中。
- **个人空间按工程目录组织、团队空间按 Project 组织**：
  - 左侧切换至「个人」后展示全部本机个人会话（以及已停止共享后切回本地的会话），按本机工程目录折叠分组（不区分团队或无团队），不进入任何 Project 简报或队友视图；
  - 在「个人」或「团队」个人会话行上右键点击（或点击悬停显示的「…」）可打开上下文菜单执行「重命名」（居中弹窗编辑）、「发布到 Project…」或「停止共享」；
  - 切换至「团队」后按 Workspace 切换团队并按 Project 折叠分组浏览协作会话，点击 Project 行可切换并展开该项目的本人及队友会话，右侧齿轮按钮可直达 Project 资料与成员管理。
- **整理个人会话（HC-257）**：个人会话行上右键（或点击「…」）还可以：
  - **置顶 / 取消置顶**：置顶的会话集中显示在个人栏最上方的「置顶」区，不再出现在原目录分组里，也不会改变会话的更新时间；
  - **归档 / 取消归档**：归档后会话移入个人栏底部默认折叠的「已归档 (n)」区，需要时点「取消归档」回到原目录分组；向已归档会话继续发送消息并完成一轮，会自动恢复。归档的会话仍保留全部内容。已发布且仍在共享中的会话请在「团队」空间处理；
  - **删除**：只对尚未发布过的纯本机会话开放，确认后会清除本机的对话记录、草稿、待发消息和代码检查点，**不会删除磁盘上的工程目录**，且无法撤销。已停止共享的会话在团队侧仍有记录，暂时只能归档，删除按钮置灰并说明原因；
  - **复制为 Markdown**：把已完成的对话按「用户 / 助手」顺序复制到剪贴板，不含工具调用输出，附件只写文件名；
  - **复制目录路径 / 在文件管理器中显示**：针对会话绑定的工作目录；目录被移走时会提示「目录不存在或已被移动」；
  - 正在运行或等待确认的会话不能归档或删除，请先停止。
- **整理工程目录分组（HC-257）**：悬停目录分组标题，点击右侧「…」可以「在此目录新建会话」（自动带上该目录和最近使用的 Agent）、复制目录路径、在文件管理器中显示、**归档整组**或**删除整组会话**。整组操作逐条执行，会跳过运行中、已停止共享（仅限删除）的会话，并在结束后提示成功、跳过与失败的数量；整组删除需勾选「我已了解，不会删除磁盘目录」才能确认。
- **搜索已归档会话**：个人栏搜索框默认只匹配未归档的会话；存在已归档会话时，搜索框右侧会出现「含已归档」开关，打开后已归档会话也参与搜索。
- **发布到 Project**：在个人会话顶部点击「发布到 Project…」（或右键菜单选择），可从当前账号已加入团队的活跃 Project 中选择目标并决定档位：
  - **完整正文**：同步后续已定稿轮次正文，并可勾选将已定稿历史轮次（可选择从第几轮起）分批补传至团队；
  - **仅共享状态与成果摘要**：只向团队分享状态与可编辑成果摘要，隐藏完整过程正文，队友侧显示「仅共享状态与成果摘要」且不提供正文同步按钮；
  - 确认不可收回说明并发布后，左侧自动切至「团队」空间并停留在当前会话，后续回复会在同一原生会话内继续按档位同步。
- **停止共享**：对已发布的协作会话可在头部或右键菜单点击「停止共享」，确认后不再上传新轮次或摘要，界面切回「个人」空间继续本地使用；队友侧与 Project 看板保留此前已上传内容为只读，并明确标注「已停止同步」。

「设置」包含窗口外观和演示身份。个人视图记录已升级至 `personal-view-v2`。上次团队按账号保存，当前项目与左右栏偏好按账号与团队保存，各项目当前页面、选中会话、新会话草稿与待选目录、单会话正文缓存与右侧文件页签（`sessionWorkspace`）按账号、团队与项目/会话保存。关窗后重新登录并确认团队/项目访问权限，才能恢复这些个人选择（旧版设备导航记录不迁移）。

Markdown 文件预览复用对话的安全渲染：标题、列表、表格与代码块会排版，原始 HTML 按文字显示，图片显示替代文字，相对链接不打开。源码和预览只读取已打开的本机文件，不会自动加载其他文件或网络图片。

在本人本机会话中，可点击 Agent 消息和工具详情里的文件引用，在会话旁打开只读预览。只有文件名时会在当前工作目录查找；有同名文件时选择完整路径。来自其他设备的只读会话不会打开本机文件。

## 项目看板、任务抽屉与轻量通知

点击 56px Rail 的「Project 看板」入口，次级侧栏会自动收起并展示 `1200px` 居中的融合看板（已合并原项目任务视图，[HC-255](../developer/task/archive/HC-255-工作台双层交互原型落地.md)）：

- **视角与范围切换**：顶部工具栏支持在「状态四列」与「成员进展」之间切换，并提供当前团队 Project 下拉切换；「状态四列」严格对应后端真实状态 **待接收（`todo`）**、**进行中（`doing`）**、**待验收（`review`）** 与 **已完成（`done`）**，支持「全部任务 / 指派给我 / 我发布的」范围筛选与「已取消」归档展开。本人待接收任务卡片可直接点击「接收任务」。
- **右侧滑出任务详情抽屉（`.t-drawer`）**：点击任意任务卡片（或通过 Inbox「在看板查看」、`⌘K`、`workbench://open/task?...` 深链接进入）时从右侧滑出详情抽屉（支持遮罩点击与 `Esc` 关闭），完整承接任务说明编辑、状态流转（接收/提交验收/通过/退回/取消）、关联已有本机会话或选目录「在本机开始」、固定快照/知识预览与流转历史。从收件箱跳转打开抽屉时，顶栏保留「返回收件箱」按钮。
- **成员进展与实时通知**：切至「成员进展」可查看各成员在线状态、接收/发起任务统计及每条共享会话的简报、最近上传时间与本机正文同步状态，点击会话条目直接定位回「工作台 → 团队」对应会话阅读或主动同步；工具栏右侧状态徽标实时显示轻量通知连接状态，断开时可手动点「刷新」重新同步。

## 全局待办收件箱、本机待确认提醒与外部轻通知（HC-246）

56px Rail「工作台」下方始终置顶 **Inbox** 入口，以 `1200px` 宽屏双栏审阅模式跨团队汇总当前账号需要拍板的异步任务，并与本机待确认会话严格隔离：

- **双栏主从审阅与角标分离**：
  - 红色数字角标仅统计跨团队处于 **待接收（`todo`）** 与 **待验收（`review`）** 的任务（含原发起人离开团队后由项目负责人代管验收的任务），`进行中（doing）` 不计入待拍板角标；
  - 收件箱顶部提供「待我处理」「我发起的」「已处理（近 30 天）」分段切换、类别与团队筛选，双栏审阅详情使用统一状态徽标并支持直接「接受任务」「通过验收」「退回修订」「取消任务」，也可点击「在看板查看」直达所属 Project 看板并滑出 `.t-drawer` 任务详情抽屉，通过顶栏「返回收件箱」一键返回。
- **方案 A 本机等待确认置顶隔离**：
  - 当后台有非当前查看的本机个人或项目会话处于权限审批、计划（Plan）确认、目标（Goal）确认、问题待答或执行出错时，Rail 的 Inbox 入口独立显示琥珀色提醒，收件箱顶部动态浮现「本机等待你确认」提醒条；
  - 点击「回到会话处理」直接切回原会话现场决策，不在收件箱内直接盲批；本机等待状态永不混入云端角标、不上云也不发送外部通知。
- **管理台「通知与提醒」与企业自研 IM 扩展**：
  - 在 56px Rail「管理与设置 → 通知与提醒」可配置外部 IM 轻通知总开关、触发事件（新任务指派、提交待验收、验收退回修订）、跨午夜免打扰时段（如 `22:00 ~ 次日 09:00`）与同项目合并窗口（默认 60 秒；窗口期内已在工作台处理完毕会自动取消外发）。
  - 企业内部接入自研 IM 时，后端仅需实现 `ExternalNotificationChannel`（以及可选的 `ExternalRecipientResolver`、`DeepLinkBuilder`）并在服务端启用 `workbench.notifications.external.enabled=true` 与 `channel=<通道名>`；外发消息强制经 `SafeNotificationBuilder` 白名单脱敏，严禁发送会话正文、代码片段或文件路径。
- **单实例唤醒与安全 Deep-Link**：
  - 正式桌面端启动后注册 `workbench://` 协议与单实例锁；外部点击通知卡片传入 `workbench://open/inbox` 或 `workbench://open/task?workspaceId=...&projectId=...&taskId=...` 时，唤醒并聚焦唯一窗口。尚未登录时安全目标会在本机暂存，登录确认后再执行只读跳转；无权或失效任务明确提示不可访问，畸形链接直接拦截提示且绝不自动触发 Agent 执行。

## 使用本机 Agent 发送消息

启动桌面前，将 `WORKBENCH_ACP_EXECUTABLE` 设为 Agent 命令的绝对路径。使用独立安装的 Harness 时，将 `WORKBENCH_ACP_ARGS_JSON` 设为 `["acp"]`。Harness 从自己的用户环境读取模型配置。源码启动方式见 [HC-197 本机复现](../developer/spec/HC-197-通用ACP运行时.md#主进程接线与本机复现)。

登录后打开本人的会话。已通过系统选择器确认的目录会在本机记住，重开或重新登录时检查目录仍是原来的文件夹后自动恢复。旧资料中只有路径的目录会显示「待确认」，可在输入区点击「确认目录」，在原生窗口确认一次，或点击「选择目录」另选。可用时输入消息并点击「发送消息」。回复会分段出现，完成后可继续发送。目录已被移动、删除或替换时会显示「已失效」，输入区保留草稿并提供重新选择入口。

尚未选择目录时只显示「选择本机文件夹…」，不显示目录确认按钮。已保存目录待确认时，输入区的「确认目录」和目录菜单中的「确认并授权此目录」使用同一个原生确认。取消时保留草稿并给出普通提示；失败时显示原因，可重试或重选。

已受理的消息即使失败或停止，也会保留在本人本机历史，重开后仍能看到原文、已收到的部分回复和真实终态；个人空间和 Project 本人页均可阅读。未受理发送继续保留为草稿。只有符合条件的成功定稿进入共享和会话恢复材料，不会自动重发失败消息。更新前已丢失的桌面轮次不会自动回填。

输入框底部的 Agent 和模型菜单左侧切换 Agent，右侧搜索和选择当前 Agent 的模型及可用推理强度。权限菜单用图标区分档位，选中完全访问后输入框会显示琥珀色提示。直接输入 `@` 查找引用，或在消息开头输入 `/` 查看可用命令。

鼠标移到已发送的用户消息上，消息下方会显示复制图标和本机时间。当天显示 `10:52`，同年跨天显示 `02-17 10:52`，跨年显示 `2025-02-17 10:52`。复制保留原文和换行。

回复完成后，思考和工具记录收起为一行，例如「Harness Code 用时 15s」。点击可以展开过程，鼠标悬停或键盘聚焦时，右侧显示完成时间，格式和用户消息一致。

回复过程中，草稿为空时可点击输入区的停止按钮，等待 Agent 确认结果。Agent 请求工具权限时，可选择一次性允许或其他已提供的选项。允许类选项需再按「提交」。拒绝时当前工具不会获得授权。

关闭重开后，重新登录并打开原会话。目录检查通过后，支持恢复的 Agent 会在下一次发送时继续原生会话。更换 Agent 命令或工作目录会建立独立绑定。若原会话不存在或恢复不可用，输入区会显示原因。之前版本尚未记录原生会话绑定的会话，在新版首次运行时开始记录。

项目会话成功完成一轮后，本机异步上传该轮输入、最终回复及简报。项目成员可以先查看简报，再点击「同步会话」读取正文。本机回复已完成但共享失败时，输入区会单独显示共享失败。临时连接中断后，本机保留待传批次并重试。停止或拒绝工具的轮次留在本机当前页面。

## 排队和立即发送

Agent 正在回复时，输入下一条指令会让停止按钮切换成发送箭头。按 Enter 或点箭头即可将消息加入「待发消息」列表，草稿清空后按钮切回停止。当前轮正常完成后，桌面依次发送。列表右侧可编辑或移除消息。

Harness Code 的普通 Build 轮支持「立即发送」。在草稿里按 Command + Enter（Windows 上按 Ctrl + Enter），或点某条待发消息右侧的箭头，将纯文本交给当前轮。Agent 确认接收后，桌面才清除草稿或移除该条待发消息。其他 Agent 只有在桌面识别到兼容的追发方式时才提供这个操作。

停止、失败、更换 Agent 或工作目录，以及重开应用时，待发消息保留在本机。确认后点击「继续发送」。如果提示某条消息发送结果待确认，先在会话中核对，随后可移除该项，或复制原文重新发送。

## 划选添加到对话

在本机会话的时间线正文、执行计划或中央分屏打开的代码文件与 Diff 中拖动划选文本，选区上方会出现「添加到对话」浮窗。点击后片段会作为行内引用块平铺出现在输入框上方，支持连续添加多条；来自代码分屏的片段会自动附带文件路径与行号，Diff 分屏附带 `(Diff)` 来源标记。

点击输入框内的任意引用块可弹出编辑浮层，同时修改所选文本本身并追加或编辑可选批注，也可删除或移出引用。未发送的引用块会随本机会话草稿保存在本机，重启桌面后仍会恢复。发送、加入队列或运行中追发时，所选原文与批注会与你的问题一并提交给 Agent，并在用户消息气泡顶部以可点击展开的行内引用块展示。

## 粘贴图片与放大预览

在本机会话输入框中按 Command + V（或 Ctrl + V）粘贴剪贴板截图或图片文件（支持 PNG、JPEG、WebP、GIF），图片缩略图会立即显示在输入框最上方。单边超过 2000 像素或大于 2 MiB 的静态图片会在渲染端等比缩放压缩，单轮最多附带 6 张图片、总大小不超过 5 MiB；动画 GIF 保留原始帧。未发送的草稿图片只保存在当前电脑的应用数据目录，不会写入你的代码仓库，重启后自动恢复。

点击输入框顶部或已发送消息中的任意缩略图可打开居中放大预览，支持按左右方向键或两侧按钮切换多张图片，按 Esc 或点击遮罩关闭；点击缩略图右上角「×」可直接移除。若当前所选本机 Agent 不支持图片输入，输入区会直接提示并阻止发送；已附带图片的消息支持随文字排队，暂不支持在运行中纯文本「立即发送」追发。

## 查看轮次代码变更

本人会话打开 Git 工作树根目录后，点击对话上方的「轮次代码变更」，选择一轮并点击文件查看 Diff。快照对比两次捕获之间的工作树，期间手动修改的文件也可能出现在 Diff 中。

专用于当前会话的 Git linked worktree 可以选择「回退到轮前」或「恢复到轮后」。先核对受影响的文件，再在原生确认框确认这份工作树只供当前会话使用。桌面保留暂存区和 HEAD，并生成可从相应轮次打开的保护快照。主工作树或存在会话目录重叠时仍可查看 Diff。非 Git 目录可以继续聊天。

兼容 Agent 的模式选项会归入同一个「模式」菜单。原生会话无法恢复时，允许重建的 Agent 会收到本机已缓存的定稿历史片段作为前情。已协商 Harness 扩展的 `/btw` 旁路问答标为「仅本机」。

## 引用、项目任务与团队知识

新建会话准备页也支持输入 `@` 选择当前项目的可读会话。查看快照后点「加入草稿」，引用会保留在当前准备页，可继续编辑。点击草稿引用卡右上角的 × 可取消本次引用，原对话和材料不变。目录和文字随草稿保存。普通 Enter 换行，选择目录并点击「开始会话」后，文字和已确认引用随首轮交给本机 Agent。仅引用材料也可开始会话。

- 在本人本机会话键入 `@` 并选择项目会话，可查看已上传消息或简报的固定快照。核对范围和正文后，选择本人本机的已有或新建会话并点击「加入草稿」。只有本人点击「发送消息」才提交给本机 Agent。来源随后追加消息时，草稿仍使用原快照。点击「刷新」可预览并确认替换。
- 在会话输入 `@成员`，或从只读会话点击「创建任务」，表单会默认准备并附带当前来源的固定快照。快照使用已上传的有限内容，默认消息范围至多最近 20 条，或按现有规则使用有效简报。核对「已附带」数量后，可展开预览或移除，再点击「发布任务」。在 Project 看板点击「新建并指派任务」时，同样可选来源并附带会话快照，发布成功后自动在看板右侧滑出任务详情抽屉。
- 被指派人可在抽屉中操作「接收任务」「关联会话」和「在本机开始」。后者将任务说明与已保存的固定材料带入草稿，保留原文字和工作目录并切回工作台会话输入区，可检查后再发送。旧任务若发布时未保存材料，不会自动补入来源对话，可在执行草稿中用 `@会话` 显式引用来源。
- 通过 56px Rail 打开「团队知识」进入 `1200px` 双栏阅读视图：左侧支持关键词搜索与按真实分类（`category`）扁平筛选，右侧展示 Markdown 正文、分类与版本徽标，可点「版本历史」切换旧版、管理员新建/编辑/归档条目，或点击「引用到当前会话」与 `@知识` 搜索带入当前工作台会话。归档后条目退出列表，已保存的固定引用仍可按原版本读取。

## 演示身份

需要登录时，由开发者先显式启动协作服务和数据库，并在启动桌面前配置 `WORKBENCH_SERVICE_ORIGIN`。没有配置时窗口仍可使用，身份区域显示连接提示。[仓库说明](../../README.md#显式启动-java-数据基础)

1. 点击导航的「登录」，在「演示账号」选择服务返回的工号与姓名，点击「演示登录」。这些账号用于演示普通用户身份。
2. 只有一个工作区时直接进入，有多个时从左侧选择。在「设置 → 团队设置」查看当前团队成员和角色，「刷新团队」会重新查询服务。
3. 点击“退出 / 切换账号”，旧成员立即隐藏。退出后可重新选择其他账号；不会沿用上一账号的请求或结果。

断库或断网时暂停业务显示，只保留上次身份提示；恢复后点击“重试连接”重新确认。服务重启或会话失效需要重登。退出失败仍清理本机凭据，并明确“本机已退出，服务端退出未确认”；远端会话可能直到超时前仍存在。关闭窗口会释放本机身份和监听，重开需重新登录。

Cookie和CSRF只保存在主进程内存。用户退出或切换账号时，已启动执行器仍使用原设备身份；只有该设备所有者可以管理它。基础身份结果见[HC-194 Task](../developer/task/HC-194-协作契约与云端基础.md)。

## 本机项目与执行器

1. 登录设备所有者账号并选择工作区。在「设置 → 本机设备」点击「选择目录并登记」，通过系统目录选择器选定项目。项目名称可选。
2. 点击“共享项目”，等待服务确认共享。工作区成员可以看到项目展示信息，本机路径和设备凭据保存在原设备。
3. 点击“启动本机执行器”，观察“正在恢复连接”到“服务已就绪”。设备共享页面的 Agent 配置仍按该 Runner 的实际能力显示。本机纯文本发送使用上方的本机 Agent 配置。
4. 关窗后可重新打开并登录。原执行器继续运行，切换其他账号后设备所有者仍保持原值。
5. 点击“撤回共享”结束项目共享，点击“停止”结束本机执行器。应用菜单或托盘中的“退出”会等待执行器退出，停止未确认时保留提示。

## 本机项目记忆与团队知识（HC-233 / HC-256）

项目记忆按服务、账号和会话所属团队保存在本人电脑的 `.harness/workbench/project-memory/`。`team.md` 概括工程用途、仓库和关系，`personal.md` 记录本人目录与副本。两份都是普通 Markdown，由当前 Agent 或本人维护，不会自动成为团队共享知识；侧栏切换不改变已有会话的团队绑定。无团队会话不读取或创建这对文档。

Agent 获得新信息或用户纠正时，先读取最新记忆再合并保存；无变化不写，歧义先问用户。工具显示已保存时文件已经落盘，之后停止或运行失败不会撤销。并发冲突会要求重读合并，不再要求填写条目来源或重复选择目录。记忆中的路径仅供理解工程，实际目录访问仍遵守当前 Agent 的能力和授权，不会改变会话起始目录。

进入「管理与设置 → 本机项目记忆」可以查看两份正文、编辑保存或取消。会话引用预览只展示引用材料和目标会话等引用操作，不展示本人项目记忆。冲突时草稿保留，点击“重新读取（保留草稿）”后对照已保存正文合并。保存空正文可清空信息；切换账号、团队或离开页面前请先保存草稿。

两份内容合计以 8 KiB 为整理目标，超出仍可保存并提示整理。MCP 整个 JSON 请求有 64 KiB 技术上限，超限会明确拒绝且文件不变，不会静默截断。首次缺失只创建最小模板，已有空文件不补回内容。新版本正常首次读取旧记忆时，会先保留逐字节原件备份，再迁为普通 Markdown；损坏原件保留并提示检查。

每个原生绑定首轮完整提供两份文档，确认送达后仅发送有变化文档的完整正文。团队知识仍按现有规则读取固定版本、审核和反馈。当前实现和必要隔离证据见 [HC-256](../developer/task/HC-256-AI自主维护项目记忆.md)，正式桌面/IPC 端到端与完整环境验收仍由统筹安排。


## 团队角色与成员交接

在左侧进入团队后，点击 56px Rail 左下角「管理与设置 → 成员角色与仓库」。管理员可按工号添加已有账号（初始为开发者）、调整成员角色、登记仓库和设置仓库负责人；开发者可查看名单和团队知识。团队角色与 Project 的负责人/成员身份相互独立，管理员不会自动取得所有 Project 的正文阅读权。

团队可有多名管理员，最后一名有效管理员不能被降级或移除。知识的直接发布与仓库管理由管理员执行；开发者可联系管理员维护团队知识。

管理员点击成员的「移除与交接」后，先读完项目、未完结任务和仓库负责人清单，再选择默认或逐项接手人。接手人若还不在某个 Project，必须逐项明确确认其将获得该项目已共享内容的阅读权。活跃任务和项目必须有人接手，仓库可选择「待认领」；归档对象保留历史。

确认后，执行中的任务回到「待接收」，新负责人需用自己的本机 Agent 主动接收；原执行会话只作为历史来源保留。任务原发起人不转名，若其已离开，由当前有效 Project 负责人代管验收。清单变化时会要求重新读取，不会只移除一部分责任。

离开团队会撤销团队知识和 Project 的访问权；留任的有权成员仍可只读查看已共享历史，作者旁标「原成员已离开」。不会删除原会话、快照、知识版本和贡献，也不会把他人的 Agent 执行权交给接手人。已同步到本机历史或已读进 Agent 上下文的内容无法收回；原成员自己的本机会话不删除，后续不再注入该团队资料或上传到原团队。

窗口重新激活、通知或管理权限被拒绝时会重新确认真实角色。失去管理员身份后，已打开的管理/发布表单也会关闭；重新加入团队不会自动恢复旧 Project 成员身份或已停止的会话共享。

## 团队知识的提议、审核与复核

团队知识分为“规约、经验、术语”，可以适用于全团队或指定的团队仓库。成员主动阅读固定版本不受适用范围筛选限制，仍须有当前团队阅读权限；自动目录和规约按本机会话实际匹配的仓库筛选。普通非 Git 目录仅自动使用全团队知识。

在团队知识库打开“我的提议”可保存草稿、提出修订并确认共享给管理员。提交内容包括正文、级别、范围和本人确认的来源摘要，个人会话原文不会自动上传。待审核、退回和私人草稿不会进入其他成员的知识目录。管理员从“待审核”比较固定基准，批准、填写理由退回，或修改后批准；发布生成新版本，旧版和原贡献记录保留。基准已变化时须重新比较，不能覆盖他人的新结论。

知识页的“让本机 Agent 整理”需选择本人可执行的本机会话；起草是可见、可停止的临时运行，采用当前 Agent 可用的新会话设置，不另配模型。它实际检索和读取知识后只生成本机候选，仍需本人编辑提交、管理员批准。会话中的“沉淀为团队知识”入口使用本人选择的定稿轮次；正常 Project 会话入口可选择已完成且共享成功的定稿，刚完成时可点击“重新读取定稿”。“查看本轮定稿材料”可检查用户消息、追发、工具摘要与终稿，不包含完整工具输出。起草前由主进程重读核验全部选材，变化后需重新选择；未完成尾段不可选，部分历史明确提示，不会声称整理了完整会话。规约整组超预算/读取失败时输入区显示可重试原因，普通消息仍可发送；普通逐轮自动材料的送达组合验证仍见开发任务待项。

正文和固定知识工具结果提供“有用 / 已过期或有误”轻反馈。每人每固定版本只有一份有效选择，可修改或撤销。读取次数只统计 Agent 通过知识工具成功取得正文，同轮同版和重试不重复；浏览页面、目录展示与自动注入不增加工具读取次数。反馈说明仅本人和当前管理员可读。

管理员的“待复核”列出超过90天未复核、尚未复核或当前版有未处理过期反馈的条目。管理员可说明核对结果、发起修订或归档；新反馈不会被旧复核覆盖。系统不会仅因一条反馈自动删除知识。

规约单条正文最多4 KiB，整组自动材料独立预算8 KiB。无法完整取得或整组超预算时，规约整组不附带并提供可重试状态，普通本机消息继续沿既有规则发送。两份本机记忆仍完整处理，不为凑预算按关键词或当前工程裁剪。


本机有效团队会话首轮提供该绑定团队的完整本机记忆和短维护指引，后续仅发送有变化文档的完整正文，并沿用匹配知识的增量机制；侧栏切换不改变绑定，无团队会话不附带。记忆工具保存成功即落盘，停止或失败不撤销已完成的保存。自动附带规约不增加Agent工具读取次数，实际知识读取工具卡可展开查看固定版本并反馈“有用/已过期或有误”。
