# 子代理（Subagent）

子代理是由主代理通过 `task` 工具委派的独立执行单元。每个子代理拥有独立的上下文窗口、工具集和系统提示词，执行完毕后向主代理返回单一结果。

使用子代理的核心收益：

- **上下文隔离**：子代理的中间推理和工具输出不会污染主代理的上下文窗口。
- **专注任务**：每个子代理只关注单一目标，减少多任务切换带来的质量下降。
- **节省 token**：代码搜索等只读任务使用精简工具集，避免加载不必要的 schema、Skill 索引与历史。

## 可用子代理角色

系统提供两个内置角色，并支持通过 Plugin 扩展专用子代理：

| 角色 ID | 来源 | 用途 | 工具范围 | 特性与限制 |
| --- | --- | --- | --- | --- |
| `general-purpose` | 内置（Builtin） | 通用多步骤研究与实现任务 | 继承父 Agent 工具集（去除排除项）+ 父 MCP + 父 Skill | 继承父 AGENTS、工作区快照；在父 `default` 模式下内部按 `auto-edit` 运行 |
| `explore` | 内置（Builtin） | 只读代码搜索与位置定位 | 仅限 `ls`、`read_file`、`glob`、`grep`、`lsp`（5 只读工具） | 纯只读，无写工具、无 Shell、无网络、无 MCP、无 Skill 索引；启动自动放行。默认继承父模型；开启 `[experimental.delegation]` 后可绑定独立 Profile |
| Plugin Agent | 插件（Plugin） | 插件声明的领域专用审查/分析角色 | 插件显式声明的工具子集（与父权限求交） | 使用独立 Managed 引擎；需要人工交互时 fail closed |

主代理会根据任务性质自动选择合适的子代理。你也可以在提示词中明确指定，例如“用 explore 搜索 task 工具的定义位置”。

## 委派生命周期与并发控制

- **调用方式**：主代理通过 `task` 工具同步委派子代理，子代理执行完成后向主代理返回单一结果。
- **委派深度**：委派深度严格限制为 1 层（主代理 → 子代理），所有子代理均强制排除 `task` 工具，禁止递归委派。
- **并发与排队**：同一父会话同时运行中的子代理硬上限为 **4** 个。当派发的子代理超过 4 个时会自动排队等待可用槽位，并在前序任务完成后按序启动，不会直接报错失败。
- **取消与超时**：
  - 取消父 Run 会同步取消所有正在执行的子代理，并阻止排队中的子代理启动；
  - 每个子代理默认带有 300 秒硬超时。执行中的子代理超时后会取消实际 runner，将子代理标记为失败并回收资源；排队超时不会启动子代理；
  - `task` 卡片会显示失败，并包含 `status: timed_out` 与 `error_code: DELEGATION_TIMEOUT`。这次工具调用不会把主 Run 判为失败，主代理会收到该结果并继续下一轮；
  - 已经启动的子代理仍可进入原子时间线查看；排队超时没有子代理 execution，因此不会显示虚假的时间线入口；
  - 所有终态（成功、失败、取消、超时）均确保释放并发槽位与资源。

## 审批模式与交互规则

子代理不会把派出瞬间的审批档位永久冻结。每次尚未开始的 child 工具、模型和目录信任决策都会读取父 Run 当前档位，再与该角色的最大档位求交；已经开始的调用不撤销、不重放，父 Run 切换档位也不会取消正在运行的 child。

1. **general-purpose 的角色默认值**：
   - 父会话处于 `default` 时，`general-purpose` 保留既有的角色默认 `auto-edit`，工作区内常规编辑通常不逐次弹窗；这是角色策略，不是 child 自行把父 Run 放宽；
   - 父会话处于 `plan` 时，child 仍受 Plan 只读硬约束；一次 `enter_plan_mode` 已生效后，即使父 UI 离开 `plan`，该 Run 约束仍不能解除；
   - 父会话处于 `auto-edit`、`auto` 或 `yolo` 时，child 使用父当前档位。执行命令、工作区外访问、敏感路径、deny/Capability/Sandbox 等硬边界始终优先。
2. **explore 的只读免审批**：
   - `explore` 严格受限于 `ls`、`read_file`、`glob`、`grep`、`lsp` 五个只读工具，不具备写文件或命令执行能力，派出时可自动放行；父 Run 档位变化不会扩大这组工具。
3. **Plugin 子代理严格 Fail-Closed**：
   - Plugin 子代理的 `approvalMode` / `permissionMode` 只用于计算其最大权限，不能通过自身配置超过父 Run 当前档位；例如声明 `yolo` 也不能把 `default` 父 Run 变成 `yolo`；
   - Plugin 子代理若需要触发人工交互（如提问或未授权操作），仍通过主会话的 Interaction 通道；没有可用通道时拒绝，不默认放行。

子代理继承父 Run 的额外目录信任 registry。父档位切到 `yolo` 后，新的工作区外路径可以按当前会话规则自动获得 session 根；切回其它档位后，新的外部路径重新显示目录信任卡片。待处理的审批、问答或目录信任期间不能切换父 Run 档位；Plugin 恢复只有在对应 resumed stream 成功消费后才会提交 `on_resume_consumed` 和授权规则。

## 子代理时间线与交互

当主 Agent 派出子代理时：

- **主时间线保持整洁**：主时间线上只展示 `task` 派出卡片（包含派出角色、任务说明与最终结论），子代理执行的具体工具调用和思考过程不会平铺在主时间线中。
- **点击卡片进入子时间线**：在 TUI 或 Web 端点击派出卡片上的「进入子时间线」，即可进入该子代理独立的只读时间线视图，实时查看其思考过程与调用的每一个工具。
- **TUI 标题与复制**：派出卡片的标题行可用鼠标左键进入子时间线；任务说明和结果正文仍可拖选复制。长任务卡通过时间线滚动查看，标题与正文各占独立行。
- **刚派出时的空态**：如果卡片已绑定、子代理还没发出第一条过程事件，子视图会显示「子代理刚开始，暂无过程」，而不是清空主对话。
- **只读浏览与返回**：子时间线为纯查看视图，不能在其中向子代理输入新消息。在 TUI 下按 `Esc` 键、在 Web 端点击「返回主对话」按钮即可随时回到主时间线，派出卡片与主会话进度完整保留。
- **审批依然在主会话**：子代理若触发高风险操作（如 `execute` 命令），审批请求依然以「子代理 {agent_id} 需要审批」汇入主会话底部 FIFO 审批队列，进出子视图不影响审批处理。

## /agents 浏览命令

在交互终端中输入 `/agents` 可打开子代理只读浏览浮层：

- 列出当前所有可派发的 Agent（内置的 `general-purpose`、`explore` 以及已启用的 Plugin Agent）；
- 查看每个 Agent 的来源（内置/插件）、描述、模型策略以及可用工具清单；
- 仅供只读查看与了解工具边界，不切换当前会话 Agent。

## 工具控制与强制排除

无论子代理如何配置，以下控制类与模式类工具始终从所有子代理中强制移除：

| 工具 | 排除原因 |
| --- | --- |
| `task` | 防止子代理嵌套委派（保证深度严格为 1） |
| `enter_plan_mode` | 防止子代理切换主会话的计划模式 |
| `exit_plan_mode` | 同上 |
| `ask_user` | 内置子代理不直接向用户提问，缺少信息在最终报告中说明 |
| `tool_search` | 内置子代理不动态发现额外外部工具（explore 保持纯只读，GP 预先继承已揭示能力） |
