# 快速开始

最终用户安装后，在任意项目目录输入 `harness` 进入交互界面。开发者仍可从本仓库源码运行。源码开发请使用 Bun `1.3.13`（CLI/OpenTUI 运行时）、Python 3.11+ 和 `uv`。依赖安装跟随 npm/pip 的当前配置：企业外使用公网源，企业内使用企业源。两边都没配置时默认是 registry.npmjs.org 和 pypi.org。`HARNESS_NPM_REGISTRY`、`HARNESS_PYPI_INDEX` 只在工具配置仍指向公网、而这一次需要改走内网时使用。依赖安装与依赖检查只使用 Node/npm/Python，不会启动 Bun。

## 安装

macOS / Linux：

```bash
curl -fsSL https://<企业安装入口>/install.sh | bash
```

Windows 请打开 **PowerShell**（不要用 CMD 或 Git Bash）：

```powershell
irm https://<企业安装入口>/install.ps1 | iex
```

安装器会检测 Bun、Python 3.11+ 和 uv，缺了就补齐。已有合格版本会跳过运行时安装。Linux musl 与 Windows ARM 会拒绝并说明原因。

装完后若命令找不到，新开一个终端，或把 `~/.bun/bin` 与 `~/.local/bin`（Windows 为 `%USERPROFILE%\.bun\bin` 与 `%USERPROFILE%\.local\bin`）加入 PATH。

已有 Bun 和 uv 时的手动安装：

```bash
bun install -g @za38/cli --registry <企业 npm>
uv tool install za38-agent --index <企业 PyPI>
```

卸载：

```bash
bun remove -g @za38/cli
uv tool uninstall za38-agent
```

## 配置并启动

安装器在没有 `~/.harness/config.toml` 时会写入示例。已有文件不会覆盖。设置模板声明的 API Key 环境变量后，进入项目目录启动：

```bash
export HARNESS_API_KEY='你的企业网关密钥'
harness
```

从源码开发时，在仓库根目录同步依赖并复制模板：

```bash
npm run deps:sync
mkdir -p ~/.harness
cp docs/user/examples/config.toml ~/.harness/config.toml
export HARNESS_API_KEY='你的企业网关密钥'
npm run dev
```

`npm run deps:sync` 会读取 `npm config get registry` 和 pip 的 `global.index-url`，校验 Node/npm/uv/Python 版本、确认两个锁文件的下载地址属于这次选中的源，然后同步依赖并应用 DeepAgents 补丁。企业外的当前锁文件来自公网，直接冻结同步即可。只有依赖声明或包源发生变化时，才执行 `npm run deps:sync -- --update-lock`；它会更新锁文件并继续完成完整同步与验证，不需要再执行另一条安装命令。不要只执行 `uv sync`，否则不会应用项目所需补丁。

临时分支 `feat_hc_179_内网依赖源码化` 另有五个源码化 npm 发布包：`@opentui/core@0.4.3`、`@opentui/react@0.4.3`、`@opentui/core-win32-x64@0.4.3`、`bun-ffi-structs@0.2.4` 和 `react-devtools-core@7.0.1`。它们由 `third_party/npm/` 的 workspace 提供；macOS、Windows、Linux 的其他 native optional package 由当前 npm 源提供，企业外即公网源。`deps:sync` 支持 OpenTUI `0.4.3` 的 x64/arm64 目标，并在安装后校验当前平台原生包；Linux 默认使用 glibc，musl 环境需设置 `OPENTUI_LIBC=musl`。单个平台的测试结果不能替代其他系统的空缓存安装或 TUI 验收。

## 开发验证

macOS、Windows、Linux 都使用相同的 npm 入口：

```bash
npm run deps:test
npm run test:project
npm run project:check
npm run typecheck
```

这四条工程检查只使用 Node/npm。`npm run build`、`npm run test:ts` 和完整 `npm test` 会转入 `packages/cli` 的 Bun 边界，因为 bundler 和现有 CLI 测试仍依赖 Bun `1.3.13`；`npm run dev` 则因 OpenTUI/FFI 运行时依赖 Bun。

环境变量是推荐的密钥来源。如果本机启动流程无法注入环境变量，可在用户配置的模型 Profile 内增加降级值：

```toml
api_key_env = "HARNESS_API_KEY"
api_key = "你的企业网关密钥"
```

Harness 首次加载含字面量密钥的用户级配置时会自动将文件权限收紧为 `600`。非空 `HARNESS_API_KEY` 始终优先；字面量密钥不能出现在 `--config` 指定的文件或项目配置中。

交互启动后直接输入任务即可。首次发送后进入 thread 视图；输入 `/` 可打开已实现的命令菜单。

项目 Skill 放在 `<workspace>/.harness/skills/<name>/SKILL.md` 后会在下一次 Harness 启动时自动发现。可用以下命令检查和管理：

```bash
harness skills list
harness skills inspect project/review
```

## 无头模式

适合脚本或本地验证：

```bash
harness -n --message "总结这个仓库"
harness -n --message "列出风险" --json
npm run dev -- --non-interactive --message "总结这个仓库"
```

使用 `--cwd <路径>` 指定 project。使用无参数的 `--resume` 打开当前 project 的 thread 选择器；不要附带 `thread_id`，它由选择器内部处理。详细行为、数据位置和清理方式见 [交互使用](交互使用.md#恢复-thread)。

应用内自动更新不是本版本范围；升级请重新运行安装命令或手动 `bun install -g` / `uv tool install`。详细安装失败处理见 [故障排查](故障排查.md)。

## OpenTUI 依赖

源码运行依赖企业源提供的 `@opentui/core` / `@opentui/react` `0.4.3`。企业引入 Core 时还必须镜像其当前平台对应的 `@opentui/core-<platform>-<arch>` optional package；安装后由 Bun 按运行平台选择，不需要本地 Zig 或源码快照。
